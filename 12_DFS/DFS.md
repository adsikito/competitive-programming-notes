## 一、为什么需要它

先用你大概率会碰壁的方式做一遍 P1706【模板】全排列：输出 1..n 的全部排列。暴力思路是"每个位置独立地从 1 到 n 枚举"，生成全部 $n^n$ 个序列，再逐个用双重循环查重筛出合法的。$n=9$ 时 $9^9 \approx 3.9 \times 10^8$ 个序列，每个查重还要 $O(n^2) \approx 81$ 次比较，总量约 $3 \times 10^{10}$，必超时。**碰壁的根源：暴力把大量时间花在生成"注定非法"的序列上**——第 1 位已经填了 1，后面还在生成另一个 1 开头的序列。

DFS 的破法只有一句话：**逐位构造，填过的数用标记数组挡住，不合法的分支根本不进入**。生成的每个序列天生合法，$n=9$ 时只走 $9! = 362880$ 条叶分支，加上每条分支 $O(n)$ 的构造开销，约 $3 \times 10^6$ 量级，轻松通过。同一套思想换到网格上就是力扣 200 岛屿数量：不枚举"哪些格子是岛"，而是从一个陆地格出发把整座岛"淹掉"。

本篇讲 5 个知识点：DFS 是什么（搜索树与递归）、回溯与现场还原、排列型搜索 P1706、网格搜索 LC200、剪枝初探。顺序理由：结构（知识点 1）先于动作（知识点 2），构造场景（知识点 3）先于淹没场景（知识点 4），优化压轴（知识点 5）。

## 二、知识点逐讲（每个知识点一节，共 5 节）

### 1. DFS 是什么：搜索树与递归实现

前置依赖：递归（C 基础：函数调用自身、递归出口）、[[枚举与模拟]]（穷举的思想）
后续衔接：[[#2. 回溯与现场还原]]、[[二叉树结构篇]]（DFS 也是树遍历的本名）

**① 它解决什么问题**

A 源 slide 1 定义：搜索是暴力——"按照题目要求构造可能的答案，对所有可能的答案进行枚举，通过穷尽所有的可能来找到最优解，或者统计合法解的个数"。搜索分为 DFS 和 BFS，本篇只讲前者。DFS（图论）："深度优先搜索，是一种用于遍历或搜索树或图的算法。所谓深度优先，就是说每次都尝试向更深的节点走。"在搜索算法语境下，DFS 常指**利用递归函数方便地实现暴力枚举的算法**，通常构造一棵搜索树（状态树）来进行搜索。它解决的问题是：答案由一串决策组成时（每位填什么、每个格子走不走），用递归把"枚举所有决策序列"写成几行代码。复杂度取决于搜索树的规模：指数型枚举是 $O(2^n)$，排列型是 $O(n \cdot n!)$——这个量级账决定了后面剪枝（知识点 5）的价值。

**② 直觉理解**

模型级类比：**走迷宫的右手定则**。进迷宫后手扶右墙走，每到一个岔路口先挑最右边的岔路一头扎到底；死路就退回上一个岔路口换下一条岔路。"一头扎到底"就是深度优先，"退回岔路口"就是回溯（知识点 2 正式讲）。整座迷宫的所有路线构成一棵树：根是入口，每个岔路口分出岔路数的子枝，叶子是出口或死路——这棵树就是**搜索树**。

用具体数字跑一遍：n=2 的指数型枚举（每个数选或不选，输出所有子集）。dfs(1) 站在第 1 个数前：分支"选 1"走进 dfs(2)，又分"选 2"（叶子：{1,2}）与"不选 2"（叶子：{1}）；退回来走"不选 1"，同理得 {2} 与空集。四个叶子恰好覆盖 $2^2=4$ 个子集，一个不多一个不少。

**③ 原理与推导**

为什么几行递归就能枚举全部方案？推导链：设 dfs(step) 的含义是"前 step-1 个决策已定，现在枚举第 step 个决策的所有选项，每个选项都调用 dfs(step+1)"。那么 dfs(1) 启动后，程序按调用顺序把决策序列的第 1 位、第 2 位、……逐位确定，到达边界（step 超过 n）时输出一个完整方案。**归纳可证**：若 dfs(step+1) 枚举了后缀的所有方案，则 dfs(step) 枚举了从第 step 位开始的所有方案；基例是边界处只有"空方案"一种。所以 dfs(1) 枚举全部方案。

递归为什么等价于一棵树？函数调用关系本身就是树：一次调用是一个结点，调用内的每次分支尝试是一个孩子。系统调用栈自动记住了"当前走在哪条分支上"，返回时自动回到岔路口——这就是递归实现 DFS 的原因：**我们不用手写栈来记路线，调用栈替我们记**（想看手动版的对应物，见 [[栈与队列]]）。A 源 slide 1 也点明：搜索算法语境的 DFS 与图论 DFS 相似但不完全相同——这里没有显式的图，树是"构造出来的状态树"。

```text
n=2 子集枚举的搜索树（括号内是已做的选择）
dfs(1){}
├── 选1 → dfs(2){1}
│         ├── 选2 → 边界 输出 {1,2}
│         └── 不选2 → 边界 输出 {1}
└── 不选1 → dfs(2){}
          ├── 选2 → 边界 输出 {2}
          └── 不选2 → 边界 输出 空集
文字版推导链：第 1 层按"第 1 个数选/不选"分两枝；第 2 层同样分两枝；
到达边界（step>n）即叶子，每个叶子对应一个完整决策序列，共 2^2 个。
```

**④ 代码演示**

指数型枚举骨架（自编；n 很小，作用是把机制跑给读者看）：

```cpp
#include <cstdio>
int n, chosen[25];            // chosen[i]：第 i 个数选(1)/不选(0)
void dfs(int step) {
    if (step > n) {           // 边界：n 个决策全部做完
        for (int i = 1; i <= n; i++)
            if (chosen[i]) printf("%d ", i);
        printf("\n");
        return;               // 没有这行，越界后继续跑 → 死循环
    }
    chosen[step] = 1;         // 分支一：选第 step 个数
    dfs(step + 1);            // 扎向更深层
    chosen[step] = 0;         // 分支二：不选（顺手把现场还原，知识点 2 展开）
    dfs(step + 1);
}
int main() {
    scanf("%d", &n);
    dfs(1);
    return 0;
}
```

逐段讲解：`dfs(step)` 的参数是当前决策位；`step > n` 是唯一出口；函数体里"赋值—深入—复原—再深入"是 DFS 的标准节奏，分支之间靠对同一数组的重新赋值区分。

**执行追踪表**（n=2，chosen 初始 [0,0]）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | dfs(1) | chosen=[0,0] | chosen[1]=1，进入 dfs(2) | 挂起在分支一 |
| 2 | dfs(2) | chosen=[1,0] | chosen[2]=1，进入 dfs(3) | 挂起 |
| 3 | dfs(3) | chosen=[1,1] | step>n，输出 `1 2` | 返回 |
| 4 | 回 dfs(2) | chosen=[1,1] | chosen[2]=0，再进 dfs(3) | 挂起 |
| 5 | dfs(3) | chosen=[1,0] | step>n，输出 `1` | 返回 |
| 6 | 回 dfs(1) | chosen=[1,0] | chosen[1]=0，再进 dfs(2) | 走分支二 |
| 7 | dfs(2)、dfs(3) | chosen=[0,1]、[0,0] | 依次输出 `2`、空行 | 四个叶子穷尽 |

**错误写法对照**：

```diff
- void dfs(int step) { chosen[step] = 1; dfs(step + 1); }   // 坑1：没有 step>n 的出口，step 无限增大，数组越界（RE）或爆栈（RE）
+ void dfs(int step) { if (step > n) { /*输出*/ return; } ... }   // 出口是递归的安全带：先判边界再分支
- chosen[step] = 1; dfs(step + 1); dfs(step + 1);   // 坑2（虚构示意）：忘了第二个分支重新赋值，chosen[step] 仍是 1，"不选"分支实际走的还是"选"（答案漏一半）
+ chosen[step] = 1; dfs(step + 1); chosen[step] = 0; dfs(step + 1);   // 两个分支各自赋值，互不污染
```

**⑤ 典型应用**

- 真题：洛谷 P1706【模板】全排列（A 源 slide 1 给出链接，知识点 3 全流程实战）——排列型枚举，搜索树的每个叶子是一个排列。
- 真题：力扣 200 岛屿数量（A 源 slide 2 给出链接，知识点 4）——网格上的 DFS，同一递归思想换了一种"决策"含义。
- 迁移题：子集和——n 个数中选出若干个使和恰好为 S，输出方案。思路：本知识点骨架的边界处把 chosen 的和与 S 对比即可。标注：自编。

**⑥ 坑点与边界**

> **【易错】** 递归出口漏写或写成 `step >= n`（提前一位返回，最后一个决策做不完）。后果：前者 RE，后者答案少一类。出口条件必须与参数含义对齐：step 是"当前要决策的位"，做完 n 位后 step 变成 n+1 才返回。

> **【易错】** 两个分支共用同一次赋值。第 4 节追踪表里每片叶子对应唯一的赋值序列，赋值漏改 = 决策序列造假（答案错）。

> **【注意】** 递归深度等于搜索树的高度。n=25 的指数型枚举深 25 层无压力；但网格 DFS 深度可达格子总数（知识点 4 展开栈深问题）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → dfs(1) 直接命中 step>0 的边界，输出一个空行（预期：仅一个空行，不崩溃——空集也是方案）。
> 2. 单元素：n=1 → 输出 `1 ` 与空行两行（预期：2=2^1 个方案）。
> 3. 全相同：n=3 全部选同一处理逻辑，无区分 → 不适用：本骨架无"元素值"概念，值全相同不影响结构（方案数仍 2^3）。
> 4. 严格递增：n=5，观察输出前五行（含 1、2 的短子集在前）→ 顺序由分支次序决定，非按字典序（预期：与手推树序一致即可）。
> 5. 严格递减：不适用：本骨架不含数值排序语义，递减输入与递增无差别。
> 6. 极值：n=25 → 方案数 2^25 约 3.3×10^7，输出耗时是该题复杂度所在；n=30 则 1×10^9 超时——指数型枚举的可用上限约 n 到 25 上下（预期：n 大时必须靠剪枝或换算法）。

回扣开场：暴力枚举"每位置独立填 + 事后查重"的 $3 \times 10^{10}$ 换成了"逐位决策、只走合法分支"。现在你能写出把 $n^n$ 压到 $2^n$ 或 $n!$ 的骨架了——但骨架里"复原"那一步还没讲透，它是下一节的主角。

### 2. 回溯与现场还原

前置依赖：[[#1. DFS 是什么：搜索树与递归实现]]、数组（C 基础）
后续衔接：[[#3. 排列型搜索：P1706 全排列]]、[[#4. 网格搜索：LC200 岛屿数量]]

**① 它解决什么问题**

A 源 slide 2 定义："回溯就是要消除搜索过程中的不同可能性之间对中间变量的影响，即搜索下一个答案之前，保证上一个答案对下一个答案没影响，恢复到之前的状态。"它解决的问题是：DFS 的多个分支共享同一批"现场变量"（标记数组、棋盘、路径），上一个分支改了现场，下一个分支就会读到脏数据。**回溯 = 分支离开时把现场改回去**。为什么必须有它？没有回溯，$n$ 个分支里第一个分支的修改会污染其余全部分支——搜索树名义上有 $n$ 枝，实际只剩一枝能走对。

**② 直觉理解**

模型级类比：**实验室借白板**。每个实验小组（分支）借同一块白板（现场数组）做记录，归还前必须擦掉自己写的内容，下一组才能从干净白板开始。"擦"的时机是"小组做完实验（本分支的递归返回前）"，擦的内容恰好是"自己写上去的那几笔"——写了什么擦什么，不多不少。

用具体数字跑一遍：P1706 n=3 的前两个解。dfs 链填出 ans=[1,2,3] 时 flag=[1,1,1]，输出第一个解；回溯时 flag[3] 清 0，第 3 位改填 2 得 [1,3,2]。如果 flag[3] 没清 0，第 3 位只剩一个可填的数，[1,3,2] 这个解就凭空消失——解少了。

**③ 原理与推导**

推导"回溯为什么放在递归调用之后"：dfs(step) 内的循环对每个候选 i 做"赋值 → 深入 → 撤销"三步。深入 dfs(step+1) 期间，i 处于占用状态（这是本分支的决策，必须让深层看见）；从深层返回意味着**以 i 开头的所有方案已经枚举完毕**，此后 i 不再属于本分支的任何方案——此刻撤销，既不影响刚才的枚举（已经做完），又不污染接下来的 i'（现场干净）。放在深入之前撤销则深层看不到决策；循环结束都不撤销则兄弟分支读脏数据。位置唯一的原理是：**撤销必须恰好卡在"本分支对 i 的一切使用结束"与"下一个候选开始"之间**。

设计动机：为什么用"标记数组 + 撤销"而不是"每个分支拷贝一份现场"？拷贝的成本是每分支 O(n) 的复制与 O(n) 的额外内存，分支数是 $n!$ 量级，总开销爆炸；撤销只改"本分支实际动过的"那几格，通常 O(1) 到 O(分支深度) 次——这就是现场还原比快照便宜得多的原因。

```text
n=3 回溯时刻图（flag 的变化）
进入第3位填3: flag=[1,1,1] → 输出 1 2 3
返回后撤销 : flag=[1,1,0] → 3 号位重新可用
进入第3位无其他候选: 循环结束 → 返回第2位
返回后撤销 : flag=[1,0,0] → 2 号位重新可用 → 第2位改填3
文字版推导链：撤销只发生在"从深层返回之后、同一层下一个候选之前"；
flag 的 1 的个数 = 当前路径长度；输出的每个解都诞生于 flag 全 1 的瞬间。
```

**④ 代码演示**

核心片段取自源文件 P1706.cpp（改动：仅截取 dfs 函数与相关全局数组，main 与 prin 见知识点 3；注释按原文保留）：

```cpp
int ans[15];                  // 存放当前构造中的解
int flag[15];                 // flag[i]=1 表示数 i 已被当前路径占用
int n;
void dfs(int x) {             // 给第 x 个位置填数
  if (x > n) { return; }      // 边界（prin 的调用位置，此处省略）
  for (int i = 1; i <= n; i++) {
    if (flag[i] == 0) {       // i 没被用过才能填
      ans[x] = i;             // 做决策：i 填到第 x 位
      flag[i] = 1;            // 现场写入：标记占用
      dfs(x + 1);             // 深入
      flag[i] = 0;            // 回溯：撤销标记（源文件注释：撤销本层所做过的事情）
    }
  }
}
```

**执行追踪表**（n=3，从输出第一个解到构造出第二个解，flag 初始全 0）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | dfs(3) 填 i=3 | flag=[1,1,1] | flag[3]=1，深入 dfs(4) | 输出解 1 2 3 |
| 2 | 回到 dfs(3) | flag=[1,1,1] | flag[3]=0（回溯） | 3 号重新可用 |
| 3 | dfs(3) 循环尽 | flag=[1,1,0] | i 到 n+1，返回 | 回到第 2 位 |
| 4 | 回到 dfs(2) | flag=[1,1,0] | flag[2]=0（回溯） | 2 号重新可用 |
| 5 | dfs(2) 填 i=3 | flag=[1,0,1] | ans[2]=3，深入 dfs(3) | 新分支 |
| 6 | dfs(3) 填 i=2 | flag=[1,1,1] | ans[3]=2，深入 dfs(4) | 输出解 1 3 2 |

**错误写法对照**：

```diff
-      dfs(x + 1);
-      // （什么都不写）              // 坑1：漏掉 flag[i]=0，第一个分支占用的数永远显示"已用"，后续解大量缺失（答案漏）
+      dfs(x + 1);
+      flag[i] = 0;                 // 回溯在深入之后：本分支用完即还，兄弟分支拿到干净现场
-      flag[i] = 0; dfs(x + 1);     // 坑2（虚构示意）：撤销写在深入之前，深层看到的是"没用过"，重复使用同一个数（答案错：出现 1 1 1 类序列）
+      flag[i] = 1; dfs(x + 1); flag[i] = 0;   // 顺序固定：标记→深入→撤销
```

**⑤ 典型应用**

- 真题：P1706 全排列（A 源 slide 2 原话"需要回溯"，知识点 3 完整实现）——标记数组的撤销是该题唯一的"隐藏步骤"。

**⑥ 坑点与边界**

> **【易错】** 回溯只撤销标记、忘了撤销路径本身（如 ans 数组）。ans 在本题中每层被覆盖写，无需显式撤销；但若改为 push 进 vector 的写法就必须 pop_back——撤销的内容 = 本分支写入的内容，逐项对账。

> **【易错】** 把回溯写在 for 循环外（整个函数结束后撤销一次）。后果：循环内后续候选全部读到被污染的标记（答案错）。

> **【注意】** "回溯必须恢复现场"是排列构造类场景的规则；LC200 的淹没不恢复是另一条规则（每个格子只需访问一次），两者的取舍原因在知识点 4③ 推导。

> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → dfs(1) 命中 x>0 边界，循环一次都不进，flag 全程全 0（预期：无撤销动作、无输出内容）。

### 3. 排列型搜索：P1706 全排列

前置依赖：[[#2. 回溯与现场还原]]、printf 场宽格式（C 基础）
后续衔接：[[#4. 网格搜索：LC200 岛屿数量]]、搜索与剪枝（[[二叉树竞赛篇]] 的遍历顺序视角，待产出先文字锚定）

**① 它解决什么问题**

洛谷 P1706【模板】全排列（A 源 slide 1 链接）：按字典序输出 1..n 的全部排列，每个数占 5 个场宽（slide 1 原话"注意题目输出格式--5 个场宽"）。它是知识点 1（逐位决策）与知识点 2（标记 + 回溯）的直接合体：搜索树的每个叶子输出一个排列。复杂度：解有 $n!$ 个，每个长 $n$，总时间 $O(n \cdot n!)$，$n \le 9$ 时约 $3.3 \times 10^6$，无压力——这个量级也是该题数据范围设计的原因。

**② 直觉理解**

模型级类比：**发扑克牌**。桌上有 n 张明牌，逐个位置发牌：每个位置从 1 号牌看起，桌面上还在的才能发；发满一手牌就登记（输出），然后从最后一位起把牌一张张收回桌面（回溯），收回哪张就试试换成下一张还在的牌。字典序自动成立的原因：每个位置总是从最小的可用数开始试。

用具体数字跑一遍（n=3）：第 1 位试 1 → 第 2 位试 2 → 第 3 位试 3，满位输出 `1 2 3`；第 3 位收回 3 后无牌可换，退回第 2 位收回 2，第 2 位试 3 → 第 3 位试 2，输出 `1 3 2`；再退到第 1 位换 2……六个解按 123、132、213、231、312、321 依次产出（实测与断言程序一致，附录 B-5）。

**③ 原理与推导**

推导"字典序为什么自动成立"：dfs(x) 的 for 循环按 i=1,2,...,n 从小到大尝试，所以第 x 位在一切可能中先取最小可用值；对固定前缀，第 x+1 位同理。归纳可得全部解按字典序产出——不需要额外排序，复杂度里也就没有 $O(n! \log(n!))$ 的排序项。这也是搜索构造解的普遍优势：**解的顺序由分支次序天然控制**。

设计动机：为什么参数是"位置 x"而不是"剩余可选的数的集合"？用集合要额外的数据结构去"删数/还数"，而位置只需 +1 前进；"哪些数可用"用 flag 数组 O(1) 查询即可。参数取"决策位"让递归出口极简（x>n），这是排列型模板千篇一律的形态。

**④ 代码演示**

完整源码取自源文件 P1706.cpp（43 行，无改动；cin 的 C 等价写法见行尾注释）：

```cpp
#include<iostream>
using namespace std;
int ans[15];
int flag[15];
int n;
void prin()
{
  for(int i=1;i<=n;i++)
  {
    printf("%5d",ans[i]);      // 每个数占 5 个场宽（题面要求）
  }
  printf("\n");

}
void dfs(int x)                // 判断第x个位置填什么数
{
  if(x>n)
  {//n个位置都填满了 输出一个答案
    prin();
    return;
  }
  for(int i=1;i<=n;i++)        // 枚举所有可以填的数
  {
    if(flag[i]==0)             // i没有被用过
    {
      ans[x]=i;                // i填到x位置
      flag[i]=1;
      dfs(x+1);                // 继续填下一个位置
      flag[i]=0;               // 回溯：撤销本层所做过的事情
    }
  }
}
int main()
{
  cin>>n;                      // C 等价：scanf("%d",&n);
  dfs(1);                      // 从第一个位置开始
  return 0;
}
```

### 4. 网格搜索：LC200 岛屿数量

前置依赖：[[#2. 回溯与现场还原]]（对比"淹没不恢复"）、vector 基础（语法糖表）
后续衔接：图的 BFS（待产出，先文字锚定：BFS 用队列换掉递归栈，数岛屿同样成立）、连通块计数类题

**① 它解决什么问题**

力扣 200 岛屿数量（A 源 slide 2 链接）：'1' 是陆地、'0' 是水，上下左右相连的陆地组成一座岛，求岛的个数。A 源思路："主循环：遍历整个矩阵。当遇到一点为 '1' 时说明遇到了一个岛屿，岛屿数目 +1。但是这个 '1' 只是岛屿的一部分，所以要通过 DFS 来搜索到整个岛屿，并把这个岛屿的值全改为 0，防止重复计算答案。"它解决的问题形态是：**连通块计数**——数"连成一片的 1"有几片。复杂度：每个格子至多被淹没一次，主循环扫一遍，总时间 $O(nm)$、额外空间 $O(1)$（直接在原网格上标记），这是在原数组上改写而不是另开标记数组的原因。

**② 直觉理解**

模型级类比：**涨潮淹岛**。从任意一块陆地出发发大水，水沿着上下左右漫延，把碰到的每一块陆地都泡成水；大水退去后，这片陆地就从地图上消失了。主循环重新扫地图时，刚才淹掉的整片岛再也不会被数第二次——扫到下一块还露着的陆地，就是一座**新的**岛，ans 再加一。"淹"就是本题的标记动作，与排列题的 flag 完全同构。

用具体数字跑一遍（自造 3x3 两岛例，与断言程序同源，附录 B-5）：地图 `110 / 000 / 011`。主循环在 (0,0) 遇 '1'，ans=1，DFS 把 (0,0)、(0,1) 淹成水；扫到 (2,1) 又遇 '1'，ans=2，DFS 把 (2,1)、(2,2) 淹掉；扫完输出 2。

**③ 原理与推导**

推导"淹没为什么不需要撤销"：排列题里现场要在兄弟分支间复用，所以必须还原；本题主循环是**一次性线性扫描**，每座岛只需被数一次，被淹的格子后续行为唯一（当水处理），不存在"第二条路径要用它"的需求——撤销没有收益，只有开销。这是知识点 2 那条"回溯必须恢复现场"规则的适用边界：**现场是否需要被其他分支复用**。不复用则标记可以永久保留。

推导"为什么进入 dfs 第一行就淹没"：若淹没推迟到"检查完四邻之后"，两个相邻陆地格会互相把对方递归两次（A 调 B、B 又调 A），无限往复直至爆栈。先淹后递归，等价于给每个格子加了一把"只进一次"的锁。slide 2 原文描述的顺序是"可以走过去，然后将走到的点的值改为 0，再以走到的点为基础进行搜索"，代码实现（进入即改）与该语义一致且更安全（A-3 登记 1）。

设计动机：为什么边界判断用四个 if 而不是方向数组循环？四个 if 展开后每个方向的条件一目了然（越界判断与陆地标判断写在一起），对刚入门的读者更直白；方向数组（dx/dy）是竞赛常用缩写，功能等价，属于写法偏好。

**④ 代码演示**

核心版取自源文件 LC 200.cpp（改动：仅省略读入用的 main 与多余 include，完整版见源文件 LC 200.cpp；vector 相关 C 等价写法见行尾注释与语法糖表）：

```cpp
void dfs(vector<vector<char> >& grid, int i, int j)
{                                   // C 等价：char grid[][105], 以及 int n=行数, int m=列数（需额外传参）
  int n=grid.size();                // 行数（C 等价：预先存好的全局行数）
  int m=grid[0].size();             // 列数
  grid[i][j]='0';                   // 进入即淹没：走过陆地标记成水，防止重复走（源文件注释）
  if(i-1>=0&&grid[i-1][j]=='1')dfs(grid,i-1,j);   // 上：先判边界再访问
  if(i+1<n&&grid[i+1][j]=='1')dfs(grid,i+1,j);    // 下
  if(j-1>=0&&grid[i][j-1]=='1')dfs(grid,i,j-1);   // 左
  if(j+1<m&&grid[i][j+1]=='1')dfs(grid,i,j+1);    // 右
}
int numIslands(vector<vector<char> >& grid)
{
  int n=grid.size(), m=grid[0].size();
  int ans=0;
  for(int i=0;i<n;i++)
    for(int j=0;j<m;j++)
      if(grid[i][j]=='1')           // 发现一块还没淹过的陆地 = 一座新岛
      {
        ans++;
        dfs(grid,i,j);              // 淹掉整座岛
      }
  return ans;
}
```

**⑤ 典型应用**

- 真题：LC200 本题。官方样例（4x5 的 `11110/11010/11000/00000`）输出 1，断言程序实测通过（附录 B-5）。
- 真题：洛谷 P1596 [USACO10OCT]Lake Counting S（题号真实，同型连通块计数，8 方向版本——slide 2 提到"考虑往 4 个或者 8 个方向搜索"）。

**⑥ 坑点与边界**

> **【易错】** 越界判断与取值顺序颠倒（坑 1）。&& 的短路求值是安全的前提：左边的边界条件不成立时右边根本不求值。四条 if 都要"先边界、后取值"。

> **【易错】** 淹没动作位置放错（坑 2）。进入即淹是防互调的锁；放在检查四邻之后就是死循环式递归。

> **【注意】** 递归深度最坏 = 陆地格子总数（蛇形全 '1' 网格）。LC200 网格上限 300x300=9 万层，力扣栈空间可过；同思路搬到洛谷大网格题时留意栈限制，必要时改手动栈（[[栈与队列]]）或 BFS。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**

### 5. 剪枝初探：甩掉注定非法的分支

前置依赖：[[#1. DFS 是什么：搜索树与递归实现]]、[[#2. 回溯与现场还原]]
后续衔接：搜索专题提高篇（待产出：可行性剪枝/最优性剪枝/搜索顺序优化展开）；[[二分]]（另一类"砍搜索空间"的思想对照）

**① 它解决什么问题**

A 源 slide 1 一句话点到："搜索有很多优化方式，如减小状态空间，更改搜索顺序，剪枝等。"（素材仅此一句，本节展开属补充。）剪枝解决的问题是：搜索树里大量分支**在半路就能断定永远造不出合法解**，走完它们纯属浪费；在分支入口处用判断直接返回，把整棵子树砍掉。复杂度收益可以是从 $n^n$ 到 $n!$（排列的合法性剪枝）、从 $C(n,k)$ 的枚举量中砍掉重复——量级变化，不是常数变化。

**② 直觉理解**

模型级类比：**快递分拣**。包裹（部分解）在传送带上前进，每个安检口（剪枝判断）发现"这个包裹注定送不到"（前缀已非法）就当场扔掉，不再占用后面的传送带。与"造完整个包裹再扔"的区别：越早扔，浪费的工时越少——剪枝在搜索树的第 k 层砍掉的是它下面整棵子树。

用具体数字跑一遍：构造"从 1..n 中选 k 个数升序排列"的组合。不剪枝：两位各从 1 到 n 独立枚举，n=4 时 16 个序列，其中 (2,1)、(3,1) 这类乱序与 (2,2) 这类重复全靠事后丢弃。剪枝：第 2 位只从"第 1 位 +1"开始枚举，序列只剩 (1,2)(1,3)(1,4)(2,3)(2,4)(3,4) 恰好 6 个 = $C(4,2)$——一个非法序列都没有被生成。

**③ 原理与推导**

推导"为什么改枚举起点能砍掉重复与乱序"：要求选出的数升序，等价于"每个位置的数严格大于前一个位置的数"。设第 pos 位从 start 枚举（start = 前一位的值 +1），则任何生成的序列天然严格递增——非法序列在构造层就被排除，而不是生成后过滤。这就是 slide 1 说的"减小状态空间"与"更改搜索顺序"的具体形态之一。

设计动机：为什么剪枝判断要放在递归入口而不是出口？放在入口（进入 dfs 先判非法即 return），砍掉的是**当前结点以下的整棵子树**；放在出口（构造完再检查），浪费已经发生。判断越浅，砍得越多——这是"可行性剪枝"全部技巧的总纲。本节只立总纲，经典展开（如 n 皇后的对角线标记、子集和的最优性剪枝）留待后续篇。

```text
n=4 选 2 的剪枝对比
无剪枝搜索树: 第1位 4 枝 × 第2位 4 枝 = 16 叶（合法 6，非法 10 全部白走）
剪枝搜索树  : start=1 → {2,3,4} 三枝；start=2 → {3,4} 两枝；start=3 → {4} 一枝
              第2层共 3+2+1=6 叶，全部合法
文字版推导链：第 pos 位的候选区间从 [1,n] 收缩成 [prev+1,n]；
区间收缩在浅层逐枝累积，第 2 层总量 6 = C(4,2)，与组合数公式吻合。
```

**④ 代码演示**

组合枚举剪枝骨架（自编）：

```cpp
#include <cstdio>
int n, k, chosen[25];             // chosen：当前选中的数序列
void dfs(int start, int cnt) {    // start：本位最小可选数；cnt：已选个数
    if (cnt == k) {               // 边界：选满 k 个
        for (int i = 0; i < k; i++) printf("%d ", chosen[i]);
        printf("\n");
        return;
    }
    for (int i = start; i <= n; i++) {   // 剪枝：i 从 start 起，序列天然升序
        chosen[cnt] = i;
        dfs(i + 1, cnt + 1);      // 下一位从 i+1 起（严格大于当前）
    }
}
int main() {
    scanf("%d%d", &n, &k);
    dfs(1, 0);
    return 0;
}
```

**执行追踪表**（n=4, k=2，追踪到前三个解）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | dfs(1,0) | chosen=[] | i=1，chosen[0]=1，深入 dfs(2,1) | 挂起 |
| 2 | dfs(2,1) | chosen=[1] | i=2，chosen[1]=2，深入 | 输出 `1 2` |
| 3 | 回 dfs(2,1) | chosen=[1] | i=3、i=4 依次 | 输出 `1 3`、`1 4` |
| 4 | 回 dfs(1,0) | chosen=[1] | i=2，深入 dfs(3,1) | 新前缀 |
| 5 | dfs(3,1) | chosen=[2] | i 从 3 起 | 输出 `2 3`、`2 4` |
| 6 | 全部返回 | — | 共 6 个解 | 恰为 C(4,2) |

**错误写法对照**：

```diff
- for (int i = start; i <= n - (k - cnt) + 1; i++)   // 坑1（虚构示意）：把"剩余名额不够"的上界收紧写错成 n-(k-cnt)+1 之外的值——写松了白枚举，写紧了漏解（答案漏）
+ for (int i = start; i <= n; i++)                   // 初学先写对：本骨架正确上界就是 n；收紧版 i <= n-(k-cnt)+1 需逐步验证
- dfs(i, cnt + 1);             // 坑2（虚构示意）：下一位起点写成 i 而不是 i+1，允许重复选同一数（答案错：出现 1 1 类序列）
+ dfs(i + 1, cnt + 1);         // 严格递增的保证：下一位必须大于当前位
```

**⑤ 典型应用**

- 真题：洛谷 P1157 输出组合（题号真实）——本节骨架的直接题面化，输出格式另有要求。
- 真题：洛谷 P1706 全排列（知识点 3）——排列题的 flag 数组本质也是剪枝：把"已用"的分支在入口砍掉，$n^n$ 降到 $n!$。
- 迁移题：从 n 个数中选 k 个使和为 S（升级版子集和）——在组合骨架上加一层"当前和 + 后续全选最大值仍 < S 则 return"的最优性剪枝雏形。标注：自编。

**⑥ 坑点与边界**

> **【易错】** 剪枝条件写紧漏解：上界收紧公式差 1。收紧行为必须有归纳论证或小数据逐枝验证，否则宁可先不收（正确但慢）——先对后快。

> **【易错】** 剪枝条件写松白剪：判断了不影响任何分支的条件（如每次判断一个恒真式），代码看起来在剪，复杂度纹丝不动。

> **【注意】** 剪枝改变的是"走哪些分支"，不改变"解的正确性定义"。验证剪枝正确性的标准手段：与不剪枝版本在小数据上对拍输出。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：k=0 → cnt==k 立即成立，输出一个空行（预期：空方案也算一个解，输出 1 行空行）；n=0 且 k=1 → dfs(1,0) 的 for 区间 [1,0] 为空，无输出。
> 2. 单元素：n=1, k=1 → 输出 `1 `（预期：恰 1 解）。
> 3. 全相同：k=n=3 → 输出 `1 2 3` 恰一个解（预期：C(3,3)=1）。
> 4. 严格递增：任何输出行天然严格递增（预期：剪枝的直接性质，可作输出正确性目检）。
> 5. 严格递减：不适用：本骨架只会产出递增序列，不存在递减输出。
> 6. 极值：n=25, k=12 → C(25,12)≈5.2×10^6 个解可枚举；n=30, k=15 → 约 1.55×10^8 解，仅输出即超时（预期：组合爆炸仍受输出量制约，剪枝救不了"答案本身太多"的题）。

## 四、总结与自测

### 核心内容（一页纸速览）

- **DFS**：暴力枚举的递归实现，构造搜索树，每次向更深处走（A 源 slide 1）；指数型 $O(2^n)$、排列型 $O(n \cdot n!)$。
- **搜索树**：函数调用关系即树，调用栈自动记路线；边界 = 叶子。
- **回溯**：消除不同可能性对中间变量的互相影响，恢复到之前状态（A 源 slide 2）；位置固定在"深入返回之后、下一候选之前"。
- **P1706**：逐位构造 + flag 标记 + 回溯；字典序由"从小到大试"天然保证；场宽 %5d 是格式命门；$O(n \cdot n!)$。
- **LC200**：主循环找起点计数 + DFS 淹没整岛；进入即淹防互调；现场不复用故不撤销；$O(nm)$。
- **剪枝**：在分支入口砍掉注定非法的子树；判断越浅砍得越多；改动先对拍后上线。
