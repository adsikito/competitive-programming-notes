# 尺取法

## 零、知识地图

```text
尺取法（滑动窗口 / 双指针）
├── 1. 尺取法原理与单调性前提 —— 双指针不回退 + 状态增量维护 = O(n)，全篇骨架总纲
├── 2. 求最短合法区间 LCR008 —— 扩到达标、缩到刚好合法、记长度，最短型记录时机
├── 3. 计数型窗口 LC713 —— 按右端点分组，每步贡献 r-l+1，计数型记录时机
└── 4. 固定定长窗口 LC2379 —— 进出各一格维护计数，取窗口最值，定长特例
学习顺序：1 → 2 → 3 → 4；理由：1 是骨架与单调性前提，2/3/4 是三种"记录时机"变体，从可变窗口到定长窗口逐步降低变形难度
```

## 一、为什么需要它

还是那个老问题：枚举所有区间。n 个数的数组，问"和至少为 target 的最短连续段有多长"。枚举左右端点是 $O(n^2)$，n = $10^5$ 时 $10^{10}$ 次操作，超时（判断标准见枚举篇知识点 2）。

但这个暴力蠢在哪儿？左端点固定时，右端点越往右、区间越长、和越大。如果当前窗口的和已经超了 target，右端点再往右毫无意义；如果还没超，左端点往左缩也没意义。**方向性**就藏在单调性里——而普通暴力完全没利用它。尺取法（滑动窗口 / 双指针）就是把这层方向性变成两根只能前进不能后退的指针：左指针、右指针各走 n 步，总共 $O(n)$。

本篇讲 4 个知识点：尺取法原理与单调性前提、求最短区间、计数型窗口、固定定长窗口。先学"什么时候能用"，再按三个题型各过一遍代码范式。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 尺取法原理与单调性前提

前置依赖：[[枚举与模拟]]（区间暴力枚举为何 $O(n^2)$）、[[前缀和与差分]]（区间状态的增量思想）
后续衔接：本篇三种记录时机 [[#2. 求最短合法区间（LCR 008）]]、[[#3. 计数型窗口（LC 713）]]、[[#4. 固定定长窗口（LC 2379）]]；[[二分]]（同一"单调性"土壤的另一工具）

**① 它解决什么问题**

尺取法是用双指针维护"满足条件的区间（滑动窗口）"的线性算法：枚举右端点 r，对每个 r 维护以 r 为终点的合法区间左端点 l，区间随 r 前进而滑动。它解决"在序列上找满足某种限制的区间"类问题——求最短/最长合法区间、数合法区间个数。性质：l 与 r 各自单调前进、互不回退，总移动 $O(n)$；前提是区间性质随长度单调变化。

**② 直觉理解**

想象用一把没有刻度的卡尺量一段连续的书架：右手固定卡尺一端往右推，另一只手在左边收——书够多了就把左端往右收，不够就把右端往右扩。两只手都只朝一个方向走，永不回头。这就是"尺取"名字的来历：像用尺子一样量取一段区间。

用具体数字跑一遍"窗口和不超过 8 的最长区间"：数组 $[2, 5, 1, 4, 3]$。r=0：窗口 [2]，和 2。r=1：窗口 [2,5]，和 7，不超。r=2：和 8，不超。r=3：和 12 超 → l 右移，弹出 2，窗口 [5,1,4] 和 10，仍超 → 弹出 5，[1,4] 和 5。r=4：[1,4,3] 和 8，不超。整个过程 l 从 0 走到 2、r 从 0 走到 4，总共 6 次指针移动，而不是 $5 \times 5$ 次区间枚举。

**③ 原理与推导**

为什么 l 不会回退？以"和 ≥ target 的最短区间"为例：r 右移后若窗口和仍小于 target，说明以这个 r 为终点、以任何更靠左的 l 起点（区间更长）……注意这里方向别搞反——长度增加和才可能变大。反过来，"和 ≥ target"时 l 已经停在"再缩就不合法"的位置；r 再往右一格，和只会更大，l 只可能继续右移，绝无理由左移。这就是单调性：**边界固定时，区间越长区间权值和越大**（课件原话）。这个单调性保证了两件事：

1. 每个 l 值最多被"跨越"一次（l 不回退），所以左指针总移动 $\le n$。
2. 每个 r 值恰好被访问一次，右指针总移动 $= n$。

两者相加得 $O(n)$。设计动机：为什么不担心"l 跳过头"？每一步 l 的移动都由"当前窗口不合法"驱动，移动后立刻重新检查条件，跳头只可能发生在条件已满足时——而那时循环已经停了。

**④ 代码演示**

尺取法的通用骨架（本篇三道例题都是这个骨架的变体）：

```cpp
int l = 0;                       // 左指针，只进不退
long long cur = 0;               // 窗口状态（和/乘积/计数），增量维护
for (int r = 0; r < n; r++) {
    cur += a[r];                 // 复杂度：总 O(n)，r 进 n 步 l 进至多 n 步
    while (窗口不合法 && l <= r) {
        cur -= a[l];             // 增量撤销，不重算整个窗口
        l++;                     // 收缩左端
    }
    // 此处 [l, r] 恰为以 r 为终点的合法窗口，按题型取答案
}
```

第 5 行用 `cur` 增量维护是尺取法能 $O(n)$ 的另一半原因：若每次收缩都重算窗口和，单次收缩 $O(n)$，总复杂度退化回 $O(n^2)$。

> [!example]-
> **执行追踪表（数据同②：数组 $[2, 5, 1, 4, 3]$，条件"窗口和不超过 8"，求最长区间）**
> | 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
> |------|---------|---------|------|------|
> | 1 | r=0 进 a[0]=2 | l=0，窗口 {2}，sum=2 | 合法，不缩 | ans=1 |
> | 2 | r=1 进 a[1]=5 | 窗口 {2,5}，sum=7 | 合法，不缩 | ans=2 |
> | 3 | r=2 进 a[2]=1 | 窗口 {2,5,1}，sum=8 | 合法，不缩 | ans=3 |
> | 4 | r=3 进 a[3]=4 | sum=12 超 | 弹出 a[0]=2，l=1 | sum=10，仍超 |
> | 5 | 继续收左端 | 窗口 {5,1,4}，sum=10 仍超 | 弹出 a[1]=5，l=2 | 窗口 {1,4}，sum=5 |
> | 6 | r=4 进 a[4]=3 | 窗口 {1,4,3}，sum=8 | 合法，不缩 | 长度 3，ans 保持 3 |
> | 7 | r 走完 | l=2，r=4 | 结束 | 指针共移动 2+4=6 次，O(n) |

**错误写法对照**

```diff
- // 坑1：数组含负数或零时仍套用骨架
- while (窗口不合法 && l <= r) { cur -= a[l]; l++; }   // 单调性破坏：加一个负数窗口和反而变小，l 不回退论证失效 → 答案错（WA）
+ if (元素全正) { /* 套用骨架 */ }                     // 修复：先确认性质随长度单调；不单调改用前缀和 + 二分或单调队列
- if (窗口不合法) for (int k = l; k <= r; k++) cur += a[k];   // 坑2：每次收缩重算整个窗口 → 复杂度退回 O(n^2)（TLE）
+ cur -= a[l]; l++;                                    // 修复：增量撤销，进窗口加、出窗口减，每步 O(1)
```

**⑤ 典型应用**

- LCR 008 长度最小的子数组（力扣）：最短合法区间，见知识点 2。
- LC 713 乘积小于 K 的子数组（力扣）：合法区间计数，见知识点 3。
- 自编迁移题（自编）：数组每个元素为正整数，求和恰好不超过 v 的最长区间长度。建议先独立做，再对照题解。

  题解：条件反转为"和 ≤ v"，收缩时机反转为"和 > v 时缩 l"，答案在每个 r 处取 `r - l + 1` 的最大值。单调性前提（正整数、和随长度增）保持成立，骨架一字不改，只换判定方向。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 数组含负数或零时仍套用本骨架 → 单调性破坏（加一个负数窗口和反而变小），l 的不回退论证失效 → 得到错误答案。正确写法：先确认元素全正（或性质严格单调），否则改用前缀和 + 二分或单调队列（后续篇章）。

> [!caution]
> **【易错】** 窗口状态用 `cur` 重算而非增量维护 → 收缩一次算一遍窗口 → 复杂度退回 $O(n^2)$ → TLE。正确写法：进窗口加、出窗口减。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 外层循环一次不进，不产生任何窗口 → 预期输出：按题型约定（如最长长度输出 0）
> 2. 单元素：a=[3]，条件"和不超过 8" → 窗口 [3] 合法 → 预期输出：1
> 3. 全相同：a=[1,1,1,1]，和 ≤ 8 → 全部元素可同窗 → 预期输出：4
> 4. 严格递增：a=[1,2,3,4]，和 ≤ 8 → 窗口 [1,2,3] 和 6，再加 4 则 10 超 → 预期输出：3
> 5. 严格递减：a=[4,3,2,1]，和 ≤ 8 → [4,3] 和 7，再加 2 则 9 超 → 预期输出：2
> 6. 极值：a=[2147483647]（INT_MAX）→ cur 若用 int 则累加一步即溢出为负、误判合法；cur 为 long long → 预期输出：1

数据范围与复杂度上限：元素值累计可能溢出（乘积型尤其危险，LC 713 题面保证乘积在 64 位内），必要时开 long long。结论失效条件：条件不随区间长度单调时（如"窗口和恰好等于 target"），双指针骨架需要变形或换算法。收尾回扣：现在你能解决开场那个 $O(n^2)$ 枚举了——把"方向性"交给两根不回退的指针，$10^{10}$ 变 $2 \times 10^5$ 次指针移动。

### 2. 求最短合法区间（LCR 008）

前置依赖：[[#1. 尺取法原理与单调性前提]]（骨架与单调性前提）
后续衔接：[[#3. 计数型窗口（LC 713）]]（收缩条件对照）、[[#4. 固定定长窗口（LC 2379）]]；[[二分]]（前缀和 + 二分解同一题）

**① 它解决什么问题**

给定正整数数组与 target，求"和 ≥ target 的最短连续子数组"的长度，不存在则输出 0。这是尺取法最标准的题面：区间性质（和）随长度单调增，求最短合法者。性质：每一步 r 处，l 停在"以 r 为终点、再缩一步就不合法"的位置，此时 `r - l + 1` 就是以 r 为终点的最短合法区间。

**② 直觉理解**

继续用卡尺类比，这次目标是"量出最短的一段够重量的书"：右端不断加书，一旦总重量达标，左端就开始扔——能扔就扔（扔完仍达标），扔不动了（再扔就不够重），这时手里的段就是以当前右端为终点的最短达标段。每一步都记一下手长度，最后取最短。

用 LCR 008 的例子完整跑一遍（$nums = [2,3,1,2,4,3]$，$target = 7$）：

```text
r=0: sum=2                    <7   ans=∞
r=1: sum=5                    <7   ans=∞
r=2: sum=6                    <7   ans=∞
r=3: sum=8  >=7  试缩: 8-2=6 <7 停  ans=4   窗口 [2,3,1,2]
r=4: sum=12 >=7  缩:12-2=10>=7 -> sum=10,l=1
              缩:10-3=7 >=7 -> sum=7,l=2
              试缩: 7-1=6 <7 停          ans=3   窗口 [1,2,4]
r=5: sum=10 >=7  缩:10-1=9>=7 -> sum=9,l=3
              缩: 9-2=7>=7 -> sum=7,l=4
              试缩: 7-4=3 <7 停          ans=2   窗口 [4,3]
答案 2
```

**③ 原理与推导**

为什么收缩条件是 `sum - nums[l] >= target`（去掉 l 后仍合法才缩）而不是 `sum >= target` 就缩？前者的语义是"l 这个元素对达标没有贡献，扔掉"；后者的语义是"已达标就扔"——后者会把窗口扔到不合法，错过更短的合法窗口记录时机。正确顺序：先缩到"刚好合法"，再记 `r - l + 1`。设计动机：答案记录必须发生在"以 r 为终点的最短合法窗口"上，缩过头就漏答案。

为什么不漏最优解？最优区间 $[l^*, r^*]$ 会在 r = $r^*$ 时被考察：那一刻 l 只会 $\le l^*$（l 的不回退性保证它不会越过任何"曾经合法"的窗口左端），而收缩恰好停在 $l^*$——因为再缩就不合法与 $[l^*, r^*]$ 最短是同一件事。

**④ 代码演示**

LCR 008 核心逻辑（取自源文件 LC LCR 008.cpp，改动：读入适配本地测试，算法部分原样）：

```cpp
#include <cstdio>
#include <vector>
#include <climits>
#include <algorithm>
using namespace std;
int minSubArrayLen(int target, vector<int>& nums) {
    int ans = INT_MAX, n = nums.size();
    int l = 0, r = 0, sum = 0;
    while (r <= n - 1) {
        sum += nums[r];              // 复杂度：O(n)
        if (sum >= target) {
            // 缩到"再去掉 l 就不合法"
            while (l <= r && sum - nums[l] >= target) {
                sum -= nums[l];
                l++;
            }
            ans = min(ans, r - l + 1);   // 刚好合法时才记录
        }
        r++;
    }
    return ans == INT_MAX ? 0 : ans;     // 全部加起来都不够 -> 0
}
int main() {
    int t, n, x; scanf("%d %d", &t, &n);
    vector<int> nums;
    for (int i = 0; i < n; i++) { scanf("%d", &x); nums.push_back(x); }
    printf("%d\n", minSubArrayLen(t, nums));
    return 0;
}
```

第 14 行的 `ans == INT_MAX` 分支对应课件特别强调的边界情况："nums 中所有元素和 < target，答案为 0"。

> [!example]-
> **执行追踪表（数据同②：$nums = [2, 3, 1, 2, 4, 3]$，$target = 7$）**
> | 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
> |------|---------|---------|------|------|
> | 1 | r=0 进 2 | l=0，sum=2 | 2 < 7，不缩 | ans=∞ |
> | 2 | r=1 进 3 | sum=5 | 不缩 | ans=∞ |
> | 3 | r=2 进 1 | sum=6 | 不缩 | ans=∞ |
> | 4 | r=3 进 2 | l=0，sum=8 | 8≥7：试缩 8-2=6 < 7，停 | ans=min(∞, 4)=4 |
> | 5 | r=4 进 4 | l=0，sum=12 | 缩出 2 → sum=10, l=1；缩出 3 → sum=7, l=2；试缩 7-1=6 < 7，停 | ans=min(4, 3)=3 |
> | 6 | r=5 进 3 | l=2，sum=10 | 缩出 1 → sum=9, l=3；缩出 2 → sum=7, l=4；试缩 7-4=3 < 7，停 | ans=min(3, 2)=2 |
> | 7 | r 走完 | l=4，r=5 | ans=2 ≠ INT_MAX | 输出 2 |

**错误写法对照**

```diff
- return ans;    // 坑1：nums 全部元素和 < target 时 ans 仍是 INT_MAX，输出 2147483647（WA）
+ return ans == INT_MAX ? 0 : ans;    // 修复：全部不合法转 0
- while (sum - nums[l] >= target) { ans = min(ans, r - l + 1); sum -= nums[l]; l++; }    // 坑2：边缩边记录，漏掉"刚好合法"的最短值（WA）
+ while (l <= r && sum - nums[l] >= target) { sum -= nums[l]; l++; }
+ ans = min(ans, r - l + 1);    // 修复：先缩到刚好合法、后记录
```

**⑤ 典型应用**

- LCR 008（力扣，即 LC 209 同题）：本知识点主例。
- 洛谷 P1638 逛画展（同型题）：找包含全部 m 种画的最短区间，窗口状态从"和"换成"颜色计数"，骨架完全一致。
- 自编迁移题（自编）：正整数数组，求"和 ≥ target 且长度恰为偶数"的最短区间。建议先独立做，再对照题解。

  题解：骨架照旧，但窗口停在"刚好合法"处时长度可能为奇数。补一步：记 l 与 l+1 两个候选左端（长度减 1 后若仍合法则为奇长合法解中更短者不可靠，需在 r 固定时同时检查长度 r-l+1 为偶的 l 位置）。更稳的写法是收缩时不只停在一步：把 l 一路缩到底（sum-nums[l] ≥ target 才缩），记录所有"长度为偶且合法"的窗口。注意：此题说明尺取骨架变形时要重新论证"不漏解"，这是从模板到能力的分水岭。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 忘记"全都不合法输出 0"的边界 → ans 保留 INT_MAX 直接输出 → 输出 2147483647 → WA。正确写法：返回前判 `ans == INT_MAX` 换成 0。

> [!caution]
> **【易错】** 把记录答案放在收缩循环内部 → 只记到中间过程、漏掉"刚好合法"的最短值 → WA。正确写法：先缩完、后记录（源码第 11-12 行的顺序）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：nums 为空（n=0）→ while (r <= n-1) 不进，ans 保持 INT_MAX → 预期输出：0
> 2. 单元素：nums=[7], target=7 → sum=7≥7，试缩 7-7=0 < 7 停 → 预期输出：1；nums=[6], target=7 → 永不达标 → 预期输出：0
> 3. 全相同：nums=[2,2,2], target=6 → r=2 时 sum=6≥6，试缩 6-2=4 < 6 停，长度 3 → 预期输出：3
> 4. 严格递增：nums=[1,2,3], target=5 → r=2 时 sum=6，缩出 1 → sum=5, l=1，试缩 5-2=3 < 5 停 → 预期输出：2
> 5. 严格递减：nums=[3,2,1], target=5 → r=2 时 sum=6，试缩 6-3=3 < 5 停，长度 3 → 预期输出：3
> 6. 极值：target=2147483647（INT_MAX），nums=[10000] 共 $10^5$ 个 → sum 最大 $10^9$ 永不达标 → 预期输出：0（sum 建议用 long long 更稳）

数据范围与复杂度上限：n ≤ $10^5$、单值 ≤ $10^4$ 时 sum ≤ $10^9$，int 勉强够但建议 long long；n ≤ $10^6$ 时 O(n) 照样通过。收尾回扣：现在你能解决开场那个"最短达标段"了——扩到刚达标、缩到刚好合法、记长度，三句口诀就是全部。

### 3. 计数型窗口（LC 713）

前置依赖：[[#1. 尺取法原理与单调性前提]]（骨架）、[[#2. 求最短合法区间（LCR 008）]]（"缩到底"与"缩到刚好合法"两种收缩条件对照）
后续衔接：[[#4. 固定定长窗口（LC 2379）]]（记录时机再变体）；[[二分]]（按右端点分组计数思想的另一出口）

**① 它解决什么问题**

上一题求"最短合法区间"，这一题数"所有合法区间的个数"：正整数数组，数乘积小于 k 的连续子数组个数。枚举每个区间是 $O(n^2)$；尺取法的关键洞察是：**以 r 为右端点的合法左端是一段前缀**（l 越小乘积越大，超过 k 就非法），数一数这段前缀多长，答案就加多少。性质：r 每走一步贡献 `r - l + 1` 个新合法区间，不重不漏。

**② 直觉理解**

数"以新到货的书为最后一本、且总价不超预算的组合"：左端从当前位置往左扩，扩到第一个超预算的位置为止——中间每一种截法都是一个合法组合。新元素进来只产生"以它结尾"的新组合，之前的组合早就数过了，所以不会重复。

用 LC 713 样例完整跑一遍（$nums = [10, 5, 2, 6]$，$k = 100$）：

```text
r=0: p=10   <100  贡献 r-l+1=1   [10]            ans=1
r=1: p=50   <100  贡献 2        [5],[10,5]       ans=3
r=2: p=100  >=100 缩: p=100/10=10,l=1
            p=10 <100 停 贡献 2  [2],[5,2]        ans=5
r=3: p=60   <100  贡献 3        [6],[2,6],[5,2,6] ans=8
答案 8（与样例一致）
```

**③ 原理与推导**

为什么"贡献 r - l + 1"不重不漏？把所有合法子数组按右端点分组：右端为 r 的合法子数组，左端必须 $\ge l_r$（$l_r$ 是以 r 为终点的最小合法左端）。以 r 结尾、左端在 $[l_r, r]$ 中的子数组恰有 $r - l_r + 1$ 个，逐一列出互不相同、也不与其他 r 组的子数组重复（右端点不同即不同）。对 r 全体求和恰是不重不漏的计数。

为什么 $l_r$ 前缀式合法？乘积随区间变长而变大（正整数），所以合法左端集是 $\{l : l \ge l_r\}$ 的后缀形式——性质单调，尺取法适用。设计动机：为什么乘积型要除法撤销（`p /= nums[l]`）而不是减法？窗口状态是累积乘积，出窗口的操作自然是"除以出去的那个数"——增量维护的加减号换成乘除号，骨架不变。

**④ 代码演示**

LC 713 核心逻辑（取自源文件 LC 713.cpp，读入部分适配，算法原样）：

```cpp
#include <cstdio>
#include <vector>
using namespace std;
long long numSubarrayProductLessThanK(vector<int>& nums, int k) {
    int n = nums.size(), l = 0, r = 0;
    long long ans = 0, p = 1;        // p：窗口乘积，long long 防溢出
    while (r <= n - 1) {
        p *= nums[r];                // 复杂度：O(n)
        while (l <= r && p >= k) {   // 超预算就扔左端
            p /= nums[l];
            l++;
        }
        ans += r - l + 1;            // 以 r 结尾的合法区间个数
        r++;
    }
    return ans;
}
int main() {
    int k, n, x; scanf("%d %d", &k, &n);
    vector<int> nums;
    for (int i = 0; i < n; i++) { scanf("%d", &x); nums.push_back(x); }
    printf("%lld\n", numSubarrayProductLessThanK(nums, k));
    return 0;
}
```

与知识点 2 的骨架对照：收缩条件从"去 l 后仍合法才缩"变成"现在不合法就缩"——因为本题不需要"刚好合法"这个位置，需要的是合法左端的最小值，缩到底（直到合法）即可。

> [!example]-
> **执行追踪表（数据同②：$nums = [10, 5, 2, 6]$，$k = 100$）**
> | 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
> |------|---------|---------|------|------|
> | 1 | r=0 进 10 | l=0，p=10 | 10 < 100，不缩 | 贡献 r-l+1=1，ans=1 |
> | 2 | r=1 进 5 | p=50 | 不缩 | 贡献 2，ans=3 |
> | 3 | r=2 进 2 | p=100 | 100≥100：p/=10 → 10，l=1 | 贡献 2，ans=5 |
> | 4 | r=3 进 6 | p=60 | 10×6=60 < 100，不缩 | 贡献 3，ans=8 |
> | 5 | r 走完 | l=1 | 结束 | 输出 8 |

**错误写法对照**

```diff
- while (p >= k) { p /= nums[l]; l++; }    // 坑1：k <= 1 时 l 被推到 r+1，p 除到 nums[r+1] 越界（RE）
+ while (l <= r && p >= k) { p /= nums[l]; l++; }    // 修复：保留 l <= r 边界，越界前停手
- int p = 1;    // 坑2：乘积中途超 int 溢出为负，收缩判断错乱（WA）
+ long long p = 1;    // 修复：乘积型窗口状态一律 long long
```

**⑤ 典型应用**

- LC 713 乘积小于 K 的子数组（力扣）：本知识点主例。
- 洛谷 P1102 A-B 数对（思想迁移）：数"差为 C 的数对"，排序后对每个元素用两根指针夹出值域区间并计数，同为"按右端点分组计数"。
- 自编迁移题（自编）：正整数数组，数"和小于 k"的子数组个数。建议先独立做，再对照题解。

  题解：把乘积换成和（`p += a[r]`、`p -= a[l]`），其余逐行照抄。正整数保证和随长度单调，前提成立。这是"换状态不换骨架"的最小改动练习。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** k ≤ 1 时（如 k = 0 或 1，乘积至少为 1）：收缩循环会把 l 推到 r+1，`r - l + 1 = 0`，贡献自动为 0——骨架天然处理，但若手写时不带 `l <= r` 保护 → p 除以 nums[r+1] 越界 → RE。正确写法：收缩循环保留 `l <= r` 边界（源码第 8 行）。

> [!caution]
> **【易错】** 乘积用 int 存 → 中途溢出为负 → 收缩判断错乱 → WA。正确写法：乘积型窗口一律 long long。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 循环不进 → 预期输出：0
> 2. 单元素：nums=[5], k=10 → p=5 < 10，贡献 1 → 预期输出：1；nums=[10], k=10 → p=100≥100，p/=10 → 1，l=1 > r=0，贡献 0 → 预期输出：0
> 3. 全相同：nums=[2,2,2], k=10 → p 依次 2、4、8 全合法，贡献 1+2+3 → 预期输出：6
> 4. 严格递增：nums=[1,2,3], k=10 → p 依次 1、2、6 全合法，贡献 1+2+3 → 预期输出：6
> 5. 严格递减：nums=[3,2,1], k=10 → p 依次 3、6、6 全合法，贡献 1+2+3 → 预期输出：6
> 6. 极值：k=2147483647（INT_MAX），nums=[46341, 46341] → long long 下 p=2147488281 ≥ k，缩一次后贡献 1，合计 2；若 p 用 int 则乘积溢出为负、误判合法 → 预期输出：2（long long 下）

数据范围与复杂度上限：乘积增长极快，窗口实际很短，复杂度仍 $O(n)$；k 用 int 接收但乘积必须 long long。结论失效条件：含 0 或负数时乘积不再单调（0 会把乘积钉在 0，负数导致符号翻转），骨架失效，需分类讨论。收尾回扣：现在你能数清所有合法区间了——按右端点分组、每组数前缀长度，$O(n^2)$ 个区间被 $O(n)$ 次贡献覆盖。

### 4. 固定定长窗口（LC 2379）

前置依赖：[[#1. 尺取法原理与单调性前提]]（骨架）、[[前缀和与差分]]（进出各一格的增量维护思想）
后续衔接：[[单调栈]]（窗口状态带"最值"、不可增量维护时的替代工具，见本节迁移题）

**① 它解决什么问题**

前两题窗口长度可变；这一题窗口长度固定为 k：字符串由 B/W 组成，每次操作可把一个 W 涂成 B，问"得到 k 个连续 B"至少涂几次。等价于：所有长度为 k 的窗口中，哪个窗口 W 最少，答案就是那个最少数。性质：窗口长度固定，l 与 r 同步每次 +1，只需进出各一个元素，$O(n)$ 扫完。

**② 直觉理解**

拉动窗帘看风景：窗帘宽度固定，从左往右拉，每一站只需"右边进来一格风景、左边出去一格风景"，不需要每站重新数整幅窗帘里有什么。定长窗口的增量维护比可变窗口更简单——进出各一个元素。

用 LC 2379 样例完整跑一遍（$blocks = $ "WBBWWBBWBW"，$k = 7$）：

```text
初始窗口 [0..6]: W B B W W B B -> wl=3   ans=3
r=7: 出 W(blocks[0]) wl=2; 进 W(blocks[7]) wl=3; l=1  ans=3
r=8: 出 B(blocks[1]) 不变;  进 B(blocks[8]) 不变; l=2  ans=3
r=9: 出 B(blocks[2]) 不变;  进 W(blocks[9]) wl=4; l=3  ans=3
答案 3（与样例一致）
```

**③ 原理与推导**

为什么只需比较各窗口的 W 数？每个操作把一个 W 变 B，窗口内剩 $\min$ 个 W 就至少需要 $\min$ 次操作把窗口全变 B；反之 $\min$ 次一定够（逐个涂掉）。所以答案 $= \min_{\text{窗口}}(\text{窗口内 W 数})$。

增量维护为什么正确：窗口从 $[l, r]$ 滑到 $[l+1, r+1]$，只有两个格子发生变化——离开的 $blocks[l]$ 与进入的 $blocks[r+1]$。离开的是 W 则计数减一、进入的是 W 则加一，其余格子没进没出不影响。设计动机：可变窗口每步可能缩很多格，定长窗口每步恰好进出各一格——这就是定长版骨架更简单的原因。

**④ 代码演示**

LC 2379 核心逻辑（取自源文件 LC 2379.cpp，改动：变量初始化等价整理，算法逻辑原样）：

```cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;
int minimumRecolors(string blocks, int k) {
    int wl = 0;                       // 窗口内 W 的数量
    for (int i = 0; i < k; i++)       // 建初始窗口 [0, k-1]
        if (blocks[i] == 'W') wl++;
    int ans = wl;
    for (int r = k; r < (int)blocks.size(); r++) {
        if (blocks[r - k] == 'W') wl--;   // 离开窗口的格子
        if (blocks[r] == 'W') wl++;       // 进入窗口的格子
        ans = min(ans, wl);           // 复杂度：O(n)
    }
    return ans;
}
int main() {
    string blocks; int k;
    cin >> blocks >> k;
    cout << minimumRecolors(blocks, k) << endl;
    return 0;
}
```

源码的循环写法是 `r` 从 k-1 起步、循环内先 `r++` 再"出旧进新"，与上述写法在窗口区间上完全等价（其 l 与 r 始终相距 k-1）；本版把"进/出"的对象直接写成 `blocks[r]` 与 `blocks[r-k]`，窗口编号更直观。

> [!example]-
> **执行追踪表（数据同②：$blocks = $"WBBWWBBWBW"，$k = 7$）**
> | 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
> |------|---------|---------|------|------|
> | 1 | 建初始窗口 | blocks[0..6] = W B B W W B B | 统计 W 的个数 | wl=3，ans=3 |
> | 2 | r=7：出 blocks[0]=W，进 blocks[7]=W | 窗口 [1..7] | 出 W（wl=2）、进 W（wl=3），取 min | ans=3 |
> | 3 | r=8：出 blocks[1]=B，进 blocks[8]=B | 窗口 [2..8] | 出 B、进 B，wl=3 | ans=3 |
> | 4 | r=9：出 blocks[2]=B，进 blocks[9]=W | 窗口 [3..9] | 出 B、进 W，wl=4 | ans=3 |
> | 5 | r 走完 | — | 返回 ans | 输出 3 |

**错误写法对照**

```diff
- int ans = 0;    // 坑1：漏建初始窗口，第一个窗口的答案缺失（WA）
+ // 先完整建好 [0, k-1]：for (int i = 0; i < k; i++) if (blocks[i] == 'W') wl++;
+ int ans = wl;    // 修复：初始窗口建好后再从 r = k 开始滑
- if (blocks[r] == 'W') wl++; if (blocks[r-k] == 'W') wl--;    // 坑2：先加后减且下标错位，窗口短暂错一格（极端样例 WA）
+ if (blocks[r - k] == 'W') wl--; if (blocks[r] == 'W') wl++;    // 修复：出旧 blocks[r-k]、进新 blocks[r]，与滑动严格同步
```

**⑤ 典型应用**

- LC 2379 得到 K 个黑块的最少涂色数（力扣）：本知识点主例。
- 洛谷 P2671 求和（进阶联想）：涉及奇偶分组的定长思想，学完 DP 后可回看。
- 自编迁移题（自编）：长度 n 的数组，求所有长度为 k 的窗口中最大值之和（n ≤ $10^5$）。建议先独立做，再对照题解。

  题解：定长窗口每次进出各一元素，但"最大值"不能像计数一样增量维护（离开的恰是最大值时无法 O(1) 更新）——需单调队列（后续篇章）。此题的价值在于认清增量维护的适用边界：可加减可撤销的状态（和、计数、乘积）能用定长窗口，带"最值"的状态要换数据结构。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 初始窗口漏建或建错（从 1 开始建却从 0 开始滑）→ 第一个窗口的答案缺失 → WA。正确写法：先完整建好 $[0, k-1]$ 的状态，再从 r = k 开始滑。

> [!caution]
> **【易错】** 先加后减写成先减后加且下标错位 → 窗口短暂错一格 → 极端样例 WA。正确写法：记住"出旧 blocks[r-k]、进新 blocks[r]"的对应关系，与 l++、r++ 严格同步。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：blocks=""（size=0）且 k=0 → 初始窗口循环与滑动循环均不进，wl=0，ans=0 → 预期输出：0（题面保证 k ≤ size 时此情形不出现，骨架天然不崩）
> 2. 单元素：blocks="W", k=1 → 初始 wl=1 → 预期输出：1；blocks="B", k=1 → 预期输出：0
> 3. 全相同：blocks="WWWW", k=2 → 每个窗口 wl=2 → 预期输出：2
> 4. 严格递增：不适用：B/W 二值字符串没有大小顺序，"递增"无定义
> 5. 严格递减：不适用：同上
> 6. 极值：n=10^5、全 W、k=10^5 → 仅一个窗口，wl=10^5 → 预期输出：100000（int 计数不溢出）

数据范围与复杂度上限：n ≤ $10^5$ 时 O(n) 无压力；k = n 时只有一个窗口，循环体一次不进，直接返回初始 wl——骨架天然覆盖。结论失效条件：状态不可增量撤销（如最大值）时本骨架不适用，见迁移题解。收尾回扣：现在你能解决开场那个最少涂色问题了——窗帘拉一遍，数每站 W 的数量，最小值即答案。

## 四、总结与自测

- 尺取法的前提：区间性质随长度单调变化（正数和/乘积、计数皆满足）；不单调时骨架失效。
- 骨架两条纪律：指针不回退（保证 O(n)）、状态增量维护（保证每步 O(1)）。
- 三种题型各有记录时机：最短区间"缩到刚好合法再记"；计数型"每步贡献 r-l+1"；定长型"进出各一格后直接记"。
- 判断能不能用尺取：先问"左端点的合法集合是不是一段连续区间"——是才有滑动的意义。
- 前置概念清单：循环与数组（骨架载体）、区间和/乘积的增量计算（知识点 2/3）、字符串下标访问（知识点 4）、复杂度估算（枚举篇）。
