## 一、为什么需要它

先构造一个你迟早会碰到的碰壁场景：给你 $10^5$ 个长度 $10^3$ 的字符串，问互异的字符串有几个。两两逐字符比较是 $O(n^2 \cdot L) \approx 10^{13}$ 次字符操作，必超时；换成排序后只比较相邻串，每次比较仍要逐字符进行，且"比较"这个动作在子串匹配类题里会被调用成千上万次——**瓶颈始终在"字符串比较太贵"**。

字符串哈希的破法只有一句话：**用哈希函数把每个字符串压成一个整数**（25.pptx S1："将一个数据，经过哈希函数，映射到一个值域较小、方便比较的范围"）。压完之后，比较两个 $10^3$ 长的串从 $10^3$ 次字符比较变成 1 次整数比较；总代价变成一次 $O(\text{总长度})$ 的预处理。代价是映射可能"撞车"（两个不同的串映到同一个整数），所以还得学怎么把撞车概率压到可忽略——这是知识点 3。

本篇讲 4 个知识点：哈希思想与多项式哈希、前缀哈希与滚动哈希、自然溢出与双哈希、模板题 P3370。顺序理由：映射（知识点 1）先于它的子串扩展（知识点 2）与冲突加固（知识点 3），板子组装（知识点 4）放最后。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 哈希思想与多项式哈希：把字符串看成一个 b 进制数

前置依赖：char 数组与 ASCII 码（C 基础）、[[枚举与模拟]]（逐字符扫描的处理习惯）
后续衔接：[[#2. 前缀哈希与滚动哈希：O(1) 取任意子串]]、[[#3. 降低冲突：自然溢出与双哈希]]

**① 它解决什么问题**

字符串哈希（25.pptx S1）：通过哈希函数，**将字符串转为整数**。动机（S1 原话）：超长的字符串若能用整数存储、需要时再转回，能极大节省空间，更省的是比较成本。它有两条核心**性质**（S1 原文）：（1）Hash 值不一样时，两个字符串一定不一样；（2）Hash 值一样时，两个字符串**不一定**一样——值同串不同称为**哈希碰撞**。单串求哈希的复杂度是 $O(|s|)$，之后比较两个串的哈希值是 $O(1)$。

**② 直觉理解**

模型级类比：**给每个字符串发一个"数位身份证"**。一个 $n$ 进制数 234 转十进制是 $2 \cdot n^2 + 3 \cdot n + 4$（S2 原例）；把字符串同样看成一个 $b$ 进制数——每个字符是一个"数位"，多项式求值后就得到一个唯一代表它的整数（取模之前）。

用具体数字跑一遍（S2 的例子 $s = $ "xyz"，取 $b = 131$，ASCII：'x'=120、'y'=121、'z'=122）：$f = 120 \cdot 131^2 + 121 \cdot 131 + 122 = 2075293$。这个 2075293 就是 "xyz" 的身份证号；另一个串算出不同的号，两串必然不同。

**③ 原理与推导**

多项式 Hash 的定义（S2）：对长度为 $l$ 的串 $s$，$f(s) = s[0] \cdot b^{l-1} + s[1] \cdot b^{l-2} + \cdots + s[l-1]$，再对质数 $M$ 取模；$M$ 需选**素数**，$b$ 是比最大字符值大的整数（S2，按 ASCII 比较）。

回答三个"为什么"：
- **为什么用多项式（进制）形式**：取模之前，$b$ 进制表示与字符串一一对应（就像 234 这个数唯一对应数位 2、3、4）；一一对应是"值不同则串不同"这条性质的来源。随便选个一次函数就丢掉了一一对应性。
- **为什么 $b$ 要比最大字符大**：进制 $b$ 的"数位"必须落在 $[0, b-1]$ 内，数位一旦超过进制，不同的数位组合会算出同一个数。字符集是小写字母时，'z'=122，所以 $b$ 至少 123 起。
- **为什么不能把字符映射到 0**（S5）：若 'a' 对应 0，则 "ab" 的值与 "b" 的值都是 $b$——前导零被吞掉了，串长信息丢失。一般把 'a'~'z' 对应到 1~26 或直接用 ASCII（'a'=97，不含 0，安全）。

由于 $b^{l-1}$ 增长极快（$131^{10} \approx 1.8 \times 10^{21}$，早已超出 64 位整数），算出的数字必须对一个质数 $M$ 取模（S2）；取模之后一一对应被破坏，才有了性质（2）的碰撞问题——降低碰撞是知识点 3 的全部内容。

**④ 代码演示**

块一「核心代码」——取自素材 P3370--自然取余.cpp 的 Has 函数（逐行原样，main 见知识点 4）：

```cpp
typedef unsigned long long ull;   // 64 位无符号：等价 C 写法相同（typedef 是 C 语法）
ull b = 131;                      // 进制：比最大字符 'z'(122) 大，且比较好用（S5 原话）
ull Has(char s[]) {
    int l = strlen(s);
    ull sum = (ull)s[0];          // 首字符直接当初值；等价 C：sum = (unsigned long long)s[0]
    for (int i = 1; i < l; i++) {
        sum = sum * b + (ull)s[i]; // 多项式递推：先乘进制再进新数位；自然溢出见知识点 3
    }
    return sum;
}
```

块二「执行追踪表」——哈希值递推过程（"xyz"，$b=131$，数值与断言程序实测一致，附录 B-5）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | s[0]='x'(120) | sum 未定 | sum = (ull)s[0] | sum=120 |
| 2 | s[1]='y'(121) | sum=120 | sum = 120*131 + 121 | sum=15841 |
| 3 | s[2]='z'(122) | sum=15841 | sum = 15841*131 + 122 | sum=2075293 |
| 4 | 循环结束 | sum=2075293 | 返回 sum | f("xyz")=2075293 |

块三「错误写法对照」：

```diff
- hash = 'a' 对应 0，再按多项式求值   // 坑1：前导零被吞，"ab" 与 "b" 哈希相同（答案错，S5 原话）
+ 直接用 ASCII 值（'a'=97）或把 'a'~'z' 对应到 1~26，数位不含 0
- int sum; sum = sum*b + s[i];      // 坑2：int 只有 32 位，串长超过约 9 就溢出，且有符号溢出是未定义行为（答案错/RE）
+ ull sum;（unsigned long long，64 位无符号）
- for (int i = 0; i < l; i++) sum = sum*b + s[i];   // 坑3：初值 0 又从 s[0] 进位，等价于给串首多塞了一个 0 数位
+ sum = s[0] 起始，从 i=1 进位（或统一从 0 起算也可，但全篇只许一种口径）
```

**⑤ 典型应用**

- 真题：洛谷 [P3370【模板】字符串哈希](https://www.luogu.com.cn/problem/P3370)（S5 给出链接），n 个串求互异个数——知识点 4 全流程实战。
- 真题：P4391 [BOI2009] Radio Transmission 无线传输（题号真实；资料未覆盖，属补充）：求最短循环节，用知识点 2 的子串哈希可 $O(1)$ 判定"s 的后缀与前缀是否相等"。
- 迁移题（自编）：输入两个长 $10^5$ 的串，判断它们是否相等，但禁止逐字符比较。思路：各算一遍多项式哈希比较整数；哈希不同必不等（性质 1），哈希相同按概率认为相等（风险见知识点 3）。

**⑥ 坑点与边界**

> **【易错】** 字符数位映射到 0：前导零被吞，"ab" 与 "b" 同值。数位一律不含 0（④坑 1）。

> **【易错】** 用 int/long long（有符号）存哈希值：串一长必溢出，有符号溢出是未定义行为。一律 unsigned long long（④坑 2）。

> **【注意】** 哈希值相同的两个串**没有**任何程序层面的保证是同一个串——是否接受这个风险，取决于数据是否可能被针对（知识点 3）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用：Has 的入参是至少含一个字符的 C 风格串（strlen=0 时 sum 读 s[0] 越界）——调用侧必须保证串非空，本题面保证 n≥1。
> 2. 单元素：s="a" → sum=97，无递推（预期：f=97，不进循环）。
> 3. 全相同：s="aaaa"（4 个 'a'）→ 97*(131^3+131^2+131+1)=219742248（预期：等比求和，实测一致，附录 B-5）。
> 4. 严格递增：s="abcde" → 递推值 97 → 12805 → 1677554 → 219759674 → 28788517395（预期：逐位进位，实测一致）。
> 5. 严格递减：s="zyx" → 与 "xyz" 数位对称：120+121*131+122*131^2（预期：不同于 2075293，数位换位值变）。
> 6. 极值：长度 1500 全 'z' 串 → 中间乘法在 ull 内自然回绕（mod 2^64，知识点 3），预期：正常返回、不崩溃；int 版在此类数据必错。

回扣开场：把字符串压成整数后，比较从 $O(L)$ 降到 $O(1)$，"比较太贵"的碰壁根源被拆掉。现在你能回答"为什么字符串能当整数用"——接下来把这个映射升级成"任意子串 $O(1)$ 查询"。

### 2. 前缀哈希与滚动哈希：O(1) 取任意子串

前置依赖：[[#1. 哈希思想与多项式哈希：把字符串看成一个 b 进制数]]、[[前缀和与差分]]（S2 原话："类似与求前缀和"）
后续衔接：[[#3. 降低冲突：自然溢出与双哈希]]、[[二分]]（子串哈希判等 + 二分长度是 LC 1044 的标准套路）

**① 它解决什么问题**

很多题要反复比较**子串**（匹配、判回文、判循环节），每问一次就重算一遍哈希太浪费。前缀哈希（S2-S3）先把所有前缀子串 $s[0..0], s[0..1], \ldots, s[0..n-1]$ 的哈希值**递推**出来，之后**任意子串 $s[l..r]$ 的哈希值可以 $O(1)$ 拼出**——S3 把这种方式称为**滚动哈希**。复杂度总账（S4）：$O(n)$ 预处理前缀数组、$O(n)$ 预处理 $b$ 的幂次表、之后每次子串查询 $O(1)$。

**② 直觉理解**

模型级类比：**带位权的前缀和**。普通前缀和 $\text{sum}[l..r] = S[r] - S[l-1]$，减掉的是"前 $l-1$ 项的裸和"；前缀哈希里前 $l-1$ 个字符是站在高位上的（乘了 $b$ 的幂），减的时候必须先把它们**降位**到与子串相同的位权再减——"乘 $b^{r-l+1}$"就是降位动作。

用具体数字跑一遍（$s=$ "abcde"，$b=131$，数值实测见附录 B-5）：前缀哈希 $hash[1]=97$、$hash[2]=12805$、…、$hash[5]=28788517395$。取子串 "cde"（即 $s[2..4]$）：$hash[5] - hash[2] \cdot 131^3 = 28788517395 - 12805 \cdot 2248091 = 1712140$，而 "cde" 直接按定义算是 $99 \cdot 131^2 + 100 \cdot 131 + 101 = 1712140$——两者相等，公式工作正常。

**③ 原理与推导**

递推式的来历（S3 用 "abcde" 展开）：$hash[2] = a \cdot b^2 + b \cdot b + c = (a \cdot b + b) \cdot b + c = hash[1] \cdot b + s[2]$——每来一个新字符，旧值整体"左移一位"（乘 $b$）再放进新数位。于是（S3）：

$$hash[i] = hash[i-1] \cdot base + s[i]$$

子串公式的推导（S3）：按定义 $h = s[l] \cdot b^{r-l} + \cdots + s[r]$；而 $hash[r]$ 与 $hash[l-1]$ 都含有前 $l-1$ 个字符的贡献，且这份贡献在 $hash[r]$ 里站在比 $h$ 高 $r-l+1$ 位的位权上。两式相减，前段贡献恰好抵消：

$$h = hash[r] - hash[l-1] \cdot b^{\,r-l+1}$$

**设计动机**：公式里为什么偏偏是 $b^{r-l+1}$？因为 $hash[l-1]$ 的最高数位是 $s[l-1]$，它比 $h$ 的最高数位 $s[l]$ 高出 $r-l+1$ 个位——乘这个幂次正好把两段对齐到同一量纲，减法才会把公共前缀完整消掉。$b$ 的幂用整个数组保存（S3："快速求 $b^{r-l+1}$，可以整个数组来保存"），查询时才不必现算。

**④ 代码演示**

块一「核心代码」——自编骨架，公式逐行对应 S3 的两条式子（有改动：素材只给公式与文字推导，代码为按公式落地）：

```cpp
typedef unsigned long long ull;
const int N = 1505;
ull pw[N], h[N];              // pw[i]=base^i；h[i]=前 i 个字符（s[1..i]）的哈希
void init(char s[], int n, ull base) {
    pw[0] = 1;
    for (int i = 1; i <= n; i++) pw[i] = pw[i-1] * base;      // 幂次表：O(n)
    h[0] = 0;                 // 约定 h[0]=0（空串），让 s[l..r] 统一用 h[r]-h[l-1]*pw[r-l+1]
    for (int i = 1; i <= n; i++) h[i] = h[i-1] * base + s[i]; // 前缀哈希：O(n)
}
ull subHash(int l, int r) {   // 子串 s[l..r]（1 起）：O(1)
    return h[r] - h[l-1] * pw[r-l+1];   // 位权对齐后相减（S3 公式）
}
```

块二「执行追踪表」——前缀哈希递推 + 一次子串查询（"abcde"，$b=131$，数值实测见附录 B-5）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | s[1]='a'(97) | h[0]=0 | h[1]=0*131+97 | h[1]=97 |
| 2 | s[2]='b'(98) | h[1]=97 | h[2]=97*131+98 | h[2]=12805 |
| 3 | s[3]='c'(99) | h[2]=12805 | h[3]=12805*131+99 | h[3]=1677554 |
| 4 | s[4]='d'(100) | h[3]=1677554 | h[4]=1677554*131+100 | h[4]=219759674 |
| 5 | s[5]='e'(101) | h[4]=219759674 | h[5]=219759674*131+101 | h[5]=28788517395 |
| 6 | 查询 cde(2,4) | h[5], h[1] 不变 | h[5]-h[1]*131^3 | 返回 1712140 |

块三「错误写法对照」：

```diff
- return h[r] - h[l-1];              // 坑1：忘乘幂次，前缀贡献的位权没对齐，公共前缀消不干净（答案错）
+ return h[r] - h[l-1] * pw[r-l+1];  // 乘 b^(r-l+1) 把 hash[l-1] 降到子串的位权
- if (l == 0) return h[r] - h[-1] * pw[...];   // 坑2：0 起下标时 l-1=-1，数组越界（RE）
+ 下标从 1 起存串、h[0]=0 当空串哨兵，l 最小取 1（或对 l==0 单独特判返回 h[r]）
- for (i = 1; i <= n; i++) h[i] = h[i-1]*base + s[i];   // 坑3：i 从 1 起但串仍按 0 起存，s[1] 跳过了首字符
+ 串下标与 h 下标口径必须统一（本文 1 起并同步读入 s[i]，i 从 1 开始）
```

**⑤ 典型应用**

- 真题：力扣 1044 最长重复子串（题号真实；资料未覆盖，属补充）：二分答案长度 + 所有长度为 mid 的子串哈希判重，子串哈希 $O(1)$ 让总复杂度降到 $O(n \log n)$——[[二分]] 与本知识点的组合套路。
- 真题：P4391 [BOI2009] Radio Transmission（资料未覆盖，属补充）：$s$ 存在循环节等价于存在 $i$ 使 $s[1..i]$ 与 $s[n-p+1..n]$ 段匹配，子串哈希 $O(1)$ 判等，整体 $O(n)$。
- 迁移题（自编）：给定长串 $s$ 与 $q \le 10^5$ 次询问，每次问 $s[l_1..r_1]$ 与 $s[l_2..r_2]$ 是否相等。思路：预处理前缀哈希与幂次表，每次询问 $O(1)$ 比较两个 subHash；复杂度 $O(n + q)$。

**⑥ 坑点与边界**

> **【易错】** 子串公式漏乘 $b^{r-l+1}$：减法消不掉公共前缀的高位贡献，查出的值毫无意义（④坑 1）。

> **【易错】** $l=0$（0 起下标）时访问 hash[-1]：越界 RE。用 h[0]=0 空串哨兵 + 下标 1 起的口径规避（④坑 2）。

> **【注意】** 不取模时（自然溢出）子串哈希可能算出"负数位权"式的回绕差值：h[r] - h[l-1]*pw[...] 在 ull 下自动回绕成 mod 2^64 的正确余数，**不需要**额外处理，但若混用有符号类型就会错。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 两个预处理循环体零次执行，无查询（预期：空转结束，不崩）。
> 2. 单元素：n=1，查 (1,1) → h[1]=s[1]，subHash= h[1]-h[0]*pw[1] = s[1]（预期：单字符哈希=字符值）。
> 3. 全相同：s="aaaa"，查 (2,4)="aaa" → 97*(131^2+131+1)=1266407（预期：等比求和）。
> 4. 严格递增：查整个串 (1,n) → 返回 h[n]-h[0]*pw[n]=h[n]（预期：与直接算整串一致）。
> 5. 严格递减：查 (1,n-1) 与 (2,n) → 两段哈希不同（预期：数位组合不同，值必不同）。
> 6. 极值：n=1500 全 'z'，查 (1,1500) → 中间量在 ull 内回绕（mod 2^64），预期：返回值稳定可复现，int 版必错。

回扣开场：前缀哈希把"整串一个身份证"升级成"每个子串都能 $O(1)$ 报身份证号"，子串判等类问题有了 $O(n+q)$ 的解法。现在你能解决"海量子串比较"的问题了——接下来处理身份证号本身会撞车的隐患。

### 3. 降低冲突：自然溢出与双哈希

前置依赖：[[#1. 哈希思想与多项式哈希：把字符串看成一个 b 进制数]]、[[质数筛法]]（选取 $10^9$ 级质数做模数时的工具）
后续衔接：[[#4. 模板题 P3370：字符串去重实战]]；KMP（下一节课件预告内容，另一条不依赖哈希的子串匹配路线，文字锚定）

**① 它解决什么问题**

碰撞无法完全避免（S1 原话："冲突无法完全避免，只能尽可能的减少"），本知识点讲 S4-S5 给出的两条降冲突路线：（1）**将 b 和 M 尽量取大**——值域越大冲突越小，$M$ 最大可到 unsigned long long 的上限 $2^{64}$，利用 ull 溢出自动取余，这就是**自然取余法**；（2）**双 Hash 法**——用不同的 Base 和 MOD 哈希两次，把两个结果组成二元组作为总哈希，两个值都相等才判相等。复杂度代价：自然取余零额外开销；双哈希每次求值时间翻倍、存储翻倍，但换来的值域约为 $m_1 \cdot m_2 \approx 1.9 \times 10^7 \times 2.0 \times 10^7 \approx 3.7 \times 10^{14}$。

**② 直觉理解**

模型级类比：**双重门禁**。单哈希像大楼只查一张门禁卡——卡可以被伪造（构造碰撞）；双哈希是两道独立的门禁各查一张卡，伪造者必须同时骗过两套互不相关的系统。值域视角：单模数 $10^9$ 级时，按生日悖论约 $\sqrt{10^9} \approx 3 \times 10^4$ 个串就可能出现碰撞；双哈希值域 $3.7 \times 10^{14}$，碰撞门槛抬到约 $1.9 \times 10^7$ 个串，且两个模数独立，构造攻击需同时命中。

用具体数字跑一遍（取材自素材两版源码的常量）：自然取余版只有一个 $b=131$，模数隐式为 $2^{64}$；双哈希版用 $(b_1, m_1) = (131, 19260817)$ 与 $(b_2, m_2) = (101, 19660813)$，"abc" 在两组下分别是 $1677554 \bmod 19260817 = 1677554$ 与 $97 \cdot 101^2 + 98 \cdot 101 + 99 = 1002894$，判等时两对分量都要相等才算同串。

**③ 原理与推导**

自然溢出法（S4）：unsigned long long 的运算遵循 C++ 标准的模 $2^{64}$ 规则——值超过 $2^{64}-1$ 时自动回绕，等价于对 $2^{64}$ 取模，代码里**不用写任何取模**（素材自然取余版的 Has 就没有 % 号）。为什么这样可行：$2^{64}$ 值域足够大，随机数据下碰撞概率可忽略。

**为什么单哈希（自然取余）会被构造卡掉**——这是 S5 的原话结论（"可能产生冲突会被卡掉"），但资料未给构造，以下实验为补充（资料未覆盖，属补充，自编）：模数 $2^{64}$ 是 2 的幂，而 $b=131$ 是奇数，$b$ 在模 $2^{64}$ 下有强规律性。构造两组串：$S_0=$"a"、$T_0=$"b"，$S_{k+1} = S_k + T_k$、$T_{k+1} = T_k + S_k$（拼接）。记 $\Delta_k = H(S_k) - H(T_k)$，由哈希对拼接的线性性可得 $\Delta_{k+1} = \Delta_k \cdot (b^{2^k} - 1)$，于是 $\Delta_k = (97-98)\prod_{i<k}(b^{2^i}-1)$。每个因子 $b^{2^i}-1$ 至少含 $i+2$ 个 2 的幂次（数论结论 LTE，此处只引不证），累加到 $k=10$ 时 2 的幂次个数达 $2+3+\cdots+11 = 65 \ge 64$，所以长度 1024 的 $S_{10}$ 与 $T_{10}$ 在 mod $2^{64}$ 下**必然**同值。实测（附录 B-5）：两串不同，但哈希同为 249608652057172992——碰撞被构造出来了。双哈希在同一对串上两个模数都不撞。S5 对双哈希的结论："目前暂时没有办法卡掉这种写法（除了卡时间让它超时）"。

**④ 代码演示**

块一「核心代码」——取自素材 P3370--双哈希.cpp（改动：仅摘 Has、二元组与比较器；main 去重主流程见知识点 4）：

```cpp
typedef unsigned long long ull;
ull b1 = 131, b2 = 101;                  // 两组进制（S5：比最大字符大的质数/数）
ull m1 = 19260817, m2 = 19660813;        // 两组 10^9 级质数模数（S5 原样）
struct hashh {                           // 等价 C：struct hashh { ull x, y; }; struct hashh h[N];
    ull x, y;
} h[10005];
ull Has(char s[], ull b, ull m) {
    int l = strlen(s);
    ull sum = (ull)s[0];
    for (int i = 1; i < l; i++) {
        sum = ((sum * b) % m + (ull)s[i]) % m;   // 每步取模，防止 ull 溢出到 2^64 口径
    }
    return sum % m;
}
bool cmp(hashh& a, hashh& b) {           // 二元组字典序比较器（引用传参：等价 C 为指针传参）
    if (a.x == b.x) return a.y < b.y;
    return a.x < b.x;
}
```

**⑥ 坑点与边界**

> **【易错】** 自然溢出法写成有符号类型或有符号中间运算：溢出成为未定义行为而非回绕。自然溢出 = ull 全程无符号（④坑 1）。

> **【易错】** 双哈希比较漏分量（④坑 2）或两组 (b, m) 取值不独立（如两组只换了 b 没换 m）：强度大打折扣。两组参数各自独立选。

> **【注意】** S5 明说双哈希"暂时没办法卡掉（除了卡时间让它超时）"——它防的是**错解**，不防**超时**：哈希每次查询 $O(1)$ 的常数若被乘上大倍数（双哈希即翻倍），卡常类题要重新算总账。

### 4. 模板题 P3370：字符串去重实战

前置依赖：[[#1. 哈希思想与多项式哈希：把字符串看成一个 b 进制数]]、[[#3. 降低冲突：自然溢出与双哈希]]、[[枚举与模拟]]（排序后相邻扫描计数的套路）
后续衔接：KMP（S5 预告"下一节：KMP 算法"，后续批次产出，先文字锚定）、[[二分]]（哈希判等作为二分 check 的构件）

**① 它解决什么问题**

[P3370【模板】字符串哈希](https://www.luogu.com.cn/problem/P3370)（S5 给出链接）：给定 $n$ 个字符串，求互异的字符串个数。它是知识点 1、3 的直接组装：每串算一个哈希（知识点 1 的 Has），排序后相邻比较去重（计数套路）。总复杂度：$O(\sum |s_i|)$ 求哈希 + $O(n \log n)$ 排序（每对相邻比较 $O(1)$）。注：素材未抄录官方数据范围，以洛谷题面为准；素材源码按 h[10005]、char s[1505] 开数组，提示按 $n \le 10^4$、单串长 $\le 1500$ 量级准备（这一段我不确定，仅从数组规模反推）。

**② 直觉理解**

模型级类比：**点名册画正字**。把每个名字（字符串）换成学号（哈希值），学号排序后相同学号必然相邻，从头扫一遍、逢新号计一次数——这就是"排序去重"三板斧：替换、排序、扫一遍。

用具体数字跑一遍（官方样例，5 个串）：ab、aaaa、abab、ab、abc。算哈希（$b=131$，实测见附录 B-5）：ab=12805、aaaa=219742248、abab=219759410、ab=12805、abc=1677554。排序后 [12805, 12805, 1677554, 219742248, 219759410]，相邻去重得 4——与官方样例输出一致。

**③ 原理与推导**

推导"排序后为什么只需比较相邻"：排序把相等的值放进连续段，任意两个相等的哈希值之间不可能夹着别的值；所以从 i=2 起逐个看 `h[i] != h[i-1]` 就能数出互异值个数，不需要两两比较。**设计动机**：为什么不用两两比较——$O(n^2)$ 次 $O(1)$ 比较在 $n=10^4$ 时是 $10^8$，而排序路线是 $O(n \log n) \approx 1.3 \times 10^5$ 次，差三个数量级。ans 初值为 1（S4 源码原样）：至少有一个互异串，从第二个开始才有"是否与前一个相同"可判。

**④ 代码演示**

块一「核心代码」——取自素材 P3370--自然取余.cpp（改动：删去未使用的 include 与空行压缩，其余逻辑逐行原样；双哈希版仅换 Has 调用与比较器，见知识点 3④）：

```cpp
#include <iostream>
#include <cstdio>
#include <cstring>
#include <algorithm>
using namespace std;
typedef unsigned long long ull;
ull b = 131;
ull h[10005];
int n, ans;

ull Has(char s[]) {
    int l = strlen(s);
    ull sum = (ull)s[0];
    for (int i = 1; i < l; i++) sum = sum * b + (ull)s[i];   // 多项式递推（知识点 1）
    return sum;
}
int main() {
    cin >> n;
    char s[1505];
    for (int i = 1; i <= n; i++) {
        cin >> s;              // 等价 C：scanf("%s", s)
        h[i] = Has(s);
    }
    sort(h + 1, h + n + 1);    // 哈希值升序：等价 C 为 qsort 或手写排序
    ans = 1;                   // 至少一个互异串
    for (int i = 2; i <= n; i++) {
        if (h[i] != h[i-1]) ans++;
    }
    printf("%d\n", ans);
    return 0;
}
```

- 真题：P3370 本题（S5 链接）：实测官方样例输出 4（附录 B-5），自然取余版与双哈希版对拍一致（50 串随机集去重计数相同）。

**⑥ 坑点与边界**

> **【易错】** ans 初值写成 0：去重计数少 1（④坑 1）。计数起点是"第一个串必然互异"。

> **【易错】** sort 区间写错（h+n 而非 h+n+1）：最后一个元素未排序，末尾相邻比较失效（④坑 2）。

> **【注意】** 本题的"相等"是**哈希相等**，不是字符串相等：若数据针对 base=131 自然取余构造（知识点 3 的实验），自然取余版会把两个不同串数成 1 个——竞赛中可以先交自然取余版，被 hack 后换双哈希版。

> **边界数据集（先自己跑一遍，再展开对照）**

## 四、总结与自测

### 核心内容（一页纸速览）

- **字符串哈希**：多项式函数把串压成整数，$O(|s|)$ 求值、$O(1)$ 比较；值不同串必不同，值同串不一定同（S1）。
- **多项式哈希**：把串看成 $b$ 进制数对质数 $M$ 取模；$b$ 比最大字符大、数位不含 0（S2、S5）。
- **前缀哈希/滚动哈希**：$hash[i]=hash[i-1] \cdot base + s[i]$ 预处理 $O(n)$，子串 $h = hash[r] - hash[l-1] \cdot b^{r-l+1}$ 查询 $O(1)$（S3）。
- **自然取余法**：ull 溢出自动回绕 = mod $2^64$，零取模代码；但模数是 2 的幂，可被 Thue-Morse 型构造卡（S4、S5 + 自编实验）。
- **双哈希**：两组 (base, MOD) 各算一次、二元组判等，值域约 $3.7 \times 10^{14}$，S5 结论"暂时无法卡掉（除卡时间）"。
- **P3370 板子**：算哈希 → 排序 → 相邻去重计数，$O(\sum |s| + n \log n)$，官方样例输出 4（实测）。
