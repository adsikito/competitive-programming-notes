## 一、为什么需要它

先用会超时的方式做一遍 LC53 最大子数组：给定整数数组，求和最大的连续子数组。课件 slide 3 给出的暴力做法是"枚举起点和终点，计算区间内的和，取最大值"，时间复杂度 $O(n^2)$——外层枚举起点、内层累加终点。$n=10^5$ 时约 $10^{10}$ 次加法，必超时。**碰壁的根源：所有区间被一视同仁地枚举，没有利用"区间可以二分"的结构。**

分治的破法：任取中点，最大子数组要么在中点左边、要么在右边、要么横跨中点——slide 3 原话"分成 3 个独立的小问题"。左右两半是原问题的缩小版（递归），横跨部分用一趟扫描（贪心延伸）解决，总复杂度 $O(n \log n)$。这套"分解-解决-合并"的形状，与 [[二叉树竞赛篇]] 里"整棵树 = 左子树 + 右子树 + 根"的递归世界观一脉相承。

本篇讲 4 个知识点：分治三步、汉诺塔、LC53 分治解法、分治的复杂度。顺序理由：骨架（1）先于最纯实例（2），区间实战（3）收在复杂度总账（4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 分治三步：分解、解决、合并

前置依赖：[[二叉树竞赛篇]]（递归世界观：子结构与整结构同形）、[[复杂度分析与递归]]（调用栈如何承载递归）、递归语法（[[函数]] 篇）
后续衔接：[[#2. 汉诺塔：T(n)=2T(n-1)+1 与 2^n-1]]、[[#3. LC53 最大子数组的分治解法：跨中点合并]]

**① 它解决什么问题**

课件 slide 2 定义：分治（Divide and Conquer，"分而治之"）把一个复杂问题分成两个或更多相同或不相同的子问题，子问题相互独立、直到可以直接求解，原问题的解即子问题的解的**合并**——并注明这是**最优子结构性质**。三步骨架：**分解**（把规模 n 的问题切成同构的小问题）、**解决**（递归到可直接回答的出口）、**合并**（把子问题的解拼成原问题的解）。slide 2 同时划清界限：递归是一种编程技巧与思维方式，分治是基于递归解决更具体问题的算法思想。复杂度特征：分治的耗时 = 子问题耗时 + 合并耗时，具体账目在知识点 4 结算。

**② 直觉理解**

模型级类比：**公司拆项目**。一个大项目拆成两个子项目分给两组人（分解），组里再拆到"一个人能直接干完"为止（解决），最后把各组成果拼装交付（合并）——拆分方式决定拼装难度，拆得整齐拼装就便宜。用具体数字跑一遍（slide 1-2 的汉诺塔前两步）：n=1 时直接把盘子从 A 放到 C（出口）；n=2 时设上面的盘子是甲、下面是乙：甲 A→B（借 C），乙 A→C（直达），甲 B→C（借 A）——三步完成。n=3 被拆成"两个 n=2 的问题 + 移动一次乙"，这正是三步骨架的具体形状。

**③ 原理与推导**

为什么拆出来的子问题必须与原问题**同构**？因为递归调用的是同一个函数——只有输入规模更小、形状与原问题完全一致，才能原样调用自己；形状稍不同就要写第二个函数，递归结构就散了。为什么必须有**递归出口**（slide 1"找全递归终止条件"）？没有出口的递归无限自我调用，调用栈层层增长直到栈溢出 RE——出口必须覆盖所有"不能再拆"的情形。为什么强调子问题**相互独立**（slide 2 原话）？若两个子问题共享需要协调的状态，合并时就要处理互相干扰，"解的合并"不再是无脑拼接——LC53 能分治，靠的是 slide 3"横跨中点的最大区间要么在左、要么在右、要么横跨"这个**互斥且完备**的三分。理解递归代码的工具是 slide 1 给出的"画递归调用图/递归树"：每行调用一层、每次展开一个结点，[[复杂度分析与递归]] 篇的调用栈视角同样适用。

**④ 代码演示**

块一「核心代码」，取自源文件 LC面试题08.06. 汉诺塔问题.cpp（改动：仅省略头文件与 main，逻辑逐行原样；C 等价：`vector<int>& s` ↔ `int s[]; int* top_s` 的引用传参）：

```cpp
void move(int x, vector<int>& s, vector<int>& e, vector<int>& h) {
    // x 个盘子：从柱 s 出发，e 是目标柱，h 是媒介柱
    if (x == 1) {                    // 出口：1 个盘子直接走
        int d = s.back();            // 取柱顶盘子（C 等价：d = s[top_s-1]; top_s--;）
        s.pop_back();
        e.push_back(d);              // 复杂度：O(1)
        return;
    }
    move(x - 1, s, h, e);            // 分解一：上面 x-1 个盘子 s 借 e 到 h
    int d = s.back();                // 解决：最下面的盘子直达
    s.pop_back();
    e.push_back(d);
    move(x - 1, h, e, s);            // 合并前半：x-1 个盘子从 h 借 s 回到 e
}
```

逐段讲：出口管 x==1；x>1 时"上面一大摞"被当作一个整体（slide 2：把上面 n-1 个盘子看成一个盘子甲，第 n 个盘子是乙），甲先让路、乙直达、甲再跟上——两次递归调用就是两次分解。

块二「执行追踪表」（move(2, A, C, B)：2 个盘子从 A 到 C，B 作媒介；A=[甲,乙] 乙在顶）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | move(2,A,C,B) | x>1，递归 move(1,A,B,C) | 甲 A→B | A=[乙], B=[甲] |
| 2 | move(1,A,B,C) | x==1，出口触发 | 乙 A→C | A=[], C=[乙] |
| 3 | 回到 move(2) | 递归 move(1,B,C,A) 后全部返回 | 甲 B→C | C=[甲,乙]，共 3 次移动 |

块三「错误写法对照」：

```diff
- void move(int x, ...) {            // 坑1：漏写 x==1 的递归出口——每次调用继续拆 x-1、x-2……
-     move(x - 1, s, h, e);          // 到 x==0 后仍继续，无限自我调用直到栈溢出（RE/死循环）
- }
+ if (x == 1) { ...; return; }       // 出口必须先写，且覆盖所有不可再拆的情形
- move(x - 1, s, e, h);              // 坑2：递归时把目标柱与媒介柱写反——x-1 个盘子被"搬到"目标柱，
+ move(x - 1, s, h, e);              // 最下面的盘子再上来时已无路可走，移动序列全错（答案错）
```

**⑤ 典型应用**

- 真题：LC 面试题 08.06 汉诺塔问题（slide 1 例题链接，注：原题要求用栈，课件改为递归实现），完整程序见知识点 2。
- 迁移题：n 个元素归并排序——分解成两半各自排好（递归），合并时两指针归并（合并步）。建议先独立做，再对照题解：出口是区间长 ≤1；合并是 $O(n)$ 扫描；总复杂度 $O(n\log n)$ 由知识点 4 的账目给出（自编，经典模型；LC53 真题详解见知识点 3）。

**⑥ 坑点与边界**

> **【易错】** 漏写递归出口或出口不全。后果是无限递归栈溢出 RE；写出口时自问"所有不能拆的情形都列了吗"，x==0 与 x==1 是两种情形（④对照坑 1）。

> **【注意】** 递归调用的三个柱子参数各就各位：`(s, h, e)` 与 `(s, e, h)` 一字之差语义全变——写递归前把每个参数的"身份"注释在函数头，是防错的最低成本手段（④对照坑 2）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：x=0 → 出口不含 x==0，会继续拆到负数——若题面可能给 0，出口须扩成 x<=1（预期：暴露出口不全）。
> 2. 单元素：x=1 → 出口直接移动 1 次（预期：1 次移动，正确）。
> 3. 全相同：三个柱子名传重复（如 h=e）→ 移动退化为自移，结果错（预期：暴露参数检查缺失）。
> 4. 严格递增：盘子编号 1..n 底大顶小 → 正常移动序列（预期：2^n-1 次，见知识点 2）。
> 5. 严格递减：底小顶大的非法塔 → 算法不检查大小照样"移动"（预期：算法不管合法性，合法性由题面保证）。
> 6. 极值：x=30 → 移动次数 $2^{30}-1$ 约 $10^9$，程序要跑很久；x=64（传说中世界末日的塔）在竞赛时间尺度内不可完成（预期：识别指数复杂度的实际含义，见知识点 4）。

### 2. 汉诺塔：T(n)=2T(n-1)+1 与 2^n-1

前置依赖：[[#1. 分治三步：分解、解决、合并]]、[[函数]]（篇内已有 hanoi 递归与断言可参考）
后续衔接：[[#4. 分治的复杂度：递归树与主定理]]、[[二叉树竞赛篇]]（调用树形状同源）

**① 它解决什么问题**

洛谷/力扣汉诺塔（slide 1 例题，LC 面试题 08.06）：n 个盘子从 A 移到 C，每次移一个、大盘不压小盘，B 可作媒介，求移动方案。关键性质：移动次数满足递推 $T(n) = 2T(n-1) + 1$，解为 $T(n) = 2^n - 1$；单次移动 $O(1)$，总复杂度 $O(2^n)$——指数级，n 到 30 量级就跑不动了，这本身是复杂度意识的活教材。为什么这个古老问题值得做？它是"分治三步"形状最纯的实例：没有任何多余逻辑，三步就是全部。

**② 直觉理解**

模型级类比：**搬家先挪小件**。最大的家具最后进门——想让最大的盘子（乙）从 A 直达 C，必须先让上面 n-1 个盘子（甲）全部离开 A、又不能挡住 C，所以甲只能整体先搬到 B；乙到位后，甲还得从 B 整体搬到 C。"整体搬 n-1 个盘子"和原问题一模一样，只是柱子角色换了个座次。

用具体数字推演（slide 1-2 的原始推导）：n=1，直接 A→C，1 步；n=2，甲 A→B、乙 A→C、甲 B→C，3 步；n=3 = 搬甲（2 盘子问题）+ 乙 1 步 + 搬甲（2 盘子问题）= 3+1+3 = 7 步。每加一个盘子，步数翻倍再加一。

**③ 原理与推导**

递推式：把"上面 n-1 个盘子"看作整体甲（slide 2 原话），三步分别是 $T(n-1)$、$1$、$T(n-1)$，故 $T(n) = 2T(n-1) + 1$，$T(1)=1$。解递推：两边加 1 得 $T(n)+1 = 2(T(n-1)+1)$，令 $S(n) = T(n)+1$，则 $S(n) = 2S(n-1)$、$S(1) = 2$——等比数列，$S(n) = 2^n$，所以 $T(n) = 2^n - 1$。归纳验证：$T(1)=1=2^1-1$；若 $T(n-1)=2^{n-1}-1$，则 $T(n)=2(2^{n-1}-1)+1=2^n-1$，成立。为什么递归解法"敢"直接给出移动方案而不搜索（设计动机）？因为它不猜路径，而是用同构性构造路径——n-1 个盘子的合法搬法存在（归纳假设），照搬即可；这是分治与暴力搜索的分野。为什么移动次数下界也是 $2^n-1$？最大盘子要动，上面 n-1 个必须先全部挪开（至少 $T(n-1)$ 步）、动完还得挪回（再 $T(n-1)$ 步），加自己 1 步——递推式同时是下界。这一段"下界论证"我不确定课件是否要求掌握，按通识补充。

**④ 代码演示**

块一「核心代码」，取自源文件 LC面试题08.06. 汉诺塔问题.cpp 中被注释保留的**展示版**（改动：把打印 `cout<<d<<' '<<s1<<"--->"<<e1` 原样启用，其余逐行原样）：

        int d = s.back();

### 3. LC53 最大子数组的分治解法：跨中点合并

前置依赖：[[#1. 分治三步：分解、解决、合并]]、[[#2. 汉诺塔：T(n)=2T(n-1)+1 与 2^n-1]]（递归手感）
后续衔接：[[线性DP]]（slide 3 给出的 $O(n)$ 解法，同批文字锚定）、[[#4. 分治的复杂度：递归树与主定理]]

**① 它解决什么问题**

LC53 最大子数组：整数数组（含负数）中找和最大的连续子数组，返回最大和。slide 3 给出三解账目：暴力 $O(n^2)$、分治 $O(n\log n)$、线性 DP $O(n)$。本节讲分治解法：取中点 m，最大区间**要么在左半、要么在右半、要么横跨中点**（slide 3 原话"分成 3 个独立的小问题"）；左右两半递归，横跨部分从中心向两侧延伸一趟扫描求出（slide 3："贪心求解——从中心点往左右两边延伸"）。关键性质：横跨合并 $O(r-l)$，总复杂度 $O(n \log n)$。

**② 直觉理解**

模型级类比：**找最长的顺路队伍**。把队伍从中点斩成两段，最长的一段队伍只有三种可能：整段在左、整段在右、或者骑在切缝上。前两种是缩小版的原问题；第三种的关键观察是——骑缝区间必含中点两侧紧邻的元素，所以它 = "从中点向左延伸的最优段 + 向右延伸的最优段"，两段各自独立、可以一趟扫出。

用具体数字跑一遍（自造 [4,-1,2]，断言实测 5）：中点 m=1。左半 [4,-1]：内部最大 4；右半 [2]：最大 2；横跨：向左延伸 i=1 得 -1、i=0 得 4-1=3，取 lmax=3；向右延伸得 rmax=2；横跨 = 3+2 = 5。三者取最大得 5，对应区间 [4,-1,2] 整段。

**③ 原理与推导**

为什么"三选一"划分是完备的？任一区间 [i,j] 与中点 m 的位置关系只有三种：j ≤ m、i > m、i ≤ m < j——即全在左、全在右、横跨。互斥（三类不重叠）且完备（没有第四种），所以三者最大值就是全区间答案。slide 3 正是这个论证。

为什么横跨部分能独立地"左右各自取最优"？横跨区间必含 m 与 m+1，其和 = 左半尾巴之和 + 右半头之和；左尾巴的起点 i 越优只影响左半部分，右半同理——两侧互不约束，可以分别独立取最大（slide 3 的 lmax、rmax）。**设计动机**：lmax 的扫描方向必须从 m 往左、rmax 从 m+1 往右——因为横跨区间的两端是被"含 m / 含 m+1"钉死的，自由的只有外端点。

与贪心/DP 解法的关系（slide 3 同页给出 DP 解）：`dp[i] = max(dp[i-1]+nums[i], nums[i])`，以第 i 个元素结尾的最大子数组和，答案 $\max dp[i]$，$O(n)$。分治胜在"教结构"，DP 胜在更快；竞赛遇到本题直接写 DP，分治的价值在可迁移的横跨合并思想（详见 [[线性DP]]）。

**④ 代码演示**

块一「核心代码」，取自源文件 LC53.cpp（改动：仅省略头文件与 main，逻辑逐行原样）：

```cpp
int maxxmid(vector<int>& nums, int l, int mid, int r) {
    int lmax = INT_MIN, sum = 0;
    for (int i = mid; i >= l; i--) {       // 从中点向左延伸
        sum += nums[i];
        lmax = max(lmax, sum);             // 复杂度：O(mid-l+1)
    }
    int rmax = INT_MIN; sum = 0;
    for (int i = mid + 1; i <= r; i++) {   // 从 mid+1 向右延伸
        sum += nums[i];
        rmax = max(rmax, sum);
    }
    return lmax + rmax;                    // 横跨最优 = 左最优 + 右最优
}
int maxxans(vector<int>& nums, int l, int r) {
    if (l == r) return nums[l];            // 出口：单元素区间
    int mid = (l + r) / 2;
    int a1 = maxxans(nums, l, mid);        // 左半递归
    int a2 = maxxans(nums, mid + 1, r);    // 右半递归
    int a3 = maxxmid(nums, l, mid, r);     // 横跨合并
    return max(max(a1, a2), a3);
}
```

逐段讲：出口是单元素（不可再拆）；两个递归是分解；maxxmid 是合并。注意 lmax 初值 INT_MIN 而非 0——子数组不能是空的，全负数组时"不选任何元素"不是合法答案。

块二「执行追踪表」（输入 [4,-1,2]，即 nums=[4,-1,2]，调用 maxxans(0,2)，断言实测 5，附录 B-5）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | maxxans(0,2) | mid=1，三个子问题 | 先递归左 maxxans(0,1) | 挂起 |
| 2 | maxxans(0,1) | mid=0 | 左=4、右=-1、横跨=4+(-1)=3 | 左半返回 4 |
| 3 | maxxans(2,2) | 出口 | 单元素 | 返回 2 |
| 4 | maxxmid(0,1,2) | lmax 扫描 | i=1 得 -1，i=0 得 3 | lmax=3 |
| 5 | maxxmid(0,1,2) | rmax 扫描后汇合 | i=2 得 2，a3=3+2=5 | max(4,2,5)=5 |

块三「错误写法对照」：

**⑤ 典型应用**

- 真题：LC53 最大子数组（slide 3 + LC53.cpp），官方样例 [-2,1,-3,4,-1,2,1,-5,4] 实测输出 6（附录 B-5）。
- 迁移题：归并排序求逆元对数（P1908，题号真实，资料未覆盖，属补充）——同一"横跨合并"骨架：左右各自数逆对，合并时数跨越中点的逆对；再进一步可求最大子数组的**区间端点**：在分治三处各带上区间信息一并返回，横跨端点由 lmax/rmax 的 argmax 位置决定（自编，无素材源码）。

**⑥ 坑点与边界**

> **【易错】** lmax/rmax 初值写 0。全负数组的正确答案是最大的单个负数，初值 0 会返回"空数组"的 0（④对照坑 1）。

### 4. 分治的复杂度：递归树与主定理

前置依赖：[[#2. 汉诺塔：T(n)=2T(n-1)+1 与 2^n-1]]、[[#3. LC53 最大子数组的分治解法：跨中点合并]]、[[复杂度分析与递归]]（大 O 记号）
后续衔接：[[二叉树竞赛篇]]（递归树与树遍历同构）、归并排序/快速排序（延伸方向，待产出先文字锚定）

**① 它解决什么问题**

本节回答一个统一问题：给定分治递推式 $T(n) = a \cdot T(n/b) + f(n)$——n 规模的问题拆成 a 个规模 n/b 的子问题，合并花 $f(n)$——总复杂度是多少？前三个知识点的账都能用它结清：汉诺塔 $T(n)=2T(n-1)+1$ 是"规模只减 1"的退化型，解 $2^n-1$；LC53 是 $T(n)=2T(n/2)+O(n)$ 型，解 $O(n\log n)$。关键性质：递推式的三个参数 a、b、f(n) 的相对大小决定答案，判据就是递归树逐层算账。

**② 直觉理解**

模型级类比：**金字塔工程结算**。总工时 = 各层工时之和：第一层 1 个老板花 $f(n)$；第二层 a 个工头各管 n/b、共花 $a \cdot f(n/b)$；层层往下，每层人数乘 a、单人工作量除以 b（规模缩小）。层数是 n 降到出口的深度——规模每次除 b，约 $\log_b n$ 层，总账 = 逐层求和，**谁占大头听谁的**。用具体数字跑一遍（LC53 型，a=2、b=2、f(n)=n）：第 0 层 1 个结点花 n；第 1 层 2 个各花 n/2，合计 n；第 2 层 4 个各花 n/4，合计 n……每层总工时都是 n，共 $\log_2 n$ 层，总计 $O(n\log n)$。对照汉诺塔型（规模减 1 不减半）：第 k 层结点数 $2^k$，共 $1+2+\cdots+2^n = 2^{n+1}-1$ 个结点，指数爆炸——**减半与减一，天壤之别**。

**③ 原理与推导**

递归树逐层求和的通用推导：深度 $\log_b n$ 层（规模 n 除 b 到出口需 $\log_b n$ 次），第 i 层有 $a^i$ 个结点、每结点工作量 $f(n/b^i)$，第 i 层合计 $a^i f(n/b^i)$。三类典型情形：叶层主导（如 $f$ 很小、$a$ 大）总和被最深层 $a^{\log_b n} = n^{\log_b a}$ 决定；根层主导（如 $f(n)=n^k$ 且 k 大）总和是等比级数、约 $f(n)$ 量级；每层均摊（$f(n)=n$、a=b）就是 $O(n\log n)$。**主定理**把这三类写成一条判据（延伸，非必需：竞赛手算递归树足够，公式与证明见 [[复杂度分析与递归]] 及任一算法教材；课件未覆盖，属补充）。**设计动机**：为什么复杂度分析偏爱"每层合计"而不是"单个结点耗时"？因为分治树的结点数是指数级的，逐结点加总没法算，而"层"恰好把指数个结点聚成一个可控的量——这是递归树方法的全部巧思。为什么汉诺塔不能套 $T(n/b)$ 公式？它每层只减 1 不除 b，层数是 n 不是 $\log n$——公式有适用域，套错域就得出荒谬结论。

**④ 代码演示**

块一「核心代码」（自编：汉诺塔计数版，只数移动次数不搬盘子，对应递推 $T(n)=2T(n-1)+1$）：

```cpp
long long moveCount(int n) {
    if (n == 1) return 1;              // 出口：T(1)=1
    return 2 * moveCount(n - 1) + 1;   // 递推：T(n)=2T(n-1)+1，复杂度 O(2^n)（C 等价：int 递归函数同形）
}
// 断言程序验证：n=1..20 时 moveCount(n) == 2^n - 1 全部成立（附录 B-5）
```

逐段讲：这函数没有"搬运"动作，是纯账本——它本身就是递推式的一行代码化；调用树恰好 $2^n-1$ 个结点，树即复杂度。

块二「执行追踪表」（moveCount(3)，调用树逐层展开）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | moveCount(3) | 拆 2 个子调用 +1 | 先进 moveCount(2) | 挂起 |
| 2 | moveCount(2) | 再拆 +1 | 先进 moveCount(1) | 挂起 |
| 3 | moveCount(1) | 出口 | 返回 1 | 回溯 |
| 4 | 回溯两层 | moveCount(2) 返回 2×1+1=3；moveCount(3) 返回 2×3+1=7 | — | $2^3-1$ 验证通过 |

**⑤ 典型应用**

- 真题：LC53 的账——$T(n)=2T(n/2)+O(n)$ 递归树每层 n、共 $\log_2 n$ 层，$O(n\log n)$（slide 3 给出该结论）。
- 迁移题：估算"每次拆成 4 份、合并 $O(n)$"的复杂度。建议先独立做，再对照题解：第 i 层合计 $4^i \cdot n/2^{2i} = n$，每层 n、$\log_2 n$ 层，仍 $O(n\log n)$；进一步可研究 P1257 平面上最接近点对，同一款账目、横跨合并是难点（题号真实，资料未覆盖，属补充，延伸非必需）。

**⑥ 坑点与边界**

> **【易错】** "分治 = 快"的条件反射。快慢由递推式决定：规模减半且合并便宜才快；规模只减 1（汉诺塔）就是指数。先写递推式，再下结论（④对照坑 1）。另外 $T(n)=2T(n-1)+1$ 的账不能套 $T(n/b)$ 公式——公式有适用域（规模按比例缩小），越域套公式是本节最隐蔽的错误。

> [!example]-
> **边界数据集（moveCount 程序）**
> 1. 空输入：n=0 → 出口不含，递归到负数（预期：暴露出口盲区，与知识点 1 同坑）。
> 2. 单元素：n=1 → 返回 1（预期：$2^1-1$）。
> 3. 全相同：重复调用 moveCount(1) → 每次独立返回 1（预期：无状态残留）。
> 4. 严格递增：n=1..20 逐个验证 → 全部等于 $2^n-1$（预期：断言程序第 4 组实测通过）。
> 5. 严格递减：先算 moveCount(20) 再算 moveCount(5) → 各自独立正确（预期：递归无记忆，重复计算不串）。
> 6. 极值：n=62 → $2^{62}-1$ 仍在 long long 范围（约 $4.6\times10^{18}$）；n=63 起溢出（预期：long long 上限意识）。

## 四、总结与自测

### 核心内容（一页纸速览）

- **分治三步**：分解（切成同构子问题）、解决（递归到出口）、合并（拼回原解）；前提是最优子结构与子问题独立（slide 2）。
- **汉诺塔**：$T(n)=2T(n-1)+1$，解 $2^n-1$；n=3 共 7 步，序列 `1 a--->c, 2 a--->b, 1 c--->b, 3 a--->c, 1 b--->a, 2 b--->c, 1 a--->c`。
- **LC53 分治**：中点三选一（左/右/横跨），横跨 = 从 mid 向左最优 + 从 mid+1 向右最优，$O(n\log n)$；DP 解 $O(n)$ 见 [[线性DP]]。
- **分治复杂度**：$T(n)=aT(n/b)+f(n)$ 递归树逐层求和；减半型 $O(n\log n)$、减一型指数；出口先写、参数身份先注释、初值按语义、候选必须齐。
