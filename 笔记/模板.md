## 一、为什么需要它

课件开场原话（22 模板.pdf p7）："想象一下，如果现在让你实现交换两个数的值（没说是整数还是小数），如何实现？"你学过 [[面向对象编程]] 的函数重载：写 `Swap(int&, int&)` 一份、`Swap(double&, int&)` 一份——p8 课件指出这条路的问题："重载的多个函数仅仅只是类型不同，代码的复用率比较低，只要出现新的类型需要交换，就需要新增对应的重载函数"。三份、五份、十份一模一样只换类型的代码，就是模板要消灭的重复。

p4 概述同时给出定位："STL 的各种组件也是基于模板的。所以，无论是写程序还是读程序，都有必要了解一下 C++ 的模板。"本篇讲 4 个知识点：函数模板、实例化、类模板与别名、竞赛模板代码的含义。顺序理由：动机（1）先于机制（2），机制先于类的扩展（3），最后落到竞赛定位（4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 函数模板：为什么要模板

前置依赖：[[函数]]（重载）、[[面向对象编程]]（引用传参）
后续衔接：[[#2. 实例化：编译器推演与类型匹配]]、[[#3. 类模板一句话与模板别名]]

**① 它解决什么问题**

函数模板是"**带类型参数的函数图纸**"：写一次逻辑，类型 T 留空，编译器按用到的实参类型自动生成对应版本。它解决的问题就是 p7-8 那三份重复的 Swap——int 一份、double 一份、再来个 string 还得加一份。关键性质：语法 `template<typename T>`（`class` 与 `typename` 完全等价，p5 原话）；模板本身**不是函数**，是编译器生成函数的模具（p10 原话）；一份模板代码在源码里只存在一份，生成的具体函数按需各一份。**复杂度**：不改变运行时复杂度，改变的是**源码行数**——N 种类型从 N 份代码变 1 份，修改逻辑只改一处。

**② 直觉理解**

模型级类比：**饼干模具**。一副模具（模板）压出一块块饼干（具体函数），面团用草莓味的（int）还是巧克力味的（double），模具本身不变——压出来的饼干形状相同、口味各异。模具不花面粉，只有"压"的动作（实例化）才产出饼干；没人用，模具就闲着，一行机器码都不生成。

用具体数字跑一遍（p13 素材案例）：`change(a, b)`，a=100、b=200——编译器看实参是 int，把 T 定成 int，生成 `void change(int&, int&)`，交换后输出 `200 100`；`change(c, d)`，c=1.112、d=23.12——生成 double 版，输出 `23.12 1.112`。两份源码、一次编写（实测一致，附录 B-5）。

**③ 原理与推导**

推导"模板为什么不算函数"：普通函数在源码里写一次、编译后地址固定；模板在编译前只是**图纸**——p10 原话"编译器需要根据传入的实参类型来推演生成对应类型的函数以供调用，彼此的地址也是不同的"。也就是说 `change<int>` 与 `change<double>` 是两个不同的函数、两个不同的地址（实测断言通过，附录 B-5）。

**设计动机**：p10 一句话点破——"模板就是将本来应该让程序员做的重复的事情交给了编译器"。人只维护逻辑，类型复制的体力活由编译器在编译期完成；这和 [[面向对象编程]] 里"构造函数自动初始化"是同一种思路：**把机械、易错、重复的步骤自动化**。

**④ 代码演示**

**块一·核心代码**（取自课堂代码 mycode.cpp 的 change 与 test02；改动：修正原文件的输出笔误——原句 `cout << "v1 = " << v2` 把 v1 打成了 v2，见 A-3 登记 3）：

```cpp
#include <iostream>
using namespace std;
template<typename T>          // 模板参数声明：T 是类型占位符
void change(T& x, T& y) {     // 或者 template<class T>，完全等价
    T temp = x;               // 临时变量的类型也跟着 T 走
    x = y;
    y = temp;
}
int main() {
    int v1 = 100, v2 = 200;
    cout << "v1 = " << v1 << "  v2 = " << v2 << endl;
    change(v1, v2);           // T 推演为 int
    cout << "v1 = " << v1 << "  v2 = " << v2 << endl;
    double v3 = 1.1, v4 = 2.2;
    cout << "v3 = " << v3 << "  v4 = " << v4 << endl;
    change(v3, v4);           // T 推演为 double：同一份源码
    cout << "v3 = " << v3 << "  v4 = " << v4 << endl;
    return 0;
}
```

实测输出 200/100 与 2.2/1.1 两组交换结果（附录 B-5）。

**块二·执行追踪表**（change(v1, v2) 的编译期与运行期两段）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 编译期 | 源码只有模板 | 实参 int 推演 T | 生成 change(int&,int&) |
| 2 | 编译期 | 同上 | 实参 double 推演 T | 再生成 change(double&,double&) |
| 3 | 运行期 | v1=100, v2=200 | temp=x | temp=100 |
| 4 | 运行期 | 同上 | x=y | v1=200 |
| 5 | 运行期 | 同上 | y=temp | v2=100，交换完成 |

**块三·错误写法对照**：

```diff
- void change(T& x, T& y) { ... }      // 坑1：没写 template<typename T> 声明行，T 无人认识 → 编译错误
+ template<typename T>                  // 声明行紧贴函数，缺一不可
- void Swap(T& x, T& y) { T t; }        // 坑2：模板参数声明后写成了普通函数签名 Swap（非 T）→ 形参类型未定义
+ 函数名与形参里至少要用到 T，否则模板毫无意义
- int n = 1, d2 = 2.5; change(n, d2);   // 坑3：两个实参类型不同，单一 T 推演矛盾 → 编译错误"no matching function"（实测 exit=1）
+ 见知识点 2：双模板参数或显式转换
```

**⑤ 典型应用**

- 素材练习（p21-22）：mathHelper 求数组的最大/最小/均值，int、double 数组各测一次——实测输出 `Max=9, min=1, 均值3.8` 与 `Max=5.5, min=1.1, 均值3.24`（附录 B-5）；素材代码缺陷见 A-3 登记 4。
- 素材案例（p13 change 案例与 p11 add 案例）：本知识点与知识点 2 的主线。
- 迁移题（自编）：写函数模板 `T myMax(T a, T b)` 返回较大值，用 int 与 string 各测一次。建议先独立做，再对照题解：与 change 同构，只换逻辑为比较。
- 竞赛衔接：[[排序]] 里用的 `sort`、`swap`、`max` 全是函数模板——你现在知道它们的 `template<typename T>` 头是什么了。

**⑥ 坑点与边界**

> **【易错】** 忘写 `template<typename T>` 声明行（④对照坑 1）——T 变成未声明标识符，编译错误在函数签名处。

> **【注意】** 模板声明与使用通常要在同一文件（模板在实例化点才生成代码，分文件编译会报链接错误——竞赛单文件写法天然规避）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用：语言机制（预期：不涉及）。
> 2. 单元素：交换两个相等值 change(x, x) → 值不变（预期：temp 自赋无害）。
> 3. 全相同：int 版与 double 版连续调用同一模板 → 两个地址、各自正确（预期：互不干扰）。
> 4. 严格递增：交换 (1,2)、(1.5,2.5)、('a','b') → 三种 T 各生成一份（预期：源码一份，实例三份）。
> 5. 严格递减：交换后再交换 → 恢复原值（预期：交换的逆是自身）。
> 6. 极值：交换 INT_MAX 与 INT_MIN → 交换本身不溢出（只搬动字节），但后续加减会溢出（预期：模板不引入新溢出，溢出责任在使用者）。

回扣开场：现在你能把三份 Swap 压成一份了——一副模具（③的原理）。但模具什么时候压、按什么类型压？下一节拆实例化。

### 2. 实例化：编译器推演与类型匹配

前置依赖：[[#1. 函数模板：为什么要模板]]
后续衔接：[[#3. 类模板一句话与模板别名]]、[[#4. 竞赛模板代码的含义：读得懂即可（延伸）]]

**① 它解决什么问题**

用具体类型的实参使用模板，就叫**实例化**（p11 原话）。分两路：**隐式实例化**——编译器根据实参类型自己推演 T；**显式实例化**——`MathHelper<int>(a, n)` 手动把 T 点名（素材练习的写法）。本知识点核心规则只有一条（p11 注释原话）："在模板中，编译器一般不会进行类型转换操作"——`add(n1, d2)`（int 配 double）对单一 T 的模板是编译错误，不是"自动转成 double"。

**② 直觉理解**

用具体数字推演（p11 素材数据）：`add(n1, n2)`，n1=100、n2=200 都是 int → T 推演为 int，得 300；`add(d1, d2)` 都是 double → 得 3.57；`add(n1, d2)` 一个 int 一个 double → 推演卡住（T 该是 int 还是 double？），实测编译失败 `no matching function for call to 'add(int&, double&)'`，退出码 1（附录 B-5）。**为什么编译器不帮着转换**：设计动机是推演发生在"类型确定"阶段，转换规则一旦介入会产生歧义（转 int 还是转 double？精度谁说了算）——C++ 的选择是把决定权还给程序员，宁可报错。

**③ 原理与推导**

双参数解法推导（p12 原式）：`template<class T, class H> T add(T& v1, H& v2)`——让两个形参各占一个类型坑位，混合调用推演为 T=int、H=double，编译通过；**返回类型取 T**，所以 `add2(n1, d2)` 结果按 int 截断为 102（实测，附录 B-5）——返回谁的类型要自己心里有数，模板不做善后。**为什么返回类型跟 T 不跟 H**：模板签名里返回类型写在最前，它自己也可以是独立参数（三个类型坑），素材为简单起见让返回值复用 T；工程写法常把返回类型显式指明或单独参数化。

**④ 代码演示**

**块一·核心代码**（取自课堂代码 mycode.cpp 的 add/add2 与 test01；改动：补注释，逻辑原样）：

```cpp
#include <iostream>
using namespace std;
template<class T>
T add(T& v1, T& v2) {              // 单参数版：两实参必须同类型
    return v1 + v2;
}
template<typename T, class H>
T add2(T& v1, H& v2) {             // 双参数版（p12 解法）：混合类型可行
    return v1 + v2;                // 注意：返回类型是 T，按 T 截断
}
int main() {
    int n1 = 100, n2 = 200;
    cout << add(n1, n2) << endl;            // 300：T=int
    double d1 = 1.234, d2 = 2.343;
    cout << add(d1, d2) << endl;            // 3.577：T=double
    double d4 = add2(n1, d2);               // T=int, H=double
    cout << d4 << endl;                     // 102.5 存进 double 前先按 int 截断为 102
    // cout << add(n1, d2) << endl;         // 错：单参数版混合类型，编译失败（实测 exit=1）
    return 0;
}
```

**块二·执行追踪表**（add2(n1, d2)，n1=100、d2=2.5）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 编译期 | 模板 add2<T,H> | 实参 int, double | T=int, H=double |
| 2 | 运行期 | 实例 add2<int,double> | v1 + v2 | 102.5（double 中间值） |
| 3 | 返回 | 返回类型 T=int | double 转 int 截断 | 返回 102 |
| 4 | main 接收 | 存入 double d4 | 102 再升回 double | 输出 102 |

**块三·错误写法对照**：

```diff
- double d4 = add(n1, d2);        // 坑1：指望编译器把 int 转成 double → 编译错误"no matching function"（实测）
+ double d4 = add2(n1, d2);       // 双参数版，或手动 add(double(n1), d2) 显式转换
- template<class T> T add(T& v1, H& v2) { ... }   // 坑2：H 没在 template 行声明就用 → 编译错误（未声明的模板参数）
+ template<typename T, class H>   // 每个类型坑位都要声明
- int r = add2(d1, d2);           // 坑3：T 推演为 double、返回 double，赋给 int 静默截断（无警告的语义陷阱）
+ 返回类型心里有数：需要精确值就显式指明返回类型或换参数顺序
```

**⑤ 典型应用**

- 素材练习（p22 写法）：`MathHelper<int>(a, sizeof(a)/sizeof(a[0]))`——显式实例化的直接示范，T 被点名、编译器不再推演。
- 迁移题（自编）：把 myMax 改成双参数版 `template<class T, class H> T myMax(T a, H b)`，用 (3, 2.9) 测试并预测返回值。建议先独立做，再对照题解：T=int，返回 int 的 3。
- 竞赛衔接：`sort(v.begin(), v.end())` 的元素类型由容器推演（隐式实例化日常形态）；显式点名则见 `sort<int*>(...)` 这类罕见写法——读懂即可。

**⑥ 坑点与边界**

> **【易错】** 混合类型调单参数模板（④对照坑 1）——报错信息长而难读，记住根因"模板不做类型转换"就能秒判。

> **【注意】** 隐式推演对"只看返回值定 T"无能为力：`double r = add(1, 2)` 推演的还是 T=int（返回值不参与推演），先截断再赋值——别指望返回类型帮你挑版本。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用（预期：不涉及）。
> 2. 单元素：add2 与单元素数组 → 推演规则与数组长度无关（预期：规则不变形）。
> 3. 全相同：两实参恒同类型 → 单参数版永远够用（预期：双参数版在此退化为单参数版）。
> 4. 严格递增：(1,2)、(1,2.5)、(1.5,2)、(1.5,2.5) → 同同/同混/混同/混混四类（预期：单参版只吃第一与第四，双参版全吃）。
> 5. 严格递减：调换实参顺序 → T、H 对调，返回类型跟着变（预期：add2(2.5, 1) 返回 double 的 3.5）。
> 6. 极值：add(INT_MAX, INT_MAX) → int 加法溢出（UB），与模板无关（预期：溢出责任在使用者，先想类型容量再调模板）。

回扣开场：现在你知道模具何时压、按什么类型压了——推演与点名两条路（③）。函数讲完，把模具思想搬进类，一句话的事。

### 3. 类模板一句话与模板别名

前置依赖：[[#2. 实例化：编译器推演与类型匹配]]、[[面向对象编程]]（类语法）
后续衔接：[[#4. 竞赛模板代码的含义：读得懂即可（延伸）]]、STL（下批素材，p4 预告）

**① 它解决什么问题**

p4 概述原话："需要设计的几个类，其功能都是一样的，仅仅只是需要操作的数据类型不同。例如需要创建一个数组类，可能是 int 数组、double 数组、string 数组等。"类模板就是这个解法：**类定义里留类型坑位 T**。关键性质三条（p14-18）：类模板实例化必须显式在类名后加尖括号（`Pair<int> myInt(1,2)`，p17）——与函数模板的自动推演不同，类没有实参可推；**类名本身不是类型，`Test<T>` 才是类型**（p18 原话）；成员函数在类外定义时要再带一行模板参数声明（p18："类模板中的成员函数若是放在类外定义时，需要加模板参数列表"）。按任务要求，类模板只求一句话读懂、能照抄框架。

**② 直觉理解**

用具体数字跑一遍（mycode.cpp test03 实测）：`Pair<int> myInt(1, 2)` → values 存 1 和 2；`Pair<double> myDouble(1.111, 2.342)` → 存浮点对。同一个类模板，两种"具体类"（附录 B-5）。

**③ 原理与推导**

模板别名的推导（p19-20）：老办法 `typedef Test<int> t;` 给**某个具体化**起短名；缺点 p20 点破——"如果代码量过大的话，那么你可能会忘记它是什么意思"，typedef 没有参数化能力，每个具体化都得单独起名。C++11 新办法：`template <class T> using t = Test<T>;`——别名本身带类型参数，`t<int>`、`t<double>` 通吃。实测：`t<int> t1; t1.setData(999);` 输出 999（mycode.cpp test04，附录 B-5）。**设计动机**：别名解决的是"名字长了不好读"，参数化别名解决的是"一族名字不好读"——把 typedef 的重复劳动也交给模板。

**④ 代码演示**

**块一·核心代码**（取自课堂代码 mycode.cpp 的 Test/Pair/别名段；改动：类外定义版被素材注释保留，正文取类内定义版并注明）：

```cpp
#include <iostream>
using namespace std;
template<class T>
class Test {
public:
    Test() {}
    void setData(const T& x) { num = x; }   // 类内定义版（素材注释掉的类外版见 p18）
    void showData() { cout << num << endl; }
private:
    T num;
};
template <class T>
class Pair {                                 // 素材 Pair：存两个任意类型元素
public:
    T values[2];
    Pair(T first, T second) {
        values[0] = first;
        values[1] = second;
    }
};
template<class T>
using t = Test<T>;                           // C++11 模板别名（p20）
int main() {
    Pair<int> myInt(1, 2);                   // 实例化：类名后加 <类型>
    cout << myInt.values[0] << "  " << myInt.values[1] << endl;
    Pair<double> myDouble(1.111, 2.342);
    cout << myDouble.values[0] << "  " << myDouble.values[1] << endl;
    t<int> t1;                               // 别名使用，等价 Test<int>
    t1.setData(999);
    t1.showData();
    return 0;
}
```

实测输出 `1  2`、`1.111  2.342`、`999`（附录 B-5）。

**块二·执行追踪表**（Pair<int> 与 Pair<double> 的实例化）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | Pair<int> | 类模板 Pair<T> | 显式点名 T=int | 生成具体类 |
| 2 | 构造 myInt(1,2) | values[2]（int） | 两个成员赋值 | values = {1, 2} |
| 3 | Pair<double> | 同一模板 | T=double | 另一个具体类 |
| 4 | 构造 myDouble(1.111,2.342) | values[2]（double） | 成员赋值 | values = {1.111, 2.342} |
| 5 | t<int> | 别名表 | 等价 Test<int> | setData(999) 后输出 999 |

**块三·错误写法对照**：

```diff
- Pair p(1, 2);                     // 坑1：类名不是类型（p18 原话），缺 <int> → 编译错误
+ Pair<int> p(1, 2);                // 类模板实例化必须显式点名
- void Test<T>::setData(...) { }    // 坑2：类外定义成员函数缺模板参数声明行 → 编译错误
+ template<class T> void Test<T>::setData(const T& x) { ... }   // p18 原话"需要加模板参数列表"
- typedef Test<int> t; ... t<double> t2;   // 坑3：typedef 别名无参数，t 已钉死为 Test<int> → 编译错误
+ template<class T> using t = Test<T>;      // 参数化别名，t<double> 合法（p20）
```

**⑤ 典型应用**

- 素材作业（p24，hw_code.cpp）：类模板 input，构造时收提示信息与上下界，成员函数校验输入在界内则输出、否则提示重输。实测输入 `1 9 3` 与 `a z f` 输出 `3` 与 `f`（附录 B-5）——int 与 char 两种具体化的现成演示。
- 迁移题（自编）：给 Pair 加一个 `T bigger()` 返回较大元素。建议先独立做，再对照题解：模板里用 `>` 比较两个 T 值即可。
- 竞赛衔接：你下一次写 `vector<int>`、`pair<int,int>` 时，尖括号里点名的就是类模板实例化——STL 全部基于模板（p4 原话），本节是读懂 STL 的入场券。

**⑥ 坑点与边界**

> **【易错】** 把类名当类型用（④对照坑 1）——`Pair p` 编译失败；类模板永远要带着尖括号点名。

> **【注意】** typedef 别名与 using 别名的边界：给一个具体化起短名用 typedef 够；要"一族短名"必须 using 模板别名（坑 3）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用（预期：不涉及）。
> 2. 单元素：Pair<int> p(5, 5) → 两元素相等（预期：构造正常，bigger 返回 5）。
> 3. 全相同：Pair<char>('a','b') → 字符比较按 ASCII（预期：T 换 char 逻辑不变）。
> 4. 严格递增：Pair<int>(1,2)、Pair<double>(1.5,2.5)、Pair<char>('a','b') → 三种具体化（预期：一份类定义三份类）。
> 5. 严格递减：构造后交换两元素再读回（预期：values[0]/values[1] 互换）。
> 6. 极值：Pair<int>(INT_MAX, INT_MIN) → 存储无溢出（原样存取），比较与运算才溢出（预期：容器型模板不做数值加工）。

### 4. 竞赛模板代码的含义：读得懂即可（延伸）

前置依赖：[[#1. 函数模板：为什么要模板]]、[[#2. 实例化：编译器推演与类型匹配]]
后续衔接：[[并查集与种类并查集]]（板子代码实例）、[[排序]]（STL 模板算法）

**① 它解决什么问题**

"模板"在竞赛语境里有**两个含义**，必须分清：一是本篇讲的**语言机制** template 关键字；二是竞赛圈说的"**模板代码/板子**"——写好背熟的算法成品（如 [[并查集与种类并查集]] 的 find 函数、快速幂）。板子里的 `template<typename T>` 读起来是什么意思？答案：**"这个函数对任意类型 T 都适用"**——读板子时把它当通配符看，不必深究实例化细节。本知识点按任务要求定位为**延伸**：竞赛极少手写模板（类型通常写死为 int 或 long long），要求是读懂，不是会写。同时回答一组对比：**#define 宏与 template 的区别**——两者都能"一份定义多处使用"，机制却完全不同。

**② 直觉理解**

模型级类比：**预制菜与中央厨房**。宏是"写菜谱时把原料名直接抄进菜谱"（文本替换，抄错了菜谱自己不负责）；模板是"中央厨房按订单食材现做"（类型检查、按需生成）。宏在预处理阶段展开（[[预处理命令]] 的地盘），编译器接手前文本已经换完；模板在编译阶段工作，全程受类型系统管辖。

用具体数字推一遍（实测，附录 B-5）：`#define BAD_SQ(x) x*x`，`BAD_SQ(2+3)` 展开为 `2+3*2+3 = 11`——不是 25；加全括号的 `SQM(2+3)` 才得 25。宏是纯文本、不挑类型也不做检查；模板实例 `add(n1, n2)` 类型不匹配直接编译报错。**一句话对比：宏的灵活没有护栏，模板的灵活有类型系统兜底。**

**③ 原理与推导**

对比推导：

| 维度 | #define 宏 | template |
|:---:|:---:|:---:|
| 处理阶段 | 预处理（编译前文本替换） | 编译期（类型推演后生成） |
| 类型检查 | 无——文本替换即完事 | 有——不匹配即编译错误 |
| 调试 | 展开后行号错位，难查 | 报错指向模板定义处 |
| 适用 | 常量（`#define N 100005`） | 通用算法/容器 |

**设计动机**：为什么竞赛代码里宏还大量存在？因为"开大数组"这类场景只用它做**常量替换**（`#define N 100005`），文本替换的简单性恰好够用、也最短；一旦逻辑里带参数（像函数），宏的文本替换立刻变危险（BAD_SQ 坑），此时必须换模板。两把刀各有案板。

**④ 代码演示**

**块一·核心代码**（自编示例：同一"平方"需求的三种实现对照）：

```cpp
#include <iostream>
using namespace std;
#define BAD_SQ(x) x*x            // 错误写法：宏参数无括号
#define SQM(x) ((x) * (x))       // 宏正确写法：内外全括号
template<typename T>
T sq(T x) { return x * x; }      // 模板版：类型安全，无展开坑
int main() {
    cout << BAD_SQ(2 + 3) << endl;   // 11：展开为 2+3*2+3（坑）
    cout << SQM(2 + 3) << endl;      // 25：括号救回来
    cout << sq(2 + 3) << endl;       // 25：先算实参再传值，无文本坑
    cout << sq(1.5) << endl;         // 2.25：模板顺带支持 double
    return 0;
}
```

**块二·执行追踪表**（三种实现的求值差异）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | BAD_SQ(2+3) | 预处理文本替换 | 2+3 拆散代入 | 2+3*2+3，先乘后加 |
| 2 | 求值 | 运算优先级 | 3*2=6 先算 | 得 11 |
| 3 | SQM(2+3) | 全括号保护 | (2+3)*(2+3) | 得 25 |
| 4 | sq(2+3) | 模板调用 | 先求实参 5，再 sq<int> | 得 25 |
| 5 | sq(1.5) | 隐式实例化 | T=double | 得 2.25 |

**块三·错误写法对照**：

```diff
- #define SWAP(a, b) { int t = a; a = b; b = t; }   // 坑1：宏当函数用——只对 int 生效，double 版再抄一份，回到知识点 1 的老路
+ template<typename T> void mySwap(T& a, T& b)      // 逻辑带参数，交给模板
- #define MAX(a, b) ((a) > (b) ? (a) : (b))          // 坑2：参数带副作用时求值两次（经典坑），类型不检查
+ template<typename T> T myMax(T a, T b)             // 副作用只算一次，类型有检查
- #define N 100005 ... int a[N];                     // 这类常量宏是合理用法（保留）
+ 常量替换用宏、通用逻辑用模板——各守各的案板
```

**⑤ 典型应用**

- 素材案例（p22 练习与 mycode.cpp test05）：模板机制在"数学工具函数"上的直接应用；实测输出见知识点 1⑤。
- 迁移题（自编）：把 [[并查集与种类并查集]] 板子里的 `int find(int x)` 改写成 `template<typename T> ...` 是否值得？建议先独立思考，再对照结论：不值得——并查集下标恒为 int，泛化无收益；判断"要不要写模板"的标准是**是否真有多类型需求**。
- 竞赛衔接说明：板子（快速幂、并查集、线段树）里的 template 读得懂即可；自己写板子时类型写死 int/long long 更快；`#define int long long` 这类邪典写法（把 main 的返回类型也换掉）慎用——知道有这回事、赛场上能读懂即可。

**⑥ 坑点与边界**

> **【易错】** 宏当函数用（④对照坑 1、2）——文本替换不查类型、参数副作用求值不定次；逻辑带参数一律模板或真函数，宏只留给常量。

> **【注意】** 本篇定位"延伸"的含义：模板元编程、特化、可变参数模板等深水区不要求；要求只有三条——能读 `template<typename T>` 头、知道实例化按类型生成、知道宏与模板的阶段区别。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用（预期：不涉及）。
> 2. 单元素：sq(3) 与 SQM(3) → 均为 9（预期：单参数时宏括号坑不触发——坑只在表达式实参时现形）。
> 3. 全相同：BAD_SQ(x) 且 x 为单变量 → 与 SQM 等价（预期：危险宏在简单场景下潜伏）。
> 4. 严格递增：sq(2)、sq(3)、sq(4) → 4、9、16（预期：模板对连续 int 稳定）。
> 5. 严格递减：SQM(-1)、SQM(-2) → 1、4（预期：平方非负，与符号无关）。
> 6. 极值：sq(100000) 用 int → 1e10 溢出（UB）；用 sq<long long>(100000) 或传 long long 实参 → 10000000000（预期：模板不防溢出，类型容量自己把关）。

回扣开场：现在你能回答开场那个"三份 Swap"的问题了——一份模板（知识点 1 的动机）；也能分清竞赛里两个"模板"——语言机制与板子（本节）；板子里的 `template<typename T>` 是通配符，读得懂就够。

## 四、总结与自测

### 核心内容（一页纸速览）

- **函数模板**：`template<typename T>`（class 等价）声明类型坑位；一份源码，编译器按实参类型生成多份具体函数（地址不同）。
- **实例化**：隐式推演（add(n1,n2)）与显式点名（MathHelper<int>(a,n)）；模板不做类型转换，混合类型调单参数模板必报错；双参数版 `<T, H>` 解决混合，返回类型跟 T。
- **类模板**：类名不是类型，`Test<T>` 才是；实例化必须显式点名；类外定义成员函数要再带模板参数行；C++11 参数化别名 `using t = Test<T>`。
- **模板 vs 宏**：宏是预处理文本替换（无类型检查、BAD_SQ(2+3)=11），模板是编译期类型安全生成；竞赛惯例——常量用宏（#define N 100005），通用逻辑用模板。
- **竞赛定位（延伸）**：板子里的 `template<typename T>` 当通配符读；自己写代码类型写死更快；"要不要泛化"看是否真有多类型需求。
