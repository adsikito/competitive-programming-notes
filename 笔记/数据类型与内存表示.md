## 一、为什么需要它

构造一个必然发生的碰壁场景：第一道"求两数之和"的变式题，输入 $a, b \le 2 \times 10^9$，你熟练地写出 `int a, b; cin >> a >> b; cout << a + b;`——样例全对，评测 WA。原因藏在类型系统里：int 的上限是 2147483647，$2 \times 10^9$ 的输入本身装得下，但 $a + b$ 最高到 $4 \times 10^9$，**加法结果在 int 里溢出回绕成负数**。类型不是语法书里的表格题，而是每道题数据范围的第一道关。

本篇讲 4 个知识点：常量变量与整型家族、unsigned 与补码直觉、浮点精度陷阱、char 与 ASCII 与 sizeof 实测。顺序理由：先掌握类型的"使用面"（知识点 1），再钻进内存看"存储面"（知识点 2），接着看浮点数为什么天生存不准（知识点 3），最后用 sizeof 把全类型占地一次量清（知识点 4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 常量变量与整型家族

前置依赖：（同批）《第一个C++程序》的程序骨架与 cout、[[C语言要点与内存管理]]（C 变量概念）
后续衔接：知识点 2（int 的内存表示）、[[前缀和与差分]]（long long 防溢出的高频应用场景）

**① 它解决什么问题**

A 源 p10-11 定义：常量是程序执行期间不变的固定值（又叫字面量），变量是运行中其值可改变的量——**变量必须先定义类型再使用**。类型回答的问题是：这块内存多大、里面的位怎么解释、能参加哪些运算。四种基本类型各管一类值（A 源 p11）：整型 int 存整数（如 666）、字符型 char 存单个字符（如 'c'）、浮点型 float 存小数（如 1.23）、布尔型 bool 存真假（true/false）。

关键性质（融入正文）：int 通常 4 字节，范围 $[-2147483648, 2147483647]$（约 $\pm 2.1 \times 10^9$）；更大的整数用 long long（8 字节，约 $\pm 9.2 \times 10^{18}$）。溢出机制：超出范围时值**回绕**（INT_MAX + 1 实测变 INT_MIN，附录 B-3）——这就是开场碰壁的全部原因，也是竞赛防溢出意识的第一课。

**② 直觉理解**

模型级类比：**类型是量杯的规格**。int 是 1 升量杯，long long 是 8 升量杯——往 1 升杯里倒 1.5 升水，多出来的不是"被礼貌拒绝"而是漫出来流得满桌都是（回绕成意想不到的值）。变量名是量杯上的标签，标签随便写（合法即可），但杯子的规格定义时就定死。

用具体数字跑一遍（变量定义与命名，A 源 p12-13）：`int aa;` 定义未初始化；`int bb = 100;` 定义同时赋初值。命名规则四条（A 源 p13）：只能字母数字下划线；首字符不能是数字；区分大小写（`Aa` 与 `aa` 是两个变量）；不能用关键字。实测反例 `int c123abc = 100;` 合法（数字不在开头）；`int 3abc;` 非法。

**③ 原理与推导**

为什么 int 上限偏偏是 2147483647？推导：4 字节 = 32 位，无符号时能表达 $2^{32}$ 个状态；有符号时最高位作符号位，正数部分是 $2^{31} - 1 = 2147483647$（减 1 是因为 0 占一个编码）。为什么是"回绕"而不是报错？设计动机：竞赛与系统编程里范围检查每步都做太贵，C/C++ 选择"不查、按模回绕"换取速度，把检查责任交给程序员——所以数据范围必须人肉审题。取值范围速查（本机 g++ x64 实测，附录 B-3）：

| 类型 | 字节 | 范围 | 竞赛量级换算 |
|------|------|------|-------------|
| int | 4 | $[-2.1 \times 10^9, 2.1 \times 10^9]$ | 10^9 内安全，两数相加即可能爆 |
| long long | 8 | $[\pm 9.2 \times 10^{18}]$ | 10^18 内安全，10^5 个 10^9 相加安全 |
| unsigned int | 4 | $[0, 4.3 \times 10^9]$ | 无负数场景，正数上限翻倍 |
| bool | 1 | true / false | 条件与标志位 |

字节数"通常 4 字节"的原因（A 源 p16 原话"不同系统会有差异"）：标准只保证下限与相对关系，具体宽度由编译器与平台定——竞赛环境固定，实测一次记死即可。

**④ 代码演示**

常量变量与整型家族一次跑全（自编示例，风格对齐源文件 数据类型.cpp 的 cin/cout 用法）：

```cpp
#include <iostream>
#include <climits>                     // INT_MAX / LLONG_MAX 所在头文件
using namespace std;
int main() {
    const double PI = 3.14;            // 常量：定义后不可改（等价 C：#define PI 3.14 但有类型）
    int a = 2147483647;                // int 上限（等价 C 写法完全相同）
    long long b = 9223372036854775807LL;  // long long 上限，字面量后缀 LL 必写
    int c = a + 1;                     // 复杂度 O(1)；结果回绕为 -2147483648
    cout << a << endl;                 // 输出 2147483647
    cout << c << endl;                 // 输出 -2147483648：溢出回绕实测
    cout << b + 1 << endl;             // long long 上限同样会回绕
    return 0;
}
```

**执行追踪表**（对 `int c = a + 1;`，a = INT_MAX）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | a + 1 | 32 位加法 | 0x7FFFFFFF + 1 | 进位溢出符号位，得 0x80000000 |
| 2 | 赋值 c | c 就绪 | 按补码解释 0x80000000 | c = -2147483648 |
| 3 | cout << c | 输出流 | 按有符号解释 | 屏幕见负数（WA 根源） |

**错误写法对照**：

```diff
- int a = 100000, b = 200000;
- int prod = a * b;                    // 坑1：中间结果 2*10^10 超 int——即使 prod 是 long long 也救不回（先在 int 里溢出，值已错）
+ long long a = 100000, b = 200000;    // 让乘法在 long long 里进行
+ long long prod = a * b;
- int x = INT_MAX; long long s = x + x;   // 坑2：x+x 仍按 int 算完才转换——s 拿到的是溢出后的错值
+ long long s = (long long)x + x;      // 先升级再运算
- int 3abc = 5;                        // 坑3：标识符以数字开头（编译错误）
+ int abc3 = 5;                        // 首字符必须是字母或下划线（A 源 p13）
```

**⑤ 典型应用**（无对应 OJ 题，给自编练习与竞赛衔接）

- 自编练习（自编）：读入 $n$（$n \le 10^5$）与 $n$ 个 $1 \le a_i \le 10^9$，输出它们的和与最大值。陷阱在总和最大 $10^{14}$——int 必爆，必须 long long；同时验证"读入 int 存值 + long long 累加"的写法（`long long s = 0; s += a;` 安全，因为累加发生在 long long 侧）。
- 竞赛衔接说明：审题先算"最大中间结果"是竞赛第一习惯——前缀和（[[前缀和与差分]]）、乘积统计、图论边权之和都以此定类型；溢出回绕不报错、悄悄给错值，比 RE 更难查。bool 类型在后续排序比较器、图论 visited 标记（[[图的概念存储与遍历]]）里大量出场。

**⑥ 坑点与边界**

> **【易错】** 中间结果溢出：操作数是 int，表达式就按 int 算，赋给 long long 也晚了。正解：把至少一个操作数升级为 long long 再运算。

> **【易错】** long long 字面量忘写 LL 后缀：`9223372036854775807` 裸写会被当 double 或直接溢出报错。带后缀 `...LL` 是硬纪律。

> **【注意】** 变量未初始化就使用是读垃圾值（不是固定 0）——定义即初始化（`int cnt = 0;`）是比"记得赋值"更可靠的纪律。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 无数据 → 循环零次，输出初始值（预期：和 0，不崩）。
> 2. 单元素：n=1, a_1=1 → 和 1（预期：最小规模）。
> 3. 全相同：n=10^5 全为 1 → 和 10^5（预期：int 可容）。
> 4. 严格递增：a_i = i（1 到 10^5）→ 和约 5*10^9（预期：int 爆、long long 过——直接验证开场碰壁）。
> 5. 严格递减：a_i = 10^9 递减 → 同样总量 10^14（预期：long long 必选）。
> 6. 极值：两个 INT_MAX 相加 → int 版输出 -2，long long 版输出 4294967294（预期：回绕机制眼见为实，附录 B-3）。

回扣开场：现在你能解决开场那道 WA 了——a+b 用的是本知识点"先升级再运算"的结论。但"回绕为什么恰好变成负数"还没解释，下一节钻进内存看补码。

### 2. unsigned 与补码直觉

前置依赖：知识点 1（int 的范围与回绕现象）、二进制基本概念
后续衔接：知识点 3（浮点的二进制表示）、（同批）《运算符与表达式》的位运算

**① 它解决什么问题**

知识点 1 留下的问题：INT_MAX + 1 为什么**恰好**变成 INT_MIN 而不是别的？答案在内存的存储方式。C 源《数据在内存中的存储方式》p4-5 定义：计算机里一个数叫机器数，最高位放符号（正 0 负 1）；同一串二进制有原码、反码、补码三种解释，而**计算机底层一律存补码**（C 源 p5 原话："计算机在底层存储数据的时候，一律存储的是二进制的补码形式"，原因是"补码形式效率最高"）。unsigned 的含义：同一块内存，放弃符号位解释，全部 32 位都当数值——正数范围翻倍、永远非负、回绕方向变为模 $2^{32}$。

关键性质：正数的原码反码补码相同；负数的补码 = 原码符号位不变、其余取反后加 1（C 源 p8）。加减法在补码下统一用加法器完成（减法即加负数的补码）——这就是"效率最高"的机制来源。

**② 直觉理解**

先补进制基础（C 源《数据的进制表示》p4-9）：进制是进位计数法，基数是可用的数字符号个数，权是每位代表的值（十进制 123 = $1 \times 10^2 + 2 \times 10^1 + 3 \times 10^0$）。两招通吃转换：**十进制转 R 进制用"除基取余倒着读"**，**R 进制转十进制用"按权展开求和"**。例：$92_{10} = 5C_{16}$（92 / 16 = 5 余 12，12 即 C，倒着读 5C）；二进制与八/十六进制按 3 位/4 位一组直接换（C 源 p18）。

模型级类比：**补码是汽车里程表的倒车**。里程表只进不退——倒车时表针"从 0 往回卷"，显示的是最大值减去倒过的格数。8 位里程表卷到头就是 255，从 255 再加 1 回到 0：**减一个数 = 加它的"补数"再绕一圈**，加法器一套机构通吃加减。unsigned 就是把里程表声明成"只显示 0 到 255、永不显示负"，范围自然翻倍。

用具体数字跑一遍（C 源 p13-14 的 -5 例）：8 位下 -5 的原码 10000101 → 反码（符号位不变取反）11111010 → 补码（加 1）11111011。验证加法：5 的补码 00000101 加 (-5) 的补码 11111011 = (1)00000000，第 9 位进位丢弃，得 00000000——**5 + (-5) = 0 恰好成立**，这就是补码完美性的小数据证明。

**③ 原理与推导**

为什么弃原码选补码？C 源 p10-12 给出完整推导链，逐步复现：

```text
原码算 1 + (-1)：0000 0001 + 1000 0001 = 1000 0010（即 -2）——符号位参与运算，结果错
反码算 1 + (-1)：0000 0001 + 1111 1110 = 1111 1111（即 -0）——接近对但出现两个 0（+0 与 -0）
补码算 1 + (-1)：0000 0001 + 1111 1111 = (1)0000 0000 ——进位丢弃，完美得 0
```

文字版推导链：原码让符号位参与加法导致 1-1 算错；反码修正了数值但制造了 -0（0 有两个编码，比较与逻辑都别扭）；补码在反码基础上加 1，把 -0 的编码腾出来给 -128（8 位下），同时让减法变加法——硬件只需一套加法器。设计动机：**用一套加法电路统一加减法、消除双零**，这是 C 源 p5"效率最高"的精确含义。

为什么 INT_MAX + 1 恰好是 INT_MIN？推导：补码编码是环——0111...1（最大）加 1 变 1000...0，按补码解释恰好是最小值。回绕不是随机错乱，是环上走了一格。

**④ 代码演示**

三种码与 unsigned 回绕的实测程序（自编示例）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int x = 5;
    cout << (x + (~x + 1)) << endl;    // ~x 是按位取反（等价 C：同款运算符），~5+1 即补码机制下的 -5
    unsigned int u = 0;
    u = u - 1;                          // 无符号回绕：0 往回卷一格
    cout << u << endl;                  // 输出 4294967295（2^32-1），不是 -1
    unsigned char uc = 250;
    uc = uc + 6;                        // 8 位里程表：250+6 模 256
    cout << (int)uc << endl;            // 输出 0
    return 0;
}
```

**执行追踪表**（8 位简化模型，对 `uc = 250 + 6`）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 250 | 1111 1010 | 加 6（0000 0110） | (1)0000 0000 |
| 2 | 8 位截断 | 0000 0000 | 第 9 位进位丢弃 | uc = 0 |
| 3 | (int)uc 输出 | 按 int 解释 | 打印 | 0（模 256 回绕实测） |

**错误写法对照**：

```diff
- unsigned int u = 0;
- for (int i = 0; i < u - 1; i++) { ... }   // 坑1：u-1 是 4294967295，循环条件永远为真（死循环）
+ for (int i = 0; i < (int)u - 1; i++) { ... }   // 先转有符号再减，或换 int 变量
- int a = -1;
- cout << (unsigned)a << endl;              // 坑2：负数强转 unsigned——补码位模式不变、解释变正（输出 4294967295），新手以为"取绝对值"
+ cout << -a << endl;                        // 要绝对值就取负，不要换类型
- // -5 的补码 = 原码取反加 1
- int m = ~( -5 ) + 1;                      // 坑3：对 -5 取反加 1 得回 5 没错，但"对负数再求补码"的口诀容易对 -5 与 5 混用出错
+ int m = ~(5) + 1;                          // 口诀固定用于"从正数造负数"：取反加一（实测 ~5+1 == -5）
```

**⑤ 典型应用**（无对应 OJ 题，给自编练习与竞赛衔接）

- 自编练习（自编）：手算 $-11$ 的 8 位原码、反码、补码（答案：10001011 / 11110100 / 11110101），再用补码加法验证 $34 - 11 = 23$（34 补码 00100010 + 11110101 = (1)00010111，丢弃进位得 23）——这是 C 源 p18 的作业原题，做完对答案。
- 竞赛衔接说明：位运算（同批《运算符与表达式》）与 [[状压DP]] 全部建立在补码位模式上；哈希与随机数里 unsigned 回绕是特性不是 bug；竞赛中 unsigned 出场率远低于 long long——**默认 long long，除非有明确理由**，是最稳的选型纪律。

**⑥ 坑点与边界**

> **【易错】** unsigned 参与比较或减法产生"巨大正数"。后果：循环条件恒真死循环、下标越界 RE。无符号运算先想回绕方向。

> **【易错】** 把补码当"显示层技巧"。后果：误以为内存里存的是原码、输出时才转换。事实是**全程补码**，加法器眼里没有符号，解释权在类型。

> **【注意】** 8 位/16 位手工推演与 32 位真实环境的差别只在位数，规则完全相同——练习时用 8 位（好写），竞赛按 32/64 位算范围。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：无运算 → 无输出（预期：概念篇无副作用）。
> 2. 单元素：~0 + 1 → 0（预期：0 的相反数是自身）。
> 3. 全相同：对同一正数反复取反加一 → 正负来回振荡（预期：取反加一是自逆运算）。
> 4. 严格递增：对 1、2、3... 逐个取反加一 → -1、-2、-3...（预期：一一对立）。
> 5. 严格递减：unsigned 从 5 减到 0 再减 1 → 0 之后跳到 4294967295（预期：回绕点）。
> 6. 极值：INT_MIN 取负（~-2147483648 情形）→ 仍是 -2147483648（预期：绝对值溢出，负数比正数多一个编码，附录 B-3 实测回绕一致性）。

回扣开场：INT_MAX + 1 恰好变 INT_MIN 的原因找到了——补码环上走一格。整数的世界严丝合缝，小数的世界却天生有裂缝，下一节看浮点为什么存不准。

### 3. 浮点精度陷阱

前置依赖：知识点 2（二进制与按权展开——小数的二进制表示）、知识点 1（类型量杯类比）
后续衔接：[[二分]]（实数二分的精度控制）、计算几何类题目的 eps 纪律

**① 它解决什么问题**

浮点型存小数（A 源 p11：float 保存小数浮点数 1.23）。解决什么问题：小数点位置可变（0.001 与 1000.5 共用一套编码），需要"科学计数法式"的存储——符号 + 指数 + 尾数。但这套编码有个天生的坑：**二进制无法精确表示多数十进制小数**。C 源《数据的进制表示》p14-15 的小数转换演示了根因：十进制 0.375 转二进制只需三步得 0.011（有限小数），而 0.68 转二进制是 0.10101100110... 无限循环——**存不下，必须截断**。截断产生误差，误差在运算中放大，于是 0.1 + 0.2 在程序里不等于 0.3（附录 B-3 实测）。

关键性质：float 通常 4 字节（约 7 位有效数字），double 8 字节（约 15 位）；double 是默认选择。判断相等必须用误差容忍：`fabs(a - b) < 1e-9`。

**② 直觉理解**

模型级类比：**二进制小数是"只有半分、四分之一、八分之一……这些刻度的尺子"**。量 0.375 恰好是 1/4 + 1/8，两个刻度拼出来分毫不差；量 0.68 却怎么拼都是无限接近——尺子刻度与被量物天生不同频。float 尺子短（刻度少，24 位尾数），double 尺子长（53 位尾数），但都不可能量准 0.68。

用具体数字跑一遍（C 源 p21 的原例，乘基取整正着读）：$0.68 \times 2 = 1.36$ 取 1；$0.36 \times 2 = 0.72$ 取 0；$0.72 \times 2 = 1.44$ 取 1；$0.44 \times 2 = 0.88$ 取 0；$0.88 \times 2 = 1.76$ 取 1——五步后还在继续，得 $0.68_{10} = 0.10101..._2$（无限）。对比 0.375：$0.375 \times 2 = 0.75$ 取 0；$0.75 \times 2 = 1.5$ 取 1；$0.5 \times 2 = 1$ 取 1——三步终止，$0.011_2$ 精确。**有限与无限的分野就是精度陷阱的分野**。

**③ 原理与推导**

推导"为什么浮点比较不能 =="：截断后的 0.1 与 0.2 各带微小误差，相加后的值是 $0.30000000000000004...$，而字面量 0.3 是另一个截断值——两个"都是错的数"互不相同。推导"为什么用误差容忍就稳"：只要误差远小于业务精度（如答案保留 6 位，容忍 1e-9），截断误差（1e-17 量级 for double）就被覆盖。设计动机：浮点用有限位编码无限的实数域，必然只存近似值——IEEE 754 把"精度"与"范围"做成可调的两端，float 换范围、double 换精度，竞赛默认 double 是精度优先的选型。

有效数字的量级依据：float 24 位尾数 $\approx 2^{24} = 16777216$，即 7 位十进制有效数字——第 8 位必失真（附录 B-3 实测：float 存 16777217 变 16777216）；double 53 位尾数 $\approx 9 \times 10^{15}$，15 到 16 位有效数字。

**④ 代码演示**

精度陷阱三连实测（自编示例）：

```cpp
#include <iostream>
#include <cmath>                       // fabs 所在头文件
using namespace std;
int main() {
    cout << (0.1 + 0.2 == 0.3) << endl;            // 输出 0：不相等！
    cout << fabs(0.1 + 0.2 - 0.3) << endl;         // 输出 5.55e-17：误差真实存在但极小
    float f = 16777217.0f;                          // 2^24 + 1
    cout << (f == 16777216.0f) << endl;             // 输出 1：第 8 位有效数字已失真
    double sum = 0;
    for (int i = 0; i < 10; i++) sum += 0.1;        // 误差累加十次
    cout << (sum == 1.0) << endl;                   // 输出 0：累加放大截断误差
    cout << (fabs(sum - 1.0) < 1e-9) << endl;         // 正确姿势：误差容忍判断（外层括号必须写，见④错误对照）
    return 0;
}
```

**执行追踪表**（对 `sum += 0.1` 循环十次的误差累积）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 第 1 次累加 | sum = 0.1000...0（截断值） | 加截断的 0.1 | 误差 +1.4e-17 |
| 2 | 第 5 次累加 | 误差缓慢累积 | 继续加 | 误差约 8.9e-17 |
| 3 | 第 10 次累加 | sum ≈ 0.9999999999999999 | 与 1.0 比较 | 不相等（== 判 0） |
| 4 | fabs(sum-1.0) | 差值 1.1e-16 | 与 1e-9 比较 | 判相等（正确姿势） |

**错误写法对照**：

```diff
- double a = 0.1 + 0.2;
- if (a == 0.3) { ... }                // 坑1：浮点直接 == 比较——两侧都是截断值，结果不可靠（答案错）
+ if (fabs(a - 0.3) < 1e-9) { ... }    // 误差容忍判断
- float s = 0;
- for (int i = 0; i < 100000; i++) s += 0.1f;   // 坑2：float 累加 10 万次——7 位有效数字被误差淹没（答案错）
+ double s = 0;                        // 累加场景一律 double
- if (fabs(a - b) == 0) { ... }        // 坑3（示意）：容忍度写成 0——与 == 无异，形改实不改（答案错）
+ if (fabs(a - b) < 1e-9) { ... }      // 容忍度必须是正的小量
```

**⑤ 典型应用**（无对应 OJ 题，给自编练习与竞赛衔接）

- 自编练习（自编）：C 源 p20 的原题——$0.68_{10}$ 转二进制精确到小数点后 5 位（答案 0.10101，过程见②）；再用程序验证 `0.68` 的 double 存储与 0.10101... 无限近似的预言：打印 `setprecision(20)` 下的 0.68，观察第 17 位之后的尾巴。
- 竞赛衔接说明：实数二分（[[二分]] 的浮点版）与几何题全部依赖 eps 纪律；输出题目要求"误差 1e-6 内"时，double 累加 + 误差容忍比较是标配。整除取余类题（同批《运算符与表达式》）则相反——全程整数运算，一步不碰浮点，两套纪律不要混。

**⑥ 坑点与边界**

> **【易错】** 浮点用 == 或 != 比较。后果：样例侥幸过、对抗数据必 WA。一律 `fabs(a-b) < eps`。

> **【易错】** 大量累加用 float。后果：7 位有效数字被误差吞掉。累加与中间结果一律 double。

> **【注意】** eps 不是万能值：答案精度 1e-6 时 eps 取 1e-9 合理，但迭代次数多的几何题误差会放大到 1e-6 以上——eps 取 1e-9 到 1e-12 之间并了解题目误差放大率，是进阶课内容（延伸，非必需）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不运算直接比较 0.0 == 0.0 → 相等（预期：零无截断误差）。
> 2. 单元素：0.5 比较 → 相等（预期：0.5 = 0.1B 二进制有限可精确）。
> 3. 全相同：0.1 加十次再逐次归零 → 回不到精确 0（预期：截断误差只进不出）。
> 4. 严格递增：0.1、0.2、...、0.9 各自转二进制 → 有的有限（0.25、0.5、0.75）有的无限（预期：分野肉眼可见）。
> 5. 严格递减：1.0、0.5、0.25（除 2 递减）→ 全部精确（预期：2 的幂必精确）。
> 6. 极值：1e308 量级的 double 溢出为 inf；16777217 的 float 失真（附录 B-3）（预期：范围上限与精度上限各爆一次）。

回扣开场：现在你知道 0.1+0.2 不等于 0.3 的根因——二进制尺子量不准十进制小数。整数与小数的存储都看清了，最后把全部类型的占地用 sizeof 一次量清。

### 4. char、ASCII 与 sizeof 实测

前置依赖：知识点 1（类型量杯模型）、知识点 2（补码——char 本质是小整数）
后续衔接：[[字符串哈希]] 与字符串题（字符即整数的直接应用）、（同批）《运算符与表达式》的类型转换

**① 它解决什么问题**

char 存单个字符（A 源 p11），但它在内存里就是**一个 8 位整数**——字符与整数的对应表叫 ASCII 码。解决什么问题：第一，竞赛里的字符处理（大小写转换、数字字符转数值、哈希取模）全部依赖"字符即整数"；第二，写程序必须知道每个类型占几字节——A 源 p16 给了"各种类型字节数"表并提醒"不同系统会有差异"，而 sizeof 运算符让你在任何环境**现场实测**，不背表也能答题。标注：ASCII 对照表在（同批）《运算符与表达式》素材 p12 有完整截图，本篇只列竞赛必备的三个锚点值，属补充展开。

关键性质：sizeof 是**编译期**运算符，返回字节数，对变量与类型都可用；char 参与算术时自动按 int 处理。三个锚点：'0' 是 48、'A' 是 65、'a' 是 97——大小写差恒为 32，数字字符转数值减 '0'。

**② 直觉理解**

模型级类比：**ASCII 是字符世界的门牌号系统**。每个字符住一间房，房号就是它的 ASCII 值；char 变量存的从来不是"字母 a 本身"，而是房号 97。大小写字母分住两栋楼，但楼层布局完全相同——97 与 65 差的 32 就是两栋楼的门牌偏移，转大小写只是跨楼换房。

用具体数字跑一遍（A 源 p11 的类型定义 + 附录 B-3 实测）：`char c = 'a';` 则 `(int)c` 是 97；`c - 'a'` 是 0（转下标用）；`'A' + 32` 是 'a'（大转小加 32）；`'5' - '0'` 是 5（数字字符转数值）——四个惯用式覆盖字符题 80% 的操作。

**③ 原理与推导**

为什么 char 参与算术要升级为 int？推导：8 位运算器的溢出风险与硬件对齐成本都更高，语言规定整型运算至少在 int 宽度进行（整型提升）——char + char 实际是 int + int，结果再截回 char 时才可能回绕（知识点 2 的机制）。为什么 sizeof 是编译期完成？设计动机：类型大小在编译期就完全确定，运行期查询是浪费——sizeof 像编译时刻好的尺寸标签，零运行时开销（这也是它能用于数组声明尺寸的原因）。

本机实测字节数（附录 B-3，g++ x64）：char 1、bool 1、int 4、float 4、double 8、long long 8。与 A 源 p16 表一致（该表同时提醒系统差异——实测法正是应对差异的手段）。

**④ 代码演示**

字符运算与 sizeof 收账一次跑全（自编示例）：

```cpp
#include <iostream>
using namespace std;
int main() {
    char c = 'a';
    cout << (int)c << endl;            // 97：字符的房号
    cout << (char)('A' + 32) << endl;  // a：大转小加 32
    cout << '5' - '0' << endl;         // 5：数字字符转数值
    cout << sizeof(int) << " "         // 4
         << sizeof(long long) << " "   // 8
         << sizeof(double) << " "      // 8
         << sizeof(char) << endl;      // 1：sizeof 一次量清
    return 0;
}
```

**执行追踪表**（对 `'5' - '0'` 的整型提升运算）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | '5' | 8 位编码 53 | 提升为 int | 53 |
| 2 | '0' | 8 位编码 48 | 提升为 int | 48 |
| 3 | 53 - 48 | int 运算 | 相减 | 5（数值意义上的 5） |

**错误写法对照**：

```diff
- char c = "abc";                      // 坑1：char 装字符串——双引号是字符串（地址），塞进单字符（编译错误或截断隐患，素材 数据类型.cpp 注释区正是此错例）
+ char c = 'a';                        // char 用单引号单字符
- char d = 'a' + 1;
- cout << d << endl;                   // 坑2：结果 'b' 恰好对，但运算在 int 里完成后截回 char——超出 char 范围时（如 'z'+5）输出乱码（答案错）
+ int v = c + 1;                       // 想要数值就在 int 域运算，需要字符时再显式转回
- cout << "int 大小固定是 4" << endl;   // 坑3（示意）：背表代替实测——换平台即失效
+ cout << sizeof(int) << endl;         // sizeof 现场实测，A 源 p16"不同系统会有差异"的正解
```

**⑤ 典型应用**（无对应 OJ 题，给自编练习与竞赛衔接）

- 自编练习（自编）：读入一行不含空格的字符串（长度 ≤ 100），输出其中大写字母个数、小写字母个数与数字个数。核心判断式：`c >= 'A' && c <= 'Z'` 等三组——本质是门牌号区间判断，字符即整数的直接应用。
- 竞赛衔接说明：字符串题的每一个算法（[[字符串哈希]]、KMP 等）底层都在操作"房号数组"；状态压缩（[[状压DP]]）里 `1 << (c - 'a')` 把字母变成位下标，用的正是 `c - 'a'` 锚点式。sizeof 在竞赛里的角色是环境核验——拿到陌生评测环境先 sizeof 一遍，比背表可靠。

**⑥ 坑点与边界**

> **【易错】** char 用双引号赋值。后果：类型不匹配（字符串 vs 单字符）。单引号单字符，双引号字符串——引号即类型。

> **【易错】** char 运算结果超范围仍当字符输出。后果：'z' + 5 这类越界房号输出乱码。跨范围运算在 int 域做，输出前想清楚要的是字符还是数值。

> **【注意】** `'\0'`（值 0）与 `'0'`（值 48）是两个字符——终止符与数字零的房号完全不同，字符串题混用直接逻辑错。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：无字符运算 → 无输出（预期：概念零副作用）。
> 2. 单元素：单个 'a' 转 int → 97（预期：锚点值）。
> 3. 全相同：十个 'A' 各加 32 → 十个 'a'（预期：偏移恒定）。
> 4. 严格递增：'a' 到 'z' 的房号严格递增 97 到 122（预期：连续编码，区间判断合法）。
> 5. 严格递减：'Z' 到 'A' 递减 90 到 65（预期：同构另一栋楼）。
> 6. 极值：char 最大 127 再 +1 → 回绕为 -128（有符号 char 的补码环，附录 B-3）（预期：char 不是"无风险小整数"）。

回扣开场：四个知识点收账完毕——类型量杯（知识点 1）、补码环（知识点 2）、二进制尺子（知识点 3）、门牌号系统（知识点 4）。开场那道 a+b 的 WA 现在从现象到根因全部透明：下一步是让这些类型动起来——《运算符与表达式》（同批）讲运算。

## 四、总结与自测

### 核心内容（一页纸速览）

- **常量与变量**：常量是字面量，变量先定义类型再使用；命名四规则（字母数字下划线、数字不开头、分大小写、避关键字）（A 源 p10-13）。
- **整型家族**：int 4 字节 ±2.1e9、long long 8 字节 ±9.2e18；溢出回绕不报错（INT_MAX+1 = INT_MIN 实测）；中间结果先升级再运算。
- **补码与进制**：底层一律存补码；负数补码 = 原码取反（符号位不变）加一；补码让加法器统一加减、消除双零（C 源 p10-12 推导链）；unsigned 同内存换解释，回绕模 2^32。进制转换两招：除基取余倒着读（10 转 R），按权展开求和（R 转 10）；二/八/十六进制按 3/4 位分组直换（C 源）。
- **浮点**：二进制无法精确表示多数十进制小数（0.68 无限循环）；float 7 位、double 15 位有效数字；比较必须误差容忍。
- **char 与 ASCII**：字符即 8 位整数；'0'=48、'A'=65、'a'=97，大小写差 32；sizeof 编译期实测字节数。四类内容收账后，《运算符与表达式》（同批）让类型动起来。
