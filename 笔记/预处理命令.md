# 预处理命令

## 零、知识地图

```text
预处理命令
├── 1. #include 与头文件 —— 编译前的文本搬运（前置：[[变量作用域与多文件编程]]）
├── 2. #define 宏与带参宏括号纪律 —— 文本替换的两大纪律（前置：知识点 1）
├── 3. 条件编译与包含守卫 —— 让一部分代码不参与编译（前置：知识点 2）
└── 4. 竞赛常用宏与节制 —— INF/rep 一行流与它的风险（前置：知识点 2、3）

学习顺序：1 → 2 → 3 → 4。理由：先懂"编译前发生了什么"（1），再学替换规则与括号纪律（2），然后让代码按条件存在（3），最后收敛到竞赛模板头的取舍（4）——从搬运到替换到裁剪到节制。
```

## 一、为什么需要它

先看一个你会踩的场景：写一道大模拟，调试时想在十几个关键点输出中间变量，交题前逐行注释——漏掉一处，`printf` 挂在正解代码里，本可 AC 的题当场 TLE 或输出格式错 WA。再看你大概率抄过的竞赛模板第一行：`const long long INF = 1e18;` 或者 `#define INF 0x3f3f3f3f`——如果哪天数据范围到 $10^{10}$，写成 `#define INF 1 << 40`，这行在 int 里**静默溢出**，答案错得莫名其妙。两类痛点的根源相同：**有些代码和常量，你希望"编译之前"就决定它的去留与形态**，而不是在运行期或靠手改。

预处理命令就是干这个的：它们以 `#` 开头，在**编译第一遍扫描之前**由预处理程序处理（16.1 pdf p4-p5）——你每份代码第一行的 `#include <iostream>` 早已是预处理命令。本篇讲 4 个知识点：#include 与头文件、#define 宏与括号纪律、条件编译与包含守卫、竞赛常用宏与节制。顺序理由：先懂搬运（知识点 1），再懂替换（知识点 2），再懂裁剪（知识点 3），最后学竞赛模板怎么用得克制（知识点 4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. #include 与头文件

前置依赖：[[变量作用域与多文件编程]]（声明与定义分离、多文件组织）、C 基础的编译概念
后续衔接：[[#3. 条件编译与包含守卫]]（守卫是 #include 的配套防重复装置）、[[结构体]]（公共结构体放头文件里供多文件共享）

**① 它解决什么问题**

`#include` 把一个头文件的**全部文本**原样插入到指令所在位置（pdf p5-6），解决"公共声明只想写一遍"的问题：函数原型、结构体定义、常量——写进头文件，谁需要谁包含。关键性质：它是预处理期的纯文本搬运，不产生任何机器码；`<>` 与 `""` 只影响搜索路径；复杂度概念上，被包含内容的规模决定编译时间，运行期为零开销。

**② 直觉理解**

模型级类比：**装订前贴复写页**。写论文时"参考文献格式页"不想每次手抄，就做成模板页，装订时把它复印一份贴到需要的位置。`#include <iostream>` 就是把 iostream 头文件的几万行声明复印进你的 cpp——编译器随后看到的，是一个"你 + iostream"合并后的完整文件。

用具体数字跑一遍：三个文件 a.h（1 行声明）、b.h（含 `#include "a.h"`）、main.cpp（含 b.h）——预处理后 main.cpp 的开头依次是 a.h 的 1 行 + b.h 的剩余内容，两份文本都在；若 main.cpp 再直接包含一次 a.h，a.h 内容出现两遍，同名定义撞车——这正是知识点 3 包含守卫要堵的洞。

**③ 原理与推导**

两种写法的差别只在搜索顺序（教材通识，素材未展开）：`<xxx>` 从编译器自带的标准库目录找，`"xxx"` 先在当前工程目录找、找不到再去标准目录。为什么设计两套符号？标准库位置固定且你不该误改，走 `<`；自己写的头文件和源文件同目录，走 `""`——把"去哪找"编码在符号形状里，省一个参数。

传递包含：b.h 包含 a.h、main.cpp 包含 b.h，则 a.h 内容也在 main.cpp 里生效——所以"我没直接包含但它能用"是常态；代价是同一个头可能被搬进来多次（嵌套包含，pdf p24 第 4 条），重复定义由此产生。C 等价对照：`#include <iostream>` ↔ C 的 `#include <stdio.h>`——#include 本身是 C 原生指令，两侧语法零差别；差别只在被包含的内容（iostream 是 C++ 的 cin/cout 声明）。

**④ 代码演示**

块一「核心代码」（自编示例：双文件最小包含实验；与附录 B-5 的 guard 实测同一套文件）：

```cpp
// ---------- 文件 mymath.h ----------
int add(int a, int b);        // 只有声明：头文件放"是什么"
// ---------- 文件 main.cpp ----------
#include <iostream>           // 标准库：尖括号走库目录
#include "mymath.h"           // 自写头：引号先走工程目录
using namespace std;
int add(int a, int b) { return a + b; }   // 定义：源文件放"怎么做"
int main() {
    cout << add(2, 3) << endl;    // 预处理后 add 的声明已在上方
    return 0;                     // 运行期无任何预处理开销
}
```

逐段讲：mymath.h 只放声明（[[变量作用域与多文件编程]] 的"声明与定义分离"落地）；main.cpp 两条 include 一条走库目录一条走工程目录；编译时链接器再把 add 的定义接上。

块二「执行追踪表」（预处理阶段的文本搬运，按处理顺序）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | `#include <iostream>` | main.cpp 原文 | 换成 iostream 全文 | 数万行声明进入 |
| 2 | `#include "mymath.h"` | 已并入库声明 | 换成 mymath.h 全文 | add 声明就位 |
| 3 | 其余正文 | 合并后的完整 cpp | 预处理结束 | 交给编译器 |
| 4 | 编译期 | 同上 | 只编译不搬运 | 运行期零开销 |

块三「错误写法对照」：

```diff
- #include <mymath.h>    // 坑1：自写头用尖括号——库目录里没有它，报"file not found"（CE）
+ #include "mymath.h"    // 自写头用引号
- int add(int a, int b);  在 a.cpp 与 main.cpp 都写定义、互相不知情   // 坑2：声明写头文件、定义写多个源文件——链接期报 multiple definition（CE）
+ 声明进 .h，定义只在一个 .cpp——包含该头的所有文件共享同一定义
- 用了 cout 却忘 #include <iostream>   // 坑3：有的编译器因传递包含侥幸能编，换环境立刻报 cout 未声明（CE）
+ 头文件里用什么就显式包含什么，不赌传递包含
```

**⑤ 典型应用**

- 例题（16.1 pdf p5）：`#include <iostream>` 本身被课件点名为预处理命令的示例——本节即它的原理课。
- 例题（自编）：把 [[结构体]] 篇的 student 定义搬进 student.h，两个源文件各自包含后共享同一类型——多文件编程的标准做法。
- 迁移检验题（自编）：写 mymath.h（声明 `int max3(int a, int b, int c);`）与 main.cpp（包含并调用），输出三数最大值。数据范围：绝对值 ≤ 1e9。建议先独立做，再对照题解：头文件放声明，main.cpp 定义 `int m = a; if (b > m) m = b; if (c > m) m = c; return m;`，编译 g++ main.cpp 即可（无需编 mymath.cpp，因为没有定义需要链接）。

**⑥ 坑点与边界**

> **【易错】** 自写头用尖括号。`<>` 不搜工程目录，直接 CE"找不到文件"；口诀：库用尖、己用引（④对照坑 1）。

> **【易错】** 头文件里写函数定义或全局变量定义。两个源文件包含同一头，定义各来一份，链接期 multiple definition（实测复现见附录 B-5 无守卫实验）；头文件只放声明、常量、结构体定义。

> **【注意】** 竞赛中 `#include <bits/stdc++.h>` 一行顶所有标准头，省心但非标准——本机 g++ 8.1 在 `-std=c++17` 下实测因 filesystem 头损坏无法编译（附录 B-6），可改用 `-std=c++14` 或显式 include；赛机环境不确定时显式包含更稳。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空头文件被包含 → 预处理换成零行文本，合法（预期：不崩）。
> 2. 单元素：头文件只有一行注释 → 同样合法，注释不进编译。
> 3. 全相同：同一头被包含 3 次（无守卫） → 同名定义 3 份，CE（预期：redefinition，实测 B-5）。
> 4. 严格递增：头文件逐版加声明 → 包含方每次重新编译可见新增声明（预期：增量生效）。
> 5. 严格递减：头文件删声明但源文件仍在用 → 包含方报"未声明"（预期：CE）。
> 6. 极值：包含超大头（iostream 数万行）→ 编译时间变长（秒级），运行期无影响——竞赛时限只算运行期，放心包含（预期：不影响 AC）。

回扣开场：现在你明白每份代码第一行到底干了什么——编译前的文本搬运。接下来解决"替换"：想让一个名字在编译前就换成一段代码，靠宏。

### 2. #define 宏与带参宏括号纪律

前置依赖：[[#1. #include 与头文件]]（同为预处理指令）
后续衔接：[[#3. 条件编译与包含守卫]]（#ifdef 检查的就是这里定义的宏）、[[#4. 竞赛常用宏与节制]]

**① 它解决什么问题**

`#define` 用一个标识符代表一段文本（pdf p7），解决"同一常量或表达式片段反复手写、改一处漏九处"的问题。无参宏 `#define PI 3.1415926`（code.cpp L7）当常量用；带参宏 `#define SQR(n) ((n) * (n))`（code.cpp L11）像函数用。关键性质：**替换发生在编译前，是纯文本操作**——没有类型检查、没有函数调用开销、也没有作用域；`#undef`（pdf p21）可中途取消。复杂度：运行期零开销（替换早已完成），这正是它比函数快的原因，也是它危险的原因。

**② 直觉理解**

模型级类比：**编辑器的查找替换**。你把"圆周率"设为查找目标，替换词填 3.1415926，点"全部替换"——预处理程序对源码做的就是这个，且它不认识语法，只认字符。带参宏是高级版替换：`SQR(x)` 里的每个 x 按你给的位置填入。

用具体数字跑一遍（pdf p15-16 的原题）：`#define SQR(n) n*n` 时 `SQR(5+5)` 替换成 `5+5*5+5`，按优先级 `5 + 25 + 5 = 35`；括号纪律版 `#define SQR(n) ((n)*(n))` 替换成 `((5+5)*(5+5)) = 100`。同一调用两种结果——差距全在括号（实测断言 SQR-good / SQR-bad-trace，附录 B-5）。

**③ 原理与推导**

推导括号纪律的两层防护：第一层**参数括号**——形参每次出现都套 `()`，防实参是表达式时被优先级拆开（上面 35 的教训）；第二层**整体括号**——整个替换体再套一层，防宏出现在更大的表达式里：`#define ADD(a,b) (a)+(b)` 时 `2 * ADD(1,2)` 展开为 `2 * (1) + (2) = 4` 而非 6，整体加括号后为 `2 * ((1)+(2)) = 6`。**设计动机**：宏没有函数调用的求值边界，替换结果直接裸露在调用点语法里，唯一防御是把参数与整体都焊死在括号里——code.cpp L11 的注释"括号很重要，优先级的改变"就是这条纪律。

宏与函数的本质差别（推导"为什么 1LL 要写进宏里"）：宏是文本，`#define SH 1 << 40` 展开后 `1 << 40` 按字面量 `1` 的类型 int 计算，40 位左移溢出 int（32 位上限），结果未定义；写 `#define SH (1LL << 40)` 才让 1 以 long long 参与。**常量携带类型，文本不携带**——这是竞赛里所有大数宏必须写 1LL / 1e18 的根因。副作用陷阱同理：`SQR(i++)` 展开为 `((i++)*(i++))`，i 被加两次且求值顺序未定义——参数在替换体出现几次就被"执行"几次，函数只执行一次。C 等价对照：#define 是 C 原生特性，两侧语法完全相同；C++ 里更安全的替代是 `const double PI = 3.1415926;`（有类型）与内联函数，见知识点 4 的节制。

**④ 代码演示**

块一「核心代码」（取自素材 code.cpp，改动：仅把注释掉的实验固化为可编译主程序、补 SQR_BAD 反例；宏定义逐行同源）：

```cpp
#include <iostream>
using namespace std;
#define PI 3.1415926                       // 无参宏：常量替换
#define SQR(n) ((n) * (n))                 // 括号纪律版（code.cpp L11）
#define SQR_BAD(n) n * n                   // 反例：无括号（自编对照）
#define MAX(x, y) (((x) > (y)) ? (x) : (y))   // 素材 hw code.cpp L3
#define ARRSIZE(arr) (sizeof((arr)) / sizeof((arr[0])))   // code.cpp L17
int main() {
    int r1 = SQR(5 + 5);      // ((5+5)*(5+5)) = 100
    int r2 = SQR_BAD(5 + 5);  // 5+5*5+5     = 35
    int num = 10;
    cout << PI << " " << r1 << " " << r2 << " "
         << MAX(100, 300) << " " << ARRSIZE(num) << endl;
    return 0;                 // 运行期零开销：全部替换已在编译前完成
}
```

逐段讲：L6 无参宏是最安全的用法；L7 括号纪律双防护；L9 三层括号（参数各一层、比较各一层、整体一层）；L10 用 sizeof 比值算元素个数，注意它只在真数组上成立（[[结构体]] 篇坑 3 同源）。

块二「执行追踪表」（预处理期的文本替换过程，r1 与 r2 对照）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | SQR(5+5) | 源码原文 | 查宏表，n:=5+5 | 展开为 ((5+5)*(5+5)) |
| 2 | 该表达式 | ((5+5)*(5+5)) | 编译器按语法求值 | 10*10 = 100 |
| 3 | SQR_BAD(5+5) | 源码原文 | 查宏表，n:=5+5 | 展开为 5+5*5+5 |
| 4 | 该表达式 | 5+25+5 | 优先级先乘后加 | 35（静默错误） |
| 5 | MAX(100,300) | 源码原文 | 三层括号展开 | (300) = 300 |

块三「错误写法对照」：

```diff
- #define SQR(n) n*n          // 坑1：无括号——SQR(5+5) 得 35，编译器不报错（答案错）
+ #define SQR(n) ((n) * (n))  // 参数与整体都套括号
- #define SH 1 << 40          // 坑2：1 是 int——40 位左移溢出（答案错/未定义）
+ #define SH (1LL << 40)      // 1LL 让字面量以 long long 参与
- #define ADD(a,b) (a)+(b)    // 坑3：缺整体括号——2*ADD(1,2) 展开为 2*(1)+(2)=4（答案错）
+ #define ADD(a,b) ((a) + (b))   // 整体再套一层
- #define SQR2(x) ((x) * (x)) 调用 SQR2(i++)   // 坑4：副作用参数——i 被自增两次且顺序未定义（答案错）
+ int t = i++; SQR2(t);       // 先消掉副作用再进宏
```

**⑤ 典型应用**

- 例题（16.1 pdf p9-10）：`#define PI 3.1415926` 求圆面积 `PI * r * r`——无参宏的最典型用途。
- 例题（hw code.cpp）：`MAX(x,y)` / `MIN(x,y)` 三层括号三元式，实测 x=100、y=300 输出 max=300、min=100（附录 B-5）。
- 迁移检验题（自编）：定义带参宏 `CUBE(x)` 求立方，要求对 `CUBE(1+2)` 也正确。数据范围：x ≤ 100。建议先独立做，再对照题解：`#define CUBE(x) ((x) * (x) * (x))`，`CUBE(1+2)` 展开为 `((1+2)*(1+2)*(1+2)) = 27`；再用一个无括号版对照出 7 的错误结果，验证括号纪律。

**⑥ 坑点与边界**

> **【易错】** 带参宏参数与整体不加括号。文本替换后运算符优先级改写语义，SQR(5+5)=35（④对照坑 1、坑 3）；纪律：参数每次出现套 `()`，替换体整体再套一层。

> **【易错】** 宏常量缺类型后缀。`#define SH 1 << 40` 溢出 int；大数据宏一律显式写 1LL、1e18 或 0x3f3f3f3f（int 用）（④对照坑 2）。

> **【注意】** 宏名写到哪，作用就到哪：宏从 #define 行起生效直到 #undef 或文件尾（pdf p21-22 的 #undef 案例：取消后再用 PI 直接 CE），没有函数那样的作用域边界——起名要长且独特，防撞名。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：`#define EMPTY` 后用 EMPTY → 展开为零字符，`int EMPTY x;` 这类用法才出事；单独定义为开关用（预期：作 #ifdef 开关合法）。
> 2. 单元素：SQR(7) → ((7)*(7)) = 49（预期：单参数无歧义）。
> 3. 全相同：SQR(5+5) 连写三次 → 每处都展开为 100（预期：替换确定性）。
> 4. 严格递增：CUBE(1)、CUBE(2)、CUBE(3) → 1、8、27（预期：独立展开）。
> 5. 严格递减：同上反向 → 27、8、1（预期：无累积效应）。
> 6. 极值：SQR(50000) → ((50000)*(50000)) = 2.5e9 溢出 int（上限约 2.1e9），赋给 int 已错——宏不改类型，接收方要 long long 且字面量写 1LL 式防溢出（防溢出）。

回扣开场：查找替换模型讲清了宏的全部能力与全部危险——能力是零开销，危险是它不认识语法。现在你能安全地写宏了；下一节让"一部分代码根本不参与编译"。

### 3. 条件编译与包含守卫

前置依赖：[[#2. #define 宏与带参宏括号纪律]]（条件编译检查的就是宏表）
后续衔接：[[#4. 竞赛常用宏与节制]]（调试开关的正确打开方式）、[[变量作用域与多文件编程]]（守卫是多文件工程的安全带）

**① 它解决什么问题**

条件编译（pdf p23-24）让**满足条件的代码才进入编译**，其余部分被预处理直接丢弃，解决四类问题（pdf p24 原文归纳）：屏蔽跨平台差异、按需包含功能模块、开关调试信息、防止头文件重复包含。关键性质：判断发生在预处理期，条件只能是"宏是否定义"（#ifdef/#ifndef）或"常量表达式"（#if/#elif）；被丢弃的代码连语法错误都不查（但必须能被预处理正确分块）。复杂度：零运行期开销——二进制里根本没有被丢弃的代码。

**② 直觉理解**

模型级类比：**电影的上映版本**。同一部片源，影院版剪掉某些镜头、导演剪辑版保留——不是放映时判断，而是出厂前就分成两版。条件编译就是给代码"出厂分版"：`#ifdef DEBUG` 段只进调试版，正式版出厂即无，交题前忘记删调试输出这种事故在出厂机制下不可能发生。

用具体数字跑一遍（pdf p27-28 案例）：代码 `#ifdef PRINT` 段输出 "PRINT has defined"——定义了 `#define PRINT` 则该段进入编译，否则被丢弃；`#else` 段反之（pdf p26）。`#ifndef` 方向相反（pdf p29，if not define），包含守卫用的正是它。

**③ 原理与推导**

推导包含守卫为什么能挡住双重包含：头文件骨架 `#ifndef X / #define X / ...内容... / #endif`——第一次包含时宏 X 不存在，`#ifndef` 成立，内容进入编译且顺路定义了 X；第二次包含（直接或经嵌套）时 X 已存在，`#ifndef` 不成立，**整段内容被预处理丢弃**。于是同一头文件无论被搬进来几次，内容只进编译一次。为什么用宏而不是注释或代码判断？因为丢弃必须发生在预处理期——运行期 if 挡不住重复定义，注释则两头都挡不住；宏表是预处理期唯一可查的状态。

`#if` 家族（pdf p33-37）：`#if 常量表达式` 值非零则编译（`#define com 0` 后 `#if com` 不成立）；`#elif` 接在 #if/#ifdef/#ifndef 后做多路（pdf p36），`#else` 只能放最后；`#endif` 收尾。`#error`（pdf p38-39）在预处理期直接报错终止编译，用于"此路不通"的硬断言。C 等价对照：全套指令 C/C++ 语法相同，无新语法糖。

**④ 代码演示**

块一「核心代码」（取自素材 code.cpp 条件编译段，改动：注释实验固化为可编译程序；三段判断骨架与素材逐行同源）：

```cpp

#endif

    cout << "PRINT has define" << endl;   // pdf p27 案例
#else
    cout << "PRINT no define" << endl;    // pdf p28 案例
#endif
```

**⑤ 典型应用**

- 例题（自编）：调试开关模板——`#define LOCAL_JUDGE` + `#ifdef LOCAL_JUDGE` 包住全部调试输出，提交版注释一行宏即可，零删除风险。
- 迁移检验题（自编）：给 mymath.h（知识点 1⑤）加包含守卫，并在 main.cpp 中包含它两次，验证编译通过。建议先独立做，再对照题解：头文件首行 `#ifndef MYMATH_H`、次行 `#define MYMATH_H`、末行 `#endif`；双重包含后 g++ 编译 exit=0 即守卫生效（与附录 B-5 的 guard_test 实测同一原理）。

**⑥ 坑点与边界**

> **【易错】** #ifdef / #if / #endif 不配对。预处理块不闭合直接 CE；多路结构顺序固定：#if(#ifdef/#ifndef) → 若干 #elif → 至多一个 #else → #endif（pdf p36）（④对照坑 2）。

> **【易错】** #if 判断未定义的标识符。#if 里未定义标识符按 0 处理，拼写错误变成"永远走假分支"的静默 bug（④对照坑 3）；先用 #ifdef 判存在，或保证 #define 在前。

> **【注意】** 守卫宏名要全局唯一：两个头文件用同一个守卫名，后包含的整头内容会被丢弃，缺声明的错在别处爆发——惯例是 `文件名_H` 或加随机后缀。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：`#ifdef X #endif` 中间零行 → 合法空块（预期：不崩）。
> 2. 单元素：块内一行输出 → 定义 X 输出一行、不定义零行（预期：二值切换）。
> 3. 全相同：同一头包含 3 次（有守卫） → 内容只进 1 次（预期：编译通过，实测 B-5）。
> 4. 严格递增：嵌套 #ifdef 两层全开 → 内外段都进编译（预期：两段输出）。
> 5. 严格递减：外开内关 → 外段进、内段丢（预期：一段输出）。
> 6. 极值：#if 判断 (1LL<<40) > 0 → 预处理期算术按 long long 求值成立；但 #if 里写 1<<40 位移行为依实现——预处理表达式也要守 1LL 纪律（防溢出）。

回扣开场：条件编译把"漏删调试输出"从事故变成不可能——出厂分版，正式版根本没有那段代码。现在你能解决开场第一个痛点了；最后一节把宏的竞赛用法收敛成一套克制的模板头。

### 4. 竞赛常用宏与节制

前置依赖：[[#2. #define 宏与带参宏括号纪律]]、[[#3. 条件编译与包含守卫]]
后续衔接：[[排序]]（竞赛模板头与 sort 的组装）、[[结构体]]（模板头 + cmp 三件套合体）

**① 它解决什么问题**

竞赛模板头里沉淀了一批高频宏：无穷大 INF、循环简写 rep、数组长度 ARRSIZE（code.cpp L17）、调试开关 LOCAL_JUDGE。它们解决"高频样板代码压到一行"的问题；但宏无类型、无作用域、报错定位差，**节制**才是本节真考点：一行省下的字，可能要花十行调试找回。关键性质：宏替换零运行期开销，但错误延迟到展开点才暴露；复杂度层面宏不改变算法，只改变书写密度。

**② 直觉理解**

模型级类比：**厨房里的预制菜**。常用半成品（INF、rep）让出菜快；但预制菜不认识你的锅——火候问题（类型、副作用）全要自己兜。会用预制菜的高手两招：只把"无争议的样板"预制（常量、固定循环形），调味现场做（有类型要求的用 const、有副作用风险的展开手写）。

用具体数字跑一遍：`#define rep(i,l,r) for (int i = (l); i <= (r); ++i)` 展开与手写完全一致，`rep(i,1,3) s += i;` 得 6；同一宏名若与变量重名——`int rep = 5;` 后写 rep(i,1,3)，预处理照展开不误，但可读性归零，这正是节制的切入点（实测：宏展开在先，语法层变量与宏可共存，坑见④）。

**③ 原理与推导**

推导"什么时候该用宏、什么时候不该"：宏的优势只有两条——运行期零开销、书写极短。C++ 的 const 常量同样零开销（编译器直接内联值）且有类型；内联函数同样零开销且有类型检查与作用域。所以判断标准是**这段样板有没有类型或作用域风险**：`const long long INF = 4e18;` 有类型，宏 `#define INF 0x3f3f3f3f` 无类型但值域全 int 安全——两者皆可，值含表达式时宏必须守 1LL 纪律而 const 天然免疫。**设计动机**：宏是 C 遗产，C++ 提供 const/constexpr/inline 逐项接管它的职能且补上类型安全；竞赛保留宏的只剩"极致书写密度"这一条理由，所以清单要短。

为什么宏报错难读：编译器在**展开点**报错，看到的是替换后的超长表达式（坑 1 的 35 就毫无线索）；const 版本报错直接指向定义行。这解释了节制清单里"逻辑复杂的一律不用宏"。

**④ 代码演示**

块一「核心代码」（自编示例：竞赛模板头最小集；ARROW/MAX 取自素材 code.cpp、hw code.cpp）：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;
#define INF 0x3f3f3f3f                    // int 域"够大"哨兵：约 1.06e9
#define LINF (1LL << 60)                  // long long 域：1LL 纪律（知识点 2）
#define rep(i, l, r) for (int i = (l); i <= (r); ++i)
#define ARRSIZE(arr) (sizeof((arr)) / sizeof((arr[0])))   // code.cpp L17
#define MAX(x, y) (((x) > (y)) ? (x) : (y))               // hw code.cpp L3
int main() {
    int a[5] = {3, 1, 4, 1, 5};
    int best = -INF;                       // 求最大前初始化为负哨兵
    rep(i, 0, ARRSIZE(a) - 1) best = MAX(best, a[i]);
    cout << best << " " << LINF << endl;   // 复杂度：O(n)，宏不改变量级
    return 0;
}
```

逐段讲：L5 哨兵值选 0x3f3f3f3f 因为两倍相加仍不溢出 int（0x7f7f7f7f 会）；L6 long long 域必须 1LL；L7 rep 三参数全括号；L10 循环体与手写 for 等价。

块二「执行追踪表」（上例 rep + MAX 组合，n=5，best 初始 -INF）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | rep 展开 | i=0, best=-INF | for 头初始化 | 循环就绪 |
| 2 | MAX(best,3) | best=-INF | (−INF>3) 假，取 a[0] | best=3 |
| 3 | MAX(best,1) | best=3 | (3>1) 真，取 3 | best=3 |
| 4 | MAX(best,4) | best=3 | (3>4) 假，取 4 | best=4 |
| 5 | i=3,4 | best=4 | 1、5 比较：5 胜出 | best=5 |
| 6 | 循环退出 | best=5 | 输出 | 5 与 LINF |

块三「错误写法对照」：

```diff
- #define rep(i, l, r) for (int i = l; i <= r; ++i)   // 坑1：形参不括号——rep(i,0,n-1) 展开为 i = 0; i <= n-1 碰巧对，但 rep(i,0,3-1) 与复合实参会错序（答案错）
+ #define rep(i, l, r) for (int i = (l); i <= (r); ++i)   // 参数一律括号（知识点 2 纪律延续）
- #define MAX(x, y) x > y ? x : y    // 坑2：三层括号省两层——cout << MAX(a,b) 展开为 cout << a > b ? ... 优先级错乱（答案错）
+ #define MAX(x, y) (((x) > (y)) ? (x) : (y))   // 素材 hw code.cpp 原样
- #define rep(i, l, r) for (...) 内再嵌 rep(i, l2, r2) 用同一形参名 i   // 坑3：内外同名——外层 i 被内层 int i 遮蔽，逻辑读乱（答案错风险）
+ 内外循环用不同变量名（i / j）   // 模板宏虽每次声明新 i，语义仍是两份，阅读期就要区分
- int INF = 1;（与宏 INF 同名变量）   // 坑4：变量撞宏名——预处理先把 INF 换成 0x3f3f3f3f，声明变成 int 0x3f3f3f3f = 1（CE，报错信息难读）
+ 宏名全大写且独特（INF/LINF），变量不取同名
```

**⑤ 典型应用**

- 例题（code.cpp）：`DIGIT(c)` 判断十进制数字（`(c >= '0' && (c) <= '9')` 双参数括号）、`ARRSIZE(arr)` 求数组长度——两个高频小宏的原型。
- 例题（hw code.cpp）：`MAX` / `MIN` 三元宏，作业原题即"宏函数求最大最小值"（pdf p43）。
- 迁移检验题（自编）：用本节模板头写程序：n（n ≤ 1e5）个整数，输出最大值与总和。数据范围：元素绝对值 ≤ 1e9。输入格式：第一行 n，第二行 n 个整数；输出格式：一行两个数。建议先独立做，再对照题解：best 初始 -INF、sum 必须 long long（1e5 个 1e9 相加 = 1e14 超 int，防溢出模式）；rep 循环 + MAX 宏，总和手写累加不用宏——总和涉及类型增长，正是"节制"里该手写的部分。

**⑥ 坑点与边界**

> **【易错】** 模板宏形参不括号。知识点 2 的两层括号纪律在 rep/MAX 上同样生效（④对照坑 1、坑 2）；复制模板宏时括号一个不能丢。

> **【易错】** 变量与宏撞名。宏替换先于一切语法分析，撞名后报错信息面目全非；宏名全大写、变量避开（④对照坑 4）。

> **【注意】** 宏不参与类型检查与作用域：它既不报类型错也不随块退出失效，行为像"全局文本替换"；有类型要求的常量用 const/constexpr，逻辑复杂的一律写成真函数——这是节制清单的兜底条。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → rep(i,0,-1) 循环零次，best 保持 -INF、sum=0（预期：哨兵不被输出为答案时需判空）。
> 2. 单元素：n=1 → 一次比较，best=该元素（预期：MAX(−INF,x) 走 x）。
> 3. 全相同：n 个同值 → 每次比较 best 不变（预期：确定性）。
> 4. 严格递增：1..n → best 逐个更新到 n（预期：更新 n 次）。
> 5. 严格递减：n..1 → 首元素即最大，后续 MAX 全走第一个分支（预期：一次更新）。
> 6. 极值：元素全取 1e9、n=1e5 → sum=1e14 必须 long long（int 上限约 2.1e9，1e5 个 1e9 相加必爆）；LINF=(1LL<<60) 约 1.15e18 贴 long long 上限 9.2e18 内（防溢出）。

回扣开场：现在你能解决开场那两个痛点了——调试事故用条件编译的"出厂分版"（知识点 3）根除；`1 << 40` 溢出用 1LL 纪律（知识点 2）根除，模板头收敛成"无争议样板才进宏"的一小份（知识点 4）。预处理命令讲完：搬运、替换、裁剪、节制，四步全是编译之前的事。

## 四、总结与自测

### 核心内容（一页纸速览）

- **#include**：编译前把头文件文本整体插入；`<>` 走库目录、`""` 先走工程目录；传递包含使内容可能进来多次（16.1 pdf p5-6、p24）。
- **#define**：纯文本替换，无类型无作用域；无参宏当常量、带参宏像函数；两层括号纪律（参数 + 整体）；大数必须 1LL（pdf p7-17、code.cpp）。
- **条件编译**：#ifdef/#ifndef/#if/#elif/#else/#endif 在预处理期裁剪代码；包含守卫用 #ifndef 挡重复包含（pdf p23-37；实测无守卫 redefinition）。
- **竞赛模板头**：INF 0x3f3f3f3f、LINF (1LL<<60)、rep、ARRSIZE、MAX/MIN；节制原则——有类型要求用 const、有逻辑复杂度用真函数。
- **#undef**：中途取消宏定义，取消后再用即 CE（pdf p21-22）。
- **复杂度总账**：预处理全部零运行期开销；#include 规模影响编译时间；宏不改变算法量级。

## 五、语法糖对照表

| 语法 | 等价 C 写法 | 一句话用途 |
|------|------------|-----------|
| `#include <iostream>` | `#include <stdio.h>` | 引入 IO 声明（指令本身两侧相同） |
| `cout << x << "\n";` | `printf("%d\n", x);` | 流式输出 |
| `cin >> x;` | `scanf("%d", &x);` | 流式输入 |
| `using namespace std;` | 每个标识符前加 `std::` | 免前缀 |
| `#define / #include / #if 家族` | 与 C 完全相同 | 本篇指令均为 C 原生，无新语法糖 |
| `const long long INF = 4e18;` | `#define INF 4e18L（C 无 const 折叠保证）` | 有类型的常量，宏的安全替代 |
