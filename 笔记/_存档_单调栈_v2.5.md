### 0-4 预备概念（横贯概念）

- **0-4-1 均摊复杂度**【资料未覆盖，属补充】：单次弹栈循环最坏弹 $O(n)$ 个，但每个元素至多入栈一次、出栈一次，全程总弹栈次数不超过总入栈次数 $n$，所以整体是 $O(n)$ 均摊——不是 $O(n^2)$。正文 K-2② 回引此结论。
- **0-4-2 「第一个更大」的严格性**：题目说「比它大」通常指严格大于。相等元素要不要弹，取决于弹栈条件写 `<` 还是 `<=`：写 `<=` 把相等的一并弹掉，留下的栈顶严格大于；写 `<` 相等的留在栈里，栈顶可能只是等于。P5788 要求严格大于，所以源码用 `<=` 弹（见 K-5⑤）。全文回引此编号。
- **0-4-3 存下标取值模式**：栈里存下标 `i`，要用值时写 `a[i]` 或 `a[s.top()]`。这一个习惯打通「值」和「位置」两个世界（见 K-3）。

## 一、知识点逐讲

### K-1　单调栈是什么

**① 核心定义**

单调栈就是**栈内元素从底到顶严格单调递增（或严格单调递减）的栈**。它不是新数据结构，而是普通栈加一条使用纪律。它专解一类问题：**左右大小边界**——对数组里每个元素，向左或向右找第一个比它大（或比它小）的数。

它解决什么问题：把「每个元素找一个邻居」这类问题从暴力 $O(n^2)$（每个数向一边扫到底）降到 $O(n)$。

| 操作 | 复杂度 | 前提 | 返回值 |
|------|--------|------|--------|
| 新元素入栈（含弹栈维护） | 均摊 $O(1)$ | 无 | 无 |
| 弹栈结算答案 | $O(1)$ | 栈非空 | 栈顶下标/值 |
| 整趟扫描（n 个元素） | 均摊 $O(n)$ | 确定方向与栈型 | 每个元素的边界答案 |

> [!important]
> **【重点】** 单调栈 = 普通 stack + 维护纪律（弹到能保持单调再入栈）+ 一个用途（O(n) 求每个元素的左右大小边界）。

**② 逐步推导（为什么恰好是栈）**

先看暴力为什么慢：求 a[i] 右边第一个更大元素，暴力要从 i+1 逐个右看，最坏看到结尾，单点 $O(n)$，全程 $O(n^2)$。

设计动机：为什么用「栈」这个结构？观察一个事实——把元素从左往右处理时，**还没找到答案的元素**有个共同点：一个元素至今没等到「右边第一个更大」，说明它右边目前的所有数都不比它大。于是这些「待定元素」从早到晚排起来，恰好从栈底到栈顶单调递减（晚来的、还活着的，必然不大于早来的）。栈只是让「最新加入的待定者」待在栈顶，方便第一时间被新来的元素结算。

> [!tip]
> **【类比】** 把栈想成一排**待结算的账单**：新来一张大额账单（更大的元素），它把前面所有比它小的账单当场结清（弹栈时它们拿到答案），然后自己躺到柜台上等下一张更大的来结它。柜台上没被结掉的账单，金额必然一张比一张大（栈内单调）。这个「待结算」模型同时解释三件事：为什么弹栈时记录答案、为什么栈内天然单调、为什么栈顶就是「最近的更大者」。

**③ 具体例子**

数组 `[3, 1, 4, 2]`，从左往右扫，维护底到顶递减栈（值入栈，只演示栈形变化，不算答案）：

```text
i=1 (3)：栈空，3 入栈            栈：[3]
i=2 (1)：1 < 栈顶 3，直接入栈     栈：[3, 1]        （底 → 顶递减）
i=3 (4)：4 > 栈顶 1，弹 1；4 > 3，弹 3；4 入栈
                                    栈：[4]          （1 和 3 的「右边第一个更大」都是 4）
i=4 (2)：2 < 栈顶 4，直接入栈     栈：[4, 2]
```

栈内始终从底到顶递减；被 4 弹掉的 1 和 3，弹栈瞬间就拿到了各自的答案。

**④ 边界与失效**

- 数据范围：$n$ 可到 $10^6$ 甚至 $3 \times 10^6$（P5788），$O(n)$ 都能过；$O(n^2)$ 必超时。
- 结论失效条件：要求「第一个大于等于」而非「严格大于」时，弹栈条件要跟着改（见 0-4-2），直接套模板会把相等元素漏掉。
- 元素全部相同（如全 1）时，按 `<=` 弹的递减栈会一路弹空再入栈，最终栈内同时只有一个元素——行为正确，不是 bug。

**⑤ 疑问与误解**

**为什么栈里的元素恰好保持单调，不需要额外排序？**

归纳法：初始栈空，单调成立。每次入栈前，我们把所有破坏单调的栈顶弹掉（新元素比栈顶大就弹到栈顶不小于它），弹完再入栈，新栈顶（刚入的元素）一定不大于下面的元素，单调性保持。单调是维护纪律的**结果**，不是额外操作。

初学者最易错的三个点：

> [!caution]
> **【易错】** 把「栈内递减」记成「数组递减」→ 后者是题目条件，前者是维护结果，两者无关 → 单调栈对任意数组都能用。

> [!caution]
> **【易错】** 以为弹掉的元素「答案丢了」→ 恰恰相反，弹栈那一刻它才拿到答案（K-2 详述）→ 弹栈处是记答案的黄金位置。

> [!caution]
> **【易错】** 忘记判栈空就 `s.top()` → 空栈访问是未定义行为，常见 RE → 先 `!s.empty()` 再 `top()`。

**⑥ 迁移检验**

> [!note]
> **【补充】** 题目（自编）：给 n 个人排队，每人有身高，问每个人**左边第一个比他矮**的人的身高，没有输出 -1。n ≤ 1e5。输入：第一行 n，第二行 n 个身高。输出：一行 n 个答案。

建议先独立做，再对照题解。

题解：与 damo.cpp「向左找第一个更大」完全同构，只改两处——弹栈条件改为「栈顶 **大于等于** 当前值时弹」（维护底到顶**递增**栈），以及答案取值方向。核心循环：

```cpp
// 相对源文件 damo.cpp 的改动：弹栈条件 <= 改为 >=，维护递增栈找更小
for (int i = 1; i <= n; i++) {
    while (!s.empty() && s.top() >= a[i]) s.pop();  // 弹掉不小于自己的，留矮的
    ans[i] = s.empty() ? -1 : s.top();              // 栈顶即左边第一个更矮
    s.push(a[i]);
}
```

对照方向-栈型表（K-4）：向左找第一个**更小** = 左到右扫 + 底到顶**递增**栈。

### K-2　维护规则与均摊复杂度

**① 核心定义**

以「底到顶递减栈」为例（递增栈完全对称），来了一个新元素 x，维护规则只有两条：

1. x 不大于栈顶 → 直接入栈；
2. x 大于栈顶 → 连续弹栈，直到栈顶不小于 x（或栈空），然后 x 入栈。

本知识点是纯流程规则，无独立性质表（操作复杂度并入 K-1 的表；见 0-4-1 的均摊结论）。

**② 逐步推导（弹栈为什么是安全的）**

关键问题：把栈顶弹掉，它的信息不就丢了吗？

不会。设被弹的元素是 y，触发弹栈的新元素是 x，则 $x > y$ 且 x 在 y 右边。y 被 x 弹出的这一瞬间，**x 恰好就是 y 的「右边第一个更大元素」**——在 x 之前，y 一直待在栈里没被弹，说明 y 与 x 之间不存在比 y 大的数（那些更小的数入栈时 y 没被弹，它们自己反而先被 x 弹掉了）。所以弹栈处正是给 y 记答案的唯一时机，记完再丢，一点不亏。

设计动机（为什么规则非这样不可）：如果 x 大于栈顶却不弹，栈内出现「底到顶递减」被破坏的相邻对，此时栈顶不再代表「最近的待定更大者」，K-1 的待结算模型就失效了。弹栈不是清理，是结算。

复杂度依据（见 0-4-1）：每个下标只经历一次 push、至多一次 pop，总操作数 ≤ 2n，均摊每元素 $O(1)$。

**③ 具体例子**

数组 `[2, 7, 5, 4]`，从左往右，递减栈，逐步执行并记录「谁在何时被结算」：

| 步骤 | 新元素 | 弹栈 | 栈（底→顶） | 结算记录 |
|------|--------|------|------------|---------|
| i=1 | 2 | 无 | [2] | — |
| i=2 | 7 | 弹 2 | [7] | 2 的右边更大 = 7 |
| i=3 | 5 | 无 | [7, 5] | — |
| i=4 | 4 | 无 | [7, 5, 4] | — |

扫描结束后栈内剩 [7, 5, 4]，它们的「右边第一个更大」不存在（答案为 0 或 -1，按题目要求）。

**④ 边界与失效**

- 弹栈循环 `while (!s.empty() && 条件)` 两个判断缺一不可：先判空防 RE，再比大小。
- 全部相等元素 `[5,5,5]` + 递减栈 + `<` 弹：谁也不弹谁，栈长到 3；换成 `<=` 弹：每个新元素弹掉前一个，栈内恒为 1 个。两种行为都对，看题目要严格还是非严格（0-4-2）。
- 均摊 $O(n)$ 的前提是**每个元素只入栈一次**。若同一下标重复入栈（写错循环），复杂度退化。

**⑤ 疑问与误解**

**相等元素到底弹不弹？**

看题目语义。「第一个比它大」（P5788）是严格大于，弹栈条件写 `a[s.top()] <= a[i]`，把相等的也弹掉，保证留下的栈顶严格更大；「第一个大于等于」则写 `<`，相等者留栈。判别口诀：**弹栈条件补齐你要找的那种大小关系**——找严格更大，就把「等于」也归入该弹的一侧。课件源码里两种写法都出现过（damo.cpp 主代码 `<=`、注释段 `<`），不是笔误，是两道题严格性不同的自然结果（见 0-3 冲突登记）。

初学者最易错的三个点：

> [!caution]
> **【易错】** 弹栈条件抄模板不核对严格性 → 相等元素处理错，WA 在「有重复值」的测试点 → 每题先问：相等算不算。

> [!caution]
> **【易错】** 弹栈循环写成 `if` 只弹一次 → 单调性没恢复就入栈，栈形逐步失控 → 必须是 `while`。

> [!caution]
> **【易错】** 在弹栈循环里顺手 `s.pop()` 之后又用旧 `s.top()` → 已弹掉的不复存在 → 需要旧栈顶就先存变量（接雨水正是这么做的，见 K-6）。

**⑥ 迁移检验**

> [!note]
> **【补充】** 题目（自编）：n ≤ 1e5 的数组，求**每个元素右边第一个更小**的元素下标，没有则 0。输入输出格式同 P5788。

建议先独立做，再对照题解。

题解：与 P5788 镜像对称——把「更大」换成「更小」，弹栈条件从 `a[s.top()] <= a[i]` 改为 `a[s.top()] >= a[i]`（弹掉所有不小于自己的，留下严格更小的），从右往左扫或从左往右扫均可。从左往右版本核心：

```cpp
for (int i = 1; i <= n; i++) {
    while (!s.empty() && a[s.top()] >= a[i]) ans[s.top()] = i, s.pop();  // 弹出者以 i 为答案
    s.push(i);
}
```

注意此版本答案记在**弹栈时**（对栈顶记当前数），与 K-5 的「取栈顶为答案」是两种视角（K-4 详述）。

### K-3　值入栈 vs 下标入栈

**① 核心定义**

栈里存什么有两种选法：直接存元素的**值**，或存元素的**下标**（要用值时写 `a[s.top()]`，见 0-4-3）。两者维护规则完全相同，差别只在「弹栈时你能拿到什么信息」。

| 存法 | 弹栈时直接可得 | 需要换算 | 适用 |
|------|--------------|---------|------|
| 存值 | 边界元素的值 | 想要下标得额外映射 | 题目只要答案值 |
| 存下标 | 边界元素的位置（下标） | 值要写 `a[s.top()]` | 要位置、距离、宽度；或既要值又要位置 |

**② 逐步推导（设计动机）**

为什么会有两种存法？因为「边界问题」的答案有两种形态。damo.cpp 主代码问「左边第一个更大的**数**」，答案直接是值，存值最省事；P5788 问「右边第一个比它大的数的**位置**」，答案本身是下标，存下标一步到位。

真正的分水岭是**距离类**问题：接雨水要算凹槽宽度 `w = 右柱下标 - 左柱下标 - 1`。值入栈时，两个值相减毫无意义（宽度是下标差，不是值差），必须存下标。设计动机总结成一句：**答案或中间量里出现「位置」二字，就存下标；纯问值且不涉及位置，存值更直接**。存下标是更通用的选择——值可以由 `a[下标]` 随时还原，反之不行。

**③ 具体例子**

同一数组 `[3, 1, 4]`，求「右边第一个更大」，两种存法的弹栈瞬间对照：

```cpp
// 存值版（damo.cpp 注释段风格）：弹栈时知道"值"是谁，但要位置没门
while (!s.empty() && s.top() < a[i]) { ans_of[s.top()] = a[i]; s.pop(); }

// 存下标版（P5788 风格）：弹栈时知道"位置"，值随时 a[] 还原
while (!s.empty() && a[s.top()] < a[i]) { ans[s.top()] = i; s.pop(); }
```

// 错：存值却想算「相隔几个位置」——值差不是距离。
// 对：存下标，距离 = i - s.top()（在弹栈前取出下标）。

**④ 边界与失效**

- 存下标时注意下标从 0 还是从 1 开始，距离计算差 1 是高发错误。
- 有重复值时存值有歧义（两个 5 你说的是哪个 5），存下标无歧义——涉及重复值 + 位置信息，必须存下标。

**⑤ 疑问与误解**

**存下标是不是多此一举，反正值能对应回去？**

在「无重复值 + 只要答案值」的题里确实等价。但「对应回去」需要值到下标的映射，数组有重复值时映射不唯一，信息已经丢了。存下标是**无损**选择：下标唯一确定，值随时可查。竞赛里除非确信不需要位置，默认存下标更稳。

初学者最易错的三个点：

> [!caution]
> **【易错】** 写 `a[s.top()]` 忘了栈里存的是下标不是值 → 直接拿栈顶当值用 → 混用两套约定是单调栈第一大笔误源头。

> [!caution]
> **【易错】** 接雨水存值，宽度算成「值差」→ 语义完全错误 → 宽度 = 下标差（K-6）。

> [!caution]
> **【易错】** 0 起下标与 1 起下标混用 → 距离差 1 → 全文统一一种，输出时再换算。

**⑥ 迁移检验**

> [!note]
> **【补充】** 题目（自编）：n ≤ 1e6 个身高，问每个人与他右边第一个更高的人之间隔了几个人，没有更高者答案为 0。输出一行 n 个间隔数。

建议先独立做，再对照题解。

题解：典型的「位置信息」题，必须存下标。弹栈时栈顶下标 j 被当前下标 i 结算，间隔 = i - j - 1（中间人数）。核心：

```cpp
for (int i = 1; i <= n; i++) {
    while (!s.empty() && a[s.top()] < a[i]) { int j = s.top(); s.pop(); gap[j] = i - j - 1; }
    s.push(i);
}
```

若存值，两个值之间算不出间隔——这就是 K-3② 的分水岭判据。

### K-4　方向-栈型对照表

**① 核心定义**

四类边界问题（左/右 × 更大/更小）各有一个最优的「遍历方向 + 栈型 + 答案时机」组合。课件第 2 页给了两张表，本节合并成一张主表。

**「对当前遍历数取答案」型**（先查后入，答案来自**现存栈顶**）：

| 目标 | 遍历方向 | 栈型（底到顶） | 答案来源 |
|------|---------|--------------|---------|
| 向左找第一个更大 | 左 → 右 | 递减 | 入栈前查栈顶 |
| 向左找第一个更小 | 左 → 右 | 递增 | 入栈前查栈顶 |
| 向右找第一个更大 | 右 → 左 | 递减 | 入栈前查栈顶 |
| 向右找第一个更小 | 右 → 左 | 递增 | 入栈前查栈顶 |

**「对栈顶记答案」型**（先弹后记，答案在**弹栈瞬间**产生）：

| 目标 | 遍历方向 | 栈型（底到顶） | 答案来源 |
|------|---------|--------------|---------|
| 向左找第一个更大 | 右 → 左 | 递减 | 弹栈时，当前数是栈顶的答案 |
| 向左找第一个更小 | 右 → 左 | 递增 | 同上 |
| 向右找第一个更大 | 左 → 右 | 递减 | 同上 |
| 向右找第一个更小 | 左 → 右 | 递增 | 同上 |

**② 逐步推导（两张表为什么长这样）**

以「向左找第一个更大」走「取答案」型为例推导：从左往右处理到 i 时，栈里躺着的正是 a[1..i-1] 中**还没被结算的元素**，它们从底到顶递减（K-1 模型）。a[i] 的左边第一个更大，就是这些待定者中**离 i 最近且比 a[i] 大**的——递减栈里从顶往底越来越大，第一个比 a[i] 大的就是栈顶（弹掉所有 ≤ a[i] 的之后）。所以「左、更大、取答案」= 左到右 + 递减 + 查栈顶。其余七行同法可推：**方向由「答案在哪边」定（同侧反向扫、异侧正向扫），栈型由「找更大还是更小」定（更大配递减、更小配递增）**。

两种视角的关系：同一个问题（如向右找第一个更大）两种做法都对——右到左扫是「取答案」型（P5788 实战），左到右扫是「记答案」型（damo.cpp 注释段）。前者按输入顺序天然正序填答案数组，后者在弹栈时填、天然也是正序。选择全看个人习惯与题目附带需求（要间隔数只能用「记答案」型，见 K-3⑥）。

**③ 具体例子**

`[3, 1, 4, 2]` 求每个数**向左第一个更大**，左到右 + 递减栈 + 取答案：

```text
i=1 (3)：栈空            ans[1] = -1（无）    栈：[3]
i=2 (1)：栈顶 3 > 1      ans[2] = 3           栈：[3, 1]
i=3 (4)：弹 1、弹 3，空  ans[3] = -1（无）    栈：[4]
i=4 (2)：栈顶 4 > 2      ans[4] = 4           栈：[4, 2]
答案：-1 3 -1 4
```

同一问题换「记答案」型（右到左 + 递减栈）会得到同样结果，只是填答案的时机移到弹栈瞬间——两条路线殊途同归。

**④ 边界与失效**

- 表格八行是**速查工具**，不是八种独立算法——全部由 K-1 模型 + 两个自由度（方向、严格性）生成。背表不如会推：方向规则、栈型规则各一句（见 ②）。
- 两种视角**不要混写**在同一趟循环里（又查栈顶又弹栈记答案），逻辑容易缠绕；选定一种写到底。

**⑤ 疑问与误解**

**左到右和右到左扫出的栈，为什么方向反着配？**

因为「答案在哪边，就从哪边开始扫」。向右找答案时从右往左扫（P5788）：处理到 i 时，栈里是 i 右边全部待定元素，它们对 i 而言「近的在上」。向左找答案则从左往右扫。反方向扫不是不行，但要等元素离场（弹栈）才有答案，就变成了「记答案」型。方向选择本质是**决定谁是供给方（入栈待定）、谁是结算方（触发弹栈）**。

初学者最易错的三个点：

> [!caution]
> **【易错】** 方向配反（向右找答案却从左往右「取答案」）→ 查到的栈顶全是左边的元素 → 按口诀核一遍方向再动笔。

> [!caution]
> **【易错】** 找更大却维护了递增栈 → 永远弹不停或答案错 → 更大配递减、更小配递增。

> [!caution]
> **【易错】** 「不存在」的哨兵值题目说 0 却输出 -1 → 对照题目要求（P5788 用 0，damo 用 -1）。

**⑥ 迁移检验**

> [!note]
> **【补充】** 题目（自编）：不写代码，口答四问——(a) 向左找第一个更小，用哪套组合？(b) 向右找第一个更小呢？(c) 两题的弹栈条件各是什么（含严格性）？(d) 各举一个 4 元素数组手推验证。

建议先独立做，再对照题解。

题解：(a) 左到右 + 递增栈 + 取答案；(b) 右到左 + 递增栈 + 取答案（或左到右 + 递增栈 + 记答案）。(c) 找更小、严格版：弹栈条件写 `>=`（弹掉所有不小于自己的，留严格更小）。(d) 用 `[2, 5, 3, 3]` 验证：注意两个 3 相等，按严格更小，3 的右边没有更小的（另一个 3 不算），答案为 0——这一步就是 0-4-2 严格性的落点。

### K-5　模板题 P5788：右侧第一个更大元素

**① 核心定义**

P5788【模板】单调栈（洛谷）：给定 $n \le 3 \times 10^6$ 的排列，输出每个数右侧第一个比它大的数的**下标**，不存在输出 0。这是单调栈的基准题，采用「右到左 + 递减栈 + 取答案」组合。

| 操作 | 复杂度 | 前提 | 返回值 |
|------|--------|------|--------|
| 整体求解 | $O(n)$ | 无（任意序列可用） | 每元素的下标答案 |
| 单步（入栈含弹栈） | 均摊 $O(1)$ | — | — |

**② 逐步推导**

为什么选右到左扫：答案在右边，从右边开始扫，处理到 i 时栈里恰好是 i 右侧的全部「待定元素」（0-4-3 存下标）。它们底到顶递减，弹掉所有 $\le a[i]$ 的之后，栈顶就是 i 右边第一个严格更大的（0-4-2：`<=` 弹保证严格）。记 `ans[i] = s.top()`，再把 i 入栈，等左边的人来结算 i。

设计动机（为什么弹栈条件必须是 `a[s.top()] <= a[i]`）：题目要**严格更大**。若用 `<`，相等元素会留在栈里，查到的「更大」可能只是相等；`<=` 把相等的也弹掉，留下的栈顶必然严格大于 a[i]。

**③ 具体例子**

样例 `n=5, a = [1, 4, 2, 3, 5]`（下标 1..5），从右往左：

| i | a[i] | 弹栈过程 | ans[i] | 栈（底→顶，存下标） |
|---|------|---------|--------|---------------------|
| 5 | 5 | 栈空，不弹 | 0 | [5] |
| 4 | 3 | a[5]=5 > 3 不弹 | 5 | [5, 4] |
| 3 | 2 | a[4]=3 > 2 不弹 | 4 | [5, 4, 3] |
| 2 | 4 | a[3]=2≤4 弹；a[4]=3≤4 弹；a[5]=5>4 停 | 5 | [5, 2] |
| 1 | 1 | a[2]=4 > 1 不弹 | 2 | [5, 2, 1] |

输出 `2 5 4 5 0`，与洛谷期望一致（已通过本地编译验证：`g++ -std=c++17 -O2`，样例输出逐字吻合）。

代码取自源文件 P5788.cpp（逻辑一致，仅重排注释）：

```cpp
#include <iostream>
#include <cstdio>
#include <stack>
using namespace std;
int n;                  // n <= 3e6
int a[3000005];
stack<int> s;           // 存下标（0-4-3）
int ans[3000005];       // ans[i]：a[i] 右边第一个更大元素的下标

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++) scanf("%d", &a[i]);
    for (int i = n; i >= 1; i--) {           // 右到左（K-4 表）
        while (!s.empty() && a[s.top()] <= a[i])  // <= 保证"严格更大"（0-4-2）
            s.pop();
        ans[i] = s.empty() ? 0 : s.top();    // 边界：不存在输出 0
        s.push(i);
    }
    for (int i = 1; i <= n; i++) printf("%d ", ans[i]);
    return 0;
}
```

// 边界：ans 初值由「栈空」分支统一给 0，不必 memset。
// 复杂度：均摊 O(n)（0-4-1）；3e6 规模必须 O(n)，O(n^2) 必超时。
// 相对源文件的改动：cin/cout 改 scanf/printf（3e6 规模快读不是可选项）；循环体加注释；其余逻辑一致。

**④ 边界与失效**

- $n = 3 \times 10^6$：数组开 `3000005`（源码如此），cin/cout 不关同步流大概率超时，源码情境下建议 scanf。
- 单调递增序列 `[1,2,3,4,5]`：从右往左扫时每次弹空，ans 全 0（每人右边都没有更大），正确。
- 单调递减序列 `[5,4,3,2,1]`：无人被弹，ans[i] = i+1，正确。

**⑤ 疑问与误解**

**为什么 P5788 用 `<=` 弹栈，damo.cpp 注释段却用 `<`？**

不是随缘。P5788 要「严格大于」，`<=` 把相等的弹掉才留得下严格更大者；damo 注释段那版若题目语义是「大于等于」，`<` 才对。判别法只有一句：**弹栈条件 = 「不满足你要找的那种大小关系的栈顶」**。找严格更大 → 「≤ 自己」的全部弹走；找 ≥ → 「< 自己」的才弹。

初学者最易错的三个点：

> [!caution]
> **【易错】** 数组开小（开成 1e5 级别）→ 3e6 数据直接 RE → 看清数据范围再开数组。

> [!caution]
> **【易错】** 用 cin/cout 不加 `ios::sync_with_stdio(false)` → 3e6 规模 IO 超时 → 换 scanf/printf 或关同步。

> [!caution]
> **【易错】** 「不存在」输出 -1 → P5788 规定输出 0 → 每题核对哨兵值。

**⑥ 迁移检验**

> [!note]
> **【补充】** 题目（取自源文件 damo.cpp）：n ≤ 100，向左找第一个比自身大的**数**（值），不存在输出 -1。

建议先独立做，再对照题解。

题解（damo.cpp 主代码，逻辑一致）：左到右 + 递减栈 + 存值 + 取答案：

```cpp
for (int i = 1; i <= n; i++) {
    while (!s.empty() && s.top() <= a[i]) s.pop();  // 递减栈；<= 保严格更大
    ans[i] = s.empty() ? -1 : s.top();
    s.push(a[i]);
}
```

与 K-5 主线的差别全在对照表里：方向换（右到左 → 左到右）、存法换（下标 → 值）、哨兵换（0 → -1）。维护骨架一行未变——这就是「一套模板，八种组合」的含义（已通过本地编译验证）。

### K-6　应用题 LC42 接雨水

**① 核心定义**

LeetCode 42 接雨水：n 根宽度为 1 的柱子（高度数组 h），下雨后能接多少水。单调栈解法是**按横向逐层切水**：每根柱子入栈（存下标，递减栈），当一个更高的柱子到来时，栈顶形成凹槽，弹栈结算这一层的水。

| 操作 | 复杂度 | 前提 | 返回值 |
|------|--------|------|--------|
| 单次凹槽结算 | $O(1)$ | 弹栈后栈非空 | 该层水量 h*w |
| 整体求解 | $O(n)$ | 高度非负 | 总水量 |

**② 逐步推导**

模型（接 K-1 的待结算账单）：递减栈里存的是「还没等到右帮柱的柱子下标」。新柱 i 比 a[s.top()] 高的瞬间，凹槽出现了：**旧栈顶 top 是凹槽底**，弹出它之后**新栈顶 ntop 是左帮柱**，**i 是右帮柱**。

为什么是这三根柱子？凹槽底 top 之所以还在栈里，说明它左边的 ntop 比它高（递减栈，越往底越高）；它至今没被弹，说明它右边直到 i 之前都不超过它；现在 i 比它高——top 上方的空间左右两壁分别是 ntop 和 i，这就是一横层水。

推导水量公式：这一层水的高度受**较矮的帮柱**限制（水从矮的一侧溢出），$h_{水} = \min(h[i], h[ntop]) - h[top]$；宽度是两帮柱之间的净空，$w = i - ntop - 1$（两端帮柱自身不占水）。课件第 6 页给出的正是这两个式子。

设计动机（为什么栈存下标）：宽度是**位置差**（K-3 的分水岭），值差算不出宽度；凹槽底、左右帮柱的高度又要随时 `a[]` 查——下标两者兼得。

> [!important]
> **【重点】** 弹栈结算三步：`top = s.top(); s.pop();`（凹槽底出栈）→ 若栈非空，`ntop = s.top()`（左帮柱）→ `sum += (min(h[i], h[ntop]) - h[top]) * (i - ntop - 1)`。

**③ 具体例子**

小样例 `h = [3, 0, 2]`（下标 0..2），手推：

```text
i=0：栈空，push 0                 栈：[0]（值3）
i=1：h[1]=0 < h[0]=3，push 1      栈：[0,1]（值3,0）
i=2：h[2]=2 > h[1]=0：
     弹 1（top=1，凹槽底）
     新顶 ntop=0（左帮柱，值3）
     h = min(2, 3) - 0 = 2；w = 2 - 0 - 1 = 1；sum += 2
     h[2]=2 > h[0]=3 假，停止弹栈
     push 2                        栈：[0,2]
总水量 = 2
```

（位置 1 的水从高度 0 积到 2，左壁 3 右壁 2，恰好 2 个单位。）

弹栈结算的流程（本篇唯一的流程图，文字版在下方）：

```mermaid
flowchart TD
    A[新柱 i 到来] --> B{栈非空且 h[i] > h[栈顶]?}
    B -- 否 --> F[push i, 处理下一根]
    B -- 是 --> C[top 出栈 = 凹槽底]
    C --> D{栈非空?}
    D -- 空 --> F
    D -- 非空 --> E[ntop = 新栈顶<br/>sum += min h i, h ntop - h top * i - ntop - 1]
    E --> B
```

文字版推导链：新柱更高 → 说明旧栈顶上方出现凹槽 → 弹出凹槽底 → 若还有更矮间隔的左帮柱则算一层水（短板定高、下标差定宽）→ 继续看新栈顶是否也构成凹槽 → 直到栈顶不矮于新柱 → 新柱入栈等待自己的右帮柱。

代码取自源文件 LC42.cpp（逻辑一致，仅调格式）：

```cpp
#include <iostream>
#include <vector>
#include <stack>
using namespace std;

int trap(vector<int>& height) {
    stack<int> s;                    // 存下标（宽度是位置差，K-3）
    long long sum = 0;
    int n = height.size();
    for (int i = 0; i < n; i++) {
        while (!s.empty() && height[i] > height[s.top()]) {
            int top = s.top(); s.pop();          // 凹槽底出栈
            if (!s.empty()) {                    // 边界：左帮柱必须存在
                int ntop = s.top();
                int h = min(height[i], height[ntop]) - height[top];
                int w = i - ntop - 1;
                sum += 1LL * h * w;              // 复杂度：单层 O(1)
            }
        }
        s.push(i);
    }
    return (int)sum;
}

int main() {
    int n, x; vector<int> h;
    cin >> n;
    for (int i = 1; i <= n; i++) { cin >> x; h.push_back(x); }
    cout << trap(h) << endl;
    return 0;
}
```

// 边界：弹栈后栈空（左边没有帮柱）时该层接不了水，直接跳过。
// 复杂度：均摊 O(n)（0-4-1）。
// 相对源文件的改动：sum 类型 int 改 long long 并在累加处显式 1LL 乘（防大数溢出）；补 <vector> 头文件源文件已有；其余逻辑一致。
// 实测：样例 [0,1,0,2,1,0,1,3,2,1,2,1] 输出 6，与 LeetCode 期望一致（g++ -std=c++17 -O2 通过）。

**④ 边界与失效**

- 全单调序列（递增或递减）不形成任何凹槽，答案 0——栈形全程无弹或有弹无左帮。
- $n \le 2 \times 10^4$（LeetCode 原题）水总量最坏约 $n \times \max h \approx 2 \times 10^4 \times 10^5$，int 能装；竞赛放大规模时用 long long（见代码改动注记）。
- 反例（公式误用）：`h = [3, 0, 2, 3]`，若把宽度写成 `i - top - 1`（用了凹槽底而非左帮柱）会多算——宽度恒以**两帮柱**下标计。

**⑤ 疑问与误解**

**横向一层层切，会不会漏掉或重复计同一格水？**

不会。每个格子的水，恰好在「它的右帮柱到来、凹槽底出栈」那一次被计入。凹槽底 top 出栈时算的是 top 这一层、ntop 与 i 之间的水；top 与 ntop 之间若还有更低洼处，它们作为更早入栈、更晚弹出的元素，会在同一轮 while 的后续迭代里各自结算自己的层。每层结算权唯一，总量不重不漏。

初学者最易错的三个点：

> [!caution]
> **【易错】** 弹栈后直接取 `s.top()` 不判空 → 无左帮柱时 RE → 先判 `!s.empty()` 再取 ntop。

> [!caution]
> **【易错】** 高度用 `h[top]`（凹槽底）当帮柱 → 算出负高度或错量 → 帮柱是 i 和 ntop，top 是底。

> [!caution]
> **【易错】** 弹栈条件写成 `>=`（相等也弹）→ 相等高度的相邻柱被误判为凹槽右壁 → 此处找「更高右壁」用严格 `>`（与 0-4-2 的方向相反，注意区分：这里弹栈条件描述的是「入栈触发结算」，不是「边界查找关系」）。

**⑥ 迁移检验**

> [!note]
> **【补充】** 题目（自编，原型为 LeetCode 84 柱状图中最大的矩形）：n ≤ 1e5 根宽 1 的柱子，选一段连续区间并截取高度 h，使矩形面积 `区间长度 × h` 最大，h 不超过区间内最矮柱。求最大面积。输入：第一行 n，第二行 n 个高度。

建议先独立做，再对照题解。

题解：与接雨水同款「弹栈结算」骨架，只是结算量换了——每根柱子作为**最矮柱**统治的宽度，右边界是「第一个比它矮的柱子 i」（弹栈触发），左边界是「弹掉它之后的新栈顶 ntop」（左边第一个比它矮者），面积 = `h[top] * (i - ntop - 1)`。核心循环：

```cpp
for (int i = 0; i <= n; i++) {      // 常用技巧：i=n 时视 h=0，强制清栈结算剩余
    int cur = (i == n) ? 0 : h[i];
    while (!s.empty() && cur < h[s.top()]) {
        int top = s.top(); s.pop();
        int left = s.empty() ? -1 : s.top();
        ans = max(ans, h[top] * (i - left - 1));
    }
    s.push(i);
}
```

与接雨水对照：凹槽水量是 `短板高 × 宽`，矩形面积是 `结算柱高 × 宽`——**弹栈时机相同（边界元素出现），结算公式随题意变**。这就是单调栈应用题的通用心法：栈负责找边界，公式你自己写。
