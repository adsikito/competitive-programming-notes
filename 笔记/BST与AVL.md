## 一、为什么需要它

先看一个具体场景：你要维护一个动态集合，$n \le 10^5$ 个 key 依次插入，中间穿插 $10^5$ 次查找，且数据近似有序（竞赛里极常见：按时间戳输入）。用数组存、每次线性扫——单次查找 $O(n)$，总共 $10^{10}$ 次，必超时。改用二叉搜索树（BST），平均每次 $O(\log n)$，看起来稳了——但数据有序时 BST 每个新结点都插到最右下角，整棵树退化成一条链（B 源 p3：序列 A={1,2,3,4,5,6} 构造出右斜树），查找回到 $O(n)$，总复杂度 $O(n^2) = 10^{10}$，照样超时。**碰壁的根源：树高失控，查找次数 = 树的深度（B 源 p1），链形树深度就是 n。**

破法分两步：先吃透 BST 的走位逻辑与三操作（知识点 1、2），再亲眼确认退化有多致命（知识点 3），最后用 AVL 的"平衡因子 + 旋转"把树高摁回 $O(\log n)$（知识点 4），末尾定位竞赛里何时直接用现成工具（知识点 5，延伸）。

## 二、知识点逐讲（每个知识点一节，共 5 节）

### 1. BST 定义与中序有序性

前置依赖：[[二叉树结构篇]]（二叉树、链式存储、中序遍历）
后续衔接：[[#2. 查找、插入与删除三情形]]、[[#3. 顺序插入退化反例]]

**① 它解决什么问题**

BST（Binary Search Tree，B 源 p1：也叫二叉排序树、二叉查找树）是在二叉树上加三条规则（B 源 p1）：左子树不空则左子树**所有**结点值小于根；右子树不空则右子树**所有**结点值大于根；左右子树各自又是 BST。它解决的问题：在动态集合上同时要"查找快"和"插入/删除也快"——数组查找快插入慢，链表反之，BST 两者都取 $O(h)$，$h$ 是树高。关键性质表（融入正文）：查找 / 插入 / 删除均为 $O(h)$；中序遍历输出升序序列（B 源 p1"二叉排序树的中序遍历，就是一个从小到大排好序的序列"）；前提是三条规则在每次操作后都被保持。

**② 直觉理解**

> [!tip]
> **【类比】** 模型级类比：**查字典**。翻到中间一页，要找的词靠前就丢掉右半本、往左半边翻，靠后就往右——每一步排除一整半。BST 的每个结点就是一次"翻页"，左子树=前半本、右子树=后半本。这个模型同时管住查找（顺着规则走）与插入（新词按同样规则走到空位放下）。

用具体数字跑一遍（B 源 p1 样例序列 8 3 10 1 6 14 4 7 13）：建好的树里查 6——8 比 6 大往左到 3，3 比 6 小往右到 6，命中。两次比较就从 9 个数里定位了目标，而线性扫要 5 次。

**③ 原理与推导**

推导"中序遍历为什么恰好升序"：中序 = 中序(左子树) + 根 + 中序(右子树)。按规则，左子树所有值 < 根 < 右子树所有值；对左右子树递归用同一结论（数学归纳：最底层空树的中序是空序列，空序列满足"升序"，归纳基座成立），得到"升序段 + 根 + 升序段"且根的值夹在两段之间——整体升序。

**设计动机**：为什么规则约束的是"子树**所有**结点"而不是"左右孩子"？反例：根 8、左孩子 10、10 的左孩子 9——孩子层面 10>8 只违反第一条，若只约束孩子，9 与 8 的关系无人管辖；约束到整棵子树后 9<8 不成立，树自动被排除。这条全序约束正是"每步排除一半"（查字典模型）的合法性来源。

查找走位（B 源 p1 给出递归与非递归两种写法）：

```text
查找 6：        8                第1步：6<8 → 左
             /    \
            3      10          第2步：6>3 → 右
           / \       \
          1   6       14       第3步：6==6 → 命中
             / \     /
            4   7   13
文字版推导链：每一步与当前结点比较，小则进左子树、大则进右子树、等则返回；走不到头（遇空）即不存在。比较次数 = 走过的层数，最坏等于树的深度（B 源 p1）。
```

**④ 代码演示**

块一"核心代码"——结点结构与查找两版，取自源文件 二叉排序树代码.c（改动：仅统一缩进与加注释，逻辑逐行原样）：

```c
typedef struct BSTNode {
    int data;
    struct BSTNode* l;
    struct BSTNode* r;
} BSTNode, *BSTree;
// 递归版 Find1（素材原样）：空树返回 NULL；命中返回结点
BSTNode* Find1(BSTree root, int x) {
    if (root == NULL || root->data == x) return root;   // 边界：空树，防止下一行取空指针
    if (x < root->data) return Find1(root->l, x);       // 小 → 左半本
    else return Find1(root->r, x);                      // 大 → 右半本
}
// 非递归版 Find2（素材原样）：循环走位，无函数调用开销
BSTNode* Find2(BSTree root, int x) {
    BSTNode* p = root;
    while (p != NULL && p->data != x) {
        if (x < p->data) p = p->l;
        else p = p->r;
    }
    return p;
}
// 复杂度：两版均 O(h)，h 为树高；非递归版在深树上避免递归栈开销
```

块三"错误写法对照"——查找忘判空先取值：

```diff
- while (p->data != x) { if (x < p->data) p = p->l; else p = p->r; }   // 坑1：不判 p==NULL 就解引用，查不存在的值走到空指针 → RE
+ while (p != NULL && p->data != x) { ... }   // 素材原样：&& 短路，先空判断后取值
- if (x <= p->data) p = p->l; else p = p->r;   // 坑2（虚构示意）：等值也走左，命中分支丢失 → 查存在的值也返回 NULL（答案错）
+ if (x < p->data) p = p->l; else p = p->r;   // 小走左、等命中、大走右，三分支齐全
```

**⑤ 典型应用**

- 自编迁移题：给定乱序数组，问"比 x 小的数有多少个"。思路：数组先建 BST，查找路径上每向右走一步，左子树整棵都小于 x，累加左子树大小 + 1（需在结点里多存子树大小，标注：自编，无素材源码）。它考的就是本知识点"路径排除一半"的性质。
- 真题背景（资料未覆盖，属补充，题号真实）：洛谷 P3369【模板】普通平衡树，其"查排名"操作正是上述套路，学到知识点 5 可回头验证。

**⑥ 坑点与边界**

> **【易错】** 先解引用后判空（④坑 1）→ RE；条件写成 `<=`（④坑 2）→ 命中分支丢失，WA。

> **【注意】** 重复值去哪：素材代码（Insert1/Insert2、Find1/Find2）的分支都是 `x < root->data` 走左、**否则**走右——相等值进右子树。这不是疏漏，是素材的统一约定；你若改成"相等走左"，全篇代码的走位方向都要同步，中序有序性才不破坏。

> **【注意】** 同一批值、不同插入顺序，建出的树形不同（如 8 3 10 与 3 8 10），但中序都是同一个升序序列——树形不唯一、有序性唯一。这是知识点 3 退化的伏笔。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0，root=NULL → Find1 直接命中第一个条件返回 NULL（预期：返回 NULL，不崩溃）。
> 2. 单结点：只插 8，查 8 → 一次比较命中；查 9 → 一次比较后 p=NULL 返回 NULL（预期：命中/未命中各一次比较）。
> 3. 全相同：连插 5 个 8 → 按素材约定全进右子树，连成右链 8→8→8→8（预期：不崩；若题目语义是"集合"则应去重，此为约定差异）。
> 4. 严格递增：插 1..5 → 全走右，退化为链（预期：见知识点 3 全文，此处仅验证走位方向）。
> 5. 严格递减：插 5..1 → 全走左，退化为左斜链（预期：查 1 一次命中，查 5 需 5 次比较）。
> 6. 极值：插 INT_MAX(2147483647) → data 为 int 可存；比较逻辑无加减运算，无溢出点（预期：正常插入；若你在结点里维护"区间和"之类信息则必须 long long）。

回扣开场：BST 让"动态集合 + 查找"平均 $O(\log n)$，查字典模型成立的前提是每步真排除一半——下一节把插入与删除也纳入这个模型。

### 2. 查找、插入与删除三情形

前置依赖：[[#1. BST 定义与中序有序性]]、[[链表]]（指针摘接的同一套手法）
后续衔接：[[#3. 顺序插入退化反例]]、[[#4. AVL 平衡因子与四种旋转]]

**① 它解决什么问题**

插入（B 源 p2"插入的新节点都是在叶节点位置"）：按查找走位走到空位，把新结点挂上——插入位置必是叶。删除（B 源 p2-p3）按被删结点的度分三情形：叶子直接摘；度为 1 让唯一孩子顶替；度为 2 不能直接摘（两个孩子会断线），用它的**中序前驱或后继**的值覆盖它，再去删那个前驱/后继——而前驱/后继至多一个孩子，问题降级回前两种情形。复杂度：插入、删除都由"查找走位 + 常数次指针改动"组成，均 $O(h)$。为什么设计成这样：三种情形全覆盖"摘掉一个结点后左右关系仍然合法"的全部可能，没有第四种。

**② 直觉理解**

继续用查字典模型：插入=新词条按查词路径走到空页放下（天然落叶）；删除分三种身份——整条词条（叶）直接撕；只带一个分册的（度 1）让分册顶上原位；两个分册都有的总词条（度 2）不能撕，取"左半本最后一个词"（中序前驱）或"右半本第一个词"（中序后继）抄到原位顶替，然后去半本里撕那个词——那边它必是前两种简单身份。

**③ 原理与推导**

推导"度 2 结点为什么用前驱/后继替换"：设被删结点 A 有两孩子，需要一个值 B 满足"左子树所有值 < B < 右子树所有值"。A 的中序前驱（左子树最右结点）恰是"小于 A 的最大值"，中序后继（右子树最左结点）恰是"大于 A 的最小值"——两者都满足夹逼条件，其他值都不保证。而"左子树最右结点"再无右孩子（否则还能更右），所以它至多一个孩子，替换后必落入情形 1/2。**设计动机**：不是随便抄个值都行——替换必须同时保住"对左子树仍是最大、对右子树仍是最小"，否则三条规则破一条。

删除三情形文本图（素材 Delete2 用后继版；Delete1 用前驱版，两版等价见 A-3）：

```text
情形1 叶子:     3           情形2 度1:    3            情形3 度2:     3
             /    \                    /    \                    /    \
            1      6                  1      6                  1      6
                    \                          \                / \      \
                     7                         7               2   5      7
删 1：摘叶，父左指空     删 3：孩子 6 顶上         删 3：后继 4 抄到根，去右子树删 4（叶）
（预期结构：均保持 左<根<右）
文字版推导链：情形1/2 只动一条父指针；情形3 = 一次值覆盖 + 一次降级删除，指针改动仍有限次，总代价 O(h)。
```

**④ 代码演示**

块一"核心代码"——非递归插入 Insert2 与递归删除 Delete2，取自源文件 二叉排序树代码.c（改动：删去素材中与主线重复的 Insert1/Delete1 及 printf 提示行，其余逻辑逐行原样；Insert1 递归版见知识点 3 对照）：

```c
// 插入（素材 Insert2 原样）：走到空位挂新结点
BSTree Insert2(BSTree root, int x) {
    if (root == NULL) return CreateNode(x);       // 边界：空树，新结点即根
    BSTNode *p = root, *pre = NULL;
    while (p != NULL) { pre = p;                  // pre 记录父亲
        if (x < p->data) p = p->l; else p = p->r; // 复杂度：O(h)
    }
    BSTNode* s = CreateNode(x);                   // p 为空时 pre 恰是 x 的父亲
    if (x < pre->data) pre->l = s; else pre->r = s;
    return root;
}
// 删除（素材 Delete2 原样）：递归，三情形
BSTree Delete2(BSTree root, int x) {
    if (root == NULL) return root;                // 边界：不存在，原样返回
    if (x < root->data) root->l = Delete2(root->l, x);
    else if (x > root->data) root->r = Delete2(root->r, x);
    else {
        if (root->l != NULL && root->r != NULL) { // 情形3：度2
            BSTNode* t = root->r;
            while (t->l != NULL) t = t->l;        // 右子树最左 = 后继
            root->data = t->data;                 // 值覆盖
            root->r = Delete2(root->r, t->data);  // 降级删除后继
        } else {                                  // 情形1/2：孩子顶替
            BSTNode* p = root;
            if (root->l != NULL) root = root->l; else root = root->r;
            free(p); p = NULL;
        }
    }
    return root;                                  // 素材注释：注意 返回新树
}
```

块二"执行追踪表"——用样例树 8(3(1,6(4,7)),10(R14(13))) 连删三个值（与附录 B-5 断言 2b 同数据，实测通过）：

|:---:|:---:|:---|:---|:---|
| 1 | 删 1（叶子） | 8(3(1,6(4,7)),10(R14(13))) | 情形1：父 3 左指针置空 | 8(3(R6(4,7)),10(R14(13))) |
| 2 | 删 10（度1） | 同上 | 情形2：右孩子 14 顶替父位 | 8(3(R6(4,7)),14(13)) |
| 3 | 删 3（度2） | 8(3(R6(4,7)),14(13)) | 情形3：后继=右子树最左=4，值覆盖；再删右子树中的 4（叶子，降级情形1） | 8(4(R6(R7)),14(13))，中序 4 6 7 8 13 14 |

块三"错误写法对照"：

```diff
- if (root->l != NULL && root->r != NULL) { free(root); }   // 坑1：度2直接 free → 两棵子树整体丢失，后续遍历走到野指针（RE），且丢数据（答案错）
+ BSTNode* t = root->r; while (t->l != NULL) t = t->l;      // 对：先找后继，值覆盖再降级删除
- BSTNode* p = root; root = root->l; free(p); return root;   // 坑2：漏掉 root->r 为空的分支，度0/度1 合并判断写反 → 唯一孩子是右孩子时顶了个空（答案错）
+ if (root->l != NULL) root = root->l; else root = root->r; // 对：左在取左，否则取右（右可能也为空，恰好覆盖叶子）
- free(p); InOrder(p);   // 坑3：free 后继续使用 p（use-after-free）→ 未定义行为（RE）
+ free(p); p = NULL;     // 素材原样：置空防误用
```

**⑤ 典型应用**

- 自编迁移题：向空 BST 依次插入 8 3 10 1 6 14 4 7 13，输出删除任意 x 后的中序。思路：Insert2 建树 + Delete2 删除 + InOrder 输出，正是素材 main 的完整流程（素材文件尾部注释即此样例输入），三情形各验一遍即满分。
- 场景题（自编）：BST 上同时支持"插 id、删 id、查最小剩余 id"——查最小 = 从根一路向左（B 源 p2"一直往左查找最左边的节点，就是最小值"），$O(h)$。

**⑥ 坑点与边界**

> **【易错】** 度 2 结点直接 free（④坑 1）——子树丢失既是 RE 又是 WA，双重错误。

> **【易错】** 递归删除忘记 `return root`。素材源码在函数尾与递归调用处都显式 `root->l = Delete2(root->l, x)` 接住新子树；漏接一次，被删结点的父亲就悬空（RE）。

> **【注意】** 前驱版（Delete1）与后继版（Delete2）删出的树形不同但中序一致（A-3 登记 1）；同一份代码里不要混用两种找法，否则树形不可预测，调试时对不上手推图。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空树删 5 → 素材 Delete2 首行 root==NULL 原样返回（预期：无变化，不崩）。
> 2. 单结点：只插 8 后删 8 → 度 0，root=root->r 即 NULL，free 原根（预期：树空，中序无输出）。
> 3. 全相同：插 3 个 8 后删 8 → 相等值进右子树的约定下，后继是下一层 8，删的是右下那颗（预期：中序仍有序 8 8；语义若需去重要另判）。
> 4. 严格递增：插 1..5 后删根 1 → 根度 1，右孩子 2 顶上（预期：1 2 3 4 5 中序变 2 3 4 5）。
> 5. 严格递减：插 5..1 后删 3 → 中间结点度 2，后继 4 覆盖再删叶（预期：中序 1 2 4 5）。
> 6. 极值：对 10^5 结点树连续删 10^5 次 → 每次 O(h)，链形最坏 O(n^2)；AVL 保证 h=O(log n)（预期：知识点 4 的动机之一）。

回扣开场：插入与删除都压在 $O(h)$ 上——$h$ 一旦失控，三操作全部陪葬。下一节专门看 $h$ 失控的最坏现场。

### 3. 顺序插入退化反例

前置依赖：[[#1. BST 定义与中序有序性]]、[[#2. 查找、插入与删除三情形]]
后续衔接：[[#4. AVL 平衡因子与四种旋转]]

**① 它解决什么问题**

它不是一个新操作，而是一个必须亲眼看到的失败案例：数据有序或接近有序时，BST 退化为单链表。B 源 p3 原文：序列 A={1,2,3,4,5,6} 依序构造 BST 得到右斜树，"同时二叉树退化成单链表，搜索效率降低为 O(n)"。复杂度账：n 个升序 key 依次插入，第 i 个要走 i-1 步，总代价 $\sum_{i=1}^{n}(i-1) = \frac{n(n-1)}{2}$，即 $O(n^2)$；$n=10^5$ 时约 $5\times10^9$ 次比较，必超时。**为什么平均 $O(\log n)$ 救不了它**：平均是对"随机插入顺序"而言的，有序输入恰好是让每步只排除一个元素的最坏顺序——查字典模型退化成"从第一页往后一页页翻"。

**② 直觉理解**

查字典模型的失效版：如果字典的词恰好按字母序从第一页排到最后一页，而你还按"翻中间页"的规则找——每次翻到的那页只比目标小一点点，每次只前进一页。BST 的每一步走位仍然"正确"，只是树的结构让每步只排除一个结点。

**③ 原理与推导**

推导退化过程：升序插入时，每个新值都大于当前树里所有结点，走位在每一层都满足"新值 > 当前结点"，全部进右孩子；递归到空位挂上。于是第 i 个插入必然落在第 i 层——树高 = n。实测（附录 B-5 断言 2）：升序插入 1..16，树高恰为 16；同样 1000 个 key，AVL 建完树高只有 10（断言 3），差距 100 倍。**设计动机视角**：树形完全由插入顺序决定（知识点 1 的"树形不唯一"推论），BST 本身没有任何机制抵抗坏顺序——这正是 AVL（知识点 4）要补的那块。

```text
升序插入 1..5：
1
  \
    2
      \
        3
          \
            4
              \
                5
文字版推导链：每个新值全走右分支，树高 = 结点数；查找 5 需比较 5 次，n 个结点最坏比较 n 次（B 源 p3"搜索效率降低为 O(n)"）。
```

**④ 代码演示**

块一"核心代码"——用递归版插入 Insert1 演示退化（取自源文件 二叉排序树代码.c，改动：仅加比较计数与警告注释；这也是素材刻意保留的递归思路版，B 源 p2"是一种递归思想"）：

```c
int cmp_cnt = 0;   // 演示用：统计比较次数
BSTree Insert1(BSTree root, int x) {
    if (root == NULL) return CreateNode(x);       // 递归出口：空位
    cmp_cnt++;
    if (x < root->data) root->l = Insert1(root->l, x);
    else root->r = Insert1(root->r, x);           // 有序数据恒走此分支 → 右斜链
    return root;                                  // 素材注释：插入之后要返回新树
}
// 复杂度：升序输入下第 i 次插入比较 i-1 次，总计 n(n-1)/2
// 警告：升序 1e5 个数用本递归版，递归深度 1e5 层 → 默认栈下栈溢出（RE）
```

块二"执行追踪表"——升序插入 1 2 3 4 5（每步结构状态即整棵树）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 1 | 空树 | 插为根 | 1 |
| 2 | 2 | 1 | 2>1 走右，遇空挂叶 | 1(R2) |
| 3 | 3 | 1(R2) | 3>1→3>2 走右 | 1(R2(R3)) |
| 4 | 4 | 1(R2(R3)) | 4>1→4>2→4>3 | 1(R2(R3(R4))) |
| 5 | 5 | 1(R2(R3(R4))) | 5>1→…→4>5 走右 | 1(R2(R3(R4(R5))))，树高 5 |

块三"错误写法对照"：

```diff
- for (i = 1; i <= 100000; i++) root = Insert1(root, i);   // 坑1：升序 1e5 个数 + 递归插入 → 递归 1e5 层，栈溢出（RE）
+ 用 AVL 的 Insert（知识点 4）或非递归 Insert2；且树高问题本身要用旋转解决，非递归只救栈不救复杂度
- printf("%d", BstHeight(root));   // 坑2（虚构示意）：以为"平均 O(log n)"意味着任何输入都 log 级，从不检查树高 → 有序数据下每次查询 O(n) 而不自知（TLE）
+ 插入完成后验一次树高：h > 2*log2(n) 就该警觉数据顺序有问题   // 防御性自查
```

**⑤ 典型应用**

- 反例即应用：这个退化场景本身就是 AVL 的"开场题"——把知识点 3 的追踪表数据（升序 1..1000，BST 树高 1000）与知识点 4 的断言数据（AVL 树高 10，附录 B-5）对照，就是"要不要学旋转"的全部理由。
- 自编迁移题：输入保证是随机排列时 BST 够不够用？——$10^5$ 随机数据期望树高约 $3\log_2 n \approx 50$，够用；但题目不保证顺序时，期望分析不作数，必须上平衡结构（标注：自编）。

**⑥ 坑点与边界**

> **【易错】** 看到"BST 平均 O(log n)"就放心用。平均的前提是插入顺序随机；有序、逆序、甚至"尾部有序段"都会造成局部退化，竞赛输入不保证随机（④坑 2）。

> **【注意】** 等值重复插入也会连右链：素材约定相等值进右子树，连插 n 个相同值同样退化为链——"数据不太随机"包括"大量重复"这一情形。

> **【注意】** 非递归 Insert2 只解决栈溢出（④坑 1 的 RE 面），树高 O(n) 的复杂度问题原样保留——两者不要混为一谈。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 无插入，树高 0（预期：cmp_cnt=0）。
> 2. 单结点：插 1 → 树高 1，cmp_cnt=0（预期：根无需比较）。
> 3. 全相同：连插 5 个 8 → 全走右，树高 5（预期：与升序等价的链）。
> 4. 严格递增：插 1..16 → 树高 16（附录 B-5 断言 2 实测），比较总数 120 = 16·15/2。
> 5. 严格递减：插 16..1 → 全走左，左斜链树高 16（预期：与递增对称）。
> 6. 极值：升序 1..10^5 用递归 Insert1 → 递归 10^5 层，默认 1MB 栈下溢出（预期：RE；改非递归可过栈但总比较约 5×10^9 次仍 TLE）。

回扣开场：碰壁的根源找到了——树高失控且 BST 无自愈机制。现在能回答"为什么光会三操作不够"，下一节引入让树高保持 $O(\log n)$ 的机制：平衡因子与旋转。

### 4. AVL 平衡因子与四种旋转

前置依赖：[[#3. 顺序插入退化反例]]、[[二叉树结构篇]]（子树、高度的概念）
后续衔接：[[#5. 竞赛定位延伸：map 与平衡树替代]]、[[二叉树竞赛篇]]

**① 它解决什么问题**

AVL 树（B 源 p3：最早的自平衡二叉查找树，以发明者 G.M. Adelson-Velsky 和 E.M. Landis 命名）：任一结点左右子树高度差绝对值不超过 1，故称高度平衡树。**平衡因子 BF = 左子树高 - 右子树高**（B 源 p3），平衡树中 BF 只取 0、1、-1。查找、插入、删除最坏都是 $O(\log n)$（B 源 p3 原文"查找、插入和删除在平均和最坏情况下的时间复杂度都是 O(logn)"）。插入或删除可能破坏平衡，"借由一次或多次树旋转实现重新平衡"（B 源 p3）——四种失衡对应四种旋法：LL 右旋、RR 左旋、LR 先左旋左孩子再右旋失衡点、RL 先右旋右孩子再左旋失衡点（B 源 p3 2.3.3 节四句定义）。

**② 直觉理解**

> [!tip]
> **【类比】** 模型级类比：**换支点**。把失衡子树看作叠歪的箱子堆——哪边高出一截，就把"低侧底下那个承重结点"提升为新支点（新根），原来的根挂到它下面；若歪的是"弯折"形（LR/RL），先把弯的那层掰直（一次反向单旋），再换支点。一个模型管住四旋：LL/RR 是直歪（换一次支点），LR/RL 是弯歪（先掰直再换）。

用具体数字跑一遍 LL（插 3、2、1）：插 3 成根；插 2 到左；插 1 到 2 的左——3 的 BF = 左高 2 - 右高 0 = 2，失衡；新值 1 在"左孩子的左边"，LL 型，对 3 右旋：2 升为根，3 变 2 的右孩子，BF 全部回到 ±1 内。

**③ 原理与推导**

以 LL 为例推导右旋为什么同时恢复平衡与有序（其余三型对称）。失衡前结构（素材 平衡二叉树代码.c 注释图同款）：

```text
右旋（LL）：    x              →      y
             /   \                 /   \
            y     xr              yl     x
          /  \                          /  \
         yl   ly                       ly   xr
文字版推导链：y 原是 x 的左孩子；旋转后 yl（y 的左子树）仍归 y，ly（y 的右子树）介于 y 与 x 之间故转挂 x 的左，x 降为 y 的右孩子。大小关系 yl < y < ly < x < xr 逐段保持 → 中序不变；高度上 y 侧减一层、x 侧加一层 → BF 回到 ±1 内。
```

**设计动机一**：为什么插入时判 LL/LR 用"新值与左孩子比大小"（素材 Insert 里 `if(a<left->data)`），而删除时改用"孙辈两侧谁更高"（素材 Delete 里 `Geth(right->r)>=Geth(right->l)`）？插入时新值位置是已知信息，直接可判；删除没有"新值"，只能看失衡点下方两层哪侧重——这解释了素材两处判定写法不同的原因（来源：平衡二叉树代码.c L93/L147 对照）。
**设计动机二**：为什么旋转函数里先更新 x 的高度再更新 y？x 已经变成 y 的孩子，算 y 高度时要用 x 的**新**高度，顺序颠倒会把旧高度抄进新根（④坑 1）。

**④ 代码演示**

块一"核心代码"——四种旋转与插入主干，取自源文件 平衡二叉树代码.c（改动：仅删去与 LL/RR 重复的大段注释、统一缩进；逻辑逐行原样，完整版含删除操作见该源文件）：

```c
typedef struct AVLNode {
    int data; struct AVLNode *l, *r;
    int h;                                    // 该结点高度（素材字段）
} AVLNode, *AVLTree;
int Geth(AVLNode* x) { return x == NULL ? 0 : x->h; }   // 空树高 0（素材原样）
AVLTree LLrotation(AVLTree x) {               // LL → 右旋
    AVLNode* y = x->l;                        // y 指向 x 的左孩子
    x->l = y->r;                              // y 的右孩子转挂 x 的左
    y->r = x;                                 // x 降为 y 的右孩子
    x->h = Maxx(Geth(x->l), Geth(x->r)) + 1;  // 先更 x（已是孩子）
    y->h = Maxx(Geth(y->l), Geth(y->r)) + 1;  // 再更 y（要用 x 新高度）
    return y;                                 // 新根
}
AVLTree RRrotation(AVLTree x) {               // RR → 左旋，与右旋镜像
    AVLNode* y = x->r;
    x->r = y->l; y->l = x;
    x->h = Maxx(Geth(x->l), Geth(x->r)) + 1;
    y->h = Maxx(Geth(y->l), Geth(y->r)) + 1;
    return y;
}
AVLTree LRrotation(AVLTree x) {               // 先对左孩子左旋（掰直），再右旋
    x->l = RRrotation(x->l);
    return LLrotation(x);
}
AVLTree RLrotation(AVLTree x) {               // 先对右孩子右旋，再左旋
    x->r = LLrotation(x->r);
    return RRrotation(x);
}
// 插入主干（素材 Insert 原样精简）：递归插入 + 回溯时逐层检查失衡
AVLTree Insert(AVLTree root, int a) {
    if (root == NULL) return CreatNode(a);
    if (a < root->data) {
        root->l = Insert(root->l, a);         // 左子树插完可能长高
        if (Geth(root->l) - Geth(root->r) > 1) {
            AVLNode* left = root->l;
            if (a < left->data) root = LLrotation(root);   // 新值在左孩子的左边：LL
            else root = LRrotation(root);                       // 在左孩子的右边：LR
        }
    } else {
        root->r = Insert(root->r, a);         // 右子树对称处理：RR / RL
        if (Geth(root->r) - Geth(root->l) > 1) {
            AVLNode* right = root->r;
            if (a > right->data) root = RRrotation(root);
            else root = RLrotation(root);
        }
    }
    root->h = Maxx(Geth(root->l), Geth(root->r)) + 1;      // 素材注释：记得更新
    return root;
}
// 复杂度：单次插入 O(log n)，旋转 O(1)（常数次指针改动）
```

块二"执行追踪表"——四型各用最小失衡例（3 结点），插入序列即触发条件（附录 B-5 断言 4 逐一实测）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| LL | 依次插 3,2,1 | 3(L2(L1))，根 BF=2 | 判 LL：1 < 左孩子 2，对 3 右旋 | 根变 2，孩子 1、3 |
| RR | 依次插 1,2,3 | 1(R2(R3))，根 BF=-2 | 判 RR：3 > 右孩子 2，对 1 左旋 | 根变 2，孩子 1、3 |
| LR | 依次插 3,1,2 | 3(L1(R2))，根 BF=2 | 判 LR：2 > 左孩子 1；先对 1 左旋成 2(R1)，再对 3 右旋 | 根变 2，孩子 1、3 |
| RL | 依次插 1,3,2 | 1(R3(L2))，根 BF=-2 | 判 RL：2 < 右孩子 3；先对 3 右旋成 2(L3)，再对 1 左旋 | 根变 2，孩子 1、3 |

样例序列 8 3 10 1 6 14 4 7 13 建 AVL 后逐结点 BF（素材 main 的 Inorder 输出格式"值 平衡因子"，实测附录 B-5）：`1 0 / 3 -1 / 4 0 / 6 0 / 7 0 / 8 1 / 10 0 / 13 0 / 14 0`——全部落在 {-1,0,1}，与 B 源 p3 的 BF 限幅一致。

块三"错误写法对照"：

```diff
- y->h = Maxx(Geth(y->l), Geth(y->r)) + 1; x->h = ...   // 坑1：先更 y 后更 x → y 算高度时用的是 x 的旧高度，新根高度错，此后所有 BF 判定连锁出错（答案错）
+ x->h = ...; y->h = ...;   // 素材原样：先孩子后新根，y 用 x 的新高度
- if (Geth(root->l) - Geth(root->r) > 1) { root = LLrotation(root); }   // 坑2：左高只判 LL 单旋，漏了 LR → 新值在左孩子的右边时右旋后依然失衡或错形（答案错）
+ if (a < left->data) root = LLrotation(root); else root = LRrotation(root);   // 素材原样：左高内再分 LL/LR
- root->h = Maxx(Geth(root->l), Geth(root->r)) + 1;   // 坑3：这行只写在无失衡分支 → 旋转分支漏更新，高度停滞，后续判定全错（答案错）
+ 该更新必须写在 return root 之前、对所有路径生效（素材原样位置）
```

**⑤ 典型应用**

- 实测账（附录 B-5 断言 3）：1..1000 连续升序插入，BST 树高 1000（知识点 3），AVL 建完树高 10、全树 BF 合法——退化反例与平衡解在同一数据上的直接对照。
- 真题（资料未覆盖，属补充，题号真实）：洛谷 P3369【模板】普通平衡树——需要"插入/删除/查排名/查第 k 小"，AVL 思想可解，实际竞赛更常用 Treap 或直接 map（见知识点 5）。完整题解超出本篇范围，此处只作定位参考。
- 自编迁移题：AVL 上查第 k 小——结点里多存"子树大小"，按左子树大小与 k 比较决定左走/右走，$O(\log n)$（标注：自编，思路与知识点 1⑤ 迁移题同源）。

**⑥ 坑点与边界**

> **【易错】** 旋转后高度更新顺序（④坑 1）与漏更新（④坑 3）。高度是 BF 的原料，原料错则全盘错；这是本知识点事故率最高的两处。

> **【易错】** LR/RL 只旋一次（④坑 2）。弯歪形必须"先掰直再换支点"，两步缺一不可；素材 LR/RL 各由两次单旋组合而成，不是独立的第三种旋法。

> **【注意】** 素材 AVL 的删除操作（平衡二叉树代码.c L125 起）思路为"按 BST 三情形删，删后沿路径逐结点查 BF，失衡即按删除侧对称旋"（B 源 p4），其旋转判定用孙辈高度比较（`>=` 时取单旋）。该段代码约 80 行且本篇断言程序未覆盖删除路径的旋转分支——这一段我不确定其在全部删除序列下无边界缺陷，正文只取其思路，完整实现建议对照源文件自行验证。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 空树，Inorder 无输出（预期：空输出不崩）。
> 2. 单结点：插 8 → 输出 `8 0`（预期：BF=0）。
> 3. 全相同：连插 3 个 8 → 相等进右子树约定下第二次插入即触发 RR 左旋（预期：根变 8(8,R8)，仍平衡；等值场景慎用 AVL，语义需先定）。
> 4. 严格递增：插 1..1000 → 树高 10、全树 BF 合法（附录 B-5 断言 3 实测，预期：不退化）。
> 5. 严格递减：插 1000..1 → 全走左，每 2 层触发一次 LL 右旋（预期：树高同为 10 量级，对称成立）。
> 6. 极值：插 INT_MAX/INT_MIN 混合 → 比较与旋转不含加减，无溢出；高度 h 字段 int 足够（2^31 层不可能达到）（预期：正常工作）。

回扣开场：碰壁场景里的有序数据插入，被"BF 限幅 + 失衡即旋"摁在 $O(\log n)$。现在你能解决开场那个 $10^{10}$ 次比较的问题了——用的是知识点 2 的三操作加知识点 4 的旋转保高。最后一节定位竞赛里何时该手写、何时用现成工具。

### 5. 竞赛定位延伸：map 与平衡树替代（延伸，非必需）

前置依赖：[[#4. AVL 平衡因子与四种旋转]]
后续衔接：[[STL容器与算法手册_复习回顾]]、[[二叉树竞赛篇]]

**① 它解决什么问题**

本节回答一个定位问题：竞赛里什么时候直接用现成的有序容器、什么时候才需要本篇的手写功底。C++ 的 `map`（底层红黑树，同为自平衡 BST 家族）一行不用写就拿到 $O(\log n)$ 的插入/删除/查找；手写 AVL 的价值在于：理解平衡机制本身（机试/面试常问）、以及需要"子树大小"这类 map 给不了的扩展信息时（排名、第 k 小）自行改造树。**本节标注：延伸，非必需**；后续知识点不再依赖它。复杂度对照：map 各操作 $O(\log n)$，与 AVL 同量级，常数略大但免实现成本。

**② 直觉理解**

查字典模型的"成品字典"版：map 就是买来的现成字典——翻页、插词条、撕词条都替你做好了；手写 AVL 是"自己装订一本按需加夹页的字典"，只有当你要在每页边缘记"这半本共多少词"（子树大小）这类自定义批注时，成品字典才不够用。

**③ 原理与推导**

设计动机：为什么竞赛默认 map 而不是手写 AVL？手写代码量 100 行上下、旋转与高度更新易错（知识点 4 的三个坑），出错成本远高于 map 的调用成本；只有当操作集合超出 map 接口（按排名访问、分裂合并等）才升级到手写平衡树，且此时竞赛主流选择是 Treap（随机优先级保证期望平衡）而非 AVL——这一段我不确定各赛场数据范围下两者的实战差异细节，只给方向不作结论。map 的中序遍历等价物：直接迭代 map，key 天然升序（有序容器的"中序有序性"由库保证）。

**④ 代码演示**

块一"核心代码"（自编演示，非素材；C++ 特性首现处附 C 等价注释）：

```cpp
#include <iostream>
#include <map>
using namespace std;                          // 等价 C：每个名字前加 std::
int main() {
    map<int, int> mp;                         // 等价 C：无直接对应，可视为"自动排序的动态数组"下标任意
    mp[8] = 1; mp[3] = 1; mp[10] = 1;         // 插入/覆盖，O(log n)
    if (mp.count(3)) cout << "find\n";        // 查找；等价 C：查哈希/自己写的 Find2
    mp.erase(3);                              // 删除，O(log n)；等价 C：手写 Delete2
    for (pair<int,int> kv : mp)               // 遍历按 key 升序（中序有序性的库版）
        cout << kv.first << " ";
    cout << "\n";                             // 输出：8 10
    return 0;
}
```

块二"执行追踪表"——同一批操作在 map 与手写 AVL 上的对应关系：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | mp[8]=1 | 空 | 红黑树插入 | {8} |
| 2 | mp[3]=1 | {8} | 插入并重平衡 | {3,8}（库内部自动旋转） |
| 3 | mp.count(3) | {3,8} | 查找 | 返回 1 |
| 4 | 遍历 | {8,10}（3 已删） | 按 key 升序访问 | 输出 8 10 |

块三"错误写法对照"：

```diff
- if (mp[5]) { ... }   // 坑1：operator[] 查不存在的 key 会自动插入 0 → "只读检查"悄悄改了集合（答案错）
+ if (mp.count(5)) { ... }   // 对：count 只查不改
- for (map<int,int>::iterator it = mp.begin(); it != mp.end(); ) { if (...) mp.erase(it++); }   // 坑2：erase(it) 后 it 已失效还继续 ++（RE）
+ mp.erase(it++);   // 对：先自增留副本再删（或用 erase 返回值）
```

**⑤ 典型应用**

- 真题（题号真实，资料未覆盖，属补充）：洛谷 P3369——前几个子任务 map 可过（插删查），"查第 k 小"超出 map 接口，对应手写平衡树的扩展字段场景；这正是"何时升级"的现成判例。
- 自编迁移题：维护一个不断增删的工资表，随时查"当前中位数"。思路：两个 map（或平衡树）对半分，各有 $\log n$ 增删与 $O(1)$ 取中（标注：自编）。

**⑥ 坑点与边界**

> **【易错】** 用 `mp[key]` 做"存在性检查"（④坑 1）—— operator[] 的副作用是自动插入，静默改变集合内容。

> **【注意】** map 的 key 唯一；需要重复 key 用 `multimap` 或 `map<int,int>` 计数（第二维存个数），与素材 BST"相等进右子树"的重复值语义不同，迁移时想清楚题目要哪种。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：无插入 → map 为空，遍历零次（预期：无输出）。
> 2. 单元素：插一个删一个 → count==0，size()==0（预期：回到空）。
> 3. 全相同：map 同 key 覆盖（预期：size 恒 1）；multimap 则累加（预期：按所选容器语义）。
> 4. 严格递增：按 1..n 插 → 库内部自平衡，遍历升序（预期：无退化问题，这正是用库的理由）。
> 5. 严格递减：同上对称（预期：升序遍历不变）。
> 6. 极值：key 取 INT_MAX → int 作 key 合法；若题目 key 超 int 范围用 long long（预期：key 类型与数据范围对齐）。

回扣开场：本篇从"动态集合查找"出发，用 BST 建立走位模型、用三操作补全增删、用退化反例逼出旋转、最后定位到 map 这条捷径。开场那个 $10^{10}$ 次比较的问题，你现在有三条路可走——map 直接过、AVL 手写保高、以及明白它们为什么都成立。

## 四、总结与自测

### 核心内容（一页纸速览）

- **BST 定义**（B 源 p1）：左子树所有值 < 根 < 右子树所有值，递归成立；查找/插入/删除均 $O(h)$。
- **中序有序性**（B 源 p1）：中序遍历 = 升序序列；树形随插入顺序变，有序性不变。
- **插入落叶、删除三情形**（B 源 p2-p3）：叶子直接摘、度 1 孩子顶替、度 2 用前驱/后继覆盖后降级删除；素材 Delete1 前驱版与 Delete2 后继版等价。
- **退化反例**（B 源 p3）：升序插入得右斜链，查找 $O(n)$、建树 $O(n^2)$；实测 1..16 树高 16。
- **AVL**（B 源 p3）：BF = 左高-右高 ∈ {-1,0,1}；LL 右旋、RR 左旋、LR 先左后右、RL 先右后左；最坏 $O(\log n)$；实测 1..1000 升序插入树高 10。
- **竞赛定位**（延伸）：默认用 map；需要子树大小类扩展（排名/第 k 小）才手写平衡树，主流选 Treap。
