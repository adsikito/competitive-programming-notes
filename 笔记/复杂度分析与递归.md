## 一、为什么需要它

先看一道你迟早会碰的壁：$n \le 10^5$ 个数，问每对数之和是否等于定值。暴力是双重循环，基本操作次数 $n^2 = 10^{10}$——按竞赛机每秒 $10^8$ 量次估算要跑 100 秒，必 TLE。更气人的是：你在自己电脑上拿 $n=100$ 的数据测，0.001 秒就出结果，"明明很快啊"。**这就是两重坑：不看增长规律会被小数据骗，只信实测会被机器骗**（素材 p2 的两个缺陷）。

复杂度分析就是给算法发的"身份证"：不跑机器，用纸笔算出操作次数随规模 $n$ 的增长量级，30 秒判断这题能不能过。而递归（递归篇 p1：函数直接或间接调用自己）是竞赛里最常用的写法，它的复杂度最容易算错——朴素的递归斐波那契是 $O(2^n)$ 级，$n=40$ 就跑不动，本篇用实测数据让你亲眼看到这个暴涨。

本篇讲 5 个知识点：复杂度为什么是身份证、大 O 记号与量级阶梯、分析法则与经典例子、递归的本质与调用栈、四类复杂度与竞赛防 TLE。顺序理由：动机（知识点 1）先于记号（知识点 2），法则（知识点 3）先于递归应用（知识点 4），实战收尾（知识点 5）。

## 二、知识点逐讲（每个知识点一节，共 5 节）

### 1. 复杂度为什么是算法的身份证：事后统计法的碰壁与时间频度

前置依赖：[[枚举与模拟]]（双重循环枚举写法）、C 语言基础（循环与计数变量）
后续衔接：[[#2. 大 O 记号与常见量级]]、[[#3. 分析法则与五个经典例子]]

**① 它解决什么问题**

素材 p1 给出好算法的标准：先要**正确**（彻底解决问题）、**健壮**（任何输入不崩溃），在此之上比**运行效率**——运行时间更短、占用内存更少。要比较效率，最直接的想法是把代码跑一遍测时间，这叫**事后统计法**（素材 p2）。但它有两个缺陷：一是**结果依赖测试环境**——同一段代码，Intel Core i9 机器就是比 i3 快，换台机器结论可能反转；二是**受数据规模影响很大**——小规模数据排序时，插入排序可能反超快排（素材 p2）。所以需要**不依赖具体测试数据的估算法**：**事前分析估算法**（素材 p2），用纸笔算。它算的量叫**时间频度** $T(n)$：算法中语句的执行次数，与算法花费的时间成正比（素材 p3）。为什么定这条：只有剥掉机器与数据的干扰，"哪个算法更快"才有公平答案。

**② 直觉理解**

模型级类比：**运费按重量段算**。比较两家物流不看某一天的路况（环境），而是看"每多一吨货多花多少钱"的增长规律——复杂度就是算法的"运费表"，自变量是数据规模。

用具体数字跑一遍：双重循环里 `cnt++` 的次数，$n=3$ 时是 $3 \times 3 = 9$ 次，$n=6$ 时是 $36$ 次，$n=12$ 时是 $144$ 次——规模翻倍、次数翻四倍，这就是 $n^2$ 的增长脾气。而单层循环 $n$ 翻倍次数只翻倍。增长规律不同，就是不同复杂度的分水岭。

**③ 原理与推导**

素材 p2 给出：程序运行时间取决于四个因素——(1) 算法采用的方法；(2) 编译产生的代码质量；(3) 问题的输入规模；(4) 机器执行指令的速度。逐个排查：因素 1 正是我们要比较的对象，因素 2 和 4 是环境（换编译器、换机器就变），因素 3 是唯一随问题变化的变量。所以素材 p2 的落点是：**从算法中选一种基本操作，以它的重复执行次数作为算法的时间量度**——这就是 $T(n)$ 只数次数、不数秒数的原因。

推导"$T(n)$ 为什么能代表快慢"（素材 p3）：语句执行次数多，花费时间就多，两者成正比；而次数是 $n$ 的确定函数，不随机器变。于是"算法 A 比 B 快"转化为"$T_A(n)$ 的增长量级低于 $T_B(n)$"，纯纸笔可判。

**④ 代码演示**

数出双层循环的基本操作次数（自编示例，对应素材 p5 的 $O(n^2)$ 例）：

```cpp
// 自编示例：数双层循环基本操作次数。改动说明：素材 p5 原为 Java 风格片段，
// 此处改写为 C++17 并加计数输出；逻辑与素材一致。
#include <cstdio>
int main() {
    long long n = 6, cnt = 0;
    for (long long i = 1; i <= n; i++)       // 循环判断执行 n+1 次（素材 p5 频度标注）
        for (long long j = 1; j <= n; j++)   // 内层体执行 n^2 次
            cnt++;                           // 基本操作：频度 n^2（素材 p5）
    printf("n=%lld cnt=%lld\n", n, cnt);     // 输出 n=6 cnt=36，复杂度 O(n^2)
    return 0;
}
```

**执行追踪表**（$n=3$，逐语句数频度）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---|:---|:---|:---|
| 1 | `sum=0` | 未进循环 | 执行 1 次 | 频度 1 |
| 2 | 外层 `for` 判断 | i=1..4 共 4 轮 | 判断执行 n+1 次 | i=4 时退出 |
| 3 | 内层 `for` 判断 | 每轮 i 配 j=1..4 | 共 3×4=12 次 | 计入 T(n) |
| 4 | `cnt++` | (i,j) 共 9 组 | 执行 9 次 | cnt=9=3^2 |

**错误写法对照**：

```diff
- 在自己电脑上跑 n=100 的数据，0.001 秒，得出"这算法能过"   // 坑1：事后统计法——n 一大结论反转，换机器也可能反转（素材 p2 两缺陷）
+ 事前分析：数基本操作次数 T(n)，看它随 n 的增长量级（素材 p2）
- "2n^2+n+1 在 n=10 时比 n^2 慢一点点，所以前者复杂度更高"   // 坑2：拿小数据的低阶项当结论——n 越大低阶项占比越小
+ 量级只看最高次幂：2n^2+n+1 与 n^2 同量级（素材 p3 化简例）
```

**⑤ 典型应用**

- 真题：洛谷 P3367【模板】并查集，$n,m \le 10^5$。暴力"改群编号"合并一次 $O(n)$，总 $O(nm)=10^{10}$ 必 TLE——正是本知识点"先算后跑"的判题应用，解法见 [[并查集与种类并查集]]。
- 真题：洛谷 P1177【模板】快速排序，$n \le 10^5$。$O(n^2)$ 排序在 $10^{10}$ 量级不可行，$O(n \log n)$ 约 $1.7 \times 10^6$ 轻松通过（量级对比，见知识点 2）。
- 迁移题（自编）：给出"单层循环求和""双重循环判相等""三重循环数三元组"三段代码，手算各自 $T(n)$ 并排量级。建议先独立做，再对照：$T_1(n)=n$ 量级 $O(n)$；$T_2(n)=n^2$ 量级 $O(n^2)$；$T_3(n)$ 约 $n^3/6$ 量级 $O(n^3)$（对应素材 p6 三重循环例）。

**⑥ 坑点与边界**

> **【易错】** 循环频度数错：`for(i=1;i<=n;i++)` 的**判断**执行 $n+1$ 次而非 $n$ 次（最后那次判断失败才退出），素材 p5 频度标注明确写了 n+1 次。对量级无影响（$n+1$ 与 $n$ 同量级），但精确计数题会错。

> **【易错】** 把"我机器上跑得快"当结论。小数据下 $O(n^2)$ 插入排序可能反超 $O(n \log n)$ 快排（素材 p2 原例），判题只认量级。

> **【注意】** 两算法复杂度相同时，常数与低阶项在的小数据上会反转胜负（素材 p2）；量级是"大规模"的判据，不是"所有规模"的判据。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 外层判断 1 次即失败，循环体零次，cnt=0（预期：输出 cnt=0，不崩）。
> 2. 单元素：n=1 → 判断 2 次，cnt++ 执行 1 次（预期：cnt=1）。
> 3. 全相同：数组全 0 不影响计数逻辑（预期：cnt 仍 n^2，与值无关）。
> 4. 严格递增：n=1,2,3,4,5 逐个跑 → cnt=1,4,9,16,25，差值 3,5,7,9（二阶差分恒 2，即 n^2 的指纹）。
> 5. 严格递减：n=5..1 → 对称同上（预期：cnt 序列逆序）。
> 6. 极值：n=10^5 → cnt=10^10 超出 int 上限（约 2.1×10^9），必须 long long，否则溢出 WA（预期：用 long long 时输出 10^10）。

回扣开场：现在你能解释"为什么 $n=100$ 测试通过不代表能过 $n=10^5$"——用的是 $T(n)$ 随规模的增长规律（本知识点 ③），接下来把这个规律压缩成一个记号。

### 2. 大 O 记号与常见量级：从频度到量级阶梯

前置依赖：[[#1. 复杂度为什么是算法的身份证]]、函数与极限的朴素直觉（n 增大时分母主导）
后续衔接：[[#3. 分析法则与五个经典例子]]、[[#5. 最好、最坏、平均、均摊与竞赛防 TLE]]

**① 它解决什么问题**

$T(n)$ 是精确次数，但精确值没必要——我们只关心**增长量级**。**时间复杂度**的定义（素材 p3）：若有辅助函数 $f(n)$，使 $n$ 趋于无穷时 $T(n)/f(n)$ 的极限为不等于零的常数，则记 $T(n) = O(f(n))$，$O(f(n))$ 称为算法的渐进时间复杂度。等价的通俗版（素材 p3 原意）：存在常数 $C$，使 $n$ 充分大时总有 $T(n) \le C \cdot f(n)$。历史（素材 p3）：Landau 记号由德国数学家保罗·巴赫曼（Paul Bachmann）在 1892 年的著作《解析数论》中首先引入，由另一位德国数学家艾德蒙·朗道（Edmund Landau）推广；大 O 最初是大写希腊字母，如今用大写英文 O，小 o 与 Θ 记号在计算算法复杂度时比较不常用。**为什么用 O 而不用精确式**：比较算法只需比量级，精确系数与低阶项是噪音（设计动机，推导见 ③）。

**② 直觉理解**

模型级类比：**树干与枝叶**（素材 p3 原话的引申）——$O(f(n))$ 只留树干（最高次幂），枝叶（系数、低阶项）全部丢弃；判断一棵树多高看树干就够了。

小数据推演：$n=1000$ 时，$T(n)=2n^2+n+1$ 中 $n^2$ 项 $=2 \times 10^6$，$n$ 项加常数只有 $1001$，占比约 $0.05\%$；$n=10^5$ 时占比降到十万分之一量级。低阶项随 $n$ 增大被最高次幂淹没——这就是"只留树干"的数字依据。

**③ 原理与推导**

化简规则（素材 p3 例）：$O(2n^2+n+1) = O(3n^2+n+3) = O(7n^2+n) = O(n^2)$。推导：设 $T(n)=2n^2+n+1$，取 $C=3$，则 $n \ge 1$ 时 $2n^2+n+1 \le 3n^2 \le C \cdot n^2$，满足定义，故 $T(n)=O(n^2)$；系数换成 7、3 同理（常数项并入 $C$）。

量级阶梯（素材 p3，从小到大）：$O(1) < O(\log_2 n) < O(n) < O(n \log_2 n) < O(n^2) < O(n^3) < \ldots < O(2^n) < O(n!)$。文字版结论：对数 < 线性 < 线性对数 < 多项式 < 指数 < 阶乘，越靠右越不可用。

多项式与指数的分界（素材 p4）：$O(\log_2 n), O(n), O(n \log_2 n), O(n^2), O(n^3)$ 称**多项式时间**；$O(2^n), O(n!)$ 称**指数时间**。计算机科学普遍认可前者（P，Polynomial）为有效算法，后者归入 NP（Non-Deterministic Polynomial，非确定多项式）相关话题。素材 p4 的例子：分解 $4294967297$，没有多项式时间的通用解法，但欧拉发现它等于 $641$ 与 $6700417$ 的乘积，验证"不是素数"反而可以在多项式时间内完成——这类"验证容易求解难"的问题是 NP 的直观面孔。

经验规则（素材 p6）：一个算法的复杂度若是 $c$、$\log_2 n$、$n$、$n \log_2 n$，时间效率比较高；若是 $2n$、$3n$、$n!$，稍大一些的 $n$ 就会让算法动弹不得。

**④ 代码演示**

量级对照演示程序（自编示例，直观感受阶梯右移的暴涨）：

```cpp
// 自编示例：打印各量级函数在 n=32 时的值，观察阶梯
#include <cstdio>
int main() {
    long long n = 32;
    printf("O(1)      : 1\n");
    printf("O(log2n)  : %lld\n", (long long)1);          // log2(32)=5，见知识点 3 推导
    printf("O(n)      : %lld\n", n);
    printf("O(nlog2n) : %lld\n", n * 5);
    printf("O(n^2)    : %lld\n", n * n);
    printf("O(n^3)    : %lld\n", n * n * n);
    printf("O(2^n)    : %lld\n", 1LL << n);              // 2^32 = 4294967296
    return 0;                                            // n! 一行不打印：32! 远超 long long
}
```

**执行追踪表**（把 $T(n)=7n^2+n$ 写成大 O，三步）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---|:---|:---|:---|
| 1 | $7n^2+n$ | 系数 7 在最高次幂上 | 按定义找常数 C 吸收 7 | 系数不影响量级 |
| 2 | $n^2+n$ | 低阶项 n 还在 | n 大时 n 项占比趋 0 | 舍低阶项 |
| 3 | $n^2$ | 只剩树干 | 放入 O 记号 | $O(n^2)$ |

**错误写法对照**：

```diff
- printf("该算法复杂度 O(2n^2)，比 O(n^2) 慢一倍\n");   // 坑1：系数写进 O 当量级差——大 O 里系数不构成量级差（素材 p3 化简例）
+ printf("该算法复杂度 O(n^2)\n");   // 系数丢弃，量级才是判据
- "O(n!) 也就比 O(n^2) 多个因子，n=20 应该能过"   // 坑2：低估阶乘——20! 约 2.4×10^18，秒级估算下是 10^10 秒
+ n>=12 时 O(n!) 实际不可用（素材 p6 经验规则）
```

**⑤ 典型应用**

- 真题：P3367（同知识点 1）——用阶梯判断：$O(nm)$ 在指数级远的右端必死，$O((n+m)\alpha(n))$ 近线性可行（并查集解法见 [[并查集与种类并查集]]）。
- 真题：P1177（同知识点 1）——$O(n \log n)$ 与 $O(n^2)$ 在 $n=10^5$ 下差约 6000 倍，这就是阶梯上的"档位差"。
- **数据范围到复杂度锚点表**（资料未覆盖，属补充；竞赛通识，配合素材 p6 经验规则使用）：按每秒 $10^8$ 量次估算——$n \le 12$ 可碰 $O(n!)$；$n \le 25$ 可碰 $O(2^n)$；$n \le 500$ 可碰 $O(n^3)$；$n \le 5000$ 可碰 $O(n^2)$；$n \le 10^6$ 可碰 $O(n \log n)$ 与 $O(n)$；$n$ 更大只接受 $O(\log n)$、$O(1)$。拿到题先看数据范围，再反推需要的复杂度档位——这是"算法的身份证"在赛场上的用法。

**⑥ 坑点与边界**

> **【易错】** 把系数当量级：$O(2n^2)$ 写出来审题时误判为"比 $O(n^2)$ 高一档"。大 O 化简后系数一律不写（素材 p3）。

> **【易错】** 低估指数与阶乘：$O(2^n)$ 在 $n=40$ 时约 $10^{12}$，$O(n!)$ 在 $n=13$ 时已超 $6 \times 10^9$——靠锚点表记档位，不靠感觉。

> **【注意】** 对数的底不影响量级：$\log_2 n = \ln n / \ln 2$，换底只差常数因子，$O(\log_2 n)$ 与 $O(\ln n)$ 同档（这一段我不确定素材是否有意强调，按通识补充；素材 p3 统一用 $\log_2 n$ 记法，本篇从之）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 各量级函数：常数 1、log 无定义（算法上取 0）、线性 0（预期：程序不崩，量级讨论从 n>=1 起）。
> 2. 单元素：n=1 → O(1)=O(log n)=O(n)=1，O(n^2)=1（预期：小 n 下各档位挤在一起——这正是"小数据骗人"的根源）。
> 3. 全相同：n=32 固定跑 10 次输出不变（预期：量级函数与输入内容无关）。
> 4. 严格递增：n=2,4,8,16,32 → 2^n 值 4,16,256,65536,4294967296（预期：每步翻倍，肉眼可见的指数爆炸）。
> 5. 严格递减：n=32..2 → 值逆序回落（预期：对称）。
> 6. 极值：n=64 → 2^64=1.8×10^19 超 long long 上限约 9.2×10^18，1LL<<64 是未定义行为（预期：打印 2^n 一行时 n 必须不超过 62，防溢出）。

### 3. 分析法则与五个经典例子：拿到代码三步出量级

前置依赖：[[#2. 大 O 记号与常见量级]]、C 语言基础（循环嵌套）
后续衔接：[[#4. 递归的本质与调用栈]]、[[二分]]（O(log n) 的来源）、[[排序]]（O(n log n) 的来源）

**① 它解决什么问题**

上一节会化简，这一节解决"从一段代码推出 $T(n)$"。素材 p3 给出三步骤：(1) **找基本语句**——算法中执行次数最多的那条语句，通常是最内层循环体；(2) **计算执行次数的数量级**——只需保留最高次幂，舍去低次幂和最高次幂的系数（素材 p3 原文措辞：忽略低次幂和最高次幂的系数），把注意力集中在增长率上；(3) **用大 O 记号表示**。配套法则（素材 p4）：顺序结构用**求和法则**——$T_1(n)=O(f(n))$、$T_2(n)=O(g(n))$，则 $T_1(n)+T_2(n)=O(\max(f(n), g(n)))$，双变量版 $T_1(m)+T_2(n)=O(f(m)+g(n))$；选择结构（if）取 then 与 else 中较费的那支，条件判断本身算 $O(1)$；循环结构用**乘法法则**——$T_1(n) \cdot T_2(n)=O(f(n) \cdot g(n))$。空间复杂度 $S(n)$ 同构定义（素材 p6）：算法运行中临时占用存储空间的量度，含算法本身、输入输出、临时工作单元三部分；常数个临时变量为 $O(1)$，一维数组为 $O(n)$，对数层递归为 $O(\log_2 n)$。**为什么法则只有两条**：顺序与嵌套覆盖了结构化程序的全部组合方式（设计动机）。

**② 直觉理解**

模型级类比：**结账**。顺序执行像把几笔账并列——总额由最大那笔决定（求和法则取 max）；循环嵌套像"每笔外账都要配一整轮内账"——外层 $f$ 笔配内层 $g$ 笔，总额相乘（乘法法则）。

小数据推演：双层循环 $n=3$，外层 3 轮、每轮内层 3 次，共 $3 \times 3 = 9$ 次——乘法法则的肉眼版。

**③ 原理与推导**

五个经典例子逐一推导（频度标注均出自素材 p5-p6）：

- $O(1)$：`Temp=i; i=j; j=temp;`——三条单语句频度各为 1，执行时间与 $n$ 无关；即使算法里有上千条语句，也只是"较大的常数"，仍记 $T(n)=O(1)$（素材 p4-p5）。
- $O(n)$（素材 p5 原例，斐波那契递推）：`a=0`（频度 2，含 `b=1` 合并计）、`for` 判断频度 $n$、循环体三条语句频度各 $n-1$，$T(n)=2+n+3(n-1)=4n-1=O(n)$。
- $O(n^2)$（素材 p5）：`sum=0` 1 次；外层判断 $n+1$ 次；内层体 $n^2$ 次；$f(n)=2n^2-2$，按 $\Theta$ 化简口径舍系数与低阶项（A-3 登记 2）得 $O(n^2)$。素材 p5 又给嵌套变体：语句 1 频度 $n-1$、语句 2 频度 $(n-1)(2n+1)=2n^2-n-1$，合计 $2n^2-2$，仍 $O(n^2)$——**步长带常数 2n 不改量级**。
- $O(\log_2 n)$（素材 p6）：`i=1; while(i<=n) i=i*2;`。设语句 2 频度 $f(n)$，则 $2^{f(n)} \le n$，解出 $f(n) \le \log_2 n$，取最大值得 $T(n)=O(\log_2 n)$。关键机理：i 每轮**翻倍**，所以轮数是 $n$ 的对数。
- $O(n^3)$（素材 p6）：三重循环 `for(i=0;i<n;i++) for(j=0;j<i;j++) for(k=0;k<j;k++) x=x+2;`。素材 p6 给出频度公式 $n(n+1)(n-1)/6$；按代码逐次实测计数为 $(n-1)n(n-2)/6$（断言程序 n=100 实测 161700，两者只差低阶项，A-3 登记 1），量级结论一致：$O(n^3)$。

空间复杂度补充推导（素材 p6）：临时空间若不随 $n$ 变（常数个变量）为 $O(1)$；递归深度为对数层（如二分）时栈占 $O(\log_2 n)$；开一维数组 `a[n]` 为 $O(n)$。**输入输出所占空间由问题本身决定，不随算法改变，不计入**（素材 p6）。

**④ 代码演示**

五个例子的合集（自编示例；素材 p4-p6 原为 C/Java 片段，改写为 C++17 单文件并加计数输出）：

```cpp
// 自编示例：素材 p4-p6 五个经典例子的 C++17 改写，每个循环配计数器
#include <cstdio>
int main() {
    int a = 1, b = 2, temp;                 // 例1 O(1)：三条交换语句
    temp = a; a = b; b = temp;
    long long cnt = 0, n = 100;
    long long x = 0, y = 0, s;
    long long a0 = 0, b0 = 1;               // 例2 O(n)：斐波那契递推（素材 p5）
    for (long long i = 1; i <= n; i++) {    // 判断 n 次，体 3(n-1)
        s = a0 + b0; b0 = a0; a0 = s;
        cnt++;
    }
    printf("O(n)      : %lld\n", cnt);
    cnt = 0;
    for (long long i = 1; i <= n; i++)      // 例3 O(n^2)：双层循环（素材 p5）
        for (long long j = 1; j <= n; j++)
            cnt++;
    printf("O(n^2)    : %lld\n", cnt);
    cnt = 0;
    long long i = 1;                        // 例4 O(log2n)：翻倍循环（素材 p6）
    while (i <= n) { i *= 2; cnt++; }
    printf("O(log2n)  : %lld\n", cnt);      // n=100 时输出 7
    cnt = 0;
    for (long long ii = 0; ii < n; ii++)    // 例5 O(n^3)：三重循环（素材 p6）
        for (long long j = 0; j < ii; j++)
            for (long long k = 0; k < j; k++)
                cnt++;                      // 实测 (n-1)n(n-2)/6（A-3 登记 1）
    printf("O(n^3)    : %lld\n", cnt);
    return 0;
}
```

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | i=1 | 1<=100 成立 | i*=2 | i=2，cnt=1 |
| 2 | i=2 | 2<=100 成立 | i*=2 | i=4，cnt=2 |
| 3 | i=4..32 | 逐轮翻倍 | i*=2 共 5 轮 | i=64，cnt=7 |
| 4 | i=64 | 64<=100 成立 | i*=2 | i=128，cnt=7 |
| 5 | i=128 | 128<=100 不成立 | 退出循环 | 总 cnt=7=log2(100) 向上取整 |

**错误写法对照**：

```diff
- long long i = 1; while (i <= n) { i += 2; cnt++; }   // 坑1：把 +2 当翻倍——i 走 n/2 轮，复杂度 O(n/2)=O(n)，不是 O(log n)（素材 p6 机理是翻倍）
+ long long i = 1; while (i <= n) { i *= 2; cnt++; }   // 翻倍才产生对数轮数
- for (i=0;i<n;i++) for (j=0;j<=i;j++) for (k=0;k<j;k++) cnt++;   // 坑2：边界 j<=i 与素材 j<i 不同——实测计数从 (n-1)n(n-2)/6 变 n(n+1)(n-1)/6，对题先核对边界（A-3 登记 1 的来源）
```

**⑤ 典型应用**

- 真题：洛谷 P2249【深基13.例1】查找——有序数组查数用二分，每次 $O(\log_2 n)$（[[二分]]），对应本知识点例 4 的对数机理。
- 真题：P1177 快排模板——快排平均 $O(n \log_2 n)$，正好落在素材 p3 阶梯的"线性对数"档；冒泡 $O(n^2)$ 落在平方档，$n=10^5$ 下两档差数千倍（[[排序]]）。
- 迁移题（自编）：分析 `for(i=1;i<=n;i++) for(j=1;j<=i;j++) cnt++;` 的量级。建议先独立做，再对照：内层频度随 i 递增，总次数 $1+2+\ldots+n=n(n+1)/2$，量级 $O(n^2)$——嵌套循环不必每层独立相乘，先求和再取量级。

**⑥ 坑点与边界**

> **【易错】** 步长加法与乘法混淆：`i+=2` 是 $O(n/2)=O(n)$，`i*=2` 才是 $O(\log_2 n)$（④对照坑 1）。

> **【易错】** 空间复杂度把输入数组算进去。输入空间由问题决定、不随算法改变（素材 p6），$S(n)$ 只数**临时**工作单元：常数个变量 $O(1)$、一维数组 $O(n)$、递归栈深 $d$ 为 $O(d)$。

> **【注意】** 三重循环这类"内层次数依赖外层变量"的结构，先写出精确和式（如 $0+1+\ldots+(n-1)$）再取量级，不要直接套"层数相乘"（⑤迁移题的教训）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 例 2/3/5 的 cnt=0，例 4 的 while 判断 1 次失败 cnt=0（预期：全 0，不崩）。
> 2. 单元素：n=1 → 例 4 的 i=1<=1 成立一次后 i=2 退出，cnt=1（预期：log2(1)=0 但算法计数 1——循环判断本身占一轮）。

> 4. 严格递增：n=1,10,100,1000 → 例 4 的 cnt=1,4,7,10（预期：每加一位十进制数 cnt 增约 3~4，对数指纹）。

> 6. 极值：n=10^6 → 例 3 的 cnt=10^12 超 int，必须 long long（预期：long long 下正常输出，int 下溢出 WA）；例 5 的 cnt 约 1.7×10^17 同理。

### 4. 递归的本质与调用栈：两条件、栈帧与尾递归

前置依赖：[[#3. 分析法则与五个经典例子]]、[[二叉树竞赛篇]]（递归世界观：子问题与子树）、[[栈与队列]]（栈的后进先出）
后续衔接：[[DFS]]（递归展开成搜索树）、[[#5. 最好、最坏、平均、均摊与竞赛防 TLE]]

**① 它解决什么问题**

**递归**就是函数直接或间接地调用了自己，这种调用方式叫递归调用（递归篇 p1）。它有一条雷打不动的原则（递归篇 p1）：**所有被调用的函数都将创建一个副本，各自为调用者服务，而不受其他函数的影响**。递归函数必须具备两个要素（递归篇 p1）：**边界条件**——递归终止条件，避免出现死循环，也叫递归出口；**递归条件**——递归体，把一个大问题分解为一步一步小问题。两要素齐备，才能在有限的计算后得出想要的结果。复杂度视角：每层调用占一份栈空间，深度为 $d$ 的递归占 $O(d)$ 栈空间；朴素递归斐波那契的调用次数是 $O(2^n)$ 级（补充推导见 ③，断言实测见附录 B-5）——**同一个问题，递归写法的复杂度可能与递推差一个指数级**，这是本知识点的存在理由。

**② 直觉理解**

模型级类比：**传话链上每人自己记账**。求 $\text{add}(5)=1+2+\cdots+5$ 时，5 号收到任务先记下"我管 +5"，把"算 1 到 4 的和"递给 4 号……每人一个副本、各记各的账，互不干扰（对应递归篇 p1 的"副本"原则）；到 1 号达到边界直接交账，然后账一层层往回归并——这就是递过程与归过程。

用具体数字跑一遍（递归篇 p2 图的文字版）：$\text{add}(5)$ 递过程依次展开 $f(5) \to f(4) \to f(3) \to f(2) \to f(1)$，$f(1)$ 命中边界返回 1；归过程依次回并 $1+2=3$、$3+3=6$、$6+4=10$、$10+5=15$，输出 15（递归篇 p2 运行结果 15）。

**③ 原理与推导**

**栈帧**（stack frame，递归篇 p4-5）：每次函数调用，计算机要"记住"调用函数的位置——返回位置，才能在调用结束时带着返回值回到该处；返回位置、函数参数、寄存器值等压在**调用栈**顶部的一块记录里，这就是栈帧。栈帧内容（递归篇 p5）：返回地址、形式参数、局部变量。推导"递归为什么会栈溢出"（递归篇 p4）：每层递归调用都新建一个栈帧；若递归太深，栈空间耗尽，即 stack overflow——递归是一种特殊的循环，但**循环不占栈空间，递归占**，这是两者的空间复杂度差异。

**尾递归**（递归篇 p4-5）：若函数在**尾位置**调用自身——返回语句形如 `return 递归函数(参数);`，最后一句就是递归调用、返回值与下一个递归调用的返回值相同——则称尾递归，它是尾调用的特殊情形。**原理**（递归篇 p4-5）：传统模式下每次调用新建栈帧压栈；而尾调用是当前活跃期内最后一条待执行语句，返回时编译器可以直接复用当前栈帧（刷新参数相当于跳到新函数），不添加新栈帧——尾调用消除（Tail Call Elimination）或尾调用优化（TCO），让尾调用像 `goto` 语句一样高性能。尾递归两特点（递归篇 p4）：尾部调用的是函数自身（Self-called）；优化后计算仅占常量栈空间（Stack Space）。

推导"普通递归与尾递归的复杂度差"（自补，素材给机制未给算式）：普通版 `add(x)` 每层挂起等 `add(x-1)` 返回后还要 `+x`，栈深 $O(n)$；尾递归版 `add(x, sum)` 把累计值放进参数，返回时不需要任何后续计算，栈深可被优化为 $O(1)$。注意（递归篇 p5）：对 C++ 等语言，`return g(x);` 不一定是尾递归——返回之前可能涉及对象的析构函数，使 `g(x)` 不是最后执行的那个；C++ 标准不保证 TCO，具体编译器行为这一段我不确定，标注延伸，竞赛防溢出优先手写递推或显式栈。

朴素递归 fib 的调用数（自补，配断言）：设 $C(n)$ 为计算 $\text{fib}(n)$ 的调用次数，$C(0)=C(1)=1$，$C(n)=C(n-1)+C(n-2)+1$，解得 $C(n)=2F(n+1)-1$（$F$ 为斐波那契数），随 $n$ 按 $\varphi^n \approx 2^{0.69n}$ 增长，量级 $O(2^n)$；递推版只循环 $n-1$ 次，$O(n)$——同题两写法，指数差。

**④ 代码演示**

递归求和与调用计数（自编示例；递归篇 p1-p2 的 Java 示例改写为 C++17，逻辑一致；fib 计数为自补验证代码）：

```cpp
// 自编示例：add 递归（递归篇 p1 Java 改写）+ 朴素 fib 调用计数（自补，验证 O(2^n) 级暴涨）
#include <cstdio>
int add(int x) {
    if (x == 1) {                 // 边界条件：递归出口（递归篇 p1）
        return x;                 // 若 x==1，返回他本身
    } else {
        return add(x - 1) + x;    // 递归条件：递归调用（递归篇 p1）
    }
}
long long calls = 0;              // 调用计数器
long long fib(int n) {            // 朴素递归 fib（自补）
    calls++;                      // 每进入一次函数体计一次
    if (n <= 1) return n;         // 边界条件
    return fib(n - 1) + fib(n - 2);
}
int main() {
    printf("add(5)=%d\n", add(5));            // 输出 15（递归篇 p2）
    calls = 0; fib(20);
    printf("fib(20) calls=%lld\n", calls);    // 输出 21891
    calls = 0; fib(25);
    printf("fib(25) calls=%lld\n", calls);    // 输出 242785，5 步规模涨 11 倍
    return 0;
}
```

**执行追踪表**（$\text{add}(5)$ 的调用栈展开，栈列从底到顶；对应递归篇 p2 图示）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | add(5) | [add(5)] | 非边界，递归 add(4) | 挂起，等 4 号账 |
| 2 | add(4) | [add(5),add(4)] | 递归 add(3) | 挂起 |
| 3 | add(3) | [...,add(3)] | 递归 add(2) | 挂起 |
| 4 | add(2) | [...,add(2)] | 递归 add(1) | 挂起 |
| 5 | add(1) | [...,add(1)] | 边界 x==1，返回 1 | 递过程到底 |
| 6 | add(2) | 弹回 [..,add(2)] | return 1+2 | 3 上传 |
| 7 | add(3) | 弹回 [..,add(3)] | return 3+3 | 6 上传 |
| 8 | add(4) | 弹回 [add(5),add(4)] | return 6+4 | 10 上传 |
| 9 | add(5) | 弹回 [add(5)] | return 10+5 | 15，归过程完成 |

**错误写法对照**：

```diff
- int add(int x) { return add(x - 1) + x; }        // 坑1：缺边界条件——无限递归，栈帧无限压入，stack overflow（RE，递归篇 p1 "避免死循环"）
+ int add(int x) { if (x == 1) return x; else return add(x - 1) + x; }   // 两要素齐备
- int add(int x, int sum) { if (x == 1) return sum + 1; else return 1 + add(x - 1, sum + x); }   // 坑2：返回前还有 +1，不是尾位置——TCO 失效，栈深仍 O(n)
+ int add(int x, int sum) { if (x == 1) return sum + 1; else return add(x - 1, sum + x); }   // 尾位置：return 后无任何计算（递归篇 p4-5）
```

**⑤ 典型应用**

- 真题：洛谷 P1706 全排列问题——按字典序输出 $1..n$ 的全排列，标准解法是 DFS 递归：每层选一个未用数，边界条件是选满 $n$ 个，递归条件是"枚举下一个位置"。递归深度 $O(n)$，栈空间 $O(n)$（[[DFS]]）。
- 真题：P3367 的 find 函数（[[并查集与种类并查集]]）——递归爬父指针链，深度最坏 $O(n)$，$n=10^5$ 斜链下递归深度贴线，是该笔记知识点 2⑥ 的极值场景。
- 迁移题（自编）：把递归版 $\text{add}(x)$ 改写为尾递归与递推两个版本，并用 $x=5$ 手算对照三版输出。建议先独立做，再对照：尾递归 `add(x,sum)` 初值 `sum=0`，返回 15；递推 `for(i=1;i<=5;i++) s+=i` 得 15——三版答案一致，栈空间 $O(n)$、$O(1)$（若 TCO 生效）、$O(1)$。

**⑥ 坑点与边界**

> **【易错】** 边界条件缺失或不可达：写成 `if (x == 0) return 0;` 但调用从负数进入，边界永远碰不到——同样无限递归 RE。写递归先写出口，再验"任何合法输入都能到达出口"。

> **【易错】** 把"尾递归一定被优化"当保证。C++ 中 `return g(x);` 若触发 `g(x)` 之外的工作（如对象析构）就不是尾调用（递归篇 p5）；标准不保证 TCO，竞赛里深递归一律按 $O(d)$ 栈空间估算，防 RE。

> **【注意】** 循环与递归的空间差异：循环体复用同一组变量不占新栈帧，递归每层新建栈帧（递归篇 p5）——同一个 $O(n)$ 时间，循环 $O(1)$ 空间、递归 $O(n)$ 空间。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：add(0) → x==1 不成立走 else，递归到负数永不触界，无限递归（预期：这是边界漏洞，出口应为 x<=1 或改题面保证 x>=1——设计出口时先想 0 与负数）。
> 2. 单元素：add(1) → 命中边界直接返回 1（预期：无递归展开，栈深 1）。
> 3. 全相同：fib(2) 反复跑 → 每次调用数恒为 3（预期：无状态残留，函数纯）。
> 4. 严格递增：fib(10..25) 调用数 177,287,1093,17711,28657,46368,75025,121393,196417,317811,514229,832040,1346269,2189131,3542465,5731475（预期：相邻比约 1.6，$\varphi$ 指纹；实测锚点 21891 与 242785）。
> 5. 严格递减：add(5..1) → 栈深逐次减 1（预期：5,4,3,2,1 层）。
> 6. 极值：add(10^6) → 每层栈帧约几十字节，10^6 层触发栈溢出 RE（预期：改递推或加编译器栈扩容，不赌 TCO）。

回扣开场：现在你能解释"为什么 $n=40$ 的朴素递归 fib 跑不动"——调用数 $2F(n+1)-1$ 按指数暴涨（③推导），且每层还压一份栈帧。最后一节把四类复杂度收拢到赛场判题。

### 5. 最好、最坏、平均、均摊与竞赛防 TLE

前置依赖：[[#2. 大 O 记号与常见量级]]、[[#3. 分析法则与五个经典例子]]、概率加权平均的朴素直觉
后续衔接：[[搜索优化]]（剪枝改变最坏情形）、[[二叉堆]]（均摊的另一战场）

**① 它解决什么问题**

同一段代码在不同输入下复杂度可能不同（素材 p7）。素材 p7-p10 把时间复杂度进一步划分为**最好、最坏、平均、摊均**（正文统一写"均摊"，A-3 登记 4）四种。最好情况时间复杂度：最理想输入下的复杂度；最坏情况：最糟输入下的复杂度；平均情况：按各种输入出现的**概率**加权；均摊：一串**有前后时序规律**的操作总摊销。素材 p7-p8 的 `find` 例：在数组中找 x 的位置，x 恰在首位则一次命中 $O(1)$（最好）；x 不在数组中要扫完全组 $O(n)$（最坏）；平均按 $n+1$ 种情况（0 到 n-1 各位置与不在数组中）算得 $O(n)$，把"在/不在"各 $1/2$、位置均匀 $1/n$ 的概率乘进去得加权均值 $(3n+1)/4$，仍 $O(n)$（素材 p8 公式）。素材 p8-p9 的 `insert` 例：数组不满时插到 count 位 $O(1)$；满了先求和清空再插 $O(n)$；但"一次 $O(n)$ 清理后必紧跟 $n-1$ 次 $O(1)$ 插入"（素材 p9），把高耗时摊给前面的低耗时，**均摊复杂度 $O(1)$**。**为什么要分四种**：一种复杂度只在"不同情况有量级差距"时才需要拆开说；均摊只在"操作有固定时序规律"时才可用（素材 p8-10，设计动机）。

**② 直觉理解**

模型级类比：**攒碗**。平时用完一只随手洗一只（$O(1)$），攒满一水槽才集中刷一整槽（$O(n)$）；摊到每一天，家务量还是常数——高耗时的那次被前面 $n-1$ 次低耗时摊薄了。find 则像抽奖：x 的位置随机，期望要扫约半数组。

小数据推演（容量 4 的数组插 8 个数）：插第 1 到 4 个各 1 份工作量；插第 5 个时数组满，先刷 4 个（求和清空）再插，共 5 份；第 6 到 8 个各 1 份。总工作量 $4 \times 1 + 5 + 3 \times 1 = 12$，均摊 $12/8 = 1.5$，常数级（断言程序容量 100、插 10000 个实测总工作量 20000，均摊 2.0，附录 B-5）。

**③ 原理与推导**

平均情况的推导（素材 p8）：x 在 0 到 n-1 各位置且不在数组中，共 $n+1$ 种情况；位置 $i$（0 基）找到要遍历 $i+1$ 个元素，不在则遍历 $n$ 个，平均遍历数 $\frac{1+2+\cdots+n+n}{n+1}=\frac{n(n+3)}{2(n+1)}$，量级 $O(n)$。考虑概率修正：在/不在各 $1/2$，位置均匀 $1/n$，加权平均 $1 \cdot \frac{1}{2n} + 2 \cdot \frac{1}{2n} + \cdots + n \cdot \frac{1}{2n} + n \cdot \frac{1}{2} = \frac{3n+1}{4}$，量级仍 $O(n)$（素材 p8 公式）。

均摊的推导（素材 p9）：insert 的 $O(1)$ 插入与 $O(n)$ 清理不是随机的，而是**有规律的循环往复**——满一次清一次，清一次后必然连插 $n-1$ 次；把 1 次 $O(n)$ 的耗时摊到这组 $n$ 次操作上，每次均摊 $O(1)$。素材 p9-p10 的两条件：大部分情况复杂度低、个别情况高；高耗时操作与低耗时操作之间存在**前后连贯的时序规律**。素材 p10 作者观点：均摊可以看作一种特殊的平均，最该掌握的是摊还分析方法，结论叫平均还是均摊并不重要；能用均摊的场景里，均摊复杂度往往就等于最好情况复杂度。

推导"find 为什么不能用均摊"：find 的查找位置**没有时序规律**（这次在首位下次在哪未知），只能走概率加权——这是平均与均摊的分水岭（素材 p9 对比段落）。

**④ 代码演示**

find 与 insert 的 C++17 改写（自编示例；素材 p7-p8 原为 Java 伪码，逐段改写，逻辑一致）：

```cpp
// 自编示例：find（素材 p7 Java 改写）+ insert 摊还模拟（素材 p8 Java 改写，Java 数组语法换 C 数组）
#include <cstdio>
int find(int *array, int n, int x) {     // 在 array[0..n-1] 中找 x，返回下标，找不到 -1
    int i = 0, pos = -1;
    for (; i < n; ++i) {
        if (array[i] == x) {             // 最好：x 在首位 O(1)；最坏：不在 O(n)（素材 p7）
            pos = i;
            break;
        }
    }
    return pos;
}
int arr[128], count_ = 0;                // 容量 100 的数组与已存个数
long long work = 0;                      // 工作量计数（均摊观察用）
void insert(int val, int cap) {
    if (count_ == cap) {                 // 满：先求和清空，O(n)（素材 p8）
        int sum = 0;
        for (int i = 0; i < cap; ++i) { sum += arr[i]; work++; }
        arr[0] = sum;
        count_ = 1;
    }
    arr[count_] = val; ++count_; ++work; // 不满：直接插，O(1)
}
int main() {
    int a[4] = {7, 3, 9, 5};
    printf("find 9 at %d\n", find(a, 4, 9));       // 下标 2
    printf("find 8 at %d\n", find(a, 4, 8));       // -1，最坏情形
    for (int i = 0; i < 10000; i++) insert(i, 100);
    printf("work=%lld avg=%.1f\n", work, work / 10000.0);   // 20000，均摊 2.0
    return 0;
}
```

**执行追踪表**（容量 4 插入 8 个数，work 列为累计工作量）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1-4 | 插 v1..v4 | count_=0..3 | 各直插 1 次 | work=4 |
| 5 | 插 v5 | count_==4 触发清理 | 求和 4 次+直插 1 次 | work=9 |
| 6-8 | 插 v6..v8 | count_=1..3 | 各直插 1 次 | work=12 |
| 9 | 结算 | 8 次插入 | 12/8 | 均摊 1.5，O(1) |

**错误写法对照**：

```diff
- "find 平均 O(n/2)，所以竞赛数据下一般很快"   // 坑1：把平均当承诺——平均是对随机输入说的，出题人专造最坏数据（素材 p2 数据规模教训的判题版）
+ 判题按最坏复杂度算：find 最坏 O(n)（素材 p7）
- if (count_ == cap) { ... } 漏写时直接 arr[count_] = val; ++count_;   // 坑2：不判满直插——越界写数组，RE
+ 先判满清理再插入（素材 p8 逻辑顺序不可换）
```

**⑤ 典型应用**

- 真题：P1177 快排模板——快排**平均** $O(n \log_2 n)$ 但**最坏** $O(n^2)$（有序数据 + 首元素基准被卡），判题按最坏算，所以模板要随机化基准（联系 [[排序]]、[[搜索优化]] 的剪枝思想：主动改变最坏情形）。
- 真题：P3367 并查集——find 的路径压缩使 $m$ 次操作**均摊** $O(\alpha(n))$，正是"高耗时摊给低耗时"的赛场版（[[并查集与种类并查集]]）。
- 迁移题（自编）：容量 100 的 insert 结构连续插 10^5 个数，问总工作量。建议先独立做，再对照：每 100 次插入触发 1 次容量 100 的清理，共 1000 次清理；总量 $10^5 + 1000 \times 100 = 2 \times 10^5$，均摊 2.0，$O(n)$ 总量 $O(1)$ 均摊——与断言程序实测一致。

**⑥ 坑点与边界**

> **【易错】** 用平均复杂度做通过性判断。平均是对"随机输入"的承诺，竞赛数据是**构造**的（素材 p2 数据规模教训）；判题一律按最坏（或已证明的均摊）算。

> **【易错】** 在没有时序规律的场景硬套均摊。find 的查找位置无规律，只能平均；硬说"find 均摊 O(1)"错（素材 p9 对比：insert 才有"满一次清一次"的规律）。

> **【注意】** 均摊与最好的区别：最好情况是"运气最好的那一次"，均摊是"一整串操作分摊后的平均值"（素材 p10）；前者不能当保证，后者可以。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 调 find → for 判断 1 次失败，返回 -1（预期：-1，不崩）；insert 容量 0 → 立即触发清理但清理循环 0 次（预期：count_=1 后可插，不崩）。
> 2. 单元素：n=1 查 x==array[0] → 首位命中，最好情形 O(1)（预期：下标 0）；查 x 不在 → 扫 1 次返回 -1。
> 3. 全相同：数组全 5 查 5 → 首位命中（预期：O(1)）；全 5 查 4 → 扫到底（预期：O(n)，-1）。
> 4. 严格递增：数组 1..n 查 n → 最坏 O(n)；查 1 → 最好 O(1)（预期：位置决定档位）。
> 5. 严格递减：数组 n..1 查 1 → 最后一位命中，O(n)（预期：递增序的镜像）。
> 6. 极值：容量 100 连插 10^6 个 → 清理 10^4 次每次 100，总工作量 2×10^6，均摊 2.0（预期：long long 计数下正常；若清理次数×容量用 int 计数则 10^6 量级尚可，10^9 量级必溢出）。

回扣开场：现在你能解决开场那个"每对数之和"的壁了——先看 $n$ 查锚点表（知识点 2⑤）定档位，双循环 $O(n^2)$ 在 $10^5$ 下必死，改用哈希或排序后双指针把档位压到 $O(n \log n)$ 以内；判题时按最坏算，不拿小数据实测赌命（本知识点 ⑥）。

## 四、总结与自测

### 核心内容（一页纸速览）

- **时间频度与事前分析**：事后统计法败于环境与数据规模两缺陷，改用语句执行次数 $T(n)$ 做时间量度（素材 p2-p3）。
- **大 O 记号**：$T(n)=O(f(n))$ 存在常数 $C$ 使充分大 $n$ 时 $T(n) \le C \cdot f(n)$；只留最高次幂；Landau 记号 1892 年由 Bachmann 引入（素材 p3）。
- **量级阶梯**：$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$；多项式时间有效，指数时间不可用（素材 p3-p4）。
- **分析法三步骤与两法则**：找基本语句、求数量级、放大 O；顺序求和取 max、循环嵌套相乘（素材 p3-p4）。
- **五个经典例子**：$O(1)$ 交换、$O(n)$ 斐波那契递推、$O(n^2)$ 双循环、$O(\log_2 n)$ 翻倍循环、$O(n^3)$ 三重循环（素材 p4-p6）。
- **空间复杂度**：只数临时工作单元，$O(1)$/$O(\log n)$/$O(n)$ 三档（素材 p6）。
- **递归两要素**：边界条件（出口）+ 递归条件（递归体）；每层调用建副本、压栈帧（递归篇 p1、p4-5）。
- **尾递归与 TCO**：尾位置调自身，编译器复用栈帧得常量栈空间；C++ 不保证 TCO（递归篇 p4-5）。
- **四类复杂度**：最好/最坏/平均/均摊；判题按最坏或已证均摊；均摊需时序规律（素材 p7-p10）。
- **锚点表**（补充）：$n \le 5000$ 配 $O(n^2)$、$n \le 10^6$ 配 $O(n \log n)$，按数据范围反推档位。
