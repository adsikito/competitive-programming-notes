## 一、为什么需要它

先用最朴素的方式碰一次壁。洛谷 P1464 要求按题面公式实现递归函数 `w(a,b,c)`，题面原话警告"当 a,b,c 均为 15 时，调用的次数将非常的多"（P1464 题面）。到底有多少？本次实测（-O2 编译，调用计数）：无记忆化的递归算 `w(8,8,8)` 要 **446 万次**函数调用，`w(10,10,10)` 涨到 **4.9 亿次**——参数每加 2，调用量翻约百倍。照这个增速，`w(20,20,20)` 是 $4^{20}$ 量级的天文数字，1 秒时限内必死。**碰壁的根源：同一个子问题被翻来覆去算了无数遍。**

另一道题碰的是另一种壁。洛谷 P1025（NOIP 2001 提高组）把 n 分成 k 份，朴素 DFS 每个位置独立枚举 $1..n$，状态空间 $n^k$：$n \le 200, k \le 6$ 时约 $6.4 \times 10^{13}$ 个状态——根源不是重复，而是**大量分支一眼就能看出无望，却还在往下搜**。

PPT 对此的总纲（17.搜索优化.pptx slide 1）："无论是何种优化方式，其本质都是想办法减少对不合法及重复的答案的枚举。"本篇就沿这句话展开 5 个知识点：先立搜索树模型（1），再学治重复的记忆化（2）、治无效的剪枝（3），用 P1025 实战（4），最后复盘搜索顺序对剪枝效果的影响（5）。

## 二、知识点逐讲（每个知识点一节，共 5 节）

### 1. 搜索树与重复子问题：搜索为什么慢

前置依赖：[[二叉树结构篇]]（树、递归遍历的直观）、[[枚举与模拟]]（枚举视角）、递归（C 基础）
后续衔接：[[#2. 记忆化搜索：P1464 Function 的去重]]、[[#3. 可行性剪枝与最优性剪枝]]

**① 它解决什么问题**

PPT 定义（slide 1）："搜索：也就是对状态空间进行枚举，通过穷尽所有的可能来找到最优解，或者统计合法解的个数。"**状态空间**就是所有候选解的全体；DFS（深度优先搜索，同批待产出）用递归把"一串决策"逐位定下来。它为什么慢？PPT 一句话："DFS 本质上还是暴力枚举答案。"本节的任务是给"慢"建一个能分析的模型——搜索树，并分清两种病：**重复子问题**（同一状态被反复计算）与**无效分支**（早就无望却还在搜）。朴素搜索的复杂度就是状态空间的大小，例如下文 P1025 场景为 $O(n^k)$。

**② 直觉理解**

模型级类比：**岔路地图**。把每个决策点看作地图上的岔路口，每步有若干选项；从入口走到出口的一条完整路线就是一个候选解。所有路线画在一张图上，恰好是一棵树——根是空决策，每个叶子是一个完整方案，树高是决策步数。走 DFS 就是把这张图逐条走到底，"回溯"就是退回最近岔路口换下一条。

用具体数字跑一遍（自编小例，n=4、k=2：统计两个 1..4 的数之和恰为 4 的方案数）：第 1 位选 1，第 2 位枚举 1..4，叶子 sum=2,3,4,5，只有 4 合法；第 1 位选 2、3 各得 1 个合法叶子；选 4 得 0 个。共 3 个合法叶子：(1,3)、(2,2)、(3,1)。注意 (1,3) 与 (3,1) 在题目"不计顺序"时是同一个划分——这就是**重复枚举**。

**③ 原理与推导**

状态空间到搜索树的映射：设决策有 k 步、每步 n 种选择，则搜索树是深度 k 的 n 叉树，叶子 $n^k$ 个——朴素 DFS 的复杂度就是这个数。树里浪费的时间分两类，两类各有对症药：

- **重复子问题**：树中不同路径通向"参数完全相同"的同一个待算状态。例如 P1464 的 w(2,2,2) 展开时，多个分支都会调用到 w(1,1,1)、w(0,2,2) 等同一参数组合——每次都从头重算。药方：算一次存起来（知识点 2）。
- **无效分支**：某前缀决策已经注定无望（不合法，或已差于已知最优），但 DFS 不知道，把整棵子树搜完。药方：提前判、提前停（知识点 3）。

**设计动机**：为什么这类题偏爱 DFS 而不是多重循环？因为 k 是变量（P1025 的 k 最大 6，写 6 层循环还行，k 更大就写不了）；递归天然按"第几步"分层展开，且累积量作参数传值时每层自带副本，回溯自动恢复现场，不用手写撤销。这也是 PPT 说"先来一段深搜模板，之后的模板将在此基础上进行修改"的原因——所有优化都是在同一副骨架上加判断。

**④ 代码演示**

朴素全枚举骨架（自编。注：PPT 提到"先来一段深搜模板"，但提取文本未含模板代码本体，此处为补充实现的等价骨架）：

```cpp
#include <iostream>
using namespace std;
int n, k, ans;
void dfs(int stp, int sum) {          // stp：下一个要填第几位；sum：前 stp-1 位已选之和
    if (stp > k) {                    // 终止：k 位全部填完（注意是 > 不是 ==）
        if (sum == n) ans++;          // 叶子上验票：合法解计数
        return;
    }
    for (int i = 1; i <= n; i++)      // 每位独立枚举 1..n，不去重、不剪枝
        dfs(stp + 1, sum + i);        // sum 作参数传值：每层副本，天然回溯
}
int main() {
    cin >> n >> k;
    dfs(1, 0);
    cout << ans << endl;
    return 0;
}
```

**执行追踪表**（上例 n=4, k=2，朴素版共 21 次调用 = 1 根 + 4 个第二层 + 16 个叶子）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | dfs(1,0) | 调用栈 [根] | 第 1 位枚举 i=1..4 | 生成 4 个分支 |
| 2 | dfs(2,1)（i=1） | 栈 [1] | 第 2 位枚举 i=1..4 | 叶子 sum=2,3,4,5，1 个合法（1+3） |
| 3 | dfs(2,2)（i=2） | 栈 [2] | 同上 | 叶子 sum=3..6，1 个合法（2+2） |
| 4 | dfs(2,3)（i=3） | 栈 [3] | 同上 | 叶子 sum=4..7，1 个合法（3+1） |
| 5 | dfs(2,4)（i=4） | 栈 [4] | 同上 | 叶子 sum=5..8，0 个合法 |

最终 ans=3：**(1,3) 与 (3,1) 是同一划分被数了两次**——重复枚举的现场证据。

**错误写法对照**：

```diff
- if (stp == k) { if (sum == n) ans++; return; }   // 坑1：第 k 个数还没选就验票，统计的是前 k-1 个数之和（答案错）
+ if (stp > k) { if (sum == n) ans++; return; }    // 对：stp 语义是"下一个要填的位"，填完 k 位后 stp 变 k+1
- int sum = 0; // 全局
- for (...) { sum += i; dfs(stp + 1); }            // 坑2：改全局 sum 却不做回溯减法，越走越大且回溯后不还原（答案错）
+ void dfs(int stp, int sum) { ... dfs(stp + 1, sum + i); ... }   // 对：累积量放参数，传值副本自动回溯
```

**⑤ 典型应用**

- 真题：洛谷 P1464 Function——重复子问题型代表，无记忆化必超时，知识点 2 全流程实战。
- 真题：洛谷 P1025 数的划分（NOIP 2001 提高组）——无效分支与重复解并存，知识点 4 实战。
- 迁移题（自编）：用本节骨架统计 1..n 的全排列个数（每个位置枚举 1..n，叶子处检查互不相同）。建议先独立做，再对照题解：骨架完全一致，把"sum==n"换成"k 个数互异"即可；n=3 时预期输出 6，可手推验证自己对搜索树的想象。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 统计"不计顺序"的方案数时直接有序枚举。后果是重复计数：P1025 若按本节朴素骨架去做，(7,3) 会输出有序拆分数 15（插板法：7-1 个空隙插 2 块板，$C_6^2 = 15$），而正确答案是 4（WA）。

> [!caution]
> **【易错】** 动手前不估状态空间。$n^k$ 型空间里 $200^6 \approx 6.4 \times 10^{13}$ 必死；先算量级再决定要不要优化，是搜索题的第一反应。

> [!note]
> **【注意】** 递归深度 = 树高 = k，本题量级极小；但同一骨架把 k 放大到 $10^5$（如链式结构）会有栈溢出风险，届时需改非递归（参考 [[栈与队列]] 的手写栈）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：本题需同时读入 n、k，无空输入形态；防御写法是读入失败即退出（预期：不崩、无输出）。
> 2. 单元素：k=1（题面 k≥2 之外的防御测试）→ 唯一方案 n=n，输出 1。
> 3. 全相同：n=k → 每份必须全为 1，输出 1（预期：骨架对退化情形也能给确定值）。
> 4. 严格递增：不适用——本节骨架的输入只有 n、k 两个数，无序列形态（知识点 4 起才有"枚举方向"）。
> 5. 严格递减：不适用，理由同上。
> 6. 极值：n=4, k=2 为手推基准；n=200, k=6 朴素版 $6.4 \times 10^{13}$ 状态必超时——这正是后续知识点的存在意义（预期：朴素版跑不完，优化版秒出）。

回扣开场：搜索树模型把"慢"拆成了两种病——重复子问题与无效分支。现在你能对着任何一道搜索题问"我的树里哪种病更重"，下一节先治重复。

### 2. 记忆化搜索：P1464 Function 的去重

前置依赖：[[#1. 搜索树与重复子问题：搜索为什么慢]]、递归（C 基础）、[[栈与队列]]（理解函数调用栈）
后续衔接：[[#5. 搜索顺序与剪枝效果：升序枚举为什么更强]]、动态规划（素材原话"它也是一种常见的动态规划实现方式"；DP 篇待产出，先文字锚定）

**① 它解决什么问题**

PPT 定义（slide 2）："因为在搜索中，相同的传入值往往会带来相同的解，那我们就可以用数组来记忆已经遍历过的状态的信息，从而避免对同一状态重复遍历的搜索实现方式。确保了每个状态只访问一次，它也是一种常见的动态规划实现方式。"**记忆化搜索 = 递归 + 备忘录数组**：函数每次算出答案就存进数组，下次带着相同参数进来直接查表返回。复杂度总账（P1464）：参数钳制到 [0,20] 后状态只有 $21^3 = 9261$ 个，每个状态只深算一次，之后全是 O(1) 查表；题目查询组数至多 $10^5$（洛谷题面数据规模），总体 $O(21^3 \cdot c + T)$ 级别，c 为常数。

**② 直觉理解**

模型级类比：**错题本**。第一次遇到某道题，费劲算出答案并抄到本子对应页码；再遇到同一题，翻本子即可。页码 = 参数组合，本子 = 备忘录数组。前提是"同一题答案永远一样"——若答案会随时间变（带全局状态的搜索），抄本子就会抄到旧答案。

用具体数字跑一遍：w(2,2,2) 不满足 a<b<c，走 else 分支，需要 w(1,2,2)、w(1,1,2)、w(1,2,1)、w(1,1,1) 四个子答案；这四个又要各自展开，反复落到 w(0,…) 一族——同一参数组合在树里大量重复。备忘录把每个组合只算一次，w(2,2,2) 最终 $2+2+2-2=4$（官方样例值，实测通过）。

**③ 原理与推导**

为什么 w 有重复子问题：递归式只由参数 (a,b,c) 决定下一步调用哪些 (a',b',c')，与"从哪条路径来"无关——所以不同路径抵达同一参数时，后续展开完全相同。实测佐证：无记忆化版算 w(8,8,8) 要 4,464,671 次调用、w(10,10,10) 要 489,048,226 次；而记忆化后整个 [0,20]³ 定义域只有 9261 个状态（w(20,20,20) 实测 3,158 次调用即完成）。**为什么这里必须记忆化**：调用数随参数指数增长而状态数只有多项式量级，差距就是重复度。

记忆化成立的三个前提：(a) 函数值只依赖参数（无副作用）；(b) 参数能映射到数组下标；(c) 同参数答案恒定（无后效性）。w 三条全满足。

两个关键实现顺序（素材 slide 2 特别强调）：**负数特判必须在查备忘录之前**——素材原话："在输入中可能存在负数，如果一开始的判断语句只写 if(dp[x][y][z]) 就炸了（因为不能访问数组负数下标），因此需要加一个特判。"因为递归会产生 0 与负数参数（else 分支 a-1 递减、题面输入可为负），先碰数组就是 RE。**值域钳制其次**：a>20 直接归到 w(20,20,20)，把无界的参数域压缩进 9261 个状态，这是"数组能开下"的原因。

**设计动机**：为什么素材版在顶层不缓存 f[a][b][c] 本身、只缓存各子层？因为子层全部命中缓存后，顶层只剩一次加减法；同一查询再来一遍，四个子层 O(1) 返回，顶层重算也只是常数代价。它与"入口处缓存 f[a][b][c]"的常见写法语义等价（附录 A-3 登记），少写一行；若想每状态严格只算一次，在 else 分支末尾补 `f[a][b][c] = 返回值` 即可。

**④ 代码演示**

取自源文件 P1464.cpp（改动：删去未使用的 `<algorithm>` `<queue>` `<utility>` 并补 `<cstdio>`；w 函数逻辑逐行原样。完整版见源文件 P1464.cpp）：

```cpp
#include <cstdio>
#include <cstring>
#define ll long long
int f[25][25][25];                        // 备忘录：f[a][b][c] 记 w(a,b,c)；-1 表示未算
ll w(ll a, ll b, ll c) {
    if (a <= 0 || b <= 0 || c <= 0) return 1;          // 特判 1 必须最先：挡负下标（素材原话的坑）
    else if (a > 20 || b > 20 || c > 20) {             // 特判 2：值域钳制，复用缓存
        if (f[20][20][20] != -1) return f[20][20][20];
        return f[20][20][20] = w(20, 20, 20);
    }
    else if (a < b && b < c) {                         // 递归式分支一
        if (f[a][b][c-1] == -1)   f[a][b][c-1]   = w(a, b, c-1);     // 复杂度：子层全部 O(1) 命中或只算一次
        if (f[a][b-1][c-1] == -1) f[a][b-1][c-1] = w(a, b-1, c-1);
        if (f[a][b-1][c] == -1)   f[a][b-1][c]   = w(a, b-1, c);
        return (ll)f[a][b][c-1] + f[a][b-1][c-1] - f[a][b-1][c];
    }
    else {                                             // 递归式分支二（其余情况）
        if (f[a-1][b][c] == -1)     f[a-1][b][c]     = w(a-1, b, c);
        if (f[a-1][b-1][c] == -1)   f[a-1][b-1][c]   = w(a-1, b-1, c);
        if (f[a-1][b][c-1] == -1)   f[a-1][b][c-1]   = w(a-1, b, c-1);
        if (f[a-1][b-1][c-1] == -1) f[a-1][b-1][c-1] = w(a-1, b-1, c-1);
        return (ll)f[a-1][b][c] + f[a-1][b-1][c] + f[a-1][b][c-1] - f[a-1][b-1][c-1];
    }
}
// main（完整版见源文件）：memset(f,-1,sizeof f) 一次；循环读 a b c；
// 遇 -1 -1 -1 停止；否则 printf("w(%lld, %lld, %lld) = %lld\n", a, b, c, w(a,b,c))
```

**执行追踪表**（官方样例 w(2,2,2)，f 初始全 -1）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | w(2,2,2) | f 全 -1 | 2<2 不成立，走 else 分支 | 挂起，等 4 个子层 |
| 2 | w(1,2,2) | f 全 -1 | 1<2 成立但 2<2 不成立，走 else | 挂起 |
| 3 | w(0,2,2) | f 全 -1 | a<=0 命中特判 1（未碰数组） | 返回 1 |
| 4 | w(1,2,2) 回溯 | w(0,…) 族全为 1 | 1+1+1-1 | 返回 2 |
| 5 | w(2,2,2) 回溯 | f[1][2][2]=f[1][1][2]=f[1][2][1]=f[1][1][1]=2 | 2+2+2-2 | 返回 4 |

**错误写法对照**：

```diff
- ll w(ll a, ll b, ll c) {
```

### 3. 可行性剪枝与最优性剪枝：给搜索树装闸门

前置依赖：[[#1. 搜索树与重复子问题：搜索为什么慢]]
后续衔接：[[#4. 数的划分 P1025：升序去重与可行性剪枝实战]]

**① 它解决什么问题**

PPT 定义（slide 1）："最优性/可行性剪枝：在搜索中导致运行慢的原因有一种是在当前解已经比已有解更差，或者可明确判断出当前解不合法时仍然在搜索，那么我们只需要判断一下当前解是否已经差于已有解或者当前解是否合法即可。"据此分两味药：**可行性剪枝**——当前部分解已不合法（且不会再变合法）就停；**最优性剪枝**——求最优解时当前部分解的代价已不优于已知最优就停。复杂度视角：剪枝不改变问题本身，改变的是**实际访问的搜索树节点数**。实测（n=6,k=3 统计有序三元组和为 6）：朴素 259 次调用，仅在函数入口加一行 `if (sum > n) return;` 就降到 133 次，答案不变（附录 B-5）。

**② 直觉理解**

模型级类比：**单向闸门**。在搜索树的每条路上装一道闸，闸的规则是"一旦触发，这条路往后全部无望"。闸门可靠的前提：状态沿这条路**单向变坏**——钱花出去回不来、长度加上了减不掉。若路上还有"往回走"的操作（如某些变换题），闸门条件就是错的。

用具体数字跑一遍（上例 n=6,k=3）：第 1 位选 6 后进入第二层，sum=6；第二层再选任何 i，sum=6+i≥7>6——入口一行判断直接把 36 个第二层节点里的多数连同它们的 6 个叶子整树拦下。

**③ 原理与推导**

可行性剪枝的正确性条件：存在关于决策的**单调量** g，沿当前路径 g 单调变化且一旦越过合法边界就永不回头。对"和为 n"型：g=sum，每步至少 +1，sum>n 后永不可能回到 n，故可剪。**反例（何时不能剪）**：若状态允许减法（比如操作序列里同时有 +x 与 -x），sum 超界后仍可能降回来，同一行判断就会错剪。这回答了"为什么剪枝条件不能照抄、必须逐题验证单调性"。

最优性剪枝的正确性条件：代价函数沿路径**单调不降**，且当前代价 ≥ 已知最优解时后续只会更差。它只适用于"求最优值"类问题；统计方案数的题（如 P1025）没有"最优"概念，不适用（注明：素材对最优性剪枝仅两句描述、无例题，本节展开为通识补充）。

**设计动机**：为什么剪枝判断要尽量放在"递归调用之前"（循环里判断后再决定调不调用）而不是子函数入口？入口判断省不掉那一次函数调用与一层栈帧，循环前判断一次比较就能整段不调。实测对比：上例中把判断放进循环（等效于剪枝版再省掉 21 次入口即返的调用）收益进一步扩大；PPT 示例代码用的正是循环内 `break`——比 continue 更彻底，一次比较切断 i 方向的整段候选（其原理与适用条件在知识点 5 展开）。

**④ 代码演示**

在知识点 1 骨架上加入口可行性剪枝（自编，标注：素材未给通用剪枝模板代码，属补充）：

```cpp
#include <iostream>
using namespace std;
int n, k, ans;
void dfs(int stp, int sum) {
    if (sum > n) return;              // 可行性剪枝：sum 已超界且每步至少 +1，永无回头（前提：只加不减）
    if (stp > k) {                    // 终止判断必须仍在剪枝之后：先排无望，再验合法
        if (sum == n) ans++;
        return;
    }
    for (int i = 1; i <= n; i++)
        dfs(stp + 1, sum + i);
}
int main() {
    cin >> n >> k;
    dfs(1, 0);
    cout << ans << endl;
    return 0;
}
```

|:---:|:---:|:---|:---|:---|

- 真题：洛谷 P1120 小木棍 [数据加强版]——可行性与最优性剪枝同场实战的经典（降序枚举、同长剪重、超长即剪等一整套闸门组合；标注：资料未覆盖，属补充，题号真实）。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 剪枝条件跨题照抄。"sum 超界就剪"只在"每步至少加正数"时成立；状态可减、可清零的题必须重新验证单调性，否则错剪漏解（WA）。

> [!caution]
> **【易错】** 边界把 `sum > n` 写成 `sum >= n`。sum==n 可能恰是合法解（或能延伸成合法解），多剪一个等号就漏解（答案错）。

> [!note]
> **【注意】** 最优性剪枝要有初始最优解作比较基准（通常先贪心/上界求一个可行解），否则 best 为空无从比较。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n、k 缺一不可，无空输入形态；读入失败即退出（预期：不崩）。
> 2. 单元素：k=1, n=5 → 第 1 位选 5 即命中，输出 1。
> 3. 全相同：n=k → 全 1 方案，输出 1（预期：剪枝不影响退化情形答案）。
> 4. 严格递增：n=10, k=4 → 存在 (1,2,3,4) 等 5 种有序解（升序 1 种）；剪枝后答案与朴素一致（预期：对拍通过）。
> 5. 严格递减：不适用——输入只有 n、k；等价场景见知识点 5 的降序枚举实验。
> 6. 极值：n=200, k=6 → 剪枝版秒出；朴素版 $6.4 \times 10^{13}$ 状态超时（预期：剪枝版 AC，朴素版 TLE，量化剪枝价值）。

回扣开场：闸门装在"单向变坏"的方向上，无望的子树整棵免搜——259 次调用砍到 133 次。现在你能给任何单调性成立的搜索装闸了；下一节把闸门装进真题。

### 4. 数的划分 P1025：升序去重与可行性剪枝实战

前置依赖：[[#1. 搜索树与重复子问题：搜索为什么慢]]、[[#3. 可行性剪枝与最优性剪枝：给搜索树装闸门]]
后续衔接：[[#5. 搜索顺序与剪枝效果：升序枚举为什么更强]]

**① 它解决什么问题**

洛谷 P1025（NOIP 2001 提高组第二题，素材 slide 1 指定例题）：把整数 n 分成 k 份，每份非空，**不考虑顺序**，求方案数。数据范围 $6 < n \le 200$，$2 \le k \le 6$，时限 1s（洛谷题面）。样例 n=7,k=3 输出 4：1+1+5、1+2+4、1+3+3、2+2+3。它同时踩中知识点 1 的两种病：朴素有序枚举既重复计数（(1,1,5) 的三种排列数三次）又搜无望分支（首位选 199 的整棵子树）。复杂度账：朴素 $O(n^k)$（$200^6 \approx 6.4 \times 10^{13}$）必死；升序去重 + 可行性剪枝后，实际访问的节点数实测仅数十万量级（n=60,k=8 时 387,237 次调用，附录 B-5），1s 内轻松通过。

**② 直觉理解**

模型级类比：**排队报数**。让 k 个数从小到大站队：第 1 个位置站最矮的，后面每个位置的人不得矮于上一位；闸门规则是"剩下的人哪怕全都取当前身高，队伍总重也超了，就地解散"。排队规则消灭重复（一个划分只有一种站法），闸门消灭无望。

用具体数字跑一遍：n=7,k=3 的 4 种分法即上述样例；若不去重、按有序枚举，会数出 $C_6^2 = 15$（插板法：6 个空隙插 2 板），与 4 之差全是排列重复。

**③ 原理与推导**

去重推导：每个"不计顺序"的划分对应**唯一**一个非降序列（把 k 个数排序即得），且任何非降序列必是某个划分的排序。因此"按非降序枚举"与"划分集合"一一对应——枚举时维护上一位的值 last，令当前位 $i \ge last$，重复解被结构性消灭（不是查重，是根本生成不出来）。

可行性剪枝推导：第 stp 位选 i 时，由于升序，后面 $k - stp$ 位每个至少也是 i，加上当前位共 $k-stp+1$ 位，总和至少 $sum + i \times (k-stp+1)$。若它已 > n，则 i 再增大只会更糟——对 i 的枚举是递增方向，一旦超界，**后面所有 i 全部超界**，故用 break 一次切断整段。这就是素材思路原话："当枚举当前划分所用分数时应该从 last 枚举到 sum+i*(k-cur)<=n 为止，因为之后划分的分数一定大于或等于当前划分所用分数"（17.搜索优化.pptx slide 1）。

**设计动机**：为什么循环上界写 $n-k+1$ 而不写 n？即使 k 个数全取最小值 1，首位也不可能超过 $n-(k-1)$——这是个宽松的保护上界，真正收紧靠 break 剪枝；两者一层保底、一层精剪，分工明确。为什么 last 与 sum 都作参数：传值副本天然回溯（呼应知识点 1 的设计动机）。

**④ 代码演示**

取自源文件 P1025.cpp（改动：删去未使用的 `<algorithm>` `<cstring>` `<queue>` `<utility>` 四个 include；其余逻辑逐行原样，含"可行性剪枝！！！！"原注释）：

```cpp
#include <iostream>
using namespace std;
int n, k;
int ans = 0;
void dfs(int last, int stp, int sum)  // last：上一位选的数；stp：本次给第 stp 位选数；sum：已选之和
{
   if (stp > k)                       // 终止：k 位填完
   {
      if (sum == n) ans++;            // 验票：总和恰为 n
      return;
   }
   for (int i = last; i <= n - k + 1; i++)  // 升序：起点 last，去重关键（上界 n-k+1：宽松保护）
   {
      if (sum + i * (k - stp + 1) > n) break;  // 可行性剪枝！！！！超界则更大的 i 全超界
      dfs(i, stp + 1, sum + i);
   }
}
int main()
{
  cin >> n >> k;
  dfs(1, 1, 0);
  cout << ans << endl;
  return 0;
}
```

|:---:|:---:|:---|:---|:---|

| 3 | dfs(1,3,2) | 同上 | i=5：2+5=7>6 | break，i=5、6 整段剪掉 |

| 8 | dfs(2,2,2) | 栈 [2] | i=3：2+3×2=8>6 | break |

```diff

+ for (int i = last; i <= n - k + 1; i++) {        // 素材原样：起点 last，每个划分只生成一次
- if (sum + i * (k - stp) > n) break;              // 坑2：系数少算当前位——剪得偏晚，白搜一批分支（答案仍对，性能损失）

- if (sum + i * (k - stp + 2) > n) break;          // 坑3：系数多算一位——合法解被剪，(7,3) 输出 2（WA，样例即挂）

```

**⑤ 典型应用**

- 真题：洛谷 P1025 本题。实测官方样例 (7,3) 输出 4（附录 B-5）；自测 (6,3) 输出 3、(200,6) 输出 4,132,096（独立划分数 DP 对拍一致）。
- 真题：洛谷 P1441 砝码称重等"枚举 + 搜索"组合题同用升序去重控制重复（标注：资料未覆盖，属补充，题号真实；思路一行：先升序枚举删哪些砝码，再搜索称重可达和）。
- 迁移题（自编）：统计把 n 分成 k 个**互不相同**的正整数（不计顺序）的方案数，$6 < n \le 200$，$2 \le k \le 6$。建议先独立做，再对照题解：把素材代码的递归起点从 `dfs(i, …)` 改为 `dfs(i + 1, …)`（严格递增），剪枝式改为"剩余 $k-stp+1$ 位至少各取 $i, i+1, \ldots, i+k-stp$"的下界和 $sum + i \times (k-stp+1) + \frac{(k-stp)(k-stp+1)}{2} > n$ 时 break；其余不动。样例 (10,3)：1+2+7、1+3+6、1+4+5、2+3+5，输出 4。

**⑥ 坑点与边界**

> **【易错】** 起点 last 写成 1（或忘传 last）。去重靠的是"结构性只生成非降序列"，起点错一个字符，重复计数全部复活（④对照坑 1，WA）。

> [!caution]
> **【易错】** 剪枝系数抄错。少算一位只是变慢（TLE 风险），多算一位直接错剪（WA）；系数必须从"剩余位数每个至少取多少"现场推导（④对照坑 2、3）。

> **【注意】** 答案量级与溢出：p_6(200)=4,132,096（独立 DP 实测），int 足够；但有序拆分上界 $C_{199}^5 \approx 2.47 \times 10^9$ 已超 int——若把题面改成"计有序"或扩大 k，优先换 long long 再说话。

### 5. 搜索顺序与剪枝效果：升序枚举为什么更强

前置依赖：[[#2. 记忆化搜索：P1464 Function 的去重]]、[[#3. 可行性剪枝与最优性剪枝：给搜索树装闸门]]、[[#4. 数的划分 P1025：升序去重与可行性剪枝实战]]
后续衔接：图上搜索与最短路（图的存储/邻接表，PPT 下节课复习点，待产出，先文字锚定）

**① 它解决什么问题**

PPT 把"减小状态空间"与记忆化并列为剪枝方式（slide 1），而 P1025 思路里"按升序记录每一次划分"正是**搜索顺序**的设计。本节回答一个对比性问题：为什么同样的剪枝条件，换个枚举方向，效率就差一截？复杂度层面：剪枝的收益取决于"无望状态是否聚集在枚举方向的尾部"——聚集则一次 break 切断整段，不聚集则只能逐个试探。实测（同一题"n 分 k 份"，答案完全相同，附录 B-5）：n=40,k=6 升序 17,606 次调用、降序 32,459 次（1.8 倍）；n=60,k=8 升序 387,237 次、降序 819,682 次（2.1 倍）。差距随约束变紧而扩大。

**② 直觉理解**

模型级类比（沿用知识点 3 的单向闸门）：**闸门只装在"越来越糟"的方向上**。升序枚举时，i 越选越大、离"超界"越来越近——坏情况全在尾部，一道闸整段拦住；降序枚举时，i 越选越小、可行性反而恢复——坏情况堆在起点方向，闸门形同虚设，只能逐个 continue 试过去。搜索顺序设计的本质：**让状态沿枚举方向单调变坏，给闸门制造用武之地**。

用具体数字跑一遍（n=6,k=3，第 2 位已选和为 1）：升序版枚举 i=4 时判断 1+4×2=9>6，break——i=4 之后整段一次比较清场；降序版枚举到 i=4 时只知 1+4=5≤6 必须放行，且 i 再小可行性只增不减，没有任何"整段无望"可剪。

**③ 原理与推导**

形式化：break 的收益是"一次比较省掉一整段候选"，其成立条件是存在关于 i 的单调量 g，使 i 越过阈值后**所有**后续 i 均不合法。升序版有 g(i)=sum+i×(k-stp+1)：每个未选位至少取 i，i 增则下界增，单调可断；降序版的剩余位是"每个至多 i"，只能给出**上界**估计，与"至少要凑够"无关——下界退化为每位至少 1，剪枝条件变成与 i 无关的 sum+(k-stp+1)>n，循环内无可切段。这就是升序强于降序的代数根源。

**设计动机**：记忆化与剪枝怎么选？（素材把两者统称剪枝，本篇按"治重复/治无效"分开讲，此处为归纳补充。）判据是搜索树的病灶：**重复子问题密集且状态可编号 → 记忆化**（P1464：状态 9261 个封顶，收益指数级）；**无效分支密集但状态本身海量难编号 → 剪枝**（P1025：状态 $n^k$ 无法列表，只能砍）；两者可叠加（P1025 的升序去重本质也是"让重复状态不生成"，与记忆化殊途同归）。

**④ 代码演示**

升序版与降序版对照（自编实验代码，调用计数；降序版同样按非增序列去重，答案与升序一致）：

```cpp
#include <cstdio>
long long n, k, cnt, ans;
void dfsAsc(long long last, long long stp, long long sum) {   // 升序版（素材原逻辑 + 计数）
    cnt++;
    if (stp > k) { if (sum == n) ans++; return; }
    for (long long i = last; i <= n - k + 1; i++) {
        if (sum + i * (k - stp + 1) > n) break;   // 坏方向在尾部：一次比较切断整段
        dfsAsc(i, stp + 1, sum + i);
    }
}
void dfsDesc(long long last, long long stp, long long sum) {  // 降序版（非增序列，答案相同）
    cnt++;
    if (stp > k) { if (sum == n) ans++; return; }
    for (long long i = last; i >= 1; i--) {
        if (sum + i > n) continue;   // i 减小可行性恢复：只能逐个试，无整段可剪
        dfsDesc(i, stp + 1, sum + i);
    }
}
int main() {
    n = 60; k = 8;
    cnt = 0; ans = 0; dfsAsc(1, 1, 0);  printf("asc  ans=%lld calls=%lld\n", ans, cnt);
    cnt = 0; ans = 0; dfsDesc(n, 1, 0); printf("desc ans=%lld calls=%lld\n", ans, cnt);
    return 0;
}
```

**执行追踪表**（n=6,k=3，第 2 位 sum=1 处两种顺序的分叉对比；以及实测总账）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 升序 dfs(4,2,1) 枚举 i=4 | sum=1，剩余 2 位 | 1+4×2=9>6 | break，i=4 起整段剪掉 |
| 2 | 降序 dfs(4,2,1) 枚举 i=4 | sum=1，剩余 2 位 | 1+4=5≤6 | 放行，必须逐个试 |
| 3 | 降序继续 i=3,2,1 | sum=1 | 剪枝条件与 i 无关 | 无整段可剪，逐一枚举 |

实测总账（-O2，n=60,k=8）：升序 387,237 次调用、降序 819,682 次，答案同为 37,638——**答案不挑顺序，效率挑**。

**错误写法对照**：

```diff
- void dfsDesc(...) { for (i = last; i >= 1; i--) if (sum + i * (k - stp + 1) > n) continue; ... }
+ // 坑1：降序版误用升序的剪枝式——"每位 ≥ i"的下界估计只对升序成立，降序下会错剪合法解（WA）
+ // 正解：降序版的合法剪枝只能基于"每位至少 1"，如 sum + i > n 时 continue（本节④降序版原样）
- for (i = last; i <= n - k + 1; i++) { if (sum + i * (k - stp + 1) > n) continue; ... }
+ // 坑2：升序版把 break 降级为 continue——判断照样做，整段切断的收益全丢（TLE 风险）
+ if (sum + i * (k - stp + 1) > n) break;   // 对：单调方向上尾部整段无望，break 才兑现剪枝价值
```

坑 1 是本次撰写验证时真实踩过的错：实验代码降序版初稿误用升序剪枝式，导致漏解，被"升序/降序答案对拍"当场抓住——对拍不是走过场。

**⑤ 典型应用**

- 真题：洛谷 P1025——升序顺序 + 可行性剪枝的组合范本（知识点 4）。
- 真题：洛谷 P1120 小木棍 [数据加强版]——搜索顺序的名场面：木棍**从长到短**枚举（长棍约束强、分支少），配合同长剪重、超长即剪等多重闸门（标注：资料未覆盖，属补充，题号真实）。
- 迁移题（自编）：把知识点 4 的迁移题（互不相同的划分）分别写出升序版与降序版，实测两者调用数并解释差在哪一层。建议先独立做，再对照题解：答案应完全一致（对拍），调用数升序更少，原因与本节③的代数推导同构——"每个至少取多少"的下界估计只有升序给得出。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 跨方向照搬剪枝式。剪枝系数（每位至少取多少）来自枚举方向的单调性假设，方向一换假设即失效（④对照坑 1，错剪漏解）。

> [!caution]
> **【易错】** 用 break 的方向写反（递减枚举却写升序式 break）。break 只在"沿枚举方向单调变坏"时合法，否则要么剪不动、要么错剪。

> [!note]
> **【注意】** "答案与顺序无关"永远要靠对拍验证——本节实验中升序/降序答案一致是结论的前提，不是当然。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用——本节是方法论对比，输入形态与知识点 4 完全一致（n、k 两数）。
> 2. 单元素：k=1 → 升序/降序均输出 1、调用数同为 2（预期：小数据无差距，差距随 k 增大显现）。
> 3. 全相同：n=k → 两版均输出 1（预期：退化情形顺序无关）。
> 4. 严格递增：升序枚举即本篇主线（预期：break 高频触发）。
> 5. 严格递减：降序枚举即对照实验（预期：答案相同、调用数约 1.8~2.1 倍，实测见④）。
> 6. 极值：n=200, k=6 → 两版均应输出 4,132,096 且对拍一致（预期：升序明显更快；若不一致说明某版剪枝条件写错）。

回扣开场：升序枚举把"坏情况"赶到尾部，break 才有整段可切——搜索顺序是剪枝的前置工程。现在你掌握了本篇全部工具，面对任何搜索题都能按"病灶 → 药方 → 方向"三步选型。

## 四、总结与自测

### 核心内容（一页纸速览）

- **搜索树模型**：决策序列成树，朴素复杂度 = 状态空间 $n^k$；两种病——重复子问题、无效分支（PPT slide 1："减少对不合法及重复的答案的枚举"）。
- **记忆化搜索**：递归 + 备忘录，同参数只深算一次；P1464 三件套——负数特判最先、值域钳制 [0,20]、f[25]³ 备忘录；状态 9261 个，实测 w(20,20,20) 仅 3,158 次调用。
- **可行性剪枝**：状态单向变坏（sum 只增）时超界即停；正确性靠单调性，反例是可减状态；实测 259→133 次调用。
- **最优性剪枝**：代价单调不降 + 已不优于已知最优即停；仅适用求最优值类，计数类不适用（素材仅两句，属补充）。
- **P1025 数的划分**：升序枚举（起点 last）结构性去重 + break 可行性剪枝（系数 k-stp+1 逐题推导）；(7,3)=4，(200,6)=4,132,096。
- **搜索顺序**：升序把坏情况赶到尾部，break 才有整段可切；降序实测多耗 1.8~2.1 倍调用；记忆化治可编号的重复状态，剪枝治难编号的无效分支。
