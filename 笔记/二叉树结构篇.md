## 一、为什么需要它

数组是"一个前驱一个后继"的线性世界，但现实大量结构是**一对多**的：文件系统的目录、比赛的淘汰赛对阵、族谱、公司组织架构。B 源第 1 页开宗明义："集合中的元素关系呈现出一对多的情况"——这就是**树**：n（n ≥ 0）个结点的有限集合，有且仅有一个根，其余结点分成 m 个互不相交的子集，每个子集又是一棵树（"树中还有树"的递归定义）。

而**二叉树**是树家族中被研究得最透的一种：每个结点至多两个孩子，且左右有序。为什么偏偏是它？因为"二分"是计算机最舒服的形态——一分为二后每层规模减半，$n$ 个结点的树深只有 $O(\log n)$；又因为**任何普通树都能规范化成一棵二叉树**（知识点 7），所以学好二叉树等于学好整个树家族。

带着一个悬念进场（本篇回扣线）：同一棵树，先序读出 `A B C D E F G H K`，中序读出 `B D C A E H G K F`——三种读法为什么都对？只给其中两个，你能把树**原样重建**吗（B 源第 9 页留了两道这样的题）？学完知识点 4，这两题就是两分钟的手推游戏。

本篇讲 7 个知识点：树的存储三式、二叉树定义与五条性质、二叉树的两种存储、遍历总纲（递归三序与层次遍历）、非递归遍历、中序线索二叉树、树/森林与二叉树互转。顺序理由：先会"存"（知识点 1-3）才谈得上"走"（知识点 4-5）；线索化（知识点 6）是遍历的直接深化；互转（知识点 7）回收知识点 1 的孩子兄弟表示法，把全篇收拢。

## 二、知识点逐讲（每个知识点一节，共 7 节）

### 1. 树的存储三式：双亲、孩子、孩子兄弟

前置依赖：[[链表]]（孩子链表与孩子兄弟链表都是链表变体）、数组与 struct（C 基础）
后续衔接：[[#3. 二叉树的顺序存储与链式存储]]（"存什么买什么"哲学延续）、[[#7. 树、森林与二叉树的互转：孩子兄弟的另一副面孔]]（孩子兄弟法在此引爆）、[[二叉树竞赛篇]]（存储是递归设计的地基）

**① 它解决什么问题**

树是非线性的，而内存是线性的——树的存储就是回答"**用线性结构怎么装下一对多**"。三种答案权衡不同（B 源 1.3 节）：**双亲表示法**找父亲飞快；**孩子表示法**找孩子飞快；**孩子兄弟表示法**把树规范成二叉链表。性质与代价对照：

| 表示法 | 结点内容 | 找双亲 | 找孩子 | 空间 |
|--------|----------|--------|--------|------|
| 双亲表示法 | 数据 + 双亲下标 | $O(1)$ | $O(n)$ 全表扫 | 紧凑 |
| 孩子表示法 | 数据 + 孩子链表头 | $O(n)$ 全表扫 | $O(\text{链长})$ | 链表开销 |
| 孩子兄弟表示法 | 数据 + 长子指针 + 右兄弟指针 | $O(n)$ | $O(\text{兄弟链长})$ | 每结点固定 2 指针 |

**② 直觉理解**

模型级类比：**三种通讯录**。双亲表示法是"只记我爸是谁"的花名册——找我爸翻一页就好，找我的孩子得把整本名册翻遍；孩子表示法是"只记我孩子花名"的家长群——找孩子秒回，找我爸要问遍所有群；孩子兄弟表示法是"只记大儿子 + 隔壁兄弟"的家族链——大儿子是头，兄弟手拉手，谁都能顺藤摸到。

用具体数字跑一遍（源码样例 13 结点树：A 的孩子 B、C、D；B 的孩子 E、F；C 的孩子 G；D 的孩子 H、I、J；E 的孩子 K、L；H 的孩子 M）：双亲表示法里 `t[0]={A,-1}`、`t[1]={B,0}`……查询"谁的孩子是 B"要扫全部 13 项；孩子表示法里 A 的孩子链表串着孩子下标，查询 A 的孩子直接沿链走；孩子兄弟表示法里 B 同时是"A 的长子"（A->ch = B）和"C 的左邻"（C->bro 的链头经过 B）。

**③ 原理与推导**

三种表示法的推导只有一个支点：**存什么指针，就买什么能力**。

- 双亲表示法（源码）：`t[i] = {data, fa}`，根的 `fa = -1`（源码注释"根结点没有双亲……置为 -1"）。插入新结点 = 数组追加 + 记下父下标，两步都 $O(1)$（找父下标的 Find 是 $O(n)$，见⑥）。找孩子只有一条路：全表扫 `t[j].fa == xi`。
- 孩子表示法（源码）："顺序表 + 链表"的组合（B 源原话）——顺序表存结点，每个结点挂一条**孩子下标链表**。叶子链表为空。找孩子沿链走，找双亲反过来扫全表、逐链检查。B 源还指出可以"将双亲表示法和孩子表示法合二为一"（结构体里同时留 `fa` 与 `son`——源码注释掉了 `//int fa;`，正是给合并预留的位置）。
- 孩子兄弟表示法（源码）：每个结点两个指针——`ch` 指向**长子**（第一个孩子）、`bro` 指向**右边的亲兄弟**。找结点 x 的所有孩子 = 先 `firstchild` 找到长子，再沿 `nextsibling` 一路向右（B 源原话）。它的真正价值在第 7 知识点引爆：这正是一棵**二叉链表**——`ch` 扮演左孩子、`bro` 扮演右孩子，任意树被规范化成了二叉树的形状。

**④ 代码演示**

双亲表示法核心，取自源文件 双亲表示法.c（改动：摘 Insert 与两段查询逻辑）：

```cpp
#define maxx 100
struct Node { char data; int fa; } t[maxx];    // fa = 双亲下标, 根为 -1
int sum = 0;                                   // 实际结点数

void InitTree(char root) {
    t[0].data = root; t[0].fa = -1; sum++;
}
void Insert(char x, char fx) {                 // x 挂到 fx 名下
    t[sum].data = x;
    t[sum].fa = Find(fx);                      // 记下父下标
    sum++;
}
// 找孩子: 只能全表扫 (xi = Find(x) 的下标)
for (int j = 0; j <= sum - 1; j++)
    if (t[j].fa == xi) printf("%c的孩子是%c\n", x, t[j].data);
```

孩子兄弟表示法核心，取自源文件 孩子兄弟表示法.c（改动：摘 Insert；`ch` 即长子、`bro` 即右兄弟）：

```cpp
typedef struct Node {
    int data;                                  // (源码 char 存值)
    struct Node *ch, *bro;                     // 长子 / 右兄弟
} Node, *TreeList;

TreeList Insert(TreeList r, char x, char fx) {
    Node* s = (Node*)malloc(sizeof(Node));
    s->data = x; s->ch = s->bro = NULL;
    Node* f = Find(r, fx);                     // 找到父结点
    if (f->ch == NULL) f->ch = s;              // x 是长子
    else {                                     // 否则沿 bro 链走到最右
        Node* p = f->ch;
        while (p->bro != NULL) p = p->bro;
        p->bro = s;                            // 尾插: 孩子序与输入一致
    }
    return r;
}
```

**错误写法对照**（对应⑥的三个坑）：

```diff
- 孩子表示法 Insert: 头插 (新孩子插链表头)        // 坑1：孩子序与输入序相反，实测输出 D C B
+ 孩子表示法 Insert: 尾插 (沿链走到最右再挂)       // 修复：孩子序与输入序一致
- 沿 p->bro 向下当右孩子用（把兄弟的子树当自己的）  // 坑2：bro 语义用错，遍历结果全错
+ ch 向下 (真孩子)、bro 横向 (兄弟)                // 修复：转换视角下 bro 才扮演右孩子
- Find(fx) 按值查下标，值重复时返回先者             // 坑3：重值时孩子挂错父结点，答案错
+ 保证值唯一，或按下标操作                          // 修复：消除按值定位的歧义
```

**⑤ 典型应用**

- 三份源码共用同一棵 13 结点样例树，查询实测（附录 B-5）：双亲表示法查 A → `A是根结点` + `A的孩子是B/C/D` 三行（全表扫得，按存储序输出）；孩子表示法查 A → 孩子输出 `D C B`——**头插法**（新孩子插链表头），孩子序与输入序**相反**；孩子兄弟表示法查 A → `B C D`——**尾插**，孩子序与输入序**一致**。查 D 时两者分别输出 `J I H` 与 `H I J`，对照鲜明。
- 选型场景：需要频繁"向上追溯"（并查集雏形、目录回退）用双亲法；需要频繁"向下展开"（层序处理）用孩子法；要把树当二叉树跑算法（遍历、转换）用孩子兄弟法。
- 自编迁移题（自编）：在双亲表示法上实现"输出结点 x 的所有祖先"（从 x 一路 fa 到 -1），并说明为何无需任何额外结构。建议先独立做，再对照题解。

  题解：`for (int i = t[xi].fa; i != -1; i = t[i].fa) printf(t[i].data)`——双亲法把"向上"做成了 $O(\text{深度})$ 的免费能力；反过来孩子表示法做"所有祖先"就要全表扫。选型即能力，能力即代价。

**⑥ 坑点与边界**

> [!caution]
> 三种表示法各有易踩处，最大的坑是"把一种表示法的能力错记到另一种头上"。

> **【易错】** 孩子表示法的孩子顺序想当然 → 头插法使链序与插入序相反 → 实测输出 `D C B`（需要正序时应尾插或先反转）。

> **【易错】** 孩子兄弟表示法把 `bro` 当"右孩子"语义用 → 兄弟不是儿子，两者的子树完全不同 → 记住 `ch` 向下、`bro` 横向（知识点 7 转换后 `bro` 才**扮演**右孩子）。

> **【易错】** 双亲表示法 Find 按值查下标 → 值重复时返回先者 → 源码 Find 循环无重复假设，竞赛使用应保证值唯一或按下标操作。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不建任何结点（双亲法 sum=0；孩子兄弟法根指针 NULL）→ 预期：全表扫无输出、根查询无操作，不崩溃。
> 2. 单元素：仅根 A → 预期：双亲法查 A 输出"A是根结点"（t[0].fa=-1）；孩子兄弟法查 A 的孩子输出为空（ch==NULL）。
> 3. 全相同：13 个结点值全为 A → 预期：Find 按值查恒返回下标 0，所有孩子挂错到根名下，结果错——必须按下标操作（坑 3 的推论）。
> 4. 严格递增：不适用：存储三式按"挂接关系"组织，与值的大小序无关。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：结点值取 char 极值 127/-128 → 预期：data 为 char 无算术运算、无溢出，存取正常；仅 printf 输出不可打印字符，不影响正确性。

### 2. 二叉树：定义、五形态与五条性质

前置依赖：[[#1. 树的存储三式：双亲、孩子、孩子兄弟]]（树的概念底座）、等比数列与归纳法（C 基础数学）
后续衔接：[[#3. 二叉树的顺序存储与链式存储]]（性质 4/5 是顺序存储的依据）、[[#4. 遍历总纲：递归三序与层次遍历]]（复杂度估计的依据）

**① 它解决什么问题**

**二叉树**（B 源 2.1 原话）："每个结点最多有两个子树的树结构。二叉树不允许存在度大于 2 的树。"**为什么要把一般的树收敛为"至多二分"？原因是：限制越死，能证明的定理越多**——它换来**可推导的数学性质**（本节核心）与**规范的下标体系**（下一节核心）。五个基本形态（B 源）：空集；仅有根；只有左子树；只有右子树（这两种叫**斜树**）；左右俱全。注意左右子树**有序**——交换左右是不同的二叉树。

两个特殊形态（B 源 2.2.1）：**满二叉树**——所有分支结点都有左右子树、所有叶子同层，"深度为 k 且有 $2^k - 1$ 个结点"；**完全二叉树**——深度 k、n 个结点，且每个结点都与深 k 满二叉树中编号 1 到 n 的结点**一一对应**（形象说法：最后一层可以不满，但必须从左往右连续排满）。

**② 直觉理解**

模型级类比：**满二叉树是"满员班车"，完全二叉树是"按顺序上客的班车"**——可以没坐满，但空座只能出现在最后一排的右侧，前排（左侧）绝不能有空位。

用具体数字跑一遍性质 3（B 源 2.2.2："在一棵二叉树中，叶结点的数目比度为 2 的结点数目多一个"）：随手画一棵 7 结点树——根 A（度 2），孩子 B（度 2）、C（叶子），B 的孩子 D、E（都叶子）。$n_2 = 2$（A、B），$n_0 = 3$（C、D、E），恰好 $n_0 = n_2 + 1$。这不是巧合，是③的代数必然。

**③ 原理与推导**

五条性质逐条落锤（B 源 2.2.2，推导不跳步）：

- **性质 1**：第 i 层至多 $2^{i-1}$ 个结点。归纳：第 1 层至多 1（即 $2^0$）；每结点至多 2 个孩子，第 i 层的每个结点都由第 i-1 层长出，故 $2^{i-1} = 2 \times 2^{i-2}$。
- **性质 2**：深度 k 的二叉树至多 $2^k - 1$ 个结点。各层取最大再求和：$\sum_{i=1}^{k} 2^{i-1} = 2^k - 1$（等比数列）。这正是满二叉树的结点数。
- **性质 3**：$n_0 = n_2 + 1$。B 源给出两式，展开写：其一，按度分类 $n = n_0 + n_1 + n_2$；其二，按"孩子总数 + 根"计数 $n = n_1 + 2n_2 + 1$（每个度 1 结点贡献 1 个孩子、度 2 贡献 2 个，再加无人贡献的根）。两式相减：$n_0 = n_2 + 1$。**与 $n_1$ 无关**——知道叶子数立刻知道二叉结点数。
- **性质 4**：n 个结点的完全二叉树深度为 $\lfloor \log_2 N \rfloor + 1$。由性质 2 夹逼：$2^{k-1} - 1 < n \le 2^k - 1$，即 $2^{k-1} \le n < 2^k$，取对数得 $k - 1 \le \log_2 n < k$，故 $k = \lfloor \log_2 n \rfloor + 1$。
- **性质 5**（B 源"特点"）：完全二叉树叶子只出现在第 k 或 k-1 层；若某结点右子树最大层次为 i，则左子树最大层次为 i 或 i+1——这是"从左往右连续"的等价刻画。

这五条是后面一切的下标公式与复杂度估计的地基：完全二叉树"深 $O(\log n)$"直接来自性质 4，堆、线段树都建立在这条之上。

**④ 代码演示**

本节是纯数学节，无需独立代码；性质 3 的计数验证用 10 行即可自证（自编，改动注记：自编验证片断）：

```cpp
// n0 = n2 + 1 的随机树验证: 递归统计三种度数的结点数
void count(BTNode* p, int& n0, int& n1, int& n2) {
    if (!p) return;
    if (!p->l && !p->r) n0++;
    else if (p->l && p->r) n2++;
    else n1++;
    count(p->l, n0, n1, n2);
    count(p->r, n0, n1, n2);
}
// 断言: 任意 n0 == n2 + 1 (随机建树 1e4 棵实测, 见附录 B-5)
```

**错误写法对照**（对应⑥的三个坑）：

```diff
- 满二叉树 = 每层都满的一般树                      // 坑1：混淆树的满与二叉树的满，概念题 WA
+ 满二叉树：分支结点全二 + 叶子同层，结点数恰 2^k - 1  // 修复：B 源 2.2.1 定义
- 完全二叉树 = 叶子在最后两层                      // 坑2：中间层空位错排也满足此条件，漏判
+ 还须编号与满二叉树 1..n 一一对应（最后一层从左往右连续）  // 修复：一一对应是判定核心
- 第 i 层至多 2^i 个结点                           // 坑3：第 1 层被算成 2 个，性质题全错
+ 第 i 层至多 2^(i-1) 个结点                       // 修复：层数从 1 起，指数是 i-1
```

**⑤ 典型应用**

- B 源 2.2.1 的判定题：给一棵树判断是否完全二叉树——按层编号后检查"编号连续且不越过 n"，顺序存储（知识点 3）下就是"数组中间无空洞"。
- 竞赛语境速算：深度 20 的二叉树最多 $2^{20} - 1 \approx 10^6$ 个结点——反推"10 万结点的随机树深约 17-20 层"，为递归遍历的栈深安全提供依据（系统栈通常可容纳 $10^5$ 递归深度，极端斜树 $10^5$ 层会爆栈，需改非递归——知识点 5 的存在理由之一）。
- 自编迁移题（自编）：一棵二叉树有 2025 个叶子，问度 2 结点几个、能否确定总结点数？建议先独立做，再对照题解。

  题解：$n_2 = 2024$（性质 3 反用）；总结点 $n = n_0 + n_1 + n_2 = 4049 + n_1$，$n_1$ 可为 0 到 2025 之间的任意值（受"完全"之外的形态自由），故不能确定。这题检验"性质 3 与 $n_1$ 无关"是否真懂。

**⑥ 坑点与边界**

> [!caution]
> 概念辨析题的重灾区：满与完全、层数与结点数。

> **【易错】** 把"满二叉树"理解为"每层都满的一般树" → 混淆树的满与二叉树的满 → 满二叉树同时要求"分支全二 + 叶子同层"，结点数恰为 $2^k - 1$。

> **【易错】** 完全二叉树只看"叶子在最后两层" → 中间层也可能有空位错排 → 还须"编号与满二叉树 1..n 对应"，即最后一层从左往右连续。

> **【易错】** 性质 1 的指数写成 $2^i$ → 第 1 层被算成 2 个 → 层数从 1 起，指数是 $i - 1$。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空树 n=0 → 预期：性质 4 的 $\lfloor \log_2 0 \rfloor$ 无定义，性质对空树不适用；验证程序 count(NULL,...) 得 n0=n1=n2=0，断言 n0==n2+1 不成立（0 与 1），须排除空树再验。
> 2. 单元素：n=1 → 预期：n0=1、n2=0，性质 3 成立；深度 k=1=$\lfloor \log_2 1 \rfloor+1$，性质 4 成立。
> 3. 全相同：不适用：五条性质只关心结点度数分布与层数，与值无关。
> 4. 严格递增：不适用：理由同上。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：n 取 $2^{30}$ 量级 → 预期：深度 31；用 int 统计 $2^k-1$ 型结点数在 k 到 32 时溢出（$2^{32}-1$ 超 int 上限），需 long long。

概念与性质就位。接下来回答"怎么存"——顺序与链式两条路，下标体系是关键。

### 3. 二叉树的顺序存储与链式存储

前置依赖：[[#2. 二叉树：定义、五形态与五条性质]]（编号规则依赖性质 4/5）、[[#1. 树的存储三式：双亲、孩子、孩子兄弟]]（存储哲学）
后续衔接：[[#4. 遍历总纲：递归三序与层次遍历]]（链式存储是遍历载体）、[[#6. 中序线索二叉树：把遍历结果焊进树里]]；堆与线段树（后续专题的基石）

**① 它解决什么问题**

**设计动机**：同一棵树为什么要备两套存法？因为"关系"和"算术"各有所长。B 源 2.3 给出两条存储路线：**顺序存储**——"依靠性质 5（完全二叉树的编号规则），可以将任意棵二叉树构造成满二叉树结构或完全二叉树结构，依据下标规则，就可以找到父结点，子结点"；**链式存储**——"每个结点定义两个指针域和一个数据域即可"。核心问题：下标规则如何把"树的关系"变成"算术"？答案是编号体系：编号 i 的结点，双亲 $\lfloor i/2 \rfloor$、左孩子 $2i$、右孩子 $2i+1$（B 源 3.1 原话："[i/2, i, 2i, 2i+1] 的规则"）。

**② 直觉理解**

模型级类比：**家属楼门牌**。完全二叉树像一栋每层房间数翻倍、从左到右连续入住的楼——知道你家门牌 i，就能算出你爸的门牌（i/2 向下取整）、你左邻右舍的孩子门牌（2i 与 2i+1），不用查表，纯算术。

用具体数字跑一遍（源码样例 7 结点树 a：孩子 b、c；b 的孩子 d、e；e 的孩子 f、g）：根 a 占 `data[1]`；b 是 a 的左孩子 → `data[1*2] = data[2]`；c → `data[3]`；d 是 b 的左孩子 → `data[4]`；e → `data[5]`；f 是 e 的左孩子 → `data[10]`；g → `data[11]`。查询 e（下标 5）：父亲 `data[2] = b`，左孩子 `data[10] = f`，右孩子 `data[11] = g`——全部是乘除法的产物，实测输出与手推一致（附录 B-5）。

**③ 原理与推导**

顺序存储的有效性依赖一条**无空洞不变量**：编号 1..n 连续占用。完全二叉树天然满足；一般二叉树则要"补成完全二叉树"再存——空位用占位符填充。源码用空格 `' '` 占位（注释原话"避免补上的 NULL 结点的影响"：初始化全数组为 `' '`，空孩子的查询结果就是空格）。

代价推演（不跳步）：一棵深度 k 的斜树只有 k 个结点，补成完全形态后编号最大 $2^k - 1$——**n 个结点最坏占 $2^n$ 数组**。所以 B 源的顺序存储落点在"完全二叉树"：堆、并查集、线段树这些"天然完全"的结构全都住数组，而一般树不这么存。

链式存储则完全按需分配：每个结点 `data + l + r`。本篇知识点 1 的孩子兄弟表示法已证明"二叉链表"还能兼任一般树的载体；源码 链式存储.c 更进一步加了 `fa` 指针（**三叉链表**）——买回 $O(1)$ 找父能力，结构变成 `data + l + r + fa`。三种指针自由组合，正是知识点 1"存什么买什么"哲学的延续。

**④ 代码演示**

顺序存储核心，取自源文件 二叉树的顺序存储.c（改动：摘建树与查询；`Find` 为按值查下标）：

```cpp
#define maxx 1005
char data[maxx];                               // 下标从 1 开始, 0 闲置
int flag;                                      // 0 左孩子 / 1 右孩子

int Find(char fx) {                            // 按值找下标 (值需唯一)
    int i;
    for (i = 1; i < maxx; i++) if (data[i] == fx) break;
    return i;
}
// 建树: 根占 data[1], 每读入 (x, fx, flag):
int fxi = Find(fx);
if (flag == 0) data[fxi * 2] = x;              // 左孩子: 下标翻倍
else           data[fxi * 2 + 1] = x;          // 右孩子: 翻倍再加一
// 查询 x (下标 i):
// 双亲 data[i/2] (i/2 == 0 即根); 左孩子 data[2i]; 右孩子 data[2i+1]
```

链式存储（三叉链表）核心，取自源文件 二叉树的链式存储.c（改动：摘结构体与 Insert 的新增两行）：

```cpp
typedef struct Node {
    char data;
    struct Node *l, *r, *fa;                   // 左孩子 / 右孩子 / 双亲
} BTNode, *BTree;
// Insert 在二叉链表版基础上只多一行:
BTree Insert(BTree root, char x, char fx, int flag) {
    BTNode* f = Find(root, fx);
    BTNode* s = (BTNode*)malloc(sizeof(BTNode));
    s->data = x; s->l = s->r = NULL;
    s->fa = f;                                 // 多的一行: 记下双亲
    if (flag == 0) f->l = s; else f->r = s;
    return root;
}
```

**执行追踪表**（数据取自②的 7 结点样例树 a(b,c; b(d,e); e(f,g))，空位为 `' '`）：

| 步骤 | 当前元素 | 结构状态（数组 data） | 动作 | 结果 |
|------|----------|----------------------|------|------|
| 1 | a（根） | data[1]='a'，其余 ' ' | InitTree 写入根 | 根占下标 1 |
| 2 | (b, a, 0) | Find(a)=1 | data[1*2]='b' | b 入位下标 2 |
| 3 | (c, a, 1) | Find(a)=1 | data[1*2+1]='c' | c 入位下标 3 |
| 4 | (d, b, 0) | Find(b)=2 | data[2*2]='d' | d 入位下标 4 |
| 5 | (e, b, 1) | Find(b)=2 | data[2*2+1]='e' | e 入位下标 5 |
| 6 | (f, e, 0) | Find(e)=5 | data[5*2]='f' | f 入位下标 10 |
| 7 | (g, e, 1) | Find(e)=5 | data[5*2+1]='g' | g 入位下标 11 |
| 8 | 查询 e（i=5） | data[2]='b'，data[10]='f'，data[11]='g' | i/2 取双亲，2i/2i+1 取孩子 | 双亲 b、左 f、右 g，与②手推一致 |

**错误写法对照**（对应⑥的三个坑）：

```diff
- 一般二叉树(斜树)硬用顺序存储                     // 坑1：n 结点最坏占 2^n 数组，MLE
+ 一般树用链式，完全形态才用顺序                   // 修复：按形态选存储路线
- char data[maxx];  // 依赖全局 0 初值直接建树      // 坑2：占位符失效，' ' 判空全错
+ for (i = 0; i < maxx; i++) data[i] = ' ';       // 修复：建树前全数组填占位符
- printf("%c", p->l->data);                        // 坑3：p->l 为空时解引用 RE
+ if (p->l != NULL) printf("%c", p->l->data);      // 修复：先判空再访问（源码查询的写法）
```

**⑤ 典型应用**

- 两份源码同输入实测（附录 B-5）：链式版查 e → `左孩子是f`、`右孩子是g`、`双亲结点是b`；查 a → 左 b、右 c、`该结点是根结点`。顺序版查 e → `该结点的父亲是:b`、`该结点的左孩子是f,右孩子是g`（空位以空格打印）；查 a → `该结点是根结点`、左 b 右 c。两种存储输出语义一致，印证下标规则与指针体系的等价。
- 竞赛主战场：**堆**（下标体系 + 完全二叉树 = 数组上的优先队列）、线段树（`p, 2p, 2p+1` 的树形分治）；这两者在后续 DP 与数据结构专题展开。
- 自编迁移题（自编）：编号从 0 开始（根为 0）时，双亲与孩子的下标公式是什么？与从 1 开始的公式相比差在哪？建议先独立做，再对照题解。

  题解：0 起编号时左孩子 $2i+1$、右孩子 $2i+2$、双亲 $\lfloor (i-1)/2 \rfloor$——从 1 起的公式全部"平移一位"。C++ 标准库/手写堆常用 0 起编号，竞赛阅读两种都要熟；错一位是高频事故。

**⑥ 坑点与边界**

> [!caution]
> 两条路线各有一个致命边界：顺序存储的空洞、链式存储的空指针。

> **【易错】** 一般二叉树硬上顺序存储 → 斜树补空位爆数组（n 结点最坏 $2^n$） → 一般树用链式，完全形态才用顺序。

> **【易错】** 顺序存储忘初始化占位符 → 全局数组初值 0，按 `' '` 判空失效 → 源码建树前全数组填 `' '`（"避免补上的 NULL 结点的影响"）。

> **【易错】** 链式存储访问 `p->l->data` 前不判 `p->l` → 空指针解引用 RE → 源码查询全部先 `if (p->l != NULL)` 再访问。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不读入任何结点（顺序版 data 全 ' '）→ 预期：查询任何值 Find 扫全表未命中、返回 maxx（循环走完的下标），若拿它算孩子下标将越界——查询前须确认 fxi < maxx。
> 2. 单元素：仅根 a 占 data[1] → 预期：查 a 输出"该结点是根结点"（i/2==0 不成立即 i==1 的判断，源码语义）；左孩子 data[2]=' ' 表示空。
> 3. 全相同：所有结点值均为 a → 预期：Find 恒返回最先命中的下标，建树全部挂到同一父名下，结构错——值须唯一或按下标操作。
> 4. 严格递增：不适用：顺序/链式存储按下标或指针定位，与值的大小序无关。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：深度 30 的斜树（30 个结点）→ 预期：补成完全形态编号最大 $2^{30}-1$，远超 maxx=1005，数组越界 RE——一般树必须用链式的实测形态。

存储问题解决。现在让树"动"起来——遍历是树的一切算法的骨架，也是本篇悬念的谜底。

### 4. 遍历总纲：递归三序与层次遍历

前置依赖：[[#3. 二叉树的顺序存储与链式存储]]（链式存储载体）、[[栈与队列]]（层次遍历的队列）、简单递归（C 基础）
后续衔接：[[#5. 非递归遍历：一个栈统一三序]]、[[#6. 中序线索二叉树：把遍历结果焊进树里]]、[[二叉树竞赛篇]]（递归设计的世界观地基）

**① 它解决什么问题**

**遍历**（B 源 3.1 原话）："沿某条搜索路径周游二叉树，对树中的每一个节点访问一次且仅访问一次。"线性结构只有一条搜索路径（唯一后继），二叉树每结点两个后继，于是产生"按什么序走"的问题。B 源给出两条总路线：**按层次**（广度，一层一层扫）与**按深度**（"一条道走到黑，然后再返回走另一条道"）。深度方向再按**根的访问时机**分三序：先序（根左右）、中序（左根右）、后序（左右根）。

**② 直觉理解**

模型级类比：**公司巡楼**。先序是"每进一层先见总经理再下基层"（自顶向下汇报）；后序是"先巡查完所有基层再向上汇报"（自底向上汇总）；中序是二叉树特有的"左半边巡完才见我"。

用具体数字跑一遍（B 源第 8 页示例树，即源码样例 9 结点树：A 左 B 右 E；B 右 C；C 左 D；E 右 F；F 左 G；G 左 H 右 K）：

| 遍历 | 序列 | 关键观察 |
|------|------|---------|
| 先序 | A B C D E F G H K | **首元素必是根** A |
| 中序 | B D C A E H G K F | **根 A 把序列切成左/右两半**：左 `B D C`、右 `E H G K F` |
| 后序 | D C B H K G F E A | **末元素必是根** A |

B 源第 8 页的三个结果与本表完全一致。层次遍历（B 源 3.2）：引入队列，根入队；取队头访问，其孩子依次入队；重复至队空——对本树输出 `A B E C F D G H K`。

**③ 原理与推导**

递归为什么是对的？B 源 3.3 给出递归两要素（原话）："**边界条件**：就是递归中止条件，避免出现死循环……**递归条件**：也就是递归体。将一个大问题分解为一步步小问题。"落到树遍历：边界 = `root == NULL` 直接返回（空树无需遍历）；递归体 = 按"根、左、右"的顺序拼装"访问根 + 对左右子树递归"。**三序的全部差异只在"访问根"插在哪个位置**——先序在递归前、中序在中间、后序在递归后。正确性由归纳保证：每棵子树内部完整走过三步、全局恰好访问每个结点一次。

复杂度：每个结点进出递归各一次，$O(n)$ 时间；递归深度 = 树高，最坏（斜树）$O(n)$ 系统栈，完全二叉树 $O(\log n)$。

层次遍历的队列存**什么**是效率分水岭：源码 LevelOrderBT 队列存"数据值"，出队后再用 `Find(root, x)` 重新定位结点——每次 Find 是 $O(n)$，整体 $O(n^2)$；竞赛标准做法是**队列存结点指针**，出队即得左右孩子，整体 $O(n)$（改进版见④，登记 A-3）。

**④ 代码演示**

递归三序核心，取自源文件 二叉树的遍历代码.c（改动：三函数并置，注释精简）：

```cpp
typedef struct BTnode {
    char data;
    struct BTnode *l, *r;
} BTNode, *BTree;

void PreOrderBT(BTree root) {                  // 先序: 根左右
    if (root == NULL) return;                  // 边界条件: 递归出口
    printf("%c ", root->data);                 // 1. 访问根
    PreOrderBT(root->l);                       // 2. 先序遍历左子树
    PreOrderBT(root->r);                       // 3. 先序遍历右子树
}
void InOrderBT(BTree root) {                   // 中序: 左根右
    if (root == NULL) return;
    InOrderBT(root->l);                        // 先左
    printf("%c ", root->data);                 // 再根
    InOrderBT(root->r);                        // 后右
}
void PostOrderBT(BTree root) {                 // 后序: 左右根
    if (root == NULL) return;
    PostOrderBT(root->l);
    PostOrderBT(root->r);
    printf("%c ", root->data);                 // 根最后
}
```

层次遍历改进版（自编，改动注记：源码队列存数据值 + Find 定位为 $O(n^2)$ 教学版；此处改为**队列存结点指针**的 $O(n)$ 标准版，登记 A-3）：

```cpp
// 复用 链式队列, 元素类型改为 BTNode* (源码注释已预留: //BTNode* data)
void LevelOrderBT(BTree root) {
    if (root == NULL) return;
    Queue q = initqueue();
    enqueue(&q, root);                         // 根入队(存指针)
    while (empty(&q) == 0) {
        BTNode* p = dequeue(&q);               // 队首出队
        printf("%c ", p->data);                // 访问
        if (p->l != NULL) enqueue(&q, p->l);   // 孩子指针直接入队
        if (p->r != NULL) enqueue(&q, p->r);   // 无需再 Find, O(n) 达成
    }
}
```

**执行追踪表**（数据取自②的 9 结点样例树 A 左 B 右 E；B 右 C；C 左 D；E 右 F；F 左 G；G 左 H 右 K，层次遍历改进版的队列变化，队首在左）：

### 5. 非递归遍历：一个栈统一三序

前置依赖：[[#4. 遍历总纲：递归三序与层次遍历]]（递归版是对照基准）、[[栈与队列]]（自建链栈）
后续衔接：[[#6. 中序线索二叉树：把遍历结果焊进树里]]（把这里的动态过程静态化）、[[二叉树竞赛篇]]（斜树爆栈的备胎，其知识点 4 引用）

**① 它解决什么问题**

递归遍历用系统栈，深度不可控（斜树 $10^5$ 层即爆栈）；线索化（知识点 6）前的通用解法是**自己拿栈模拟递归**。源文件 二叉树遍历-非递归.c 用自建链栈（栈元素是 `BTNode*` 结点指针）实现三序，骨架完全统一：**沿左链下行时入栈，走不动了出栈转向右子树**。

**② 直觉理解**

模型级类比：**带备忘的探洞**。左手扶墙（p 指针）往深处走，每经过一个岔口就往包里塞张字条（入栈）记"这里还有条右路没走"；走到头（p 为 NULL）就掏出最后一张字条（出栈），按字条去走那条右路。三序的差别只是**掏字条时做不做事**：先序在塞字条时访问（下行即访问），中序在掏字条时访问（回溯即访问），后序在掏字条后还要确认"右路真的走完了"才访问。

**③ 原理与推导**

先序与中序的骨架（源码注释原文级别的推导）：`p != NULL` 时——先序：访问 p、push、`p = p->l`；中序：push、`p = p->l`（访问挪到出栈时）。`p == NULL` 时：出栈 f，`p = f->r`。循环条件 `p != NULL || 栈非空`——p 非空说明还有左路，栈非空说明还有右路欠账，两者都尽才结束。

**后序的难点与 pre 技巧**（本节核心论证）：出栈的时机不等于访问的时机——栈顶 f 出栈前必须先确保**右子树访问完毕**。源码方案：`f = Get(top)` 只看不取；若 `f->r != NULL && pre != f->r`，说明右子树存在且**刚访问的最后一个结点不是 f 的右孩子**（右子树还没走或没走完），转向 `p = f->r`；否则（右空，或 `pre == f->r` 即右子树刚刚整体访问完）才 pop 并访问 f，`pre = f` 记录"最后访问者"。pre 的两用：既是"防止右子树被二次进入"的哨兵，又是后序序列的天然记录者。

全轨迹手推（9 结点样例树，值得逐行过一遍——这是理解 pre 的唯一途径）：A 入栈下行至 B 入栈、p 空掏出 B 见右子 C 未访 → 访 C 支（D 先出：`D C`）→ B 出栈访问（此时 `pre == B->r == C`，右子树确已完成）→ A 出栈前见右子 E 未访 → E 支先走 `H K G F`（K 出栈后 G 因 `pre == K` 而出）→ E 出（`pre == F`）→ A 出（`pre == E`）。输出 `D C B H K G F E A`——**实测与递归版逐字一致**（附录 B-5），pre 技巧实证成立。

**④ 代码演示**

非递归中序与后序核心，取自源文件 二叉树遍历-非递归.c（改动：链栈部分从略——与栈与队列篇链栈同构；`Get` 为取顶不出栈）：

```cpp
void InOrder(BTree root) {                     // 非递归中序
    if (root == NULL) { printf("空树\n"); return; }
    sstack* top = Initstack();
    BTNode *p = root, *f = NULL;
    while (p != NULL || Empty(top) == 0) {
        if (p != NULL) {                       // 左路未尽: 入栈再下行
            Push(top, p);
            p = p->l;
        } else {                               // 左尽: 出栈访问, 转右
            f = Pop(top);
            Visit(f);                          // 中序: 出栈时访问
            p = f->r;
        }
    }
}
void PostOrder(BTree root) {                   // 非递归后序
    if (root == NULL) { printf("空树\n"); return; }
    sstack* top = Initstack();
    BTNode *p = root, *pre = NULL, *f = NULL;
    while (p != NULL || Empty(top) == 0) {
        if (p != NULL) { Push(top, p); p = p->l; }
        else {
            f = Get(top);                      // 只看不取
            if (f->r != NULL && pre != f->r)
                p = f->r;                      // 右子树未走完: 先走右
            else {                             // 右空 或 右刚访问完
                f = Pop(top);
                Visit(f);                      // 此时才访问
                pre = f;                       // 记录最后访问者
            }
        }
    }
}
```

- 源码 main 实测（9 结点树）：非递归后序输出 `D C B H K G F E A`，与递归版、B 源示例三方一致（附录 B-5）。
- 工程语境：深树的受控遍历（自控栈深，可扩容）；迭代式"找中序后继"的基础——正是知识点 6 线索化要静态化的那个动态过程。
- 自编迁移题（自编）：把非递归中序改造成"输出中序序列的第 k 个结点"（不停机版改停机版：数到 k 即返回），分析为什么栈版比"先全遍历再取第 k 个"省。建议先独立做，再对照题解。

  题解：栈版在访问（出栈）计数达 k 时直接 return，此后不再入栈——最坏也只走前 k 个结点的工作量；全遍历版恒 $O(n)$。这是"遍历即流"的视角：非递归版天然支持惰性求值。

**⑥ 坑点与边界**

> [!caution]
> 非递归的坑集中在循环条件与 pre 的初始化。

> **【易错】** 循环条件只写 `p != NULL` → 左链走完后栈里的右路欠账没人还 → 必须 `p != NULL || 栈非空`（源码 `Empty(top) == 0`）。

> **【易错】** 后序忘了 `pre = f` 或初始化漏 `pre = NULL` → 右子树被反复进入死循环 → pre 是后序版的灵魂，三处（判、赋、初）一个不能少。

> **【易错】** 栈存数据值而非结点指针 → 出栈后无法拿左右孩子 → 栈元素必须是 `BTNode*`（源码 stackNode 的 data 域类型即结点指针）。

> **边界数据集（先自己跑一遍，再展开对照）**

> 2. 单元素：单结点 A → 预期：push A、p 置空，pop 访问即栈空，输出 `A`；三序版在单结点上输出相同。
> 3. 全相同：所有结点值同为 A → 预期：栈行为与值无关，中序输出 n 个相同字符，正常。

> 6. 极值：$10^5$ 层左斜树 → 预期：栈深达 $10^5$——自建链栈在堆上分配可承受，递归版系统栈爆栈；这正是本知识点的存在理由，无溢出算术可查。

### 6. 中序线索二叉树：把遍历结果焊进树里

前置依赖：[[#4. 遍历总纲：递归三序与层次遍历]]（中序遍历与全局 pre 思想）、[[#3. 二叉树的顺序存储与链式存储]]（二叉链表载体）
后续衔接：中序迭代器与范围游标（延伸，非必需）、[[二叉树竞赛篇]]（flag 守卫思想通用于"指针多义"场景）

**① 它解决什么问题**

B 源 4.1 从一笔空间账切入：n 个结点的二叉链表共有 $2n$ 个指针域，其中有效分支只有 $n - 1$ 条（n 个结点、除根外人人有一个父指针指向它），故"二叉链表中存在 $2n - (n-1) = n + 1$ 个空指针域"。这些空指针纯属浪费。线索化的方案（B 源 4.2 原话）："若结点的左子树为空，则该结点的左孩子指针指向其**前驱**结点；若结点的右子树为空，则该结点的右孩子指针指向其**后继**结点。"——空指针再利用，遍历信息静态化。**设计动机**一句话：用 $n+1$ 个废指针换遍历的"无栈化"。核心收益（B 源 4.4）："线索化之后就不需要这些辅助了，直接可以像遍历数组一样遍历"，且"加快查找结点的前驱和后继的速度"。复杂度账：线索化本身一遍中序 $O(n)$；此后查前驱/后继，线索直读 $O(1)$、沿真实分支最坏 $O(h)$；遍历也不再需要 $O(h)$ 的辅助栈。

**② 直觉理解**

模型级类比：**景区单行道装路标**。原来每个岔路口只标"通往左右景点"（孩子指针），大量路口的另一半标牌空着；装上线索等于把"上一个/下一个景点"的路标补进空牌——游客（遍历者）不用再带地图和面包屑（栈），顺着路标就能走完全程。

用具体数字跑一遍（9 结点树，中序 `B D C A E H G K F`）：B 是中序第一个，无前驱；D 的前驱 B（D 左空 → 左指针指 B）；C 的前驱 D；A 的前驱 C（A 左非空不装前驱线索，但 C 的右空装上"后继是 A"）；E 的前驱 A……结果：A 沿左指针（孩子 B）找不到前驱，但它的**左子树最右端** C 有后继线索指向 A——查 A 的前驱走"左子树最右"路径，实测输出 `前驱是C`（附录 B-5）。

**③ 原理与推导**

**歧义与标志位**：左指针现在有两种含义（孩子 / 前驱），必须自报家门——B 源 4.3 原话："ltag 为 0 时，指向左孩子，为 1 时指向前驱；rtag 为 0 时，指向右孩子，为 1 时指向后继。"

**线索化 = 中序遍历 + 记账**：遍历到 p 时（B 源"设置一个指针（名为 pre），时刻指向当前访问结点的前一个结点"）做两笔账——p 左空则 `p->l = pre`（装前驱线索）；pre 右空则 `pre->r = p`（给**上一个**装后继线索）。一笔遍历、两处收益，`pre = p` 后移。源码 Visit 函数正是这两笔账的实现（`pre` 为全局指针，初始 NULL）。

**前驱后继的查询推导**（源码 main 的两条路径）：查 x 的前驱——`lflag == 1` 则线索直读 `x->l`；否则左孩子真实存在，前驱是"**左子树中最后被中序访问的结点**" = 左子树最靠右者：从 `x->l` 出发 `while (q->r != NULL && q->rflag == 0) q = q->r`（右指针是真孩子才继续向右，是线索就停）。查后继对称：右子树最靠左者（`while (q->l != NULL && q->lflag == 0) q = q->l`）。实测：查 A 得前驱 C（左子树 B→C，C 的 rflag==1 停）、后继 E（右孩子 E 的 lflag==1 即最左）；查 E 得前驱 A（线索直读）、后继 H（F→G→H，H 的 lflag==1 停）——四值全中（附录 B-5）。

**连带修改**：线索装进原孩子指针域后，一切"沿孩子走"的旧代码都可能误入线索——源码 Find 专门加了守卫（注释"注意细节"）：`ro->l != NULL && ro->lflag == 0` 才向左递归。

**④ 代码演示**

线索化核心，取自源文件 二叉树的中序线索化代码.c（改动：摘结构体、Visit、查询两段；建树部分同前从略）：

```cpp
typedef struct BTNode {
    char data;
    struct BTNode *l, *r;
    int lflag, rflag;                          // 0 孩子 / 1 线索
} BTNode, *BTree;
BTNode* pre = NULL;                            // 全局: 当前结点的前一个

void Visit(BTNode* p) {                        // 中序访问时记账
    if (p->l == NULL) {                        // p 无左孩子
        p->l = pre;  p->lflag = 1;             //   装前驱线索
    }
    if (pre != NULL && pre->r == NULL) {       // 上一个无右孩子
        pre->r = p;  pre->rflag = 1;           //   给 pre 装后继线索
    }
    pre = p;                                   // pre 后移
}
void InOrderBTree(BTree ro) {                  // 线索化 = 中序遍历
    if (ro == NULL) return;
    InOrderBTree(ro->l);
    Visit(ro);
    InOrderBTree(ro->r);
}
// 查 x 的前驱 (p = Find 后):
if (p->lflag == 1) printf("前驱是%c\n", p->l->data);   // 线索直读
else {                                          // 左子树最靠右
    BTNode* q = p->l;
    while (q->r != NULL && q->rflag == 0) q = q->r;
    printf("前驱是%c\n", q->data);
}
// 查后继对称: rflag==1 直读; 否则右子树最靠左
//   while (q->l != NULL && q->lflag == 0) q = q->l;
```

**执行追踪表**（数据取自②的 9 结点样例树，中序 `B D C A E H G K F`，Visit 记账过程；pre 为进入本步时的值）：

| 步骤 | 当前结点 p | pre | 动作 | 记账结果 |
|------|-----------|-----|------|----------|
| 1 | B | NULL | B 左空，l=pre=NULL 装前驱；pre 为 NULL 跳过后继账；pre 移向 B | B.lflag=1（无前驱） |
| 2 | D | B | D 左空，l=B 装前驱；B 的右指向 C 非空不装；pre→D | D.lflag=1，前驱 B |
| 3 | C | D | C 左孩子 D 存在不装；D 右空，D.r=C 装后继；pre→C | D.rflag=1，后继 C |
| 4 | A | C | A 左孩子 B 存在不装；C 右空，C.r=A 装后继；pre→A | C.rflag=1，后继 A |
| 5 | E | A | E 左空，l=A 装前驱；A 的右是孩子 E 不装；pre→E | E.lflag=1，前驱 A |
| 6 | H | E | H 左空，l=E 装前驱；E 的右是孩子 F 不装；pre→H | H.lflag=1，前驱 E |
| 7 | G | H | G 左孩子 H 存在不装；H 右空，H.r=G 装后继；pre→G | H.rflag=1，后继 G |
| 8 | K | G | K 左空，l=G 装前驱；G 的右是孩子 K 不装；pre→K | K.lflag=1，前驱 G |
| 9 | F | K | F 左孩子 G 存在不装；K 右空，K.r=F 装后继；pre→F | K.rflag=1，后继 F |

**错误写法对照**（对应⑥的三个坑）：

```diff
- if (ro->l != NULL) 向左递归（沿用旧 Find）        // 坑1：沿前驱线索误入已访问区域，死循环
+ if (ro->l != NULL && ro->lflag == 0) 向左递归     // 修复：flag 守卫（源码注释"注意细节"）
- if (pre->r == NULL) { pre->r = p; pre->rflag = 1; }  // 坑2：中序首结点时 pre 为空，崩
+ if (pre != NULL && pre->r == NULL) { ... }        // 修复：两条件缺一不可
- 前驱 = p->l（无脑取左指针）                        // 坑3：有左孩子时 l 是孩子不是前驱，答案错
+ 分支：lflag==1 直读 p->l；否则找左子树最靠右者     // 修复：源码 main 的 if-else 全覆盖
```

**⑤ 典型应用**

- 源码 main 实测（9 结点树 + 查询，附录 B-5）：查 A → `前驱是C`、`后继是E`；查 E → `前驱是A`、`后继是H`——与③手推四值全中。
- B 源 4.4 场景：大数据量下频繁查前驱后继（如中序迭代器、范围查询的游标推进），线索化把每次 $O(n)$ 的"从根再遍历"降为 $O(1)$ 直读或 $O(\text{树高})$ 的子树内行走。
- 自编迁移题（自编）：在线索树上实现"从中序第一个结点出发，不递归不出栈输出全序列"。建议先独立做，再对照题解。

  题解：找最左结点（一路 `lflag == 0` 向左）作为起点；访问后看 rflag——为 1 则线索直跳后继；为 0 则在右子树里再找最左。全程 $O(n)$ 且只用两个指针——这正是 B 源"像遍历数组一样遍历"的落地形态。

**⑥ 坑点与边界**

> [!caution]
> 线索树的坑全部源于"一个指针域两种含义"。

> **【易错】** 线索化后沿用旧 Find/遍历 → 沿着"前驱线索"误入已访问区域 → 一切孩子向的移动都要检查 flag（源码 Find 的 `lflag == 0` 守卫，注释"注意细节"）。

> **【易错】** Visit 里漏掉 `pre != NULL` 判断 → 中序第一个结点时给空指针装后继线索崩 → `pre != NULL && pre->r == NULL` 两个条件缺一不可。

> **【易错】** 查前驱时只看 `p->l` → 有左孩子时 l 是孩子不是前驱 → 分支：lflag==1 直读，否则左子树最右（源码 main 的 if-else 全覆盖）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空树 → 预期：InOrderBTree(NULL) 直接 return，pre 保持 NULL，无线索生成。
> 2. 单元素：单结点 A → 预期：Visit(A) 中 A 左空装前驱线索 l=pre=NULL 且 lflag=1；pre 为 NULL 不装后继；pre 移向 A——A 的左线索为空（无前驱），右孩子域保持 NULL（无后继，rflag=0）。
> 3. 全相同：值全同 → 预期：记账只看指针与 flag，与值无关，线索结构正常。
> 4. 严格递增：不适用：线索化按中序位置记账，与键值大小无关。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：不适用溢出检查（无算术运算）；形态极值 $10^5$ 层斜树——线索化本身仍是递归中序，建线索阶段仍有爆栈风险，查询阶段则 O(1)/O(h) 无栈。

结构、遍历、线索化的能力全部就位。最后一战：普通树、森林与二叉树之间**自由变形**——前面埋的孩子兄弟伏笔在此引爆。

### 7. 树、森林与二叉树的互转：孩子兄弟的另一副面孔

前置依赖：[[#1. 树的存储三式：双亲、孩子、孩子兄弟]]（孩子兄弟表示法即转换的存储形态）
后续衔接：森林遍历（树的先根/后根对应二叉树先序/中序）、[[二叉树竞赛篇]]（转换出的二叉树直接进入递归设计）

**① 它解决什么问题**

普通树不规整、算法难写；二叉树规整、算法成体系。**转换**让两者互通（B 源《转换》PDF 原话）："二叉树转换成普通树是刚才的逆过程，步骤也就是反过来做而已。"核心问题：为什么任意树都能无损变成二叉树？因为**孩子兄弟表示法**（知识点 1）已经把树存成了二叉链表——`ch` 占据左指针位、`bro` 占据右指针位，转换只是把这个存储事实"画"出来。

**② 直觉理解**

模型级类比：**多胞胎排队变身**。普通树里一串兄弟（B、C、D 并排挂在 A 下）；转换时让他们**手拉手站成一列**（B 拉着 C、C 拉着 D），然后只让母亲 A 牵老大的手（去线：A 只连 B）——B 的"右手"牵着 C，在二叉树视角里 C 就成了 B 的"右孩子"。

用具体数字跑一遍（转换 PDF 示例树：A 的孩子 B、C、D；B 的孩子 E、F；C 的孩子 G；D 的孩子 H、I、J），按 PDF 三步：

| 步骤 | 动作（PDF 原话级） | 本例效果 |
|------|--------------------|----------|
| 1 加线 | "在所有兄弟结点之间加一条连线" | B-C、C-D；E-F；H-I-J 各连成兄弟链 |
| 2 去线 | "对树中每个结点，只保留它与第一孩子结点的连线，删除与其他孩子之间的连线" | A 只留 A-B；B 只留 B-E；D 只留 D-H |
| 3 层次调整 | "以树的根结点为轴心，将整棵树顺时针旋转一定的角度" | 得二叉树：A 左 B；B 右 C；C 右 D；B 左 E；E 右 F；D 左 H；H 右 I；I 右 J |

森林转二叉树（PDF 三步）："把每棵树都转换为二叉树"→"第一棵二叉树不动，从第二棵二叉树开始，依次把后一棵二叉树的根结点作为前一棵二叉树的根结点的右孩子"→层次调整。

**③ 原理与推导**

**为什么无损**：转换的信息守恒账——原树中每个结点的"孩子序列"信息 = 长子（保留的连线）+ 兄弟链（加的线）；兄弟链正好落在二叉树的右指针位上。所以"树 → 二叉树"与"孩子兄弟表示法"是**同构的两种视角**：存储时就是孩子兄弟链表，画图时就是那棵二叉树。转换后 `结点的左孩子` 恒等于 `原树的长子`、`右孩子` 恒等于 `原树的下一位兄弟`——这组对应是逆向转换的全部依据。

**逆向三步**（PDF 第 3 页原话）：①"若结点 x 是其双亲结点 y 的左孩子，则把 x 的右孩子，右孩子的右孩子……都与结点 y 用线连起来"（右链还给父母，变回兄弟）；②"去掉所有双亲到右孩子之间的连线"（右指针本来就是兄弟假象）；③调整位置。左孩子是真儿子、右链是假儿子——**左右语义不对称**是逆向的钥匙。

**森林还是树**（PDF 第 4 页原话）："判断一棵二叉树能够转换成一棵树还是森林，标准很简单，那就是只要看这棵二叉树的根结点**有没有右孩子**，有的话就是森林，没有的话就是一棵树。"推导：森林转二叉树时第二棵以后的树全挂在根的右链上——右链长度 = 森林的树数。

**④ 代码演示**

转换是"画图规则"而非独立算法，其代码形态就是知识点 1 的孩子兄弟表示法本身（构建即转换）。把三份存储代码的查询行为再对一次账（自编对照片断，改动注记：复刻孩子兄弟 Insert 的挂链逻辑）：

```cpp
// 树 A(孩子 B,C,D) 按输入序插入 -> 孩子兄弟链表:
//   A->ch = B, B->bro = C, C->bro = D          (尾插, 与输入同序)
// 画成二叉树: B 是 A 的左孩子; C 是 B 的右孩子; D 是 C 的右孩子
// 等价于"加线去线"手工转换的结果 —— 存储与转换同构的实证
// 实测(附录 B-5): 查 A 输出孩子 B C D; 查 D 输出 H I J
```

**错误写法对照**（对应⑥的三个坑）：

```diff
- 逆向转换: 保留双亲到右孩子的连线                  // 坑1：树多出幽灵结点，结构错
+ 逆向转换: 右链一律拆成兄弟，删光双亲到右孩子的连线  // 修复：PDF 逆过程第 2 步
- 看到二叉树直接按一棵树转回                        // 坑2：根有右孩子时实为森林，少转出几棵树
+ 先看根有无右孩子：有即森林，无才是树              // 修复：PDF 第 4 页判定标准
- 沿 bro 链向下当孩子方向遍历                       // 坑3：走进兄弟子树，遍历全乱
+ ch 向下 (真孩子)、bro 横向 (兄弟)                 // 修复：转换视角下 bro 才扮演右孩子
```

**⑤ 典型应用**

- 源码实测（13 结点树，附录 B-5）：孩子兄弟表示法查 A → `该结点的孩子有: B C D`、查 D → `H I J`（尾插正序）；与孩子表示法的头插逆序（`D C B` / `J I H`）形成双向对照——同一棵树、两种链向，转换后右链方向要注意。
- 森林遍历的桥梁：森林的先序 = 对应二叉树的先序；森林的中序 = 对应二叉树的中序（由转换的右链结构直接可证）——"树/森林遍历"考研题全部经此化为二叉树遍历。
- 自编迁移题（自编）：把示例树手工转换为二叉树后，写出该二叉树的先序与中序，并验证"森林中序 = 二叉树中序"。建议先独立做，再对照题解。

  题解：转换后二叉树先序 `A B E F C G D H I J`、中序 `E F B G C H I J D`；回代原树做"先根遍历"（根-孩子依次）恰得 `A B E F C G D H I J` 与"后根遍历"（孩子依次-根）恰得中序序列。树的先根/后根遍历与二叉树先序/中序的对应关系就此坐实。

**⑥ 坑点与边界**

> [!caution]
> 转换的坑集中在"左右语义反转"上。

> **【易错】** 逆向转换时把右孩子当真儿子保留 → 树多出幽灵结点 → 右链一律拆成兄弟（PDF 逆过程第 2 步"去掉所有双亲到右孩子之间的连线"）。

> **【易错】** 忘记"根有右孩子即森林" → 把森林当一棵树转 → 先看根右链再决定转换次数（PDF 第 4 页判定标准）。

> **【易错】** 孩子兄弟链表里把 `bro` 链的方向当孩子方向 → 遍历全乱 → 记牢 `ch` 向下（真孩子）、`bro` 横向（兄弟），转换视角下 `bro` 才**扮演**右孩子。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空树/空森林 → 预期：无结点可画，转换结果为空二叉树，无操作。
> 2. 单元素：单结点树 → 预期：无兄弟无孩子，加线去线均无操作，转出单结点二叉树；根无右孩子，判定为树非森林。
> 3. 全相同：值全同 → 预期：转换按孩子/兄弟关系（结构）进行，与值无关，结果正常。
> 4. 严格递增：不适用：转换是画图规则，与值的大小序无关。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：不适用溢出检查（画图无算术）；形态极值——n 结点链状树（每结点只有一个孩子）转出的二叉树为单右链：长子占据左指针位但无左孩子，其余结点依次成为前一个的右孩子，右链长 n-1。

## 四、总结与自测

### 核心内容（一页纸速览）

- **树的存储三式**：双亲法 `{data, fa}` 找父 $O(1)$ 找孩子 $O(n)$；孩子法 `{data, 孩子链}` 反之（头插链序与输入反）；孩子兄弟法 `{ch 长子, bro 右兄弟}`——本质是二叉链表，为转换埋伏笔。
- **二叉树性质**：第 i 层至多 $2^{i-1}$；深 k 至多 $2^k-1$；$n_0 = n_2 + 1$（与 $n_1$ 无关）；完全二叉树深 $\lfloor \log_2 n \rfloor + 1$。
- **两种存储**：顺序（下标 $i \to \lfloor i/2 \rfloor, 2i, 2i+1$，仅适合完全形态，堆/线段树的基石）；链式（l/r，可加 fa 成三叉链）。
- **遍历**：递归三序只差"访问根"的位置（前/中/后）；复杂度 $O(n)$；层次遍历队列存**结点指针**；**先+中 或 中+后 可唯一重建**（中序是切分器），先+后不能（反例 `AB/BA`）；B 源两道重构题答案 `gdbehfca` 与树 A(B(C(D,E)),F(G(H)))。
- **非递归**：一个栈统一三序——下行入栈、出栈转右；先序下行时访问、中序出栈时访问、后序用 `pre != f->r` 防右子树重复进入。
- **线索化**：$n+1$ 个空指针再利用；中序遍历时"p 左空装前驱 + pre 右空装后继"；查询前驱 = 左子树最右（rflag==0 才继续）、后继 = 右子树最左；一切孩子向移动要查 flag。
- **互转**：树→二叉树 = 加线（兄弟连线）、去线（只留长子）、旋转；与孩子兄弟表示法同构；森林右链连接；根有右孩子即森林；逆向把右链还给父母。
