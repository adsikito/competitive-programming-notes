## 一、为什么需要它

你已经在 [[结构体]] 里写过 `struct Point { int x, y; };`，用它存坐标、排序、建边。但有没有遇到过这种别扭：二维平面上两个点，"求距离"的逻辑写在类外——任何拿到 Point 的代码都要自己再写一遍距离公式，写错一处就错一处。课件（19.1 pdf 目录）把这一步进化讲成十个子题：类与对象、构造/析构、new/delete、静态成员、this 指针——全部围绕一件事：**把数据和操作它的函数绑在一起，交给一个类型统一管理**。

本篇讲 4 个知识点：类与对象（struct 的进化）、封装与访问修饰、继承与多态、竞赛定位。顺序理由：先有类型（1），再有权限（2），再有复用（3），最后回答竞赛里怎么取舍（4）。全篇定位提前声明：**这是 C++ 语言的工程能力，不是竞赛算法——竞赛极少写类，本篇按"理解即可"的延伸深度讲**（知识点 4 专述）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 类与对象：struct 的进化

前置依赖：[[结构体]]（成员变量、struct 定义与使用）、[[函数]]（函数定义与调用）
后续衔接：[[#2. 封装与访问修饰：public、protected、private]]、[[#3. 继承与多态：代码复用与 virtual]]

**① 它解决什么问题**

struct 把几个变量捆在一起，但"怎么用这些变量"的逻辑散落在各处。class 在 struct 的基础上把**成员函数**也装进类型里：数据（成员变量）+ 行为（成员函数）合为一个整体（19.1 pdf"对象实现了数据和操作的结合"）。类的实例叫**对象**——类是图纸，对象是按图纸造出的每件产品（实例化）。关键性质：类内可含 0 到多个成员变量与成员函数；创建对象时自动调用**构造函数**（与类同名、无返回值），销毁时自动调用**析构函数**（类名前加 `~`，不可重载、最多一个）（19.1 pdf）；这层"自动"就是 class 区别于 struct 的第一件礼物。设计动机先给一句：**自动初始化消灭了"忘记初始化"这一大类 bug**——课件 p4 原话"使用未初始化的对象是程序出错的一个重要原因"。

**② 直觉理解**

模型级类比：**图纸与产品**。struct 是一张"零件清单"（只有数据字段）；class 是一张"产品图纸"（数据字段 + 组装说明 + 使用说明）。`new` 或栈上声明一次，就按图纸生产一件产品；每件产品出厂时自动跑一遍组装工序（构造函数），报废时自动跑一遍拆解工序（析构函数）。

用具体数字跑一遍（code1.cpp 矩形类）：`Rect r1(100, 100)` —— 构造函数把 100、100 存进 width、height；`r1.is_square()` 比较 100 == 100 返回 true；`r1.area()` 输出 100 * 100 = 10000。实测输出 `r1是正方形` 与 `10000`（附录 B-5）。

**③ 原理与推导**

语法骨架（19.1 pdf）：`class 类名 { 修饰符: 成员; };`——**结尾分号不能丢**。构造函数可以重载（无参版、带参版并存）、可以带默认参数；带参构造存在时，实例化必须传匹配的实参。析构函数自动调用、程序员无法显式调（课件原话），用于清理堆内存、关文件。

this 指针的本质（19.1 pdf 原文摘述）：**this 是成员函数的隐式形参**——调用 `r1.area()` 时，编译器把 r1 的地址偷偷塞进参数表，函数体里的 `this->width` 就是顺着这个地址找到本对象的成员。**为什么参数表里看不见它**：因为它是编译阶段加的，不在源码里；也因此 static 成员函数没有 this（不属于任何对象）。推导一句：成员函数只有一份代码，却能服务无数对象——靠的就是每次调用都换一个 this。

**④ 代码演示**

**块一·核心代码**（取自课堂代码 code1.cpp 的矩形类段；改动：仅摘录类定义与 main 中对应调用，删去注释掉的旧实验代码）：

```cpp
#include <iostream>
#include <string>
using namespace std;              // C 等价：std::cout 写全称
class Rect {
private:                          // 私有区（知识点 2 展开）
    double width, height;         // 成员变量：宽和高
public:                           // 公有区
    Rect(double width, double height) {   // 构造函数：与类名同名、无返回值
        this->width = width;      // this-> 区分成员与形参（同名）
        this->height = height;
    }
    bool is_square() {            // 成员函数：判断正方形
        return this->width == this->height;
    }
    void area() {                 // 成员函数：输出面积
        cout << this->width * this->height << endl;
    }
};
int main() {
    Rect r1(100, 100);            // 实例化：栈上对象，自动调构造
    if (r1.is_square()) cout << "r1是正方形" << endl;
    else cout << "r1不是正方形" << endl;
    r1.area();
    return 0;
}
```

实测输出 `r1是正方形` / `10000`（附录 B-5）。

**块二·执行追踪表**（r1 的生命周期，`Rect r1(100,100)` 起）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | r1 声明 | 未初始化栈内存 | 调 Rect(100,100) | width=100, height=100 |
| 2 | r1.is_square() | width=100, height=100 | this 指向 r1，比较 | 返回 true |
| 3 | if(b) | b=true | 走真分支 | 输出 r1是正方形 |
| 4 | r1.area() | 同上 | this->width * this->height | 输出 10000 |
| 5 | main 返回 | r1 出作用域 | 自动调 ~Rect() | 对象销毁 |

**块三·错误写法对照**：

```diff
- class Rect { ... }          // 坑1：类定义结尾忘分号——下一行代码被吞进声明，报出一串难读的编译错误
+ class Rect { ... };         // 类定义必须以分号结束
- void Rect(double w, double h) { width = w; }   // 坑2：构造函数写了返回类型 void——不再被认作构造函数（编译错）
+ Rect(double w, double h) { this->width = w; }  // 构造函数与类名同名、无返回值
- Rect(double width, double height) { width = width; }   // 坑3：形参与成员同名且不写 this——width=width 是形参自己赋自己，成员未初始化（逻辑失效）
+ this->width = width;        // 用 this-> 消歧义，或初始化列表 width(width)
```

**⑤ 典型应用**

- 素材练习（19.1 pdf 练习页）：矩形类，判正方形 + 输出面积——即④的 code1.cpp（课堂代码即此题实现）。
- 素材作业（19.1 pdf 作业页）：动物类 + static 变量 count 记录实例化次数——把知识点 1 的构造函数与静态成员串起来；实现思路：构造函数里 `count++`。
- 迁移题（自编）：写一个 Counter 类，成员 `int val`，构造置 0，成员函数 `inc()`、`get()`，main 里连续 inc 三次后输出 3。建议先独立做，再对照题解：类骨架与④同构，只换成员与逻辑。

**⑥ 坑点与边界**

> **【易错】** 类定义结尾忘分号（④对照坑 1）——报错位置在下一行，极难读，是新手第一坑。

> **【易错】** 形参与成员同名时不写 `this->`（④对照坑 3）——编译不报错、成员是随机值，运行结果错得莫名。同名场景一律 `this->` 或初始化列表。

> **【注意】** 构造函数可以重载多个，析构函数最多一个且不可重载（19.1 pdf 原话：析构函数没有参数、不能被重载）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用：类是语言机制，无输入流程（预期：不涉及）。
> 2. 单元素：Rect r1(5, 5) → 正方形，面积 25（预期：单对象全流程正常）。
> 3. 全相同：两个 Rect(10,10) 对象 r1、r2 → 各自独立成员，互不影响（预期：对象间数据隔离）。
> 4. 严格递增：Rect(1,2)、Rect(2,3)、Rect(3,4) → 全非正方形，面积 2、6、12（预期：递增输入逐个正确）。
> 5. 严格递减：Rect(9,3)、Rect(6,2)、Rect(3,1) → 面积 27、12、3（预期：同上，宽高比一致）。
> 6. 极值：Rect(1e18, 1e18) 成员用 double → 面积 1e36 已超 double 有效精度边界（仍有值但精度损失）；若成员是 int 则直接溢出（预期：选成员类型先估数据范围）。

回扣开场：现在你能解决"距离公式到处复制"的问题了——把数据与操作绑进一个类型（③的结论），用法只认 `对象.函数()`。接下来给这个类型装上权限外壳。

### 2. 封装与访问修饰：public、protected、private

前置依赖：[[#1. 类与对象：struct 的进化]]
后续衔接：[[#3. 继承与多态：代码复用与 virtual]]（protected 在继承里的意义）

**① 它解决什么问题**

成员全公开等于没有规则：任何代码都能把 `r1.width = -5` 改成负数，类的约束形同虚设。访问修饰符解决的就是**谁能碰哪些成员**：`public` 谁都能访问；`private` 只有本类（和友元）能访问，**对象自己也不能访问**；`protected` 介于中间——本类和派生类能访问，对象不能（19.2 pdf 权限表）。关键性质：修饰符以"标签 + 冒号"出现，管到下一个标签为止；一个类可有多段标签；class 默认 private（struct 默认 public）。

**② 直觉理解**

模型级类比：**药瓶**。药片（private 成员）不让人直接抓，说明书（public 成员函数）告诉你"一天三片"——服药规则由类保证，吃错药（非法状态）从源头杜绝。protected 相当于"家人可用"：外人碰不得，但子孙类（派生类）可以。

用具体数字跑一遍（19.2 pdf 访问限定符案例）：类内 v1=100（public）、v2=200（private）、v3=300（protected）。对象 `s1.func1()` 合法（public 函数内能读全部三个）；`s1.v1 = 99` 合法；`s1.v2 = 11` 编译报错——**private 的墙连对象自己都不放行**（实测编译确认，附录 B-5）。

**③ 原理与推导**

权限表推导（19.2 pdf 原表压缩）：

| 修饰符 | 本类内 | 派生类内 | 对象/外部 |
|:---:|:---:|:---:|:---:|
| public | 可 | 可（public 继承下） | 可 |
| protected | 可 | 可 | 不可 |
| private | 可 | 不可 | 不可 |

**设计动机**：为什么 C++ 宁可让程序员多写几个标签？因为封装把"不变式"（width、height 永远大于 0 这类约束）的维护权收到类内——成员一私有，所有赋值都必须过 public 函数这道关，检查写一次、处处生效；这是知识点 1"自动初始化"思想的延续：**把容易错的动作变成唯一入口**。

**④ 代码演示**

**块一·核心代码**（自编示例，结构取自 19.2 pdf 访问限定符案例与 code1.cpp 矩形类）：

```cpp
#include <iostream>
using namespace std;
class Rect {
private:                          // 私有：对象碰不到
    double width, height;
public:
    Rect(double w, double h) { width = w; height = h; }
    double area() { return width * height; }   // 本类内可读私有成员
};
int main() {
    Rect r1(100, 100);
    cout << r1.area() << endl;    // 对：经公有成员函数间接用数据
    // r1.width = -5;             // 错：width 是 private，对象访问 → 编译错误
    return 0;
}
```

注释里标注了错误行；取消注释即复现编译失败（实测确认，附录 B-5）。

**块二·执行追踪表**（r1 的访问路径）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | r1 声明 | width/height 私有 | 构造（类内，可写私有） | width=100, height=100 |
| 2 | r1.area() | 同上 | public 函数，this 读私有成员 | 返回 10000 |
| 3 | r1.width | 同上 | 外部直接访问 private | 编译错误（防在编译期） |
| 4 | 友元函数 | 声明 friend 后 | 可访问私有（19.2 pdf） | 例外通道，慎用 |

**块三·错误写法对照**：

```diff
- r1.width = -5;              // 坑1：对象访问 private 成员 → 编译错误（防住了，好事）
+ r1.setWidth(-5) 不提供、或 setWidth 里拒绝负数——非法值挡在入口
- class Rect { double w; };   // 坑2：以为 class 像 struct 默认公开——默认 private，main 里 r.w 直接编译错
+ 显式写 public: 标签；struct 默认 public 但竞赛里也建议写明
- friend void hack(Rect&);    // 坑3（示意）：到处开友元——封装形同虚设，权限体系白建
+ 友元只给确需穿透的少数场景（如重载 << 输出），标注：延伸
```

**⑤ 典型应用**

- 素材案例（19.2 pdf 友元函数案例）：printName 想读 Student 私有 name——类内加一行 `friend void printName(Student stu);` 即可，未加则编译报错（课件先后对照两个版本）。
- 迁移题（自编）：给 Rect 加 `setWidth(double w)`，宽度小于等于 0 时拒绝赋值并保持原值。建议先独立做，再对照题解：这就是封装的第一笔红利——校验逻辑只写一处。
- 竞赛衔接：竞赛代码几乎不建权限墙（见知识点 4），但读别人的工程代码（含 STL 实现、模板库）时必须看得懂 public/private 的分界。

**⑥ 坑点与边界**

> **【易错】** 以为 `class` 与 `struct` 权限默认一致——class 默认 private，struct 默认 public；成员没写标签就访问，报错（④对照坑 2）。

> **【注意】** protected 对对象不可见、对派生类可见——它在单用类时表现和 private 一样，意义要到继承里才兑现（知识点 3 的伏笔）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用：权限是编译期机制（预期：不涉及）。
> 2. 单元素：单对象全公有成员 → 一切访问合法（预期：无墙）。
> 3. 全相同：三个成员全标 private，类内函数逐个访问 → 全部合法（预期：类内无限制）。
> 4. 严格递增：public、protected、private 三段标签 → 对象可访问性依次递减（预期：可访问集合逐级缩小）。
> 5. 严格递减：private、protected、public → 对象可访问性递增（预期：对称验证）。
> 6. 极值：给友元声明无节制的类（10 个 friend）→ 编译通过但封装失效（预期：机制不拦，纪律要自己守）。

回扣开场：现在你能回答"为什么要 private"——不是防自己，是把不变式的维护权收到类内（③设计动机）。墙立好了，下一节看墙内的类怎么生娃。

### 3. 继承与多态：代码复用与 virtual

前置依赖：[[#2. 封装与访问修饰：public、protected、private]]、[[#1. 类与对象：struct 的进化]]
后续衔接：[[#4. 竞赛定位：算法竞赛极少写类]]、[[变量作用域与多文件编程]]（综合案例5 的多文件形态）

**① 它解决什么问题**

课件开场原话（19.3 pdf）："你是选择重新写一个狗的类？还是选择把动物类的代码 copy 来改改？"继承是第三条路：`class Dog : public Animal`——Dog 自动拥有 Animal 的非 private 成员，只需补自己的新增部分。**多态**（19.4 pdf）是继承的下一层：基类指针指向哪个派生类对象，就调哪个派生类版本的函数——前提是该函数标了 `virtual`。一句话点到虚函数（按任务要求控制深度）：**在基类函数前加 virtual，通过基类指针调用时就会自动落到派生类的同名版本；基类的析构函数也应当是虚的，否则 delete 基类指针时派生类的析构不会执行**。本知识点只求读懂，不求手写。

**② 直觉理解**

模型级类比：**家族继承**（课件原类比：儿子继承父亲财产）。Animal 把 name、age、printInfo 全部传给 Dog；Dog 自己添一个 sex 字段。多态则是"同一句 `a->eat()`"，给狗吃狗粮、给猫吃猫粮——**同一个调用点，不同的实际函数**。

用具体数字跑一遍（code3.cpp 练习题）：Animal(name, weight)，Lion 与 Aardvark 各自 public 继承、构造时调 `Animal(name, weight)`。`Lion lion("leo", 400); lion.who();` 输出 `name is leo weight is 400`；`Aardvark a1("djfj", 600)` 输出 `name is djfj weight is 600`——who() 只在基类写了一次，两个派生类直接用（实测一致，附录 B-5）。

**③ 原理与推导**

继承语法与构造顺序（19.3 pdf）：派生类构造函数用初始化列表调基类构造 `Student(...) : Person(name, age), score(score) {}`；**实例化派生类一定先跑基类构造**（语法规定），析构顺序相反（先派生后基类）。若不指明基类构造则调基类默认构造，基类没有默认构造就编译失败。

多态三条件（19.4 pdf）：继承关系存在；同名函数构成覆盖（原型相同）；通过基类指针（或引用）调用虚函数。**设计动机**：为什么多态要 virtual 而不是默认开启？因为动态绑定要经过虚函数表间接跳转，有运行时开销——C++ 的原则是"不用不付费"，默认静态绑定保性能，需要多态时显式声明。

**④ 代码演示**

**块一·核心代码**（取自课堂代码 code3.cpp 的 Animal/Lion/Aardvark 段；改动：仅摘录，删去注释掉的旧实验代码与 main 中无关行）：

```cpp
#include <iostream>
#include <string>
using namespace std;
class Animal {
private:
    string name; int weight;
public:
    Animal(string name, int weight) :name(name), weight(weight) {}
    void who() {   // 只写一次，派生类直接继承使用
        cout << "name is " << this->name << " weight is " << this->weight << endl;
    }
};
class Lion :public Animal {   // public 继承
public:
    Lion(string name, int weight) :Animal(name, weight) {}   // 调基类构造
};
class Aardvark :public Animal {
public:
    Aardvark(string name, int weight) :Animal(name, weight) {}
};
int main() {
    Lion lion("leo", 400);
    lion.who();
    Aardvark a1("djfj", 600);
    a1.who();
    return 0;
}
```

实测输出两行 who 信息（附录 B-5）。

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |

| 1 | 构造 GoldenMonkey | 无对象 | 先调 Animal() | 输出 call Animal |
| 2 | 同上 | 基类已就绪 | 再调 Monkey() | 输出 call Monkey |
| 3 | 同上 | 对象建成 | 最后 GoldenMonkey() | 输出 call GoldenMonkey |

**块三·错误写法对照**：

```diff
- Lion(string n, int w) {}            // 坑1：不调基类构造且基类无默认构造 → 编译错误
+ Lion(string n, int w) :Animal(n, w) {}   // 初始化列表显式调基类构造
- Lion(string n, int w) { name = n; }  // 坑2：在派生类构造函数体里给继承来的 private 成员赋值 → 编译错误（private 派生类也不可访问）
+ 基类成员改 protected，或一律经基类构造函数初始化
- ~Animal() { ... }                   // 坑3：基类析构非虚，delete 基类指针时 ~Monkey 不执行 → 子类堆资源泄漏（19.4 pdf 虚析构节原话）
+ virtual ~Animal() { ... }           // 做基类的类，析构函数声明为虚
```

**⑤ 典型应用**

- 素材综合案例5（20 综合案例5.pdf"计算器--多态实现"）：抽象计算器基类（纯虚 getResult），加/减/乘/除/取余/乘方/开根等派生类各自实现；主函数按选择 new 对应子类、用基类指针统一调 getResult。实测：原工程 chCal.h 用 sqrt/pow 未含 `<cmath>` 编译失败，补一行 `#include <cmath>` 后编译通过、菜单正常（附录 B-5 与 A-3 登记 1）。
- 迁移题（自编）：把 Rectangle 基类（虚 area()）派生出 Rect 与 Square，基类指针数组存三个对象逐个输出面积。建议先独立做，再对照题解：骨架即综合案例5 的缩小版。
- 竞赛衔接：竞赛中你**读**到类的地方是 STL——vector、priority_queue 全是类模板（下一批《模板》篇）；operator 重载如 code2.cpp 的 `operator<` 正是 sort 自定义比较的原理（[[排序]] 的 struct 版 cmp）。

**⑥ 坑点与边界**

> **【易错】** 派生类构造函数体里给基类 private 成员赋值（④对照坑 2）——private 对派生类也上锁，要么初始化列表调基类构造，要么把成员升为 protected。

> **【易错】** 基类析构忘写 virtual（④对照坑 3）——new 派生类、delete 基类指针，只跑基类析构，子类资源泄漏。课件原话：做基类的类，析构一般都声明为虚函数。

> **【注意】** 构造函数不能继承也不能是虚函数（19.3/19.4 pdf 与 hw_virtualFunc.txt 一致）；派生类不指明基类构造时必须有基类默认构造，否则编译失败。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不适用：继承是编译期机制（预期：不涉及）。
> 2. 单元素：单层继承 Dog : Animal，构造输出 call Animal 后 call Dog（预期：先基后派）。
> 3. 全相同：三个类都有无参构造且都不显式调基类构造 → 链式默认构造逐层跑（预期：顺序仍先基后派）。
> 4. 严格递增：A、B:A、C:B、D:C 四层 → 构造 A/B/C/D、析构 D/C/B/A（预期：链长加深顺序不变）。
> 5. 严格递减：析构阶段单独观察 → 与构造严格相反（预期：栈式生灭）。
> 6. 极值：基类指针 delete 后再访问 → 悬空指针未定义行为（预期：delete 后指针置空；虚析构保证析构链完整，不保证指针可用）。

### 4. 竞赛定位：算法竞赛极少写类（延伸）

前置依赖：[[#1. 类与对象：struct 的进化]]、[[排序]]（比较函数）
后续衔接：[[模板]]（待产出同批：template 读得懂即可）

**① 它解决什么问题**

本知识点回答一个定位问题：学了三节面向对象，竞赛代码里该写多少？答案（延伸定位，非必需掌握）：**几乎不写 class，一个 struct 加几个自由函数就是竞赛代码的常态**。理由是目标函数不同——工程代码的生命周期以年计，封装、继承、多态买的是长期可维护性（19.1 pdf：面向对象优点"易维护，易复用，易扩展"，代价"性能比面向过程低"、开发量更大）；竞赛代码生命周期以小时计，追求的是**写码速度与零心智负担**，类机制的收益兑现不了。这一段是本篇的立场声明，不引入新语法。

**② 直觉理解**

模型级类比：**租房与装修**。工程代码是自住房，值得装封装修继承（结构长期演化）；竞赛代码是连夜赶工的工棚，能住就行——敲一行 `struct Node{...};` 比设计一个类层级快十倍。竞赛里类的两种低频出现方式：STL 全是类模板（你只管用）；题解里偶见运算符重载让 struct 进 sort。

用具体数字推一遍（code2.cpp 素材数据）：Animal a1(10), a2(20), a3(30)，重载 `<` `==` `>` 后 `a1 < a2` 为真、`a1 == a3` 为假、`a3 > a2` 为真——实测输出 `a1 < a2` / `a1 != a3` / `a3 > a2`（附录 B-5）。竞赛等价写法见④：三行 cmp 函数，无类无重载。

**③ 原理与推导**

竞赛风格的推导：sort 需要的是"两个元素谁在前"的判定，这个判定可以写成成员函数 `operator<`（面向对象版，code2.cpp），也可以写成自由函数 `bool cmp(const Node&, const Node&)`（过程版）。两者对 sort 等价，后者少一层封装语法，写码与调试都更快——**为什么竞赛选后者**：比较逻辑通常只用一次，不值得为它建类型体系；而 member 函数版在"按多个字段多轮排序"时才显出组织力（工程场景）。

**④ 代码演示**

**块一·核心代码**（自编示例：竞赛风格的结构体 + 比较函数，与 code2.cpp 的面向对象版互为对照）：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;
struct Stu {          // 竞赛常态：struct 全公开、无构造
    string name; int age;
};
bool cmp(Stu& a, Stu& b) {        // 等价 code2.cpp 的 operator<(Student& t)
    return a.age < b.age;         // 年龄小的在前
}
int main() {
    Stu s[3] = {{"ww", 21}, {"zs", 20}, {"zz", 22}};
    sort(s, s + 3, cmp);
    for (int i = 0; i < 3; i++)
        cout << s[i].name << " " << s[i].age << endl;
    return 0;
}
```

**块二·执行追踪表**（三个对象按年龄排序）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 初始数组 | ww21, zs20, zz22 | sort + cmp 按 age | 开始排序 |
| 2 | 比较 zs 与 ww | 20 < 21 | cmp 返回 true | zs 排 ww 前 |
| 3 | 比较 zz 与 ww | 22 < 21 为假 | 交换 | zz 挪后 |
| 4 | 排序完成 | zs20, ww21, zz22 | 输出 | 三行按年龄升序 |

**块三·错误写法对照**：

```diff
- bool cmp(Stu a, Stu b) { ... }        // 坑1：传值拷贝两个结构体——对象大时排序常数暴涨（TLE 风险）
+ bool cmp(Stu& a, Stu& b)              // 引用传参免拷贝（code2.cpp 重载版同为引用）
- bool cmp(Stu& a, Stu& b) { return a.age <= b.age; }   // 坑2：比较器不满足严格弱序（相等也返回 true）→ sort 未定义行为/RE
+ return a.age < b.age;                 // 相等返回 false 是硬规矩
```

**⑤ 典型应用**

- 素材作业（19.2 pdf 作业页）：分数类重载加减乘除，对应 hw_rational.cpp（素材自带完整实现，实测编译通过，附录 B-5）——工程练习，竞赛里等价写法是分数化简函数，不建类。
- 迁移题（自编）：用④竞赛风格给 n 个学生按"成绩降序、同分按姓名升序"排序。建议先独立做，再对照题解：cmp 里先比成绩（`a.score > b.score` 返回 true），成绩相等再比姓名。
- 竞赛衔接说明：面向对象四件套（封装/继承/多态/运算符重载）在 CSP-J/S 前两题、蓝桥杯真题里出现率极低；需要的只是"读懂类代码"的被动能力——阅读量由本篇三节覆盖。真正高频的 C++ 机制是 STL 与模板（同批《模板》篇）。

**⑥ 坑点与边界**

> **【易错】** 把工程习惯带进赛场：每个数据结构都建类、都写构造析构——写码时间翻倍，算法一分未得。竞赛写码的衡量标准是"从读到敲的总时间"。

> **【注意】** 本篇定位"延伸"的含义：四节课的机制细节（虚函数表、虚继承、菱形继承等 19.3/19.4 pdf 深水区）不要求复述，只要求遇到能查、读到能懂。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0，sort 空区间 → 无输出不崩溃（预期：sort 对空区间安全）。
> 2. 单元素：n=1 → 原样输出（预期：排序无比较发生）。
> 3. 全相同：三个同年龄学生 → cmp 全返回 false，保持原序（预期：稳定输出、不崩——严格弱序的价值）。
> 4. 严格递增：年龄 18,19,20 → 排序前后同序（预期：有序输入零交换）。
> 5. 严格递减：年龄 20,19,18 → 完全逆转（预期：最坏交换次数）。
> 6. 极值：age=2147483647 与 age=-2147483648 比较 → cmp 用减法写法（a.age-b.age）会溢出得错值，比较写法（a.age<b.age）安全（预期：比较器永远用比较运算符，不用减法）。

回扣开场：现在你能回答开场那个定位问题了——面向对象是给"长期演化的代码"买的保险，竞赛代码买短期速度，所以 struct + cmp 就是赛场答案（④的结论）；类的机制读得懂，就够了。

## 四、总结与自测

### 核心内容（一页纸速览）

- **类与对象**：class = struct + 成员函数；构造/析构自动调用；this 是成员函数的隐式形参（对象地址）。
- **封装**：public 全通、protected 本类与派生类、private 仅本类与友元；class 默认 private；封装把不变式维护权收到类内。
- **继承与多态**：`class Dog : public Animal` 复用基类成员；构造先基后派、析构相反；virtual 函数让基类指针调到派生类版本；基类析构要 virtual。
- **运算符重载**：本质是函数重载，`operator<`、`operator+` 皆函数；竞赛等价物是自由 cmp 函数。
- **竞赛定位（延伸）**：极少写 class；struct 全公开 + cmp 函数是赛场常态；STL 与模板才是高频 C++ 机制。
- 综合案例5（计算器·多态）：抽象基类 + 纯虚 getResult + 派生类实现；素材缺 `<cmath>` 已登记修正。
