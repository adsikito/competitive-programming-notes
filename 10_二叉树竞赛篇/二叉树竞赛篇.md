## 一、为什么需要它

结构篇解决了"树怎么存、怎么走"，但考场上拿到一道树题，真正难的是另一个问题：**怎么想到用递归、递归函数到底该设计成什么样**。A 源 13 号课件第 1 页只有一句话总纲："**二叉树的题目多是基于递归的**"——为什么"多是"？因为树本身就是递归定义的（结构篇 B 源 1.1："树中还有树"），根牵着若干棵子树，子树又是树。**定义是递归的，答案往往也能递归地定义**：整棵树的性质 = 左子树的性质 + 右子树的性质 + 根自己的事。

带着一个悬念进场（本篇回扣线）：递归函数写起来不过十来行，可为什么有人盯着题目半天憋不出一行？差距不在语法，在**能不能一句话说清"这个递归函数的返回值到底是什么"**。学完知识点 4 的三板斧对照表，你会看到 LCR 145 和 LC 236 这两道经典题其实是同一份设计合同的两种填法。

本篇讲 4 个知识点：递归世界观（方法论总纲）、对称二叉树 LCR 145（双指针镜像递归）、最近公共祖先 LC 236（后序信息归并）、递归三板斧（两题对照成通法）。顺序理由：先有方法论（知识点 1）再看两道题各自的递归设计（知识点 2、3），最后把两题摆在一起抽通法（知识点 4）——从一般到特殊再回到一般。

### 1. 递归世界观：树中还有树，答案中也有答案

前置依赖：[[二叉树结构篇#4. 遍历总纲：递归三序与层次遍历]]（递归三序与空树边界）、简单递归（C 基础）
后续衔接：[[#2. 对称二叉树（LCR 145）：双指针镜像递归]]、[[#3. 最近公共祖先（LC 236）：后序遍历的信息归并]]、[[#4. 递归三板斧：两题对照成通法]]

**① 它解决什么问题**

面对一道二叉树题，第一反应不该是"怎么遍历"，而是"**整棵树的答案能否由左右子树的答案拼出来**"。为什么可以？因为树的结构自带递归：每个结点都是一棵子树的根，"以我为根的树"与"以我孩子为根的树"在结构上完全同型，只是规模更小——这正是分治的用武之地。性质与复杂度先记住一条总账：一趟递归遍历全树，每个结点被访问常数次，时间 $O(n)$；递归调用栈的深度等于树高，空间 $O(h)$，斜树退化为 $O(n)$。

**② 直觉理解**

模型级类比：**公司层层汇报人数**。CEO 想知道全公司多少人，他不会挨个数工位，只问每个副总裁"你的部门多少人"，收到答复后加 1（自己）上交。每个副总裁对下属做一模一样的事，直到最底层员工回答"1（就我自己）"。

用具体数字跑一遍（结点计数）：树 A(B, C(D))——A 问 B、问 C；B 没有下属，回答 1；C 问 D，D 回答 1，C 加自己上交 2；A 收到 1 和 2，加自己上交 4。四个结点，四层调用，每层的"单层工作"只有一句：把下属的答案加起来再加 1。

**③ 原理与推导**

递归设计的三个要素，缺一个就写不出对的递归：

1. **终止条件**：最小不可再分的问题是什么？对树而言几乎总是"空树"——空树的答案直接可知（计数为 0、高度为 0、对称性为真）。
2. **单层逻辑**：本层结点只做一件事，子树的事**全部委托**给递归调用，绝不越俎代庖。
3. **返回值语义**：递归函数交给上一层的是什么？这一句话必须能在动手前说出口。它的设计动机是**划定契约边界**：语义一旦含糊，调用方不知道该拿返回值干什么，递归立刻崩盘。

推导"为什么三要素足够"：数学归纳法。终止条件保证 base case 正确；若左右子树（规模更小的同型问题）都返回了正确答案，单层逻辑又能把两个子答案正确拼成本层答案，则整棵树正确——递归就是归纳法的代码形态。

**④ 代码演示**

递归骨架与两个最小实例（自编示意，基于知识点 1 总纲）：

```cpp
// 骨架：返回值 f(树) = 单层逻辑( f(左子树), f(右子树), 根自己的事 )
int count(TreeNode* root) {          // 语义：以 root 为根的树的结点数
    if (root == NULL) return 0;                  // 终止：空树 0 个
    return count(root->left) + count(root->right) + 1;  // 单层：左+右+我
}
int height(TreeNode* root) {         // 语义：以 root 为根的树的高度
    if (root == NULL) return 0;                  // 终止：空树高 0
    return max(height(root->left), height(root->right)) + 1;
}
```

改动注记：这两个函数是为讲骨架自编的 10 行示意，不在素材源码内；素材的两个实战函数见知识点 2、3。

**错误写法对照**（对应⑥的两个【易错】坑）：

```diff
- int count(TreeNode* root) {
-     return count(root->left) + count(root->right) + 1;  // 坑1：漏终止条件，空树解引用段错误 (0xC0000005)
+ int count(TreeNode* root) {
+     if (root == NULL) return 0;                         // 修复：空树答案直接可知，永远第一行
- 返回值一会儿当"子树结点数"、一会儿当"最终答案"用      // 坑2：语义模糊，中间结果与最终答案混通道
+ 动手前一句话写死"f(root) 返回什么"再落笔               // 修复：语义即合同（三板斧第一条）
```

**⑤ 典型应用**

- 真题 1（本篇知识点 2）：LCR 145 对称二叉树——"对称"这个性质恰能由左右子树拼出。
- 真题 2（本篇知识点 3）：LC 236 最近公共祖先——"答案在哪"要由左右子树的查找结果归并。
- 迁移题：LC 104 二叉树的最大深度——就是上面的 `height`，把语义说清后五行收场。

题解（LC 104 思路）：终止条件空树返 0；单层逻辑取左右较大者加 1；返回值语义"以我为根的树高"。三要素齐备，代码自明。

**⑥ 坑点与边界**

> **【易错】** 动手前答不出"这个函数返回什么"。返回值语义是递归的地基，语义模糊时写出的代码常常把"中间结果"和"最终答案"混在一个通道里，调一层错一层。

> **【易错】** 终止条件漏掉空树。树的递归第一行几乎永远是 `if (root == NULL)`，漏了就是空指针解引用（段错误，exit 码 0xC0000005）。

> **【注意】** 两条计数路线别混：路线一"返回值传递"（推荐，如上）；路线二"全局变量累加"（遍历时顺手 ++）。混用两条路线（又返回值又改全局）会重复计数。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：count(NULL) → 预期：返回 0；height(NULL) → 返回 0——终止条件兜住，不崩溃。
> 2. 单元素：单结点树 → 预期：count=1、height=1，空判断放行后恰好走一次单层逻辑。
> 3. 全相同：所有结点值相同的树 → 预期：count/height 只看结构不看值，结果与普通树一致；值语义类判断见知识点 2。
> 4. 严格递增：不适用：count/height 与键序无关；键序仅在 BST 类题有语义（本篇未涉及）。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：$10^5$ 层斜树跑 count → 预期：递归栈深 $O(n)$，可能爆栈（段错误）——需改迭代或扩栈（知识点 4⑥ 的注意项）。

回扣开场：递归不是玄学，是"说清语义 + 相信委托"。下一节看它在镜像对称问题里的第一次实战。

### 2. 对称二叉树（LCR 145）：双指针镜像递归

前置依赖：[[#1. 递归世界观：树中还有树，答案中也有答案]]、[[二叉树结构篇#4. 遍历总纲：递归三序与层次遍历]]（先序时机与空树边界）
后续衔接：[[#4. 递归三板斧：两题对照成通法]]（收进通法）、LC 100 同构判断与 LC 226 翻转二叉树（同型变形）

**① 它解决什么问题**

判断一棵二叉树是否**镜像对称**（力扣 LCR 145，原《剑指 Offer》对称的二叉树）。A 源第 3 页把判定拆成两步：一棵树何时镜像对称？——左子树与右子树镜像对称即可；如何判断左右子树镜像对称？——三条**性质**同时成立：两根同值、左的左与右的右镜像、左的右与右的左镜像。复杂度：每个结点恰好被比较一次，时间 $O(n)$，递归栈 $O(h)$。

**② 直觉理解**

模型级类比：**两人面对面跳操**。你出左手，对面必须出右手才算镜像；你抬右腿，对面必须抬左腿。"左手对右手、右腿对左腿"——这就是交叉比较。

用具体数字跑一遍（样例树 `[1,2,2,3,4,4,3]`：根 1，左 2 带 3、4，右 2 带 4、3）：p 指向左 2，q 指向右 2。第一关 `p->val == q->val`（2 == 2）；第二关 `check(p->left=3, q->right=3)`，同值，且二者都无子，返真；第三关 `check(p->right=4, q->left=4)`，同值返真。三关全过，整树对称。再看反例 `[1,2,2,null,3,null,3]`：左 2 的右是 3、左空；右 2 的右是 3、左空。第二关 `check(p->left=空, q->right=3)`——一空一非空，直接返假，整树不对称。

**③ 原理与推导**

A 源第 3 页给出算法框架："用两个指针 p、q 对称地递归遍历树，进行比较即可"——初始化 `p = root->left, q = root->right`；递归出口：p、q 都空返真，只有一个空返假；递归条件：值相等，且 `p` 的左对 `q` 的右、`p` 的右对 `q` 的左。

**为什么要交叉比较？**这是镜像的本质决定的。照镜子时，你左半边身体的像落在镜子的右半边。设左子树根为 p、右子树根为 q：p 的左孩子在镜像中应对应 q 的右孩子（都在"外侧"），p 的右孩子应对应 q 的左孩子（都在"内侧"）。若改成顺向比较（左对左、右对右），判断的就变成"两棵子树**同构**"——完全不同的另一个问题（见知识点 2 ⑤ 迁移 1）。把镜像与同构画成对照表，一字之差、题意全变：

| 问题 | 第二、三关写法 | 含义 |
| --- | --- | --- |
| 镜像对称 | `check(p->left, q->right)` + `check(p->right, q->left)` | 外侧对外侧、内侧对内侧 |
| 同构相等 | `check(p->left, q->left)` + `check(p->right, q->right)` | 左对左、右对右 |

短路求值是安全防线：C++ 的 `&&` 从左往右求值、遇假即止，所以"先判双空、再判单空、最后访问 `p->val`"的顺序保证了访值前两指针必非空。

**④ 代码演示**

取自源文件 LC LCR 145.cpp（改动：补结构体结尾分号——素材原文件缺分号、本地 g++ 编译报错，实测见附录 B-5；删注释掉的等价展开版）：

```cpp
bool check(TreeNode* p, TreeNode* q) {
    if (p == NULL && q == NULL) return 1;    // 双空：镜像
    if (!q || !p) return 0;                  // 单空：不对称
    return (p->val == q->val)                // 第一关：同值
        && check(p->left, q->right)          // 第二关：外侧对外侧
        && check(p->right, q->left);         // 第三关：内侧对内侧
}
bool checkSymmetricTree(TreeNode* root) {
    if (root == NULL) return 1;              // 特殊情况：空树算对称
    else return check(root->left, root->right);
}
```

**执行追踪表**（数据取自②的样例树 `[1,2,2,3,4,4,3]`，轻量表）：

| 步骤 | 当前元素 (p, q) | 结构状态（递归位置） | 动作 | 结果 |
|------|----------------|---------------------|------|------|
| 1 | (左2, 右2) | 主调用第一层 | 双空否、单空否，比值 | 2==2 过第一关 |
| 2 | (3, 3) | 外侧关 check(p->left, q->right) | 比值后下探 | 3==3 |
| 3 | (NULL, NULL) | 3 的孩子层 | 双空返真 | 外侧关为真 |
| 4 | (4, 4) | 内侧关 check(p->right, q->left) | 比值后下探 | 4==4 |
| 5 | (NULL, NULL) | 4 的孩子层 | 双空返真 | 内侧关为真 |
| 6 | — | 回到主调用 | 外侧真 且 内侧真 | 整树对称返真 |

**错误写法对照**（对应⑥的两个【易错】坑）：

```diff
- return (p->val == q->val)
-     && check(p->left, q->left)     // 坑1：顺向比较判的是同构不是镜像
-     && check(p->right, q->right);  //      反例 [1,2,2,null,3,null,3] 被误判为对称
+ return (p->val == q->val)
+     && check(p->left, q->right)    // 修复：外侧对外侧
+     && check(p->right, q->left);   // 修复：内侧对内侧
- return p->val == q->val && ...;     // 坑2：先访值再判空，p/q 为空时解引用 RE
+ if (p == NULL && q == NULL) return 1;  // 修复：双空真
+ if (!q || !p) return 0;                // 修复：单空假；短路与保证访值前两指针非空
```

**⑤ 典型应用**

- 真题：LCR 145 对称二叉树（A 源第 2、3 页例题）。题解即上：双指针从根的左右孩子出发，三关递归。边界全在出口两句：双空真、单空假；入口特判空树为真（A 源第 3 页末尾"特殊情况：空树也满足条件"）。
- 迁移 1：判断两棵树是否**同构相等**（LC 100）——把交叉改顺向：`check(p->left, q->left) && check(p->right, q->right)`，其余骨架一字不动。
- 迁移 2：翻转二叉树（LC 226）——递归交换每个结点的左右孩子；翻转之后"镜像对称"就变成"同构相等"，两个概念由此互相转化。

**⑥ 坑点与边界**

> **【易错】** 把镜像写成顺向 `check(p->left, q->left)`。这样判的是同构，`[1,2,2,null,3,null,3]` 会被误判为对称——本知识点②的反例正是抓这个笔误。

> **【易错】** 出口顺序颠倒：先访问 `p->val` 再判空。必须先用"双空 / 单空"两句把空指针挡在门外，短路与求值才是防线。

> **【注意】** 空树按题意算对称（入口特判返真）；单结点树也对称——走的是主流程：`check(NULL, NULL)` 双空返真。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：root == NULL → 预期：入口特判返 1，空树算对称。
> 2. 单元素：`[1]` → 预期：check(NULL, NULL) 双空返 1，对称。
> 3. 全相同：`[2,2,2,2,null,2,null]`（值全为 2，但左 2 带左孩、右 2 带左孩）→ 预期：外侧关 check(左2.left=2, 右2.right=NULL) 单空返 0，整树返 0——值全等救不了结构不对称，这正是本算法按结构而非按值判断的证据。
> 4. 严格递增：不适用：对称性只比较对应位置值是否相等，与键序无关。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：结点值取 INT_MAX/INT_MIN → 预期：算法只做 `==` 比较、无任何算术，无溢出，行为与普通值一致。

回扣：这道题里递归函数的语义是"p、q 两棵子树是否互为镜像"——注意它是**双结点**参数，这是镜像问题的签名特征。下一题的递归只带一个根，却要带回三种信息。

### 3. 最近公共祖先（LC 236）：后序遍历的信息归并

前置依赖：[[#1. 递归世界观：树中还有树，答案中也有答案]]、[[#2. 对称二叉树（LCR 145）：双指针镜像递归]]（双指针递归先例）、[[二叉树结构篇#4. 遍历总纲：递归三序与层次遍历]]（后序时机）
后续衔接：[[#4. 递归三板斧：两题对照成通法]]、LC 235（BST 剪枝版 LCA）与树上距离公式（路径问题枢纽）

**① 它解决什么问题**

给定二叉树中两个结点 p、q，求它们的**最近公共祖先**（Lowest Common Ancestor，力扣 LC 236）：所有公共祖先中离它们最近（最深）的那个。A 源第 5 页的分析就是性质本身：若 p、q 分别出现在 root 的左右子树中，root 就是答案；若同在某棵子树 x 中，问题递归地转化为在 x 中找。换句话说，**LCA 是 p、q 首次"分居两侧"的分叉点**。复杂度：全树扫描一遍，时间 $O(n)$，递归栈 $O(h)$。

**② 直觉理解**

模型级类比：**族谱寻亲**。两个人查共同祖先，各自沿父链上报家族成员名单；名单第一次出现交集的那个人，就是最近公共祖先。放到树上：p 在左支、q 在右支的那个分叉结点，正是两边名单的"第一交集"。

用具体数字跑一遍（力扣官方样例树 `[3,5,1,6,2,0,8,null,null,7,4]`）：求 LCA(5, 1)。根 3 问左子树"见到 5 或 1 吗"，左答"见到 5"；问右子树，右答"见到 1"——左右各有所获，3 就是分叉点，答案 3。再求 LCA(5, 4)：根 3 问左，左子树里 5 自己站出来说"我是目标之一"（直接上交 5，不再下探），右子树答"啥也没有"——一边有货一边空，上交有货的那边，答案 5（5 自己就是 4 的祖先）。

**③ 原理与推导**

A 源第 5 页的递归函数 `f(root, p, q)`："在以 root 为根的树中找 p、q"。三出口：

1. `root == NULL`：空树，返回 NULL；
2. `root == p || root == q`：找到一个目标，直接返回 root；
3. 否则递归左右得 `l`、`r`：l、r 全空返回空；一空返另一个；都不空返回 root。

**推导：为什么"左右都非空"时 root 一定是最近的那个？**l 非空说明左子树含 p、q 至少其一，r 非空说明右子树亦然；又因为 p、q 各只有一个，左右必各含其一。任何更深的分叉点只能位于某一侧子树内，不可能同时管辖两侧——所以第一个看到"左右皆有所获"的结点就是最深的公共祖先，即答案。

**推导：为什么"找到一个就直接返回、不再下探"是对的？**设 `root == p`。若 q 在 p 的子树中，则 p 本身就是 LCA（祖先定义含自身），无需再找 q；若 q 不在，则真正的分叉点必然在 p 的上方，此时把"找到了 p"这条线索上交，由上层去完成归并——两种情形都不亏。返回值因此一条通道承担三种语义：NULL 是"这侧没有线索"，非空是"这侧找到了目标结点"，也是"这侧已找到答案"。三语义合一，靠出口 2 与归并规则的配合保持自洽。

**设计动机**一句话：后序位置（先收齐左右的结果再决定本层返回什么）是唯一能"等两边消息到齐再拍板"的时机——先序做不到，因为先序在消息到齐前就得行动。

**④ 代码演示**

取自源文件 LC 236.cpp（改动：补结构体结尾分号，原因同知识点 2；排版整理。`if (l && r)` 分支为素材原样保留，见⑥与附录 A-3）：

```cpp
TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (root == NULL) return NULL;               // 出口1：空树无线索
    if (root == p || root == q) return root;     // 出口2：找到一个就上交
    TreeNode* l = lowestCommonAncestor(root->left, p, q);   // 左子树的消息
    TreeNode* r = lowestCommonAncestor(root->right, p, q);  // 右子树的消息
    if (l == NULL) return r;   // 左无右有：上交右边（目标或答案）
    if (r == NULL) return l;   // 右无左有：上交左边
    if (l && r) return root;   // 左右皆有：root 是分叉点，即答案
    return NULL;
}
```

**执行追踪表**（数据取自②的样例树 `[3,5,1,6,2,0,8,null,null,7,4]`，LCA(5, 1) 的递归返回值归并过程）：

| 步骤 | 当前元素（调用） | 结构状态（递归栈） | 动作 | 结果 |
|------|-----------------|-------------------|------|------|
| 1 | f(3, 5, 1) | 栈 [f3] | 出口 1/2 检查：非空、非 p 非 q | 委托左右，等待归并 |
| 2 | f(5, 5, 1)（f3 的左） | 栈 [f3, f5] | 出口 2：root == p 命中 | 返回 5，不再下探（6/2/7/4 全部不入栈） |
| 3 | f(1, 5, 1)（f3 的右） | 栈 [f3] | 出口 2：root == q 命中 | 返回 1 |
| 4 | f3 收到 l=5、r=1 | 栈 [f3] | 归并：l 非空不交右、r 非空不交左 | 走到 `if (l && r)` |
| 5 | f3 返回 | 栈 [] | 左右皆有所获，root 是分叉点 | 返回 3，即 LCA(5,1)=3，与②一致 |

**错误写法对照**（对应⑥的两个【易错】坑）：

```diff
- // 错误心智模型：以为必须同时找到 p、q 才能返回，层层下探找齐
- // 后果：逻辑绕远，且"一侧找到、一侧没找到"的情形丢答案
+ if (root == p || root == q) return root;  // 修复：找到一个就立刻上交（出口 2）
+ if (l == NULL) return r;                  // 修复：一空交另一边（线索或答案）
+ if (r == NULL) return l;                  // 修复：由上层继续归并裁决
+ if (l && r) return root;                  // 修复：左右皆有 → 当前根即答案
- // 错误心智模型：返回值 = 最终答案（"找到 p 就当作找到答案"）
+ // 正确心智模型：返回值 = 这侧的线索（NULL 无线索 / 非空有线索），答案只在归并点产生
```

**⑤ 典型应用**

- 真题：LC 236 最近公共祖先（A 源第 4、5 页例题）。题解即上。实测（附录 B-5）：样例树六组断言全过——LCA(5,1)=3、LCA(5,4)=5（自身即祖先）、LCA(6,4)=5、LCA(7,8)=3、LCA(0,8)=1、LCA(4,4)=4。
- 迁移 1：LC 235 二叉**搜索**树的 LCA——利用 BST 性质剪枝：p、q 值都小于根则去左、都大于根则去右、否则根即答案，一趟 $O(h)$ 不必扫全树。
- 迁移 2：树上两结点距离——`dist(p, q) = dist(root, p) + dist(root, q) - 2 * dist(root, lca)`，LCA 是路径问题的公共枢纽。

**⑥ 坑点与边界**

> **【易错】** 以为"必须同时找到 p、q 才返回"。恰恰相反：找到一个就立刻上交（出口 2），归并规则保证不丢答案——③的两段推导是这条规则的依据。

> **【易错】** 返回值语义混淆：NULL、目标结点、答案共用一条返回通道，写代码时心里必须同时装着三种语义，分不清就会写出"找到 p 就当作答案返回"的错误版本。

> **【注意】** 素材源码的 `if (l && r)` 在逻辑上是冗余分支——前两个 `if` 已排除 l 或 r 为 NULL 的全部情形，走到第三句时 l、r 必非空。冗余无害（实测 6 组断言全过），属防御性写法，保留原样并登记附录 A-3。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：root == NULL → 预期：出口 1 返 NULL，空树无 LCA。
> 2. 单元素：树中只有 p 自己，调 lowestCommonAncestor(root, p, p) → 预期：出口 2 返 root，即 LCA(p, p)=p 自身（祖先定义含自身；附录 B-5 断言 LCA(4,4)=4 同理）。
> 3. 全相同：不适用：查找按结点指针身份（root == p 指针相等），与值无关。
> 4. 严格递增：不适用：理由同上，全程无值比较。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：结点值取 INT_MAX/INT_MIN → 不适用溢出检查（无算术、无值比较）；形态极值 $10^5$ 层斜树 → 栈深 $O(n)$ 爆栈风险，同知识点 1⑥ 的注意项。

回扣：本题递归的语义是"这侧有什么线索"，答案诞生于**后序位置的归并**。两道题都讲完了——把它们摆在一起，通法就浮出来了。

### 4. 递归三板斧：两题对照成通法

前置依赖：[[#2. 对称二叉树（LCR 145）：双指针镜像递归]]、[[#3. 最近公共祖先（LC 236）：后序遍历的信息归并]]（两题是对照素材）
后续衔接：[[二叉树结构篇#5. 非递归遍历：一个栈统一三序]]（斜树爆栈的备胎）、LC 226/543 等通法套用的题型族

**① 它解决什么问题**

素材只给了两道具体题的题解，没给可迁移的设计流程。为什么必须自己抽出通法？因为考场上遇到的是没见过的题——背诵题解迁移不了，设计流程才能。本知识点把两题摆进同一张对照表（下表即性质总表），回答开场悬念：递归函数到底在设计什么。复杂度两题同账：时间 $O(n)$、递归栈 $O(h)$。

**② 直觉理解**

模型级类比：**递归函数是一份合同**。签名（参数）是甲方乙方，单层逻辑是合同条款，返回值是交付物。签合同前先想清楚交付物长什么样，条款才有得写；先动手写条款再想交付物，必然返工。

**③ 原理与推导**

三板斧 = 终止条件、单层逻辑、返回值语义。两题对照：

| 三板斧 | LCR 145 对称二叉树 | LC 236 最近公共祖先 |
| --- | --- | --- |
| 返回值语义 | p、q 两子树是否互为镜像 | 这侧子树的线索（空/目标/答案） |
| 终止条件 | 双空真、单空假 | 空树返空；遇 p/q 返自身 |
| 单层逻辑 | 三关：同值 + 外侧对外侧 + 内侧对内侧 | 归并：左空交右、右空交左、皆有则我是答案 |
| 遍历时机 | 先序即可（本层判完再下潜） | 必须后序（等两边消息到齐） |

**先序还是后序的选择依据**：本层的行动是否依赖子树的结果？对称判断里本层只比两个值，不依赖——先序即可；LCA 里本层要等左右消息归并——必须后序。一句话：**要先知子树答案才能定本层的，走后序；只向下传递信息的，走先序**。

**④ 代码演示**

三行设计模板（自编通法，登记附录 B-4）：

```cpp
// 第一步：写语义注释 —— 一句话说清返回值
// 第二步：写终止条件 —— 最小不可再分的情形直接给答案
// 第三步：写单层逻辑 —— 委托子树，只拼一层
RetType f(TreeNode* root, ...) {
    if (终止条件) return 直接答案;
    auto l = f(root->left, ...);   // 委托
    auto r = f(root->right, ...);  // 委托
    return 单层归并(l, r, 根的事);
}
```

**错误写法对照**（对应⑥的【易错】坑）：

```diff
- // 错误：在本层写开子树内部的事（如 LCA 里本层就去查"左子树的左子树有没有 p"）
- if (root->left->left == p) ...   // 后果：单层越界干子树的活，递归退化成多重循环
+ // 修复：只拼一层——归并 l、r 与根自己的事，其余全部委托
+ auto l = f(root->left, ...);     // 委托
+ auto r = f(root->right, ...);    // 委托
+ return 单层归并(l, r, 根的事);    // 修复：委托不彻底等于没递归
```

**⑤ 典型应用**

- 现场设计（用三板斧推 LC 226 翻转二叉树）：语义"把以 root 为根的树就地翻转"；终止"空树返回"；单层"交换左右孩子，再委托左右子树各自翻转"。三行写完，正确性由三板斧自证。
- 真题回扣：LCR 145 与 LC 101 同题（力扣两站同题不同编号），LC 236 是 LCR 194 的同源题——三板斧设计一次，多处通关。
- 迁移：LC 543 二叉树的直径——语义改为"经过 root 的最长路径相关的树高"，单层逻辑里顺手更新全局最大值，是先序后序混用的进阶样例。

**⑥ 坑点与边界**

> **【易错】** 单层做多了：把子树内部的事也在本层写开（比如 LCA 里本层就去判断"左子树的左子树里有没有 p"）。委托不彻底等于没递归。

> **【注意】** 递归深度：斜树时栈深 $O(n)$，竞赛数据 $n \le 10^5$ 时递归可能爆栈，需改迭代或扩栈——结构篇的非递归遍历（一个栈统一三序）就是为此准备的备胎。

> **【补充】** 素材两份代码的 struct 缺分号（附录 A-3）提醒我们：判题器环境里 TreeNode 由系统预定义，本地复现时必须自己补全定义与测试驱动——验证环节的脚手架本身就是解题能力的一部分。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：模板对空树 → 预期：终止条件直接给答案（返 0/NULL/true 视语义而定），不崩溃。
> 2. 单元素：单结点 → 预期：终止条件不命中时，单层逻辑收到两个"空子树答案"，归并函数须能处理 base 答案（如 max(0,0)+1=1）。
> 3. 全相同：不适用：三板斧是设计流程，不涉及值语义。
> 4. 严格递增：不适用：理由同上。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：n=$10^5$ 斜树 → 预期：三板斧照常设计，但递归栈 $O(n)$，需按知识点 4⑥【注意】改迭代（结构篇非递归遍历）或扩栈。

回扣开场悬念：递归函数设计的就是一份"语义—终止—单层"的合同，两道题是同一合同模板的两种填法。三句话问完再动手，递归不再是玄学。

## 四、总结与自测

### 核心内容（一页纸速览）

- **总纲**：二叉树题多基于递归（A 源原话），因为树的定义本身递归；一趟全树递归时间 $O(n)$、栈 $O(h)$。
- **三板斧**：返回值语义（一句话）→ 终止条件（空树优先）→ 单层逻辑（只拼一层，其余委托）。
- **对称二叉树 LCR 145**：双指针镜像递归；三关=同值 + `check(p->left, q->right)` + `check(p->right, q->left)`；交叉比较是镜像本质，顺向是同构；出口双空真单空假；空树算对称。
- **最近公共祖先 LC 236**：后序归并；遇到一个目标立即上交；左右皆有所获则当前根即答案；返回值一通道三语义（空/目标/答案）；LCA 即"p、q 首次分居两侧"的分叉点。
- **先序 vs 后序**：本层依赖子树结果→后序；只向下传信息→先序。
- **素材缺陷**：两份源码 struct 缺分号，属判题器环境复写笔误，补正后实测 11/11 PASS。

| `bool check(TreeNode* p, ...)` | `int check(...)`，返 0/1（或 `#include <stdbool.h>`） | 返回值语义为真假判断 |
| `!q \|\| !p` | `q == NULL \|\| p == NULL` | 指针当布尔用的判空简写 |
| `auto l = f(root->left, ...)` | `TreeNode* l = f(root->left, ...)`（显式写出类型） | 自动类型推导：让返回值类型由编译器推（知识点 4 模板） |
