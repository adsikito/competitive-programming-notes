## 一、为什么需要它

先碰一次壁：上一篇的素数判断逻辑写在一行行循环里，现在题目要求"检查 111、663、781 三个数是否是素数"——不用函数，同一段"能否被 2 到 n/2 整除"的判断要抄写 3 遍；10.1 函数.pdf p5 的原话就是"这里就产生了不必要的重复代码"。再进一步：要输出 10 到 30 之间所有素数，逻辑还要再抄一遍。**碰壁的根源：同一段逻辑无法命名、无法复用、无法组合。**

函数的破法一句话：**给一段逻辑起名字，参数进、返回值出，之后用名字随处调用**。而"参数怎么进出"（传值还是别名）与"函数能否调用自己"（递归）是本篇的两条主轴。本篇讲 4 个知识点：函数定义与参数传值、引用传参对传值、递归与汉诺塔、函数重载与默认参数。顺序理由：先立定义与传值规则（1），马上补引用（2），两节合答"数据怎么进出"；然后递归（3）复用前两节的调用机制；最后语法糖收尾（4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 函数定义与参数传值：四种形式与形参拷贝

前置依赖：流程控制（同批，循环与分支）、数据类型与内存表示（同批）
后续衔接：本篇 ### 2. 引用传参 vs 传值：别名机制与 C 等价指针、本篇 ### 3. 递归与汉诺塔：出口、逼近与调用栈

**① 它解决什么问题**

函数（10.1 函数.pdf p4）：在其他语言里也叫过程或子例程——**封装一段逻辑，起名字，反复调用**。两大优点（p5）：提高代码可重用性（同一逻辑不必抄写多遍）、代码优化（大程序拆模块降低复杂性）。定义语法（p7）：`type funcName(paramlist) { ... return value; }`；四种基本形式（p10）按"有无参数 × 有无返回值"组合，返回类型 void 表示不返回。单次调用的额外开销是常数级（压栈出栈），函数本身不改变算法复杂度——复杂度由函数体内的逻辑决定。

**② 直觉理解**

模型级类比：**带窗口的自动售货机**。函数是一台机器：参数是投币口收进去的"复印件"，返回值是取货口吐出来的成品。机器内部怎么折腾复印件，都不会影响你口袋里的原钞票——这正是传值的本质。

小数据推演（p13-14 的 change 案例，这是本篇最重要的小实验）：`void change(int num) { num *= 2; }`，main 里 `int x = 100; change(x); cout << x;`——输出**还是 100**。调用时发生的事：x 的值 100 被复制一份塞进形参 num，函数内翻倍的是 num 这份复印件；函数结束 num 销毁，x 原封不动。p14 结论原话："函数的参数是形式参数，即是实参的拷贝。"

**③ 原理与推导**

定义与声明的区别（p7-9）：定义给出函数体（逻辑在哪），声明只给签名（长什么样）；编译器自上而下工作，**main 之前必须"见过"函数**——要么把定义写在 main 前（p9 左版），要么先声明后定义（p9 右版：`void printName();` 告诉编译器"这个名字存在，实体在后"）。为什么语言要区分两者？多文件编程（下一篇《变量作用域与多文件编程》（同批））里函数定义在 .cpp、声明在 .h，正是靠"声明先行"让不同文件互相调用——这是声明存在的设计动机。

形参与实参（p22）：形参是定义处括号里的变量（占位的空盒子），实参是调用处给的实值（装进去的货）。**为什么 C++ 默认传值而不默认传地址？** 传值天然隔离：被调函数无法破坏主调函数的数据，副作用显式可控；代价是需要修改实参时必须走别的通道——这正是知识点 2 的引用与 C 语言指针的存在理由。另注意返回值（p34）：C++ 函数不支持返回多个值，需要"多出口"时用引用参数（知识点 2）或返回结构体（结构体篇，同批）。

**④ 代码演示**

块一「核心代码」——四种形式 + 传值实验（取自 10.1 pdf p9/p10/p13/p39，自编整合，注明：自编示例，逻辑取自素材）：

```cpp
#include <iostream>
using namespace std;

void printName() {                 // 形式 1：无参无返回值
    cout << "c++" << endl;
}
int getFive() { return 5; }        // 形式 2：无参有返回值
void doublePrint(int v) {          // 形式 3：有参无返回值
    cout << v * 2 << endl;
}
int factorial(int num) {           // 形式 4：有参有返回值（p39 嵌套调用案例）
    int ret = 1;
    for (int i = 1; i <= num; i++) ret *= i;
    return ret;
}
void change(int num) { num *= 2; } // 传值实验（p13）

int main() {
    printName();
    doublePrint(getFive());        // 嵌套调用：返回值直接当实参
    cout << factorialSum(3) << endl;   // 函数嵌套调用（p39，见下方定义）
    int x = 100;
    change(x);                     // 复印件翻倍
    cout << "x= " << x << endl;    // 输出 100：传值不改实参
    return 0;
}
// factorialSum 定义在 main 之后？不——它必须在此前可见，见下方声明实验
```

块二「执行追踪表」（change 传值实验，x=100）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | x=100 | main 栈帧 | 调用 change(x)，复制 100 | 新栈帧 num=100 |
| 2 | num=100 | change 栈帧（独立） | num *= 2 | num=200（副本） |
| 3 | 函数结束 | change 栈帧销毁 | 无 return，num 随栈帧消失 | main 的 x 未被触碰 |
| 4 | x | main 栈帧 | cout << x | 输出 100 |

块三「错误写法对照」：

```diff
- int main() { printName(); ... } void printName() { ... }   // 坑1：定义在 main 之后且无前置声明，编译器在调用点"不认识"它（编译错误）
+ void printName(); int main() { printName(); ... } void printName() { ... }   // 先声明后定义（p9 右版）
- int swap(int num1, int num2) { int num3 = num1; num1 = num2; num2 = num1; return num1, num2; }   // 坑2（p36 原文）：num2 = num1 写错（应为 num2 = num3），且 return num1,num2 是逗号表达式只返回 num2——C++ 不支持返回多个值
+ 见知识点 2：引用参数才是一对多"返回"的正解
- int arr[a]; a = 10;   // 坑3（示意）：编译器自上而下，使用必须晚于"见过"
+ 先声明/定义，后使用——变量同理
```

**⑤ 典型应用**

- 课堂案例（10.1 pdf p13-14）：change 传值实验——理解传值的必做小实验，实测逻辑推演见④追踪表。
- 课堂案例（10.1 pdf p38-39）：factorial 嵌套调用求阶乘之和——函数作构件组装更大逻辑的示范（factorialSum 内部调 factorial）。
- 竞赛衔接：竞赛代码的函数通常只有几类——判素/判回文等谓词函数（下节 isPrime）、递归搜索函数（知识点 3）、板子函数（如快速幂）。竞赛衔接说明：判断"一个函数该不该抽出来"的标准是"这段逻辑是否需要独立测试或复用"；isPrime 抽出来后既能在素数筛题里单测，也能在数论题里复用。

**⑥ 坑点与边界**

> **【易错】** 以为传值函数能改实参。后果：x 不变（答案错，逻辑悄悄失效），见④追踪表。需要修改实参时用引用（知识点 2）。

> **【易错】** 忘写前置声明或定义顺序颠倒。后果：编译错误"未声明的标识符"。对策：小文件函数定义全放 main 之前；多文件时声明进头文件（下一篇）。

> **【注意】** 形参名与实参名无关：`change(x)` 里形参叫 num，两者只是"值相同"；重名不报错但易误导阅读——形参名按语义起。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：factorialSum(0) → 内层循环 i=1..0 零次，ret=1，sum=0（预期：0 的阶乘约定为 1、空和为 0，两约定不冲突）。
> 2. 单元素：factorialSum(1) → sum = 1! = 1（预期：1）。
> 3. 全相同：change(1) 与 change(1) 连调 → 每次 num 都从 1 复制、翻成 2、销毁（预期：x 永远 1，传值无累积效应）。
> 4. 严格递增：factorialSum(5) → 1+2+6+24+120=153（预期：153，可手验）。
> 5. 严格递减：调用顺序 factorial(5) 到 factorial(1) → 各自独立计算（预期：函数间无隐藏状态）。
> 6. 极值：factorial(20) → 20! 约 2.4e18 超 long long 前的 int 上限（2.1e9）——int 版在 13! 即溢出（预期：溢出为垃圾值；大阶乘换 unsigned long long 或边乘边取模）。

### 2. 引用传参 vs 传值：别名机制与 C 等价指针

前置依赖：本篇 ### 1. 函数定义与参数传值：四种形式与形参拷贝、数据类型与内存表示（同批，内存模型）
后续衔接：本篇 ### 4. 函数重载与默认参数（重载常配引用参数）、数组遍历与最值查找（同批，swap 是排序的构件）

**① 它解决什么问题**

引用（10.1 pdf p15）：**为已存在的变量取别名**，`type &name = data;`——"土豆和马铃薯都是同一种东西的不同命名"。引用做参数（p18）：`void change(int &num)`，函数收到的不再是复印件而是实参本尊的别名，改别名即改本尊。p19 的引用版 change 与 p13 传值版只差一个 `&` 字符，输出从 100 变 200。单次引用传参不发生拷贝，$O(1)$——但大对象（如结构体、string）传值时拷贝代价与对象大小成正比，引用传参同时解决"改实参"与"免拷贝"两件事。

**② 直觉理解**

模型级类比：**别名花名册**。传值是" photocopy 一份文件给对方改"（你的原件无恙）；引用是"告诉对方文件柜的哪个格子"（对方直接动你的原件）。C 语言的等价物是**递纸条**：把格子的地址写在纸条上传过去，对方拿地址自己找（指针）；引用则由编译器替你递纸条——写法像传值，机制是传址。

小数据推演（p17 的引用特性实验）：`int num1 = 100; int &num2 = num1; int num3 = 200; num2 = num3;`——给 num2 赋值 200，实际写的是 num1 的内存：num1=200、num2=200、num3=200。**num2 = num3 不是让 num2 改投 num3**（引用一旦绑定不可更改，p16 特性 3），而是把 num3 的值 200 写进 num1。这一步是引用与指针最容易混的点。

**③ 原理与推导**

引用三特性（p16）：不占新内存、与被引用变量共用一块空间；使用时与普通变量无异（& 只在定义处）；必须在创建时初始化且此后不可改绑，"类似指针常量"；不存在 NULL 引用。**为什么函数参数偏爱引用而不是指针？** 语义等价（都动本尊），但引用调用处写法不变（`change(x)` 而非 `change(&x)`）、函数体内免解引用、且不存在空引用——把指针的三个易错点（忘取址、忘星号、空指针）全部从接口上消灭。C 等价写法：

```cpp
void change_ptr(int *num) { *num *= 2; }   // C 等价：收地址
int main() { int x = 100; change_ptr(&x); }   // 调用处显式取址
```

返回引用（p20-21）：`int& func(int &v1)` 返回别名本身，调用处 `func(num)` 直接把 num 当返回值用且 num 已被改成 200——返回引用要注意被引对象不能超出作用域（p20 明确：返回局部变量的引用不合法，可返回静态变量或参数的引用）。设计动机：为什么引用必须初始化且不可改绑？因为引用不是"另一个变量"而是"同一个变量的第二个名字"——名字出生时就钉死在变量上，没有"改投"一说，这是它与指针的根本分界。

**④ 代码演示**

块一「核心代码」——传值 swap 与引用 swap 对照（取自 10.1 pdf p36 的错误交换与 p18 引用参数，自编整合，注明：自编示例，p36 原文缺陷见 A-3 登记 1）：

```cpp
#include <iostream>
using namespace std;

void swapBroken(int num1, int num2) {   // 传值版：改的是复印件
    int tmp = num1;
    num1 = num2;
    num2 = tmp;                          // p36 原文写 num2 = num1，两变量同值（A-3 登记 1）
}
void swapRef(int &num1, int &num2) {     // 引用版：动的是本尊
    int tmp = num1;
    num1 = num2;
    num2 = tmp;
}

int main() {
    int a = 1, b = 2;
    swapBroken(a, b);                    // 交换发生在副本上
    cout << a << " " << b << endl;       // 输出 1 2：交换失效
    swapRef(a, b);
    cout << a << " " << b << endl;       // 输出 2 1：交换生效
    return 0;
}
// 复杂度：两次调用均 O(1)；引用版免拷贝
```

块二「执行追踪表」（swapRef(1, 2)）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 调用 | main：a=1, b=2 | 绑定 num1↔a、num2↔b（别名，无拷贝） | 新栈帧两个别名 |
| 2 | tmp | 栈帧内 | tmp = num1 | tmp=1 |
| 3 | num1 | 别名写入 | num1 = num2 | a 变 2 |
| 4 | num2 | 别名写入 | num2 = tmp | b 变 1 |
| 5 | 返回 | 栈帧销毁，别名消失 | a、b 本尊已被改 | 输出 2 1 |

块三「错误写法对照」：

```diff
- void change(int num) { num *= 2; } change(x);   // 坑1：想改 x 却漏 &，传值只改副本（答案错）——p13 教学案例本身
+ void change(int &num) { num *= 2; } change(x);   // 一个 & 之差（p19 正解）
- int& bad() { int local = 5; return local; }     // 坑2：返回局部变量的引用，函数返回后栈帧销毁，别名悬空（未定义行为）
+ int& good(int &v) { return v; }                 // 返回参数或静态变量的引用（p20 约束）
- int &r; r = x;                                  // 坑3：引用未初始化（编译错误）；且引用定义后不可改绑
+ int &r = x;                                     // 创建时绑定
```

**⑤ 典型应用**

- 课堂案例（10.1 pdf p19）：引用版 change——一个 `&` 让输出从 100 变 200 的最小对照。
- 课堂案例（10.1 pdf p21）：返回引用的 func——v1*=100 后返回别名，实测逻辑推演 num=200。
- 竞赛衔接：数组篇的 swap(arr[i], arr[j]) 之所以能真交换，正因标准库 swap 是引用参数；竞赛函数中"要改实参""传大对象免拷贝"两类场景一律引用。竞赛衔接说明：结构体作参数时（结构体篇，同批）传值拷贝整个结构体，n 次调用就是 $O(n \times 大小)$——DFS 传图结构时用引用是复杂度习惯的一部分。

**⑥ 坑点与边界**

> **【易错】** 想改实参却传值。后果：静默失效（答案错），编译器不警告。对策：写函数前先问"这个参数是输入还是输出"——输出参数必须引用。

> **【易错】** 返回局部变量的引用。后果：悬空引用，未定义行为（RE 或随机值）。对策：只返回参数、静态变量或全局变量的引用。

> **【注意】** 引用不是指针的语法糖替代品：不可改绑、不可为空、必须初始化；需要"可空、可重指、可算术移动"时仍用指针（指针篇，同批）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：swapRef(x, x) 同一变量交换自己 → tmp=x、x=x、x=tmp（预期：无变化、不崩，别名写回自身）。
> 2. 单元素：change(x) 只有一个实参 → x 翻倍（预期：单参数引用版生效）。
> 3. 全相同：swapRef(5, 5) → 值相同交换无感（预期：仍 5 5）。
> 4. 严格递增：a=1,b=2 → 换成 2 1（预期：序反转）。
> 5. 严格递减：a=2,b=1 → 换成 1 2（预期：序恢复，与方向无关）。
> 6. 极值：a=-2147483648, b=2147483647 → 交换只是搬字节不参与运算（预期：安全；但若在函数内做 a+b 就溢出——INT_MIN+正数越界）。

回扣开场：数据进出函数的两条通道（值通道、别名通道）全部打通。现在函数不只是"封装"，还能可靠地"输出"——下一节让它调用自己。

### 3. 递归与汉诺塔：出口、逼近与调用栈

**① 它解决什么问题**

函数递归（10.1 pdf p40）：**函数在函数体内调用自身**。适用场景（p42 递归条件）：问题的解可以由"同型的小问题"拼出来，且存在明确的出口。两个必备件（p42 条款 3）：**递归出口**（什么时候停）与**向出口逼近**（每层调用规模变小，"否则就是无限递归"）。汉诺塔（p51-54）：n 个圆盘从起始柱搬到目标柱，每次只动顶端一个、大盘永在大盘下；n 盘最少移动次数 $T(n) = 2T(n-1) + 1$，$T(n) = 2^n - 1$——n=64 时约 $1.8 \times 10^{19}$ 次，指数爆炸（传说中的世界末日题）。递归是 [[二叉树竞赛篇]] 全篇的执行引擎，这里先把调用栈看清楚。

**② 直觉理解**

模型级类比：**套娃任务卡**。你接到任务"搬 5 层套娃"，发现它等于"先搬 4 层套娃到中转站，再把最大那层搬过去，再把 4 层从中转站搬过去"——于是你抄三张新任务卡派下去，其中两张还是"搬 4 层"。每张卡开打时各带一个独立信封（栈帧：自己的局部变量），任务完成的信封当场销毁，结果写给派卡的上一张卡。**n==1 的卡是唯一不用再抄卡的任务（出口）。**

小数据推演（p53 的两盘汉诺塔，起始 A 目标 C 辅助 B）：把上面 1 盘从 A 搬到 B；把下面大盘从 A 搬到 C；把 1 盘从 B 搬到 C——3 步，恰为 $2^2-1$。三盘 7 步、四盘 15 步，每加一盘翻倍加一。

**③ 原理与推导**

三步策略（p54 原文）：1. 将起始柱上的 n-1 个圆盘移动到辅助柱上；2. 将起始柱上遗留的 1 个圆盘移动到目标柱上；3. 将辅助柱上的所有圆盘移动到目标柱上。**为什么这样是对的？** 归纳：假设 n-1 盘可从任意柱搬到任意柱（归纳假设），则第 1 步与第 3 步各是一次"小一号的同型问题"，第 2 步大盘孤立无碍（此时大盘下无盘、上无盘）；大盘到位后永远不再移动，小盘继续按归纳假设安置。基例 n==1 直接一步直达。这条"相信小问题已解决，只管拼装"的思维方式就是递归世界观——[[二叉树竞赛篇]] 的前中后序遍历全是这个套路。

栈帧推导（p42 条款 1-2、4）：每次调用创建受保护的独立空间，局部变量互不影响；执行完毕或 return 时"谁调用，就将结果返回给谁"，栈帧随之销毁。递归深度 = 同时存活的栈帧数，$O(n)$ 空间——**为什么深递归会栈溢出？** 栈空间有限（p56 原话："栈空间是有限的……死循环递归调用的最终结果就是导致栈内存空间枯竭"），10^6 层的朴素递归必炸，需要出口更浅或改迭代。汉诺塔本身递归深度 n 层（n=64 也才 64 层栈帧，安全），但移动次数 $2^n$ 不可行——**深度与次数是两个独立的复杂度**，初学者常混。

**④ 代码演示**

块一「核心代码」——递归求和、斐波那契、汉诺塔（取自素材 code.cpp，逻辑逐行原样，注明改动：仅精简注释；static 的语义属下一篇《变量作用域与多文件编程》（同批），此处只需知道 count 全程累加不销毁）：

```cpp
#include <iostream>
using namespace std;

int func(int n) {                    // 递归求 1+2+...+n（code.cpp 原样）
    if (n == 1) return 1;            // 出口：n==1 停
    else return func(n - 1) + n;     // 逼近：n 每层减 1
}
int fibo(int n) {                    // 斐波那契第 n 项（p50 原样）
    if (n <= 2) return 1;            // 出口：前两项都是 1
    else return fibo(n - 1) + fibo(n - 2);   // 两支逼近
}
void hanoi(int num, char sou, char tar, char aux) {   // 起始/目标/辅助
    static int count = 1;            // 移动计数（跨调用存活，见①说明）
    if (num == 1) {                  // 出口：单盘直达
        cout << "第" << count << "次：从" << sou << "移动到" << tar << endl;
        count++;
    } else {
        hanoi(num - 1, sou, aux, tar);      // 步骤1：n-1 盘起始 -> 辅助
        cout << "第" << count << "次：从" << sou << "移动到" << tar << endl;   // 步骤2：大盘直达
        count++;
        hanoi(num - 1, aux, tar, sou);      // 步骤3：n-1 盘辅助 -> 目标
    }
}
int main() {
    cout << func(5) << endl;         // 15（实测附录 B-5）
    cout << fibo(10) << endl;        // 55（实测附录 B-5）
    hanoi(3, 'A', 'B', 'C');         // 7 次移动（实测附录 B-5）
    return 0;
}
```

**⑥ 坑点与边界**

> **【易错】** 缺出口或参数不逼近。后果：无限递归，栈溢出 RE（编译器不报错，运行才炸）。对策：写递归先写出口，再确认每条递归支路的参数单调趋向出口。

> **【易错】** 以为递归是"零成本循环"。后果：朴素 fibo 指数级调用次数（TLE）；深递归栈溢出（RE）。对策：估算"深度 × 每帧局部变量"与"调用总次数"两个数。

> **【注意】** 汉诺塔的 static count：跨所有调用累加，因此打印的"第 N 次"是全局序号；若改成普通局部变量，每次调用各自从 1 数，序号全错——static 的完整机制在下一篇《变量作用域与多文件编程》（同批）正式展开。

### 4. 函数重载与默认参数：同名不同参与省略实参

前置依赖：本篇 ### 1. 函数定义与参数传值：四种形式与形参拷贝、本篇 ### 2. 引用传参 vs 传值：别名机制与 C 等价指针
后续衔接：面向对象编程（同批，重载是运算符重载与成员函数的前身）、预处理命令（同批，宏与内联的对照）

**① 它解决什么问题**

C 语言里函数名不可重复，"求两个数的和"对 int、float、double 要起三个名字。函数重载（10.1 pdf p64-65）：**C++ 允许同名函数共存，条件是参数列表必须不同（个数、类型、顺序）**；仅返回类型不同不足以构成重载（p65 规则 4）。默认参数（p31）：定义时给形参指定默认值，调用时省略对应实参则自动启用默认值。两者都是编译期的"接口便利"——单次调用 $O(1)$，不引入运行时开销。

**② 直觉理解**

模型级类比：**同名窗口按单据类型分流**。银行只有一个"开户"窗口（同名），但柜员看你递的是身份证还是护照（参数类型），走不同的内部流程（不同函数体）；单据上的可选项没填（省略实参），按"默认网点"处理（默认参数）。分流发生在进门一刻（编译期决议），不是进门后再猜。

小数据推演（code.cpp 的重载 sum，实测附录 B-5）：`sum(100, 200)` 匹配 int 版打印 "int"；`sum(1.1f, 1.2f)` 匹配 float 版打印 "float"；`sum(12.31, 1.3232)` 匹配 double 版。默认参数（p33）：`sum(num1)` 一个实参 → num2 用默认值 100，输出 101；`sum(num1, num2)` 两个实参 → 3。同一名字，四种行为，全由"你递了什么"决定。

**③ 原理与推导**

重载的底层机制（p66 原话）：C++ 编译时会根据参数列表对函数**重命名**——`void Swap(int a,int b)` 变成 `_Swap_int_int` 一类的内部名字，`void Swap(float x,float y)` 变成 `_Swap_float_float`；调用时按实参逐个匹配（重载决议），匹配失败编译报错。**为什么仅返回类型不同不算重载？** 因为决议只看"你递了什么"（调用处实参），返回值在调用处可以丢弃——`sum(1,2)` 的返回值接不接、接成什么都不影响匹配，编译器无从区分两个只差返回类型的候选。默认参数规则（p31-33）：默认值从右往左连续给出（`f(int a, int b=100)` 合法，`f(int a=1, int b)` 不合法）——为什么？实参按位置左对齐分配，若左参数可省则"省了第一个、留下第二个"的对应关系无法表达。

延伸两笔（了解即可）：**内联函数**（p56-58）：`inline` 建议编译器把函数体在调用处展开，消掉压栈出栈开销，适合一两句话的小函数（p57：函数体长则调用开销占比小，不值得）；与宏展开类似但带类型检查。**可变参数**（p23-30）：`int mulSum(int n, ...)` 配 va_list/va_start/va_arg/va_end 逐个读可选参数（printf/scanf 即此机制）；类型安全差，竞赛中几乎不用，了解即可（code.cpp 里的 MSVC 风格 __crt_va_start 宏属平台差异，已注释，A-3 登记 4）。

**⑥ 坑点与边界**

> **【易错】** 仅返回类型不同的"重载"。后果：重定义编译错误（p65 规则 4）。对策：记住决议只看实参列表。

> **【易错】** 默认参数与重载叠加产生二义调用。后果：编译错误"重载歧义"。对策：一组功能同类时二选一。

> **【注意】** 全角字符（括号、引号、分号）是抄课件代码的高频事故：10.1 pdf p71 `isPrime（int n)`、p45-46 的笔误都属此类，粘贴课件代码后先过一遍编译器。中文引号 "" 在字符串字面量里同样非法（素材 PDF 中多处如此，正文一律用半角）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：add() 无实参 → v1 无默认值，编译错误（预期：编译期拦截，第一个参数必须显式给）。
> 2. 单元素：add(1) → 101（预期：默认值生效的最小样本）。
> 3. 全相同：sum(1,1) / sum(1.0f,1.0f) / sum(1.0,1.0) → int/float/double 三版各输出 2（预期：同名不同版各司其职）。
> 4. 严格递增：sum(1,2), sum(1,3), sum(1,4) → 3,4,5（预期：int 版连续调用无状态残留）。
> 5. 严格递减：add(9), add(8) → 109, 108（预期：默认值每次重新使用，非累积）。
> 6. 极值：sum(2147483647, 1) → int 加法溢出为 -2147483648（预期：重载不改变溢出事实；大数求和重载 long long 版）。

回扣开场：函数从此有了"一套名字、多种接口"的弹性——素数判断抽成 isPrime（知识点 1）、批量输出配 printPrime（重载思想在同名谓词上的落点）、需要改实参时走引用（知识点 2）、需要自相似时上递归（知识点 3）。现在你能把开场那道"三个数判素数"写成两行调用，并且能说清每一行背后用的是本篇哪一步的结论。

## 四、总结与自测

### 核心内容（一页纸速览）

- **定义与传值**：四种基本形式；形参是实参的拷贝，改形参不动实参（change 案例 x=100 不变）；定义/声明分离支撑多文件。
- **引用**：变量的别名，共用内存、必须初始化、不可改绑；引用参数改本尊、免拷贝；C 等价写法是指针（取址调用 + 解引用）。
- **递归**：出口 + 逼近缺一不可；每次调用独立栈帧，深度 O(n) 空间；汉诺塔 T(n)=2T(n-1)+1 即 2^n-1；深度与调用次数是两个复杂度。
- **重载与默认参数**：同名按参数列表决议（编译期改名）；仅返回类型不同不算；默认参数从右连续给；延伸：inline 内联、va_list 可变参数。
- **复杂度账**：函数调用本身 O(1)；算法复杂度看函数体；朴素双递归是指数级的活教材。

### 前置概念清单

- 流程控制（同批）：循环与分支——函数体的全部控制流。
- 数据类型与内存表示（同批）：栈帧、内存布局——传值拷贝与引用别名的底层依据。
- 复杂度分析与递归（同批）：递归式与增长量级——T(n)=2^n-1 与 fibo 指数级的记账工具。
