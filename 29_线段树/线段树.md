## 一、为什么需要它

先用你大概率碰过壁的方式做 P3372【模板】线段树 1：n 个数的数列，m 条指令，`1 x y k` 给区间 [x,y] 每个数加 k，`2 x y` 问 [x,y] 的和。暴力逐格加、逐格求和，单次 $O(n)$，m 次 $O(nm)$；$n, m \le 10^5$ 时是 $10^{10}$ 量级，超时（32.线段树.pptx slide 1 记"暴力 O(n^2) TLE"，严格是 $O(nm)$，A-3 登记 2）。[[前缀和与差分]]（同批）能把静态查询降到 $O(1)$，可一次区间修改就把前缀和数组整体作废，代价回到 $O(n)$，还是死。

碰壁的根源：**修改和查询都要"逐格"扫区间，两者代价被绑死在区间长度上**。线段树的破法：把数列按分治装进一棵树，长区间的信息由短区间现成拼出，两个操作都只走树上的一条到两条路径——$O(\log n)$。

本篇讲 5 个知识点：结构（O(log n) 从哪来）、建树与单点修改、区间查询拆分、懒标记、P3372 总装。顺序理由：结构先于操作，"建→查→改"按依赖递进，实战收尾。

## 二、知识点逐讲（每个知识点一节，共 5 节）

### 1. 线段树的结构：分治与二叉树的结合体

前置依赖：[[二叉树结构篇]]（二叉树、数组存树）、递归分治（[[DFS]]（同批）的递归框架、[[二分]]（同批）的折半直觉）
后续衔接：[[#2. 建树与单点修改：自底向上汇总]]、树状数组（同批，待产出，先文字锚定——同一问题的另一把刀）

**① 它解决什么问题**

线段树是维护**区间信息**的数据结构（slide 2-3）：把长度 n 的数列按"每次对半分"装进一棵二叉树，每个结点存一段区间 [l, r] 和该区间的聚合值（和、最值等）。slide 3 给出适配特征："大区间的解可以从小区间的解合并而来"。关键性质：单点修改、区间修改、区间查询（求和 / 最大 / 最小）都能在 $O(\log N)$ 内完成，前提是聚合运算满足"大区间 = 左右子区间合并"（加法、取 max 都满足），返回值即所查区间的聚合值。

| 操作 | 复杂度 | 前提 | 返回/效果 |
|------|--------|------|-----------|
| 建树 | $O(n)$ | 区间非空 | 每个结点拿到 [l,r] 与聚合值 |
| 单点修改 | $O(\log n)$ | 已建树 | 根到叶路径上的结点更新 |
| 区间修改（懒标记） | $O(\log n)$ | 已建树 | 整段记账（知识点 4） |
| 区间查询 | $O(\log n)$ | 已建树 | 返回区间聚合值 |

**② 直觉理解**

模型级类比：**公司分层报表**。最底层是每张原始票据（叶子），每个部门经理只交一张"我管辖范围的总和"报表；总部（根）只看总表。查"3 到 9 月合计"时，若有现成的"3-6 月报表"和"7-9 月报表"，两张一拼就是答案——不必翻任何原始票据。这个类比管住三件事：汇总（建树）、拼表（查询）、先记总账后补明细（知识点 4 的懒标记）。

用具体数字看（n=4，数组 {1, 5, 4, 2}）：查 [2,4] 的和，用叶子 [2,2]=5 加现成结点 [3,4]=6，得 11——只访问 3 个结点，全程没碰 a[1]。这就是"用现成报表拼"省掉的部分。

```text
                [1,4] sum=12  (结点1，根)
               /               \
      [1,2] sum=6 (结点2)   [3,4] sum=6 (结点3)
        /        \             /        \
  [1,1]=1(结点4) [2,2]=5(结点5) [3,3]=4(结点6) [4,4]=2(结点7)
```

文字版推导链：[1,4] 对半分成 [1,2] 与 [3,4]；[1,2] 再分成两个叶子；根的 sum 是两个孩子之和（6+6=12）。分裂只看下标 mid=(l+r)/2，与数值无关。

**③ 原理与推导**

slide 2 的五条特征：分治自顶向下建树，每次左右各半；每个结点表示一个区间，非叶结点含多个元素、叶子只含一个；"近似完全二叉树"，可用数组存树——下标 k 的左孩子是 2k、右孩子是 2k+1；l==r 是叶子；l<r 时左儿子 [l,m]、右儿子 [m+1,r]，m=(l+r)/2。

**为什么是 O(log n)**：n 个叶子的树，每层区间长度减半（奇数时差 1），层数至多 $\lceil \log_2 n \rceil + 1$；而单点修改和查询都只沿"根到某叶子"的一两条路径走（知识点 3 论证查询每层至多下钻 2 个结点），路径长度就是树深——$O(\log n)$。n=10^5 时约 17 层，10^10 量级的逐格扫描被压到 10^1 量级的路径行走，这就是 slide 2 问"他为什么这么高效"的答案。

**设计动机：为什么用数组存树、为什么要开 4n**——完全二叉树形状使"孩子下标可计算"（2k、2k+1），省掉全部指针字段（slide 2 特征 3）；空间上叶子可能被顶到下一层，总结点数与最大下标不足 4n（slide 3 原话"4*n（可能存在空间浪费）"）。精确的"最小够用常数"与 n 的二进制位形有关，这一段我不确定，竞赛口径一律开 4n，只多花一倍内存，换来绝不开小。另外下标从 1 开始而非 0：0 号结点的"左孩子 2×0=0"与自身重合，父子编号塌缩（slide 3 只说"初始节点为1"，原因属补充：资料未覆盖，属补充）。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** tree 数组只开 N 不开 4N。结点编号在奇数分裂时会被顶到很深，n=1e5 的 4n≈4×10^5 个位置才够——开小即 RE（④对照坑 1）。

> [!caution]
> **【易错】** 把线段树当二叉搜索树用。slide 2 原话"线段树是一种二叉搜索树"，但它的"有序"在区间划分不在键值大小——不能按 BST 的"比大小走左右"查找，只能按覆盖关系下钻（A-3 登记 1，采信教材口径）。

> [!note]
> **【注意】** 树的形状只由 n 决定，与数值无关。给数组排序、取绝对值都不改变树形，只改各结点 sum——这让"边界数据集"里的递增/递减档失去结构意义，只查数值。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → Build(1,1,0) 的 le==ri 不成立，mid=0 后区间不再缩小，递归不终止——分治前提是区间非空，n≥1 才适用（预期：识别为不适用并标注理由）。
> 2. 单元素：n=1，{9} → Build(1,1,1) 一步到叶，树只有根结点一个，sum=9（预期：无孩子、编号 1）。
> 3. 全相同：{7,7,7,7} → 树形与 {1,5,4,2} 完全一致，根 sum=28（预期：形状只由 n 决定）。
> 4. 严格递增：{1,2,3,4,5} → 结构同"全相同"档，仅 sum 不同（预期：分裂只看下标）。
> 5. 严格递减：{5,4,3,2,1} → 与递增档同构（预期：同上理由，两档合并为同一结论）。
> 6. 极值：a[i] 全取 1e9，n=1e5 → 总和 1e14，int（上限约 2.1e9）必溢出；ll（约 9.2e18）在题面保证的 2e18 内安全（预期：sum 必须 long long，int 版 WA）。

回扣开场：结构讲清了"为什么 O(log n)"——但树要先用 O(n) 建出来才有得查。现在你能解决"树长什么样"了，下一步看它怎么被 O(n) 地建出来。

### 2. 建树与单点修改：自底向上汇总

前置依赖：[[#1. 线段树的结构：分治与二叉树的结合体]]、递归（C 基础）
后续衔接：[[#3. 区间查询：覆盖拆分]]、[[前缀和与差分]]（同批——静态对偶：单点改一次，前缀和数组整体作废，线段树只改一条路径）

**① 它解决什么问题**

建树回答"每个结点的 sum 从哪来"：递归分裂到叶子，叶子读入 a[le]，回溯时父结点 sum = 左右孩子之和（slide 3 建树段、P3372.cpp Build）。单点修改回答"改一个数要动多少结点"：只动根到该叶子的一条路径，$O(\log n)$（slide 4"当你改变了一个点，这个点的所有父节点都得改变"）。为什么建树肯花一次 $O(n)$：它换来之后每次操作 $O(\log n)$，m 次操作总账 $O(n + m\log n)$，对 $10^5$ 规模绰绰有余。

**② 直觉理解**

报表类比：建树就是月底从原始票据一层层汇总出各级报表；单点修改是"发现一张票据记错了"——从这张票据到总部的每一层报表都得改，但**只改这一条线**，其他部门纹丝不动。

具体数字（n=4，{1,5,4,2}）：Build 先到叶子 4、5、6、7 号分别填 1、5、4、2；回溯时 2 号=1+5=6、3 号=4+2=6；最后 1 号=6+6=12。改 a[3]+10：只有 6 号（4 变 14）、3 号（6 变 16）、1 号（12 变 22）三个结点变——恰好是根到叶 6 号的一条路径。

**③ 原理与推导**

Build 的三段结构：先记区间（tree[i].l、tree[i].r——后面所有覆盖判断的依据）；再判叶子（le==ri 时直接取 a[le]，slide 2 特征 4）；否则 mid 分裂递归两侧，回溯时 sum 相加。复杂度 $O(n)$（slide 4 原话"建树的时间复杂度为O(n)"）：结点总数不足 4n、每结点 O(1) 工作。

单点修改（资料未给出独立函数，属补充：资料未覆盖，属补充——slide 4 的"先递归找到叶子再回传"）：与 Build 同框架，x 落在哪半边就走哪半边，叶子处 +=k，回溯重算 sum。它与 [[线性DP]]（同批）"父问题的解由子问题拼出"是同一个思想，只是这里"拼"发生在树上。注意 P3372.cpp 注释区保留了一个无懒标记的区间修改旧版（L87-98，注释原话"最坏的情况下退化成O(n)"）——单点用它没有问题（路径 O(log n)），整段区间用它就退回逐格扫描，这正是知识点 4 要解决的。

**④ 代码演示**

块一「核心代码」（Build 取自 P3372.cpp L15-29，改动：仅注释精简；addPoint 为自编补充——依据 slide 4 文字描述，无素材源码）：

```cpp
void Build(int i, int le, int ri) {          // 复杂度：O(n)
    tree[i].l = le;                          // 对：先记区间（坑1）
    tree[i].r = ri;                          // 错：不记 l/r——后续覆盖判断全部失效
    if (le == ri) {                          // 边界：叶子（slide 2 特征 4）
        tree[i].sum = a[le];
        return;
    }
    int mid = (le + ri) / 2;                 // 下取整：保证两半都严格变小
    Build(2 * i, le, mid);                   // 左孩子管 [le, mid]
    Build(2 * i + 1, mid + 1, ri);           // 右孩子管 [mid+1, ri]
    tree[i].sum = tree[2 * i].sum + tree[2 * i + 1].sum;   // 回溯汇总
}
void addPoint(int i, int x, ll k) {          // 单点加（自编），复杂度：O(log n)
    if (tree[i].l == tree[i].r) { tree[i].sum += k; return; }   // 叶子：直接改
    int mid = (tree[i].l + tree[i].r) / 2;
    if (x <= mid) addPoint(2 * i, x, k);
    else addPoint(2 * i + 1, x, k);
    tree[i].sum = tree[2 * i].sum + tree[2 * i + 1].sum;   // 只重算路径上的结点
}
```

块二「执行追踪表」（Build(1,1,4)，数组 {1,5,4,2}）：

| 步骤 | 当前结点 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 结点1 [1,4] | 空 | le<ri，mid=2，递归左 | 进入结点2 |
| 2 | 结点2 [1,2] | 空 | mid=1，递归两侧 | 进入结点4 |
| 3 | 结点4 [1,1] | 叶子 | le==ri，sum=a[1] | sum=1，返回 |
| 4 | 结点5 [2,2] | 叶子 | sum=a[2] | sum=5，结点2 sum=6 |
| 5 | 结点3 [3,4] | 分裂 | 叶 6=4、叶 7=2 | 结点3 sum=6 |
| 6 | 结点1 [1,4] | 回传 | sum=6+6 | sum=12，建树完成 |

块三「错误写法对照」（从⑥【易错】转化）：

```diff
- void Build(int i, int le, int ri) { if (le == ri) { tree[i].sum = a[le]; return; } ... }
- // 坑1：漏写 tree[i].l=le; tree[i].r=ri —— 建树不报错，但修改/查询的覆盖判断读到的 l/r 全是 0（答案错）
+ 先记 l/r，再判叶子（P3372.cpp L17-19 的顺序）
```

**⑤ 典型应用**

- 真题：洛谷 P1531 I Hate It——单点改成绩 + 区间查最大值，把 addPoint 的 sum 换成 max、Build 的汇总换成 max 即可，题号真实。
- 真题：洛谷 P1198 [JSOI2008] 最大数——末尾动态加数后查最近一段的最大值，建树与单点更新的合体场景。
- 迁移检验题（自编）：a={1,5,4,2}，执行 addPoint(3,+10)，再求 [2,4] 的和。建议先独立做，再对照答案：路径 1→3→6，sum 变为 1 号 22、3 号 16、6 号 14；[2,4]=a[2]+a[3]+a[4]=5+14+2=21，用结点 5（=5）与 3 号（=16）拼出 21。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 建树漏记 l/r。后果隐蔽：Build 本身能跑完，之后所有覆盖判断全在跟 0 比较，答案整体错（④对照坑 1）。

> [!caution]
> **【易错】** 单点修改改完叶子忘记回传。树上留着"新旧不一致"的结点，后续查询读到旧 sum（④对照坑 3）。

> [!note]
> **【注意】** 多组数据复用 tree 数组时，Build 不会清掉上一轮残留的 tag（P3372.cpp 的 Build 只写 l/r/sum）。单次建树的 OJ 场景不触发；断言程序多轮复用时必须显式清零（附录 B-5 的实测教训）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 建树前提不成立，理由同知识点 1 边界第 1 条（预期：不适用）。
> 2. 单元素：n=1，addPoint(1,1,+5) → 路径只有根自己，tree[1].sum 直接 +5（预期：一步完成）。
> 3. 全相同：{7,7,7}，addPoint(2,+3) → 仅路径 [1,3]→[2,3]→[2,2] 三个结点 sum 变化（预期：改动结点数 = 树深 + 1）。
> 4. 严格递增：{1,2,3,4}，addPoint(4,+1) → 路径 1→3→7，与值序无关（预期：路径由下标 x 决定）。
> 5. 严格递减：{4,3,2,1}，addPoint(1,+1) → 路径 1→2→4（预期：同上，两档验证同一性质）。
> 6. 极值：a[i]=1e9，addPoint(+1e9) 执行 1e5 次 → 单点 sum 至 2e14，ll 安全（预期：int 在第一次加完就可能溢出）。

回扣开场：树建好了（O(n)），单点能改了（O(log n)）。现在你能解决"怎么改一个数"了——接下来是把"查一段"也压到 O(log n)。

### 3. 区间查询：覆盖拆分

前置依赖：[[#2. 建树与单点修改：自底向上汇总]]
后续衔接：[[#4. 懒标记：区间修改为何仍是 O(log n)]]（查询下钻前必须兑现欠账）、[[栈与队列]]（迭代改写时存待访问结点）

**① 它解决什么问题**

区间查询把 [L,R] 的聚合值用树上现成结点拼出来（slide 5"区间查询：直接递归查询即可"）。每个结点相对查询区间只有三种关系：**完全覆盖**（结点区间 ⊆ [L,R]，直接返回它的 sum，整棵子树不再看）、**无交集**（不进入）、**部分覆盖**（下钻两个孩子）。复杂度 $O(\log n)$：每层至多 2 个结点"部分覆盖"而下钻——部分覆盖意味着 [L,R] 的左端点或右端点跨过该结点的 mid，两个端点各至多对应一条下钻路径；其余结点要么完全覆盖直接返回、要么无交不进入。总访问结点 $O(\log n)$ 量级（教材通识口径，逐层论证资料未给出）。

**② 直觉理解**

报表类比：查"3-9 月合计"，总部若恰好有"3-9 月报表"直接抄（完全覆盖）；没有就拆成"3-6 月"与"7-9 月"两张现成的一拼；1-2 月、10-12 月的报表连看都不看（无交集）。

具体数字（树同知识点 2 的 {1,5,4,2}）：查 [2,4]——根 [1,4] 部分覆盖下钻；左 [1,2] 部分覆盖，其孩子 [1,1] 无交集不进、[2,2] 完全覆盖取 5；右 [3,4] 完全覆盖取 6。答案 5+6=11，只访问 5 个结点，7 个结点的树一个没浪费。

```text
查询 [2,4]：
结点1 [1,4] 部分覆盖 → 下钻
 ├─ 结点2 [1,2] 部分覆盖 → 下钻
 │   ├─ 结点4 [1,1] 与 [2,4] 无交集 → 不进入
 │   └─ 结点5 [2,2] 完全覆盖 → 取 5
 └─ 结点3 [3,4] 完全覆盖 → 取 6
答案 = 5 + 6 = 11
```

文字版推导链：完全覆盖的判定是"结点区间 ⊆ 查询区间"（tree[i].l>=le && tree[i].r<=ri）；下钻条件是"查询区间与左半有交（le<=mid）"与"与右半有交（ri>=mid+1）"；两条判定互斥地切开了 mid。

**③ 原理与推导**

为什么判定方向必须是"结点 ⊆ 查询"而不是反过来：返回的是"结点整段的现成 sum"，只有结点整段都被要求时它才可直接用；若写反成"查询 ⊆ 结点"，会把没被要求的格子也算进去。为什么下钻判定用 le<=mid 与 ri>=mid+1：左孩子管辖 [le_,mid]（此处 le_ 指结点左端），查询 [L,R] 触到左半当且仅当 L≤mid；右半同理——两个 if 恰好把 [L,R] 落在 mid 两侧的部分分给对应孩子，一格不漏、一格不重。

**设计动机：为什么要"完全覆盖就停"**——若去掉这个分支一路拆到叶子，任何查询都变成全树遍历 $O(n)$（slide 2 问"为什么高效"的反面教材）；正是"现成报表直接抄"把访问量从"全部结点"压到"两条边界路径附近"。P3372.cpp 注释区保留的无懒标记 query（L99-121）就是本知识点代码的同源版本。

**④ 代码演示**

块一「核心代码」（取自 P3372.cpp 注释保留的 query L99-121；相对源文件的改动：精简注释；注意此版无 down(i)，进入知识点 4 后部分覆盖处必须先下传）：

```cpp
ll query(int i, int le, int ri) {            // 查询 [le,ri]，复杂度：O(log n)
    ll ans = 0;                              // 对：就地初始化（坑2）
    if (tree[i].l >= le && tree[i].r <= ri) {
        // 完全覆盖：结点整段都要，直接抄现成 sum
        return tree[i].sum;
    }
    int mid = (tree[i].l + tree[i].r) / 2;
    if (le <= mid) {                         // 查询区间触到左半
        ans += query(2 * i, le, ri);
    }
    if (ri >= mid + 1) {                     // 查询区间触到右半
        ans += query(2 * i + 1, le, ri);
    }
    return ans;
}
```

### 4. 懒标记：区间修改为何仍是 O(log n)

前置依赖：[[#3. 区间查询：覆盖拆分]]
后续衔接：[[#5. P3372 实战：区间加区间和总装]]、P3373 双标记（乘法+加法，真题延伸）、树状数组（同批，待产出——区间加+单点查的对偶实现）

**① 它解决什么问题**

无懒标记的区间修改把 [L,R] 逐叶子扫一遍，最坏 $O(n)$——P3372.cpp 注释原话"区间修改--->最坏的情况下退化成O(n)"（L88），m 次操作退回 $10^{10}$。**懒标记**（slide 4"引进一个新玩意：lazy-tag"）：修改递归走到"完全覆盖"的结点时**记账不细算**——tag 记"这一整段还欠孩子多少增量"，同时用"区间长度 × k"立即把本结点 sum 改对，孩子先不动（slide 4 原话"tag[i] 记录了区间 i 的修改……那啥时候修改？一会再修改"）。复杂度：区间修改回到 $O(\log n)$，因为完全覆盖就停，访问的仍是两条边界路径附近。

**② 直觉理解**

报表类比升级：经理收到"全体员工每人加 200"的通知，不逐个通知员工——先在部门总账上加"人数 × 200"，并挂一张"待传达到位"的便签（tag）。哪天总部要查某小组明细，经理才把便签兑现给相关小组——检查哪一部分只做哪一部分（slide 5 原话"平时先把事情放着，等到哪天要检查的时候，就临时再去做……实至名归"）。

具体数字（树同前，{1,5,4,2}）：执行"1 [1,4] +2"——根完全覆盖，一个动作：tag=2、sum=12+4×2=20，四个叶子纹丝不动。再查 [2,3] 时才下传：孩子们 sum 各补 2×2=4。修改付 O(1)，欠账的偿还被摊进以后的必经之路。

**③ 原理与推导**

下传 down(i) 做三件事（P3372.cpp L30-43）：两个孩子 tag 各 += 父 tag（欠账记到孩子头上）；两个孩子 sum 各 += 孩子区间长 × 父 tag（先把孩子的总账改对）；父 tag 清 0（L41 注释"注意"——不清则每次下传都重复发同一笔账）。修改 Updata 的完全覆盖分支做两件事：tag+=k、sum+=(r-l+1)×k；部分覆盖分支先 down(i) 再下钻，回溯时重算 sum。

**为什么下传时机是"部分覆盖要下钻时"**：任何读取（查询）或更细的修改都只会从根往下走，"走到哪补到哪"保证经过的每个结点账都是清的——不在路径上的子树保持欠账状态完全无害。这是"懒"能成立的原因：欠账只在必经之路上偿还，偿还成本被摊平。**tag==0 的语义修正**：P3372.cpp L13 注释"tag==0 说明该结点对应的区间没被修改过"，严格说 tag 是"尚未下传的加法增量"，==0 只表示"没有欠账"——加了 0 或加减相抵后 tag 也是 0，但结点确实被修改过；sum 已经改对，不影响正确性（A-3 登记 4）。

```text
操作 1 [1,3] +2（树同前，{1,5,4,2}）：
结点1 [1,4] 部分覆盖 → down(1)（tag=0，无事）→ 下钻
 ├─ 结点2 [1,2] 完全覆盖 → tag+=2，sum=6+2*2=10（账记在这，结点4、5 不动）
 └─ 结点3 [3,4] 部分覆盖 → down(3)（无事）→ 结点6 [3,3] 完全覆盖（tag+=2，sum=6）
    → 回传结点3 sum=8 → 回传根 sum=18
```

文字版推导链：完全覆盖付"长度×k + tag 记账"两笔；部分覆盖先兑现旧账再下钻；回溯把孩子们改对的新 sum 加回父结点。修改后 2 号结点的孩子 sum 仍是旧值 1、5——欠账挂在 2 号 tag 上，等有人下钻再补。

**④ 代码演示**

块一「核心代码」（取自 P3372.cpp L30-61；相对源文件的改动：删空行、注释精简，逻辑逐行一致）：

```cpp
void down(int i) {                           // 下传懒标记
    if (tree[i].tag != 0) {
        tree[2 * i].tag += tree[i].tag;      // 欠账记到孩子头上
        tree[2 * i].sum += (ll)(tree[2 * i].r - tree[2 * i].l + 1) * tree[i].tag;
        tree[2 * i + 1].tag += tree[i].tag;
        tree[2 * i + 1].sum += (ll)(tree[2 * i + 1].r - tree[2 * i + 1].l + 1) * tree[i].tag;
        tree[i].tag = 0;                     // 注意：清账（P3372.cpp L41"注意"）
    }
}
void Updata(int i, int le, int ri, ll k) {   // 区间 [le,ri] 加 k，复杂度：O(log n)
    if (tree[i].l >= le && tree[i].r <= ri) {
        // 完全覆盖：记账不细算（可能有连续多次修改，tag 用 += 累积）
        tree[i].tag += k;
        tree[i].sum += (ll)(tree[i].r - tree[i].l + 1) * k;
        return;
    }
    down(i);                                 // 部分覆盖：先兑现欠账，再下钻
    int mid = (tree[i].l + tree[i].r) / 2;
    if (le <= mid) Updata(2 * i, le, ri, k);
    if (ri >= mid + 1) Updata(2 * i + 1, le, ri, k);
    tree[i].sum = tree[2 * i].sum + tree[2 * i + 1].sum;   // 回传新 sum
}
```

**⑥ 坑点与边界**

> [!caution]
> **【易错】** down 忘清父 tag。账被反复兑现，sum 越查越大且无报错（④对照坑 1）——素材特意在 L41 注释"注意"的就是这一行。

> [!caution]
> **【易错】** 完全覆盖分支只加 k 不乘长度。单点改侥幸不错，整段改必错（④对照坑 2）。

> [!note]
> **【注意】** 修改与查询**都要** down。欠账可能被任意一条下钻路径撞上，只防一处不够（④对照坑 3）；叶子上的 tag 无人下传也无害——它没有孩子，sum 已含增量。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：m=0 → 无任何操作（预期：无行为，不崩）。
> 2. 单元素：n=1，[1,1]+5 → 根（即叶）完全覆盖：tag+=5、sum+=5（预期：叶子 tag 永不下传，查询直接读 sum=初值+5，正确）。
> 3. 全相同：{7,7,7,7}，[1,4]+2 后查 [1,4] → 根完全覆盖直接读 sum=36，全程不下传（预期：读值正确且树未动——懒的极致）。
> 4. 严格递增：{1,2,3,4}，[1,3]+2 后查 [2,3] → 7+6=13（预期：tag 途经结点2 中转一次，对账一致）。
> 5. 严格递减：{4,3,2,1}，[2,4]+10 后查 [3,4] → 12+11=23（预期：部分覆盖触发一次下传）。
> 6. 极值：k=1e9、区间长 1e5 → 单次 len×k=1e14，int 即爆、ll 安全；连做 1e4 次同类修改，sum ≤ 2e18 在题面保证内（预期：ll 全程安全）。

回扣开场：修改 O(log n)、查询 O(log n)，暴力碰壁的两头都堵上了。现在你能解决"为什么区间改没有退化成 O(n)"了——记账与下传时机。下一节把四个知识点装进 P3372 的完整流程。

### 5. P3372 实战：区间加区间和总装

前置依赖：[[#1. 线段树的结构：分治与二叉树的结合体]]、[[#2. 建树与单点修改：自底向上汇总]]、[[#3. 区间查询：覆盖拆分]]、[[#4. 懒标记：区间修改为何仍是 O(log n)]]
后续衔接：P3373 双标记、动态开点与可持久化（延伸，非必需）、树状数组（同批，待产出）

**① 它解决什么问题**

洛谷 P3372【模板】线段树 1（slide 1）：n 个数的数列，m 条指令——`1 x y k` 给 [x,y] 每个数加 k，`2 x y` 输出 [x,y] 的和。数据范围 $1 \le n, m \le 10^5$，a_i、k 为正数，任意时刻数列的和不超过 $2 \times 10^{18}$——long long 是底线。总复杂度 $O(n + m\log n)$：建树 O(n) 一次，每次指令 O(log n)，10^5 条指令约 10^5×17 次basic运算，1 秒时限宽裕。

**② 直觉理解**

工单类比（报表模型的操作面）：op1 是"给某部门发加薪通知"（完全覆盖就记账，欠着明细）；op2 是"总部要看某范围总账"（路过欠账先兑现，再拼现成报表）。板子题的价值是把"读入→派发→建树→两操作"的回路跑顺，不留死角。

用官方样例跑一遍（输入 `5 5 / 1 5 4 2 3 / 2 2 4 / 1 2 3 2 / 2 3 4 / 1 1 5 1 / 2 1 4`）：`2 2 4` 查 5+4+2=11；`1 2 3 2` 后数列变 {1,7,6,2,3}；`2 3 4` 查 6+2=8；`1 1 5 1` 后变 {2,8,7,3,4}；`2 1 4` 查 2+8+7+3=20。输出 11、8、20（附录 B-5 实测一致）。

**③ 原理与推导**

main 的骨架三段（P3372.cpp L122-157）：读入数组；`Build(1,1,n)`——L131 注释原话"从根结点开始建树 根结点上1号结点 [1,n]"，对应知识点 1 的下标起点约定；循环读 op 派发，op==1 走 Updata、否则走 query 并 printf。**为什么用 scanf/printf 而非 cin/cout**：源码保留了被注释的 cin 版（L124、L128），量级 10^5 的 IO 两者都能过，但源码最终选了更稳的 scanf——ll 要配 %lld（L129、L141），这也是本篇最高频的失分点之一。**为什么根结点区间是 [1,n] 而数组下标从 1 起**：结点编号 1 起与元素下标 1 起对齐，l、r 直接兼作 a 的下标，省掉 0 号的换算。

**④ 代码演示**

块一「核心代码」（取自 P3372.cpp 的 main L122-157；相对源文件的改动：删去被注释的 cin 备选与末尾空行，op/x/y/k 就地声明，四函数见知识点 2-4，拼装后即可编译——见附录 B-5）：

```cpp
int main() {
    int op, x, y;
    ll k;
    scanf("%d %d", &n, &m);
    for (int i = 1; i <= n; i++) {
        scanf("%lld", &a[i]);            // 对：%lld 配 ll（坑1）
    }
    Build(1, 1, n);                      // 根结点 1 号，区间 [1,n]（L131）
    for (int i = 1; i <= m; i++) {
        scanf("%d", &op);
        if (op == 1) {                   // 区间加：走知识点 4 的 Updata
            scanf("%d %d %lld", &x, &y, &k);
            Updata(1, x, y, k);
        }
        else {                           // 区间和：走知识点 3+4 的 query
            scanf("%d %d", &x, &y);
            printf("%lld\n", query(1, x, y));
        }
    }
    return 0;
}
```

块二「执行追踪表」（官方样例，n=5，树结点记作 [区间]sum；初始 {1,5,4,2,3}，建树后根 [1,5]sum=15）：

| 步骤 | 当前指令 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 2 2 4 | 根 [1,5] 部分覆盖 | 拆分拼合（知识点 3） | 输出 11 |
| 2 | 1 2 3 2 | 结点 [2,3] 完全覆盖 | tag 记账、sum+=2×2（知识点 4） | 根 sum=19，叶子未动 |
| 3 | 2 3 4 | 下传兑现 | [2,3] 的欠账传给叶 | 输出 8（=6+2） |
| 4 | 1 1 5 1 | 根 [1,5] 完全覆盖 | tag+=1，sum+=5 | 根 sum=24 |
| 5 | 2 1 4 | 部分覆盖+下传 | 兑现根欠账后拼合 | 输出 20（=2+8+7+3） |

块三「错误写法对照」（从⑥【易错】转化）：

```diff
- scanf("%d %d %d", &x, &y, &k);   // 坑1：k 是 ll 却用 %d 读 —— 未定义行为（答案错/RE）
+ scanf("%d %d %lld", &x, &y, &k); // 源码 L141 原样
- int ans; printf("%d\n", ans);    // 坑2：答案用 int 存/打 —— 和上限 2e18 远超 int（答案错）

+ struct Node tree[N << 2];        // 4n 空间 + ll 字段（知识点 1）
```

**⑤ 典型应用**

- 真题：P3372 本体（板子总装），官方样例输出 11、8、20，实测通过（附录 B-5）。
- 真题：素材内置数据重演（P3372.cpp L158-177 注释区，8 个数 10 条指令，五问答案 11574 / 38941 / 20004 / 22776 / 25882）——断言程序逐问核对通过（附录 B-5）。
- 迁移检验题（重演素材内置样例，出处 P3372.cpp 注释区）：按指令序列手算五问。建议先独立做，再对照答案：2 6 7 → 6119+5455=11574；两笔区间加后 2 1 6 → 38941；2 6 8 → 20004；1 1 6 2948 后 2 1 2 → 22776；2 4 6 → 25882。全部与断言程序实测一致。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** ll 与 %d 混搭。k 的读入、ans 的输出都用 %lld，一处错全盘错且编译器不报（④对照坑 1、坑 2）。

> [!caution]
> **【易错】** 忘了数列和可到 2e18 而用 int 聚合。样例数值小侥幸通过，大数据必错——题面这句话就是在提醒 ll（④对照坑 2）。

> [!note]
> **【注意】** 模板常量不可跨题照抄：N=100005 对应本题 n≤1e5，换题先重算 4n 与 IO 格式；多组数据的题还要处理 tree 残留（知识点 2⑥ 注意项）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=1, m=0 → 建树后无指令，无输出（预期：空输出、不崩）。
> 2. 单元素：n=1，指令 `1 1 1 5` 与 `2 1 1` → 根即叶，输出 5（预期：全程无下传无拆分）。
> 3. 全相同：{7,7,7,7}，`2 1 4` → 根完全覆盖直接读 sum=28（预期：零递归）。
> 4. 严格递增：{1..100000}，`2 1 100000` → 5000050000（预期：超 int 上限约 2.1e9，%lld 输出——递增档专查求和溢出）。
> 5. 严格递减：{100000..1}，`2 2 3` → 199999（预期：拆分与值序无关）。
> 6. 极值：`1 1 100000 1000000000` 后 `2 1 100000` → 1e14（预期：ll 全程安全；k 误用 %d 即错）。

回扣开场：现在你能解决开场那道 P3372 了——建树用知识点 2 的 O(n) 汇总，op2 用知识点 3 的拆分拼答案，op1 用知识点 4 的懒标记把区间改压回 O(log n)，op 的派发就是本节 main 的三段骨架。$10^{10}$ 到 $O(n+m\log n)$，这条路每一站都有名字。

## 四、总结与自测

### 核心内容（一页纸速览）

- **结构**：分治 + 二叉树；结点存 [l,r] 与聚合值；数组存树（k → 2k、2k+1）；开 4n；下标 1 起（slide 2-3）。
- **O(log n) 的来源**：树深 $\lceil\log_2 n\rceil+1$；查询每层至多 2 个结点下钻（知识点 1③、3①）。
- **建树**：叶读 a[le]，回溯 sum=左+右，$O(n)$（slide 4、P3372.cpp Build）。
- **区间查询**：完全覆盖直接取、无交不进、部分覆盖下钻，$O(\log n)$（slide 5）。
- **懒标记**：完全覆盖"tag 记账 + 长度×k 改 sum"，部分覆盖先 down；down 三件事记 tag、补 sum、清父账（slide 4-5、P3372.cpp down/Updata）。
- **P3372**：建树 + 派发，$O(n+m\log n)$；sum 必须 long long（和上限 2e18）。

### 前置概念清单

- 二叉树与数组存树（[[二叉树结构篇]]）：本篇树形与 2k/2k+1 编号的载体。
- 递归与分治（[[DFS]]（同批）的递归框架）：Build、Updata、query 的骨架都是"判边界 → 分裂 → 回溯"。
- 折半直觉（[[二分]]（同批））：mid 分裂与二分的取半同源。
- 子问题合并（[[线性DP]]（同批））：pushup"父由子拼出"与状态转移同思想。
- long long 与 %lld：和上限 2e18 的唯一解。
- scanf/printf 格式符：竞赛 IO 的稳定底座。
- 前缀和（[[前缀和与差分]]（同批））：静态区间和的对照物，被"区间修改"逼下场的参照。
