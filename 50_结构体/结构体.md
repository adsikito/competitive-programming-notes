## 一、为什么需要它

先做一道你会卡壳的题：输入 $n$（$2 < n < 100$）个学生的姓名、年龄和三科成绩，输出总分最高的学生全部信息（15.1 pdf p48 案例 1）。用你现在的武器库做：开三个平行数组 `name[n]`、`age[n]`、`score[3][n]`，找最值没问题——但如果题目加一句"按总分从高到低输出"，你得排序。平行数组排序时，交换第 i 和第 j 个人意味着**四个数组各交换一次**，漏搬任何一个，数据就串位：名字对上了别人的分数，答案是整题报废。$n = 100$ 时一次排序要搬几百次，每次四个赋值，出错概率随代码行数线性上涨。

碰壁的根源：**"一个学生的信息"是一个逻辑整体，平行数组却把它拆散在四处**。结构体（struct）的破法一句话：把属于同一个事物的多个变量**打包成一个整体**，交换时整体赋值一次完成。本篇讲 4 个知识点：struct 定义与成员、结构体数组与 typedef、点与箭头访问、竞赛 cmp 比较器打包写法。顺序理由：先定义（知识点 1），再批量（知识点 2），再取址访问（知识点 3），最后组装成排序实战（知识点 4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. struct 定义与成员

前置依赖：[[数据类型与内存表示]]（成员类型决定成员占多少字节）、C 基础的变量与函数
后续衔接：[[#2. 结构体数组与 typedef]]、[[排序]]（知识点 4 的结构体排序用 [[#1. struct 定义与成员]] 的打包作前提）

**① 它解决什么问题**

结构体（struct）是**由相同或不同类型的数据构成的数据集合**（15.1 pdf p5）。它解决"一个事物的多项属性必须作为一个整体存取"的问题：学生的姓名（string）、年龄（int）、分数（double）类型不同、不能塞进同一个数组，但它们逻辑上属于同一个学生——struct 把它们捆绑成一个新类型。关键性质：定义结构体得到的是**类型**（像 int 一样的蓝图），定义变量后才占内存；成员用名字访问；同类型结构体变量之间可以整体赋值。复杂度账先记下：整体赋值的代价与成员多少成正比（本篇复杂度意识的起点），访问单个成员 O(1)。

**② 直觉理解**

模型级类比：**档案袋**。平行数组是三列格子（一列放所有人的名字、一列放年龄、一列放分数），第 3 个人的信息分散在三列的第 3 格；结构体是一个档案袋，每个人的姓名、年龄、分数装进**同一个袋子**，袋子上写着类型名 student。"交换两个学生"从"搬三列格子各一格"变成"换两个袋子"——一次赋值完成。

用具体数字跑一遍（15.1 pdf p8-9）：定义 `student s1 = {"张三", 20, 99.5};`——袋子 s1 装入三项；`s1.age = 21` 改袋中第二项；`student s2 = s1` 复制整个袋子，之后改 `s2.age` 不影响 `s1.age`（实测断言 value-copy-indep，附录 B-5），因为赋值复制的是**成员的值**，不是引用。

**③ 原理与推导**

语法（15.1 pdf p6）：`struct` 类型名 `{` 成员声明 `};`——每个成员以 `;` 结尾，**最后的大括号后面也有一个 `;`**，没有它程序报错。为什么这个分号必须存在？因为 `struct {...}` 在语法上是一个"类型表达式"，C++ 允许在它后面直接跟变量名（如 `} s1, s2, s3;`，素材 classcode.cpp L16 的注释正是这种写法）；编译器要靠分号判断"类型定义到此结束"，缺了它就无法断定下一行是变量声明还是新语句——这是 C 语法继承下来的解析规则。

定义与初始化的三种形态（pdf p7-10）：先定义类型再定义变量；定义类型的同时定义变量 `}s1, s2;`；C++11 起可在定义时给成员默认值（`string name="C++"; int age{20};`，pdf p10、classcode.cpp L7-9）。为什么设计成员默认值？没有它，每个变量定义后都要手写一遍初始化；竞赛里"忘了初始化"是 WA 大户，默认值把这笔账一次性付清。C 等价对照：`student s1 = {"张三",20,99.5};` ↔ C 写法 `struct student s1 = {"张三",20,99.5};`（C++ 里 struct 关键字可省）；成员默认值在 C 里没有对应物，C 靠 memset 或手写初始化函数。

**④ 代码演示**

块一「核心代码」（自编示例，取 15.1 pdf p7-10 的定义与初始化组合；相对源文件改动：把 pdf 分散在 4 页的片段合成一个可编译程序）：

```cpp
#include <iostream>
#include <string>
using namespace std;
struct student {              // 类型定义：蓝图，不占内存
    string name;              // C 等价：char name[20];
    int age;
    double score;
};
int main() {
    student s1 = {"张三", 20, 99.5};   // 整体初始化：按成员声明顺序
    s1.age = 21;                        // 点访问：整体名.成员名
    student s2 = s1;                    // 整体赋值：逐成员复制
    s2.age = 99;                        // 改 s2 不影响 s1
    cout << s1.name << " " << s1.age << " " << s1.score << endl;
    cout << s2.name << " " << s2.age << " " << s2.score << endl;
    return 0;                            // 复杂度：整体赋值 O(成员字节数)，成员访问 O(1)
}
```

逐段讲：第 6-10 行是类型定义（末尾分号不能省，见③）；L13 按声明顺序初始化，`"张三"` 给 name、`20` 给 age、`99.5` 给 score，顺序错位则类型不匹配报错；L15 整体赋值把三个成员各复制一份。

块二「执行追踪表」（上面程序的四次结构状态变化）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | s1 初始化 | s1={张三,20,99.5} | 按序装袋 | s1 三成员就位 |
| 2 | s1.age = 21 | s1={张三,21,99.5} | 改第二成员 | age 20→21 |
| 3 | s2 = s1 | s2={张三,21,99.5} | 逐成员复制 | s2 独立于 s1 |
| 4 | s2.age = 99 | s2={张三,99,99.5} | 改 s2 | s1.age 仍为 21 |

块三「错误写法对照」：

```diff
- struct student { string name; int age; double score; }   // 坑1：末尾漏分号——编译器把下一行当声明接在类型后，报 error（CE）
+ struct student { string name; int age; double score; };   // 大括号后必须有 ;
- student s1 = {20, "张三", 99.5};   // 坑2：初始化顺序错位——int 位置收到 string，类型不匹配（CE）
+ student s1 = {"张三", 20, 99.5};   // 按成员声明顺序给值
- struct s1;   // 坑3：定义变量漏类型名——struct 后要跟类型名 student（CE）
+ student s1;  // C++ 中 struct 关键字可省：student s1; 即可
```

**⑤ 典型应用**

- 例题（15.1 pdf p48-49 案例 1）：输入 n 个学生姓名、年龄、三科成绩，输出总分最高者。思路：struct 存每人信息，边读边算 total，线性扫一遍取最大，$O(n)$——开场那道"平行数组会串位"的题，用打包一次解决。
- 例题（hw_code.cpp）：teacher 结构体内嵌 `student sarray[5]`——结构体成员可以是另一个结构体，打包可以嵌套（下一知识点展开）。
- 迁移检验题（自编）：输入 3 个平面的直线方程参数 a、b、c（ax+by=c），输出斜率最大的一条。数据范围：系数绝对值 ≤ 100。输入格式：3 行每行 3 个整数；输出格式：一行 3 个整数。建议先独立做，再对照题解：定义 `struct line { int a, b, c; double k; }`，读入后 `k = -1.0 * a / b`（b 为 0 记 k 为 1e18），线性比较输出，骨架与 pdf 案例 1 同构。

**⑥ 坑点与边界**

> **【易错】** struct 定义末尾漏分号。报错位置通常在**下一行**，与真实错误位置错开，排查时先看报错行的上一行有没有缺分号（④对照坑 1）。

> **【易错】** 整体初始化顺序与成员声明顺序不对应。`{"张三", 20, 99.5}` 必须严格按 name、age、score 的顺序，错位轻则 CE 重则静默类型转换（④对照坑 2）。

> **【注意】** 整体赋值复制的是成员的值。含 string 成员时复制的是字符串内容（深拷贝由 string 类完成）；本篇只涉及这种安全情形，指针成员的整体赋值语义到 [[链表]] 再展开。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不定义任何结构体变量 → 类型定义不占内存，程序空转（预期：无输出、不崩）。
> 2. 单元素：只定义 s1 并整体初始化一次 → 输出 s1 三成员（预期：与初始化值一致）。
> 3. 全相同：s1 = s2 = s3 同值 → 互不影响，各自输出同值（预期：无串扰）。
> 4. 严格递增：age 依次 18、19、20 赋给同一变量 → 每次覆盖，最终 20（预期：最后一值生效）。
> 5. 严格递减：score 依次 99.5、90、60 → 同上，最终 60。
> 6. 极值：score 赋 2.1e9 量级 → double 上限约 1.8e308，安全；若成员是 int 则 2.1e9 溢出（int 上限约 2.1e9）——选成员类型时按数据范围定（防溢出）。

回扣开场：档案袋模型把"一个学生的多项属性"装进一个整体，现在你能解决平行数组串位问题了——靠的是本节的整体初始化与整体赋值。下一节把"一个袋子"扩成"一排袋子"。

### 2. 结构体数组与 typedef

前置依赖：[[#1. struct 定义与成员]]、C 基础数组
后续衔接：[[#4. 竞赛 cmp 比较器打包写法]]（排序对象就是结构体数组）、[[排序]]

**① 它解决什么问题**

结构体数组（15.1 pdf p17-19）是**每个元素都是一个结构体的数组**，解决"批量存取同一类事物"的问题：3 个学生、54 张牌、n 条边。typedef（pdf p40-43）给已有类型起别名，解决"类型名太长反复写"的问题。关键性质：结构体数组的下标访问 O(1)，整体交换两个元素 O(成员字节数)——这正是知识点 4 排序的代价来源；typedef 纯编译期改名，零运行时开销。

**② 直觉理解**

模型级类比：**档案柜**。结构体变量是一个档案袋，结构体数组是一排柜子，`s[i]` 是第 i 个柜子，`s[i].score` 打开第 i 个袋子看分数。typedef 是给柜子上贴的标签：`typedef student stu;` 之后 `stu` 与 `student` 是同一类型的不同叫法。

用具体数字跑一遍（15.1 pdf p19）：`student arrstu[3] = {{"name1",20,90},{"name2",21,92},{"name3",22,99}};`——三个袋子一次装入；`arrstu[1].age` 是 21。整体交换：`swap(arrstu[0], arrstu[1])` 一个动作完成三成员搬运，平行数组要写三次。

**③ 原理与推导**

数组的元素类型没有限制（pdf p17），结构体自然可以作为元素类型，内存布局是**成员紧挨着排，再一个元素紧挨一个元素**——这就是 [[数据类型与内存表示]] 里"连续存储"的自然延伸，也是下标访问 O(1) 的原因（地址 = 首地址 + i × 单个元素字节数）。

typedef 三条竞赛高频形态（pdf p41-43）：基本类型 `typedef int myint;`；结构体 `typedef student stu;`；**数组别名** `typedef int arr[10];`——别名被挤在元素类型与元素个数之间，`arr a;` 等价 `int a[10];`。为什么 typedef 要存在？C 时代 struct 关键字不能省，每次定义变量都要写 `struct student s1;`，typedef 一次定义处处省字；C++ 里虽然 struct 关键字可省，竞赛里 typedef 仍常用于给长类型名（如 pair 的嵌套）缩短书写。C 等价对照：`typedef student stu; stu a[3];` ↔ C 写法 `typedef struct student stu; struct student a[3];`——C 里 typedef 后才能省 struct 关键字，这正是它诞生的原始动机。

hw_code.cpp（素材）展示了嵌套打包：teacher 结构体含 `string t_name` 与 `struct student sarray[5]`，一层柜子里嵌一排小柜子，sizeof 也会随嵌套增长（classcode.cpp 注释段用 sizeof 实测过字节数）。

**④ 代码演示**

块一「核心代码」（取自素材 hw_code.cpp，改动：把随机赋值改为定值以便追踪；学生数 5 改 2；函数签名与遍历骨架逐行同源）：

```cpp
#include <iostream>
#include <string>
using namespace std;
struct student { string s_name; int score; };
struct teacher {                 // 嵌套打包：老师袋里装一排学生袋
    string t_name;
    struct student sarray[2];
};
void printinfo(struct teacher tarray[], int len) {   // 结构体数组做参数
    for (int i = 0; i < len; i++) {
        cout << tarray[i].t_name << endl;
        for (int j = 0; j < 2; j++)
            cout << "  " << tarray[i].sarray[j].s_name
                 << " " << tarray[i].sarray[j].score << endl;
    }
}
int main() {
    typedef student stu;         // 别名：stu 即 student
    stu a[2] = {{"stu_A", 90}, {"stu_B", 80}};
    struct teacher tarray[2] = {{"teacher_A", {{"stu_A",90},{"stu_B",80}}},
                                {"teacher_B", {{"stu_C",70},{"stu_D",60}}}};
    printinfo(tarray, sizeof(tarray) / sizeof(tarray[0]));  // 数组元素个数
    return 0;                    // 复杂度：遍历 O(n × 内层长度)
}
```

逐段讲：L15 形参写 `struct teacher tarray[]` 与素材一致，数组传参传的是首地址（不拷贝整个数组，这是复杂度能到 O(n) 而非 O(n²) 的原因）；L21 `sizeof(tarray)/sizeof(tarray[0])` 算元素个数，只在**原数组**上成立（传参退化为指针后失效，坑 2）。

块二「执行追踪表」（printinfo 遍历 tarray，len=2）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | i=0 | tarray[0]={teacher_A,{A90,B80}} | 输出 t_name | teacher_A |
| 2 | j=0 | 同上 | 访问 sarray[0] | 输出 stu_A 90 |
| 3 | j=1 | 同上 | 访问 sarray[1] | 输出 stu_B 80 |
| 4 | i=1 | tarray[1]={teacher_B,{C70,D60}} | 输出 t_name | teacher_B |
| 5 | j=0,1 | 同上 | 访问 sarray[0..1] | 输出 stu_C 70、stu_D 60 |

块三「错误写法对照」：

```diff
- void f(struct teacher t) { int len = sizeof(t.sarray)/sizeof(t.sarray[0]); }   // 坑1：对退化后的指针 sizeof——t.sarray 若按数组形参传入则已是指针，结果是 8 不是 40（答案错）
+ void f(struct teacher tarray[], int len) { ... }   // 素材原样：长度由调用方显式传入
- typedef int arr[10]; arr a; int n = sizeof(a)/sizeof(a[0]);   // 坑1 实际成立：a 是真数组，n=10——对比理解"退化"只发生在传参时
+ struct teacher tarray[3]; f(tarray, 3);   // 元素个数在定义作用域内算好再传
- stu a[2] = {"stu_A", 90, "stu_B", 80};   // 坑2：嵌套初始化缺内层大括号——依赖编译器逐成员填充，可读性差且部分编译器告警（潜在 WA 源）
+ stu a[2] = {{"stu_A", 90}, {"stu_B", 80}};   // 每个元素一对大括号
```

**⑤ 典型应用**

- 例题（cards.cpp，18.1 综合案例 4）：54 张牌每张是 `struct CARD { char suit[10]; char face[10]; }`，全局 `card[54]` 就是结构体数组；洗牌是"随机挑一张与当前位置整体交换"（`temp = card[i]; card[i] = card[j]; card[j] = temp;`，三行完成两张牌的成员级搬运）——打包让"交换一张牌"天然原子。
- 例题（hw_code.cpp 作业原题）：3 名老师各带 5 名学生，嵌套结构体数组 + 函数赋值 + 遍历打印，即本节核心代码的 5 人版。
- 迁移检验题（自编）：输入 n（n ≤ 1000）张牌的花色（字符串 ≤ 9 字符）与点数（整数 1~13），按点数从大到小输出。建议先独立做，再对照题解：`struct card { char s[10]; int p; } c[1000];` 读入后按 p 排序（排序写法见知识点 4），输出——牌面排序就是 cards.cpp 数据结构 + cmp 的组合。

**⑥ 坑点与边界**

> **【易错】** 数组传参后用 sizeof 求元素个数。形参退化为指针，`sizeof(形参)` 是指针大小（64 位下 8 字节）；长度必须显式传参，或用素材 hw_code.cpp 的做法在 main 里算好再传（④对照坑 1）。

> **【易错】** 结构体数组整体初始化漏内层大括号。每个元素是一个结构体，应当 `{{...},{...}}`；漏写后编译器把值顺序填给第一个元素的所有成员（④对照坑 2）。

> **【注意】** typedef 数组别名的位置特殊：`typedef int arr[10];` 的 `arr` 代表"int[10] 数组类型"，写成 `typedef int[10] arr;` 是错的——别名夹在元素类型与元素个数之间（15.1 pdf p43 原话"别名被挤在……之间"）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 遍历循环零次，无输出（预期：空输出、不崩）。
> 2. 单元素：n=1 → 输出唯一元素各成员（预期：一次循环）。
> 3. 全相同：3 个元素完全同值 → 输出三份相同行（预期：无串扰，整体赋值正确）。
> 4. 严格递增：score 10、20、30 → 线性扫描可正确取最大 30（预期：max 逻辑成立）。
> 5. 严格递减：score 30、20、10 → 同上取 30，首元素即最大（预期：边界正确）。
> 6. 极值：`char suit[10]` 存 10 字符以上字符串 → 溢出改写相邻成员（素材用 char 数组，string 无此忧）；n 取数组上限时下标必须 < n（防越界 RE）。

回扣开场：一排柜子解决了"一批学生"的批量存取，现在你能把开场题扩展到"按总分输出全班"的数据组织了——下一节解决"隔着地址访问柜子"的最后一个基本功。

### 3. 点与箭头访问

前置依赖：[[#1. struct 定义与成员]]、指针基础（C 已掌握）
后续衔接：[[#4. 竞赛 cmp 比较器打包写法]]（cmp 的 const 引用形参本质是免拷贝的访问）、[[链表]]（结点全部靠箭头访问串起来）

**① 它解决什么问题**

结构体指针（15.1 pdf p13-16）是**存放结构体地址的指针**，解决"只有地址、没有变量名时如何访问成员"的问题：函数间传大结构体不想拷贝、结构体在数组/堆上、以及 [[链表]] 的结点互相只存地址。关键性质：变量用点 `.` 访问成员；指针用箭头 `->`；两者等价关系是 `p->member` 完全等价于 `(*p).member`。复杂度：取地址与解引用均 O(1)；传指针替代传值的收益 = 省掉整份结构体拷贝（成员多时是数量级差距，这是它存在的原因）。

**② 直觉理解**

模型级类比：**门牌号**。变量名 s1 是"档案袋上贴的名字"，指针 ps 是"写着档案柜地址的纸条"。拿纸条找袋子里的年龄：先按地址找到袋子（`*ps` 解引用）再看年龄，合并起来写就是 `(*ps).age`；因为"找袋子再看"太常用，C 语言给了个专门的记号"箭头"：`ps->age`。

用具体数字跑一遍（15.1 pdf p16 案例）：`student s1; student* ps1 = &s1; ps1->name = "诸葛亮"; (*ps1).age = 20;`——两行赋值落在**同一个袋子**上，输出 `ps1->name` 与 `(*ps1).age` 即"诸葛亮"和 20（素材 classcode.cpp 注释段同一案例，age 赋 29 同理）。

**③ 原理与推导**

推导两记号的等价性：`ps->age` 在编译期被翻译为"先解引用 ps，再取 age 成员"，与 `(*ps).age` 生成的访问序列相同，语义零差别——箭头纯粹是书写糖。为什么需要箭头这个新记号？因为 `*ps.age` 会先算 `.`（优先级高于 `*`），含义变成"ps 是个结构体、取它的 age、再解引用"——类型完全不对；不加括号的写法几乎总是错的，于是干脆发明一个不与优先级纠缠的记号。这是**设计动机**：`->` 的存在就是为了消灭 `(*)` 的括号负担（15.1 pdf p15 明确要求"必须使用 () 改变运算符优先级"）。

函数传参三种形态（pdf p20-23、classcode.cpp L18-30）：传值（拷贝整袋，函数内修改不影响原变量）、传指针（传地址，`ps->` 修改直达原变量，classcode.cpp 的 printStudent2）、传结构体数组（本质也是传首地址，printStudent3）。C 等价对照：`void f(student* ps) { ps->age = 1; }` ↔ C 写法完全相同——结构体指针是 C 原生特性，本节没有引入新语法糖；真正的 C++ 新增在知识点 4 的引用传参。

**④ 代码演示**

块一「核心代码」（取自素材 classcode.cpp 的指针段，改动：把注释掉的实验代码固化为一个可编译最小程序；函数定义与 `->` 用法逐行同源）：

```cpp
#include <iostream>
#include <string>
using namespace std;
struct student {
    string name;
    int age;
    double score;
};
void printStudent2(student* ps) {   // 传指针：免整袋拷贝
    ps->age = 29;                   // 箭头访问：直达原变量
    cout << ps->name << " " << ps->age << " "
         << (*ps).score << endl;    // 两记号等价演示
}
int main() {
    student s1 = {"李四", 20, 100};
    student* ps1 = &s1;             // 存 s1 的地址
    ps1->age = 29;
    cout << (*ps1).name << endl;    // 必须带括号
    printStudent2(ps1);             // 等价于 printStudent2(&s1)
    cout << s1.age << endl;         // 已被函数改为 29
    return 0;                       // 复杂度：解引用 O(1)；传指针省 O(整袋字节数) 拷贝
}
```

逐段讲：L14 `student* ps1 = &s1;`——类型是 `student*`，指向 student；L15 箭头赋值与 L16 括号解引用等价；L18 传 `&s1` 与传 ps1 完全相同（classcode.cpp L86-87 两行注释正是这对等价调用）。

块二「执行追踪表」（上面程序，s1 初始 {李四,20,100}）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | ps1 = &s1 | s1={李四,20,100} | 取地址入指针 | ps1 指向 s1 |
| 2 | ps1->age = 29 | s1={李四,29,100} | 箭头改成员 | s1.age 20→29 |
| 3 | (*ps1).name | 同上 | 括号解引用取成员 | 输出 李四 |
| 4 | 进入函数 | 同上 | 传指针不拷贝 | 函数内即 s1 本体 |
| 5 | ps->age = 29 | s1={李四,29,100} | 再改一次 | 值不变（已是 29） |
| 6 | 输出 s1.age | 同上 | 回到 main 验证 | 输出 29（修改直达） |

块三「错误写法对照」：

```diff
- cout << *ps1.age << endl;   // 坑1：漏括号——. 优先级高，先算 ps1.age（ps1 是指针没有成员），类型错误（CE）
+ cout << (*ps1).age << endl;   // 括号强制先解引用；或直接 ps1->age
- student* ps; ps->age = 1;   // 坑2：野指针解引用——ps 未指向任何变量，写入随机地址（RE）
+ student s1; student* ps = &s1; ps->age = 1;   // 先让指针有家可回
- void f(student s) { s.age = 29; } f(s1);   // 坑3：传值想改原变量——函数改的是拷贝，s1.age 不变（答案错）
+ void f(student* ps) { ps->age = 29; } f(&s1);   // 传地址才能写回
```

**⑤ 典型应用**

- 例题（cards.cpp）：洗牌与发牌函数签名全用 `CARD* card`——54 张牌每次拷贝几百字节到函数毫无必要，传地址是默认选择（作业原题 pdf p10 还要求"通过指针的方式实现"，正是本节）。
- 例题（15.1 pdf p22 案例）：`printStudent(student *s)` 打印三名学生，传 `&s1`。
- 迁移检验题（自编）：写函数 `void bump(student* ps)`，把传入学生的 age 加 1、score 加 5，main 中验证原变量确实变了。数据范围：age ≤ 100, score ≤ 100。建议先独立做，再对照题解：函数体内 `ps->age += 1; ps->score += 5;`，main 传 `&s`，输出改后两成员——本质是 classcode.cpp printStudent2 的改造版。

**⑥ 坑点与边界**

> **【易错】** `*p.m` 漏括号。`.` 优先级高于 `*`，语义变成"先取成员再解引用"，直接 CE；只要解引用整个指针就带括号，或一律用箭头（④对照坑 1）。

> **【易错】** 未初始化的指针直接 `->`。野指针指向随机地址，写入即未定义行为，轻则答案错重则 RE；指针定义后立刻赋地址（④对照坑 2）。

> **【注意】** 传值与传指针的选择标准：只读小结构（两三个 int）传值即可，代码更安全；成员多或要在函数内修改的一律传指针（本篇）或引用（知识点 4 的 cmp）——拷贝代价 = 每次调用复制全部成员。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：不创建任何指针 → 无行为（预期：无输出）。
> 2. 单元素：一个变量一个指针，读一次成员 → 输出与直读一致（预期：等价）。
> 3. 全相同：两个指针指向同一变量 → 两个指针读到的成员恒相同（预期：别名一致性）。
> 4. 严格递增：循环中 ps 依次指向 a[0..2] 并读 age → 输出三个递增值（预期：与下标访问一致）。
> 5. 严格递减：同上反向 → 输出递减（预期：一致）。
> 6. 极值：指针存地址本身无溢出问题；但要防"指针加 1 越过数组末尾后解引用"——ps 指向 a[n-1] 时不可再 ++ 后访问（防越界 RE）。

回扣开场：门牌号模型解决了"隔着地址改袋子"，现在你有了打包、批量、指针三件基本功——最后一节把它们组装成竞赛里出场率最高的套路：结构体排序。

### 4. 竞赛 cmp 比较器打包写法

前置依赖：[[#2. 结构体数组与 typedef]]、[[#3. 点与箭头访问]]、[[排序]]（排序与比较器的基本原理）
后续衔接：[[链表]]（按多关键字排序后建链）、堆的比较器版本（延伸，非必需）

**① 它解决什么问题**

竞赛里的排序对象几乎从不是裸 int，而是"一组带属性的记录"：按分数排学生、按矛盾值排仇怨、按右端点排区间。cmp 比较器就是**告诉 sort"什么算靠前"的函数**——`bool cmp(a, b)` 返回 true 表示 a 应排在 b 前面。打包写法三件套：`struct` 定义记录 → `cmp` 定义顺序 → `sort(a, a+n, cmp)` 一行完成。关键性质：sort 复杂度 $O(n \log n)$ 次比较，每次比较 O(1)（cmp 函数体），每次元素交换 O(成员字节数)；cmp 用 const 引用形参可把交换与比较的拷贝开销都压掉。为什么 cmp 形参要写引用？值传递每次比较拷贝两份完整结构体，$n=10^5$ 时多花两倍内存搬运时间，`const student&` 只传地址不改原值。

**② 直觉理解**

模型级类比：**裁判规则卡**。sort 是只会"两两比较"的赛会，cmp 是你递给它的规则卡："分数高者靠前"。赛会不需要懂学生，只反复问规则卡"这两个谁靠前"，问 $O(n \log n)$ 次后排完。规则卡写错（比如说不清"相等时谁靠前"），赛会行为未定义。

用具体数字跑一遍（实测 tr.cpp，附录 B-5）：4 名学生 zhao88、qian92、sun88、li95，cmp 为分数降序 `a.score > b.score`。sort 内层对短数组用插入排序，过程见④追踪表，终局 li 95、qian 92、zhao 88、sun 88。

**③ 原理与推导**

sort 的第三个参数接受"比较函数"，其调用约定：`cmp(x, y)` 为 true 当且仅当 x 排在 y 前。推导"降序为什么写 `a.score > b.score`"：排在前面的元素应当满足 cmp(它, 后面的) 为 true；分数大的在前，即 `大 > 小` 为 true，故返回大于号。**设计动机**：sort 不内置任何顺序，把"顺序"抽象成一个可替换的函数——裸数组、结构体、多关键字用同一个 sort，只换 cmp，接口复用最大化。

推导"cmp 必须满足严格弱序"：sort 的正确性建立在"如果 a 不在 b 前、b 不在 c 前，则 a 不在 c 前"这类传递假设上；若 cmp 对相等元素也返回 true（写成 `>=`），赛会会认为"a 在 b 前且 b 在 a 前"，内部指针交错后行为未定义，常见表现是越界 RE。结论：**相等必须返回 false**（等价元素不分先后），这正是④对照坑 1。

C 等价对照：`bool cmp(const student& a, const student& b)` 是 C++ 的**引用传参**，等价于 C 写法 `int cmp(const void* a, const void* b)` 里把指针转回类型再取成员——C 的 qsort 比较器每次收 void 指针还要自己转型，C++ 的 const 引用让"免拷贝 + 类型安全"一行写完。这是本篇最后一块新语法糖：`const T& x` ↔ C 的 `const T* px`（函数内用 `px->m` 访问，不改原值）。

**④ 代码演示**

块一「核心代码」（自编示例，cmp 骨架与 sort 调用对应素材 15.1 pdf 案例 1 的扩展；结构体定义同知识点 1）：

```cpp
#include <iostream>
#include <string>
#include <algorithm>          // sort 所在头文件
using namespace std;
struct student { string name; int age; double score; };
bool cmp(const student& a, const student& b) {   // const 引用：免拷贝且禁改
    return a.score > b.score;    // 分数降序：相等返回 false
}
int main() {
    student a[4] = {{"zhao",20,88},{"qian",19,92},
                    {"sun",21,88},{"li",18,95}};
    sort(a, a + 4, cmp);         // 区间 [a, a+4) 按规则卡重排
    for (int i = 0; i < 4; i++)
        cout << a[i].name << " " << a[i].score << endl;
    return 0;                    // 复杂度：O(n log n) 次比较 + 每次交换 O(成员字节数)
}
```

逐段讲：L6 形参写 `const student&`——`&` 免拷贝、`const` 保证 cmp 不改元素（sort 要求比较器只读）；L7 大于号即降序、小于号即升序；L11 传函数名 cmp（不带括号）作为规则卡。

块二「执行追踪表」（上面数据，cmp 为分数降序；sort 短数组阶段用插入排序，元素逐个左移到 cmp 为 false 为止）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | qian92 | [zhao88, qian92, sun88, li95] | cmp(qian,zhao)=92>88 为真 | qian 与 zhao 交换 |
| 2 | sun88 | [qian92, zhao88, sun88, li95] | cmp(sun,zhao)=88>88 为假 | sun 不动 |
| 3 | li95 | [qian92, zhao88, sun88, li95] | cmp(li,sun) 为真，交换；再与 zhao、qian 连换两次 | li 移到首位 |
| 4 | 收尾 | [li95, qian92, zhao88, sun88] | 全部满足 cmp | 排序完成 |

块三「错误写法对照」：

```diff
- bool cmp(student a, student b) { return a.score > b.score; }   // 坑1：值传参——每次比较拷贝两份结构体，n 大时明显变慢（TLE 风险）
+ bool cmp(const student& a, const student& b) { return a.score > b.score; }   // const 引用：免拷贝、禁修改
- bool cmp(const student& a, const student& b) { return a.score >= b.score; }   // 坑2：相等也返回 true——违反严格弱序，相等元素互相"在前"，sort 行为未定义（常见 RE）
+ return a.score > b.score;   // 相等返回 false：等价元素不分先后
- sort(a, a + n, cmp); 若 cmp 里写 return true; 恒真   // 坑3：cmp 与数据无关——所有元素"互在前"，同样违反严格弱序（RE 或输出乱序）
+ cmp 只依赖元素的成员值，且相等返回 false
```

**⑤ 典型应用**

- 例题（15.1 pdf p48-49 案例 1 扩展）：按总分从高到低输出全部学生——cmp 写 `a.total > b.total`，total 在读入时算好存进结构体，排序一行。开场"平行数组串位"的终局答案：打包 + 规则卡。
- 例题（cards.cpp 数据 + 本节 cmp）：54 张牌按花色字典序、同花色按点数升序——多关键字 cmp 先比第一键、不等即返回，相等再比第二键（多关键字 cmp 的标准形状）。
- 迁移检验题（自编）：n（n ≤ 10^5）名学生，姓名（不含空格 ≤ 10 字符）与分数（0~100），按分数降序输出；同分按姓名字典序升序。输入格式：第一行 n，后 n 行"姓名 分数"；输出格式：n 行"姓名 分数"。建议先独立做，再对照题解：cmp 先比 score（降序），相等时比 name（`a.name < b.name`），string 的 `<` 即字典序；`const student&` 传参防 TLE；总体 $O(n \log n)$。这条题同时是知识点 2、3、4 的合卷。

**⑥ 坑点与边界**

> **【易错】** cmp 写 `>=` 或 `<=`。相等元素"互相在前"破坏严格弱序，sort 内部越界，典型症状是段错误（RE）且随数据规模随机出现（④对照坑 2）。

> **【易错】** cmp 值传参。每对元素比较拷贝两份结构体，$10^5$ 个 100 字节的记录排序要多搬上百 MB 数据，常数膨胀直接 TLE；一律 `const T&`（④对照坑 1）。

> **【注意】** sort 是不稳定排序：同分元素的相对顺序不保证与输入一致；需要"同分按输入顺序"时在 cmp 里补第二关键字（如知识点 4⑤ 的姓名字典序），不要赌稳定性。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → sort 空区间合法（a+0, a+0），零次比较，无输出（预期：不崩）。
> 2. 单元素：n=1 → sort 一次比较都不需要，原样输出（预期：唯一元素）。
> 3. 全相同：4 条记录完全同值 → cmp 恒 false，不交换，输出顺序同输入（预期：幂等）。
> 4. 严格递增：score 60,70,80,90 输入 → 降序 cmp 排成 90,80,70,60（预期：完全反转）。
> 5. 严格递减：已降序输入 → 每次比较为 false，零交换（预期：原序输出）。
> 6. 极值：score = 2×10^9 存 int 溢出（上限约 2.1×10^9 贴线）→ 数据范围贴上限时用 long long 或改题目给定的 double；比较本身 O(1) 不受值大小影响（防溢出）。

回扣开场：现在你能解决开场那个平行数组串位的问题了——用的是知识点 1 的打包（数据成整体）、知识点 2 的数组（批量组织）与知识点 4 的 cmp（排序一行完成）。三件套组装完毕，竞赛里"读入一批记录、排序、输出"的题从此有了固定起手式。

| 4 | 结构体数组初始化漏内层大括号 | 每个元素一对 `{}` |
| 5 | typedef 数组别名位置写错 | `typedef int arr[10];` 别名夹在类型与个数之间 |
| 6 | `*p.m` 漏括号 | `(*p).m` 或直接 `p->m` |
| 7 | 野指针解引用 | 定义后立刻赋地址 |
| 8 | 传值函数想改原变量 | 传指针（`T*` + `->`）或引用 |

| 10 | cmp 值传参 | 一律 `const T&` 免拷贝 |
| 11 | 赌 sort 稳定性 | cmp 补第二关键字 |

## 四、总结与自测

### 核心内容（一页纸速览）

- **struct 定义与成员**：异构数据打包成新类型；成员用点访问；整体初始化按声明顺序；整体赋值逐成员复制、互不影响（15.1 pdf p5-10）。
- **结构体数组与 typedef**：数组元素可以是结构体，`s[i].m` 下标 + 点访问；typedef 给类型起别名，数组别名 `typedef int arr[10];`（pdf p17-19、p40-43；hw_code.cpp 嵌套 teacher/student）。
- **点与箭头**：变量用 `.`、指针用 `->`，`p->m` 等价 `(*p).m`；`*p.m` 漏括号必错；传指针免整袋拷贝且可写回（pdf p13-16、classcode.cpp）。
- **cmp 三件套**：`struct` + `bool cmp(const T& a, const T& b)` + `sort(a, a+n, cmp)`；大于号降序、小于号升序、相等必须 false；$O(n\log n)$ 次比较。
- **复杂度总账**：成员访问 O(1)、结构体数组下标 O(1)、整体赋值/交换 O(成员字节数)、排序 $O(n \log n)$。

## 五、语法糖对照表

| 语法 | 等价 C 写法 | 一句话用途 |
|------|------------|-----------|
| `student s1;`（省 struct） | `struct student s1;` | C++ 中类型名可直接当类型用 |
| `string name;` | `char name[20];` | 自动扩容字符串成员 |
| `student s1 = {...};` | `struct student s1 = {...};` | 整体初始化 |
| `int age{20};`（成员默认值） | C 无对应，靠 memset/初始化函数 | 每个变量自带初值 |
| `typedef student stu;` | `typedef struct student stu;` | C 里 typedef 后才能省 struct 关键字 |
| `void f(student* ps){ps->m;}` | 同 C（结构体指针是 C 原生特性） | 传地址访问与写回 |
| `bool cmp(const student& a, ...)` | `int cmp(const void* a, const void* b)` 转型取成员 | 引用传参：免拷贝且类型安全 |
| `sort(a, a+n, cmp)` | 手写 qsort / 插入排序 | 按规则卡排序 |
