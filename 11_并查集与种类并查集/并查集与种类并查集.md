## 一、为什么需要它

先用你大概率碰过壁的方式做一遍 P3367【模板】并查集：n 个人、m 条指令，`1 x y` 表示 x y 并成一群，`2 x y` 问 x y 是否同一群。暴力做法是给每个人记一个"群编号"，合并时把一群人的编号全部改掉——单次合并 $O(n)$，最坏 m 次合并就是 $O(nm)$；$n, m \le 10^5$ 时是 $10^{10}$ 量级，必超时。**碰壁的根源：合并的代价花在"改所有成员"上。**

并查集的破法只有一句话：**只记每个人的"上级"，合并时只改一个上级指针**。代价是"找代表"要顺着上级链爬，而路径压缩（知识点 2）把爬链的均摊代价压到几乎常数。这一加一减，$O(nm)$ 变 $O((n+m)\alpha(n))$，$\alpha$ 是增长慢到可以当常数看的反阿克曼函数。

本篇讲 4 个知识点：并查集是什么（三操作与树表示）、路径压缩、模板题 P3367、种类并查集与 P1525 关押罪犯。顺序理由：结构（知识点 1）先于优化（知识点 2），板子（知识点 3）先于变体（知识点 4）。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 并查集是什么：不相交集合的树表示

前置依赖：[[二叉树结构篇]]（树、根、森林的表示）、数组与递归（C 基础）
后续衔接：[[#2. 路径压缩：链退化与扁平化]]、[[#3. 模板题 P3367：合并与查询的板子]]

**① 它解决什么问题**

B 源 p1 定义：并查集处理**不相交集合**的合并与查询——"不相交"就是集合两两交集为空：{1, 3, 5} 与 {2, 4, 6} 交集为空，是不相交集合；{2, 3, 5} 与 {1, 3, 5} 共享 3、5，不是。使用时首先存在一组不相交的动态集合 $S = \{S_1, S_2, \ldots, S_k\}$，一般用一个整数表示集合中的一个元素。B 源给出三**性质**操作：1. 建立一个含 s 个单元集合的新并查集（makeSet）；2. 合并元素 x 与 y 所在的集合，要求两集合不相交（union）；3. 找到元素 x 所在集合的**代表**（find）——比较两个人的代表是否相同，就回答了"是否同一集合"。复杂度总账先给出：三操作在带路径压缩的实现里均摊几乎常数，一次合并 O(1) 次指针改动。

**② 直觉理解**

模型级类比：**公司拉群改汇报线**。每个员工只记一条信息——"我的汇报对象是谁"。两部门合并成一个大部门时，不需要通知所有人，只让一个部门的总经理改口"以后向对方总经理汇报"即可；查两个人是否同部门，各自顺着汇报线爬到顶，看顶上是不是同一个人。**顶（根）就是集合的代表**。

用具体数字跑一遍（B 源 p2 的例子）：两个集合 {a, b, c, d} 代表是 a（b、c、d 的父指针最终指向 a），{e, f, g} 代表是 e。现在把 e、f、g 并进前一个集合，代表仍是 a——合并只是"让 e 的父指针指向 a"一个动作，b、c、d、f、g 什么都不用动。

**③ 原理与推导**

树的表示（B 源 p1-p2）：每个结点是一个元素，**指针指向父结点，根结点的指针指向自己**，沿父指针不断向上找，最终到达的根就是代表元素。makeSet 做的就是构造一个森林：每个元素自成一个单元素集合，父结点（根）指向自身。

用数组落地的两种约定（A-3 冲突登记 1）：A 源 P3367 用**自指式**——`fa[i] = i` 表示 i 是根；B 源并查集代码.c 用**哨兵式**——`fa[i] = -1` 表示 i 是根。两者逻辑等价（实测同一组操作对拍输出一致，附录 B-5），竞赛主流是自指式（省去 -1 魔法值的特判心智），本篇正文以自指式为主线。

三操作的数组形态：makeSet 就是 `for (i=1..n) fa[i]=i`；find 是"沿父指针递归到根"；union 是"先 find 两个根 fx、fy，再 `fa[fx] = fy`"——**只改根的一个指针**。为什么合并必须找根再挂根？如果直接 `fa[x] = y`，x 的整棵子树会被整体拖到 y 下面，而 x 原来的同伴还留在旧树里，两棵树并没有真正合一——这是④的错误写法对照第一坑。

**④ 代码演示**

三操作的最小实现（自编骨架，取 A 源 P3367 的自指式约定）：

```cpp
int fa[200005];                       // fa[i]：i 的父结点；fa[i]==i 表示 i 是根
void makeSet(int n) {                 // makeSet：森林初始化
    for (int i = 1; i <= n; i++) fa[i] = i;
}
int find(int x) {                     // find：沿父指针爬到根（此处未压缩，见知识点 2）
    if (x == fa[x]) return x;
    else return find(fa[x]);
}
void unionSet(int x, int y) {         // union：根挂根，只改一个指针
    int fx = find(x), fy = find(y);
    if (fx != fy) fa[fx] = fy;        // 已同集合时不合并（B 源操作 2 要求不相交）
}
```

**执行追踪表**（B 源 p2 的合并序列 `(4,3), (3,2), (2,1)`，n=4，初始 fa[i]=i）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | union(4,3) | fa=[1,2,3,4] | fx=find(4)=4, fy=find(3)=3 | fa[4]=3 |
| 2 | union(3,2) | fa=[1,2,3,3] | fx=find(3)=3, fy=find(2)=2 | fa[3]=2 |
| 3 | union(2,1) | fa=[1,2,2,2] | fx=find(2)=2, fy=find(1)=1 | fa[2]=1 |
| 4 | find(4) | 链 4→3→2→1 | 爬 3 步到根 | 代表=1 |

**错误写法对照**（合并直接挂元素而非挂根）：

```diff
- void unionSet(int x, int y) { fa[x] = y; }   // 坑1：x 的子树整体被拖走，x 的旧同伴留在旧树，集合没有真正合一；查询 find(x) 的根也变成 y 树的根，连通性全错（答案错）
+ void unionSet(int x, int y) { int fx = find(x), fy = find(y); if (fx != fy) fa[fx] = fy; }   // 先找根再挂根，只动根指针
- void unionSet(int x, int y) { int fx = find(x), fy = find(y); fa[fx] = fy; }   // 坑2：漏掉同集合判断，fx==fy 时自挂自虽不崩，但把"合并"语义用在了已连通集合上，若题目统计集合个数会多减一次（答案错）
+ if (fx != fy) fa[fx] = fy;   // 同集合时什么都不做
```

**⑤ 典型应用**

- 真题：洛谷 P3367【模板】并查集（A 源 slide 1-2，"板子题"原话），知识点 3 全流程实战。
- 真题：B 源并查集代码.c 的同构练习（op=1 合并、op=2 查询输出 YES/NO），与 P3367 仅输出格式不同——板子一次写对，两种题面通吃。
- 迁移题：统计"朋友圈个数"——n 人 m 条朋友关系，问最终分几群。思路：makeSet 后每成功合并一次计数减 1（这也是为什么④对照里"漏判同集合"会错）。合并与查询的骨架完全复用本知识点。

**⑥ 坑点与边界**

> **【易错】** 合并写成 `fa[x] = y` 而不是挂根。后果不是崩溃而是**答案悄悄错**：子树被整体拖走、连通性断裂，见④对照第一坑。

> **【易错】** union 里漏 `if (fx != fy)` 判断。单次查询题无感，但"统计集合个数"类题会多数一次。

> **【注意】** 两种根的约定不能混用：自指式 `fa[i]=i` 与哨兵式 `fa[i]=-1` 的 find 终止条件分别是 `x==fa[x]` 与 `fa[x]==-1`，初始化也要配套；同一份代码里混写会死循环（fa[i] 既不是 i 也不是 -1，爬链永不停）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 且无操作 → makeSet 循环体零次执行，任何查询不存在，程序空转结束，无输出（预期：无输出、不崩溃）。
> 2. 单元素：n=1，查 `2 1 1` → find(1)==find(1)，输出 Y（自己和自己当然同群）。
> 3. 全相同：m 条指令全是 `1 1 1` → 每次fx==fy 均跳过合并，fa[1] 始终为 1（预期：结构无变化、不崩）。
> 4. 严格递增：不适用：并查集与键序无关（它只认"合并事件"，不认元素大小）。
> 5. 严格递减：不适用：理由同上。
> 6. 极值：n=10^5 全部串成一条链（fa[i]=i-1）后 find(10^5) → 未压缩版递归 10^5 层，有栈溢出风险——这正是知识点 2 的存在意义；另注意 fa 数组按题面 2n（种类并查集）开时 P3367 的 200005 与 P1525 的 40005 不可混用（数组开小 → RE）。

回扣开场：并查集把"改一群人"变成"改一个指针"，合并 O(1) 了，但 find 还在爬链——斜链一次爬到底，O(n)。现在你能回答"为什么合并便宜了"，接下来解决"查询为什么也能便宜"。

### 2. 路径压缩：链退化与扁平化

前置依赖：[[#1. 并查集是什么：不相交集合的树表示]]、递归（C 基础）
后续衔接：[[#3. 模板题 P3367：合并与查询的板子]]、[[栈与队列]]（非递归改写时用栈保序）

**① 它解决什么问题**

B 源 p3 给出问题：按 `(4,3), (3,2), (2,1)` 的顺序合并后得到链 4→3→2→1，"如果此时我们合并了一万个结点，查找的次数就非常多了"——最坏一次 find 爬 $O(n)$，m 次操作最坏 $O(nm)$，暴力碰壁换了个地方复现。**路径压缩**（B 源 p3-p4）的方案："在每次查找时，令查找路径上的每个节点都直接指向根节点"——爬一次的顺便，把整条链拍扁。复杂度结论：路径压缩后单次操作均摊 $O(\alpha(n))$（$\alpha$ 为反阿克曼函数，增长极慢，$n \le 10^{10}$ 时 $\alpha(n) \le 4$），全篇的总账 $O((n+m)\alpha(n))$ 由它兑现；$\alpha$ 的推导超出课件范围，作为延伸记录，不展开。

**② 直觉理解**

模型级类比：**公司裁撤中间层**。每次有人问路，就顺着汇报线走到顶；回来时顺手告诉沿途每个人："别一层层转达了，直接记总经理的名字。"问的人越多，汇报线越短，最终几乎人人都直连总经理。

用具体数字跑一遍（B 源 p4 的图）：链 4→3→2→1 上执行 find(4)——路径 {4, 3, 2}，压缩后 4、3、2 三个结点的父指针全部改指 1，链从 3 层变 1 层。下次再查 4，一步到位。

**③ 原理与推导**

实现只有一个字符的改动：递归版 find 里把 `return find(fa[x])` 改成 `return fa[x] = find(fa[x])`——先递归求根，回溯时**顺路把 fa[x] 改成根**再返回。推导"为什么是对的"：压缩只改父指针的指向，且新指向（根）与旧指向（祖先）属于同一集合——集合的 membership 不变，find 的返回值不变；而树高严格不增，后续 find 只会更快。A 源 P3367 源码把无压缩版注释保留在文件里（对照用），两版逐字对比如下，改动仅一处赋值：

推导"递归改成赋值后语义不变"：`fa[x] = find(fa[x])` 先求出子树的根 r，赋给 fa[x]，再返回 r——返回值与无压缩版相同；多出来的只是沿途的父指针改写。实测（附录 B-5）：链 4→3→2→1 压缩后 fa[4]==1、fa[3]==1，find 结果不变。

**④ 代码演示**

取自源文件 P3367.cpp（A 源，改动：仅摘 find 与其注释对照；main 见知识点 3）：

```cpp
int find(int x) {
    if (x == fa[x]) {
        return x;
    }
    else {
        return fa[x] = find(fa[x]);   // 压缩：回溯时顺路直指根
    }
}
/* 素材中同文件注释保留的无压缩对照版（O(n)）：
int find(int x) {
    if (x == fa[x]) return x;
    else return find(fa[x]);
} */
```

**执行追踪表**（链 4→3→2→1，即 fa[2]=1, fa[3]=2, fa[4]=3，执行 find(4)）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | x=4 | fa=[1,1,2,3] | 4 不是根，递归 find(fa[4]=3) | 挂起 |
| 2 | x=3 | 同上 | 3 不是根，递归 find(fa[3]=2) | 挂起 |
| 3 | x=2 | 同上 | 2 不是根，递归 find(fa[2]=1) | 挂起 |
| 4 | x=1 | 同上 | fa[1]==1，返回根 1 | 回溯开始 |
| 5 | 回到 x=2 | fa[2]=1 | fa[2] = 1，返回 1 | 2 直指根 |
| 6 | 回到 x=3 | fa=[1,1,1,3] | fa[3] = 1，返回 1 | 3 直指根 |
| 7 | 回到 x=4 | fa=[1,1,1,1] | fa[4] = 1，返回 1 | 链拍平，全直指根 |

**错误写法对照**（B 源并查集代码.c 里 Find1 的"引以为戒"迭代版，与递归压缩版的对照）：

```diff
- int Find1(int x) { int p = x; while (fa[p] != -1) p = fa[p]; return p; }   // 坑1：迭代找根但不压缩，B 源注释"引以为戒"——每次查询都从头爬链，最坏 O(n)（TLE）
+ int Find(int x) { if (fa[x] == -1) return x; int f = Find(fa[x]); fa[x] = f; return f; }   // B 源压缩版：递归回溯顺路改父指针
- return find(fa[x+1]);   // 坑2（虚构示意）：手滑写成 fa[x+1]，查的是下一个人，答案整体错位（答案错）
+ return fa[x] = find(fa[x]);   // 素材原式：先递归后赋值，两件事一个表达式
```

**⑤ 典型应用**

- 真题：P3367（知识点 3 全流程）——$n, m \le 10^5$，无压缩最坏 $O(nm)$ 超时，压缩后满分，是"压缩与否"差别最直观的板子。
- 真题：P1525 关押罪犯（知识点 4）——find 出现在排序后的每条边处理里，压缩直接决定总复杂度假格。
- 迁移题：把递归 find 改成迭代两趟版（第一趟找根，第二趟再走一遍改父指针）——思路相同，递归深度大的数据下防栈溢出（呼应结构篇非递归遍历的思想）。

**⑥ 坑点与边界**

> **【易错】** 压缩版写成先赋值再递归：`fa[x] = find(fa[x])` 求值顺序是"先调 find、后赋值"，若反过来写成 `int r = fa[x]; fa[x] = r;` 就什么也没压。认清它是一个表达式的两步：递归求根在前，赋值在后。

> **【易错】** 路径压缩没有副作用这个结论的前提是"只改父指针、不改集合语义"。若你在 fa 里同时维护了"集合大小"等附加信息，压缩改父指针时要把信息迁移规则一起想清楚（本篇不涉及，标注：延伸）。

> **【注意】** 递归 find 的栈深等于压缩前的链长；极端斜链 + 栈限制严的场合用迭代两趟版（⑤迁移题）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0，无 find 调用 → 无行为（预期：无输出）。
> 2. 单元素：n=1，find(1) → fa[1]==1 直接返回，压缩分支不触发（预期：返回 1，fa[1] 仍为 1）。
> 3. 全相同：fa[i]=1 对所有 i（已全压平）→ 任意 find 一步到位，再压缩无变化（预期：幂等）。
> 4. 严格递增：fa[i]=i-1 的链（1 为根）→ find(n) 爬 n-1 步，回溯把全链拍平（预期：第一次 O(n)，之后 O(1)）。
> 5. 严格递减：fa[i]=i+1 的链（n 为根）→ find(1) 同理，根是 n（预期：压缩后全直指 n）。
> 6. 极值：n=10^5 递减链 + 未压缩递归 find → 递归 10^5 层，默认栈（1MB 量级）下每层约几十字节，恰好贴线——竞赛里遇到大 n 斜链优先考虑迭代版（预期：不赌栈，防 RE）。

回扣开场：合并 O(1)、查询均摊 O(α(n))，暴力碰壁的两头都堵上了。现在你能用这把板子去接 P3367 的任意指令序列了——下一节把它按题面格式组装完整。

### 3. 模板题 P3367：合并与查询的板子

前置依赖：[[#1. 并查集是什么：不相交集合的树表示]]、[[#2. 路径压缩：链退化与扁平化]]

**① 它解决什么问题**

洛谷 P3367【模板】并查集（A 源 slide 1-2"板子题"）：n 个人 m 条指令，`1 x y` 合并 x y 所在集合，`2 x y` 查询 x y 是否同集合，同输出 `Y` 否则 `N`。它就是知识点 1、2 的直接组装：makeSet + 压缩 find + 分指令派发。数据 $n, m \le 10^5$，压缩后总复杂度 $O((n+m)\alpha(n))$ 轻松通过。

**② 直觉理解**

模型级类比：**客服工单分流**。指令 1 是"把两个工单组并成一组"（改一次汇报线），指令 2 是"这两个工单是不是一个组的"（两边各爬到顶对个名）。板子题的价值在把"派发-合并-查询"的回路跑顺，不留死角。

用具体数字跑一遍（官方样例 n=4, m=7）：`2 1 2` 查（1、2 各自成群）→ N；`1 1 2` 并；`2 1 2` 查 → Y；`1 3 4` 并；`2 1 4` 查（1、2 群与 3、4 群不同）→ N；`1 2 3` 并（两群合一）；`2 1 4` 查 → Y。输出 `N Y N Y`，与官方一致（附录 B-5）。

**③ 原理与推导**

main 的骨架只有三段：初始化 `fa[i]=i`；读指令按 z 派发；z==1 时 `fa[find(x)] = find(y)`（A 源原式，注释还标了备选方向 `fa[fy]=fx`——**为什么不直接挂元素**？推导见知识点 1③：子树会被整体拖走；方向选谁不影响正确性，只影响树的形状与谁当代表，对照见④）。z==2 时比较 find(x)、find(y)。推导"查询等价于比较根"：x、y 同集合当且仅当它们的根相同（根唯一确定集合），这是知识点 1 操作 3 的直接应用。

**④ 代码演示**

取自源文件 P3367.cpp（改动：仅删去文件头多余 include 与注释掉的旧版 find——已在知识点 2④ 完整保留对照；其余逻辑逐行原样）：

```cpp
#include <iostream>
using namespace std;
int fa[200005];
int find(int x) {
    if (x == fa[x]) return x;
    else return fa[x] = find(fa[x]);   // 路径压缩
}
int main() {
    int n, m, z, x, y, fx, fy;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) fa[i] = i;   // makeSet
    for (int i = 1; i <= m; i++) {
        cin >> z >> x >> y;
        if (z == 1) {                          // 合并
            fx = find(x); fy = find(y);
            fa[fx] = fy;                       // 根挂根（注释：fa[fy]=fx 方向亦正确）
        } else {                               // 查询
            fx = find(x); fy = find(y);
            if (fx == fy) cout << "Y\n";
            else cout << "N\n";
        }
    }
    return 0;
}
```

**执行追踪表**（官方样例，n=4；fa 初始 [1,2,3,4]，仅列结构状态的变化点）：

| 步骤 | 当前指令 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 2 1 2 | fa=[1,2,3,4] | find(1)=1, find(2)=2 | 输出 N |
| 2 | 1 1 2 | fa=[1,2,3,4]→fa[1]=2 | fa[find(1)]=find(2) | fa=[2,2,3,4] |
| 3 | 2 1 2 | fa=[2,2,3,4] | find(1)=2, find(2)=2 | 输出 Y |
| 4 | 1 3 4 | fa[3]=4 | 根 3 挂 4 | fa=[2,2,4,4] |
| 5 | 2 1 4 | 两群不同 | find(1)=2, find(4)=4 | 输出 N |
| 6 | 1 2 3 | fa[find(2)]=find(3) | fa[2]=4 | fa=[2,4,4,4] |
| 7 | 2 1 4 | 同群 | find(1)=4, find(4)=4 | 输出 Y |

**错误写法对照**：

```diff
- if (z == 1) fa[x] = y;   // 坑1：跳过 find 直接挂元素——子树拖走、连通性断（答案错），即知识点 1④ 第一坑在题面上的复现
+ int fx = find(x), fy = find(y); fa[fx] = fy;   // 先找根再挂根
- cin >> z >> x >> y; if (z == 1) { ... } else if (z == 2) { ... }   // 坑2：这题没问题，但若题面新增第三种指令而 else 分支兜底了所有非 1 指令，会把非法指令也当查询处理（答案错）——"else 当查询"成立的前提是题面保证只有两种指令（【注意】）
+ if (z == 1) { ... } else { ... }   // 本题两指令场景下 else 可用，但心里要清楚依赖了题面保证
- int fa[100005];   // 坑3（示意）：数组开成 n 的上限而忘了并查集扩域题要开 2n——本题恰好不用扩域，到知识点 4 就是 RE（数组开小 → RE）
+ int fa[200005];   // 素材原样：200005 > 2×10^5，为知识点 4 的扩域留足余量
```

**⑤ 典型应用**

- 真题：P3367 本题（板子）。题解即④：初始化、派发、挂根、比较根，实测官方样例输出 `N Y N Y`（附录 B-5）。
- 真题：B 源并查集代码.c 同构题（YES/NO 版）——把输出串换掉即可，实测与 A 版对拍一致（附录 B-5）。
- 迁移题：P3367 变式"合并时输出两群人数"——fa 之外再维护 size[]，合并时 `size[fy] += size[fx]`（提示：仅根上的值可信；呼应知识点 1④ 坑 2 的"漏判同集合"）。标注：自编，未提供源码。

**⑥ 坑点与边界**

> **【易错】** 数组大小照抄 P3367 的 200005 去做扩域题。P1525 需要 2n+1 个位置，n=40000 时 200005 够用纯属巧合，n 更大的题（如 2n=8×10^4）一旦套错模板常量就是 RE。数组大小永远从"这题 fa 要存多少个域"重新算。

> **【易错】** 查询输出忘换行或大小写错（`Y` vs `YES`）。P3367 是 `Y/N`，B 源同构题是 `YES/NO`——板子题的失分常不在算法在题面格式（审题决策卡第 5 问）。

> **【注意】** `fa[fx] = fy` 与 `fa[fy] = fx` 都对，但全篇要统一方向；一会左挂一会右挂不会错，只是让"代表是谁"不可预测，统计类题若假设了代表身份就会踩坑。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=1, m=0 → 初始化后无指令，无输出（预期：空输出，不崩）。
> 2. 单元素：n=1, 指令 `2 1 1` → 输出 Y（自己与自己同群）。
> 3. 全相同：m 条 `1 1 1` → 全部跳过合并（fx==fy），后续 `2 1 1` 仍 Y（预期：结构幂等）。
> 4. 严格递增：指令序列 `1 1 2 / 1 2 3 / 1 3 4` 顺次合并 → fa 变化 [1,1,3,4]→[1,1,3,4]→…链形增长，find 均摊仍近常数（预期：全部合并成功）。
> 5. 严格递减：`1 4 3 / 1 3 2 / 1 2 1` 逆序合并 → 等价于知识点 2 的链构造，压缩后拍平（预期：最终全群合一）。
> 6. 极值：n=10^5, m=10^5 交替 `1 i i+1` 与 `2 1 i` → 总操作 $O(n\alpha(n))$，实测级 10^5 规模瞬间完成；若误用未压缩 find 且指令构造成链，则 10^10 量级 TLE（预期：压缩版 AC，无压缩版超时）。

回扣开场：暴力"改群编号"的 $O(nm)$，被"一个指针 + 压缩"降到位。现在你能解决开场那个 P3367 了——用的是知识点 1 的挂根（步骤 2）与知识点 2 的压缩（让步骤 7 的查询一步到位）。

### 4. 种类并查集与 P1525 关押罪犯：扩域一倍

前置依赖：[[#3. 模板题 P3367：合并与查询的板子]]、贪心的排序（[[枚举与模拟]] 的复杂度意识）
后续衔接：[[图的概念存储与遍历]]（二分图染色与"矛盾图"视角，待产出，先文字锚定）

**① 它解决什么问题**

A 源 slide 3 原话引入："并查集能维护连通性、传递性，通俗地说，**亲戚的亲戚是亲戚**。然而当我们需要维护一些对立关系，比如**敌人的敌人是朋友**时，正常的并查集就很难满足我们的需求。这时，种类并查集（扩展域并查集）就诞生了。"它要解决的问题：关系有" friend / enemy "两种极性，且都要满足传递性。方案（slide 3）：**将原并查集扩大一倍规模，划分两个种类——[1, n] 表示朋友域，[n+1, 2n] 表示敌人域**。同域内合并仍是"是朋友"；跨域合并表达"是敌人"；靠传递性自动推出任意两人的关系；"某个元素到底属于哪个种类不清楚，因此两个种类都试试"。

复杂度与正确性总账：扩域后元素翻倍，find 仍 $O(\alpha(2n))$；P1525 另加排序 $O(m \log m)$，总复杂度 $O(m \log m)$——瓶颈在排序不在并查集。

**② 直觉理解**

模型级类比：**一人两个格子**。给每个人发两张卡片："本人卡"（朋友域）和"影子卡"（敌人域）。"x 和 y 是朋友"→ 两张本人卡钉一起；"x 和 y 是敌人"→ x 的本人卡与 y 的影子卡钉一起（同时 y 的本人卡与 x 的影子卡钉一起）。于是"x 的本人卡与 z 的本人卡钉在一起"读出来的就是"x 和 z 要么同一人、要么是共同的敌人"——**敌人的敌人是朋友**由卡片传递自动成立，不需要任何特判。

用具体数字跑一遍（自造三角形，P1525 规则 n=3）：矛盾 (1,2,10)、(2,3,9)、(1,3,8)。处理 (1,2)：f[find(1)]=find(2+3)=5，f[find(2)]=find(4)——1 的朋友域挂 2 的敌人域，2 的朋友域挂 1 的敌人域；处理 (2,3) 同理；处理 (1,3) 时 find(1) 与 find(3) 同根（都经敌人域传递归到一起）→ **输出当前矛盾值 8**（附录 B-5 实测 8）。三个人两两为敌不可能安放，最早爆炸的那条边（降序下即矛盾值最小的边）就是答案。

**③ 原理与推导**

P1525 关押罪犯题意：n 名罪犯、m 对仇怨各有矛盾值 c，两人同监狱则积累 c 的冲突；监狱数量不限，求**冲突的最大值最小化**。A 源 slide 5 思路："我们要尽可能让矛盾值大的罪犯在两个监狱里——矛盾值排序"（贪心），然后按"敌人的敌人就是朋友"用扩域并查集模拟分配。

推导贪心的正确性：矛盾值降序处理后，若处理到边 (x, y) 时 x、y 已被前面的决策逼进同一集合，则这条怨仇**无法再避开**（拆开它们需要违背更早、更大的矛盾约束），当前 c 就是"无法避开"中最小的——立即输出它即为最优。而尚未处理的边矛盾值都 ≤ 当前 c，不影响答案下界。归纳成立。

推导扩域合并的语义（A 源 slide 5 步骤 2）："看矛盾的两人 x、y 是否已同集合：同则输出；不同则把 **x 与 y 的其他敌人分在同一组，y 与 x 的其他敌人分在同一组**"——落到数组：`f[find(x)] = find(y+n)`（x 的朋友域挂到 y 的敌人域：x 与 y 是敌 → x 的朋友恰好是 y 的敌人）；`f[find(y)] = find(x+n)` 对称。两条合并各是"根挂根"，与知识点 1 同款。

**设计动机**：为什么不开"每种关系一个并查集"而是扩原并查集一倍？因为两种极性共享同一批元素、且要通过传递性互相推——独立的并查集之间没有传递通道，扩域把两种极性塞进同一个森林，让传递性自动工作。

**④ 代码演示**

取自源文件 P1525.cpp（改动：L30 乱码注释 `//??????` 按位置语义还原为 `// 初始化`——见 A-3 冲突登记 2；其余逻辑逐行原样）：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;
int f[40005];                       // 扩域：[1,n] 朋友域，[n+1,2n] 敌人域
struct crime { int a, b, c; } e[100005];
bool cmp(crime &x, crime &y) { return x.c > y.c; }   // 矛盾值降序
int find(int x) {
    if (x == f[x]) return x;
    else return f[x] = find(f[x]);  // 路径压缩
}
int main() {
    int n, m, fa, fb, fad, fbd;
    cin >> n >> m;
    for (int i = 1; i <= 2 * n; i++) f[i] = i;   // 初始化（素材注释乱码已按语义还原）
    for (int i = 1; i <= m; i++) cin >> e[i].a >> e[i].b >> e[i].c;
    sort(e + 1, e + m + 1, cmp);
    for (int i = 1; i <= m; i++) {
        fa = find(e[i].a);  fb = find(e[i].b);      // 朋友域根
        fad = find(e[i].a + n); fbd = find(e[i].b + n);   // 敌人域根
        if (fa == fb) { cout << e[i].c << endl; return 0; }   // 已同监狱：必爆，输出当前矛盾值
        f[fa] = fbd;   // x 的朋友域挂 y 的敌人域
        f[fb] = fad;   // y 的朋友域挂 x 的敌人域
    }
    cout << 0 << endl;   // 全部怨仇都可避开
    return 0;
}
```

**执行追踪表**（自造三角形 n=3：边 (1,2,10)、(2,3,9)、(1,3,8)，降序后处理顺序不变；f 初始 [1,2,3,4,5,6]）：

| 步骤 | 当前边 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | (1,2,10) | fa=1, fb=2, fad=4, fbd=5 | f[1]=5, f[2]=4 | 1 友域挂 2 敌域；2 友域挂 1 敌域 |
| 2 | (2,3,9) | fa=find(2)=4, fb=3, fad=find(5)=5, fbd=6 | f[4]=6, f[3]=5 | 2 友域根挂 3 敌域；3 友域挂 2 敌域 |
| 3 | (1,3,8) | fa=find(1)=5, fb=find(3)=5 | **fa==fb** | 输出 8，程序结束 |

**错误写法对照**：

```diff
- for (int i = 1; i <= n; i++) f[i] = i;   // 坑1：只初始化朋友域，[n+1,2n] 的敌人域全是 0——find 走到 0 结点，越界或死循环（RE）
+ for (int i = 1; i <= 2 * n; i++) f[i] = i;   // 素材原样：扩域两段都要自指
- sort(e + 1, e + m + 1, cmp);   // 坑2：忘排序（或 cmp 写成 x.c < y.c 升序）——贪心前提崩塌，输出的不是"最小化后的最大矛盾值"（答案错）
+ sort(e + 1, e + m + 1, cmp);   // cmp 必须降序：return x.c > y.c
- if (fa == fb) { cout << e[i].c << endl; }   // 坑3：输出后忘了 return 0，继续处理后续边可能再次触发输出（多输出 → WA）
+ if (fa == fb) { cout << e[i].c << endl; return 0; }   // 素材原样：输出即终止
- f[fa] = fbd; f[fb] = fad; f[fa] = fbd;   // 坑4（虚构示意）：只写一对合并漏了对称的另一对——"敌人的敌人"传递链断半边，样例可能侥幸全过、对抗数据必错（答案错）
+ f[fa] = fbd; f[fb] = fad;   // 两条合并缺一不可：x 友挂 y 敌 与 y 友挂 x 敌
```

**⑤ 典型应用**

- 真题：P1525 关押罪犯（A 源 slide 4-5 例题）。实测官方样例（n=4, m=6）输出 0——样例的仇怨图是可二分的偶圈，全部怨仇都能避开（附录 B-5）。
- 真题：种类并查集思想题"食物链"（NOI 2001，P2024）——三种关系环（吃/被吃/同类），扩域三倍，套路与本篇完全一致。标注：资料未覆盖，属补充，题号真实。
- 迁移题：给 P1525 加一问——输出两个监狱各自人数。提示：人数维护在根上（呼应知识点 3⑤），但注意只有朋友域的人数有意义。标注：自编。

**⑥ 坑点与边界**

> **【易错】** 初始化只做 [1, n]。敌人域 [n+1, 2n] 未初始化时 f 值为 0，find 一旦爬进去就是未定义行为——**必须 `for (i = 1; i <= 2n)`**（④对照坑 1）。

> **【易错】** 贪心排序方向写反。降序（大矛盾先处理）才能保证"第一次爆掉的就是最优答案"；升序处理时先爆的是小矛盾，直接把答案做错（④对照坑 2）。

> **【注意】** "fa==fb 就输出"里的 fa、fb 是**朋友域**的根；比较敌人域根是另一个判断（本题用不到，但食物链类三关系题会用到），两套根不要混着比较。另外 A 源 slide 3 的"两个种类都试试"体现在"两条对称合并都做"——漏一条传递就断（④对照坑 4）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：m=0 → 排序空区间、主循环零次，输出 0（预期：无冲突，答案 0）。
> 2. 单元素：n=1, m=0 → 同上输出 0；n=1 且 m=1 的边 (1,1,c) 自怨——fa==fb 直接输出 c（预期：自己与自己对峙，c 即答案，题面通常保证 a≠b）。
> 3. 全相同：m 条同值矛盾边 → 降序后顺序任意，第一条爆边输出该值（预期：确定性不变）。
> 4. 严格递增：矛盾值 1..m 递增输入 → 排序后逆序处理，第一条（最大值）若成仇即直接输出最大值（预期：理解"降序"的意义）。
> 5. 严格递减：已降序输入 → sort 稳定无重排，直接处理（预期：与手推一致）。
> 6. 极值：矛盾值 c=10^9（题面 1e9 内）→ int 可存（2.1e9 上限），但若题改求"矛盾值之和"则 10^5 条 1e9 相加必爆 int——sum 必须 long long（防溢出模式 3）；另 n=2×10^4 时数组需 4×10^4+1，素材 40005 恰好贴线，套用其他题面要重算（预期：防数组开小 RE）。

回扣开场：P3367 教会板子，P1525 教会"板子不够用时扩域"——亲戚的亲戚是亲戚（连通性传递），敌人的敌人是朋友（对立关系传递），一个森林装下两种极性。现在你能解决开场那个"暴力改群编号"的问题，也能处理带极性关系的分配问题了。

## 四、总结与自测

### 核心内容（一页纸速览）

- **并查集**：不相交集合的合并与查询；树表示——每人只记父指针，根=代表、根自指（A 源）或 -1（B 源）；三操作 makeSet / union（根挂根）/ find（爬到根）。
- **路径压缩**：`return fa[x] = find(fa[x])`——回溯顺路直指根；均摊 $O(\alpha(n))$；无压缩对照版 O(n)（B 源"引以为戒"）。
- **P3367 板子**：makeSet + 压缩 find + 指令派发；查询 = 比较两根；官方样例 `N Y N Y`。
- **种类并查集**：扩域一倍，[1,n] 朋友域、[n+1,2n] 敌人域；敌人合并 = 交叉挂（f[fa]=fbd, f[fb]=fad）；传递性自动推出"敌人的敌人是朋友"。
- **P1525 关押罪犯**：矛盾值降序贪心 + 扩域并查集；朋友域同根即爆，输出当前矛盾值；全处理完输出 0；总复杂度 $O(m \log m)$。
- **素材两版根约定等价**（实测对拍一致）；竞赛用自指式。
