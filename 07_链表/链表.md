## 一、为什么需要它

先看一段再熟悉不过的操作：在数组中间插一个数。`{1, 2, 4, 5, 6, 7}` 要在第 3 个位置插入 3——后面每个元素都得整体后移一位；删一个数则整体前移一位。一次插删 $O(n)$，竞赛里"边插边维护"的场景下就是 $O(n^2)$，$10^5$ 的数据量直接出局。根子在于**数组的物理连续性**：元素挨着存放，动一个就得挪一片。

但换一种存法呢？每个元素带上"下一个元素在哪"的指针，物理上散落各处、逻辑上环环相扣——插入删除只改两个指针，$O(1)$ 搞定。代价是失去随机访问能力（想知道第 i 个是谁，只能从头数）。**链表**与**顺序表**是线性表的两大存储形态，本篇把两者放在一起讲透"为什么、是什么、怎么用"，再以力扣三道题（反转链表、倒数第 k 个、跳表设计）收尾。

本篇讲 7 个知识点：顺序表、单链表与头结点、单链表基本操作、双链表与循环链表、反转链表、快慢指针、静态链表与跳表。前四个是结构与操作（B 源数据结构课），后三个是竞赛技巧（A 源集训课）；顺序理由：不熟"带头结点"的约定（知识点 2）就看不懂竞赛代码为什么直接用 `head`（知识点 5），不掌握基本操作的指针改写（知识点 3）就推不动反转的指针交换（知识点 5）。

## 二、知识点逐讲（每个知识点一节，共 7 节）

### 1. 顺序表：连续存储与搬移代价

前置依赖：数组与下标、结构体与指针（纯基础概念，本库无对应笔记；主题链前站为 [[单调栈]]）
后续衔接：[[#2. 单链表与头结点：两套约定的统一]]（线性表另一存储形态）、[[#7. 静态链表与跳表：数组的另一种打开方式]]（连续内存跑链式逻辑）

**① 它解决什么问题**

**顺序表**是"以数组形式保存的线性表"（B 源 PDF 第 1 页原话）——一段地址连续的存储单元依次存放数据元素。它解决"按位置快速存取"的问题：支持下标随机访问 $O(1)$。性质：访问 $O(1)$；插入与删除因需整体搬移为 $O(n)$；长度固定（动态扩容需整体复制）。

| 操作 | 复杂度 | 前提 | 代价来源 |
|------|--------|------|---------|
| 按下标访问 | $O(1)$ | 无 | 地址 = 首址 + i × 元素大小 |
| 末尾追加 | 均摊 $O(1)$ | 未满 | 无搬移 |
| 按位插入 / 删除 | $O(n)$ | 无 | 后续元素整体后移 / 前移 |
| 扩容（复制到新数组） | $O(n)$ | 满且要再加 | 整体 copy（B 源第 4 页） |

**② 直觉理解**

模型级类比：**电影院连座**。一排座位上坐了一排人，中间来一个新人，从他往后所有人都得挪一个座位——挪动人数与"他后面坐了多少人"成正比；坐最后一排末尾（尾插）则谁也不用挪。数组元素的搬移量只取决于插入点后面的元素个数，与前面无关。

用具体数字跑一遍（B 源第 3 页例）：`{1, 2, 4, 5, 6, 7}` 在下标 2 处插 3——**倒着**搬移：7 从下标 5 挪到 6，6 从 4 到 5，5 从 3 到 4，4 从 2 到 3，腾出下标 2，放入 3，得 `{1, 2, 3, 4, 5, 6, 7}`。为什么必须倒着？正着搬会把后面的元素**覆盖丢失**（4 挪到下标 3 的同时，原下标 3 的 5 还没搬走就被 4 踩了）——源码注释里专门标注这是"典型的错误"。

**③ 原理与推导**

删除的复杂度为什么是 $O(n)$（不跳步）：删除下标 i 的元素，需把下标 $i+1 \dots s-1$ 逐个前移，移动次数为 $s-1-i$。最好情况（删尾）移动 0 次 $O(1)$；最坏情况（删头）移动 $s-1$ 次 $O(n)$。复杂度按**最坏情况**计——B 源第 2 页把这句写作"分析最快情况"，按上下文（"最坏……才有意义"）应为**最坏情况**之笔误，本篇按最坏口径讲解（已登记 A-3）。插入对称：先倒序腾位再写入，移动次数 $s-i$，同为 $O(n)$。

设计动机：为什么插入要"腾位"、删除要"补位"？连续性的硬约束——任意时刻数组必须保持"元素从下标 0 起无空洞"的状态，否则随机访问公式失效。一切搬移都是为维护这条不变量。

**④ 代码演示**

取自源文件 顺序表代码.c（相对源文件的改动：摘取核心操作、去交互 main；`Delet` 保留源码拼写）：

```cpp
#include <cstdio>
#include <cstdlib>
#define maxx 20
typedef struct ArrayList { int* data; int s; } Array;

void Insert(Array *a, int i, int k) {
    if (a->s == maxx) { printf("数组已满\n"); return; }
    for (int j = a->s - 1; j >= i; j--)   // 倒着枚举移动（正着会覆盖）
        a->data[j + 1] = a->data[j];
    a->data[i] = k;
    a->s++;                                // 复杂度：O(n)
}
void Delet(Array *a, int k) {
    int i = -1;
    for (int j = 0; j < a->s; j++) if (a->data[j] == k) { i = j; break; }
    if (i == -1) { printf("%d不存在,无法删除\n", k); return; }
    for (int j = i + 1; j <= a->s - 1; j++) a->data[j - 1] = a->data[j];  // 前移补位
    a->s--;                                // 复杂度：O(n)
}
```

// 边界：插入前判满（a->s == maxx）、删除前判存在；Add 尾插无搬移 O(1)
// 相对源文件：Find 合并进 Delet 内联，逻辑一致

**执行追踪表**（数据取自②：{1, 2, 4, 5, 6, 7} 在下标 2 插入 3，倒序搬移）

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|------|---------|---------|------|------|
| 1 | - | [1, 2, 4, 5, 6, 7]，s=6 | 判满：s < maxx 通过 | 开始倒序搬移 |
| 2 | 7 | j=5，待挪 | data[6] = data[5] | 7 挪到下标 6 |
| 3 | 6 | j=4，待挪 | data[5] = data[4] | 6 挪到下标 5 |
| 4 | 5 | j=3，待挪 | data[4] = data[3] | 5 挪到下标 4 |
| 5 | 4 | j=2，待挪 | data[3] = data[2] | 4 挪到下标 3，腾出下标 2 |
| 6 | 3 | 下标 2 已空 | data[2] = 3，s++ | 得 {1, 2, 3, 4, 5, 6, 7}，s=7 |

**错误写法对照**

```diff
- for (int j = i; j < a->s - 1; j++) a->data[j + 1] = a->data[j];  // 坑1：正着搬移 → 4 踩掉未搬走的 5，后面元素被覆盖丢失 → 答案错
+ for (int j = a->s - 1; j >= i; j--) a->data[j + 1] = a->data[j];  // 修复：倒着枚举，从尾部往插入点搬
- a->s--;  // 坑2：删除只减 size 不搬移 → 中间留空洞，随机访问读到脏数据 → 答案错
+ for (int j = i + 1; j <= a->s - 1; j++) a->data[j - 1] = a->data[j]; a->s--;  // 修复：前移补位，维持"无空洞"不变量
- a->data[i] = k;  // 坑3：忘判满就插入 → 越界写坏相邻内存 → RE
+ if (a->s == maxx) { printf("数组已满\n"); return; }  // 修复：插入类操作先查 s == maxx
```

**⑤ 典型应用**

- 洛谷 B3545 / 教材例题：顺序表增删查改演示（源码 main：Add 五次 → Insert 两次 → Find → Delet，实测输出 `{1 8 2 7 0}` → 下标 1 插 3、下标 3 插 5 得 `{1 3 8 5 2 7 0}` → 查 7 得下标 5 → 删 8 得 `{1 3 5 2 7 0}`）。
- 竞赛语境：绝大多数题直接用原生数组或 `vector`（`push_back` 即尾插，`insert`/`erase` 即本节操作 $O(n)$）。
- 自编迁移题（自编）：长度为 s 的顺序表，"把所有值为 x 的元素删掉"若对每个 x 独立调用 Delet，最坏多少次移动？能否一趟 $O(n)$ 解决？建议先独立做，再对照题解。

  题解：最坏 $O(n^2)$（n 个 x 挨个删，每次搬一半）。一趟双指针：写指针 w 慢、读指针 r 快，`a[r] != x` 时 `a[w++] = a[r]`——非 x 元素整体"压实"，0 次多余搬移。这道题是顺序表与尺取法（前一主题）的交汇点。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 插入正着搬移 → 后面元素被覆盖丢失 → 倒着枚举（从尾部往插入点搬）。

> [!caution]
> **【易错】** 删除只减 size 不搬移 → 中间留空洞，随机访问读到脏数据 → 前移补位维持连续性不变量。

> [!caution]
> **【易错】** 忘判满就插入 → 越界写坏相邻内存 → 插入类操作先查 `s == maxx`。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空表（s=0）在下标 0 插入 5 → 正常写入，得 [5]，s=1（插入不依赖已有元素，判满即过）
> 2. 单元素：[7] 删 7 → 找到 i=0，无搬移，s=0 得空表；随后再删 7 → 打印"7不存在,无法删除"
> 3. 全相同：[3, 3, 3] 删 3 → 只删第一个 3（查找命中即 break），得 [3, 3]；删净需循环调用
> 4. 严格递增：[1, 2, 3] 在下标 1 插 99 → 得 [1, 99, 2, 3]（本节 Insert 不管有序性，按位直插）
> 5. 严格递减：不适用：顺序表插删与输入有序性无关，行为与上条对称
> 6. 极值：s 已满（s == maxx）时插入 INT_MAX → 打印"数组已满"不写入；若去掉判满，写入 data[maxx] 越界——这正是极值下标溢出点

数据范围与边界：`maxx` 编译期固定，竞赛按数据范围开够；动态扩容要整体复制 $O(n)$，能预估就一次开足。结论失效条件：元素本身很大（结构体）时搬移代价不止 $O(n)$ 次赋值，常改为存下标或指针。收尾回扣：开场那个 $O(n^2)$ 的插删之痛，根源就是"物理连续、动一挪一"——下一节把连续性这个枷锁卸掉。

### 2. 单链表与头结点：两套约定的统一

前置依赖：[[#1. 顺序表：连续存储与搬移代价]]（对照两种存储形态）
后续衔接：[[#3. 单链表基本操作：查找、插入、删除]]、[[#5. 反转链表（LC206）：双指针迭代]]（竞赛段判空约定的来源）

**① 它解决什么问题**

**单链表**：每个节点只含一个指针域（指向后继）的链表。它解决顺序表"插删要搬移"的问题：节点在内存中任意摆放，逻辑相邻靠指针维系，插删只改指针 $O(1)$（找到位置后）。性质：访问第 i 个必须从头数 $O(n)$；大小不固定（按需 malloc）；物理不连续、逻辑连续（B 源第 4 页）。

| 术语（B 源第 5 页） | 含义 | 备注 |
|--------------------|------|------|
| 头指针 | 指向链表第一个存储位置的指针 | 链表的"入口"，有头结点时指向头结点 |
| 头结点 | 不存数据的第一个节点（有时存表长做监视） | 带头结点约定才有 |
| 首元结点 | 存放第一个数据元素的节点 | 查找必须从它开始（头结点数据域是脏数据） |

**② 直觉理解**

模型级类比：**寻宝游戏**。顺序表是"会议室点名"——知道房间号直接找人；链表是"藏宝图接力"——每张纸条写着下一条线索在哪，想找第 5 条线索必须从第 1 条挨个翻。**头结点**则是游戏起点前多设的一个"集散点"：它不藏宝，但所有操作都从它出发，哪怕"往空游戏里放第一张纸条"和"往已有游戏里加一张"变成同一个动作。

用具体数字跑一遍（头插法 vs 尾插法，源码 main）：对空表依次头插 6, 7, 1, 8——每次新节点都插在头结点后面，得到 `8 1 7 6`，**与插入顺序相反**（B 源注释原话"链表结点顺序与插入顺序相反"）；改为尾插同样数据得 `6 7 1 8`，顺序一致但每次都要找尾。

**③ 原理与推导**

为什么头结点值得存在（不跳步）：不带头结点时，"在第一个节点前插入"要改头指针本身——`head = 新节点`，与"在中间插入"（改前驱的 next）是**两种不同的操作**，空表、非空表又要分别处理（B 源第 6 页图示）。带头结点后，任何插入都是"改某个前驱的 next"，第 1 个节点的前驱就是头结点——**空表、非空表、首元结点统一处理**（B 源第 7 页结论）。代价：一个多余节点的空间。

设计动机：竞赛代码为什么常常不带头结点？A 源两份例题（LC206 / LCR140）直接 `head` 指首元——力扣接口给定不带头结点的链表，且算法题往往"建表一次、只读改局部"，省掉头结点更简洁。两套约定都对，但**不可混写**：传给函数的到底是头结点还是首元，判空条件一个是 `L->next == NULL` 一个是 `head == NULL`，混了就错。本篇竞赛段（知识点 5、6）跟随 A 源用不带头约定，结构段（知识点 2、3、4）跟随 B 源用带头约定。

**④ 代码演示**

节点定义与建表（相对源文件的改动：合并 A 源力扣风格与 B 源教学风格两套定义，注释注明各自归属）：

```cpp
struct Node {                 // B 源：typedef struct Node {...}Node,*LinkList;
    int data;
    struct Node* next;
};                            // A 源力扣版：struct ListNode { int val; ListNode* next; };

Node* InitLink() {            // 建头结点；复杂度 O(1)
    Node* head = (Node*)malloc(sizeof(Node));
    head->next = NULL;        // 源码注释：局部变量版是野指针陷阱，必须 malloc
    return head;
}
LinkList Head_insert(LinkList L, int k) {   // 头插：O(1)
    Node* s = (Node*)malloc(sizeof(Node));
    s->data = k;
    s->next = L->next;        // 先接后断：s 接住原首元
    L->next = s;              // 头结点指向 s（顺序反了会丢链）
    return L;
}
LinkList Rear_insert(LinkList L, int k) {   // 尾插：找尾 O(n)
    Node* s = (Node*)malloc(sizeof(Node));
    s->data = k;
    Node* p = L;
    while (p->next != NULL) p = p->next;    // 找到尾结点
    s->next = p->next;
    p->next = s;
    return L;
}
```

// 边界：头插两行不可对调（对调后 L->next 被覆盖，原链丢失）
// 竞赛建表常"尾插 + 记尾指针 r"（A 源例题写法）：r->next=s; r=s;，建表降为 O(n) 总量

**错误写法对照**

```diff
- L->next = s; s->next = L->next;  // 坑1：先断后接 → s->next 指向自己，原链整条丢失 → 答案错
+ s->next = L->next; L->next = s;  // 修复：口诀"先接后断"
- Node* p = L; while (p != NULL && p->data == x) p = p->next;  // 坑2：从头结点起比数据 → 头结点数据域是脏数据 → 查找结果错
+ Node* p = L->next; while (p != NULL && p->data == x) p = p->next;  // 修复：永远从首元 L->next 起查
- Node head; head.next = NULL; return &head;  // 坑3：头结点用局部变量 → 函数返回后栈上内存回收 → 野指针 RE
+ Node* head = (Node*)malloc(sizeof(Node)); head->next = NULL; return head;  // 修复：必须 malloc 堆上分配
```

**⑤ 典型应用**

- B 源教材例题：带头结点单链表的建表演示（头插 6,7,1,8 → `8 1 7 6`；再尾插 4,9,10 → `8 1 7 6 4 9 10`，实测吻合）。
- 力扣 LC206 / LCR 140（力扣）：竞赛约定的不带头结点链表（知识点 5、6 主讲）。
- 自编迁移题（自编）：用"尾插 + 尾指针"方式读入 n 个数建表，说明为什么总时间 $O(n)$ 而朴素尾插是 $O(n^2)$。建议先独立做，再对照题解。

  题解：朴素尾插每次都从头发一遍，第 i 次走 i 步，总量 $1+2+\cdots+n = O(n^2)$；记尾指针 r 后每次直接 `r->next = s; r = s;` 两步 $O(1)$，总量 $O(n)$。这正是"空间换时间"的微缩版——多存一个指针，省掉重复找尾。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 头插时先写 `L->next = s` 再取 `L->next` → 原链整条丢失 → 口诀"先接后断"。

> [!caution]
> **【易错】** 查找从头结点开始比数据 → 头结点数据域是脏数据（源码注释原话）→ 永远从首元 `L->next` 起查。

> [!caution]
> **【易错】** 头结点用局部变量 `Node head; return &head;` → 栈上变量函数返回后回收，野指针 → 必须 malloc（源码注释专门标注的陷阱）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：InitLink 后头结点 next=NULL → 判空 L->next == NULL 成立；对空表头插 6 → 6 成为首元，链为 6
> 2. 单元素：对 [8] 头插 6 → 得 6 8（头插"与插入顺序相反"的最小验证）
> 3. 全相同：依次头插 5, 5, 5 → 得 5 5 5；Find(5) 返回首个 5 的地址（最靠近头结点者）
> 4. 严格递增：依次头插 1, 2, 3 → 得 3 2 1（递增输入被头插反转为递减输出）
> 5. 严格递减：依次头插 3, 2, 1 → 得 1 2 3（递减输入被反转为递增输出）
> 6. 极值：数据域存 INT_MAX（2147483647）→ 建表与遍历正常，int 域可存；本节无算术运算，溢出风险不在数值而在野指针（坑 3 的 malloc 纪律）

数据范围与边界：malloc 返回值判空在竞赛可省（源码注释掉了），工程上必须查。结论失效条件：需要频繁按位访问的场景（第 i 个是谁）链表退化为 $O(n)$，该用顺序表。收尾回扣：现在你知道"卸掉物理连续的枷锁"具体长什么样了——但指针维系的结构，一个写错就断链。下一节把增删查改的指针改写逐个钉死。

### 3. 单链表基本操作：查找、插入、删除

前置依赖：[[#2. 单链表与头结点：两套约定的统一]]（带头结点约定与建表原语）
后续衔接：[[#4. 双链表与循环链表：用指针买能力]]（卸掉"找前驱"负担）、[[#5. 反转链表（LC206）：双指针迭代]]（指针改写是反转的语言）

**① 它解决什么问题**

在带头结点单链表上实现三件套：查找（返回数据 x 所在节点地址或 NULL）、指定插入（x 后插 k）、删除（删数据 k 的节点）。它们共同回答一个问题：**没有下标，怎么安全地改指针？** 性质：查找 $O(n)$；找到位置后插删本体 $O(1)$；删除需要前驱——这是单链表操作的全部难点来源。

| 操作 | 前置条件 | 本体动作 | 复杂度 |
|------|---------|---------|--------|
| Find | 从首元起 | 逐个比较 | $O(n)$ |
| Insert（x 后插） | 拿到 x 的节点 p | 两行指针改写 | $O(1)$ 本体 |
| Delete | 拿到 k 的节点 p **及其前驱 q** | 绕过 p + free | $O(1)$ 本体 |

**② 直觉理解**

继续寻宝模型：插入是把新纸条"塞进"两条线索之间（新纸条先抄下下一条线索的位置，再让前一条指向它）；删除是把某张纸条抽走，但它上面记着"下一条在哪"——所以必须**先让它前一张纸条直接抄下下一条的位置**，再抽走。单链表的每个操作都是"线索改写"，而**前一张纸条**是改写发生的地方——这就是删除为什么一定要找到前驱。

用具体数字跑一遍（源码 main）：建表 `8 1 7 6 4 9 10` 后 `Insert(6, 19)`——Find 定位到 6，s 接住 19 的 next 指向 4，6 的 next 改指 19，得 `8 1 7 6 19 4 9 10`；`Delete(4)`——p 停在 4、q 停在 19（前驱），q 绕过 p 指向 12 插入后的 9？不对，此时序列是 `8 1 7 6 19 4 12 9 10`（两次插入后），q 停在 4 的前驱 19，`q->next = p->next` 后 4 被绕过，`free(p)`，得 `8 1 7 6 19 12 9 10`（实测吻合）。

**③ 原理与推导**

删除为什么必须前驱（不跳步）：单链表节点只有一个 next，站在 p 上无法回头改 p 的前驱。绕过 p 的动作是 `q->next = p->next`——改的是 **q** 的指针域。找不到 q 就无从下笔，只能从头带一个"尾巴指针"同步走。对比：双链表（知识点 4）节点自带 pre，删除可以不要 q——这是 pre 域用空间买来的能力。

循环条件的短路顺序（源码注释隐含的教学点）：`while (p != NULL && p->data != x)` 中判空**必须**写在比较之前——`&&` 短路求值保证 p 为 NULL 时不解引用 `p->data`；写反了空链表直接 RE。循环停止有两种可能（源码注释逐条列出）：p 为空（x 不存在）或 `p->data == x`（找到了），返回前必须区分。

设计动机：为什么删除源码给了两个版本（注释版用 q 找"下一个是否为 k"，正式版 p/q 同步走）？前者逻辑是"盯着 q->next 判断"，后者是"p 走 q 跟"。两者等价，但 p/q 同步走与"找前驱"的心智模型直接对应，且删除/反转/快慢指针共用这个骨架——保留它作为标准形。

**④ 代码演示**

```cpp
Node* Find(LinkList L, int x) {          // 复杂度 O(n)
    Node* p = L->next;                   // 从首元开始（脏数据警告见知识点 2）
    while (p != NULL && p->data != x) p = p->next;   // 判空在前（短路保护）
    return p;                            // NULL 表示不存在
}
LinkList Delete(LinkList L, int k) {     // 复杂度 O(n)（找前驱），本体 O(1)
    Node* p = L->next;                   // 工作指针
    Node* q = L;                         // 前驱跟随
    while (p != NULL && p->data != k) { p = p->next; q = q->next; }
    if (p == NULL) { printf("%d不存在,无法删除\n", k); return L; }
    q->next = p->next;                   // 绕过 p
    free(p);
    p = NULL;                            // 源码注释：防止 p 成为野指针
    return L;
}
```

// 相对源文件：仅合并排版，逻辑一致（源码另有"盯 q->next"注释版，等价）
// 边界：删首元时 q 恰为头结点，q->next 改写天然成立——头结点统一性（知识点 2③）的兑现

**执行追踪表**（数据取自②：建表 8→1→7→6→4→9→10 后 Insert(6, 19) 与 Delete(4)，含两次插入后的完整序列）

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|------|---------|---------|------|------|
| 1 | 6 | 链 8→1→7→6→4→9→10 | Find 定位 x=6，p 从首元逐个比较 | p 停在节点 6 |
| 2 | 19 | 新节点 s，s->data=19 | s->next = p->next（先接） | 19 接住 4 |
| 3 | 19 | | p->next = s（后断） | 链变 8→1→7→6→19→4→9→10 |
| 4 | 4 | 再 Insert(4, 12) 后链 8→1→7→6→19→4→12→9→10 | Delete(4)：p=L->next、q=L | p/q 从头同步走 |
| 5 | 8, 1, 7, 6 | p->data != 4 | p=p->next，q=q->next | p 停在 4，q 停在前驱 19 |
| 6 | 4 | p 指向 4 | q->next = p->next | 19 直接指向 12，4 被绕过 |
| 7 | 4 | | free(p)，p=NULL | 得 8→1→7→6→19→12→9→10，删除完成 |

**错误写法对照**

```diff
- while (p->data != k) { p = p->next; q = q->next; }  // 坑1：判空写在比较之后 → 空链表解引用 NULL → RE
+ while (p != NULL && p->data != k) { p = p->next; q = q->next; }  // 修复：p != NULL && 永远放前面（短路保护）
- free(p);  // 坑2：只 free 不接链 → 后半条链整段丢失 → 答案错
+ q->next = p->next; free(p);  // 修复：先 q->next = p->next 再 free
- free(p); p = p->next;  // 坑3：free 后继续用 p → 野指针 → 未定义行为
+ free(p); p = NULL;  // 修复：源码惯例置空防误用（竞赛不写也行，工程必写）
```

**⑤ 典型应用**

- B 源教材例题：Insert(6,19) / Insert(4,12) / Delete(100)（不存在，打印提示）/ Delete(4)，最终输出 `8 1 7 6 19 12 9 10`（实测吻合）。
- 力扣 LC 203 移除链表元素（力扣）：本节 Delete 的力扣版，注意不带头结点时删头要特判，或引入哨兵节点（虚拟头结点）——头结点思想的回响。
- 自编迁移题（自编）：单链表"原地逆置"若用本节的插删原语表达，等价于哪种建表法？建议先独立做，再对照题解。

  题解：逐个摘下首元结点头插到新链——正是 A 源 LC206 的"思路 1"（课件原话"摘下后用头插法建立新的链表，链表原地逆置"）。头插法的"顺序相反"性质就是逆置本身。知识点 5 会给出更优的双指针写法。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 判空写在比较之后 → 空链表解引用 NULL，RE → `p != NULL &&` 永远放前面。

> [!caution]
> **【易错】** 删除时只 free 不接链 → 后半条链整段丢失 → 先 `q->next = p->next` 再 free。

> [!caution]
> **【易错】** free 后继续用 p → 野指针 → 源码惯例 `p = NULL`（防误用；竞赛不写也行，工程必写）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：空表（头结点 next=NULL）Delete(4) → p==NULL 即刻成立，打印"4不存在,无法删除"（判空短路兜底，不 RE）
> 2. 单元素：[8] 删 8 → p 停在 8、q 停在头结点，q->next = p->next = NULL，free 后回到空表（删头=删尾，头结点统一性兑现）
> 3. 全相同：[5, 5, 5] 删 5 → 只删首元那个 5，得 [5, 5]（Delete 单次只删一个）
> 4. 严格递增：[1, 2, 3] 删 2 → q 停在 1、p 停在 2，得 [1, 3]（链表删除与有序性无关，冒烟验证）
> 5. 严格递减：[3, 2, 1] 删 3 → q 恰为头结点、p 为首元，得 [2, 1]（删首元场景，q->next 改写天然成立）
> 6. 极值：删除 INT_MAX（2147483647）→ 整值比较可正确匹配并删除；本节无算术运算，不适用：无溢出点

数据范围与边界：单链表插入/删除的本体 $O(1)$ 是"拿到位置后"——定位本身 $O(n)$，宣传复杂度时别只报一半。结论失效条件：需要 O(1) 删除给定节点时用双链表（知识点 4）。收尾回扣：现在增删查改的指针改写都齐了，但"拿前驱"这个负担还压在每次操作上——下一节用 pre 域与循环结构把它卸掉。

### 4. 双链表与循环链表：用指针买能力

前置依赖：[[#3. 单链表基本操作：查找、插入、删除]]（删除要前驱的痛点）
后续衔接：[[#7. 静态链表与跳表：数组的另一种打开方式]]（pre/nxt 的数组形态）、约瑟夫问题类环形模拟（与 [[枚举与模拟]] 交汇）

**① 它解决什么问题**

**双链表**：节点多一个 pre 指针域（保存前驱地址），删除与反向遍历不再需要"找前驱"。**循环链表**：尾结点 next 指回头（单循环）或头结点 pre 指尾、形成双向环（双循环），任何节点出发可达全表。两者合计给出链表的四种形态（B 源第 4 页）：单向链表、单向循环链表、双向链表、双向循环链表。性质：空间多一指针；能力买回 $O(1)$ 删除给定节点、双向遍历、循环判空改形。

| 形态 | 判空 / 停止条件 | 找尾条件 | 删除给定节点 p |
|------|---------------|---------|---------------|
| 带头单链 | `p != NULL` | `p->next != NULL` | 需前驱 q |
| 带头单循环 | `p != L` | `p->next != L` | 需前驱 q |
| 带头双链 | `p != NULL` | `p->next != NULL` | `p->pre->next = p->next` 直接删 |
| 带头双循环 | `p != L` | `p->next != L` | 同上，且**无需任何判空** |

**② 直觉理解**

双链表的类比：单链是**单程巴士**（只记得下一站），想回上一站得从头再坐；双链是**往返巴士**（每站记得前后两站），"跳过某一站"（删除）只需改前后两站的站牌。循环链表的类比：**操场跑道**——没有"最后一站"，判空条件从"到站台"（NULL）变成"回到出发点"（p == L）。

用具体数字跑一遍（循环双链表，源码 main）：空表 InitLink 后 `head->next = head, head->pre = head`（自己指自己）；头插 6 —— `s->next = L->next`（接到原首元，即 L 自己）、`L->next->pre = s`（此时 `L->next` 是 L，即 `L->pre = s`，**自动更新了尾指针**）、`L->next = s`。三行写完，单元素环建立且 L->pre 恰好指向尾——非循环双链表这里必须写 `if (L->next != NULL)` 判空（对比 双链表代码.c 第 41 行），循环结构把判空**吃掉了**。

**③ 原理与推导**

循环双链表为什么可以不判空（不跳步）：非循环双链表的边界是"首元没有前驱之外还可能有 NULL 后继"——插在尾后时 `p->next->pre = s` 里 `p->next` 是 NULL，必须判。循环结构里**头结点也在环上**：尾结点的 next 恒为 L（不是 NULL），`p->next->pre = s` 无条件执行时改的是 `L->pre`，而"L 的前驱 = 尾结点"正是循环双链表的性质——看似省掉的判空，其实被循环不变式**自动满足**了。源码 循环双链表代码.c 的 Rear_insert 还显式维护 `L->pre = s`（尾插后更新尾），Insert / Delete 里 `p->next->pre` 的无条件写法同理安全。

设计动机：为什么竞赛更常用"数组模拟"而不是 malloc 链表？malloc 慢且散，`next[i]` 数组（静态链表，知识点 7）访问快、可随机定位。双链表竞赛最常用形态是 `pre[]/nxt[]` 两个数组——pre/nxt 的思想不变，载体换成连续内存，兼得两者之长。

**④ 代码演示**

双链表删除（对比两形态，相对源文件的改动：并排摘录并加对照注释）：

```cpp
// 双链表（非循环）删除 p：源文件 双链表代码.c
p->pre->next = p->next;
if (p->next != NULL) p->next->pre = p->pre;   // p 是尾时 p->next 为 NULL，必须判
free(p);

// 循环双链表删除 p：源文件 循环双链表代码.c
p->pre->next = p->next;
p->next->pre = p->pre;    // p->next 恒非 NULL（最坏是 L），判空消失
free(p);                   // 复杂度：两形态均 O(1) 本体
```

// 边界：循环双链表删到只剩头结点（空表）时 p->pre = p->next = L，两行退化为自环，天然正确
// 复杂度：找到 p 后删除本体 O(1)——单链表做不到（要前驱）

**错误写法对照**

```diff
- p->next = s;  // 坑1：双链表插入只改前驱指向，漏改后驱的 pre → 倒着遍历时断链 → 答案错
+ s->next = p->next; s->pre = p; p->next->pre = s; p->next = s;  // 修复：口诀"先接两头（s->next / s->pre），再改中间（p->next 与 p->next->pre）"
- while (p != NULL) p = p->next;  // 坑2：循环链表沿用 != NULL 判空 → 条件永远为假 → 死循环
+ while (p != L) p = p->next;  // 修复：终止条件全部换成 != L
- while (p != L) p = p->next;  // 坑3：循环单链表找尾判 p != L → p 从 L 出发第一轮就停
+ while (p->next != L) p = p->next;  // 修复：看"下一个"是不是回到头
```

**⑤ 典型应用**

- B 源教材例题：双链表 / 循环单链表 / 循环双链表三份代码的 main 与单链表版完全同参（头插 6,7,1,8 → 尾插 4,9,10 → Insert ×2 → Delete ×2），输出一致 `8 1 7 6 19 12 9 10`（四版实测吻合）——结构换了，操作语义不变。
- 洛谷 P1996 约瑟夫问题（洛谷）：n 人围成圈报数出列——循环链表的经典原型（单循环建圈，数到 m 删节点）。
- 自编迁移题（自编）：用双链表实现一个"文本编辑器光标"——支持左移、右移、当前位置前插入字符、删除当前字符，说明各操作的指针改写。建议先独立做，再对照题解。

  题解：光标即节点 p，`p = p->pre`（左移，无需找前驱——单链表做不到）、`p = p->next`（右移）、插入即在 p 前（或后）双改四指针、删除即绕过 p 双改两指针再 `p = p->next`。四操作全部 $O(1)$——这道题是"pre 域买回的能力"的直接兑现。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 双链表插入漏改后驱的 pre → 倒着遍历时断链 → 口诀"先接两头，再改中间"：s->next / s->pre 接好，再改 p->next 与 p->next->pre。

> [!caution]
> **【易错】** 循环链表沿用 `!= NULL` 判空 → 永远为假，死循环 → 全部换成 `!= L`。

> [!caution]
> **【易错】** 循环单链表找尾用 `p != L`（p 从 L 出发）→ 第一轮就停 → 用 `p->next != L`（看下一个是不是回到头）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：循环双链表初始化后 head->next = head、head->pre = head（自指空环）；遍历首轮 p == L 即停，无输出（空环是合法状态）
> 2. 单元素：环上仅一个数据节点 s（s->next = s->pre = L）→ 删除它，两行改链退化为自环，天然正确（无判空也安全）
> 3. 全相同：值全为 5 的循环单链表遍历 → 按 p != L 正常出环（结构行为与值无关）
> 4. 严格递增：不适用：双链/循环操作只改指针，与输入有序性无关
> 5. 严格递减：不适用：同上
> 6. 极值：数据域存 INT_MAX → 双向遍历打印正确；指针域存地址不存数值，不适用：无算术溢出场景

数据范围与边界：竞赛大规模链表用数组模拟（知识点 7），malloc 版教学与中小规模适用。结论失效条件：只需单向且不删给定节点时，双链表浪费空间，单链表够用。收尾回扣：现在四种形态的能力/代价表齐了——但竞赛里链表题考的不是背结构，而是**指针操作的推理**。接下来两节用两道力扣真题练这个推理。

### 5. 反转链表（LC206）：双指针迭代

前置依赖：[[#2. 单链表与头结点：两套约定的统一]]（不带头约定）、[[#3. 单链表基本操作：查找、插入、删除]]（指针改写功夫）
后续衔接：[[#6. 快慢指针（LCR 140）：倒数第 k 个]]（同族双指针）、[[栈与队列]]（主题链下一站，本篇课件末预告其两道真题）

**① 它解决什么问题**

力扣 206：给定不带头结点的单链表头 head，把链表反转并返回新头（`1→2→3→4→5` 变 `5→4→3→2→1`）。它解决的问题是链表指针推理的**试金石**：把每个节点的 next 从"指后继"改为"指前驱"。性质：一趟扫描 $O(n)$、空间 $O(1)$（迭代法）。

| 方法 | 时间 | 空间 | 来源 |
|------|------|------|------|
| 摘下首元 + 头插重建 | $O(n)$ | $O(1)$ | 课件思路 1（借知识点 3⑥ 的头插性质） |
| 双指针迭代 | $O(n)$ | $O(1)$ | 课件思路 2，例题源码采用 |
| 递归 | $O(n)$ | $O(n)$ 栈 | 课件笔记链接提及，竞赛少用 |

**② 直觉理解**

模型级类比：**倒着传接力棒**。一列人手拉手（每人只认识下一个），要反着排——让每人转身抓住"刚离开自己的那个人"。cur 是"已经反好转身的那一段"的队头，pre 是"还没转身的那一段"的队头，每轮做一次"pre 转身抓 cur"，两段边界整体右移一格。课件描述的"pre 在右 cur 在左、每次让 pre 的 next 指向 cur"正是此意——**必须先用 t 记下 pre->next 再改**（课件提醒"不能丢失结点"），否则后半段失联。

用具体数字跑一遍（`1→2→3→4→5`）：cur=NULL, pre=1 → t=2, 1→NULL, cur=1, pre=2 → t=3, 2→1, cur=2, pre=3 → t=4, 3→2, cur=3, pre=4 → t=5, 4→3, cur=4, pre=5 → t=NULL, 5→4, cur=5, pre=NULL 退出，返回 cur=5。五轮，每轮一次"转身"。

**③ 原理与推导**

为什么每轮三行的顺序不可动（不跳步）：`pre->next = cur` 这一步会**覆盖** pre 原本的 next——没保存就改，pre 之后的整段失联。所以顺序强制为：先 `t = pre->next`（保存），再 `pre->next = cur`（转身），最后 `cur = pre; pre = t`（边界右移）。循环不变量：cur 指向的已反转段 + pre 指向的未反转段合起来恰是原链全部，且 cur 段的头（原链尾）最终成为新表头。pre 走到 NULL 时未反转段为空，cur 即新头。

设计动机：为什么迭代法优于头插重建法？两者同为 $O(n)$/$O(1)$，但头插法要 malloc 新节点（或维护两条链），常数与代码量都大；迭代法原地改指针，零分配。课件把思路 2 列为解法正说明"竞赛优先原地改"。

```mermaid
flowchart LR
    A[pre 指向未反转段头] --> B[t 记住 pre.next]
    B --> C[pre.next 指向 cur 已反转段]
    C --> D[cur 前移到 pre]
    D --> E[pre 前移到 t]
    E --> F{pre == NULL?}
    F -- 否 --> A
    F -- 是 --> G[返回 cur 即新表头]
```

文字版推导链：保存后继 → 当前节点转身指向前一段 → 两段边界整体右移 → 未反转段耗尽时，已反转段头就是答案。

**④ 代码演示**

```cpp
ListNode* reverseList(ListNode* head) {     // 相对源文件：仅补注释
    ListNode* cur = NULL;                    // 已反转段的头（初始空）
    ListNode* pre = head;                    // 未反转段的头
    ListNode* t = NULL;                      // 保存后继的暂存指针
    while (pre != NULL) {
        t = pre->next;                       // 先保存（课件：不能丢失结点）
        pre->next = cur;                     // 转身
        cur = pre;                           // 已反转段边界右移
        pre = t;                             // 未反转段边界右移
    }
    return cur;                              // 复杂度 O(n) / O(1)
}
```

// 边界：空表（head=NULL）时循环不进，返回 NULL；单节点时一轮后 pre=NULL、cur 原节点，均天然正确
// 相对源文件的改动：仅补注释；建表部分（尾插 + 尾指针 r）与输出见源文件 LC206.cpp

**执行追踪表**（数据取自②：1→2→3→4→5，五轮"先保存、再转身、边界右移"）

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|------|---------|---------|------|------|
| 1 | 1 | cur=NULL，pre=1→2→3→4→5 | t = pre->next | t=2，后继已保存 |
| 2 | 1 | | pre->next = cur | 1→NULL，已反转段 = [1] |
| 3 | 1 | | cur=pre，pre=t | cur=1，pre=2，边界右移 |
| 4 | 2 | 已反转段 1←2，未反转段 3→4→5 | t=3，2→1，cur=2，pre=3 | 已反转段 2→1 |
| 5 | 3 | | t=4，3→2，cur=3，pre=4 | 已反转段 3→2→1 |
| 6 | 4 | | t=5，4→3，cur=4，pre=5 | 已反转段 4→3→2→1 |
| 7 | 5 | | t=NULL，5→4，cur=5，pre=NULL | 循环退出，返回 cur=5（新表头） |

**错误写法对照**

```diff
- pre->next = cur; t = pre->next;  // 坑1：先改指针后存后继 → pre 原本的 next 被覆盖 → 后半段失联，只反转出一个节点
+ t = pre->next; pre->next = cur;  // 修复：口诀"先保存，再转身"
- while (pre->next != NULL)  // 坑2：最后一个节点没转身 → 尾断 → 答案错
+ while (pre != NULL)  // 修复：循环条件用 pre != NULL
- return pre;  // 坑3：循环结束时 pre 是 NULL → 返回空指针 → RE
+ return cur;  // 修复：cur 才是新表头
```

**⑤ 典型应用**

- 力扣 LC206 反转链表（力扣）：输入 n 与 n 个数，反转后输出（实测：`5` + `1 2 3 4 5` → `5 4 3 2 1`）。
- 自编迁移题（自编，原型力扣 92 反转链表 II）：反转链表的第 left 到 right 个节点，其余不变。建议先独立做，再对照题解。

  题解：三段式——先用知识点 6 的"走 steps 步"定位到 left 的前驱 cut（引入哨兵节点避免 cut 为空），段内做本节的双指针反转 right-left+1 次，最后把 cut->next 接到段尾、段头接到 right 后继。核心还是"先保存、再转身、边界右移"三行，只是外加两层定位。哨兵节点（虚拟头结点）在此再次兑现"头结点统一性"（知识点 2③）。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 先写 `pre->next = cur` 后存 t → 后半段失联，只反转出一个节点 → 口诀"先保存，再转身"。

> [!caution]
> **【易错】** 循环条件写成 `pre->next != NULL` → 最后一个节点没转身，尾断 → 用 `pre != NULL`。

> [!caution]
> **【易错】** 返回 pre（此时是 NULL）→ 空指针 → 返回 cur。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：head = NULL → 循环不进，直接返回 cur = NULL（输出空）
> 2. 单元素：[7] → 一轮：t=NULL，7→NULL，cur=7，pre=NULL 退出，返回 7（原样输出 7）
> 3. 全相同：[5, 5, 5] → 指针反转与值无关，输出 5 5 5
> 4. 严格递增：1→2→3→4→5 → 5→4→3→2→1（②逐轮推演原题）
> 5. 严格递减：5→4→3→2→1 → 1→2→3→4→5（递减输入反转为递增）
> 6. 极值：节点值取 INT_MAX 与 INT_MIN 混排 [2147483647, -2147483648] → 只改指针不做算术，输出 -2147483648 2147483647，无溢出

数据范围与边界：力扣约束 $n \le 5000$，$O(n)$ 稳过；递归法 $O(n)$ 栈深在 n 大时爆栈，竞赛一律迭代。结论失效条件：需要"只反转一部分"时套迁移题三段式，本节三行仍是核心。收尾回扣：现在"指针推理"的第一关过了——下一关仍是双指针，但两个指针不再一前一后，而是**一快一慢**。

### 6. 快慢指针（LCR 140）：倒数第 k 个

前置依赖：[[#5. 反转链表（LC206）：双指针迭代]]（双指针推理同款心法）
后续衔接：[[#7. 静态链表与跳表：数组的另一种打开方式]]、[[二叉树结构篇]]（主题链下一站，链式结构升级）

**① 它解决什么问题**

力扣 LCR 140（课件第 3-4 页，链接为"链表中倒数第 k 个节点"）：不带头结点单链表，求倒数第 k 个节点。单链表不能倒着走——本节用**快慢指针**一趟解决：fast 先走 k 步拉开差距，然后 fast、slow 同步走，fast 到达尾部空节点时，slow 恰在倒数第 k。性质：一趟 $O(n)$、空间 $O(1)$。

| 两个指针 | 初始 | 领先关系 | 终止时 |
|---------|------|---------|--------|
| fast | head，先行 k 步 | 恒比 slow 前 k 个位置 | 尾后空节点 NULL |
| slow | head | 同步 +1 | 倒数第 k |

**② 直觉理解**

模型级类比：**双尺量布**（尺取法同款直觉）。想量出"离布尾 k 寸"的位置，不必先量全长再回头——把两把尺并排放，其中一把先右移 k 寸，然后两把同步右移，先动的这把碰到布尾时，另一把指的位置就是答案。两指针的**间距 k 是不变量**——这就是"快"的全部含义：不是速度不同，是**起点不同、步速相同**。

用具体数字跑一遍（`2→4→7→8`，cnt=1）：f=s=2（第 1 个），t=1；先行循环 `t < cnt+1 = 2` 执行一次 → f=4, t=2 退出（f 在第 2 个，与 s 间隔 1，与题意吻合）。同步：f=7, s=4 → f=8, s=7 → f=NULL, s=8 退出，返回 8（倒数第 1，正确）。再验证 cnt=2：f 先走 2 步到 7（第 3 个），同步后 s 停在 7（倒数第 2，正确）。实测程序输出 8 / 7 吻合。

**③ 原理与推导**

为什么间距恒为 k（不跳步）：先行阶段 fast 走了 k 步（源码 `t` 从 1 计到 cnt+1，共 cnt 次移动），此后每轮 fast、slow 各走一步，间距保持 k。fast 从"第 k+1 个节点"出发，同步走到"尾后 NULL"共走 $n-k$ 步；slow 同样走 $n-k$ 步，从第 1 个出发，落在第 $n-k+1$ 个——即倒数第 k。这是"间距不变量 + 终点对齐"的完整推导，不依赖任何长度预计算（对比"先数全长 n 再走 n-k 步"的两趟法，省一趟）。

设计动机：为什么 fast 停在"尾后空节点"而不是"尾节点"？若以"fast 是尾节点"为终止条件，slow 停在倒数第 k+1——那是"倒数第 k 个的**前驱**"。两个终止条件各有所用：本题型要节点本体（用 NULL 终止）；若要"删除倒数第 k 个"则恰好要前驱（用尾节点终止）——终止条件的选择由答案语义反推。

**④ 代码演示**

```cpp
ListNode* trainingPlan(ListNode* head, int cnt) {   // 相对源文件：仅补注释
    ListNode* f = head;
    ListNode* s = head;
    int t = 1;
    while (f != NULL && t < cnt + 1) {   // fast 先行 cnt 步（判空在前防 cnt 越界）
        f = f->next;
        t++;
    }
    while (f != NULL) {                  // 同步走，间距恒为 cnt
        f = f->next;
        s = s->next;
    }
    return s;                            // 复杂度 O(n) / O(1)
}
```

// 边界：cnt > n 时先行循环因 f==NULL 提前停，s 停在 head——返回值语义是"不存在时返回头"，调用方需自知（源码未处理，坑点见 ⑥）
// 相对源文件：仅补注释；建表（尾插 + 尾指针）与输出见源文件 LCR140.cpp

**执行追踪表**（数据取自②：2→4→7→8，cnt=1，先拉开间距再同步走）

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|------|---------|---------|------|------|
| 1 | 2 | f=s=第 1 个，t=1 | 检查 f != NULL && t < 2 | 进入先行循环 |
| 2 | 4 | f=第 2 个，s=第 1 个，t=2 | f=f->next，t++ | t=2 不再小于 2，先行结束，间距拉开为 1 |
| 3 | 7 | f=第 3 个，s=第 2 个 | f=f->next，s=s->next | 同步走，间距保持 1 |
| 4 | 8 | f=第 4 个，s=第 3 个 | 同步各走一步 | 间距保持 1 |
| 5 | NULL | f=尾后空节点，s=第 4 个 | f==NULL 退出同步循环 | 返回 s=8，即倒数第 1 |

**错误写法对照**

```diff
- while (t < cnt + 1) { f = f->next; t++; }  // 坑1：先行不判空 → cnt > n 时解引用空指针 → RE
+ while (f != NULL && t < cnt + 1) { f = f->next; t++; }  // 修复：判空与步数双条件
- // cnt = 0 或负数直接进入流程  // 坑2：先行不走，返回头节点 → 语义错
+ if (cnt < 1) return NULL;  // 修复：入参先判 k 合法性
- while (f != NULL) { f = f->next; s = s->next; } return s;  // 坑3：NULL 终止版拿到的是待删节点本体而非前驱 → 删倒数第 k 时错位
+ while (f->next != NULL) { f = f->next; s = s->next; } return s;  // 修复：按语义反推终止条件——要前驱改用"尾节点终止"
```

**⑤ 典型应用**

- 力扣 LCR 140（力扣）：倒数第 k 个节点（实测：`4` + `2 4 7 8` + `cnt=1` → 8；`cnt=2` → 7）。
- 自编迁移题（自编，同族三问）：用快慢指针求 (a) 链表中点（偶长取后中）；(b) 判断链表有环并找入环口（原型力扣 141/142）；(c) 删除倒数第 k 个。建议先独立做，再对照题解。

  题解：(a) fast 每次走 2 步 slow 走 1 步，fast 到尾时 slow 在中点——"快"第一次真正体现在**步长**。(b) 同款步长差：有环则 fast 必在环内追上 slow（每轮间距缩 1）；相遇后一头一相遇点同速走，交点即入环口。(c) 按本节③的结论改终止条件——fast 终止于尾节点时 slow 在倒数第 k+1（前驱），`slow->next = slow->next->next` 即删。三问共享"间距/步速差不变量"一个心法。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 先行循环去掉 `f != NULL` 判空 → cnt > n 时解引用空指针 RE → 判空与步数双条件。

> [!caution]
> **【易错】** cnt = 0 或负数 → 先行不走，返回头节点（错误语义）→ 入参先判 k 合法性。

> [!caution]
> **【易错】** 想删倒数第 k 个却用"NULL 终止"版 → 拿到的是待删节点而不是前驱 → 按③的语义反推终止条件。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：head = NULL → 先行循环条件 f != NULL 不成立直接退出，同步循环不进，返回 s = NULL
> 2. 单元素：[7] 取 cnt=1 → 先行一轮后 f=NULL（t=2），同步循环不进，返回 s=7（倒数第 1 是自己）
> 3. 全相同：[5, 5, 5, 5] 取 cnt=2 → 返回第 3 个节点（值 5），位置推导与值无关
> 4. 严格递增：2→4→7→8 取 cnt=1 → 8；cnt=2 → 7（②实测两组）
> 5. 严格递减：8→7→4→2 取 cnt=1 → 2（倒数第 1 恒为尾节点，与值序无关）
> 6. 极值：n=10^4 全部 INT_MAX 取 cnt=10^4 → 先行恰好走完 n 步后 f=NULL，s 停在第 1 个（倒数第 n = 正数第 1）→ 返回该 INT_MAX 节点；本节无算术，无溢出点（cnt > n 时返回 head 的错误语义见⑥坑 2）

数据范围与边界：力扣约束 $1 \le k \le n \le 10^4$，一趟 $O(n)$ 稳过。结论失效条件：链表带环时"走到 NULL"永不发生，先判环（迁移题 b）。收尾回扣：开场说链表"不能倒着走、不能跳着看"——快慢指针用两个指针的**相对运动**把"倒数"变成了"正数"。还剩最后一块拼图：竞赛里链表怎么存才又快又稳。

**① 它解决什么问题**

**静态链表**（课件第 5 页）：用数组描述的链表——"分配一整片连续的内存空间，各个结点集中安置……用数组来实现链式存储结构，静态链表实际上就是一个结构体数组"。它解决 malloc 链表的两个痛点：分配慢、节点散落缓存不友好。**跳表**（课件第 6 页）：在有序链表基础上增加多层索引——"每一层链表都是有序的，最下面一层包含所有数据，从下往上节点个数逐渐减少"，让有序链表获得二分查找能力 $O(\log n)$。

| 结构 | 本质 | 访问 | 插删 | 竞赛形态 |
|------|------|------|------|---------|
| 静态链表 | 数组模拟的链 | $O(n)$ 顺链 | $O(1)$ 改游标 | `nxt[]` / `pre[]` 数组 |
| 跳表 | 多层有序链 | $O(\log n)$ 跳跃 | $O(\log n)$ | 力扣 1206 设计跳表 |

**② 直觉理解**

静态链表模型级类比：**座位表排戏**。剧组不再临时租人（malloc），而是把全班同学（数组）列成花名册，每人发一张"下一个上场的是几号"的卡片（游标）。"链"不再是内存地址而是**数组下标**——`nxt[i]` 存"i 号的下一位是谁"。插入 = 改两张卡片，删除 = 把某人卡片上的"下一位"抄给前一位，0 次内存分配。

跳表模型级类比：**地铁快车线**。普通线（底层）每站都停，快车线（上层）只停大站、越上层的线站越少。从起点出发先在快车线上尽量坐，坐过头了下一层接着坐——每换一层淘汰一半站，$O(\log n)$ 层内到位。这正是"有序链表上的二分"。

用具体数字跑一遍（静态链表建 `2→4→7`）：`nxt[1]=2, nxt[2]=3, nxt[3]=0`（0 当 NULL），遍历从 head=1 起：走 nxt 直到 0。头插 9：`nxt[9]=nxt[head]; nxt[head]=9;` 两行完成，与知识点 2④ 头插完全同构——**游标替代指针，逻辑一字不改**。

**③ 原理与推导**

跳表为什么能二分（不跳步）：有序数组的二分靠"下标随机访问 $O(1)$"（知识点 1③ 的访问公式），有序链表没有下标——课件第 6 页的解法是**把"跳过一半"显式建进结构里**：上层链是下层链的抽样，"在第 L 层发现下一个节点太大"就降到 L-1 层继续。设每层抽样率 1/2，从顶层走到目标平均访问 $O(\log n)$ 个节点——把"随机的访问能力"换成了"确定的多级索引"。上层元素与下层相同（课件特性 4"上一层的元素指向下层的元素必须是相同的"），保证索引不丢数据。

设计动机：为什么竞赛静态链表比 malloc 链表常见？三个理由：分配 O(1) 且总量可控（数组开够）、缓存连续遍历快、可"按值寻址"（下标即身份，配合桶/排序）。代价：需预估规模（数组开够）——与顺序表"大小固定"的短板呼应，但链式逻辑不受搬移之苦。

**④ 代码演示**

静态链表核心（自编示意，游标版头插与遍历；竞赛标准写法）：

```cpp
int nxt[100005], val[100005];    // 下标即节点身份；nxt=0 表示"没有下一个"
int head = 1, cnt = 1;           // head：链首下标；cnt：下一个可用节点
void push_front(int x) {         // 头插：O(1)，与知识点 2④ 同构
    ++cnt;
    val[cnt] = x;
    nxt[cnt] = nxt[head];        // 先接：新节点接住原首元
    nxt[head] = cnt;             // 后断：head 改指新节点
}
void walk() {                    // 遍历：从 head 顺游标走，0 即终点
    for (int p = nxt[head]; p != 0; p = nxt[p]) printf("%d ", val[p]);
}
```

**⑤ 典型应用**

- 力扣 1206 设计跳表（力扣）：课件第 6 页给的原题——实现 add / search / erase，多层索引 + 随机层数。
- 洛谷 P7912（洛谷，子序列合并等题族）：静态链表/双链表数组版在过程模拟类题的典型用法（`pre[]`/`nxt[]` 双数组即知识点 4 的数组形态）。
- 自编迁移题（自编）：n 个人围成圈玩约瑟夫游戏（报 m 出列），用**循环**静态链表（`nxt` 成环）模拟，输出出列顺序。建议先独立做，再对照题解。

  题解：`nxt[i] = i+1`、`nxt[n] = 1` 成环；当前人 p 报数 m-1 次走到"被删者的前驱"，删除即 `nxt[p] = nxt[nxt[p]]`，共 n 轮，总 $O(nm)$；m 用取模优化可到 $O(n)$（周期与取模，见枚举与模拟篇）。这题同时用到循环结构（知识点 4）、静态载体（本节）与取模（前篇）——跨主题综合的收束题。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 静态链表数组开小 → 下标越界写穿 → 按数据范围 + 余量开（如 1e5 开 100005）。

> [!caution]
> **【易错】** 把"空"写成 NULL 或 -1 混用 → 游标语义混乱 → 全篇统一哨兵值（本节约定 0）。

> [!caution]
> **【易错】** 以为跳表每层节点数"逐渐减少"是严格减半 → 实现用随机层数（概率 1/2 进上层），期望 $O(\log n)$ → 课件特性是统计性质不是硬保证。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：初始化 nxt[head] = 0 → walk() 首轮 p=0 不进循环，无输出（空表遍历安全）
> 2. 单元素：nxt[head]=2、val[2]=7、nxt[2]=0 → 输出 `7 `
> 3. 全相同：连续头插三个 5 → 输出 5 5 5（头插反序但值相同，冒烟验证不崩）
> 4. 严格递增：依次头插 1, 2, 3 → 输出 `3 2 1`（游标版头插同样与插入顺序相反，与知识点 2④ 同构）
> 5. 严格递减：依次头插 3, 2, 1 → 输出 `1 2 3`
> 6. 极值：val[cnt] = INT_MAX → 可存可打印；溢出点不在数值在下标——cnt 超过 100005 时写穿（坑 1），按数据范围开余量

数据范围与边界：静态链表规模静态、跳表层数期望 $O(\log n)$；两者都要求"先想清楚哨兵与终止值"。结论失效条件：需要严格 $O(\log n)$ 上界（非期望）时跳表不适用，用平衡树。收尾回扣：现在你能完整回答开场那个问题了——顺序表赢在随机访问、输在搬移；链表赢在原地插删、输在只能顺链走；而竞赛把两者杂交成静态链表（连续内存 + 链式逻辑），把有序链表的二分缺憾补成跳表。四形态、两约定、两指针套路（反转、快慢），链表的全部家当已清点完毕。

## 四、总结与自测

- 线性表两大存储：顺序表（连续、随机访问 $O(1)$、插删搬移 $O(n)$、大小固定）vs 链表（离散、顺链访问 $O(n)$、插删改指针 $O(1)$、按需分配）。
- 三术语：头指针 / 头结点 / 首元结点；带头结点的价值 = 空表、非空表、首元操作三者统一（B 源第 7 页）。
- 四形态能力表：单链 / 单循环 / 双链 / 双循环——循环把判空 `!= NULL` 换成 `!= L`，双链把"找前驱"内建进 pre 域。
- 两个指针套路：反转链表（先保存再转身，三行一轮回）与快慢指针（间距 / 步速差不变量）——链表题的本质是指针推理。
- 竞赛载体：静态链表 `nxt[]/pre[]` 数组——游标替代指针，逻辑同构、缓存友好；跳表 = 多层有序索引，给链表补上二分。
- 前置概念清单：结构体与指针、malloc/free、短路求值、数组下标与地址、（延伸）尺取法的双指针直觉。
