# 枚举与模拟

## 零、知识地图

```text
枚举与模拟
├── 1. 枚举的四要素（集合、条件、范围、顺序——枚举题的通用检查单）
├── 2. 复杂度估算与数据范围（用 1s = 10^8 判断暴力试不试得起）
├── 3. 枚举顺序与剪枝（利用覆盖单调性反转方向，找到即停）
├── 4. 周期与取模（取模折叠时间轴，只模拟一个周期）
└── 5. 边界模拟（四边界收缩，二维绕圈化为四个一维循环）
学习顺序：1 → 2 → 3 → 4 → 5——先学总纲，再学"试不试得起"的判断，最后三个变形互相独立、按考频排列。
```

## 一、为什么需要它

先看一道题：洛谷 P1003 铺地毯。舞台上铺 n 张地毯，后铺的盖住先铺的，最后问某个坐标点 $(x, y)$ 上面盖的是第几张地毯——没有就输出 -1。

很多人第一反应是"这要用什么高级数据结构"。答案是：什么都不用。n 最多 10000，把每张地毯挨个检查一遍"它盖没盖住这个点"，就是正解。$10000$ 次判断，一毫秒都不到。

这就是枚举：答案的范围题目已经圈死了，挨个试就是了。而模拟，是把题目描述的操作原样翻译成代码。这两件事统称暴力，是一切算法的起点——后面学的每个高效算法，都要先问一句"暴力怎么做、暴力慢在哪"，才谈得上优化。不学本篇，你连判断"暴力能不能过"都不会。

本篇讲 5 个知识点：枚举的四要素、复杂度估算与数据范围、枚举顺序与剪枝、周期与取模、边界模拟。先学怎么"把答案试出来"，再学怎么"判断试得起试不起"，最后三个知识点是三个最常考的变形。

## 二、知识点逐讲（每个知识点一节，共 5 节）

### 1. 枚举的四要素

前置依赖：C 语言的循环、数组与条件判断（本篇全部代码的骨架），无库内前置笔记
后续衔接：[[#2. 复杂度估算与数据范围]]（判断枚举试不试得起）、[[#3. 枚举顺序与剪枝]]（顺序要素的展开）

**① 它解决什么问题**

枚举是基于已有知识猜测答案的问题求解策略：答案一定藏在某个范围里，就把范围里的每个候选挨个拿出来，用题目条件检验，成立的留下。它解决的是"答案范围有限、判定容易"这类问题——搜索空间小到能全试一遍。性质：正确性 $100\%$（穷举不漏），代价是时间复杂度等于"候选个数 × 单次判定成本"。

**② 直觉理解**

把它想成开密码锁：转盘有 1000 种组合（答案集合），密码锁自己会告诉你"对没对"（判定条件），你从 000 试到 999（枚举顺序）。只要锁的反馈可靠、组合总数你能接受，这个笨办法就保证能打开——它不聪明，但它绝不会错过正确答案。

用具体数字跑一遍：求 $1 \sim 100$ 中最大的质数。候选集合是 $2 \sim 100$，条件是"是质数"，顺序从大到小试：$100$ 不是（被 2 整除）、$99$ 不是（被 3 整除）……试到 $97$，成立，输出。一共做了 4 次判定——这就是"从可能的答案里挑"。

**③ 原理与推导**

课件把枚举拆成四个要素，为什么偏偏是这四个？因为它们分别回答四个必答题：

| 要素 | 回答的问题 | 不管它会怎样 |
|------|-----------|-------------|
| 找对答案集合 | 答案在哪个范围里？ | 集合漏了答案，怎么试都错 |
| 判定条件 | 什么算成立？ | 条件抄错题面，WA |
| 缩小枚举范围 | 哪些候选根本不用试？ | 范围太大，TLE |
| 枚举顺序 | 按什么方向试？ | 找到就停时，方向错会拿到错误答案 |

第 3、4 条是水平的分水岭。"缩小范围"的依据是数学性质：比如判断 $n$ 是否为质数，试除只需枚举到 $\sqrt{n}$——因为若 $n = a \times b$ 且 $a \le b$，则 $a \le \sqrt{n}$，小因子找不见，大因子也不存在。这一步把单次判定从 $O(n)$ 降到 $O(\sqrt{n})$。"枚举顺序"的典型用法见知识点 3。

**④ 代码演示**

用 P1003 的骨架看四要素如何落进代码（完整逻辑见知识点 3）：

```cpp
#include <cstdio>
int a[10005], b[10005], g[10005], k[10005];
int main() {
    int n; scanf("%d", &n);
    for (int i = 1; i <= n; i++)
        scanf("%d %d %d %d", &a[i], &b[i], &g[i], &k[i]); // 集合：n 张地毯
    int x, y; scanf("%d %d", &x, &y);
    for (int i = n; i >= 1; i--) {  // 顺序：从最后一张往前
        // 条件：点在地毯覆盖的矩形内
        if (a[i] <= x && x <= a[i] + g[i] && b[i] <= y && y <= b[i] + k[i]) {
            printf("%d\n", i);
            return 0;          // 找到最上面的就停
        }
    }
    printf("-1\n");            // 范围：全部试完仍无
    return 0;
}
```

第 8 行的循环方向就是"枚举顺序"：后铺的地毯在上层，从后往前找到的第一张就是答案。为什么这样设计循环而不是先全存下来再找？因为答案只要一张，边枚举边判定可以找到就停。

**错误写法对照**

```diff
- for (int i = 1; i <= n; i++)      // 坑1（最小示意）：从 1 起枚举质数，1 被误判 → WA
+ for (int i = 2; i <= n; i++)      // 修复：候选从 2 起，并显式处理 n < 2
- for (int i = n; i >= 1; i--)      // 坑2：下面这行找到答案后没有 return 0
-     if (a[i] <= x && x <= a[i] + g[i] && b[i] <= y && y <= b[i] + k[i]) printf("%d\n", i);
+ for (int i = n; i >= 1; i--)
+     if (a[i] <= x && x <= a[i] + g[i] && b[i] <= y && y <= b[i] + k[i]) { printf("%d\n", i); return 0; }
+                                   // 修复：确认题目要"最上面的"后，找到即停
```

**⑤ 典型应用**

- P1003 铺地毯（洛谷）：上面完整讲过，n 张地毯逐张判定，复杂度 $O(n)$。
- LC 59 螺旋矩阵 II（力扣）：模拟填数过程，见知识点 5。
- 自编迁移题（自编）：统计 $1 \sim n$（$n \le 10^6$）中数字里含 7 的数的个数。建议先独立做，再对照题解。

  题解：候选集合是 $1 \sim n$ 每个整数；判定条件是"某一位是 7"；对每个数反复 `x % 10 == 7` 再 `x /= 10` 即可逐位检查。总复杂度 $O(n \log_{10} n)$，$n = 10^6$ 时约 $6 \times 10^6$ 次操作，轻松通过。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 候选集合漏边界：题面说"大于 1 的自然数"，代码却从 1 开始枚举质数 → 1 会被误判（1 不是质数）→ WA。正确写法：循环从 2 起，并显式处理 $n < 2$。

> [!caution]
> **【易错】** 找到答案后忘记 break/return → 多余枚举不一定错（P1003 若继续扫会找到更早的地毯）→ 输出被覆盖成错误答案 → WA。正确写法：确认题目要"最上面的"后，从后往前找到即停。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0，查询点 (0,0) → 循环一次不执行，直接走到 printf("-1")，输出 -1
> 2. 单元素：n=1，地毯 (0,0,1,1)，查询 (0,0) → 输出 1；查询 (5,5) → 输出 -1
> 3. 全相同：n=3 张均为 (1,1,2,2)，查询 (2,2) → 从后往前第一张命中的是第 3 张 → 输出 3
> 4. 严格递增：不适用：候选是 n 个矩形而非有序数值序列，输入单调性对覆盖判定无语义（顺序已由覆盖层级决定）
> 5. 严格递减：不适用：同上
> 6. 极值：n=10000 张 (0,0,1000000000,1000000000)，查询 (1000000000,1000000000) → 恰落在边界上（a ≤ x ≤ a+g 成立）→ 输出 10000；a+g=10^9 在 int 内无溢出

反例：若 P1003 改成"从前往后"枚举且找到即停，输出的是**最下面**那张盖住该点的地毯——条件没错、集合没错，只是顺序错了。收尾回扣：现在你能解决开场那个问题了——把 n 张地毯当候选集合、覆盖关系当判定条件、从后往前当顺序，三要素一拼就是 $O(n)$ 的正解。

### 2. 复杂度估算与数据范围

前置依赖：[[#1. 枚举的四要素]]（先会写枚举，才谈得上估算它试不试得起）
后续衔接：[[前缀和与差分]]（P1387 的优化决策直接用到本节的 1s = 10^8 标尺）、[[#3. 枚举顺序与剪枝]]

**① 它解决什么问题**

枚举写出来只是第一步，你还必须回答"这个暴力跑得完吗"。这个知识点解决的是：拿到数据范围，反推出允许的最大操作次数，从而判断当前做法会不会超时。性质：竞赛评测机 1 秒约接受 $10^8$ 次简单操作（课件原话：1s = $10^8$），这是判断的唯一标尺。

**② 直觉理解**

把评测机想成一个每秒搬 $10^8$ 块砖的工人。你交上去的代码就是一张搬运清单：清单上写着 $10^{10}$ 块砖，工人 100 秒都搬不完，直接判 TLE。所以交代码前先数砖——数清单（循环层数与每层规模）。

**③ 原理与推导**

推导规则只有一条：总操作数 = 各层循环规模相乘，再和 $10^8$ 比。为什么乘而不是加？循环嵌套时内层完整跑一遍外层才走一步，外层每走一步内层做 $m$ 次工作，n 步就是 $n \times m$。

用 P1387 的暴力做法算一笔账：n、m ≤ 100，暴力枚举左上角（$nm$ 种）、枚举边长 l（最多 $\min(n,m)$ 种）、再逐格求和判断（$l^2$ 次），总操作约 $n \cdot m \cdot l^3 \approx 100^5 = 10^{10}$——远超 $10^8$，必超时。后来用二维前缀和把"逐格求和"的 $l^2$ 压成 $O(1)$，变成 $10^7$，稳过。这就是"先估算、再决定要不要优化"的完整决策链，前缀和那篇会展开。

| 数据范围 | 可接受复杂度 | 典型做法 |
|---------|-------------|---------|
| $n \le 10^6$ | $O(n)$ 或 $O(n \log n)$ | 线性扫、排序、筛法 |
| $n \le 10^4$ | $O(n^2)$ | 双重循环枚举 |
| $n \le 500$ | $O(n^3)$ | 三重循环、Floyd |
| $n \le 20$ | $O(2^n)$ | 状压枚举子集 |

（表的作用：拿到题先看范围，就知道该写哪一档算法。来源：课件"看数据范围确定时间复杂度"条目的展开。）

**④ 代码演示**

本知识点无新代码——它是"写代码之前的那一步"。落地的形式是一句注释纪律：写完循环骨架先估算，超了再想优化。例如：

```cpp
// 估算：n=1e4，双重循环 -> 1e8 次操作，贴着上限，需谨慎
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= n; j++)
        check(i, j);   // 单次判定必须足够轻
```

**错误写法对照**

```diff
- for (int i = 1; i <= n; i++)
-     for (int j = 1; j <= n; j++)
-         sort(a, a + n);      // 坑：只数了 n^2 次循环，单次判定却是 O(n log n)，总量要乘上去 → TLE
+ for (int i = 1; i <= n; i++)
+     for (int j = 1; j <= n; j++)
+         check(i, j);         // 修复：总成本 = 循环次数 × 单次成本，判定保持 O(1)
```

**⑤ 典型应用**

- P1003：$n \le 10^4$，$O(n)$ 判定，总操作 $10^4$，远低于上限。
- 自编迁移题（自编）：n ≤ 3000 的数组，问能否枚举所有数对 $(i, j)$ 找满足条件的对。建议先独立做，再对照题解。

  题解：数对个数约 $\frac{n(n-1)}{2} \approx 4.5 \times 10^6$（$n=3000$），单次判定若为 $O(1)$，总操作 $4.5 \times 10^6$，可以过；若判定本身又是 $O(n)$ 的内层循环，就是 $1.35 \times 10^{10}$，必超时。结论：枚举数对可行，但判定必须 $O(1)$。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 只算循环次数不算单次成本：内层调用了排序或字符串比较，单次是 $O(\log n)$ 甚至 $O(n)$，总量要乘上去 → 估算失真 → TLE。正确写法：总成本 = 循环次数 × 单次成本，分别估。

> [!note]
> **【注意】** 常数修正：递归、取模、除法比加减乘慢若干倍，贴着 $10^8$ 上限的写法（如 $9 \times 10^7$ 次取模）实际可能超时，估算留 2 倍余量。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 双重循环 0 次，总操作数 0 → 估算结论"不超时"
> 2. 单元素：n=1 → 循环 1 次，总操作数 = 单次判定成本本身
> 3. 全相同：n=10^4 且每次判定都走最坏分支 → 总操作 10^8 贴上限 → 按"留 2 倍余量"纪律判危险
> 4. 严格递增：不适用：估算只依赖循环规模与单次成本，与输入数值是否递增无关
> 5. 严格递减：不适用：同上
> 6. 极值：n=10^5 的 O(n^2) → 10^10 次操作，超出 10^8 标尺一百倍 → 必 TLE，任何常数优化无效，须换算法量级

反例：$n = 10^5$ 的 $O(n^2)$ 算法是 $10^{10}$ 次操作，任何常数优化都救不了——量级不对时，优化常数没有意义。收尾回扣：现在你能解决"要不要优化"这个问题了——数清单、比 $10^8$，一步定夺。

### 3. 枚举顺序与剪枝

前置依赖：[[#1. 枚举的四要素]]（顺序要素的展开）
后续衔接：[[#4. 周期与取模]]、[[#5. 边界模拟]]（同属枚举的变形）；更远的 [[二分]]（在有序候选上"找到即停"的加速版）

**① 它解决什么问题**

同一批候选，试的顺序不同，找到答案的速度与正确性完全不同。这个知识点解决：当题目问"最上面/最先/最大"这类带优先级的答案时，如何选一个"找到即停"的枚举顺序，把多余判定全部省掉。性质：不改变候选集合，只改变遍历次序，最坏复杂度不变、平均复杂度大幅下降。

**② 直觉理解**

在摞起来的书里找"最上面那本红色封面"。两种办法：一、把每本红的都找出来记下位置，最后挑位置最高的；二、从顶往下翻，碰到第一本红的就停。办法二永远不慢于办法一——因为后翻的书不可能在先翻的上面。这就是"顺序反转"带来的剪枝。

**③ 原理与推导**

为什么"从后往前"对 P1003 正确？铺设时间与覆盖层级是单调关系：地毯按输入顺序铺，第 $i+1$ 张永远盖在 $1 \sim i$ 张之上。题目要最上层的，等价于要编号最大的满足条件的。所以按编号从大到小判定，第一个满足的就是全局最优。

用具体数字跑一遍：3 张地毯，第 1 张盖 $(1,1)$ 到 $(5,5)$，第 2 张盖 $(2,2)$ 到 $(6,6)$，第 3 张盖 $(10,10)$ 到 $(20,20)$；查询点 $(3,3)$。从后往前：第 3 张不含 $(3,3)$，跳过；第 2 张含，输出 2，停。若从前往后且找到就停，会错输出 1。设计动机：这个顺序利用了题面里"后铺盖前铺"这条性质，性质存在才可反转——若题目改成"每张地毯透明度随机"，顺序反转立刻失效。

**④ 代码演示**

P1003 核心逻辑（取自源文件 P1003.cpp，仅省略读入部分，完整版见源文件 P1003.cpp）：

```cpp
int flag = 0;
for (int i = n; i >= 1; i--) {   // 顺序：最后铺的先查
    if (a[i] <= x && x <= a[i] + g[i] &&
        b[i] <= y && y <= b[i] + k[i]) {
        printf("%d\n", i);
        flag = 1;                // 复杂度：O(n) 次矩形判定
        break;                   // 找到即停，后面全是无用功
    }
}
if (flag == 0) printf("-1\n");
```

第 1 行的 flag 记录"是否找到过"，循环外统一处理 -1。为什么不用 return 0 直接退？两种写法都对，源码选择 flag 是为了把"输出"集中在一处，调试时更容易打日志。

**错误写法对照**

```diff
- for (int i = 1; i <= n; i++)     // 坑：题目要"最上层"，却从前往后找到即停
-     if (in_carpet(i, x, y)) { printf("%d\n", i); break; }   // 输出的是最下面那张 → WA
+ for (int i = n; i >= 1; i--)     // 修复：先在草稿上确认"后铺盖前铺"的单调性，再反转方向
+     if (in_carpet(i, x, y)) { printf("%d\n", i); break; }
```

**⑤ 典型应用**

- P1003 铺地毯（洛谷）：本知识点主例，反转顺序 + 找到即停。
- 自编迁移题（自编）：n 个人按时间顺序到餐厅占座，每人占一个座位，后来者可以坐走先来者的位置；问最终某个座位最后归属谁（占座记录按时间给出，问第 k 号座位最终被谁占）。建议先独立做，再对照题解。

  题解：与 P1003 同构——"后来者覆盖先来者"对应"后铺地毯盖住先铺"。候选：按时间从后往前扫占座记录，第一条涉及第 k 号座位的记录就是最终归属；都没有则座位从未被占。复杂度 $O(m)$（m 为记录数）。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 反转顺序前没确认"覆盖/优先级单调性"→ 拿到的是第一个满足条件者而非题目要求者 → WA。正确写法：先在草稿上写出"谁盖谁"的关系，确认与输入顺序同向（或反向）再定循环方向。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 循环不执行，flag 保持 0 → 输出 -1
> 2. 单元素：n=1，地毯不覆盖查询点 → 扫完 1 张仍无 → flag=0 → 输出 -1
> 3. 全相同：3 张相同且都覆盖查询点 → 从后往前第 1 次判定即命中编号 3 → 输出 3（只做 1 次判定，剪枝生效）
> 4. 严格递增：不适用：循环方向由"谁盖谁"的层级关系决定，与输入数值单调性无关
> 5. 严格递减：不适用：同上
> 6. 极值：n=10^4 张全不覆盖查询点 → 反转后仍要扫满 10^4 次（最坏情形无剪枝）→ 输出 -1，复杂度仍 O(n)

数据范围与复杂度上限：反转不改变最坏情况（全都不满足时仍要扫完 $n$ 个），只优化"找到就停"的平均情形。结论失效条件：候选之间没有层级/优先关系时（如无序集合找最大值），顺序反转不产生任何剪枝。收尾回扣：现在你能解决开场那个问题了——把"后铺盖前铺"翻译成"从后往前找"，就是本知识点的全部内容。

### 4. 周期与取模

前置依赖：[[#1. 枚举的四要素]]（周期即候选集合按时间折叠）
后续衔接：同余与快速幂类周期题（库内暂无对应笔记，先以文字锚定）

**① 它解决什么问题**

很多题目里的序列是循环的：出拳有节奏、灯有规律地亮灭、动作按套路重复。直接把 $10^9$ 轮全模拟一遍必超时。这个知识点解决：如何用取模把"第 i 轮"映射到"周期内第几位"，只模拟一个周期。性质：把与轮数成正比的复杂度压成与周期长度成正比。

**② 直觉理解**

日历就是周期查询：问"第 1000 天是星期几"，没有人会一天天数到 1000，大家算 $1000 \bmod 7$ 再查表。取模循环做的正是这件事——把无限长的天数轴折叠进 7 格的小表里。

**③ 原理与推导**

设序列 $a_0, a_1, \dots, a_{p-1}$ 之后不断重复（周期为 p）。第 $i$ 轮（从 0 数起）用到的元素是 $a_{i \bmod p}$。为什么成立：$i = qp + r$（$0 \le r < p$），前 q 个完整周期恰好消耗 $qp$ 个元素，第 i 轮落在下个周期的第 r 位，而新周期第 r 位与原序列 $a_r$ 相同——这就是周期的定义。

用 P1328 的具体数字跑一遍：小 A 出拳周期 na=3（如 [2, 4, 0]），小 B 周期 nb=5。第 7 轮（i 从 1 数）：小 A 用 `a[(7-1) % 3] = a[0]`，小 B 用 `b[(7-1) % 5] = b[1]`。源码用自增指针实现同一件事：每轮 `x = (x + 1) % na`，指针在周期内打转，效果与取模完全一致。

**④ 代码演示**

P1328 核心逻辑（取自源文件 P1328.cpp，得分表与读入省略，完整版见源文件 P1328.cpp）：

```cpp
int x = 0, y = 0, suma = 0, sumb = 0;   // x、y 是两人当前的周期内指针
for (int i = 1; i <= n; i++) {
    suma += f[a[x]][b[y]];   // f[A][B]=1 表示 A 赢 B
    sumb += f[b[y]][a[x]];   // 反查一张表即可得到 B 的得分
    x = (x + 1) % na;        // 周期推进：越界回 0
    y = (y + 1) % nb;
}
printf("%d %d\n", suma, sumb);
```

设计动机：为什么不预先算出周期长度再算最小正周期？题目只要求 n 轮结果（$n \le 200$），逐轮推进 O(n) 已足够；预计算周期只在与极大战役（课件提到 n 可到 $10^9$ 的变体）时才需要。

**错误写法对照**

```diff
- int v = a[i % p];        // 坑1：第 i 轮从 1 数起却忘减 1 → 第 1 轮取到 a[1]，整体错位 → WA
+ int v = a[(i - 1) % p];  // 修复：先约定轮次起点，再写取模式
- y = (y + 1) % na;        // 坑2：小 B 的指针用小 A 的周期取模 → 越界访问 → RE
+ y = (y + 1) % nb;        // 修复：各自独立指针、各自独立周期（x 对 na，y 对 nb）
```

**⑤ 典型应用**

- P1328 生活大爆炸版石头剪刀布（洛谷）：两人出拳周期不同，逐轮取模推进，$O(n)$ 完成全部对局。
- 自编迁移题（自编）：灯串初始全灭，第 1 秒操作 a[0]，第 2 秒 a[1]……操作序列周期为 p，共 $10^9$ 秒，问第 $10^9$ 秒结束时每盏灯状态（操作为翻转）。建议先独立做，再对照题解。

  题解：$10^9$ 秒逐个模拟是 $10^9$ 次，贴着上限且含取模，危险。改为：完整周期数 $q = \frac{10^9}{p}$，每个位置 i 被翻转 $\lfloor \frac{10^9 - 1 - i}{p} \rfloor + 1$ 之类可 $O(p)$ 统计的次数，翻转次数为奇数则亮。核心仍是"取模折叠时间轴"，复杂度从 $O(10^9)$ 降到 $O(p)$。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** 下标从 1 数起却忘了减 1：第 i 轮应取 `a[(i-1) % p]`，写成 `a[i % p]` → 第 1 轮取到 a[1] → 整体错位 → WA。正确写法：先约定"第几轮从 0 还是 1 数"，再写取模式。

> [!caution]
> **【易错】** 两人（或多方）周期不同却共用一个取模 → 指针越界访问 → RE。正确写法：各自独立指针、各自独立周期取模（如源码 x 对 na、y 对 nb）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 对局循环不执行 → 输出 0 0
> 2. 单元素：n=1，na=nb=1，双方同拳 → f[同拳][同拳]=0 → 输出 0 0
> 3. 全相同：n=200，na=nb=1，每轮同拳 → 200 轮全平局 → 输出 0 0
> 4. 严格递增：不适用：出拳序列是周期结构，单调性无语义
> 5. 严格递减：不适用：同上
> 6. 极值：n=10^9（极大战役变体），na=nb=1，f[a[0]][b[0]]=1 → 每轮 suma 加 1 → 输出 1000000000 0（取模指针 O(1) 推进，此规模逐轮模拟必 TLE）

结论失效条件：序列不是严格周期（如带随机扰动、前缀预热）时，直接取模会错，需先手动模拟前若干轮确认周期起点。收尾回扣：现在你能解决开场那个问题了——出拳节奏就是周期，取模就是日历，$10^9$ 轮对局被一张 5×5 得分表加两个取模指针吃完。

### 5. 边界模拟（四边界收缩）

前置依赖：[[#1. 枚举的四要素]]（模拟是"逐候选判定"的扩展形态）
后续衔接：[[前缀和与差分]]（二维网格上的预处理工具，主题链下一站）

**① 它解决什么问题**

模拟题最怕方向多、边界乱。螺旋矩阵是代表：按"右-下-左-上"绕圈填数，转着转着就越界或重复访问。这个知识点解决：如何用四个边界变量把"一圈"变成"四条边"，每填完一条边就把对应边界向内收缩一格，让循环条件自动终止。性质：四边界法把二维绕圈问题化为四个一维循环，无遗漏、无重复。

**② 直觉理解**

想象裁纸：一张 n×n 的纸，沿着最外圈剪一圈，纸变小一圈；再剪一圈，又小一圈……每剪一圈，纸的四条边各退一格。剪到纸没有了（或只剩中间一格），过程结束。四个边界变量 t、b、l、r 就是这张不断变小的纸的四条边。

**③ 原理与推导**

为什么四条边各退一格就保证不重不漏？用不变式论证：填到第 k 圈开始时，未填区域恰是行 $[t, b]$、列 $[l, r]$ 的矩形（k 从 0 起，初始 $t=l=0$，$b=r=n-1$）。这一圈内所有格子分属四条边且仅属于一条边：上行属于 t 行、右列属于 r 列、下行属于 b 行、左列属于 l 列——四个一维循环遍历这四条边，恰好覆盖整圈。填完后 t+1、r-1、b-1、l+1，矩形缩小一圈，不变式保持。当矩形为空（t > b 或 l > r）时终止。

用 n=3 具体跑一遍：

```text
t=0 b=2 l=0 r=2  上行(0,0..2)=1 2 3   t=1
                右列(1..2,2)=4 5     r=1
                下行(2,1..0)=6 7     b=1
                左列(1..1,0)=8       l=1
t=1 b=1 l=1 r=1  上行(1,1..1)=9      t=2
                右列 i=2..1 空转     r=0
                下行 i=0..1 空转     b=0
                左列 i=0..2 空转     l=2
t=2 > b=0 终止
```

结果矩阵第一行 1 2 3、第二行 8 9 4、第三行 7 6 5，与 LC 59 样例一致。

**④ 代码演示**

LC 59 核心逻辑（取自源文件 LC59.cpp。相对源文件 LC59.cpp 的改动：补 `#include <vector>`——源文件使用了 vector 却未包含此头文件，直接编译报错 `'vector' does not name a type`）：

```cpp
#include <cstdio>
#include <vector>
using namespace std;
vector<vector<int> > mat(15, vector<int>(15));   // 也可用普通二维数组
int main() {
    int n; scanf("%d", &n);
    int t = 0, b = n - 1, l = 0, r = n - 1, num = 1;
    while (num <= n * n) {                 // 终止：所有格子填完
        for (int i = l; i <= r; i++) mat[t][i] = num++;  // 上行：左到右
        t++;                               // 上边界内缩
        for (int i = t; i <= b; i++) mat[i][r] = num++;  // 右列：上到下
        r--;                               // 右边界内缩
        for (int i = r; i >= l; i--) mat[b][i] = num++;  // 下行：右到左
        b--;                               // 下边界内缩
        for (int i = b; i >= t; i--) mat[i][l] = num++;  // 左列：下到上
        l++;                               // 左边界内缩
    }
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) printf("%d ", mat[i][j]);
        printf("\n");
    }
    return 0;
}
```

设计动机：终止条件用 `num <= n*n` 而不是 `t <= b && l <= r`，因为空转的内层循环（n=3 第二圈的四条边有三条空转）不会出错、也无需单独判断奇偶中心格——用计数器终止让代码完全不用特判 n 的奇偶。

**执行追踪表**（数据取②节 n=3 推演）

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|------|---------|---------|------|------|
| 1 | 上行 (0,0..2) | t=0 b=2 l=0 r=2，num=1 | 沿 t 行左到右填 3 格，t++ | mat 第 0 行 = 1 2 3，t=1 |
| 2 | 右列 (1..2,2) | t=1 b=2 l=0 r=2，num=4 | 沿 r 列上到下填 2 格，r-- | mat[1][2]=4、mat[2][2]=5，r=1 |
| 3 | 下行 (2,1..0) | t=1 b=2 l=0 r=1，num=6 | 沿 b 行右到左填 2 格，b-- | mat[2][1]=6、mat[2][0]=7，b=1 |
| 4 | 左列 (1..1,0) | t=1 b=1 l=0 r=1，num=8 | 沿 l 列下到上填 1 格，l++ | mat[1][0]=8，l=1 |
| 5 | 上行 (1,1..1) | t=1 b=1 l=1 r=1，num=9 | 沿 t 行填 1 格，t++ | mat[1][1]=9，t=2 |
| 6 | 右列 (2..1,1) | t=2 b=1 l=1 r=1，num=10 | i 从 2 到 1 空转，r-- | 无填入，r=0 |
| 7 | 下行 (0..1,0) | t=2 b=1 l=1 r=0，num=10 | i 从 0 起不满足 i>=1，空转，b-- | 无填入，b=0 |
| 8 | 左列 (1..2,0) | t=2 b=0 l=1 r=0，num=10 | i 从 0 起不满足 i>=2，空转，l++ | 无填入，l=2 |
| 9 | — | t=2 > b=0 | num=10 > n*n=9，while 退出 | 输出 1 2 3 / 8 9 4 / 7 6 5 |

**错误写法对照**

```diff
- if (t == b && l == r) mat[t][l] = num++;   // 坑1：奇数 n 的中心格手动特判失误 → 重复填或漏填 → WA
+ while (num <= n * n) { /* 四条边循环 */ }  // 修复：num 总闸免特判，空转循环天然安全
- r--;                                        // 坑2：先缩右边界再填右列
- for (int i = t; i <= b; i++) mat[i][r] = num++;   // 最右列漏填 → WA
+ for (int i = t; i <= b; i++) mat[i][r] = num++;   // 修复：每条边"先填、后缩"
+ r--;
```

**⑤ 典型应用**

- LC 59 螺旋矩阵 II（力扣）：本知识点主例，n×n 顺时针填数。
- LC 54 螺旋矩阵（力扣，同族题）：n×m 长方形按螺旋顺序读出，同一套四边界收缩，只是矩形非正方形，收缩后同样成立。
- 自编迁移题（自编）：m×n 矩阵从外圈向内、但**逆时针**填数。建议先独立做，再对照题解。

  题解：把源码四条边的顺序改为"左列(上到下)-下行(左到右)-右列(下到上)-上行(右到左)"，每条边填完同样收缩对应边界。正确性论证与顺时针完全同构——不变式只依赖"四条边不重不漏覆盖一圈"，不依赖绕向。复杂度 $O(mn)$。

**⑥ 坑点与边界**

> [!caution]
> **【易错】** n 为奇数时中心格重复填或漏填：有人手写四条边时对最后"单行单列"特判失误 → 中心格被填两次或为 0 → WA。正确写法：像源码一样用 `num <= n*n` 做总闸，空转循环天然安全，中心格在最后一圈的"上行"被恰好填一次。

> [!caution]
> **【易错】** 收缩顺序错：先填右列再内缩右边界是对的，若先 `r--` 再填 → 最右列漏填 → WA。正确写法：每条边"先填、后缩"，四步固定顺序背诵。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → num=1 > 0=n*n，while 不执行 → 无输出行（0×0 矩阵）
> 2. 单元素：n=1 → 第一圈上行填 mat[0][0]=1，num=2 > 1 退出 → 输出 1
> 3. 全相同：不适用：本算法输入只有整数 n，没有"重复元素"的序列概念
> 4. 严格递增：不适用：同上（输入无序列）
> 5. 严格递减：不适用：同上
> 6. 极值：n=46340 → n*n=2147395600 仍在 int 上限内，num <= n*n 比较安全；n=46341 → n*n 溢出为负值，循环提前退出 → 需 long long 或题目保证 n 更小（本篇 n ≤ 100，安全）

数据范围与复杂度上限：每个格子恰好写入一次，$O(n^2)$ 时空均为最优；n ≤ 100 时矩阵开 `mat[105][105]` 余量充足。结论失效条件：四边界法假设"填充路径严格绕圈"，若题目路径不规则（蛇形走位、马步跳跃），需另行设计遍历器。收尾回扣：现在你能解决开场那个问题了——把"绕圈"翻译成"四条边 + 各退一格"，模拟就变成了四个不会出错的一维循环。

## 四、总结与自测

- 枚举四要素：集合、条件、范围、顺序，缺一不可；正确性由穷举保证，效率由范围与顺序决定。
- 1 秒约 $10^8$ 次操作：先看数据范围反推允许复杂度，再决定写哪档算法；贴上限的写法留 2 倍余量。
- 枚举顺序即剪枝：题目要"最上层/最终态"时，按覆盖关系反转顺序、找到即停，最坏不变、平均大降。
- 周期序列用取模折叠：第 i 轮取 `a[(i-1) % p]`，多周期各自独立指针。
- 模拟二维绕圈用四边界收缩：四条边覆盖整圈不重不漏，`num <= n*n` 免特判。
- 前置概念清单：循环与数组（本篇所有代码骨架）、结构体或平行数组存矩形（P1003）、二维数组下标含义（LC59）、取模运算（知识点 4）。
