## 一、为什么需要它

先用会超时的方式做一遍 P1090 [NOIP2004] 合并果子：n 堆果子，每次把两堆合成一堆，代价是两堆重量之和，求合成一堆的最小总代价。直觉做法是"每次合并后重新排序，最前面两堆就是最小的"——课件 slide 2 原话算过账：单次排序 $O(n \log n)$、要排 $n-1$ 次，总 $O(n^2 \log n)$；$n \le 10^4$ 时约 $10^9$ 量级，超时。**碰壁的根源：找"最小的两堆"这件事做重了。** 贪心的破法分两层：决策层照旧贪——每次合并当前最小的两堆（为什么对，用知识点 1 的交换论证说清）；实现层换工具——优先队列把"找最小"降到 $O(\log n)$，与 [[栈与队列]] 里的 priority_queue 正面呼应。

本篇讲 4 个知识点：贪心的本质与交换论证、P1090 合并果子、P4995 跳跳！、贪心的危险。顺序理由：先有证明套路（知识点 1）再上例题（2、3），最后专门讲翻车场景（4）——贪心是"写了就过"和"全错"两极分化最严重的思想，防翻车和会用同等重要。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 贪心的本质与交换论证：局部最优凭什么到全局最优

前置依赖：[[复杂度分析与递归]]（排序复杂度 $O(n \log n)$ 的账）、排序（C 基础）
后续衔接：[[#2. P1090 合并果子：优先队列贪心与哈夫曼]]、[[#3. P4995 跳跳！：排序与高低交替]]、[[#4. 贪心的危险：反例意识与转 DP 信号]]

**① 它解决什么问题**

课件 slide 1 定义：贪心法把一个最优决策过程变成**多步决策过程**，每步总做出"当前看来最好"的选择；它不从全局最优考虑，所做的是**局部最优选择**。适用题型特征：求最值 + 可分步 + 每步局部最优。关键性质：无决策回溯、单步代价通常 $O(1)$ 到 $O(\log n)$，总复杂度往往就是"每步怎么找到局部最优"的复杂度。slide 1 同时给出警告原话："并不是所有的时候贪心法都能获得最优解，所以一般使用贪心法的时候，都要确保自己能证明其正确性"——证明工具就是本节主角**交换论证**。

**② 直觉理解**

模型级类比：**排队办事只看窗口**。每到一个岔路口只挑眼前最短的队排，从不回头看——贪心。它什么时候真的最优？当"任何最优答案都能被逐步交换成贪心答案、且交换不使答案变差"时。用具体数字跑一遍（slide 1 的矩阵题）：3 行 4 列矩阵每行选一个数使总和最大——每行独立，选本行最大即可；加约束"互不同列"后最大值可能撞列，必须有人让位——**让谁让、让多少，正是需要证明而不是想当然的地方**。

**③ 原理与推导**

交换论证的标准套路（排序类贪心的通用证明模板，本篇知识点 2、3 都要用它）：1. 设贪心方案为 G、任一最优方案为 O；2. 找到 G 与 O 的**第一处不同**；3. 把 O 里的局部安排**交换成 G 的安排**，证明交换后总代价不变差；4. 反复交换，O 被逐步改造成 G 而每步不变差——所以 G 也是最优。为什么成立？因为交换只动两步决策的相对位置，其余原封不动；只要"局部更优的那步"交换后承担的代价不增，总代价就不增——它把"全局最优"这个说不清的命题，压缩成"相邻两步交换不变差"这个能算的命题。

以 LC2611 [力扣 2611] 小老鼠吃奶酪为例走完整流程（LC2611.cpp + slide 3）：1 号鼠必须恰吃 k 块奶酪，第 i 块给 1 号得 $r_1[i]$、给 2 号得 $r_2[i]$，求总得分最大。先全给 2 号得 $\sum r_2[i]$；把第 i 块改给 1 号，得分变化恰为差值 $r_1[i] - r_2[i]$。答案 = 基线 + 最大的 k 个差值之和。证明"选差值最大的 k 块"：设最优方案中差值更大的 i 没被选而更小的 j 被选，把 j 换成 i，总分变化 $d_i - d_j > 0$，与"最优"矛盾——最简形态的交换论证。复杂度：求差 $O(n)$、排序 $O(n \log n)$，瓶颈在排序。

**④ 代码演示**

块一「核心代码」，取自源文件 LC2611.cpp（改动：仅删去与评测无关的输入回显，逻辑逐行原样）。逐段讲：第一循环立"全给 2 号"的基线；差值数组把"换谁"压缩成一个可比的数；排序后从尾部取 k 个——排序让"最大的 k 个"能被一次性收割，这是排序类贪心的标准形态：

```cpp
int miceAndCheese(vector<int>& reward1, vector<int>& reward2, int k) {
  int n = reward1.size();
  vector<int> d(n);        // d[i]：第 i 块改给 1 号鼠的得分变化（C 等价：int d[N];）
  int ans = 0;
  for (int i = 0; i < n; i++) {
    d[i] = reward1[i] - reward2[i];   // 差值：换人决策的唯一依据
    ans += reward2[i];                // 先假定全给 2 号
  }
  sort(d.begin(), d.end());           // 复杂度瓶颈：O(n log n)
  for (int i = n - 1; i >= n - k; i--) // 取最大的 k 个差值
    ans += d[i];
  return ans;
}
```

块二「执行追踪表」（官方示例 1：reward1 = [1,1,3,4]，reward2 = [4,4,1,1]，k=2）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | i=0..1 | d=[-3,-3]，ans=8 | 两个差值 -3，累加 r2 | 基线累积 |
| 2 | i=2..3 | d=[-3,-3,2,3]，ans=10 | 差值 2、3，累加 | 基线 10 |
| 3 | 排序后 | d=[-3,-3,2,3] | 取尾部 k=2 个 | ans=10+3+2=**15** |

块三「错误写法对照」：

```diff

- sort(idx by reward1 降序); 选前 k 个;   // 反例：r1=[5,4], r2=[4,4], k=1 → 选第 1 块得 5；
+ // 对：按差值 r1[i]-r2[i] 降序选         // 但选第 2 块得 4 且 2 号仍拿 4，总分 8 > 5+0=5？（自测：基线 8 + 差值 -1=7 < 8+0=8，选错块直接丢 1 分）

+ for (int i = n - 1; i >= n - k; i--)    // 恰好 k 个：下标 n-1, n-2, ..., n-k
```

- 真题：LC2611 小老鼠吃奶酪（slide 3 完整推导 + LC2611.cpp），官方示例 1 实测输出 15（附录 B-5）。

**⑥ 坑点与边界**

> **【易错】** 贪心的比较对象选错：按"自身大小"而不是按"选择带来的变化量"排。后果是样例可能全过、对抗数据全错（④对照坑 1）。

> **【注意】** 交换论证只证了"排序依据"这一件事，基线与取法各有各的依据。另外若 reward 至 $10^9$、n 至 $10^5$，总和至 $10^{14}$ 须 long long——这一段我不确定官方数据是否卡 int，按"预留 long long"处理更稳。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 且 k=0 → 两个循环零次执行，返回 0（预期：0，不崩）。
> 2. 单元素：n=1, k=0 → ans=r2[0]；k=1 → ans=r1[0]（预期：两种归属各取所得）。
> 3. 全相同：r1 与 r2 全等 → 差值全 0，答案 = 基线（预期：给谁都一样，k 任意）。

> 5. 严格递减：差值递减 → 取的是原序头部 k 个的翻转（预期：与手推一致）。

### 2. P1090 合并果子：优先队列贪心与哈夫曼

前置依赖：[[#1. 贪心的本质与交换论证：局部最优凭什么到全局最优]]、[[栈与队列]]（priority_queue 的接口与堆本质）
后续衔接：[[哈夫曼树]]（同一贪心的树形态）、[[#4. 贪心的危险：反例意识与转 DP 信号]]

**① 它解决什么问题**

洛谷 P1090 [NOIP2004] 合并果子（slide 1-2 例题）：n 堆果子各有重量，每次合并两堆代价为重量和，求合成一堆的最小总代价。贪心策略（slide 2 原话）："要使得总体力值最小，需要每次合并的体力值尽可能的小，所以每次合并两堆数量最少的果子。"关键性质：每次取最小两堆 + 插入新堆，优先队列单步 $O(\log n)$，共 $n-1$ 次合并，总复杂度 $O(n \log n)$（slide 2 明确给出该账目）。

**② 直觉理解**

模型级类比：**滚雪球先滚小的**。两堆果子无论哪两堆合并，总重不变；差别只在"每堆被计入代价的次数"——轻堆早点合并，让重堆晚进场、少被重复计费。用具体数字跑一遍（官方样例 n=3：1、2、9）：先并 1+2=3（付 3）；再并 3+9=12（付 12）；总代价 15。反过来先并 2+9=11（付 11）、再并 11+1=12（付 12），总 23——轻的堆被拖到最后，每一步都在为大数陪跑。

**③ 原理与推导**

交换论证：设 G 为"每次合并最小两堆"的方案，O 为任一最优方案。若 O 的首次合并不是全局最小的两堆 x、y，把它换成并 x、y，后续把 x+y 当普通元素继续——交换后每堆在合并树中的深度至多与原来持平（x、y 最小，顶替他人位置只会让更大的数下沉）。所以存在含"先并最小两堆"的最优方案；去掉这次合并，剩下是规模减一的同类问题——归纳成立。

为什么复杂度能压到 $O(n \log n)$ 而不是课件的 $O(n^2 \log n)$？原因在"找最小两堆"的数据结构选择：重排整个数组是 $O(n \log n)$，而优先队列只维护"最小者在上"的偏序，取最小 $O(1)$、插入 $O(\log n)$——**这是设计动机：我们只需要偏序（谁最小），不需要全序（全排好），只为偏序付费**。这棵"每次合并最小两堆"长出来的合并树，正是**带权路径长度最小的二叉树——哈夫曼树**：每个果子重量 = 叶权，总代价 = $\sum$ 叶权 × 叶深，最小化它就是 [[哈夫曼树]] 的定义本身——本节贪心与哈夫曼构造是同一件事的两种叙述。

**④ 代码演示**

块一「核心代码」，取自源文件 P1090.cpp（逐行原样，仅注释增补）。逐段讲：主循环恰好 $n-1$ 次（每轮堆里少一堆、多一个合成堆，净减 1）；`greater<>` 是把默认大根堆翻成小根堆的关键参数：

```cpp
#include <iostream>
#include <queue>
using namespace std;
int n;
long long ans, x, y;                       // 10^4 堆各 2×10^4：n-1 次累加至 2×10^8——int 贴线，统一 long long
priority_queue<long long, vector<long long>, greater<long long> > q;   // greater：小根堆（C 等价：手写数组+每次线性找最小）
int main() {
  cin >> n;
  for (int i = 1; i <= n; i++) { cin >> x; q.push(x); }   // 建堆：O(n log n)
  for (int i = 1; i < n; i++) {            // 共 n-1 次合并
    x = q.top(); q.pop();                  // 最小堆顶 1：O(1)
    y = q.top(); q.pop();                  // 最小堆顶 2：O(1)
    ans += x + y;                          // 本次合并代价
    q.push(x + y);                         // 新堆入队：O(log n)
  }
  cout << ans << endl;
  return 0;
}
```

块二「执行追踪表」（官方样例 n=3，输入 1 2 9；建堆后 q=[1,2,9]，以小根堆形式记，队首在左）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | 第 1 轮 | q=[1,2,9] | 取 1、2，ans=3 | push(3)，q=[3,9] |
| 2 | 第 2 轮 | q=[3,9] | 取 3、9，ans=15 | push(12)，q=[12] |
| 3 | 收尾 | q=[12] | 堆中仅 1 堆 | 输出 15 |

块三「错误写法对照」：

```diff
- priority_queue<long long> q;                    // 坑1：忘写 greater——默认大根堆，每次合并最大两堆：
+ priority_queue<long long, vector<long long>, greater<long long> > q;   // 小根堆；样例 1 2 9 会输出 23 而非 15（答案错）
- for (int i = 1; i <= n; i++) { ... }            // 坑2：合并循环写成 n 次——第 n 次时堆里只剩 1 堆，两次 pop 越界（RE）
+ for (int i = 1; i < n; i++) { ... }             // 恰好 n-1 次：每轮净减一堆
```

**⑤ 典型应用**

- 真题：P1090 合并果子本体（slide 1-2 + P1090.cpp），官方样例实测输出 15（附录 B-5）。
- 迁移题（自编，思想同 [[哈夫曼树]] 的 k 叉哈夫曼）：改成"每次最多 k 堆合一"求最小总代价。建议先独立做，再对照题解：仍是哈夫曼 k 叉化，若 $(n-1) \bmod (k-1) \ne 0$ 需补重量为 0 的虚堆凑满，保证每次恰好 k 堆合一次；n 至 $10^5$ 的加强版为 P6033（题号真实，资料未覆盖，属补充）。

**⑥ 坑点与边界**

> **【易错】** 小根堆参数漏写 `greater<long long>`。默认大根堆方向完全相反，样例 1 2 9 输出 23 ≠ 15（④对照坑 1）。

> **【易错】** 合并次数写 n 次而不是 n-1 次。最后一次 pop 时堆中只有 1 个元素，pop 两次越界 RE（④对照坑 2）。

> **【注意】** ans 开 long long：n=$10^4$、每堆 $2\times10^4$ 时约 $2\times10^8$，int 贴线；同族题代价带平方（见知识点 3）int 必炸，习惯性 long long 是廉价保险。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 读入循环零次，合并循环零次，输出 0（预期：0，不崩）。
> 2. 单元素：n=1 → 合并循环零次，输出 0（预期：无需合并，代价 0）。
> 3. 全相同：n=4 全 5 → 5+5=10、5+5=10、10+10=20，ans=40（预期：10+20=30？自测：共三次合并 10+10+20=40）。
> 4. 严格递增：1 2 3 4 → 3、7、15 逐层，ans=25（预期：与手推一致）。
> 5. 严格递减：4 3 2 1 → 与递增同一结果 25（预期：堆只认值不认输入顺序）。
> 6. 极值：n=$10^4$、每堆 $2\times10^4$ → ans 约 $2\times10^8$，int 未炸但贴线；把堆数换成 $10^5$ 则约 $2\times10^{10}$，int 必炸（预期：long long 版正确，专查溢出）。

回扣开场：暴力重排的 $O(n^2 \log n)$ 被"优先队列 + 只付偏序的钱"降到 $O(n \log n)$。现在你能解决开场那个合并果子了——用的是知识点 1 的交换论证（为什么并最小两堆）与本节的堆（怎么快速找到它们）。

### 3. P4995 跳跳！：排序与高低交替

前置依赖：[[#1. 贪心的本质与交换论证：局部最优凭什么到全局最优]]、排序（C 基础）
后续衔接：[[#4. 贪心的危险：反例意识与转 DP 信号]]、[[哈夫曼树]]（同为"差值累积"型贪心的另一道真题）

**① 它解决什么问题**

洛谷 P4995 跳跳！（slide 2 例题）：小跳蛙从地面（高 0）出发，跳到每块石头上各一次，从高 a 跳到高 b 耗体力 $(a-b)^2$，求**体力总耗费最大**。贪心策略（slide 2 原话）："先跳到最高的柱子，再跳到最低的柱子，再跳到次高的柱子，再跳到次低的柱子……"关键性质：排序 $O(n \log n)$ 主导复杂度，$n \le 300$ 内轻松通过；代价是平方项，答案用 long long 存（素材 P4995.cpp 第 18 行即 `long long ans`）。

**② 直觉理解**

模型级类比：**来回拉弓**。每跳一次的代价是高度差的平方——差越大，代价按平方放大；要总耗费最大，就该每次"拉满弓"：最高与最低来回横跳。用具体数字跑一遍（官方样例 2：n=3，高度 6 3 5）：加地面排序后为 [0,3,5,6]，0→6 付 36、6→3 付 9、3→5 付 4，合计 49 与官方一致。若不交替而按 0→6→5→3 跳：36+1+4=41，白丢 8——平方项对"大差值"的偏爱比直觉更狠。

**③ 原理与推导**

交换论证：设贪心跳序为"高、低、次高、次低……"，任取最优跳序 O。把 O 中未按"与当前极值配对"的相邻两跳与贪心所用的两块石头交换，可以证明总代价不变差。关键是**平方函数的凸性**：对 $a < b \le c \le d$，"最大减最小 + 次大减次小"的和 $\ge$ 任何其他配对的和（完整代数展开较长，给结论与复核方法：用具体数字代入，如 a=0,b=3,c=5,d=6 时左式 $(6-0)^2+(5-3)^2=40 \ge$ 右式 $(6-5)^2+(3-0)^2=10$）。反复交换，O 收敛为贪心跳序。复杂度：排序 $O(n \log n)$ 主导，扫描 $O(n)$。设计动机：为什么排序后用双指针而不是真的"跳来跳去"？因为跳序只是叙事，本质是把排序数组按"尾、首、次尾、次首……"的顺序读出——两个指针就够了，素材 P4995.cpp 的 `l++ / r--` 正是这个双指针。

**④ 代码演示**

块一「核心代码」，取自源文件 P4995.cpp（逐行原样，仅注释增补）。逐段讲：把地面 h[0]=0 混进排序，"从地面起跳"就统一成普通跳跃；每轮 while 做两跳（高→低、低→次高），指针向中间收拢：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;
int n;
int h[305];                       // n<=300（题面），开 305
int main() {
  cin >> n;
  for (int i = 1; i <= n; i++) cin >> h[i];
  h[0] = 0;                       // 边界：地面高度 0 也要进排序
  sort(h, h + n + 1);             // 排 [0, n] 共 n+1 个元素——含地面
  int l = 0, r = n;               // 双指针：左=最矮，右=最高
  long long ans = 0;              // 平方代价，必须 long long
  while (l < r) {
    ans += (h[r] - h[l]) * (h[r] - h[l]);   // 高→低一跳
    l++;
    ans += (h[r] - h[l]) * (h[r] - h[l]);   // 低→次高一跳
    r--;
  }
  cout << ans << endl;
  return 0;
}
```

块二「执行追踪表」（官方样例 2：n=3，输入 6 3 5；排序后 h=[0,3,5,6]）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | l=0, r=3 | h=[0,3,5,6]，ans=0 | 跳 6-0=36 | ans=36，l=1 |
| 2 | l=1, r=3 | 同上 | 跳 6-3=9 | ans=45，r=2 |
| 3 | l=1, r=2 | 跳 5-3=4 后 l==r 退出 | ans=49 | 输出 49 |

块三「错误写法对照」：

```diff
- sort(h, h + n);            // 坑1：漏排地面 h[0]——若输入含 0 高度或首跳未含地面，起跳代价算错（答案错）
+ h[0] = 0; sort(h, h + n + 1);   // 素材原样：地面与石头一起排，起跳统一处理
- int ans = 0;               // 坑2：平方代价上界 (10^4)^2 × 300 = 3×10^10，int 上限约 2.1×10^9——必炸（答案错，本题实测重灾区）
+ long long ans = 0;         // 素材原样：long long 扛平方累积

+ while (l < r) { ... }      // 素材原样：每轮消耗两块石头，l==r 即收尾
```

**⑤ 典型应用**

- 真题：P4995 跳跳！本体（slide 2 + P4995.cpp），官方样例 1（2 1 → 5）与样例 2（6 3 5 → 49）实测均通过（附录 B-5）。
- 迁移题（自编）：n 根木棒两两连接费用为长度和的平方，合成一根的最小费用——把"最大"改成"最小"，贪心方向整体翻转：每次合并当前最短两根，即知识点 2 的合并果子原题结构。

**⑥ 坑点与边界**

> **【易错】** 排序区间漏掉地面 h[0]。起跳是"从 0 跳到某石头"，不把 0 排进去就要单独特判起跳，容易漏（④对照坑 1）。

> **【易错】** ans 用 int。平方项 × n 的上界 $3\times10^{10}$ 远超 int，本题实测最常见 WA 就是它（④对照坑 2）。题面保证高度互异；若允许同高，交替策略依然正确（差值 0 排中间即可），追踪表出现"零差跳"不是 bug。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → while 不进入，输出 0（预期：0，不崩）。
> 2. 单元素：n=1，h={7} → 排序后 [0,7]，一轮 while：36+…自测 (7-0)²=49（预期：只跳一次 7²，输出 49）。
> 3. 全相同：本题保证互异，改用近似全同 {5,5+ε} → 基本零差跳，代价极小（预期：交替不放大错误）。
> 4. 严格递增：1 2 3 → [0,1,2,3]，0→3 付 9、3→1 付 4、1→2 付 1，ans=14（预期：与手推一致）。
> 5. 严格递减：3 2 1 → 排序后与递增同结果 14（预期：堆只认值序）。
> 6. 极值：n=300、全 $10^4$ 附近 → ans 量级 $3\times10^{10}$（预期：long long 正确、int 溢出，专查溢出）。

回扣开场：现在你能解决"怎么把体力耗费拉满"了——用的是知识点 1 的交换论证（凸性保证极端配对最优）与本节的排序双指针（怎么把交替跳落成 O(n) 扫描）。

### 4. 贪心的危险：反例意识与转 DP 信号

前置依赖：[[#1. 贪心的本质与交换论证：局部最优凭什么到全局最优]]
后续衔接：[[线性DP]]（贪心失效后的标准退路，同批文字锚定）、[[区间DP]]（决策带区间依赖时的另一条退路）

**① 它解决什么问题**

slide 1 的警告是本节题眼："并不是所有的时候贪心法都能获得最优解。"本节回答两个问题：什么样的贪心**看起来对其实是错的**；以及什么信号出现时，应该放弃贪心转 DP。关键性质：贪心成立的充要前提是"局部最优选择能被证明不会排除全局最优"（贪心选择性质 + 无后效性），两者缺一，贪心给出的只是一个"过得去的解"，不是最优解。

**② 直觉理解**

模型级类比：**只看眼前的棋手**。每步吃对方最大的子，可能正好把己方主力送进包围圈。贪心的危险不在"想不出策略"，而在**策略能自圆其说**——越是讲得通的贪心，越需要主动找反例。用具体数字跑一遍（经典硬币反例，自编）：币值 {1, 3, 4} 凑 6，贪心每次拿最大面值得 4+1+1 共 3 枚，最优是 3+3 共 2 枚。原因：拿 4 这步"局部最优"堵死了两个 3 的路——**当前步的最优选择改变了后续可选的局面，且变得更差**。

**③ 原理与推导**

贪心失败的结构性原因拆开看是两条（slide 1 定义的推论）：1. **贪心选择性质不成立**——不存在任何一个最优解包含当前的局部最优选择，硬币反例就是这条：任何包含"4"的最优解都不存在；2. **决策之间不独立**——后面的决策受前面决策改变了的局面约束，矩阵选数题加上"互不同列"约束后开始变难，正是这条在起作用。

**转 DP 的信号**（按强度排序）：当前选择影响后续可选的**局面**而不只影响一个可加和的数值；题面出现"选或不选、容量限制、恰好 k 次、顺序约束"字眼；数据范围落在 $O(n^2)$ 或 $O(n \cdot V)$ 能过的区间——DP 的复杂度预算通常比贪心大一两个量级，出题人放宽数据范围往往就是在暗示贪心不可行。P4995 若把"体力最大"改成"恰好跳 k 次限制下的最优"，交替贪心就不再直接成立——**约束一加，同一个问题可能就从贪心题变成 DP 题**。

**④ 代码演示**

块一「核心代码」（自编演示：同一凑硬币问题的贪心版与 DP 版对照，面值 {1,3,4}）。逐段讲：DP 把"凑 6"拆成"凑 5、凑 3、凑 2 里最优的那个 + 1"，每一步保留所有可能，不被单步选择绑架——贪心输在方向，不输在码量：

```cpp
#include <iostream>
#include <algorithm>
#include <cstring>
using namespace std;
int main() {
  int m = 6, c[3] = {1, 3, 4};       // 反例目标：凑 6
  int g = 0, rest = m;               // 贪心版：每次拿最大面值
  for (int i = 2; i >= 0 && rest > 0; i--)
    while (rest >= c[i]) { rest -= c[i]; g++; }   // 6 -> 4+1+1，3 枚
  int f[10];                         // DP 版：f[j] = 凑出 j 的最少枚数（C 等价：int f[M];）
  memset(f, 0x3f, sizeof(f));
  f[0] = 0;
  for (int j = 1; j <= m; j++)       // 复杂度 O(m*3)
    for (int i = 0; i < 3; i++)
      if (j >= c[i]) f[j] = min(f[j], f[j - c[i]] + 1);
  cout << "greedy=" << g << " dp=" << f[m] << endl;   // 输出 greedy=3 dp=2
  return 0;
}
```

块二「执行追踪表」（DP 版，面值 {1,3,4}，m=6；f 初始全极大、f[0]=0）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | j=1..2 | f=[0,1,2,..] | 面值 1 只能逐格 | f[1]=1, f[2]=2 |
| 2 | j=3 | f[3]=1 | f[0]+1 经面值 3 | 3 一枚搞定 |
| 3 | j=6 | f[6]=2 | f[3]+1 经面值 3 | 3+3 两枚 |
| 4 | 对照 | — | 贪心=3 枚 | DP 少 1 枚 |

块三「错误写法对照」：

```diff
- cout << g << endl;               // 坑1：把贪心答案直接当最优提交——币值 {1,3,4} 凑 6 输出 3，正确答案 2（答案错）
+ // 先想反例：面值不成倍数关系时，拿最大面值可能堵死更优组合；面值成倍数（如 1,2,5,10）时交换论证才走得通
- // 反过来，看到"最值"一律上 DP 也是坑：P1090 若硬上 O(n^2) DP 会 TLE
+ // 决策顺序：先写交换论证，走不通再找反例，反例找到转 DP，走通了才写贪心
```

**⑤ 典型应用**

- 真题：LC2611（slide 3 + LC2611.cpp）作为"贪心成立"的对照面——它的差值排序能通过交换论证，所以敢用贪心；与硬币反例对照体会"有没有证明"的差别。
- 迁移题（自编，经典模型）：n 个活动占用同一会议室，问最多安排几个活动。建议先独立做，再对照题解：按结束时间升序排、能选就选——把最优解里"结束最晚的选中活动"换成贪心的"结束最早者"，不与任何活动冲突且给后面留更大空间，交换论证可证。

**⑥ 坑点与边界**

> **【易错】** "样例过了"当成"贪心对了"。贪心题的对抗数据专打局部最优，唯一防线是交换论证或找反例（slide 1 原话要求"确保自己能证明其正确性"）。

> **【注意】** 别把"这题是贪心"当成题目固有属性——加一个约束（互不同列、恰好 k 次、容量限制）就可能翻转为 DP 题；构造不了反例也写不出证明时，宁可多花时间写 DP，先对再快。

> [!example]-
> **边界数据集（凑硬币演示程序）**
> 1. 空输入：m=0 → 贪心 0 枚、DP f[0]=0（预期：两边一致为 0）。
> 2. 单元素：m=1 → 贪心 1 枚、DP 1 枚（预期：一致）。
> 3. 全相同：面值全 2、m=6 → 贪心 3 枚、DP 3 枚（预期：面值可整除时贪心退化后仍对）。
> 4. 严格递增面值 {1,3,4}：m=6 → 贪心 3、DP 2（预期：本节主反例复现）。
> 5. 递减场景：面值 {4,3,1} 同 m=6 → 贪心枚举顺序不影响结果，仍 3 枚（预期：贪心对输入顺序不敏感，错在策略本身）。
> 6. 极值：m=$10^9$、面值 {1,3,4} → 贪心 O(面值数) 仍瞬间出解但可能非最优；DP O(m) 内存时间双双爆炸（预期：识别 DP 的复杂度上限，也是贪心尚存的理由——先用小 m 验证贪心对不对）。

回扣开场：现在你手里有了一双"判断贪心真假"的眼睛——交换论证走通就用贪心，反例找到就转 [[线性DP]]。开场那道合并果子，你可以放心地说出"为什么并最小两堆是对的"了。

## 四、总结与自测

### 核心内容（一页纸速览）

- **贪心本质**：多步决策 + 每步局部最优（slide 1）；是否最优靠证明不靠感觉，标准工具是交换论证（取最优 O、找第一处不同、交换不变差、归纳收敛）；LC2611 即差值取最大 k 个、$O(n\log n)$，官方示例 1 答案 15。
- **P1090 合并果子**：每次并最小两堆，小根堆实现 $O(n\log n)$；合并树即 [[哈夫曼树]]；官方样例 1 2 9 答案 15。
- **P4995 跳跳！**：排序含地面 + 高低交替双指针，平方代价用 long long；官方样例 2（6 3 5）答案 49。
- **贪心的危险**：局部最优堵死全局（硬币 {1,3,4} 凑 6：贪心 3 枚 vs DP 2 枚）；转 DP 信号是决策依赖与约束打破独立性。
