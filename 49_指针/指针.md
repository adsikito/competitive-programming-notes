## 一、为什么需要它

先看一个你大概率写翻过车的程序（源 p20 课堂案例）：想把两个变量换值，写了 `void mySwap(int a, int b)`，调用后打印——`num1`、`num2` 纹丝不动。再比如源 p20 的 `func1(num)`，函数里 `v1++` 自增了，出来后 `num` 还是 100。**碰壁的根源：C++ 函数实参默认按值拷贝，函数拿到的是复印件，改复印件动不了原件。**

指针的破法一句话：**把变量的内存地址交给函数，函数顺着地址直接操作原件**。本篇讲 4 个知识点：地址与解引用（概念地基）、指针与数组（`a[i]` 的真面目）、指针传参（swap 真正换成功的原理）、指针事故（野指针与空指针——竞赛 RE 报错 0xC0000005 的头号来源）。顺序理由：概念（1）先于语法应用（2），函数用法（3）需要前两者垫底，排雷（4）收尾。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 地址与解引用：指针是什么

前置依赖：[[数据类型与内存表示]]（变量在内存里的字节布局与 int 占 4 字节）
后续衔接：[[#2. 指针与数组：a[i] 即 *(a+i)]]、[[#3. 指针传参：swap 为什么能换动原件]]、[[链表]]（结点之间的连接全靠指针）

**① 它解决什么问题**

源 p4 定义：**指针表示内存的地址，指针变量就是保存内存地址的变量**。计算机给内存每个字节编了号，程序靠编号精确定位某个字节——指针变量里装的就是这个编号。两个核心操作（源 p6）：`&x` 取变量 x 的地址；`*p` 解引用，顺着 p 存的地址找到那块内存。关键性质：解引用读写都是 $O(1)$；64 位系统下任何类型的指针变量本身都占 8 字节；指针的类型决定"顺着地址读几个字节、按什么格式解释"。

**② 直觉理解**

模型级类比：**酒店房间号**。变量是房间里的住客，地址是房号，指针是一张写着房号的卡片。拿着卡片（`p`）能找到房间；查卡片上房号对应的住客（`*p`）是解引用；把住客换人（`*p = 新值`）不必进房——凭卡片指挥前台办事。卡片本身也有自己的存放位置（二级指针 `pp = &p` 是"写着卡片放在哪个抽屉的卡片"）。

用具体数字跑一遍：`int num = 100;` 假设 num 住在 0x61FE14（示意地址）；`int* p = &num;` 让 p 存下 0x61FE14；`cout << *p` 顺地址找到 num 的 4 字节，按 int 解释，得 100；`*p = 200` 改写后，`num` 自己也变成 200——因为 `*p` 和 `num` 是同一块内存。

**③ 原理与推导**

为什么解引用必须带类型？源 p5 说 `type *varName;` 中 type 可以是任意类型。推导：地址只告诉你"从哪个字节开始"，不告诉你"读几个字节、怎么解释"。`int*` 解引用读 4 字节按补码解释，`double*` 读 8 字节按浮点解释——类型错了就读错。**设计动机：指针带类型，就是把"地址 + 解释方式"打包成一个整体**，让编译器能自动算出读写宽度。

二级指针（源 p15-17）：指针变量自己也是变量，也有地址，存指针地址的指针叫二级指针 `int** pp = &p;`，`*pp` 得到 p（一个地址），`**pp` 才得到 num。链表的"指向下一个结点"本质就是一级指针，本知识点是 [[链表]] 的地基回顾。

**④ 代码演示**

定义、取地址与解引用（取自源 p8 案例与 code.cpp，自编整理成可编译版）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;              // 普通变量：某块 4 字节内存里存着 100
    int* p = &num;              // 指针变量：存 num 的地址（& = 取地址）
    cout << &num << "\n";       // 打印 num 的地址（每次运行可能不同）
    cout << p << "\n";          // 与上一行相同：p 存的就是它
    cout << *p << "\n";         // 解引用：顺地址找格子，取出 100
    *p = 200;                   // 通过指针写：改的是 num 本尊
    cout << num << "\n";        // 输出 200（源 p8 案例同款）
    int** pp = &p;              // 二级指针：存指针 p 的地址（源 p15-16）
    cout << **pp << "\n";       // 解两次：还是 num 的 200
    return 0;
}
```

**执行追踪表**（num 初始 100，假设 num 地址为 0x61FE14）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | p = &num | num=100 | 取 num 地址存入 p | p = 0x61FE14 |
| 2 | *p（读） | num=100 | 顺地址读 4 字节按 int 解释 | 得 100 |
| 3 | *p = 200（写） | num=200 | 顺地址写 200 | num 本尊被改 |
| 4 | **pp（读） | p 与 num 均有效 | 先解 p 再解 num | 得 200 |

**错误写法对照**：

```diff
- int* p; *p = 100;        // 坑1：p 未初始化就解引用——p 里是栈上垃圾地址，写进随机内存，RE（0xC0000005 常客，知识点 4 详查）
+ int* p = nullptr;        // 暂不指向任何数据时先置空，用前再赋合法地址
- int* p2 = 100;           // 坑2：把整数 100 当地址——编译报错或造出非法指针；地址必须来自 & 或别的指针
+ int* p2 = &num;          // & 取地址才是合法来源
- double* pd = &num;       // 坑3：类型不匹配——解引用按 double 读 8 字节，num 只有 4 字节，读穿到隔壁变量（答案错）
+ int* pi = &num;          // 指针类型与所指变量类型一致
```

**⑤ 典型应用**

- 课堂案例：源 p8「定义指针变量指向 num，输出地址与值」——本知识点④即其完整版。
- 迁移题（自编）：读入三个整数，只用指针解引用（不直接用变量名）把它们排成升序输出。思路：`int* pa = &a;` 之后所有比较与交换都写成 `*pa`、`*pb` 形式，$O(1)$ 三次比较。
- 竞赛衔接：[[链表]] 手写版每个结点存 `next` 指针；函数出参、动态结构全部建立在本节"地址 + 解引用"上。

**⑥ 坑点与边界**

> **【易错】** 未初始化的指针直接解引用。`int* p;` 定义后 p 里是残留垃圾值，`*p` 读写随机内存——这是知识点 4 的头号事故源，定义即初始化是铁律。

> **【易错】** 指针类型与所指类型不一致。`double* pd = &num;` 解引用多读 4 字节，读到的"值"毫无意义（答案错），编译器只会给警告不会拦住你。

> **【注意】** 打印指针得到的是地址值，每次运行都可能不同，比较两次运行的地址输出没有意义；地址恒定的只有 nullptr（全 0）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：程序不读输入，固定输出 → 与数据无关（预期：输出 100、200、200 等固定序列）。
> 2. 单元素：只有一个变量 num 与一个指针 p → 解引用一次即达（预期：`*p` 与 num 恒相等）。
> 3. 全相同：p1、p2、p3 都指向 num → 任一指针写入，三个指针读出的值同步变化（预期：同一块内存）。
> 4. 严格递增：num 从 1 加到 5，每步打印 *p → 五次输出同步递增（预期：指针视角与变量视角一致）。
> 5. 严格递减：num 从 5 减到 1 → 同上反向。
> 6. 极值：对 `nullptr` 解引用 → 必触发访问违例 0xC0000005（实测见知识点 4，预期：RE，不侥幸）。

回扣开场：func1 改不动 num，是因为它只拿到复印件；指针能改 num，是因为它拿着原件地址。现在你能回答"地址和解引用分别是什么"——下一节把指针用到你最熟悉的数据结构上。

### 2. 指针与数组：a[i] 即 *(a+i)

前置依赖：[[#1. 地址与解引用：指针是什么]]、[[数据类型与内存表示]]（数组连续存放）
后续衔接：[[#3. 指针传参：swap 为什么能换动原件]]、[[二维数组]]（行优先存储是"首地址 + 偏移"公式的二维推广）

**① 它解决什么问题**

源 p11：数组所有元素**连续存放**，数组名可以看成指向首元素（下标 0）的指针，首元素地址称首地址。由此得到本节核心等式：**`a[i]` 就是 `*(a + i)`**——下标访问从第一天起就是指针运算的语法糖。关键性质：数组名是常量地址，不能 `arr++`；指针变量可以移动，`p++` 前进一个元素而不是一个字节；遍历复杂度 $O(n)$，与下标版完全等价。

**② 直觉理解**

模型级类比：**病房走廊**。病房编号连续，护士站（数组名）记着第一间房的位置；"第 i 间房"= 从护士站往前走 i 间。指针移动 `p++` 就是"走到下一间"——一次走一整间（一个元素宽），不是走一步（一个字节）。

用具体数字跑一遍：`int arr[5] = {1,2,3,4,5};` 设首地址 B。`arr` 与 `&arr[0]` 相等（源 p12 实验项）；`arr + 1` 的值是 B+4（int 占 4 字节，源 p12 打印 `arr+1` 可验）；`*(arr + 2)` = 从 B 走 2 个元素 = 8 字节处 = arr[2] = 3。

**③ 原理与推导**

推导核心等式：连续存放保证"第 i 个元素的地址 = 首地址 + i × sizeof(元素)"（源 p11 连续存放 + 源 p9-10 指针加减按元素大小缩放）。于是 `a[i]` 的语义"取第 i 个元素"可以完全翻译成 `*(a + i)`——编译器对下标的处理就是这一句。**设计动机：为什么 `p + 1` 走 4 字节而不是 1 字节？** 指针加减的单位是"所指类型的宽度"，编译器拿类型信息自动乘好 sizeof；这让人可以按"第几个元素"思考，字节账交给机器。

`*p++` 的读法（源 p 与 code.cpp 均用）：`++` 后缀优先级低于解引用，等价于"先取 `*p` 的值，再把 p 后移一格"——读和移动一次完成。

**④ 代码演示**

指针视角遍历数组（取自源 p12-14 与 code.cpp 的数组段，自编整理）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    cout << arr << " " << &arr[0] << "\n";   // 相同：数组名即首元素地址（源 p12）
    for (int i = 0; i < 5; i++)
        cout << *(arr + i) << " ";           // a[i] 的本质：首地址 + i 个元素
    cout << "\n";
    int* p = arr;                            // 指针指向数组（源 p13 语法）
    for (int i = 0; i < 5; i++)
        cout << *p++ << " ";                 // 先取 *p 再后移一格（源 p 写法）
    cout << "\n";                            // 复杂度：O(n) 遍历，与下标版等价
    return 0;
}
```

**执行追踪表**（arr = {1,2,3,4,5}，p 从 arr 出发，走 `sum += *p++` 五次）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | *p（p 指向 arr[0]） | p=B | 取值 1，p 移到 arr[1] | 累加 1 |
| 2 | *p（指向 arr[1]） | p=B+4 | 取值 2，p 继续后移 | 累加 2 |
| 3 | *p（指向 arr[2]） | p=B+8 | 取值 3 | 累加 3 |
| 4 | *p（指向 arr[3]） | p=B+12 | 取值 4 | 累加 4 |
| 5 | *p（指向 arr[4]） | p=B+16 | 取值 5，p 移到尾后 | 累加 5，合计 15 |

**错误写法对照**：

```diff
- arr++;                    // 坑1：给数组名自增——arr 是常量地址，编译错误（素材 code.cpp 注释原话：arr 常量，不能更改）
+ int* p = arr; p++;        // 要移动就用指针变量装下首地址
- for (int i = 0; i <= 5; i++) cout << *(arr + i);   // 坑2：i 取到 5——越过最后一个元素读垃圾值（答案错，不报错）
+ for (int i = 0; i < 5; i++) cout << *(arr + i);    // 下标合法范围 0..n-1
- 循环里 *p++ 走完一趟后又用 *p              // 坑3：p 已停在尾后位置，再解引用是越界（答案错/RE）
+ 复用前写 p = arr 把指针拉回首地址
```

**⑤ 典型应用**

- 课堂案例：源 p29 字符串指针遍历——`char str[] = "hello world";` 配 `cout << *(str + i)` 或 `*pc++` 逐字符输出，原理与本节完全相同。
- 迁移题（自编）：用纯指针写法实现 `myStrlen`（不使用下标）。思路：`char* p = s; while (*p) p++; return p - s;`——指针相减得元素个数，$O(n)$。
- 竞赛衔接：传数组给函数时传的正是首地址（知识点 3）；[[二维数组]] 的地址公式 `(i*col + j) × sizeof` 是"首地址 + 偏移"的二维版。

**⑥ 坑点与边界**

> **【易错】** 越界后继续解引用。指针走到 `arr + n`（尾后位置）时只允许比较、不允许解引用——尾后一格是"只能站不能碰"的哨兵位。

> **【易错】** 指针移动后忘记复位。`p` 走完一趟已不指向开头，第二趟遍历前必须 `p = arr`；否则从尾后开始读全是垃圾（答案错）。

> **【注意】** `arr` 与 `&arr[0]` 数值相同但 `sizeof(arr)` 是整个数组的大小、`sizeof(p)` 是 8 字节——"数组名可看成指针"只在传值与运算语境成立，不是真指针（源 p11 用词是"看成"）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 时不进入循环 → 无访问（预期：无输出、不崩）。
> 2. 单元素：arr={7}，遍历一次 → 输出 7（预期：首元素即全部）。
> 3. 全相同：arr 全填 3 → 五次输出 3 3 3 3 3（预期：指针每步走 4 字节逐步递增）。
> 4. 严格递增：arr=1..5 → 输出 1 2 3 4 5（预期：与下标版逐位一致，验证 a[i]==*(a+i)）。
> 5. 严格递减：arr=5..1 → 输出 5 4 3 2 1。
> 6. 极值：arr[4] 存 2147483647（int 上限）→ 读出原值不溢出（读不改变数据；溢出只发生在运算时）。

回扣开场：现在你知道 `a[i]` 从来不是什么魔法——它就是"从首地址走 i 步再解引用"。下一节把指针递进函数，正面解决开场 swap 换不动的问题。

### 3. 指针传参：swap 为什么能换动原件

前置依赖：[[#1. 地址与解引用：指针是什么]]、[[函数]]（参数传递与栈帧）
后续衔接：[[#4. 指针事故：野指针、空指针与 0xC0000005]]、[[链表]]（插入删除都以指针传参实现）

**① 它解决什么问题**

源 p18：函数参数可以是指针类型，**把函数外部的地址传进函数内部，函数内就能操作外部数据**，且改动不随函数结束而消失。它解决的正是开场碰壁：值传递的形参是实参的复印件，函数结束复印件销毁；指针传参把"原件地址"递进去，`*p` 直接改原件。关键性质：一次指针传参只传 8 字节地址；通过出参指针，一个函数可以"带出"多个结果。

**② 直觉理解**

模型级类比：**复印件 vs 房卡**。值传递是把文件复印一份给对方，对方涂改多少原件无损；指针传参是把房卡给对方，对方开门进屋直接搬东西——改动落在原件上。

用具体数字跑一遍（源 p22 交换案例）：`num1=100, num2=200`，调 `change(&num1, &num2)`：`temp = *p1` 存下 100；`*p1 = *p2` 把 200 写进 num1；`*p2 = temp` 把 100 写进 num2。返回后 `num1=200, num2=100`——真换了。

**③ 原理与推导**

推导 func1 为什么无效（源 p20）：调用 `func1(num)` 时，栈上为形参 `v1` 分配新格子，把 num 的值 100 抄进去；`v1++` 改的是这个新格子；函数返回栈帧回收，num 原封不动。func2 为什么有效（code.cpp L9-11）：`func2(&num)` 传的是 num 的地址，形参 `v1` 存这个地址；`(*v1)++` 顺地址找到 num 本尊加 1。**原因：无论哪种传参，形参都是新格子——差别只在格子里装的是"值的复印件"还是"原件的地址"**。设计动机：C++98 时代指针是函数改动外部变量的唯一通道；后来引用 `int&`（func3，hw.txt 面试题主角）本质是指针常量的语法糖，两者效果等价，竞赛中输出参数两种写法都常见。

**④ 代码演示**

三种传参对照与指针版 swap（取自素材 code.cpp 的 func1/func2/func3 与 change，逻辑原样整理）：

```cpp
#include <iostream>
using namespace std;
void func1(int v1)  { v1++; }        // 值传递：改复印件（源 p20）
void func2(int* v1) { (*v1)++; }     // 指针传参：顺地址改原件（code.cpp L9-11）
void change(int* p1, int* p2) {      // 指针版 swap（code.cpp L17-21）
    int temp = *p1;                  // 暂存 p1 所指的值
    *p1 = *p2;                       // p2 所指的值写进 p1 所指的格子
    *p2 = temp;                      // 暂存值写进 p2 所指的格子
}
int main() {
    int num = 100;
    func1(num);  cout << num << "\n";   // 100：复印件自增，原件无感
    func2(&num); cout << num << "\n";   // 101：实参写 &num，改动落到原件
    int a = 100, b = 200;
    change(&a, &b);
    cout << a << " " << b << "\n";      // 200 100：真换成功
    return 0;
}
```

**执行追踪表**（a=100, b=200，执行 `change(&a, &b)`，设 p1 指向 a、p2 指向 b）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | temp = *p1 | a=100, b=200 | 顺 p1 读 a 存入 temp | temp=100 |
| 2 | *p1 = *p2 | 不变 | 顺地址把 200 写进 a | a=200 |
| 3 | *p2 = temp | a=200 | 把 100 写进 b | b=100 |
| 4 | 函数返回 | a=200, b=100 | 栈帧回收（p1/p2 消失） | 改动保留在 a、b 上 |

**错误写法对照**：

```diff
- void change(int* p1, int* p2) { int* t = p1; p1 = p2; p2 = t; }   // 坑1：换的是两份"地址复印件"，出函数即销毁，a、b 纹丝不动（答案错）
+ void change(int* p1, int* p2) { int t = *p1; *p1 = *p2; *p2 = t; }   // 解引用换内容，才动到原件
- change(a, b);           // 坑2：实参忘取地址——int* 形接收不下 int，编译错误
+ change(&a, &b);         // 指针传参实参必须写 &（素材注释原话：不能直接写变量）
- void mySwap(int p1, int p2) { int t = p1; p1 = p2; p2 = t; }   // 坑3：退回值传递——即开场碰壁的原样复刻（答案错）
+ 参数类型必须是 int*
```

**⑤ 典型应用**

- 课堂案例：checkMax（源 p42-43 练习、code.cpp L36-43）——`checkMax(int* p1, int* p2, int* pMax)` 用第三个指针当出参把最大值带出来；实测 v1=900、v2=200 输出 900（附录 B-5）。一个函数带出一个结果，靠的正是"写 *pMax 就是写调用方的变量"。
- 迁移题（自编）：写 `void minMax(int* a, int n, int* pMin, int* pMax)`，一趟遍历同时带出数组最小值与最大值。思路：双循环扫描时比较后写 `*pMin`、`*pMax`，$O(n)$；注意 n=0 时不要解引用（衔接知识点 4）。
- 竞赛衔接：手写 [[链表]] 的 push/erase 全是指针传参；后续学引用传参时，本节的"地址语义"就是它的底层原理（hw.txt：引用"从一而终"、指针"见异思迁"——竞赛写题两者混用，理解语义即可）。

**⑥ 坑点与边界**

> **【易错】** 在函数里交换指针本身而不是交换 `*p1`、`*p2`。换指针只换了复印件上的房号，出函数即失效（④对照坑 1）。

> **【易错】** 实参漏写 `&`。`change(a, b)` 把 int 递给 int* 形参，直接编译错误；写对类型后还要确认传的确实是"想改的那个变量的地址"。

> **【注意】** 出参指针传入前必须指向合法变量（`int v3; checkMax(&v1, &v2, &v3);` 合法——v3 虽未初始化，但取地址合法）；出参指向 nullptr 再解引用就是事故（知识点 4）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：无输入直接 return → 无输出（预期：空、不崩）。
> 2. 单元素：change(&a, &a) 自换 → 值不变（预期：三步换回自己，幂等）。
> 3. 全相同：a=b=50 → 换后仍 50 50（预期：等值交换无副作用）。
> 4. 严格递增：a=1, b=2 → 换后 2 1（预期：追踪表四步可逐行对上）。
> 5. 严格递减：a=2, b=1 → 换后 1 2。
> 6. 极值：a=2147483647, b=-2147483648 → 换后 -2147483648 2147483647（预期：搬运不改值，溢出只在运算时发生）。

回扣开场：开场那个换不动的 swap，现在你能写出真正换成功的版本——用的是知识点 1 的取地址与知识点 3 的解引用写回。最后一节集中排雷：指针什么时候会炸。

### 4. 指针事故：野指针、空指针与 0xC0000005

前置依赖：[[#1. 地址与解引用：指针是什么]]、[[变量作用域与多文件编程]]（局部变量随栈帧销毁）
后续衔接：[[链表]]（判空 head != nullptr 是链表题第一道防线）、[[DFS]] 与递归（栈深超限同样表现为 0xC0000005）

**① 它解决什么问题**

竞赛里最吓人的报错是 `0xC0000005`（Windows 的访问违例），它的根源几乎都是同一件事：**解引用了不该解引用的指针**。三大事故源（源 p23-26、p30-31）：**野指针**——定义后没初始化，里面是垃圾地址；**空指针解引用**——对 nullptr 顺藤摸瓜，地址 0 所在页受系统保护；**悬垂指针**——指向已被销毁的局部变量的地址（源 p23 原话：函数返回的指针不要指向局部数据）。本节的目标是认全三种事故并建立防法：**定义即初始化、解引用前判空、不返回局部地址**。

**② 直觉理解**

模型级类比：**快递单上的地址**。野指针是地址栏印着出厂随机字符——包裹投到随机人家；空指针是地址栏写着"0 号收件人"——这个编号不存在，投递被系统拦下；悬垂指针是写着"某某已拆迁的房子"——地址格式合法，房子没了。

用具体数字跑一遍（实测程序 null_deref.cpp）：`int* p = nullptr; cout << *p;`——p 存全 0；解引用要求读地址 0 起 4 字节；地址 0 所在页禁止用户程序访问；操作系统立刻终止程序，退出码 -1073741819，十六进制正是 **0xC0000005**（实测附录 B-5）。

**③ 原理与推导**

推导野指针为什么"时对时错"：垃圾地址可能落在没人用的页（侥幸不炸但读出脏值，答案悄悄错，WA），也可能落在受保护页（当场 RE）——**错误的程度由运气决定，这正是它比编译错误更危险的原因**。空指针必炸的原因：操作系统把低地址页（含 0 页）设为禁止访问，任何用户态读写都触发异常。悬垂指针的原理衔接 [[变量作用域与多文件编程]]：局部变量生存在栈帧里，函数返回栈帧回收（源 p23：函数结束会销毁内部定义的所有局部数据），地址还在、内存已改作他用——test2 返回 `&local`（code.cpp L29-33）后 `*p2` 读到的是废墟。设计动机：nullptr（C++11，源 p32）之所以取代 NULL/0，是它只表示"指针空值"，避免整数 0 与空指针的二义性。

**④ 代码演示**

事故三源与防法三件套（自编示例；空指针崩溃已实测，附录 B-5）：

```cpp
#include <iostream>
using namespace std;
int* danger1() {
    int local = 42;
    return &local;          // 事故源：返回局部变量地址（源 p23 明令禁止）
}
int main() {
    int* wild;                          // 事故源：野指针（源 p31 明令禁止的写法）
    int* np = nullptr;                  // 防法一：定义即置空
    if (np != nullptr) cout << *np;     // 防法二：解引用前判空，空则跳过
    // 把上行改为 cout << *np; 即复现 0xC0000005：p 存全 0，解引用读受保护 0 页
    // int* dangling = danger1();       // 事故源：接住悬垂指针（注释防炸）
    // cout << *dangling;               // 读废墟：轻则脏值 WA，重则 RE
    wild = nullptr;                     // 防法三：用完即置空，本程序不再解引用它
    cout << "safe end" << endl;         // 复杂度：判空是 O(1) 的保险丝
    return 0;
}
```

**执行追踪表**（null_deref.cpp 三步）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | p = nullptr | p 存全 0 | 初始化完成 | p 指向 0 号受保护页 |
| 2 | *p | 不变 | 解引用：读地址 0 起 4 字节 | 硬件拒绝，触发访问违例 |
| 3 | 程序终止 | - | 操作系统接管进程 | 退出码 -1073741819（0xC0000005） |

**错误写法对照**：

```diff
- int* p; *p = 1;                    // 坑1：野指针直接写——目标随机，轻则脏数据（WA）重则 0xC0000005（RE）
+ int* p = nullptr; if (p != nullptr) *p = 1;   // 置空 + 判空后才解引用
- int* f() { int x = 1; return &x; } // 坑2：返回局部变量地址——调用方拿到悬垂指针，读的是已回收的栈（WA/RE）
+ 结果通过出参指针带回，或返回前把值拷出局部作用域
- int* q = nullptr; cout << *q;      // 坑3：判空形同虚设——判完不等就解引用，等于没判（RE）
+ 先 if (q != nullptr) 再解引用，两行缺一不可
```

**⑤ 典型应用**

- 课堂案例：源 p30-31「定义指针时把不指向任何数据的指针置为 NULL，防野指针」——防法一出自此处，nullptr 是它的现代版。
- 迁移题（自编）：写 `int safeMax(int* a, int n)`，a 为空或 n 为 0 时返回特殊标记 0 并不崩溃，否则返回最大值。思路：入口先判 `a == nullptr || n <= 0`，判空通过后才进循环解引用，$O(n)$。
- 竞赛衔接：[[链表]] 模板题里 `while (head != nullptr)` 是遍历的标配护栏；调试时看到 0xC0000005，第一反应按本节顺序排查——数组越界、解引用空/野指针、递归爆栈。

**⑥ 坑点与边界**

> **【易错】** 认为"指针没解引用就没危险"。把野指针的垃圾地址打印出来通常不炸，但把它赋给另一个指针再解引用就炸——垃圾地址会传染，源头必须堵住。

> **【易错】** 用 `p != nullptr` 判空后，循环体内忘了推进指针（如漏写 `p = p->next`），死循环反复停在原地——判空护栏不替代逻辑正确性。

> **【注意】** 竞赛代码大多用全局数组代替 new/delete，本节三事故中最常见的是"数组越界 + 指针越界"合体：`int a[100]; int* p = a; p[100] = 1;` 越界写——下标越界与指针越界是同一件事的两副面孔。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：程序无输入 → 判空逻辑不被触发（预期：正常结束）。
> 2. 单元素：safeMax 只收一个元素 → 判空通过，返回该元素（预期：与暴力一致）。
> 3. 全相同：数组全 0 → 最大值 0，返回值与"空标记 0"重合——自编题的教训：特殊标记要与合法值域错开（预期：设计出参比返回标记更稳）。
> 4. 严格递增：数组 1..n → 返回 n（预期：指针走 n 步停在尾后，只比较不解引用）。
> 5. 严格递减：数组 n..1 → 返回 1（预期：首元素即最大，循环正常走完）。
> 6. 极值：对 nullptr 与野指针分别解引用 → 前者稳定复现 0xC0000005（实测），后者随垃圾值浮动——防法是同一句：解引用前确认地址合法。

回扣开场：碰壁题教会你"值传递改不动原件"，本节告诉你"乱用地址会当场爆炸"。现在你能写出换得动、炸不了的指针代码——四步排雷顺序（越界、空/野指针、悬垂、爆栈）从此成为你的调试直觉。

## 四、总结与自测

### 核心内容（一页纸速览）

- **指针**：存内存地址的变量；`&` 取地址、`*` 解引用；解引用 $O(1)$；指针类型决定读写宽度与解释方式。
- **指针与数组**：数组名即首元素地址（常量）；`a[i]` 就是 `*(a+i)`；`p++` 前进一个元素而非一个字节。
- **指针传参**：值传递是复印件、指针传参是房卡；swap 换 `*p1`/`*p2` 才动原件；出参指针可带出结果（checkMax）。
- **指针事故**：野指针（垃圾地址）、空指针（0 页受保护）、悬垂指针（局部变量已销毁）——0xC0000005 的三大来源；防法三件套：定义即初始化、解引用前判空、不返回局部地址。
