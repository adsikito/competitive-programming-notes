# 学习工程 · 使用说明

> **定位**：`资料\学习工程\` 是竞赛整合讲解笔记的**唯一产出目录**。本文件说明目录规则、工作流、注意事项与质量提升方向。
> **定版时间**：2026-09-24

---

## 一、目录规则（硬规则）

| 规则 | 说明 |
|------|------|
| **产出唯一入口** | 全部产出（提示词、笔记、素材副本）只写入本目录 |
| **源目录只读** | `02_数据结构\` `03_算法集训\` `C++\` `00_学习工程\` 一律不修改、不重命名、不删除 |
| **素材复制使用** | 需要哪份源文件，复制进 `素材\<主题>\` 后再用，不直接操作源目录：课件文档放 `素材\<主题>\`，**例题代码放 `素材\<主题>\code\`**，提取的文本放 `素材\<主题>\提取文本\`（中间产物留存复用，避免重复提取） |
| **产出归位** | 笔记存 `笔记\<主题>.md`；笔记配套的完整可运行代码存 `笔记\代码\<主题>\` |
| **索引维护** | `笔记\_索引.md` 手动登记每篇笔记的主题 / 优先级 / 掌握状态 / 链接（装 Dataview 后可由查询替代） |

## 二、工作流（四步）

```text
第 1 步　复制源文件到  素材\<主题>\          （课件文档 + code\ 例题代码，只复制本主题用得上的）
第 2 步　提取文本　    PDF 用 fitz；PPTX 用 python-pptx；扫描版先 OCR；结果存 素材\<主题>\提取文本\（可由阿枢代做）
第 3 步　填变量投喂　  按 竞赛资料整合讲解_提示词.md 第一节变量表填写，粘贴提取文本与例题代码，注明当天日期
第 4 步　验收归位　    跑 lint 机器校验 → 对照自检清单人工验收 → 代码本地编译核对 → 存入 笔记\ 并登记 笔记\_索引.md
```

### 2.1 模型侧的整合六步（v3.0 提示词内部逻辑，了解即可）

```text
① 逐份提取　每份源文件一张知识点提取表（放附录 A，不占正文）
② 合并去重　多份讲同一知识点 → 合并讲一次，取最清晰的表述
③ 冲突登记　表述不一致 → 以公认教材结论为准并登记理由（附录 A-3）
④ 学习排序　按依赖关系排出学习先后，形成总清单（N 条）
⑤ 逐讲成文　每个知识点六步叙事：问题开场 → 直觉 → 推导 → 实现 → 应用 → 坑点
⑥ 对账自检　附录 A 总清单 N 条对正文 N 个小节，逐项过附录 C 自检清单后才交付
```

> **v3.0 格式裁决（2026-09-25）**：主体从「六段盒子」改为「六步叙事」；源文件对账、假设与缺口登记、交付前自检清单全部移至**附录 A/B/C**，正文零工程痕迹；mermaid ≤2 → ≤3 鼓励图解；例题真题优先。参照 Hello 算法 / OI Wiki / labuladong 体例。lint 脚本自动识别 v2.5 旧格式与 v3.0 新格式分别校验。

**三方分工**：你负责选主题、定「已掌握 / 没学过」清单、验收与回写掌握状态；阿枢负责复制素材、提取文本、投喂与本地编译验证；模型负责整合与成文。

### 2.2 复习回顾版（第二条线）

用 `复习回顾版生成_提示词.md`（v2.0，98 分）：素材流程相同（复制 → 提取 → 投喂 → 验收），产出存 `笔记\<主题>_复习回顾.md` 并登记 `笔记\_索引.md`。两种用法：独立用（直接喂源文件提取文本），或串联用（先整合讲解、再浓缩复习，两遍口径天然一致）。**v2.0 框架卡片体**（吸收 labuladong 框架思维）：每个知识点一张卡——识别信号 / 核心模板 / 复杂度 / 首坑 / 口诀；**覆盖优先于简短**：知识点一个不落，按 P0/P1/P2 分层详略（P0 卡五字段齐全、P1 卡三字段、P2 一行）。**emoji 限量特许仅适用于复习版文件**（仅 ❌✅⭐⚠️，全篇 ≤ 15 个）；讲解笔记仍然全禁。

### 2.3 lint 机器校验（`tools\lint_notes.py`）

覆盖《交付前自检清单》中全部可机器化的条目，共 30 项检查（通用 14 / 讲解笔记 10 / 复习回顾版 6）。

```text
执行　python tools\lint_notes.py                扫描 笔记\ 下全部 md（自动跳过 _索引.md）
　　　python tools\lint_notes.py 笔记\二分.md     单篇检查
　　　python tools\lint_notes.py -v -o 报告.txt   输出全部条目（含 PASS）到文件

自动识别类型　frontmatter tags 含「复习回顾」→ 复习版（含「框架卡片」字样判 v2.0）；正文含 ### K-x → v2.5 讲解笔记；含 ### N. 小节 + ## 附录 → v3.0 讲解笔记。新旧格式分别按对应契约校验。
检查项摘要　　通用：frontmatter 五项 / emoji 合规 / 标题不跳级 / 表格 ≤6 列 / callout 类型与声明行 /
　　　　　　　　　单块单主标签 / 无 [[]] 双链 / 尾部两节 / 代码块语言与长度 / mermaid 数量与文字版 /
　　　　　　　　　禁用措辞 / 自检清单节
　　　　　　　讲解：N 对 N 对账 / 六步(段)齐全 / 附录或预备概念节 / 坑点总表 / 总结与自测 /
　　　　　　　　　性质交代 / 设计动机 / 编译验证记录
　　　　　　　复习：P0/P1/P2 标注 / 全篇 ≤600 行 / 必备节 / 文本树 ≥ mermaid / P0 卡识别信号（v2.0）

退出码　0 = 无 FAIL（可交付）；1 = 有 FAIL（门禁拦截）；WARN 项需人工确认
依赖　　纯 Python 标准库，无需第三方包
```

**判定口径的两处注意**：① 复习版「12 行上限」只约束「高频代码模板」节内的代码块，其余文本树（框架树、速查树）按 40 行软上限给 WARN；② `[[]]` 与禁用措辞检查会剔除行内代码、并跳过「交付前自检清单」节——自检条目本身引用的规则文案不算违规。

## 三、注意事项（使用前必读）

1. **模型读不了二进制**。PDF/PPTX 必须先提取文本再粘贴；扫描版 PDF 无文本层，需先 OCR，提取失败的源文件要在「读取缺口」登记，不得让模型编造其内容。
2. **大主题必须拆批**。单篇笔记知识点 ≤ 8 个（超了让模型在分析区先出拆篇计划）；一次投喂 3 至 6 个知识点质量最高；一次喂整章（10+ 知识点）会明显缩水。
3. **md 旧笔记只作覆盖度参考**。知识内容一律以 PDF / PPTX / 源码 / 题面等原始资料为准，两者冲突时采信原始资料。
4. **代码必须本地实测**。模型给的代码与「预期输出」可能自洽但错误；入库前用 `g++ -std=c++17 -O2` 编译并跑样例核对，通过后在笔记中标注「已通过本地编译验证」。
5. **多源冲突不取多数决**。以公认教材结论为准并在「冲突登记」说明理由，三份资料都错的可能真实存在。
6. **全文无 emoji**。本目录产出一律不用 emoji，视觉区分交给 8 标签体系与 Markdown 原生排版（2026-09-24 用户裁决回退）。
7. **版权边界**。课件 PDF/PPTX 为付费课程资料，笔记供个人学习使用；若要公开发布（如 GitHub），需先做版权评估，参照旧工程 `23_GitHub发布规范.md` 的教训。
8. **源文件清单要写全**。漏列的源文件不会被提取表覆盖，等于主动制造知识缺口。
9. **Obsidian 语法档位已定（均衡档，2026-09-24 裁决）**。callout 只用 `NOTE / TIP / IMPORTANT / WARNING / CAUTION` 五种（GitHub 也渲染）；公式用 LaTeX；mermaid 每篇 ≤ 2 个且配文字推导链；链接用标准相对路径，不用 `[[]]` 双链。
10. **掌握状态要回写**。学完一篇，把 frontmatter 的「掌握状态」从「未学」改为「在学 / 已掌握」。装 Dataview 插件后可用查询列出全部「P0 且未掌握」的笔记，形成知识点监控面板——这是「知识点不要少」的长期兜底。
11. **图片与目录**。简单图让模型用 mermaid 重画；复杂图才贴原图，存 `素材\<主题>\img\` 并用标准相对路径嵌入。`笔记\` 下最多一层子目录，靠 tags 与链接组织，不搞深目录。
12. **Obsidian 打开方式**。把 `学习工程\` 作为独立仓库（Vault）打开即可；若并入现有仓库，附件路径设为相对路径，避免贴图链接失效。

## 四、五个质量提升方向与解决方案

| # | 方向 | 问题 | 解决方案 |
|---|------|------|---------|
| 1 | **源文件提取质量** | PDF 公式与图、PPTX 版式在提取时丢失，模型拿到残缺信息会自行脑补 | 提取时保留页码；图与公式用文字转述并标注「原资料第 X 页图」；提取失败的源登记「读取缺口」，不编造 |
| 2 | **上下文长度管理** | 整个主题的资料可能超出模型窗口，导致后半部分被静默丢弃 | 先发「源文件清单 + 提取表」让模型出整合计划，再按知识点族分 3 至 6 个一批生成，最后合并去重；长文档前置、指令后置 |
| 3 | **漏讲双保险** | 单次提取可能漏知识点，N 对 N 对账只能管住「已提取的」 | 每份源单独出提取表（防单源漏提取）+ 总清单 N→N 小节对账（防漏讲）+ 生成后脚本统计小节数与清单数是否一致 |
| 4 | **代码真实性** | 模型手写的「预期输出」可能与代码实际行为矛盾 | 全部代码本地 `g++ -std=c++17 -O2` 编译 + 跑样例核对后入库；例题至少跑 2 组数据（含 1 组边界数据） |
| 5 | **多篇风格一致性** | 不同批次产出的标注密度、章节结构会漂移 | 标注体系与模板固化在提示词输出契约中（已做）；**已实现 lint 脚本** `tools\lint_notes.py`：emoji 计数、callout 规范、标题跳级、表格列数、双链、代码块长度、mermaid 数量、N 对 N 对账、六段齐全等 30 项检查，有 FAIL 时返回退出码 1，可作交付门禁 |
