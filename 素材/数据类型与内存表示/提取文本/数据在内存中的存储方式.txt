===== 第4页 =====
前言
一个数在计算机中的表示形式是二进制，这个数其实就叫机器数。
机器数是带符号的，在计算机用一个数的最高位存放符号，正数为
0， 负数为1。比如，十进制中的数 +7 ，计算机字长为8位，转换
成二进制就是00000111。如果是 -7 ，就是 10000111 。一个存储的
二进制码分原码、反码、补码

===== 第5页 =====
原码、反码和补码
• 计算机在任何情况下都只能识别二进制
• 计算机在底层存储数据的时候，一律存储的是“二进制的补码形
式”
为什么采用补码形式存储数据？
补码形式效率最高。

===== 第6页 =====
原码
原码（0表示正数，1表示负数）
x=1100110,则[X]原=01100110
x=-1100111,则[X]原=11100111

===== 第7页 =====
反码
反码(正数的反码就是自身，负数的反码除符号位外，其他各位求
反)
x=1100110,则[X]反=01100110，
x=-1100111,则[X]反=10011000，
反码肯定属于有符号位，相当于上面有符号位求反

===== 第8页 =====
补码
补码(正数的补码还是自身，负数的补码，符号位不变，其余取反，
然后最低为加1)
x=1100110,则[X]补=01100110，
x=-1100111,则[X]补=10011001

why?
为什么计算机要采用补码的方式来存储数据呢？采用原码不是更容
易理解吗？

===== 第10页 =====
原码来处理数据
如果使用原码来处理数据，在运算时会是怎样呢？
十进制运算：   1 -  1   =   0
                        1 + (-1)=  0
二进制原码：0000 0001 + 1000 0001 = 1000 0002 = -2
很明显，对于1-1这个十进制计算的结果并不正确，于是我们想到用反码来
解决这个问题

===== 第11页 =====
反码处理数据
使用反码来计算：
十进制运算： 1  -   1  = 0
                       1 + (-1)= 0
二进制反码：反码[0000 0001] + 反码[1111 1110] = 反码[1111 1111] = 原码[1000 0000] = -0
对于以上结果，已经大致上符合了我们的预期，但是对于完美的答案0来说，多了一个负号总
是不舒服的。于是，补码隆重登场！

===== 第12页 =====
补码处理数据
使用补码来计算：
十进制运算：   1 -  1   =   0
                        1 + (-1)=  0
二进制反码：补码[0000 0001] + 补码[1111 1111] = 补码[0000 0000] = 原码[0000 0000] =  0
完美！到此为止，我们终于获得了完美的0。
因此，计算机使用了补码来对数据进行存储
