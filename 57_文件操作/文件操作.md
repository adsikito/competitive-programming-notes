## 一、为什么需要它

你已经会 `cin >> x` 读键盘、`cout << x` 写屏幕。但两个场景立刻卡住：场景一，程序算出的成绩表要**留下来**给下次运行用——控制台一关输出就没了；场景二（素材 25 课件作业原型），data.txt 里几百行英文要统计每个单词出现几次，`cin >>` 只读到空格就停，带标点的文章切出来全是残词。两个场景都要求数据的进出端从「键盘/屏幕」换成「文件」——这就是文件流。
素材 24 课件给出完整通路「打开-处理-关闭」，25 课件用单词统计器把文件读、string 处理、map 计数串成完整程序——作业明确要求「找出程序中的 bug」。本篇 4 个知识点按此组织：文件流总览、文本写入与读取、文件状态与关闭纪律、string 深入。最后一个就是那批 bug 的解剖台。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 文件流总览：ofstream / ifstream / fstream 与 cin、cout 的同构性

前置依赖：[[第一个C++程序]]（编译与运行目录）、[[STL]]（string 类）
后续衔接：[[#2. 文本写入与读取：>> 的分词与 getline 的整行]]、[[#3. 文件状态与关闭纪律：eofbit、failbit 与 while(!eof) 之坑]]

**① 它解决什么问题**
数据流（24 课件）是「一组有序、有起点和终点的字节序列」。C++ 用**流（stream）**统一一切输入输出：键盘和屏幕是控制台流（cin/cout），文件是文件流。24 课件给出三类：**ofstream** 写（由 ostream 引申）、**ifstream** 读（由 istream 引申）、**fstream** 双向（由 iostream 引申）。性质总账：三类的 `<<`、`>>`、`get`、`getline` 与 cin/cout 同名同义，读写量 O(内容长度)；前提是 open 成功（is_open 检查），用完 close。

**② 直觉理解**
模型级类比：**同一个水龙头，换水管**。cout 是出厂就接好「显示器水管」的出水口，ofstream 是同一规格的出水口、由你自己接一根「文件水管」——接上后 `outf << "hi"` 与 `cout << "hi"` 语法一模一样，只是水流进了文件。具体小数据：执行 `outf << "hi" << endl;` 后，工作目录多出 file.txt，打开就是两字节 `hi` 加换行——与写屏幕相比只有目的地变了。

**③ 原理与推导**
为什么语法同构？24 课件继承图给出答案：ofstream 继承自 ostream，`<<` **定义在 ostream 里**，子类原样继承——会写 cout 就会写 ofstream。为什么 cin/cout 不用 open？键盘和屏幕是**默认设备**，流对象程序启动时已建好；文件不是默认设备，必须先 open（接水管）后 close（关水管）。打开模式（24 课件 mode 表精选，模式可用 `|` 组合）：

| 模式 | 含义 | 关键后果 |
|------|------|---------|
| ios::out | 写（ofstream 默认） | 不存在则新建；**已存在则清空** |
| ios::in | 读（ifstream 默认） | 不存在则打开失败 |
| ios::app | 追加写 | 接在末尾，不清空 |
| ios::binary | 二进制 | 按 bytes 原样读写 |

**设计动机**：为什么 out 默认清空？「写」的语义是「重新写这个文件」，最危险的操作设为默认值，逼使用者主动选择「保留旧数据」（app）——比反过来安全。实测 A6/A7：app 两次写得到 abcd，默认第二次写只剩 xy。

**④ 代码演示**
核心代码（自编示例，逻辑取自素材 test01 与课件写入案例，加 is_open 检查）：

```cpp
#include <iostream>
#include <fstream>   // 文件流三件套的唯一头文件
using namespace std;
int main() {
    ofstream outf;                        // 1.创建流对象
    outf.open("file.txt", ios::out);      // 2.接水管（默认模式可省略第二参数）
    if (!outf.is_open()) { cout << "打开失败" << endl; return 1; }   // 3.检查水管接通了没有
    outf << "山村咏怀" << endl;           // 4.用法与 cout 完全相同
    outf << 123 << " " << 4.5 << endl;    //    任意类型都能 <<
    outf.close();                         // 5.关水管，缓冲区落盘
    return 0;
}
```

**执行追踪表**（写后重开读回的全过程）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | outf << "hi" | 文件不存在，写指针=0 | 新建并写入 2 字节 | file.txt 内容为 hi |
| 2 | outf << endl | 写指针=2 | 写入换行 | 内容 hi\n |
| 3 | outf.close() | 输出缓冲区 | 刷新并断开关联 | 数据确定落盘 |
| 4 | inf.open + inf >> s | 读指针=0 | 建立读关联，跳过空白读一词 | is_open()==true，s=="hi" |

**错误写法对照**：

```diff
- ofstream outf("file.txt"); outf << "hi"; return 0;   // 坑1：不 close 就退出。缓冲区通常照样刷新，但这是依赖实现的行为；中途 return 或崩溃时缓冲区数据直接丢（WA）
+ outf.close();   // 显式关闭：落盘 + 断开关联
- outf.open("file.txt");   // 坑2：不检查打开是否成功——路径写错时静默失败，后面全白写（WA）
+ if (!outf.is_open()) { /* 报错退出 */ }   // 素材 test05-test07 的标准开头（实测 A12）
```

**⑤ 典型应用**
- 素材作业（24 课件）：把喜欢的诗写入 file1.txt 再读回显示——五步通路直接套用；词频统计（25 课件）里 `ifstream in("data.txt")` 构造即打开。
- > [!note]
  > **【延伸，非必需】** 竞赛场景定位：标准 OJ（洛谷/力扣/CSP 笔试）从 stdin 读、往 stdout 写，**直接用 cin/cout，不要碰文件**。只有少数特定赛制（部分学校机试、ACM 历史现场规则）要求从 data.in 读、写 data.out，此时用 C 函数 `freopen("data.in", "r", stdin); freopen("data.out", "w", stdout);` 把 cin/scanf 重定向到文件，之后代码一行不改（freopen 本就是 stdio.h 的 C 函数，即等价 C 写法；实测片段 g++ -std=c++17 语法通过）。

**⑥ 坑点与边界**

> **【易错】** 忘 `ios::app` 导致每次运行覆盖旧文件——课件写入案例原话注释「每次运行都会覆盖原来的内容」，默认 out 就是 trunc，保留历史必须显式 app（实测 A6/A7）。
> **【易错】** open 失败不检查就读写——读不存在文件时流进 fail 状态，后续读静默得空值（WA）。`if (!f.is_open())` 紧跟 open（实测 A12）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空文件（0 字节）：打开成功、is_open 为 true，但首次读立即 eof（预期：读不到内容、不崩溃）。
> 2. 单行文件 "hi"：>> 与 getline 都读出 "hi"（预期：两种粒度同结果）。
> 3. 无换行结尾 "hi"：getline 照常读到 "hi"，eof 在读到尽头时置位（预期：内容完整，时序分析见知识点 3）。
> 4. 二进制：ios::binary + write 写 int 数组 {1,2,3} 共 12 字节，read 回逐个相等（预期：往返一致；记事本打开是乱码属正常）。
> 5. 定位极值：seekg(0, ios::end) 后 tellg 即文件字节数（实测 A8：5 字节文件差值恰为 5；seekg/seekp 定位读/写指针，24 课件「文件定位和大小」）。极值另测：文件名含中文/空格时 open 参数照常工作，但源码 GBK、系统 UTF-8 编码不一致会打不开（预期：is_open 为 false，回坑 2 的检查）。

回扣开场：场景一「成绩表留下来」已被五步通路解决——用的是 ofstream 与 app 模式。接下来解决场景二「整行整行读文章」。

### 2. 文本写入与读取：>> 的分词与 getline 的整行

前置依赖：[[#1. 文件流总览：ofstream / ifstream / fstream 与 cin、cout 的同构性]]、[[STL]]（string）
后续衔接：[[#3. 文件状态与关闭纪律：eofbit、failbit 与 while(!eof) 之坑]]、[[#4. string 深入：拼接、查找、子串、替换]]

**① 它解决什么问题**
读文件有**两种粒度**（24 课件读取案例四种写法归并为两类）：`>>` 按空白（空格/换行/Tab）**切词读**，适合读整数、单词；`getline(流, string)` **整行读**，保留行内空格、丢掉行尾换行，适合读句子、古诗。课件原话：「以空格为分隔符，遇到空格就不读取了」——这正是 `infile >> cf` 对「山村咏怀 邵雍」只读出前半句的原因。

**② 直觉理解**
模型级类比：**>> 是切菜的勺子，getline 是端盘子的托盘**。勺子只舀一块（一个无空白的 token），锅里的空白一概绕开；托盘把一整行连汤带菜端走（含行内空格，只倒掉行尾换行）。具体小数据：file.txt 内容 `山村咏怀 邵雍`，`infile >> cf` 得 `山村咏怀`（遇空格停），`getline(infile, cf)` 得 `山村咏怀 邵雍`（整行）。

**③ 原理与推导**
`>>` 的规则：跳过前导空白，读字符直到**再次遇到空白就停**——注意是「停」不是「吃掉」，停下的空白（比如换行）**留在流里**。getline 的规则：从当前位置读到 `\n`，把 `\n` 丢掉、其余装进 string。
**流分离坑推导**（为什么 `cin >> x` 后接 getline 会读到空行）：`cin >> x` 读到数字后停在 `\n` 前；紧接的 `getline(cin, s)` 从 `\n` 开始——第一个字符就是行结束符，立刻返回**空串**。不是 getline 坏了，是「勺子把菜舀走了，托盘只端到剩下的汤底」。**设计动机**：`>>` 为什么不吃掉停下的空白？token 之间的分隔符可能属于下一个读取者（下一行的 getline 要自己处理行边界）——「谁消费谁负责」才有混用的灵活性，代价是必须记得手剥残留换行（④ diff）。

**④ 代码演示**
核心代码（取自素材 test05，改动：仅加注释）：

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;
int main() {
    ifstream ifs;
    ifs.open("file.txt", ios::in);
    if (!ifs.is_open()) { cout << "文件打开失败！" << endl; return 0; }   // 打开检查：素材 test05 原样
    string buf;
    while (getline(ifs, buf)) {           // 整行读；getline 是自由函数，需 <string>
        cout << buf << endl;
    }
    ifs.close();
    return 0;
}
// 对照：while (ifs >> buf) 是分词版（素材 test06），一行变多个 buf
```

**执行追踪表**（模拟流分离坑：输入 `42\nworld\n`，先 `>> age` 再 getline）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | iss >> age | 流内余 \nworld\n | 读 42，停在 \n | age==42，\n 留在流 |
| 2 | getline(iss, w1) | 从 \n 开始 | 首字符即行尾 | w1==""（空串，坑现场） |
| 3 | getline(iss, w2) | 从 w 开始 | 读到行尾丢 \n | w2=="world" |
| 4 | 修正：iss.ignore() | 丢弃 1 字符 | \n 被扔掉 | 下次 getline 直接拿到 world |

**错误写法对照**：

```diff
- cin >> n; getline(cin, s);   // 坑1：>> 留下换行，getline 空读——读 n 行文本的经典全错（WA，所有行错位）
+ cin >> n; cin.ignore();      // 手剥残留换行，再进循环
- while (infile.getline(buf, 1024))   // 坑2：char buf 版容器固定，长行被截断且流状态变脏（WA）
+ string buf; while (getline(infile, buf))   // string 版无上限（24 课件「第四种」，推荐）
```

**⑤ 典型应用**
- 素材作业（24 课件）：诗写入 file1.txt 再读出——写入 `<<`，读出 getline 保住每行空格；词频统计（25 课件 dataProcessing）逐行 getline 再切词，行读是流水线入口。
- 迁移题（自编）：文件第一行是人数 n，接下来 n 行每行一个名字，读全部名字输出。关键：`cin >> n; cin.ignore();` 之后才能 getline——正是流分离坑的正面应用。

**⑥ 坑点与边界**

> **【易错】** `cin >> n` 后直接 getline 读 n 行——第一次 getline 空读，所有行整体错位（WA）。正解：中间补 `cin.ignore()` 或空 getline（④坑 1；实测 A3 复现：w1 为空串）。
> **【易错】** 分不清 `>>` 与 getline——读数字/单词用 `>>`；读含空格的整行用 getline 后自行切分。getline 返回流本身，放进 while 条件既判「读完」又处理失败，比手写 eof 判断安全（知识点 3 展开）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空文件：getline 首次调用即失败，循环体零次执行（预期：无输出、不崩溃）。
> 2. 单行无换行结尾 "hi"：getline 读到 "hi" 并置 eof，循环正常结束（预期：输出 hi 恰一次）。
> 3. 带换行结尾 "hi\n"：同样一次（预期：行尾换行被 getline 丢弃，与上条无差异）。
> 4. 连续空行 "\n\n"：各读到空串，输出两个空行（预期：空行也是行，不跳过）。
> 5. 极值：一行 100 万字符——string 版 getline 无上限正常读；char buf[1024] 版截断（预期：string 版完整，验证坑 2）。混用极值：>> 读 int 后紧接 getline 读 10^5 行，漏 ignore 则首行丢失（预期：补 ignore 后 10^5 行全读到）。

回扣开场：场景二「读文章」的入口打通了——getline 整行读入。行进来后怎么切词、洗标点靠知识点 4；中间还隔着「while(!eof) 为什么是坑」这道最密的雷，先排它。

### 3. 文件状态与关闭纪律：eofbit、failbit 与 while(!eof) 之坑

前置依赖：[[#2. 文本写入与读取：>> 的分词与 getline 的整行]]、[[函数]]（返回值与状态传播）
后续衔接：[[#4. string 深入：拼接、查找、子串、替换]]、[[STL]]（map 计数收尾）

**① 它解决什么问题**
流对象内部有**状态标志**：eofbit（读到文件末尾）、failbit（格式错误或读取失败）、badbit（严重 IO 错误）。is_open 只回答「文件接上没有」，状态标志回答「刚才那次读成没成」。本知识点解决两件事：**怎么正确判断「读完了」**（素材 bug_fixed.cpp 的 fail 修复），**什么时候必须 close**（缓冲与落盘纪律）。性质总账：eof 在「读失败之后」才置位；判断读完成的标准姿势是「把读操作本身放进 while 条件」。

**② 直觉理解**
模型级类比：**快递签收状态单**。eofbit 是「货送到了尽头」（不是错误），failbit 是「签收失败」（要整数却收到字母），badbit 是「包裹损坏」。关键在时序：**状态单是在你验货失败之后才打勾的**——先看状态单再伸手拿货，永远慢一拍。
具体小数据：文件 `aa\nbb\n`，用 `while (!in.eof()) getline` 读。第三轮 eof 尚未置位（前两轮各读完一行还没碰到尽头），循环进入；getline 试图读第四行，**先失败、eofbit 才置位**，且 string 被清空——一个空串混进处理流程。

**③ 原理与推导**
为什么 while(!eof) 是坑？把时序写开：eofbit 只在**某次读操作实际碰到文件尽头**时置位，而循环条件检查发生在**下一次读之前**——「先判后读」的顺序决定了判断永远基于上一次的信息。对换行结尾的文件，最后一轮判定「没到末尾」，读操作却失败，产出空串/残留值。
**设计动机**：为什么 C++ 推崇 `while (getline(f, s))` 这种「读即判」写法？流的 bool 转换综合了 failbit 与 badbit——**读失败与判断在同一瞬间发生**，没有时序差，天然挡掉空串。素材 bug_fixed.cpp 的修复就是给 eof 循环补一道闸：

```cpp
while (!stringeam.eof()) {
    stringeam >> s;
    if (stringeam.fail()) break;   // bug_fixed.cpp 修复点：读失败立即退出（原始版缺此判断，空值入表）
    set_111.wordset_add(s); map_111.wordmap_add(s);
}
```

等价性由实测 A5 验证：eof 循环放进一个空词，fail 修复版与 getline 版都不会。

**④ 代码演示**
核心代码（自编示例，对照素材 bug_fixed.cpp 与 test03 的 eof 写法）：

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;
int main() {
    ifstream in("t.txt");
    if (!in.is_open()) return 1;
    string s;
    while (getline(in, s)) {       // 推荐：读即判，无时序差
        cout << s << endl;
    }
    // 素材 test03 的等价物（字符级）：
    // char c; while (!in.eof()) { in.get(c); cout << c; }   // 未修版：空串/末字符隐患
    in.close();
    return 0;
}
```

**执行追踪表**（文件 `aa\nbb\n`，eof 循环版）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | getline | eof 未置位 | 读第一行 | s=="aa"，输出 aa |
| 2 | getline | eof 未置位 | 读第二行 | s=="bb"，输出 bb |
| 3 | !in.eof() | 读指针在文件末尾 | 判定「未到尽头」，进循环 | 隐患出现 |
| 4 | getline | 第四次读触碰尽头 | 失败，eofbit+failbit 置位 | s 被清空为 "" |
| 5 | 空 s 进处理 | 词表被污染 | wordmap_add("") | 多出一个空词（bug 复现，实测 A5） |

**错误写法对照**：

```diff
- while (!in.eof()) { getline(in, s); process(s); }   // 坑1：先判后读——末次失败的空串/残留值进处理（WA：词频多算、行数多一）
+ while (getline(in, s)) { process(s); }              // 读即判，失败瞬间退出
- while (!se.eof()) { se >> w; add(w); }              // 坑2：同款在分词上的复现（素材词频统计原始 bug：空值入表）
+ se >> w; if (se.fail()) break; add(w);              // bug_fixed.cpp 的修复：fail 补闸
```

**⑤ 典型应用**
- 词频统计 bug 修复（25 课件作业「找出程序中的 bug」）：原始程序在 `stringeam.eof()` 循环里让空值入表，bug_fixed.cpp 补 fail 判断——本知识点③的实战原型；素材 test05-test07 三个读取函数开头全部做 is_open 检查。
- 迁移题（自编）：统计文件行数。`while (getline(in, s)) n++;` 对照 eof 循环版——换行结尾的文件 eof 版多数 1；两版各跑边界数据集第 3 条自证。

**⑥ 坑点与边界**

> **【易错】** while(!eof) 系列写法——后果不是崩溃而是**结果多算一拍**（空词入表、行数多一、末字符重复处理）。正解：读操作进 while 条件，或循环内首句 fail 即 break。
> **【易错】** close 纪律缺失——写文件不 close 就依赖程序退出刷新，中途 return/异常路径数据直接丢；同一文件先写后读必须 close 再重开（素材 test10 两次 open 的范例）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空文件：eof 在首次读之前就置位（打开即末尾），eof 循环与 getline 循环均零次（预期：一致，无输出）。
> 2. 单行无换行结尾 "hi"：eof 版读到 hi 后 eof 置位退出（预期：与 getline 版同输出，恰好一次）。
> 3. 带换行结尾 "hi\n"：getline 版 1 行；eof 版第二轮进入后失败产出空串（预期：2 行——坑的实锤，实测 A5）。
> 4. 二进制 read：请求字节数大于文件剩余时按实际读取，gcount() 查真实读取量（预期：gcount 等于剩余字节数）。
> 5. fail 区分：要 int 读到字母 "abc"——failbit 置位但 eof 未置位（预期：用 fail 与 eof 的组合区分「读完」与「格式错」）。极值：10^6 行大文件逐行 getline，流式处理内存恒定（预期：不因文件大而涨内存，复杂度 O(总字节数)）。

回扣开场：「暴力读文章」的雷排完了——读即判的 getline 与 fail 补闸，用的是「先判后读必慢一拍」的时序结论。现在补齐 string 工具箱，词频统计就能整个跑通。

### 4. string 深入：拼接、查找、子串、替换

前置依赖：[[#3. 文件状态与关闭纪律：eofbit、failbit 与 while(!eof) 之坑]]、[[一维数组与字符串]]（C 风格字符数组）
后续衔接：[[KMP]]（模式匹配的线性算法）、[[STL]]（map 计数收尾）

**① 它解决什么问题**
词频统计把一行英文读进来后还差三步：洗标点（把 `,` `.` `?` 换成空格）、切词、计数。洗标点靠 string 的**查找** find/find_first_of 与**替换** replace，切词靠 istringstream 的 `>>`，计数由 map 完成（25 课件 Wordmap 类）。性质总账：拼接 `+=` 均摊 O(新增长度)；find/find_first_of 朴素匹配 O(n·m)；substr 取子串 O(m)；replace O(n)——被替换点之后的字符整体搬移。

**② 直觉理解**
模型级类比：**string 是一张可以变长的便签纸**。`+=` 在纸尾续写；find 是拿放大镜从左往右找第一个命中处并报出坐标；substr 把某段裁下来；replace 裁掉一段再原位贴上新纸片——贴的纸片长短无所谓，后面的字自动挪位。
具体小数据：`s = "hi, ok?"`，delim = ",?"。find_first_of 找「任一属于集合的字符」首次位置，命中下标 2 的逗号；`s.replace(2, 1, " ")` 得 `hi  ok?`；再找命中下标 6 的问号，替换后得 `hi  ok `；找不到时返回 npos，循环结束。

**③ 原理与推导**
为什么词频统计用 find_first_of 而不是 find？find(子串) 找**完整的子串整体**，find_first_of(集合) 找**集合中任意一个字符**首次出现的位置——「洗掉任何一种标点」是集合语义，只能用后者（C 等价写法：strchr 逐字符调用）。npos 是 size_t 的最大值，作「找不到」的返回值，判断必须 `!= string::npos`。
替换循环的一个细节（25 课件 dataProcessing 原文没有 pos++）：它不死循环的原因是**替换目标空格不在 delim 集合里**，下次查找自然越过；若替换目标仍在集合内（比如把元音换成 x 再从 pos 找元音），就原地死循环。这是「写循环要验证前进条件」的实例——自编版补 `pos++` 显式保证前进。**设计动机**：为什么切词不自己写扫描循环而用 istringstream？「按空白切 token」的规则 `>>` 已经实现过一遍（cin 就是这么工作的）——把切好的行塞进 istringstream，等于给这行字接上「内存水管」，cin 的全部分词规则原样复用（素材 string IO 案例 test01-02 正是这个用法）。

**④ 代码演示**
核心代码（自编示例，净化逻辑与素材 dataProcessing 的 find_first_of + replace 一致）：

```cpp
#include <iostream>
#include <sstream>
#include <string>
using namespace std;
int main() {
    string s = "hi, there? ok.", delim = ",.?";   // getline 读到的一行 / 标点集合
    size_t pos = 0;
    while ((pos = s.find_first_of(delim, pos)) != string::npos) {
        s.replace(pos, 1, " ");           // 标点变空格（空格不在集合内，循环能前进）
        pos++;                            // 从下一位置继续找
    }
    istringstream se(s);                  // 行内容变成可 >> 的流
    string w;
    while (se >> w) {                     // 读即判分词（知识点 3 的纪律）
        cout << "[" << w << "]" << endl;  // 每词交给 map 计数（素材 wordmap_add）
    }
    return 0;
}
```

**执行追踪表**（s = "hi, ok?"，delim = ",?"）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | find_first_of(",?", 0) | hi, ok? | 从 0 找集合字符 | 命中下标 2（逗号） |
| 2 | replace(2, 1, " ") | hi  ok? | 逗号换空格 | s 变 hi  ok? |
| 3 | find_first_of(",?", 3) | hi  ok? | 继续找 | 命中下标 6（问号） |
| 4 | replace(6, 1, " ") | hi  ok  | 问号换空格 | 无标点残留 |
| 5 | find_first_of | hi  ok  | 找不到返回 npos | 退出循环，进入分词 |

**错误写法对照**：

```diff
- while ((pos = s.find_first_of(delim, pos)) != npos) { s.replace(pos, 1, ","); }   // 坑1（虚构示意）：替换目标仍在集合内又不前进——原地死循环（TLE）；npos 裸写也依赖实现
+ s.replace(pos, 1, " "); pos++;   // 替换目标必须不在集合内，或显式 pos++ 保证前进
- if (s.find("abc") == -1)   // 坑2：npos 与 -1 数值碰巧相同，但类型是 size_t，写 -1 可读性差且依赖实现
+ if (s.find("abc") == string::npos)   // 标准判断写法
```

**⑤ 典型应用**
- 词频统计全流程（25 课件 Test001）：getline 逐行读（知识点 2/3）→ find_first_of+replace 洗标点（本知识点）→ istringstream 分词 → map 计数（Wordmap::wordmap_add：find 到则 second++ 否则 insert 1）。洗标点的缺口正是作业提示的 bug：「加上标点符号再运行试试」——没洗的标点让 `ok?` 与 `ok` 算两个词。
- 真题：洛谷 P1308 统计单词数——统计给定单词在文章中的出现次数与首次位置；关键思路是整行读入后统一转小写、按非字母切词，与本知识点「洗字符 + 分词」同构。

**⑥ 坑点与边界**

> **【易错】** npos 判断写成 `== -1` 或漏判——漏判时 find 返回的 npos 被当位置用，`s.replace(npos, 1, ...)` 下标越界（RE）。正解：`!= string::npos`（④坑 2）。
> **【易错】** 替换循环不前进——替换目标仍在查找集合内、或 pos 推进量小于匹配长度时死循环（TLE）。正解：验证「每轮 pos 至少前进 1」（③的细节推导）。另注意大字符串拼接一律 `+=`（均摊 O(1)）；「循环里 s = s + ch」每次整体复制，n 次是 O(n^2)。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空文件：getline 不进循环，s 为空串，find_first_of 直接 npos（预期：零输出，不崩溃）。
> 2. 单行无标点 "hi ok"：find_first_of 首轮即 npos，分词得 2 词（预期：[hi] [ok]）。
> 3. 无换行结尾 "i love china"（素材 data.txt 原样）：分词得 3 词，末词 china 恰好入表一次（预期：实测 A4 两种写法均计数 1）。
> 4. 全标点行 ",.?"：三个字符逐个变空格，分词得零词（预期：空输出，map 不新增键）。
> 5. 极值：一行 10^6 字符全为待替换标点——O(n) 替换与分词瞬时完成（预期：不超时；误用「s = s + ch」级拼接则 O(n^2) 卡死）。极值下标：find 目标在文件末尾才出现，find_first_of 全程 O(n) 单遍（预期：不因位置靠后而退化）。

回扣开场：现在你能解决场景二了——getline 整行读入（知识点 2）、fail 纪律挡空值（知识点 3）、find_first_of+replace 洗标点再分词（本知识点），词频统计每一环都有了着落。

## 四、总结与自测

### 核心内容（一页纸速览）

- **文件流总览**：ofstream 写 / ifstream 读 / fstream 双向；`<<`、`>>` 定义在基类，语法与 cin/cout 同构；五步通路「含头文件-建对象-open-读写-close」；out 默认清空、app 追加、binary 原样字节；标准 OJ 用 stdin/stdout，特定赛制才用 freopen 重定向（延伸）。
- **两种读取粒度**：`>>` 按空白切词且把停下的空白留在流里；getline 整行读并丢行尾换行——混用必须 ignore 残留换行。
- **流状态与纪律**：eofbit/failbit 在读失败之后才置位，先判后读必慢一拍；「读即判」与 fail 补闸是唯一正解；close 是落盘保证。
- **string 四件套**：+= 均摊 O(1) 拼接、find/find_first_of 查找、substr 裁段、replace 原位替换；npos 是「找不到」的唯一规范判断。
- **词频统计流水线**：getline 行读 → find_first_of+replace 洗标点 → istringstream 分词 → map 计数；素材原始 bug（空值入表）由 fail 判断修复。
