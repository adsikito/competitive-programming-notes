## 一、为什么需要它

先碰一次壁：上一篇的循环已经能"重复做事"，但变量只能一次记一个数——题目要你存 30 个学生的年龄再找最大值，你只能声明 age1、age2、……、age30 三十个变量，代码瞬间不可维护；一维数组.pdf p4 的原话就是："保存 100 0000 个年龄呢？太多了，咋整？"**碰壁的根源：离散变量无法用循环统一编号访问。**

数组的破法一句话：**给同类型的一批数据连续编号，下标即变量名的可变部分**——于是"遍历 30 个数"退化成上一篇已会的一个 for。字符串是字符的数组，string 是替你管好内存的字符数组升级版。本篇讲 4 个知识点：数组定义与下标越界、数组遍历与最值查找、字符数组与 string、排序与查找应用。顺序理由：容器（1）先于动作（2），普通容器（1、2）先于字符变体（3），综合应用（4）收尾，直接通往 [[排序]] 与 [[二分]] 的正式讲解。

## 二、知识点逐讲（每个知识点一节，共 4 节）

### 1. 数组定义与下标越界：连续内存与编号访问

前置依赖：数据类型与内存表示（同批）、本篇前置《流程控制》（同批，循环基础）
后续衔接：本篇 ### 2. 数组遍历与最值查找：打擂台与范围 for、本篇 ### 3. 字符数组与 string：'\0' 与 string 类

**① 它解决什么问题**

一维数组.pdf p5：数组用来保存**一组类型完全一致**的数据。定义语法 `数据类型 数组名[长度]`（p6），四种初始化形态（p9）：全量 `int ar1[5] = {100,200,300,400,500};`、部分 `int ar2[5] = {10,20};`（其余补 0）、全零 `int ar3[5] = {};`、反推 `int ar4[] = {1,2,3,4,5};`（编译器数元素定长度）。访问用 `数组名[下标]`，**下标从 0 开始，最后一个是长度减一**（p10）。访问单元素 $O(1)$——原因见③，这是数组相对链表（[[链表]]）的核心优势。

**② 直觉理解**

模型级类比：**一排编了号的储物柜**。柜子从 0 号开始编号（C++ 惯例），每格一样大、紧紧相连；`arr[i]` 就是"拿 i 号柜的东西"，报号即取，不用挨个翻。整排柜子的位置一旦定下（定义），数量就不能变了——数组是静态容器。

小数据推演（8.1classcode.cpp 的地址实验）：`bool arr[5]` 定义后打印 `&arr[0]`、`&arr[1]`、`&arr[2]`，地址依次差 1（bool 占 1 字节）；换成 int 数组，相邻地址差 4（int 占 4 字节）。**相邻元素地址等距**正是"报号即取"的底层依据。

**③ 原理与推导**

为什么下标访问是 $O(1)$：数组首地址记为 $A$，每个元素占 $S$ 字节，则 `arr[i]` 的地址恒等于 $A + i \times S$——一次乘法一次加法，与 i 多大无关。这也推出两条纪律：其一，长度必须是**编译期常量**（字面量、`#define N 100` 或 `const int N = 100`，p15），因为 $S$ 与长度都要在编译期确定；`int a = 10; int arr[a];` 不是合法 C++（8.1classcode.cpp 注释里的这行是反例）。其二，越界访问 `arr[n]` 读写的是柜子排之外的危险区域——**下标越界是未定义行为**，轻则读到垃圾值（WA），重则段错误（RE），与同批《数据类型与内存表示》的内存模型呼应。

数组名本身的语义：`arr1 == arr2` 比较的不是内容而是**地址**（p20 明确"不能使用 == 运算符与两个数组的名称来确定数组是否相等"）——两个不同数组地址必然不同，所以恒为"不相等"；比内容要逐元素比（p21 给出 sizeof 求长度 + 逐元素对照的完整代码）。

**④ 代码演示**

块一「核心代码」——定义、初始化、循环赋值与遍历（取自素材 8.1classcode.cpp 与 8.1 pdf p12-14，自编整合，注明：自编示例）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[5] = {10, 20};        // 部分初始化：{10,20,0,0,0}，其余补 0
    int n = 5;
    for (int i = 0; i < n; i++)   // 边界：i < n，下标 0..4
        cin >> arr[i];            // 循环赋值（pdf p14）
    int sum = 0;
    for (int i = 0; i < n; i++)
        sum += arr[i];
    cout << sum << endl;
    for (int i : arr)             // 范围 for（C++ 糖）：逐个取元素，i 是拷贝
        cout << i << " ";
    return 0;
}
// 等价 C 写法：for 循环用下标 arr[i] 访问（见⑤语法糖对照表）
```

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | i=0 | arr=[?,?,-,-,-] | 读 3 存入 arr[0] | arr=[3,?,...,-] |
| 2 | i=4 | arr=[3,7,1,9,4] | 读入完成，下标 0-4 填满 | 越界检查：i 最大 4 < 5 |

| 5 | i=4 | sum=20 | sum += 4 | sum=24，输出 24 |

**⑤ 典型应用**

- 课堂练习（8.1 pdf p18 练习2）：输入 n 个数求和与平均值——`sum * 1.0 / n` 用 1.0 触发浮点除法，int 除法会丢小数。
- 点餐系统（综合案例2，Self service ordering system 2.cpp）：菜名 `string name[19]`、价格 `int price[19]`、数量 `int cnt[19]` 三组数组按**同一编号平行存放**——`name[7]` 的价格就是 `price[7]`、数量就是 `cnt[7]`。这种"平行数组"模式是"多条互相关联的数据按主键组织"的最朴素实现，结构体（同批后续篇）是其升级版。案例代码取核心：单点循环读编号、`cnt[input-1]++`、结账时 `total += price[i] * cnt[i]` 汇总（完整版见源文件）。
- 竞赛衔接：竞赛中数组几乎总是"开到数据范围上限 + 常用下标从 1 起"（如 `int a[100005]`），下标从 1 起可让第 i 个数就是 a[i]、0 号位留给边界哨兵。竞赛衔接说明：开数组前先看数据范围，`10^5` 个 int 约 0.4 MB，在多数题 256 MB 限制内安全；`10^9` 个则必炸——这是复杂度之外的第二道空间闸。

**⑥ 坑点与边界**

> **【易错】** 循环边界 `i <= n` 多摸一位。后果：`arr[n]` 越界，未定义行为（RE 或悄悄污染相邻变量，答案错且极难复现）。正解 `i < n`。

> **【易错】** 部分初始化以为"没赋值的元素是随机值"。后果：`int ar2[5] = {10,20};` 的后三个元素是 0 而非随机值（p9）；但 `int arr[5];` 完全不初始化时才是随机值（8.1classcode.cpp 的 arr[1] 实验可验证）——两种情况要分清。

> **【注意】** 数组名退化场景：作 `==`、作函数参数时数组名不是"整组内容"；比较、传参、赋值都不能整组进行，需逐元素（赋值同理，`arr1 = arr2` 编译不过）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0，读入循环零次，sum=0（预期：输出 0，范围 for 输出 5 个 0——部分初始化的补零在此暴露，属预期行为）。
> 2. 单元素：n=1，数组只有 arr[0]（预期：sum 即该元素本身）。
> 3. 全相同：5 个元素全为 7 → sum=35（预期：与手算一致，验证读入覆盖）。
> 4. 严格递增：1 2 3 4 5 → sum=15（预期：顺序读入无损）。
> 5. 严格递减：5 4 3 2 1 → sum=15（预期：与顺序无关，求和可交换）。
> 6. 极值：5 个元素全为 2147483647 → sum 溢出为负（int 上限约 2.1e9，5 个极值相加必爆）（预期：改 long long 计数——极值类边界的标准动作）。

回扣开场：三十个年龄现在只要一个 `int age[30]`。容器就位，接下来把"扫一遍"变成固定套路——最值查找是它的第一个产出。

### 2. 数组遍历与最值查找：打擂台与范围 for

前置依赖：本篇 ### 1. 数组定义与下标越界：连续内存与编号访问
后续衔接：本篇 ### 4. 排序与查找应用：冒泡、顺序与二分、[[枚举与模拟]]（线性扫描是模拟题的骨架动作）

**① 它解决什么问题**

遍历回答"把数组每个元素都处理一遍"：下标遍历 `for (i=0..n-1)` 是全能形态（能改值、能拿到下标）；范围 for `for (int x : arr)` 只读最快（8.1 pdf p13）。最值查找是遍历的第一个应用：**打擂台法**——8.1 pdf p17 五只小猪练习：`max = arr[0]` 先上台，之后每个元素与擂主比较，更大就换人。一趟扫描 $O(n)$，空间 $O(1)$；比"先排序再取头"（$O(n \log n)$）便宜——为什么不排序？因为只要最大值就不必维持全序，打擂台把信息利用到刚好。

**② 直觉理解**

模型级类比：**擂台赛**。擂主初始站上去一位选手（`max = arr[0]`，不能初始化成 0 或负数以外的想当然值——体重都是正数时 0 可行，但气温可到负数时初始化 0 就错，**用数组第一个元素当初始擂主永远安全**）。挑战者逐个上台：打得过擂主就换人，打不过就走。全部比完，台上就是最大值。

小数据推演（p16 练习1，体重 764, 942, 613, 476, 940）：max 初始 764；942 > 764 换人 max=942；613、476 不敌；940 < 942 不换。最终 max=942。若还要最重小猪的编号，换人时同步记下标（8.2 pdf p30 赛跑案例的 maxi/mini 双变量正是此法）。

**③ 原理与推导**

打擂台的正确性归纳：每处理完第 i 个元素时，不变式"max 等于前 i 个元素中的最大值"成立——初始 i=1 时 max=arr[0] 平凡成立；第 i+1 步若 arr[i] 不大于 max，前 i+1 个的最大值仍是 max；若大于，新最大值恰是 arr[i]。处理完全部元素，max 即全体最大。**为什么初始值必须取 arr[0] 而非手填常量？** 归纳基例要求"max 是前 1 个元素的最大值"，手填常量在"全负数数组找最大"这类题上直接违反基例（初始化 0 会输出 0 而数组里根本没有 0）——这是初学者最高频的逻辑坑。

范围 for 的语义：`for (int x : arr)` 把 arr 的每个元素**拷贝**进 x；想借它改数组要写引用 `for (int &x : arr)`（引用传参（同批《函数》）的数组版）。为什么默认拷贝？防误改；代价是元素大时多一次复制。另外范围 for 拿不到下标——需要下标（如"最大值的位置"）时回到下标遍历。

**④ 代码演示**

块一「核心代码」——打擂台找最值 + 同步记下标（取自 8.1 pdf p17 与 8.2 pdf p30 赛跑案例合并，注明：自编示例，逻辑取自素材）：

```cpp
#include <iostream>
using namespace std;
int main() {
    const int N = 5;
    double arr[N];
    for (int i = 0; i < N; i++) cin >> arr[i];

    double maxv = arr[0], minv = arr[0];   // 擂主：首元素，防全负数翻车
    int maxi = 0, mini = 0;                // 擂主的下标同步记录
    for (int i = 1; i < N; i++) {          // 从 1 起即可：0 号已上台
        if (arr[i] > maxv) { maxv = arr[i]; maxi = i; }
        if (arr[i] < minv) { minv = arr[i]; mini = i; }
    }
    cout << maxv << " @" << maxi << " / " << minv << " @" << mini << endl;
    return 0;
}
// 复杂度：一趟扫描 O(n)，空间 O(1)
```

块二「执行追踪表」（输入 764, 942, 613, 476, 940）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | i=0 | maxv=764, minv=764 | 擂主就位（首元素） | maxi=mini=0 |
| 2 | i=1 (942) | 挑战者 942 | 942>764 且 942<764 为假 | maxv=942, maxi=1 |
| 3 | i=2 (613) | maxv=942, minv=764 | 613 双双不敌 | 无变化 |
| 4 | i=3 (476) | 同上 | 476<764 | minv=476, mini=3 |
| 5 | i=4 (940) | maxv=942, minv=476 | 940<942 且 940>476 | 无变化，输出 942 @1 / 476 @3 |

块三「错误写法对照」：

```diff
- int maxv = 0;              // 坑1：擂主手填 0——全负数组（如气温 -5,-9）会输出 0，数组里根本没有 0（答案错）
+ int maxv = arr[0];         // 首元素当擂主，任何值域都安全
- for (int i = 0; i <= N; i++) if (arr[i] > maxv) ...   // 坑2：i<=N 越界，arr[N] 是垃圾值，可能比真擂主大（答案错/RE）
+ for (int i = 1; i < N; i++) ...   // 右开区间，最大下标 N-1
- for (int x : arr) x = 0;   // 坑3：x 是拷贝，清零的是副本，数组原封不动（答案错）
+ for (int &x : arr) x = 0;  // 引用绑定原元素，才真的写回
```

**⑤ 典型应用**

- 课堂练习（8.1 pdf p17 练习1）：五只小猪最重者——打擂台最小实例。
- 课堂案例（8.2 pdf p29-30 赛跑）：找最高/最低分并交换两人位置——最值 + 下标记录 + swap 三合一。
- 竞赛衔接：最值查找是 [[排序]] 的前身与构件——选择排序每趟就是一次"剩下元素里打擂台"；同理"次大值""最大值与下标"都是本套路的微变体。竞赛衔接说明：要求"最大值出现位置最早/最晚"时，比较条件用 `>` 还是 `>=` 决定取先者还是后者，需按题面显式选择。

**⑥ 坑点与边界**

> **【易错】** 擂主初始化为手填常量（0 或 -1e9 拍脑袋值）。后果：值域踩到常量之外即答案错。正解 `maxv = arr[0]`，从 i=1 开始比。

> **【易错】** 范围 for 想改值却漏 `&`。后果：改在副本上（答案错，编译器不报错，最难查的一类）。需要下标或改值时用下标遍历或引用。

> **【注意】** 求平均值 `sum * 1.0 / n`：先乘 1.0 升级成浮点再除；直接 `sum / n` 是整数除法，小数全丢（8.1 pdf p19 原代码的细节）。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 读入零次，maxv=arr[0] 本身读的是未输入的 arr[0]（预期：竞赛保证 n≥1；n=0 时打擂台无定义，应特判）。
> 2. 单元素：n=1 → 循环从 1 起零次，max=min=arr[0]（预期：正确，最值即自身）。
> 3. 全相同：5 个 7 → maxv=minv=7，maxi=mini=0（预期：比较不触发换人）。
> 4. 严格递增：1 2 3 4 5 → 每步换擂主，maxi=4（预期：最值在末端）。
> 5. 严格递减：5 4 3 2 1 → mini=4（预期：最小值在末端）。
> 6. 极值：元素含 -2147483648 → 若用 `abs()` 或加减处理会溢出（INT_MIN 的相反数超出 int）（预期：纯比较不受影响；一旦参与算术改用 long long）。

回扣开场：扫一遍 + 打擂台，30 个年龄的最大值一个循环拿下。容器处理的是数字，下一节换一种货——字符。

### 3. 字符数组与 string：'\0'、cctype 与 string 类

前置依赖：本篇 ### 1. 数组定义与下标越界：连续内存与编号访问（字符数组就是 char 型数组）
后续衔接：[[字符串哈希]]、[[KMP]]（字符串进阶的容器基础）、本篇 ### 4. 排序与查找应用：冒泡、顺序与二分（string 同样可排序查找）

**① 它解决什么问题**

字符数组.pdf p4：字符数组是存放一连串字符的数组，可直接用字符串字面量初始化——这就是 **C 风格字符串**。关键机制（p5）：字符串以 **'\0'（NULL，编码 0）结尾**——`char c2[10] = "abcde";` 实际存了 6 个字符，`c2` 与 `{ 'a','b','c','d','e' }` 列表初始化的区别就在有无这个终止符；cout 遇到 char 数组会一直输出直到 '\0'（p7：没有 '\0' 的字符数组会输出乱码，p54 实验"改成5 乱码？"正是此因）。string 类（8.4 pdf p4-7）把数组性质藏起来：自动调长度、直接 `+` 拼接、`==` 比较内容、`size()` 求长。strlen 类操作 $O(n)$（要数到 '\0'）。

**② 直觉理解**

模型级类比：**句号结尾的信纸**。C 风格字符串是一张格子上写一个字母的信纸，约定"读到空格子（'\0'）就算句子结束"——所有 strlen/strcpy/strcmp 都是"从头走到空格子"的翻译：strlen 数走了几格，strcpy 是连正文带句号一起誊抄。string 类则像一本**会自动加页的笔记本**：写不下了自己换纸（自动扩容），你只管写。

小数据推演（8.4classcode.cpp 课堂练习2，s = "abccga"）：计数数组 cnt[26] 全 0。扫一遍：cnt[0]=1（a）、cnt[1]=1（b）、cnt[2]=2（c 两次）、cnt[6]=1（g）、cnt[0]=2（a 又来）。第二遍扫：i=0 时 cnt['a'-'a']=2 不符合；i=1 时 cnt[1]==1，输出下标 1（实测附录 B-5）。**计数数组 = "字符当数组下标"**——把 26 个字母映射到 26 个格子，是字符串题的核心套路之一。

**③ 原理与推导**

字符比较的底层：char 就是 0-127 的整数（p5），数字字符 '0' 到 '9' 的 ASCII 是 48 到 57——8.3classcode.cpp 里 `arrc[i] >= 48 && arrc[i] <= 57` 与 `isdigit(arrc[i])` 完全等价（实测一致，附录 B-5）。**为什么 `s1[i] - 'a'` 能当计数下标？** 小写字母连续编码，'a'=97，减去 'a' 后恰好落在 0-25——这是"字符算术"的标准用法；大写同理减 'A'。

string 常用操作对照（8.4 pdf p7-33 集中整理）：求长 `size()` 与 `length()` 同义（p9：一个为 STL 兼容、一个为 C 习惯保留）；拼接 `+`、`+=`、`append()`、`push_back(单字符)`；比较直接用关系运算符（按字典序，p14）；截取 `substr(pos, len)`（p17："Hello,World!" 的 substr(3,5) 是 "lo,Wo"）；查找 `find` 返回首现下标、找不到返回 `string::npos`（即 -1，p19）；删除 `erase(pos, len)`、插入 `insert(pos, str)`、替换 `replace(pos, len, str)`；反转 `reverse(s.begin(), s.end())`（algorithm 头文件，p33）。设计动机：为什么有了字符数组还要 string？p7 原话——"与使用数组相比，使用 string 对象更方便，也更安全"，它把 '\0' 管理、内存扩容这些易错点收进类内部。

输入输出差异（p30）：`cin >> s` 遇空格截断；`getline(cin, s)` 读整行含空格——8.3 课堂练习"统计一行字符"必须用整行读入（cin.getline 或 getline），用 cin >> 只能读到第一个词。

**④ 代码演示**

块一「核心代码」——string 计数数组找第一个不重复字符（取自素材 8.4classcode.cpp 课堂练习2，逻辑逐行原样，注明改动：仅补注释）：

```cpp
#include <iostream>
#include <string>
using namespace std;
int main() {
    string s1;
    int c[26] = { 0 };                 // 计数数组：26 个格子对应 26 个小写字母
    cin >> s1;
    int len = s1.size();               // 等价 C：strlen(s)（字符数组版）
    for (int i = 0; i < len; i++)
        c[s1[i] - 'a']++;              // 字符算术：'a'->0，'b'->1 ...
    for (int i = 0; i < len; i++) {
        if (c[s1[i] - 'a'] == 1) {     // 第一个只出现一次的字符
            cout << i << endl;         // 输出其下标（题面要求索引）
            return 0;
        }
    }
    cout << -1 << endl;                // 不存在
    return 0;
}
// 复杂度：两趟扫描 O(n)，计数数组 O(26) 空间
```

| 1 | i=0 'a' | c[0]=0 | c[0]++ | c[0]=1 |
| 2 | i=1 'b' | c[0]=1 | c[1]++ | c[1]=1 |
| 3 | i=2 'c' | 前两格已计 | c[2]++ | c[2]=1 |

- 竞赛衔接：计数数组（本知识点④）是字符串题的第一反应套路——判回文、判字母重排、找异位词全靠它；更进阶的整串判等加速是 [[字符串哈希]]，逐字符匹配的极限优化是 [[KMP]]。竞赛衔接说明：读入方式（cin >> / getline）决定程序能否处理带空格输入，审题时先确认"一行"还是"一个词"。

**⑥ 坑点与边界**

### 4. 排序与查找应用：冒泡、顺序与二分

前置依赖：本篇 ### 2. 数组遍历与最值查找：打擂台与范围 for、本篇 ### 1. 数组定义与下标越界：连续内存与编号访问
后续衔接：[[排序]]（各大排序的正式讲解）、[[二分]]（二分查找的进阶形态）、[[链表]]（插入删除 O(1) 的对照结构）

**① 它解决什么问题**

8.1 pdf p23："很多数据都需要排序——考试成绩、价格、重量。"**冒泡排序**：相邻比较、逆序交换，每趟把当前最大值"冒"到末尾（p24 三步）。$n-1$ 趟、第 i 趟比 $n-i-1$ 次，总比较 $\frac{n(n-1)}{2}$ 次，$O(n^2)$——n=100 的课堂规模毫秒级，n=10^5 时约 $5 \times 10^9$ 次必超时（什么时候能用在竞赛：n 在 10^3 量级以内或求稳的局部整理）。**查找**：顺序查找从头扫到尾 $O(n)$（sequencesearch.cpp）；**二分查找**在**有序**数组上每次砍掉一半，$O(\log n)$——n=10^6 只需约 20 次（8.2 pdf p8 用猜数字游戏引入："为啥先猜 50？"因为一次比较排除一半）。插入、删除、合并是数组上的移位操作（8.2 pdf p24-47）。

**② 直觉理解**

模型级类比：**冒泡 = 队伍里相邻两人比个子，高者右移**。每趟从左扫到右，相邻逆序就交换——一趟下来最高的人一定被顶到最右（像气泡上浮）；对剩下的人重复，队伍规模逐趟减一。

二分 = **翻字典找字**：不从头翻，先翻中间页，决定往左还是往右半本——每翻一次，剩余页数减半。前提是字典有序；乱序的"字典"翻中间页毫无意义——这就是 8.2 pdf p10 注意点的第一句"用于查找的内容逻辑上需要有序"。

小数据推演（hw_bubblesort.cpp 的数组 {99,11,2,3,4,6,9,7,100,1} 第一趟）：j=0 比较 99,11 逆序交换 → 11,99,2,...；j=1 比较 99,2 交换；……99 一路右移到 99,100 相邻时不再交换，100 再顶 99——第一趟结束末两位有序。实测完整排序输出 `1 2 3 4 6 7 9 11 99 100`（附录 B-5）。

**③ 原理与推导**

冒泡每趟减少一次比较的原因：第 i 趟结束后末尾 i 个元素已是全局最大的 i 个且有序——它们不再参与后续比较，故第 i 趟只需比 $n-1-i$ 次（代码 `j < N-i-1`）。**为什么交换写 swap 而不是三行临时变量？** 临时变量法与加减法（8.1 pdf p30-31 的两种手写法）都易在复用时抄错变量名；swap 一词即语义，且对任何可交换类型通用——可读性即正确性。

二分正确性的不变式：若 k 存在，则它始终位于 `[left, right]` 内。初始区间覆盖全数组；每轮 mid=(left+right)/2：arr[mid]==k 命中；k < arr[mid] 则右半全被排除（数组有序，mid 右侧更大），right=mid-1；反之 left=mid+1。区间每轮至少缩 1，最多 $\log_2 n$ 轮；left>right 时区间为空，k 不存在，输出 -1（binarysearch1.cpp 逻辑）。**为什么 while 条件是 left<=right 而不是 left<right？** 区间闭着，只剩一个元素（left==right）时它还没被检查——写成 < 会漏判单元素区间的命中。

设计动机：为什么二分在有序数据上能砍一半？有序性保证"比较一次即可断言一整侧都不含 k"——信息来自序，不来自数组本身。8.2 pdf p15-23 的三个变式（最小下标 / 最大下标 / 元素个数）都基于"有序数组中相同元素必然相邻"（p21 原话），命中后向左/右线性扫过重复段即可。

**④ 代码演示**

块一「核心代码」——冒泡排序 + 二分查找（取自素材 hw_bubblesort.cpp 与 binarysearch1.cpp，合并改写为一份可编译程序；改动注明：仅整合 main 与补注释）：

```cpp
#include <iostream>
using namespace std;
int main() {
    const int N = 10;
    int arr[N] = { 99,11,2,3,4,6,9,7,100,1 };
    for (int i = 0; i < N - 1; i++)          // 趟数：n-1 趟
        for (int j = 0; j < N - i - 1; j++)  // 每趟比较 n-i-1 次
            if (arr[j] > arr[j + 1])
                swap(arr[j], arr[j + 1]);    // 逆序交换，大者右移
    for (int i = 0; i < N; i++) cout << arr[i] << " ";
    cout << endl;

    int k; cin >> k;                          // 二分：查 k 的位置（1 起），找不到 -1
    int left = 0, right = N - 1, mid;
    while (left <= right) {
        mid = (left + right) / 2;             // 中点（极值场合防溢出写法见⑥）
        if (k == arr[mid]) { cout << mid + 1 << endl; return 0; }
        else if (k < arr[mid]) right = mid - 1;   // k 在左半
        else left = mid + 1;                       // k 在右半
    }
    cout << -1 << endl;    // left > right：区间空，不存在
    return 0;
}
// 复杂度：冒泡 O(n^2)（本例 n=10）；二分 O(log n)
```

块二「执行追踪表」（二分段，有序数组 [1,2,3,4,6,7,9,11,99,100]，查 k=9）：

| 步骤 | 当前元素 | 结构状态 | 动作 | 结果 |
|:---:|:---:|:---|:---|:---|
| 1 | left=0,right=9 | 区间 [0,9] | mid=(0+9)/2=4，arr[4]=6 < 9 | left=5 |
| 2 | left=5,right=9 | 区间 [5,9] | mid=7，arr[7]=11 > 9 | right=6 |
| 3 | left=5,right=6 | 区间 [5,6] | mid=5，arr[5]=7 < 9 | left=6 |
| 4 | left=6,right=6 | 区间 [6,6] | mid=6，arr[6]=9 == k | 输出下标 7（mid+1） |
| 5 | （查 99 对比） | 区间 [0,9] | 三轮内命中 arr[8] | 输出 9——对数级速度直观可见 |

块三「错误写法对照」：

```diff
- int left = 0, right = m;    // 坑1：right 取 m（元素个数）而数组读入到 arr[m-1]——arr[m] 越界（RE/脏值）；binarysearch1.cpp 正解 right = m - 1
+ int right = m - 1;          // 闭区间 [0, m-1] 与下标约定一致
```

**⑤ 典型应用**

- 课堂练习（8.1 pdf p38 + random_sort.cpp）：随机 n 个数装入数组后冒泡排序——排序与知识点 1 的组合；8.1classcode.cpp 的课堂练习版把比较条件改成 `arr[j] < arr[j+1]` 即降序（附录 B-5 实测通过）。
- 课堂案例（8.2 pdf p6 + sequencesearch.cpp）：顺序查找 k 首现位置，找不到输出 -1——实测样例 `1 3 5 6 3` 查 3 输出 2（附录 B-5）。
- 课堂案例（8.2 pdf p13 + binarysearch1.cpp）：有序数组二分查找——实测样例输出 2、查 99 输出 -1（附录 B-5）；变式：最小下标（p17 命中后向左扫）、最大下标（p20 向右扫）、元素个数（p23 双向扫计数）。竞赛衔接说明：插入（p37 新同学）、删除（p40 删负分）、有序合并（p47 归并双指针）三案例的"移位 + 双指针"手法是数组题的通用配件；数组插入删除要整体搬移 $O(n)$，[[链表]] 把它降到 $O(1)$——容器选型的第一笔账。迁移检验题（自编）：有序数组插入一个数仍保持升序（8.2 pdf p51 作业：`1 5 8 11 15` 插 3 → `1 3 5 8 11 15`）。建议先独立做，再对照题解——思路：从末尾向前扫描，比 k 大的元素整体后移一位，遇到第一个不大于 k 的位置写入；复杂度 $O(n)$，全程无需额外数组。

**⑥ 坑点与边界**

> **【易错】** 二分前忘了保证有序。后果：mid 两侧无任何序信息，结果随机错（答案错，且样例可能侥幸通过）。输入无序时先排序再二分。

> **【易错】** `mid = (left + right) / 2` 在 left、right 都是 $10^9$ 量级时溢出 int。后果：mid 为负，arr[mid] 越界（RE）。正解 `mid = left + (right - left) / 2`——本篇课堂规模 n≤100 无碍，但上界习惯要从这里养成。

> **【注意】** 冒泡的提前退出优化：某一趟零交换说明全局有序，用 flag 记录直接 break（8.1 pdf p33 优化版）——对已有序输入从 $O(n^2)$ 降到 $O(n)$；8.1classcode.cpp 注释区完整保留了此版本。

> [!example]-
> **边界数据集（先自己跑一遍，再展开对照）**
> 1. 空输入：n=0 → 冒泡 n-1=-1 趟零执行，二分区间 [0,-1] 为空输出 -1（预期：不崩，空集无元素）。
> 2. 单元素：n=1，查 k → 若 k==arr[0] 命中输出 1，否则 -1（预期：单元素区间 left==right 的 <= 判定在此接受检验）。

> 5. 严格递减：10..1 查 1 → 未排序输入，裸二分无意义输出 -1（预期：暴露"先排序"前置步骤）。
> 6. 极值：k=2147483647 查 → 大于一切元素，left 一路推到 right+1 输出 -1（预期：查找值本身极值不影响正确性；若改"求 mid"环节传入 10^9 级 left/right 则须防溢出写法）。

回扣开场：排序让数据有序，二分借"序"把查找降到对数级——开场"30 个年龄找最大值"如今有三个答案：打擂台 $O(n)$、排完序取头 $O(n^2)$、无序查找 $O(n)$——会算这笔复杂度账，才算真正学完本篇。现在你能解决开场那个问题了，用的正是知识点 2 的打擂台（一次扫描）与知识点 4 的复杂度对比（为什么不必排序）。

## 四、总结与自测

### 核心内容（一页纸速览）

- **数组**：同类型数据的连续编号容器；四种初始化；下标 0 起、访问 $O(1)$（地址 = 首址 + i×步长）；越界是未定义行为。
- **遍历与最值**：下标遍历全能、范围 for 只读快；打擂台 max=arr[0] 一趟 $O(n)$；平行数组按同编号组织多维信息（点餐系统）。
- **字符数组与 string**：'\0' 终止、字符即整数（'0'=48）；计数数组 s[i]-'a' 是字符串题第一反应；string 自动管理长度，find 找不到返回 npos。
- **排序与查找**：冒泡相邻交换 $O(n^2)$、有序标志可提前退出；顺序查找 $O(n)$；二分 $O(\log n)$ 但前提有序、闭区间 left<=right；插入删除是移位操作。
- **复杂度选型**：n=100 冒泡无压力、n=10^5 必超时；单次最值用打擂台不必排序。

### 前置概念清单

- 流程控制（同批）：for/while、break/continue——遍历与查找的全部控制流。
- 数据类型与内存表示（同批）：int/char 字节数、int 范围——越界与溢出的判定依据。
- ASCII 编码：字符与整数的桥梁——'0'-'9' 48-57、'a'=97（8.3 pdf p5）。
